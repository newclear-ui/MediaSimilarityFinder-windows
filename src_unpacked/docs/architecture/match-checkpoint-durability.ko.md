# 매치 체크포인트 강제 종료 내구성 설계 (제안, 미구현)

상태: **PROPOSED** — 0.9.4.153까지 미구현. 본 문서는 설계안이며 동작 변경을 포함하지 않는다.
관련: `docs/build-history/0.9.4.151.ko.md`(C1/C2), `0.9.4.152.ko.md`(킬 내구성 미입증 선언), `0.9.4.153.ko.md`(P1-A/P1-B 종료 경로).

## 1. 문제 정의

스캔 중 매치 집합은 세 곳에서 영속화된다: 5초 간격 체크포인트(`ScanWorker::onMatch` 내),
analyze-slice 경계(`control_.analyzeCheckpoint`), 최종 저장(`run()` 말미).
이 중 마지막만 트랜잭션 밖(autocommit)에서 실행되고, 앞의 둘은 스캔 트랜잭션 안에서
SAVEPOINT로 기록된다(`Database::saveMatches`, `txActive_` 분기, 0.9.4.151 C2).

프로세스 강제 종료(`kill -9`, 전원 차단, AV 강제 종료)는 커밋되지 않은 트랜잭션을
모두 롤백한다. 따라서 **마지막 엔진 커밋 이후에 체크포인트된 매치는 소실**된다.
파일 행도 같은 커밋 경계를 공유하므로, 소실 구간은 "마지막 엔진 커밋 이후"로 동일하다.
즉 매치 내구성은 파일 행 내구성을 최대 1 체크포인트 구간만큼 뒤쫓는다.

현재 코드가 보장하는 것(검증됨):
- 정상/취소/실패 종료 경로의 최종 persist + baseline 무효화(`invalidateMatchBaseline`, 0.9.4.152~153).
- 엔진 file-row 체크포인트 커밋(0.9.4.78~).
- 중첩 save의 정합성(롤백 시 함께 롤백, 0.9.4.151 C2).

보장하지 못하는 것(미입증으로 유지):
- 강제 종료 후 "어디까지 살았는가"를 다음 스캔이 아는 방법. baseline이 유효하면
  다음 A/AB가 전체 검증을 생략하고, 소실된 매치는 `unchanged` 판정으로 영원히
  복구되지 않는다(파일 행은 살아 있으므로 변경 감지도 동작하지 않는다).

## 2. 설계안 D1 (권장): crash marker

스캔 시작 시점에 별도 autocommit 트랜잭션으로 `meta.scan_dirty='1'`을 기록한다.
정상 완료·사용자 취소·처리된 실패(worker의 모든 settled 종료) 시점에 삭제한다.
다음 스캔 시작 시 키가 남아 있으면 이전 실행이 중간에 죽은 것으로 보고,
baseline 값과 무관하게 1회 전체 검증을 수행한 뒤 stamp를 갱신한다.

- 비용: 스캔당 2회 소규모 쓰기(시작/종료). 매치 검증을 추가하지 않는다.
- 기존 메커니즘과 충돌 없음: meta 테이블은 schemaless key-value라 스키마 상향 불필요.
- `.152/.153`의 무효화와 상호 보완적이다(알려진 불완전 종료 vs 알 수 없는 강제 종료).
- 롤백 안전: 마커 쓰기 자체가 독립 트랜잭션이라 스캔 트랜잭션과 얽히지 않는다.

## 3. 기각된 대안 (기록용, 삭제 금지)

- D2 co-commit: 매치 체크포인트마다 엔진 커밋을 강제. 효과는 D1과 동등 이하이며
  커밋 빈도 증가로 wall time이 늘어난다. NOT ACCEPTED (비용 대비 이득 없음).
- D3 분리 DB + autocommit 체크포인트 + 완료 시 병합: 내구성은 최상이나 DB 2개의
  일관성·복구·백업이 모두 두 배가 된다. DEFERRED (D1으로 부족함이 입증될 때 재검토).
- 매치 단위 실시간 fsync: 수백만 쌍 스캔에서 측정 없이 도입할 수 없음. REJECTED.

## 4. 검증 계획 (구현 시)

1. 격리 fixture 인덱스에서 대용량 스캔 시작 후 강제 종료(`TerminateProcess`)한다.
2. 재시작한 스캔이 마커를 보고 전체 검증을 수행하는지 로그(`forceFullPass`)로 확인한다.
3. 종료 후 매치 집합이 완전 복구되는지 DB(`loadMatches`)와 GUI(재적용 화면) 양쪽에서 확인한다.
4. 정상 종료 시 마커가 남지 않음을 확인한다(다음 스캔이 불필요한 전체 검증을 하지 않음).
5. 오버헤드: 마커 2회 쓰기의 스캔 wall time 기여도를 측정한다(기대값: 측정 한계 이하).

## 5. 범위 밖

- 본 문서는 구현을 포함하지 않는다. 채택되면 별도 버전에서 `scan_dirty` 키 추가와
  시작/종료 경로 3곳의 쓰기/삭제 + 회귀 테스트(강제 종료 주입)로 진행한다.
- Test Mode·재검증·불러오기 경로는 대상이 아니다(해당 경로는 별도 트랜잭션 계약을 따른다).

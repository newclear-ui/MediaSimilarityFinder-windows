# MediaSimilarityFinder v0.9.4.137 — 미리보기 게이지: 0.05 단위 스냅 + 비율 버블 소수 둘째 자리

기준선 `0.9.4.136` → 본 빌드 `0.9.4.137`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (표시 전용).

## 1. 변경 필요성

- 실기 피드백(0.9.4.136): ① 드래그 버블을 **소수 둘째 자리**까지 표시, ② 0.9→1.0 사이에서 미리보기 크기가 너무 촘촘하게(1px 단위 13단계) 바뀐다. 사용자 제안은 0.1 단위 이동.
- 판단: 0.1 단위(12.8px)는 0.9→1.0이 한 번에 13px 점프하고 전체 17단계뿐이라 투박하다. **0.05 단위(6.4px, 33단계)**가 "변화가 잦다"는 문제를 해결하면서 둘째 자리(0.95→1.00→1.05)도 의미 있게 유지한다. 이 기준으로 적용.

## 2. 기존 구조

- 0.9.4.136의 `ZoomSlider`는 1px 단위로 움직였고(48..256, 208단계), 버블은 소수 1자리, 소비자는 `QSlider::valueChanged`(원시 값)를 직접 연결했다.

## 3. 변경 구조

- **0.05×비율 스냅**: `ZoomSlider::snapValueFor(v, reference)`가 `round(round((v/128)/0.05) * 0.05 * 128)`로 픽셀 값을 결정(0.40~2.00, 33스톱). `onValueChanged`가 스냅 값으로 `setValue`(QSignalBlocker로 재진입 방지) 후 **`previewSizeChanged(px)` 신호로 스냅 값만 방출**한다. `MainWindow`는 이 신호를 `zoomChanged`에 연결(원시 `valueChanged` 미사용). 키보드/휠: `singleStep=6px`, `pageStep=26px`.
- **버블 소수 둘째 자리**: `round(ratio*100)/100`을 `'f', 2`로 표시(0.50 / 0.95 / 1.00 / 1.25 …).
- 1.0 기준선(128px)은 스냅 스톱과 정확히 일치한다.

## 4. 해결된 상황

- 0.9→1.0 이동이 0.90→0.95→1.00 두 단계로 줄어 "과도한 미세 변화"가 사라지고, 버블이 둘째 자리까지 표시되어 0.05 단위가 읽힌다.

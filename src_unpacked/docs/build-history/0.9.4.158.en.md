# MediaSimilarityFinder v0.9.4.158 — Partial-Fingerprint Cache Ban + Sample Completeness Contract

Baseline `0.9.4.157` → this build `0.9.4.158`.
CPU CTest **132/132**, GPU CTest **132/133 + 1 unrelated GUI flake green on retry** (1 new CTest: video_complete_test).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` unchanged, `kCacheFormatVersion 9 → 10` (purges possibly-poisoned rows), `kProtocol 1` unchanged.

## 1. Why the change was needed

- The external review's P0 (cancelled partial decode succeeding via `return !out.empty()` and reaching the memory/persistent caches) and P1 (no EOF flush/drain, no requested-vs-returned sample reconciliation) were confirmed against the code. A partial fingerprint of a file stopped mid-sweep entering the normal cache would cause comparison misses on later rescans reusing the incomplete cache.
- `VideoSimilarityStats.gpuPairs` counted small batches that never met the GPU execution condition, diverging from actually GPU-processed pairs.

## 2. Previous structure

- `framesAt()`: on cancel, `break` then `return !out.empty()` → partial success. No `avcodec_send_packet(cc,nullptr)` drain at EOF. No `next==targets.size()` reconciliation.
- `build()`: straight to `memoryStore` + `savePersistent` after decode success, with no cancel re-check.
- `gpuPairs+=map.size()` incremented before and regardless of the `ssimBatch()` call and its outcome.

## 3. New structure

- `framesAt()` completeness contract: cancel → clear output + `false`. Emit failure → clear + `false`. After EOF NULL-packet drain, remaining targets are excused only within endpoint-quantization slack of the last actually-decoded frame (`clamp(1.5/fps,0.15,1.5)` s when `fps>0`, else 0.5 s); anything missing beyond that clears and fails. Per-sample timestamp correspondence (`+0.05`) and monotonicity are also verified.
- Why the slack is needed: the plan always appends the exact duration endpoint as the last target, but the last decodable frame precedes it by up to a frame interval. Demanding it would fail legitimate low-fps files. Misses inside the slack produce fingerprints identical to the complete file's (no selected sample lost), so caching them is safe; real content loss (truncation, decoder errors) misses by far beyond the slack and still fails with nothing stored.
- `build()`: cancel re-check immediately before persisting. No store path for incomplete results.
- `kCacheFormatVersion 9 → 10`: purges possibly-incomplete fingerprint rows at open. Engine/DB versions stay (no judgement change).
- `VideoSimilarityStats` gains `gpuSubmitted`/`gpuCompleted`. `gpuPairs` stays as the legacy offered-count for telemetry continuity.
- Regression pin: new `video_complete_test` — pre-cancelled build fails traceless, async mid-sweep cancel fails traceless (4K-noise fixture racing a measured 2.1 s sweep), 80% truncation fails traceless (incl. a direct decoder-level pin), stats-split assertions.

## 4. Resolved state

- Partial sample sets from Stop, EOF, or decoder errors never reach fingerprinting or the caches.
- Sub-threshold batches on the CPU fallback path no longer advance `gpuCompleted`; only `gpuFallback` is set.

## 5. Verification

```text
CPU Release CTest 100% tests passed out of 132
GPU CTest 132/133 (reveal_window_test failed once -> green on standalone and -R reruns; GUI timing flake unrelated to video changes)
video_complete_test green (both trees; submitted/completed branch measured on the GPU tree)
GUI/Backend --version 0.9.4.158 (all 4 binaries)
```

- One mid-implementation regression proved the contract's value: the initial strict version (no slack) failed legitimate low-fps files and took 10 video tests down with it; all green after introducing the slack.

## 6. Impact and limits

- Judgement, storage format, protocol unchanged. Only the cache version rises to 10, causing a one-time video-cache rebuild on first scan.
- Degenerate-but-valid files far shorter than the plan (e.g. single-frame videos) now fail closed (honest failure reporting). Extreme files whose VFR tail gap exceeds the slack do the same. This is the P1 direction; adjust the slack if field measurement objects.
- Time-axis representativeness of kept-frame selection (variance-only) stays a post-V2/V3-gate task, not in this build.

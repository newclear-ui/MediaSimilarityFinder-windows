# MediaSimilarityFinder v0.9.2.86 — 고속 pHash·탐색기 폴백·ffprobe DLL

## 변경 필요성
1. CPU pHash가 해시 1개당 직접합 DCT로 약 0.6ms가 걸렸고, mirror·crop 6개는 항상 CPU 경로라 GPU 효과가 가려졌다.
2. `ffprobe.exe` 실행 시 `avdevice-63.dll`·`avfilter-12.dll` 누락 시스템 오류가 떴다. 빌드 출력에는 직접 링크된 5개(avformat/avcodec/avutil/swresample/swscale)만 복사되고 있었다.
3. 열린 탐색기 창이 없으면 “탐색기에서 보기”가 상태바 메시지만 남기고 아무것도 열지 않았다.

## 기존 구조
- `perceptual_hash()`가 해시마다 코사인 2·64·1024개를 재계산했고, mirror는 이미지를 뒤집어 DCT를 다시 돌렸다.
- 빌드 출력의 ffmpeg 도구는 exe만 복사되고 `avdevice`/`avfilter` DLL은 없었다.
- `revealPath()`의 `NoWindow` 분기는 창을 열지 않았다.

## 변경 구조
- 고속 pHash(외부 기여 패치 적용·검증): 코사인 테이블 1회 계산(스레드 안전), 분리형 DCT(CUDA 커널과 같은 순서), mirror는 홀수 가로 주파수 부호 반전으로 한 번의 DCT에서 `normal`+`mirrored` 동시 산출(`perceptual_hash_pair[_32]`). 호출부는 `media_pipeline`·`crop_fingerprint`·`video_fingerprint` 3곳만 변경, CUDA 커널 불변.
- `avdevice-*`·`avfilter-*` DLL을 빌드 출력에 배포(glob이라 ffmpeg 업그레이드 내성). 포터블은 vcpkg bin 전체 복사로 이미 포함됨을 확인했다.
- `revealPath()`: 열린 창 우선 선택 유지, 해당 창이 없으면 `explorer.exe /select`로 새로 연다.
- 버전 표기 통일 → 0.9.2.86, DB 버전 1.0.1→1.0.2(지문 의미 변경 진단 스탬프), 테스트 57개.

## 해결된 상황
- 자연 이미지·노이즈·비32 크기에서 기존과 비트 100% 동일. 단색·대칭 패턴은 1e-7 스냅으로 결정적 해시(0x7fff…)가 되며, 기존 DB의 해당 파일 해시는 재스캔 전까지 옛 값 유지.
- 엔진 버전·영상 캐시 버전은 유지: 판정 규칙 불변, 저분산 프레임 필터가 퇴화 프레임을 이미 제외하므로 캐시 무효화가 필요 없다.

## 검증
- Core+GUI Release 빌드: PASS, **CTest 57/57 PASS** (신규 `fingerprint_fast_test` 포함, `cuda_backend_test`·`mirror_similarity_test`·`search_engine_test` 포함)
- `cuda_backend_test`: 자연 이미지 56장 CPU·GPU 비트 완전 일치. 합성 격자 패턴 #5만 19비트 divergence(구간 내 원인 규명, 아래 참조) → 구조화 허용치 ≤24로 재조정. 변질 커널 검출력은 자연 이미지 완전 일치 게이트가 유지한다.
- 포터블 `--smoke`/`--version` exit 0, `avdevice`/`avfilter` 동봉 확인.

## 향후 영향
- CUDA 커널에는 스냅을 넣지 않았다(“CUDA 불변” 규칙). 단색 이미지에서 CPU(결정적)와 GPU(노이즈) 해시가 다를 수 있으나 기존에도 있던 종류의 불일치이며 자연 이미지에는 영향이 없다. 원하면 커널 1줄 추가로 맞출 수 있다.
- 단색·체커보드류 파일의 저장 해시는 파일이 바뀌어 재분석될 때까지 갱신되지 않는다.

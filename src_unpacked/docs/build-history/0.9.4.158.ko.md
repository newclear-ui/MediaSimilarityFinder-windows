# MediaSimilarityFinder v0.9.4.158 — 부분 지문 캐시 저장 금지 + 샘플 완전성 계약

기준선 `0.9.4.157` → 본 빌드 `0.9.4.158`.
CPU CTest **132/132**, GPU CTest **132/133 + 무관한 GUI 플레이크 1건 재시도 통과** (신규 CTest 1건: video_complete_test).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` 불변, `kCacheFormatVersion 9 → 10` (오염 가능 행 purge), `kProtocol 1` 불변.

## 1. 변경 필요성

- 외부 리뷰에서 지적된 P0(취소된 부분 디코드가 `return !out.empty()`로 성공 처리되어 메모리·영속 캐시에 저장될 가능성)와 P1(EOF flush/drain 부재, 요청/반환 샘플 수 미대조)이 코드상 확정됐다. Stop이 스윕 중간에 떨어진 파일의 부분 지문이 정상 캐시에 들어가면 이후 재스캔에서 불완전 캐시를 재사용해 비교가 누락된다.
- `VideoSimilarityStats.gpuPairs`가 GPU 실행 조건을 충족하지 않는 작은 batch에서도 증가해 실제 GPU 처리 쌍과 달랐다.

## 2. 기존 구조

- `framesAt()`: cancel 시 `break` 후 `return !out.empty()` → 부분 성공. EOF에서 `avcodec_send_packet(cc,nullptr)` drain 없음. `next==targets.size()` 대조 없음.
- `build()`: decode 성공 후 cancel 재확인 없이 `memoryStore` + `savePersistent` 직행.
- `gpuPairs+=map.size()`가 `ssimBatch()` 호출·성공 여부와 무관하게 먼저 증가.

## 3. 변경 구조

- `framesAt()` 완전성 계약: cancel → 출력 clear + `false`. emit 실패 → clear + `false`. EOF에서 NULL 패킷 drain 후에도 남은 타깃이 있으면, 마지막 실제 디코드 프레임으로부터 endpoint 양자화 허용오차(`fps>0`이면 `clamp(1.5/fps,0.15,1.5)`s, 아니면 0.5s) 안에 들 때만 용인하고, 그 밖의 누락은 clear + `false`. 방출된 각 샘플의 타임스탬프 대응(`+0.05`)과 단조성도 검증한다.
- 허용오차가 필요한 이유: 플랜이 항상 정확한 duration 종단점을 마지막 타깃으로 추가하는데, 마지막 디코딩 가능 프레임은 최대 한 프레임 간격 앞에 있다. 저fps 정상 파일까지 실패시키지 않으려면 종단점 양자화가 필수다. 허용오차 안의 누락은 지문이 완전 파일과 동일하므로(선택된 샘플 손실 없음) 캐시해도 안전하고, 실제 내용 손실( truncation·디코더 오류)은 허용오차를 아득히 벗어나 실패한다.
- `build()`: decode 성공 후 저장 직전 cancel 재확인. 불완전 결과의 저장 경로가 없다.
- `kCacheFormatVersion 9 → 10`: 기존에 저장됐을 수 있는 불완전 지문 행을 open 시 purge한다. 판정 로직 불변이므로 engine/DB 버전은 유지.
- `VideoSimilarityStats`에 `gpuSubmitted`/`gpuCompleted` 추가. `gpuPairs`는 기존 텔레메트리 연속성을 위해 offered 카운트로 유지한다.
- 회귀: `video_complete_test` 신규 — 사전 취소 빌드 실패+무흔적, 비동기 중간 취소 실패+무흔적(4K 노이즈 fixture로 실측 2.1s 스윕과 경합), 80% truncation 실패+무흔적(디코더 직접 핀 포함), stats 분리 단언.

## 4. 해결된 상황

- Stop·EOF·디코더 오류로 인한 부분 샘플 집합이 지문 생성과 캐시에 들어가지 않는다.
- 작은 batch가 CPU fallback으로 처리될 때 `gpuCompleted`는 증가하지 않고 `gpuFallback`만 선다.

## 6. 향후 영향 및 한계

- 판정·저장 형식·프로토콜 불변. 캐시 버전만 10으로 올라가며 첫 스캔에서 비디오 캐시 1회 재구축이 발생한다.
- 단일 프레임 영상처럼 플랜 대비 현저히 짧은 정상 파일은 실패로 닫힌다(정직한 실패 표기). VFR 꼬리 간격이 허용오차를 넘는 극단 파일도 마찬가지다. 이는 P1이 요구한 방향이며, 실측에서 문제되면 허용오차 조정으로 대응한다.
- 프레임 선택의 시간축 대표성(variance-only) 개선은 V2/V3 gate 승인 후 과제이며 본 빌드에 포함하지 않는다.

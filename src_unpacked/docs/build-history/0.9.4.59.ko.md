# MediaSimilarityFinder v0.9.4.59 — Video Cancelled/Failed 분리

기준선 `0.9.4.58` → 본 빌드 `0.9.4.59`.
CPU CTest **107/107**, GPU CTest **108/108** (기존 106/107 + 신규 1).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 제품 VERSION만 bump.

## 1. 변경 필요성

0.9.4.58이 이미지 drain을 해결했으나 비디오는 잔여 버그가 있었다.
`processVideoRange()`가 `bool` 하나로 Success/Cancelled/Failed를 표현해서,
사용자 Stop이 `failed=true` → transaction 전체 rollback으로 변환됐다.
실제 오류 없는 Stop이 Failed로 승격되던 구조다. 완료된 future도 버려졌다.

## 2. 기존 구조

- harvest에서 `stopSeen` 이후 완료 future를 `continue`로 폐기
- `stopSeen`이면 `return false` → 호출부가 `failed=true` → `rollbackTransaction`
- 취소 스캔은 generation 스탬프도 못 받아서 (`r.completed` false),
  다음 스캔이 비디오 전체를 재분석했다 (`videoRegrid`)

## 3. 변경 구조

- `VideoRangeResult { Success, Cancelled, Failed }` 도입 (파일 범위,
  헤더/API 불변, 버전 bump 불필요)
- harvest는 stop 이후 완료분도 정상 persist. DB 오류만 Failed
- `stopSeen`이면 Cancelled 반환. 호출부는 Cancelled를 `cancelled=true`로
  받고 `videoBase`를 전진 (해당 range는 전부 join·소진됐으므로)
- generation 스탬프는 취소 시에도 조건부로 기록. 단 맹목이 아니라
  기존 비디오 row가 이번 스캔에서 전부 admission됐을 때만 (`seen` 기준).
  닿지 않은旧 row가 있으면 스탬프 없이 다음 스캔이 regrid한다

## 4. 해결된 상황

- Stop이 Failed가 아니다. rollback 없음, `telemetry failed:false`
- Stop 시점 완료 비디오가 DB에 남아 rescan에서 unchanged로 재사용된다
- 실제 decode 실패는 기존 failure 의미 그대로 (analysisFailed 기록·집계·
  재시도 없음·스캔 완료)
- 스탬프 조건부 기록으로 취소 후 비디오 재사용과 구버전 row 보호를 양립

## ERRATUM — 2026-10-06 post-build semantic review

0.9.4.59의 구현 설명 중 generation-stamp 조건은 현재 코드 재검토 결과 **불완전한 것으로 정정**한다. 이 항목은 역사 기록을 보존하기 위해 원문을 유지하고 본 erratum을 추가한다.

### 정정 내용

기존 문서의 '기존 비디오 row가 모두 `seen`이면 stamp'라는 설명은 `seen`의 실제 의미를 admission과 동일시한다. 현재 `processOne()`은 `scanVideos=false`인 out-of-scope video도 `seen`에 넣기 때문에, **이미지 전용 스캔이 video sampling generation을 갱신할 수 있다.** 정상 완료 경로의 `r.completed` 분기도 video scope를 확인하지 않는다.

따라서 0.9.4.59는 Video Cancelled/Failed 분리는 해결했지만 generation semantic은 아직 최종 CLOSED가 아니다.

필수 정정 invariant:

- `scanVideos=false`에서는 `sampling_generation`을 절대 변경하지 않는다.
- generation stamp 판정은 일반 `seen`이 아니라 현재 scan scope의 video admission/processing 상태를 사용한다.
- 일반 `seen`은 deletion detection 등 기존 용도를 위해 그대로 유지한다.

### 추가 진단/검증 보강

- `finishScan(false)`가 live cancel flag로 terminal reason을 추론하는 구조는 실제 failure 뒤 늦은 Stop에 의해 telemetry가 Cancelled로 오판될 수 있으므로 explicit terminal state가 필요하다.
- deterministic DB-error regression을 추가하여 rollback + Failed telemetry를 검증해야 한다.
- `setSamplingGeneration()` 반환값을 무시하지 않고 실패 계약을 보수적으로 검증해야 한다.

### 범위

이 erratum은 **0.9.4.59의 측정 결과와 Cancelled/Failed split 자체를 취소하지 않는다.** 다음 후속 빌드에서 semantic correction과 regression tests를 수행한다.

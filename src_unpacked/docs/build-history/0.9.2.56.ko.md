# MediaSimilarityFinder v0.9.2.56 — 스캔 중 UI 프리징 수정(썸네일 디코드 예산)

## 변경 필요성
Balanced에서도 스캔 중 UI가 멈췄다(응답 없음·일시정지/중지 불가·강제종료 필요). v0.9.2.54의 프로그레스 스로틀(150ms)만으로는 부족했고, 진짜 원인은 600ms UI 틱마다 GUI 스레드에서 일어나는 무제한 썸네일 디코딩이었다.

## 기존 구조
- `uiTimer` 600ms마다 `rebuildGroups→refreshGroupList→refreshFileViews`. `fillPair`가 그룹마다 `fileThumb()` 호출(미캐시분은 셸 COM·이미지 디코드·FFmpeg seek 포함). 비디오 1장당 수십~수백ms × 수백 그룹 = 틱마다 수 초 블로킹
- `thumbCache_`가 3000개 넘으면 전체 `clear()` → 대용량 스캔에서 매 틱 수천 개 재디코딩의 영구 폭풍. 이벤트루프가 안 돌아 pause/cancel 클릭 자체가 처리 불가
- `refreshGroupList`가 보이는 탭·숨은 탭 양쪽 위젯을 매번 재생성(수만 개 아이템 + 디코드 낭비)

## 변경 구조
- **디코드 예산**: 틱당 신규 디코드 4개(`kThumbBudgetPerTick`, `thumbBudget_` 멤버, 틱 시작 시 리셋). 캐시 히트는 무제한 무료. 예산 초과분은 파일형식 아이콘으로 표시하고 캐싱하지 않아 다음 틱에 재시도. 명시적 선택 파일(상세 미리보기)은 `bypassBudget`으로 항상 디코드
- **청크 퇴출**: 3000개 초과 시 전체 clear 대신 750개만 제거. 2250개 히트 유지로 재디코드 폭풍 제거
- **보이는 탭만 갱신**: `refreshGroupList`가 현재 탭의 `fillPair`만 수행. 탭 전환 시 `activateTab`이 refresh하므로 숨은 쪽은 지연 갱신으로 항상 정합
- 버전 표기 통일 → 0.9.2.56

## 해결된 상황
- 틱당 GUI 블로킹이 예산(수백ms 이내)으로 상한. 일시정지·중지·닫기가 항상 반응. 대용량 스캔에서 그룹이 늘어도 placeholder 아이콘으로 먼저 표시되고 썸네일은 점진 충전
- 캐시 폭풍 제거로 3000+ 썸네일 환경에서도 안정

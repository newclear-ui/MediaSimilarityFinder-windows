## 1. Why the change was needed

Files without EXIF Orientation, or with an unresolvable EXIF path, had no
readable orientation. `I-exif-orientation-path-fix` explicitly forbade an XMP
fallback, so XMP was promoted to a standalone contract
(`I-xmp-orientation-fallback.*`) with its own production path. The existing
EXIF contract was not retroactively changed.

## 2. Previous structure

- `exifOrientationToTransform()` returned identity for EXIF absent, query
  failure, and invalid values alike, with no distinction. No XMP query code
  existed.

## 3. Changed structure

- New `resolveOrientationToTransform()`: a usable EXIF VT_UI2 value (1..8)
  wins and XMP is never queried. EXIF absent / query failed / wrong type /
  out-of-range value all count as unresolved and fall through to XMP.
- XMP supports exactly one representation, `tiff:Orientation`. Measured WIC
  behavior surfaces it as a `VT_LPWSTR` string; integer VARIANTs are
  normalized too. EXIF wins on conflict.
- Both call sites (fingerprint decodeBoth, color display lane) share the same
  helper, so transform semantics stay unified.
- No telemetry field added. XMP is queried only when EXIF is unresolved.

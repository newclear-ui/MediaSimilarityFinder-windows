# MediaSimilarityFinder v0.9.2.79 — Reuse Existing Explorer Window + Three GPU States

## Need for change
1. "Reveal in Explorer" spawned `explorer.exe /select` in a new window, and the file was often not actually selected. When the folder is already open somewhere, the file must be found in that window instead.
2. The scan summary's "GPU accel." value always read "GPU on", so accelerating / stopped / idle-with-CPU-work were indistinguishable.

## Previous structure
- Both `revealSelected()` and the monitor alert's "Reveal in Explorer" fired `QProcess::startDetached("explorer.exe", /select, …)` — a new process/window
- The summary GPU row appeared only while accelerating and was hard-coded to "GPU on". Pause and CPU-only phases looked identical to real GPU work

## New structure
- **Reuse open windows**: enumerate open Explorer windows through `IShellWindows`, read each window's folder with `IPersistFolder2::GetCurFolder` (falling back to `IWebBrowser2::LocationURL`) and pick the window whose folder equals the file's parent
- **Select inside that window**: bring it to the foreground, build the child PIDL from the view's folder PIDL plus `SHGetIDListFromObject(file)`, then select it with `IShellView::SelectItem`. No new window is spawned
- **Result reporting**: success = silent (as before), focused-but-not-selected, no matching window, and generic failure messages (three new ko/en keys)
- **Three GPU states**: added the engine's `gpuActive` atomic flag, true only inside `MediaPipeline::imageBatch`'s CUDA `hashBatch` calls (cleared immediately on fallback and by an RAII guard). The GUI shows 가속 중 (batch in flight) / 정지 (paused) / 대기 (listing, unchanged-file walk, video FFmpeg analysis, final pair analysis, GPU off or CUDA missing, before/after a scan)
- The summary GPU row is now always visible (previously hidden unless accelerating)
- `media_pipeline_batch_test` now verifies the activity flag is cleared, and `search_engine_test` verifies `gpuActive()==false` after a scan
- Version strings unified → 0.9.2.79

## Resolved situation
- With the folder already open, the file gets selected and focused in that window with no extra window
- The summary value now distinguishes real acceleration, a paused scan, and phases that do not need the GPU

## Validation
- Core+GUI Release build: PASS, **CTest 55/55 PASS**
- `--version` 0.9.2.79, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (only the activity flag was added)

## Future impact
- With no Explorer window open at all, no window is spawned (per request); the status bar explains why
- Windows 11 tabbed Explorer resolves against the active tab; per-tab PIDL matching is not implemented
- Similar-group reference selection is unchanged: the member with the highest best-to-any-other similarity (`bestPct`). A resolution/size-based rule is a separate proposal on hold

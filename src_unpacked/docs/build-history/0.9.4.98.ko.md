기준선 `0.9.4.97` → 본 빌드 `0.9.4.98`.

## 1. 변경 필요성

사용자 지시: 테스트 버튼 표시 유무 설정을 설정 일반 탭에 두고, 순서는 상세로그 → CPU 사용량 표기 → 모니터링 GPU가속 → 테스트 버튼 표시 → 맨 마지막 매칭 검증 방식으로 한다.

## 2. 기존 구조

- 테스트 버튼(툴바 맨 오른쪽)은 항상 표시되었고 표시 여부를 바꿀 방법이 없었다.
- 일반 탭 순서는 언어 → 상세 로그 → CPU 표기 → GPU 가속 → 매칭 검증 방식이었다.

## 3. 변경 구조

- **새 체크박스** (`gui/mainwindow.cpp` 설정 대화상자): `테스트 버튼 표시` (`showTestButton` 신규 키, `ui/showTestButton`, 기본 ON). 상세로그·CPU 표기·GPU 가속 다음, 매칭 검증 방식 이전에 배치. 기존 저장 흐름과 동일하게 저장·적용.
- **툴바 연동**: `testBtnAct_`에 표시 전환 (`applyTestButtonVisibility()`, 기존 액션 패턴과 동일). 토글 상태(`ui/testMode`)는 손대지 않으며, 숨겨도 체크 상태가 유지되어 다시 보이면 동작이 복원된다.
- 번역키 `showTestButton`. `ui_translation_keys_test` 65 → 66 keys.

## 4. 해결된 상황

- 테스트 버튼을 툴바에서 숨길 수 있다 (기본 ON이라 기존 화면 그대로).
- 일반 탭 순서는 지시대로 언어 → 상세 로그 → CPU 표기 → GPU 가속 → 테스트 버튼 → 매칭 검증 방식이다.

## 5. 검증

```text
CPU Release CTest 100% tests passed out of 122
GPU Release CTest 100% tests passed out of 123
GUI/Backend --version 0.9.4.98
```

- `ui_settings_test --cpu-policy` 기존 + `resource_ui=ok`에 테스트 버튼 토글 단언 추가 (OFF→숨김/ON→표시, 기본값 복원).
- `ui_translation_keys_test --tr-keys` 66 keys PASS.
- **정정 (기록 오류 수정)**: 원래 기록 — 0.9.4.96 문서의 `tr-keys 67 keys`. 오류 원인 — 0.9.4.95 기준을 65로 잘못 기산 (실제는 0.9.4.94의 62 + `sumVerify` 1 = 63). 수정된 값 — 0.9.4.96은 65 keys, 본 빌드는 66 keys. 수정 이유 — 키 목록 실측(`--tr-keys` 출력)과 대조. 0.9.4.96 문서와 worklog 0.9.4 항목의 해당 수치를 같은 변경에서 정정했다.
- **미검증/확인 필요**: 실제 GUI 설정·툴바 육안 확인.

# MediaSimilarityFinder v0.9.3.13 — First-Stage CUDA Batch Acceleration for Video pHash

## Need for change
- Video search kept both FFmpeg decoding and sampled-frame pHash on the CPU, leaving CUDA underused.
- The first speedup step needed to preserve decoder behavior and temporal-verdict semantics.

## Previous structure
- `VideoFingerprintEngine::build()` calculated normal and mirror pHash for 32x32 frames on the CPU.
- The CUDA backend was used only by the image batch hash path.
- Video workers ran in parallel, but video GPU usage and fallback were not visible in Benchmark output.

## New structure
- FFmpeg decoding remains on the CPU, while valid 32x32 video frames are batched through CUDA pHash.
- Normal and mirrored inputs are prepared from the same frame and use the existing `GpuBackend::hashBatch()` API.
- CUDA failures or unsupported environments immediately fall back to the existing per-frame CPU pHash.
- Video fingerprint GPU calls are protected by a mutex so multiple video workers can share one backend safely.
- Benchmark JSON now reports videos using GPU hashing, fallback videos, GPU hash time, and sampler activity.

## Resolved situation
- The video fingerprint pHash stage can now use CUDA.
- FFmpeg decoding, crop fingerprinting, and temporal verification retain their previous behavior, so verdict semantics are unchanged in this step.
- Environments without CUDA and runtime failures continue through the CPU fallback.

## Validation
- Physical CUDA device: RTX 3080 Ti, SM86, `cuda_backend=ok`.
- Real FFmpeg video regression: 8 frames, similarity 100, `gpu_video_hash=yes`.
- Full Release build: PASS.
- CTest: **60/60 PASS**.
 - Portable v0.9.3.13 creation and smoke: PASS.
 - Multilingual real-video path regression: FFmpeg decoding and fingerprint comparison passed for Japanese, Chinese, Arabic, and Korean paths.

## Future impact
- Video decoding and 96x96 crop/temporal comparison remain CPU-bound; this is not full video acceleration.
- Next candidates are crop-fingerprint batching, temporal pair batching, and NVDEC evaluation.
 - Batch size and host/device transfer costs require measurement on a large real-video corpus.
 - `thumb48`-based MSSIM is currently CPU-bound. GPU expansion should be a separate step using row-wise batches of 48x48 pairs with CPU fallback on failure.
 - A 10x-plus GPU MSSIM improvement should be treated as a target only after measuring candidate counts, transfer cost, and GPU-to-GPU behavior.

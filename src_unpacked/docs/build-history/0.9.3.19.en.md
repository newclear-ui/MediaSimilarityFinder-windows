# MediaSimilarityFinder v0.9.3.19 — PDH Disk Counter Fix, Integrated Prompt Review

## Need for change
- The 0.9.3.18 benchmark captured `diskVolume:"G:"` but reported `diskAvailable:false`. The first `PdhCollectQueryData` commonly returns `PDH_NO_DATA` for rate counters (it needs two samples), and that was treated as fatal, closing the query.
- The external integrated prompt written at v0.9.3.14 had meta, constraints, and a schedule that no longer matched the actual releases (0.9.3.15–18).

## Previous structure
- `diskAvailable=true` required counter adds plus a successful first collection.
- The integrated document assumed baseline d806e5f, engine 1.2.0, cache v8, CTest 61/60.

## New structure
- The first collection is best-effort; availability follows successful counter adds. Per-tick sampling tolerates failures and records successes (existing logic).
- Added review status §0-1 to the integrated document. The §8 version mapping is retired in favor of actual history, with a per-item status table (P0-1 open through P3-4 valid) and refreshed numbers (CTest 63/63, tolerance 1e-6, cache v9, 63/62 tests).
- Remaining repo doc fixes: `video-gpu-hash` KO/EN now scopes temporal MSSIM to GPU, `candidate-index` KO/EN notes the fold identifier, `BUILD_STATUS.md` broken `??` dashes restored, `AGENTS.md` reworded to verdict-semantics, `llms.txt` stale cache v8 fixed.

## Resolved situation
- Volumes with counters record disk I/O from the first tick. Volumes without counters still report `diskAvailable:false`.
- The integrated document points at the current state.

## Validation
- CUDA Release build PASS, **CTest 63/63 PASS**.
- CPU-only Release build PASS, **CTest 62/62 PASS**.
- Portable v0.9.3.19 creation and smoke PASS, `--version` 0.9.3.19.

## Future impact
- Verdict and engine versions are unchanged, so no revalidation is needed.
- Volumes without LogicalDisk counters (network/virtual drives) stay false. Use the always-recorded process-cumulative I/O (`procIo*`) as the substitute.

# MediaSimilarityFinder v0.9.2.35 — Windows CPU Build/Test Hardening

## Need for change
Building the v0.9.2.34 source-ready tree in the real validation environment (Visual Studio 18 2026 + project-local vcpkg `sqlite3`/`ffmpeg`/`qtbase`, 31 packages) passed CMake configure but failed at link/compile time with 8/36 CTest failures. Prior Linux validation used `GUI OFF`, hiding Qt issues, and POSIX assumptions (deleting open files, rename-over-existing) do not hold on Windows.

## Previous structure
- `msf_core` static library declared FFmpeg includes/links as `PRIVATE`
- `MediaMonitor::emit()` collides with Qt's empty `emit` macro
- `MainWindow` missing the `QCheckBox* gpuEnabled_` member declaration and the `QClipboard` include
- The WIC decoder called `CoUninitialize()` before its `ComPtr` objects were released
- No PGM reader on the Windows WIC path (test fixtures are PGMs named `.jpg`)
- No `close()` on `Database`/`MediaSearchEngine`; tests deleted open database files
- `updateLastScan()` renamed over a file it still held open; the test also held a `meta` handle
- Deployment copied applocal DLLs only, missing the vcpkg Qt layout (`<prefix>\Qt6\plugins`)

## New structure
- `CMakeLists.txt`: FFmpeg compile definitions/includes/links are now `PUBLIC` so consumers of the static library (tests, GUI) inherit them at their own link step. `MSF_HAS_FFMPEG` is `PUBLIC` too, keeping the `video_decoder.h` interface identical for consumers
- `src/monitor.h`/`monitor.cpp`: renamed `emit()` to `emitEvent()` (avoids the Qt macro collision; 6 call sites included)
- `gui/mainwindow.h`: added the `QCheckBox* gpuEnabled_` member. `mainwindow.cpp`: added `#include <QClipboard>`
- `src/image_decoder.cpp`: WIC work moved into static helpers (`decodeWicFile`/`decodeWicFileAspect`) so every `ComPtr` dies strictly before `CoUninitialize()`. The PGM reader became shared helpers (`decodePgm`/`decodePgmAspect`): Windows falls back to it when WIC fails, other platforms keep existing behavior
- `src/database.h`/`.cpp`: added `Database::close()` (also reused by `open()`). `src/media_search_engine.h`/`.cpp`: added `MediaSearchEngine::close()` (closes the DB plus the video fingerprint cache)
- Six tests (`database`, `database_performance`, `search_engine`, `search_report`, `integration_v37`, `index_manager`) now close before cleanup
- `src/index_manager.cpp` `updateLastScan()`: reader scoped/closed before the replace-rename. The test's metadata reader scoped as well
- `scripts/package_portable.ps1`: when windeployqt is absent, mirrors project-local `vcpkg_installed\x64-windows\Qt6\plugins` to `Qt6\plugins`. Version strings unified to 0.9.2.35

## Resolved situation
- Core Release build: PASS (msf_core + 36 test binaries + Qt6 GUI executable)
- `MediaSimilarityFinder.exe --version` exits 0 (after placing `Qt6\plugins`)
- Version strings unified: `CMakeLists`/`vcpkg.json`/`main.cpp kVersion`/window title/`package_portable.ps1`/`kApplicationVersion` → 0.9.2.35

## Validation
- Full Windows CPU pipeline: `scripts/build_windows_cpu.ps1` → configure PASS → Release build PASS → **CTest 36/36 PASS**
- Before: 36× LNK1181, C2146/C2065/C2027 GUI compile errors, 28/36 (6 WIC-teardown AVs + 2 remove-while-open failfasts)
- Root causes proven with probes: `probe_wic` (AV after return) vs `probe_wic2` (exit 0 after fixing release order), `probe_rm` (remove-while-open throw confirmed), Qt6Core-in-CWD bisection → missing `Qt6\plugins` confirmed
- No Linux behavior change (same PGM logic, CUDA algorithms untouched)

## Future impact
- Next step is the CUDA build validation (`nvcc` required — absent in the current environment)
- CI workflows (`windows-cpu.yml`/`windows-cuda.yml`) still pin VS17 2022 and reference old doc names — need VS18 2026 alignment
- vcpkg ships no `windeployqt.exe`, so portable packaging uses the script's mirror path. Formal Qt deployment validation happens at packaging time
- Future Windows tests must respect the no-delete/no-rename-over-open-files rule. The `close()` APIs are the boundary

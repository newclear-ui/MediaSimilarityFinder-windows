# MediaSimilarityFinder v0.9.3.12 — 탐색기 재사용 및 freshness 후속 수정

## 변경 필요성
- 이미 열려 있는 Windows 탐색기에서 대상 파일 선택이 실패했고, 일부 저수준 freshness API와 GUI 그룹 anchor가 파일 교체·정렬 변경 상황을 충분히 반영하지 못했다.

## 기존 구조
- Explorer 대상 파일을 절대 PIDL로 만든 뒤 현재 폴더 PIDL에 `ILFindChild()`를 적용했다.
- Incremental/Database unchanged 판정은 path·size·mtime만 비교했다.
- 영상 메모리 thumbnail fast path는 quick identity를 검사하지 않았다.
- 그룹 선택과 scroll anchor는 transient vector index를 사용했다.

## 변경 구조
- 현재 Explorer view가 직접 반환하는 child PIDL을 열거하고 절대 경로를 비교한 뒤 해당 child PIDL로 선택한다. Shell parsing에는 native Windows path를 사용한다.
- Incremental/Database unchanged 판정에 quickHash를 포함했다.
- Video thumbnail memory hit에도 quick identity를 포함하고, persistent crop cache가 있는 `build()`는 crop 데이터를 보존한다.
- 그룹 선택과 viewport anchor는 대표 경로 identity를 통해 재생성 후 다시 매핑한다.
- 실패 scan의 benchmark 기본 카운터를 반환 전에 채운다.

## 해결된 상황
- 열린 동일 폴더 Explorer 창을 유지하면서 파일 선택이 가능해졌다.
- 동일 메타데이터의 파일 교체가 저수준 unchanged/cache 경로에서 조용히 재사용되지 않는다.
- 그룹 정렬·streaming refresh 후 선택 및 scroll 위치가 같은 대표 그룹을 가리킨다.

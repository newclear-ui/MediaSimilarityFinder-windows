# MediaSimilarityFinder v0.9.3.15 — 퇴화 해시 오판 수정·리포트 대기 UI·영상 GPU 활성 연결

## 변경 필요성
- 서로 다른 영상 5개가 모두 동일한 파일로 판독됐다. 실측 결과 crop pHash가 퇴화(sparse, popcount 2~4) 상태였고, 이런 해시끼리는 87~96% 유사도가 나와 L1 short-circuit으로 곧바로 매치됐다(temporal 점수는 전부 0이라 한 번도 consulted되지 않음).
- 영상 검색에서 GPU를 전혀 사용하지 않는 현상이 보고됐다. 원인은 세 가지였다: (a) L1 short-circuit 쌍은 temporal(유일한 SSIM GPU 경로)을 타지 않는다, (b) SSIM batch 구간에서 GPU 활성 플래그를 세우지 않아 상태바·sampler에 잡히지 않았다, (c) 모니터 영상 분석이 GPU backend 없이 CPU로만 빌드됐다.
- 검색 완료/종료 시 리포트 작성 대기 안내가 없어 사용자가 도중 종료했고, 파일 선택 하이라이트가 옅고, 영상 미리보기가 흑백으로 표시됐다.

## 기존 구조
- `bestMatch()`/`bestAgainst()`/`anchorSim()`이 0이 아닌 해시를 전부 비교했고, 퇴화 해시를 걸러내지 않았다.
- `VideoSimilarityOptions`에 GPU activity 전달 수단이 없어 SSIM batch 중 `gpuActive_`가 false로 남았다.
- `MediaMonitor`가 영상 fingerprint를 CPU로만 빌드했다.
- 스캔 완료 시 별도 안내 팝업이 없었고(성공 경로는 모달 없음), 선택 하이라이트는 OS 네이티브 테마에 의존했다.
- 구형 빌드가 저장한 회색 engine 썸네일이 디스크 캐시에 남아 이후 모든 조회를 흑백으로 고정시켰다.

## 변경 구조
- `similarity.h`에 `hash_usable()` 가드를 추가했다(popcount 8 미만·0은 비교 제외, 정상 median-split pHash는 약 32비트).
- `bestMatch()`, `anchorSim()`, `bestAgainst()`에 가드를 적용했다. 인덱스(후보 열거)는 그대로라 열거 의미는 불변, 판정만 수정된다.
- 검색엔진 판정 버전을 1.2.0 → 1.3.0으로 상향했다. 다음 스캔에서 저장 쌍이 자동 재검증되어 기존 오판 그룹이 탈락한다(전체 재스캔 불필요).
- `VideoSimilarityOptions::gpuActivity`를 추가해 SSIM batch 구간에 활성 플래그를 세우고, `ScanPipeline::setVideoGpuActivity()`로 scan/revalidate/live 경로에 연결했다.
- `MediaMonitor`에 `videoGpu_` backend를 추가하고 정책(`policy_.gpuEnabled`) 허용 시 영상 분석에 사용한다.
- 스캔 완료(`scanFinished`/`onResults`) 시 "검색 리포트를 작성 중입니다. 잠시만 기다려 주세요…" 작은 비모달 팝업을 먼저 띄우고 리포트 뷰 재구축이 끝나면 닫는다. 스캔 중 창 닫기 시 종료 확인을 묻는다.
- 결과/파일 6개 뷰에 고대비 선택 스타일(활성 #2b6cb0·비활성 #7aa7d9, 흰색 글자)을 적용했다.
- 회색 디스크 캐시 항목은 건너뛰고 컬러 디코더로 폴백하며, 회색 engine 썸네일은 저장하지 않는다.
- `msf_cuda_backend_ssim_batch`에 grid x차원 상한(`count>2147483647ULL`) 가드를 추가해 `hashBatch`와 일관되게 했다.
- `tests/video_degenerate_hash_test`를 추가했다(가드 계약 + 퇴화 crop 공유 쌍 미매치 + 정상 쌍 매치).

## 해결된 상황
- 샘플 5개 영상 end-to-end 스캔 결과 그룹 0개(수정 전에는 모두 동일 그룹). temporal 검증 없이 L1에서 걸러진다.
- SSIM GPU 사용이 상태바·Benchmark sampler에 정상 표시된다.
- 엔진 1.3.0 재검증으로 기존 저장 오판 쌍이 다음 스캔에서 자동 탈락한다.
- 사용자는 리포트 작성 대기를 인지하고 종료를 보류할 수 있다.

## 향후 영향
- 퇴화 판정 기준(popcount 8)은 경험적 하한이다. 대규모 corpus에서 정상 쌍 탈락(false negative) 징후가 보이면 조정해야 한다.
- 인덱스에는 퇴화 해시가 그대로 들어가 후보 열거 비용만 들고 판정은 거부한다. 필요하면 인덱스 단계 제외를 검토한다.
- 작은 후보군에서 DTW 행 단위 호출·전송 비용이 가속폭을 제한한다는 0.9.3.14의 결론은 그대로다. 이미지 배치 해시와 영상 SSIM이 같은 스캔에서 동시에 도는 실제 부하 기준으로 벤치마크를 재측정해야 한다.
- SSIM "최대 오차 0"은 RTX 3080 Ti 실측값(허용 오차 1e-6)이며 다른 SM 세대 재확인이 필요하다.

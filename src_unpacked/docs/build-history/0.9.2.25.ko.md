# 0.9.2.25 — SQLite/Index 성능 최적화 및 마이그레이션 강화

## 중요 변경

이번 버전은 대규모 미디어 Index가 증가할 때 SQLite와 Index 관리 계층에서 발생할 수 있는 반복 작업을 줄이고, 기존 DB migration을 더 안정적으로 처리하도록 구조를 정비했다.

### 변경 필요성

기존 구현은 파일 upsert/remove/unchanged 확인 때마다 SQL statement를 반복 준비할 가능성이 있었고, SQLite 동시 접근 시 busy 상태에 대한 명시적인 대기 정책도 필요했다. 또한 crop fingerprint schema migration은 누락 컬럼마다 별도의 schema 조회를 수행했다.

### 설계 변경

- `upsert`, `remove`, `containsUnchanged`용 SQLite prepared statement를 Database 연결에서 재사용한다.
- statement 재사용 전 binding을 명시적으로 reset/clear한다.
- SQLite에 WAL, `synchronous=NORMAL`, `busy_timeout=5000`, `temp_store=MEMORY` 정책을 적용한다.
- crop schema migration은 6개 컬럼을 각각 검사하지 않고 한 번의 schema scan으로 누락 항목을 확인한다.
- `IndexManager` application version metadata를 0.9.2.25로 정정한다.
- portable packaging version을 0.9.2.25로 동기화한다.

### 해결된 상황

DB 연결이 반복 SQL 준비에 의존하지 않도록 하고 migration의 schema 조회 횟수를 줄였다. SQLite busy 상황에서도 즉시 실패하지 않고 짧은 시간 대기할 수 있다.

### 주의 사항

현재 Database prepared statement는 연결 소유권을 전제로 한다. 향후 동일 Database 연결을 여러 스레드에서 동시에 사용한다면 별도 mutex 또는 connection ownership 정책이 필요하다.

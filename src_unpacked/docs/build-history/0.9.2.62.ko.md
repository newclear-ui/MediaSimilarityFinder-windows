# MediaSimilarityFinder v0.9.2.62 — Similarity 참고 반영 (Pairs·남은시간·썸네일 skip-list)

## 변경 필요성
외부 참고 분석(`docs/architecture/reference-similarity.ko.md`)에서 Similarity의 세 가지 실용 패턴을 확인했다. 그룹당 파일 수만으로는 대그룹의 비교 규모를 가늠할 수 없었고(Pairs 컬럼 부재), 스캔 중 경과 시간만 보여 완료 시점을 예측할 수 없었으며(남은시간 부재), 손상·디코딩 불가 파일이 썸네일 예산을 반복 소모했다(skip-list 부재). 모두 GUI 공통 계층에서 해결 가능하고 CUDA 알고리즘과 무관하다.

## 기존 구조
- 그룹 트리 4컬럼: 그룹 / 파일 수 / 유사도 / 크기. `fillPair`가 쌍 수를 계산하지 않음
- 상태 메시지: `done / total (pct%) — 파일명 — 경과` 고정. 남은시간 없음 (`scanProgress`, 600ms `uiTimer` 틱)
- `fileThumb`: 실패 시 placeholder를 캐시하지만, 캐시 퇴출(3000 상한) 후 손상 파일이 다시 헤비 디코드를 소모. 실패 경로 별도 기억 없음

## 변경 구조
- **Pairs 컬럼** (`gui/mainwindow.cpp` `fillPair`): `pairs = n*(n-1)/2`, 트리 5컬럼(그룹/파일/쌍/유사도/크기) + 그리드 라벨에 `N 쌍` 병기. 한영 문자열 `pairs` 추가
- **ETR 표시** (`scanStatusText` 신규): `남음 = 경과×(total-done)/done` 선형 외삽. `elapsed<1s·done==0·total<=done`이면 기존 표시 유지. `scanProgress`와 틱 표시가 같은 헬퍼를 공유. 한영 문자열 `remain` 추가
- **썸네일 skip-list** (`thumbFail_`, 최대 2000, 500씩 퇴출): 헤비 디코드 실패 경로를 기억, 이후 틱에서 예산 소모 없이 파일형 아이콘 즉시 반환. 스캔 시작 시 초기화, 파일 삭제 시 해당 항목 제거
- 버전 표기 통일 → 0.9.2.62

## 해결된 상황
- 대그룹의 실제 비교 쌍 수를 트리·그리드에서 즉시 확인 (Similarity v1.8.1 Pairs 컬럼 대응)
- 스캔 중 `… — 남음 HH:MM:SS` 표시로 완료 예측 가능 (Similarity Estimated Time Remaining 대응)
- 손상 파일이 셸/헤비 디코드 예산을 더 이상 소모하지 않음 (Similarity skip-list 대응, 썸네일 범위)

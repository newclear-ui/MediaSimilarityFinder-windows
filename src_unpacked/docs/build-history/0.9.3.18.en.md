# MediaSimilarityFinder v0.9.3.18 — Benchmark Disk I/O, Duration Direct Fallback, Popup Readability

## Need for change
- In the measured benchmark, video analysis took 97% of wall time with 17% CPU and 0.2% GPU duty, so decoder vs disk bottlenecks were indistinguishable. Recording the scanned volume's I/O lets slow files be compared against drive saturation.
- The detail duration still showed "-" on live/cancelled scans. One fallback layer was not enough when the engine list has no entry either.
- The stop popup text was clipped in a fixed 360px box. CJK glyphs clip sooner at the same width.

## Previous structure
- Benchmark `resources` recorded CPU, memory, and GPU only.
- Duration lookup used `fileDur_` then the engine list only.
- The wait popup had a fixed size. The `newName:` call had a key typo showing the raw key in both languages.

## New structure
- `BenchmarkRecorder` opens PDH LogicalDisk read/write Bytes/sec counters for the scan root's volume (e.g. `G:`, English counter names so display language does not matter). Each 250ms sample records drive-wide read/write Bps plus process-cumulative I/O (GetProcessIoCounters).
- Benchmark JSON `resources` gains `diskVolume`, `diskAvailable`, `ioReadBpsMax/Mean`, `ioWriteBpsMax/Mean`, `procIoReadBytes/WriteBytes/Ops`; `series` entries grow to 7 elements. The search-log dialog gains a disk I/O line (`benchIo`, KO/EN).
- A still-empty duration is read straight from the container (`VideoDecoder::open` + `info`, ~30ms, cached). Not applied to images.
- The wait popup now word-wraps with a 460px minimum width sized to content. Fixed the `newName:` typo to `newName` (audit: the only missing key out of 119 used, zero empty EN strings).

## Resolved situation
- Slow files' `buildMs` can now be compared against drive I/O in the same window.
- Video durations display regardless of scan state.
- Popup text shows fully on two lines.

## Validation
- `benchmark_test` extended with `diskVolume`, `ioReadBpsMax`, `procIoReadBytes` assertions, PASS.
- CUDA Release build PASS, **CTest 63/63 PASS**.
- CPU-only Release build PASS, **CTest 62/62 PASS**.
- Portable v0.9.3.18 creation and smoke PASS, `--version` 0.9.3.18.

## Future impact
- On PDH failure (permissions, missing volume), I/O records 0 with `diskAvailable:false`. Verdict and engine versions are unchanged, so no revalidation is needed.
- The `series` format grew to 7 elements. External parsers need updating.

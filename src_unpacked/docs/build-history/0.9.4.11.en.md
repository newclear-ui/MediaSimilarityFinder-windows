# MediaSimilarityFinder v0.9.4.11 — Node C3: Opportunistic Recalibration

Validation baseline for C3: short re-measurement only when live
observation repeatedly diverges from baseline on runs with a healthy
profile. Engine 1.5.0, DB 1.0.3, cache v9, schema 2 unchanged.

## Why the change was needed
- Through C2 a profile was written once and frozen. Hardware, driver,
  or load changes left baselines detached from reality with no update
  path.

## Previous structure
- Calibration on Missing/Hard only; Exact/Soft reused forever.

## New structure
- `DeviationTracker` (calibration.h/.cpp): per-scan live pair vs the
  feeding baseline. Fires only on 3 consecutive scans deviating over
  25% on either rate; counter resets after firing (next trigger needs a
  fresh run of 3). Profile switches reset the run; invalid inputs reset
  instead of firing.
- Fixed policy numbers: threshold 25%, repetitions 3, consistency 40%,
  confidence ±0.1 (cap 0.95, floor 0.1). Provisional, stated as such.
- Candidate consistency: the fresh candidate must agree with the firing
  live observation within 40% to replace. On mismatch metrics stay and
  confidence steps down. On failure the file is untouched.
- `[lastUpdate]` persistence (reason, old/new ids, confidences;
  absent = never updated). Ids are identity-based so old == new
  normally — a continuity marker.
- Engine `finishScan`: evaluates the trigger only on completed,
  profile-fed scans with both live rates observed. Bounded re-measure
  on fire, rules above applied. Whole block in try/catch —
  recalibration can never fail a scan. Cancelled scans excluded.
- CPU-only scans never enter trigger evaluation (no GPU live
  observation; profiles yield no pair there either — consistent).

## Why this shape
- The single-outlier ban is one counter reset: repetition, not complex
  statistics.
- Candidate consistency asks one question: does the fresh measurement
  agree with live? A mid-change measurement is discarded and the old
  value trimmed — safer.
- Confidence moves in fixed ±0.1 steps, same conservative family as
  C2's 0.8/0.5.

## Resolved state
- The profile lifecycle is closed: create (C2) → reuse → drift detect →
  update/keep.

## Accuracy impact
- None. Verdict paths untouched, recalibration failures non-propagating.
  Identical `scan_workflow_test` on both trees; parity suites green.

## Compatibility impact
- Benchmark JSON keys unchanged. INI gains the `[lastUpdate]` section
  (old files load as absent, consistent with the ignore-unknown rule).

- Tracker groups (normal, single, repeated, switch, invalid/CPU-only),

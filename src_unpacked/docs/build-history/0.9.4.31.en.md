## 1. Purpose · Hypothesis · Target

- Purpose: measure whether the two per-miss decodes of the verify path can be
  replaced by one shared-resolution decode plus two in-memory resizes.
- Hypothesis: one shared decode + two resizes is cheaper than two file decodes
  while preserving `f`/`a` semantics and groups/verdict.
- Target: baseline `decode(path,64,64)` + `decodePreserveAspect(path,64)` versus
  candidate (`decodePreserveAspect(path,R)` + in-memory Fant scale × 2), in cost
  and accuracy.
- Reason for candidacy: D3 measured the second decode at 49.60 % of
  verifyDecodeMs, so decode count itself is the remaining large cost. But `f`
  and `a` are different geometries, so "removal" would be an accuracy
  regression — measure substitutability first.

## 2. Implementation

- New file: `tests/shared_decode_probe.cpp` (measurement-only executable
  `msf_shared_decode_probe`). No production code changes.
- Baseline: existing `decode()` / `decodePreserveAspect()` calls (unmodified).
- Candidate shared decode: existing `decodePreserveAspect(path,R)` call
  (unmodified).
- Candidate derivation: in-memory `GrayImage` → WIC Fant scaler → 8bppGray
  converter → `CopyPixels`. Same call order as the baseline's
  scaler/converter/copy stages, so the comparison is between the same
  operations. Isolated helper, wired into no product path.
- `a` target dimensions: same long-edge-fixed, `lround`-rounded formula as
  `decodeWicFileAspect` (`src/image_decoder.cpp:293`), applied to the shared
  image size.
- Verdict threshold 87.5 corresponds to scan `maxDistance 8`
  (`src/scan_pipeline.cpp:18` `thresholdFor`,
  `tests/dataset_baseline.cpp:256` `engine.scan(root, 8, ...)`).
- `--selfcheck` mode: 6 shared-dim formula checks, 3 pixel-compare checks,
  3 WIC-derivation checks, 1 crop check — no dataset needed, 14 checks total.
- CMake registration: `add_executable(msf_shared_decode_probe)` + `msf_core`
  link. Not registered as CTest: like `msf_dataset_baseline` it needs a
  measured dataset-root argument and takes minutes.

The 2 flips are the same pairs with identical scores in all 5 runs
(deterministic computation), both TIFF near-duplicate pairs:

```text
R=384/512: hpredict_packbits.tiff <> hpredict.tiff   base=87.43/86.81 cand=94.87/94.86
R=384/512: l1_xmp.tiff <> l1.tiff                    base=86.86/85.81 cand=95.00/94.86
```

Pairs sitting just below the threshold (85.8–87.4) are pushed above it (~95)
by the candidate. The candidate therefore **adds matches** the baseline misses.
Max delta grows with R (2.63 → 9.19): higher shared resolution does not close
the score gap.

## 8. Answers to the Three Questions

- Q1 (reproduce f/a semantics): geometry mostly reproduced, pixel bytes never
  reproduced. NO.
- Q2 (keep groups/verdict): 0 flips at R≤256, 2 flips at R≥384 (same pairs,
  reproduced 5×). Full-scan groups comparison not performed — no candidate scan
  driver exists; see Known limitation. Verdict preservation not guaranteed.
- Q3 (cost): YES. 24–46 % cheaper than baseline at every resolution.

## 9. Status · Reason

```text
measurement PASS (all three questions answered with numbers)
candidate DEFERRED (not adopted into production)
```

Reason: the cost saving is large and real, but (1) byte reproduction fails and
(2) verdict flips are observed on near-threshold pairs, so an accuracy
regression cannot be ruled out. The flip direction (adding matches) could be
favorable for recall, but equivalence with the baseline is broken, so it is not
adopted as-is.

Future revisit condition:

```text
1. when a verdict-band policy is defined (a tolerance rule for near-threshold
   pairs: within how many points a difference still counts as equivalent —
   flips cannot be judged without it)
2. when rotated-EXIF / PGM-fallback / cache hit-miss split coverage exists
3. when a candidate scan driver enables full-scan groups comparison
4. when the Windows/WIC runtime changes
```

Related experiments: D2 (Path C DEFERRED), D3 (PASS, follow-up opened).

## 10. Known limitation (explicitly unmeasured)

```text
- EXIF orientation: 0 orientation-applied files in the dataset
  (orient_applied_files=0) — rotated-JPEG comparison not covered. Needs an
  orientation-EXIF fixture.
- PGM fallback: 0 files (pgm_fallback_files=0) — PGM path unverified.
- Cache: the probe bypasses the verify cache and calls decoders directly (same
  as the D2/D3 probes). On a hit both paths cost ~0 (cached pair), so the
  candidate effect concentrates on the miss path (D3's 12,962 misses) — recorded
  as a structural consequence, not a separate measurement.
- Full-scan groups: verdict evaluated on 1691 sampled pairs without a candidate
  scan driver. Full groups equivalence unmeasured.
- Candidate telemetry lives in probe stdout, not in the benchmark JSON schema.
  schemaVersion unchanged.
```

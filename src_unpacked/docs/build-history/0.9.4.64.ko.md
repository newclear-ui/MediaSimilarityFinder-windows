## 1. 변경 필요성

- 0.9.4.63은 ☰ 메뉴에 "설정"(모니터 설정)과 "표시 설정"(상세 로그 표시)을
  나란히 두었다. 체크박스 1개를 위해 대화상자 1개가 통째로 추가된 모양이라
  설정 진입점이 둘로 갈라진다.
- 사용자 정정: 별도 표시 설정 대화상자를 없애고, 해당 옵션을 기존 설정
  대화상자의 일반 탭으로 옮긴다. 설정 진입점은 하나로 유지한다.

## 2. 기존 구조

- ☰ 메뉴: `monSettingsAct_`("설정" → `configureMonitor`) +
  별도 action("표시 설정" → 별도 `QDialog`).
- 별도 대화상자 objectName `displaySettingsDlg`, action `displaySettingsAct`,
  geometry 키 `ui/displaySettings`.
- 체크박스 문안 키 `displaySettings`.

## 3. 변경 구조

- 별도 대화상자·action·`ui/displaySettings` 키 전부 삭제.
- `configureMonitor()` 일반 탭에 "상세 로그 표시" `QCheckBox` 추가
  (objectName `showDetailLogBox`, 문안 키 `showDetailLog`).
- 대화상자 objectName `settingsDlg`, ☰ action `settingsAct` 부여
  (자동화 hook, 기존 `folder_` 패턴과 동일).
- 저장 키는 기존 `ui/showDetailLog` 그대로. OFF면 `logTglAct_` 경유로
  toolbar 체크박스만 숨기고, checked 상태·telemetry 배선은 그대로라
  다시 켜면 기존 UI가 복원된다 (0.9.4.63 동작 유지).
- `ui_settings_test.cpp`의 tr-key 핀을 `displaySettings` →
  `showDetailLog`로 변경.

## 4. 해결된 상황

- 설정 진입점이 하나로 통합되었다. 표시 옵션의 자리는 설정 대화상자
  일반 탭이다 (Test Mode follow-up의 Settings 위치 결정도 이 계열에서).
- round-trip 동작 불변: OFF 저장·숨김·상태 유지 → ON 저장·재표시.

## 5. 검증

### `ui_usability_test` (13 checks, CPU·GPU PASS)

- 드라이버를 `displaySettingsDlg`/`displaySettingsAct`에서
  `settingsDlg`/`settingsAct`로 변경. 검사 항목·개수 동일.
- 테스트 자체의 race 수정: benchmark 요약 대화상자용 closer가 *모든*
  modal을 닫고 있어서, Phase A에서 설정 대화상자를 먼저 닫아버리는
  경우가 있었다 (ON round-trip이 flaky하게 실패 — 두 번째 trigger는
  슬롯까지 도달했으나 대화상자가 closer에 의해 즉시 닫힘).
  closer 시작을 스캔 구간(Phase C)으로 한정하고, 디버그 마커는 제거했다.
  이 race는 테스트 한정 문제이며 제품 코드 변경은 아니다.

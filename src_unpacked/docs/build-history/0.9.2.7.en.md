## ⚠ IMPORTANT UPCOMING UPDATE: Real-Time Media Duplicate Monitoring

Starting with the next development batch, the project will design and implement a **resident real-time duplicate monitor** based on the existing search engine, SQLite Index, fingerprints, and Candidate Index.

### Goal

Monitor multiple user-defined folders across multiple drives. When a new media file finishes being saved, compare it against the existing Index and report files that are likely identical or highly similar, including their drive and full path.

### Direction

1. Prefer filesystem events, but never analyze a file while it is still being copied/downloaded.
2. Confirm that file size/write activity has stabilized before analysis.
3. Allow separate definitions of watched folders and comparison Index roots.
4. Reuse the existing search engine and database rather than creating a separate duplicate-search engine.
5. Use the pipeline: fingerprint → Candidate Index → precise similarity comparison → user report.
6. Keep the DB and Candidate Index continuously synchronized with file additions, changes, and deletions.

### ⚠ PRIMARY DESIGN PRINCIPLE: SYSTEM LOAD PROTECTION

**Protecting the user's workload takes priority over real-time analysis speed.**

- The monitor must not cause a sudden CPU/GPU load spike during gaming, encoding/rendering, or other heavy workloads.
- Do not rely only on fixed CPU/GPU limits; continuously observe current system load.
- Dynamically reduce or pause work according to CPU/GPU/memory/I/O pressure.
- Increase analysis throughput only when sufficient resources are available.
- Immediately throttle or pause background analysis under high load, keeping pending files in a queue when necessary.
- The user should be informed when analysis is delayed because the monitor deliberately avoided impacting system performance.

### UI Direction

Use a single comparison popup with the new file and existing file side by side.

- Left: preview of the newly saved file
- Right: preview of an existing match
- Filename / full path / drive / size / similarity
- Open the corresponding location in Windows Explorer
- Move the new file to the Recycle Bin
- Move the existing file to the Recycle Bin
- Skip the current decision
- Show multiple existing candidates when applicable

### Resident Operation

A Windows system-tray background Monitor mode is being considered. The normal search function and real-time monitor should share the same Core/Index/Search Engine.

### Documentation Rule

This is treated as an **important architectural expansion**, not merely a UI feature. Once the implementation structure is finalized, the corresponding architecture documentation will be updated separately.

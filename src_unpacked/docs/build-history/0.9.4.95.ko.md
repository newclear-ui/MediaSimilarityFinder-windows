# MediaSimilarityFinder v0.9.4.95 — 요약 패널 쌍검증 표기 + 안정형 재스캔 측정 기록

기준선 `0.9.4.94` → 본 빌드 `0.9.4.95`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 요청 3건:

1. 0.9.4.94 안정형 재스캔 로그 리뷰(`detailed-log-2026-10-13T200015.json`)를 **예제 측정 기록**으로 남긴다.
2. 차후 다른 설정(고속형/자동)으로 측정한 검색 기록도 같은 형식으로 **계속 기록**한다.
3. 쌍검증 전체 갯수와 검증 갯수를 GUI 좌측 하단 검색 요약 패널에 **표기**한다 (결과 중심: 전체 = 후보 쌍, 검증 = 중복 확정 쌍).

## 2. 기존 구조

- 요약 패널(좌측)은 총 파일 / 읽기 완료 / 인덱스 완료 / 그룹 / 중복 파일 / 시간 / GPU / CPU / RAM 행만 있었다. 쌍검증 투입량(`verifyCalls`)과 결과(`pairs`)는 상세 로그 JSON에만 있어 스캔이 끝나도 한눈에 안 보였다.
- 사용자 dataset 측정 기록은 `database-verification-benchmark` §7.1(0.9.4.92 콜드 스캔)까지만 있었다.

## 3. 변경 구조

- **요약 행 추가** (`gui/mainwindow.cpp`, `gui/mainwindow.h`): 중복 파일 행 다음에 `sumVerify_` / `sumValVerify_` 행. 라벨 `sumVerify`("쌍검증 (전체/확정)" / "Pair verify (total/confirmed)"), 값은 `"전체 / 확정"` (예: `19234 / 15193`), 기록 없으면 `-`.
- **데이터원**: `onDetailedLog()`에서 같은 텔레메트리 기록의 `matches.candidates` / `matches.pairs`를 `lastVerifyTotal_` / `lastVerifyDone_`에 파싱해 둔다. 다이얼로그 표시·저장과 무관하게 패널이 읽는다. 스캔/불러오기 시작 시 리셋된다.
- **완료 메시지는 손대지 않는다**: `finished` 문자열의 위치 파싱 규약을 유지한다.
- **측정 기록**: `docs/architecture/database-verification-benchmark.{ko,en}.md`에 §7.2(0.9.4.94 안정형 재스캔 예제: 177,581 중 80 변경, wall 980.6 s = walk 347 s + verify 592 s, DBV-1 유지, 지문 34 s, Fast 전환 권고) 추가. §7.3부터 고속형/자동 측정 기록을 같은 형식으로 추가한다.
- 번역키 `sumVerify` + `ui_translation_keys_test` 키 목록(63 keys).

## 4. 해결된 상황

- 스캔 완료 후 요약 패널에서 쌍검증 투입(후보 쌍)과 결과(확정 쌍)를 바로 확인한다. 기록이 없으면 `-`.
- 안정형 재스캔 비용 구조가 측정 기록 예제로 보존되었고, 설정별 후속 측정 자리가 마련되었다.

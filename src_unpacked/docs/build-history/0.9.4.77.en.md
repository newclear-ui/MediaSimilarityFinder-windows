# MediaSimilarityFinder v0.9.4.77 — Crash on filenames outside the ANSI code page, fixed

Baseline `0.9.4.76` → this build `0.9.4.77`.
CPU CTest **118/118**, GPU CTest **119/119**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged. No search-verdict change. No schema change.

## 1. Why the change was needed

- A real user scan (`G:\Downloads\ss_twit`, at 89%) died with a modal:
  `No mapping for the Unicode character exists in the target multi-byte code page.`
- That text is `filesystem_error::what()` thrown when MSVC reinterprets
  narrow `std::string` bytes as the ANSI code page on entry to
  `std::filesystem` (same family as the 0.9.4.47 `dataset_fingerprint` case).
- A full dataset survey found **1,778** of 273,169 filenames unmappable to
  CP949. The moment analysis reached one, the worker thread threw, travelled
  through the `ScanWorker` catch into `failed`, and surfaced as the modal.
  The ASCII filename on screen was only the last completed file, not the cause.
- The existing `unicode_path_test` used Korean names only, which CP949 covers,
  so it never caught this bug.

## 2. Previous structure

- The `path_from_utf8`/`path_to_utf8` rule existed, but narrow leftovers
  remained on the scan hot path. Passing narrow UTF-8 bytes straight in —
  `std::ifstream f(path)`, `file_size(path, ec)`, `p.extension().string()` —
  throws at the conversion step, before any `error_code` can help.
- Leftover sites: thumbnail quick-hash (`database.cpp`), the verify key block
  (`image_verify.cpp`), `quickIdentity` (`video_fingerprint.cpp`), the
  no-FFmpeg branch (`video_decoder.cpp`), and extension checks (`scanner.cpp`,
  `monitor.cpp`).

## 3. Changed structure

- All six sites now go through `path_from_utf8` / `path_to_utf8`. Open
  failures keep flowing into the existing `false`/skip paths and never throw.
- `unicode_path_test` gained an ACP-unmappable fixture (U+20000, CJK
  Extension B) covering walker discovery, grey-zone `verifyImagePair` decode,
  the thumbnail quick-hash roundtrip, and a full engine scan (2 analyzed +
  1 stored pair).
- No verdict/matching/scan semantic change. Failed files are still recorded
  as `analysis_failed` with the existing retry policy.

## 4. Resolved state

- Filenames outside ANSI no longer kill scans; they fail/skip per file.
- Thumbnail serving, verification, video identity, and extension checks all
  ride the wide path now.

## 6. Future impact

- Non-CP949 filenames are no longer scan blockers. `ffprobe` CLI children
  (`file_meta.cpp`, no-FFmpeg branch) parse paths in the system code page and
  may quietly miss unmappable names; they fail without dying, so that stays a
  separate follow-up.
- The next `0xC0000005` reproduction gets the fingerprint-0 frontier plus
  LocalDumps together.

# MediaSimilarityFinder v0.9.2.91 — 검색 벤치마크 로그(JSON)

## 변경 필요성
- 검색 성능을 비교·개선하려면 단계별 소요 시간, 파일당 디코드/해시 비용, 비디오 재생시간·용량당 스캔 시간, CPU/GPU 자원 활용의 실측이 필요했다.
- 완료·중단 시점에 사람이 읽는 요약과 기계가 파싱하는 원본을 함께 남겨야 했다.

## 기존 구조
- 단계별 타이머·자원 샘플러·결과 로그가 없었다. GPU 가동은 상태 표시용 플래그만 있었다.

## 변경 구조
- `src/benchmark.{h,cpp}` 신설: `BenchmarkRecorder`가 단계 시간(walk/revalidate/image/video/analyze),
  이미지별 디코드/해시/crop 시간+GPU 여부, 비디오별 빌드 시간+재생시간+프레임,
  250ms 자원 샘플(CPU 프로세스·시스템·메모리·GPU 플래그), slowest top-20, 매치 통계를 모아
  단일 JSON으로 직렬화한다. JSON은 의존성 없이 수작업 생성하며 경로는 이스케이프한다.
- `MediaPipeline::imageBatch`가 이미지별 시간을 기록하고, 엔진이 단계·비디오·리턴 경로마다
  확정한다(취소 포함 전 경로). `ScanControl`에 `revalidateMs`/`buildVersion`을 추가했다.
- GPU 활용율은 기존 `gpuActive_` 원자 플래그의 듀티사이클(가동 샘플 비율·최장 유휴)으로 산출한다.
  외부 의존성·프로세스 스폰이 없다.
- `ScanWorker::benchmarkReady` 신호 → `MainWindow::onBenchmark` 팝업: QJson 파싱 후 한/영 요약,
  JSON 저장 버튼(기본 `benchmark-<시각>.json`). 완료·중단 모두 표시, 실패 시 미표시.
- 버전 표기 통일 → 0.9.2.91, 테스트 59개(`benchmark_test`).

## 해결된 상황
- 이미지: 개수·용량·GPU/CPU 해시 수·디코드/해시 평균·GPU 배치 시간·느린 파일 20.
- 비디오: 개수·재생초·프레임·평균 빌드·재생분당 초·GB당 초·느린 파일 20.
- 자원: CPU 평균/최대/표준편차(널뛰기 지표)·시스템 평균·메모리 최대·GPU 듀티%·최장 유휴+원시 시계열.
- 요약 팝업은 slowest 5개까지, JSON은 20개 전체를 담는다.

# MediaSimilarityFinder v0.9.2.45 — 스캔 활동 로그 (0% CPU 원인 규명용)

## 변경 필요성
"CPU/GPU 0%에 디스크만 읽는다"는 보고에 대해 엔진 감사로 게이트·교착을 배제했다 (`expensiveStageGuard`는 모니터 전용, 스캔 워커에 미설정. `stopped()`·스레드 배선 정상). 남은 가설(23분 워킹/재스캔 스킵/특정 파일 정체) 중 어느 것인지 원격에서 판별할 방법이 없었다. 워커 재현 프로브(3000개, 641,358 매치)는 정상 동작을 확인했다.

## 기존 구조
스캔 중 UI 표시는 콜백 기반이라 콜백이 안 오면(워킹 단계·단일 파일 정체) 화면이 완전히 멈춰 보였다.

## 변경 구조
- UI 타이머(600ms)에서 스캔 중일 때 10초마다 heartbeat 기록: 경과·마지막 진척도·마지막 파일·그룹 수. 워커와 무관한 GUI 스레드 동작이라 정체와 크래시를 구분할 수 있다
- 스캔 시작/종료/실패를 `%TEMP%\msf_scan.log`에 기록 (append)
- 버전 표기 통일 → 0.9.2.45

## 해결된 상황
- 사용자가 로그 파일을 보내주면: heartbeat 정지=프로세스 교착/크래시, 동일 파일 장기 체류=병목 파일 특정, 카운터 증가=정상이지만 느림으로 판정 가능

## 검증
- Core Release 빌드 PASS, **CTest 39/39 PASS**, `--smoke` exit 0, `--version` 0.9.2.45

## 향후 영향
- 로그는 진단용으로 유지. 정체 파일이 특정되면 해당 파일 형식의 타임아웃/스킵 처리를 별도 버전에서 구현
- 참고 실측: 27만 파일 워킹 23분(초당 196파일). GPU는 배치 해시 특성상 상시 0%대에 보이는 게 정상 — `gpuImages` 카운터로 실제 사용 확인

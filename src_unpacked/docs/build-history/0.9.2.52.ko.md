# MediaSimilarityFinder v0.9.2.52 — 스캔 중 매치 점진 저장(이어하기 보장)

## 변경 필요성
v0.9.2.50의 매치 영속화(quick load)는 저장이 **스캔 종료 시 1회뿐**이었다. 스캔 중에 화면에 그룹이 보여도 DB에는 아직 없어서, 스캔 완료 전에 앱을 닫거나 강제종료·크래시·스캔 예외가 발생하면 그 스캔에서 찾은 결과가 전부 유실됐다. 특히 첫 스캔이 끝나기 전에 종료하면 DB가 빈 채로 남아, 다음에 같은 폴더를 재검색해도 이전에 확인된 동일 파일 목록이 복원되지 않았다. 사용자가 "못 끝낸 파일 작업 이어하기"를 하려면, 찾은 즉시 저장되는 구조가 필요했다.

## 기존 구조
- `ScanWorker::run()` 종료 직전에만 `engine_.saveMatches(allMatches_)` 1회 호출. `allMatches_` = quick load로 불러온 기존 쌍 + 이번 스캔의 신규 쌍
- 예외 경로(`catch`)에서는 저장 없이 `failed`만 emit → 실패한 스캔의 부분 결과도 유실
- `saveMatches`는 wholesale 교체(upsert + 저장 집합에 없는 행 DELETE)이므로, 부분 집합을 저장하면 기존 기록이 삭제되는 footgun 존재

## 변경 구조
- **스캔 중 점진 저장**: `control_.onMatch`에서 신규 매치 25개마다 + 마지막 저장 후 5초 경과 시 `persistMatchesSnapshot()` 호출. 저장 집합은 항상 전체 누적(`allMatches_`)이라 wholesale DELETE 의미론과 충돌 없음. 개수+시간 이중 스로틀로 수백만 매치 스캔도 느려지지 않음
- **`persistMatchesSnapshot()` 헬퍼**: `ScanWorker` 멤버. `allMatches_`→`SearchMatch` 벡터 변환 후 `engine_.saveMatches`. worker 스레드 전용이라 락 불필요 (`pending_` GUI 전달용 큐와 분리 유지). `onMatch`의 크리티컬 섹션도 `pending_` push로 축소
- **예외 경로 저장**: `catch`에서 스냅샷 저장 후 `failed` emit → 실패한 스캔의 부분 결과도 다음 스캔에서 quick load로 복원. DB 미오픈 시 `saveMatches`가 early-return이라 안전, 트랜잭션 ROLLBACK이라 부분 wipe 불가
- **주석 정정**: 기존 "keeps deleted files out of stored results"는 실제 동작(loaded 재저장)과 달라, union 의미론(디스크에 없는 파일의 쌍 포함 전부 보존)으로 명시
- 로드·그룹 경로에 존재 여부 필터링이 없음을 확인 — 누락 파일 쌍도 그대로 복원됨. mark 영속화는 요구사항에서 제외
- 버전 표기 통일 → 0.9.2.52

## 해결된 상황
- 스캔 중 언제 종료해도(정상·중단·실패·강제종료 직전 체크포인트까지) 그때까지 찾은 동일 파일 쌍이 DB에 남아 있음
- 같은 폴더 재검색 시 quick load로 이전 그룹 목록이 즉시 복원되어, 이전에 못 끝낸 파일 작업을 이어서 가능
- 저장 집합이 항상 전체 누적이라 wholesale DELETE가 기존 기록을 날리는 일 없음

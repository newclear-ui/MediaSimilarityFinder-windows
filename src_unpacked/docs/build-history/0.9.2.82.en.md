# MediaSimilarityFinder v0.9.2.82 — Portable Launch Fix (Qt Plugin Layout + Bundled CRT)

## Need for change
- The portable package failed at startup with `no Qt platform plugin could be initialized`.
- Two causes: (1) `windeployqt.exe` is absent from vcpkg, so only the script's manual fallback ran, copying plugins into a nested `Qt6\plugins` path Qt never searches. (2) VS 2026 toolchain output can mismatch older system CRTs on other PCs.

## Previous structure
- `package_portable.ps1` delegated to `windeployqt` when present, otherwise nested-copied `Qt6\plugins` into the package.
- No VC++ runtime was bundled.

## New structure
- Plugin category directories (`platforms/`, `styles/`, `imageformats/`, `iconengines/`, etc.) are copied to the package root. The executable directory is itself a plugin search path, so this matches the standard `windeployqt` layout. The nested `Qt6\plugins` copy is removed.
- `vcruntime140(dll/_1)`, `msvcp140(dll/_1/_2)`, and `concrt140` from the VS Redist `Microsoft.VC145.CRT` are bundled app-local. UCRT is inbox on Windows 10+, so it is excluded.
- No matching-logic or CUDA algorithm changes. Version strings unified → 0.9.2.82.

## Resolved situation
- The regenerated package launches with a minimal PATH and no `QT_PLUGIN_PATH`: `--smoke` and `--version` exit 0. No nested `Qt6` directory remains in the package.

## Validation
- Core+GUI Release build: PASS, **CTest 56/56 PASS**
- Portable launch validation: `--smoke` exit 0, `--version` exit 0 in a clean environment
- `MediaSimilarityFinder-v0.9.2.82-Portable-Windows-x64.zip` produced

## Future impact
- If vcpkg ever ships `windeployqt`, the script's delegation block runs, harmless alongside the manual layout.
- Other-PC requirements: Windows 10 or later. No separate VC++ Redistributable install needed (CRT bundled).

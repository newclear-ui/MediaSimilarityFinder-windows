# MediaSimilarityFinder v0.9.2.70 — Image False-Positive Second-Stage Gate

## Need for change
Report: two completely different photos matched at 85% similarity. Root cause confirmed: pHash keeps 8×8 low-frequency DCT only, and `bestMatch()` takes the max over dozens of full/mirror/crop variant pairs as a single gate. Two dark, smooth, warm photos coincide in low frequencies into Hamming D≤8 (87.5%). Images had no verification stage (no L2/L3 like videos), so it confirmed directly.

## Previous structure
- Candidate → `bestMatch()` max → immediate confirm on threshold. No structural check

## New structure
- **New `verifyImagePair`** (`src/image_verify.h/.cpp`): >=97 returns immediately with no decode (exact-duplicate UX, existing tests safe). Grey-zone pairs re-score 0.5·Hamming + 0.5·SSIM over full + center 4:3/1:1/9:16 regions (flipped included, max taken); below threshold they drop. Decode failures keep Hamming (legacy); videos pass through (temporal L2/L3 owns them)
- **Wired at 3 emit points**: `addAndMatch`, `analyze`, `compareFingerprint` (monitor path, only with a query path)
- `frame_ssim` relaxed to floor windows (covers 36px 9:16 regions). Existing w=0/null rejections kept
- New `image_verify_test` (7 deterministic cases: fast path, blend accept, false-positive cut, 2 fallbacks, video passthrough, empty path). Version strings unified → 0.9.2.70

## Resolved situation
- At scan threshold 87.5: H=90 pairs of different photos (SSIM≈0.2) fall to ~55 and drop; H=90 identical photos (SSIM≈1) hold at 95. The reported false-positive shape is caught at the gate
- Exact/mirror/center-crop true detections preserved via fast path/region SSIM

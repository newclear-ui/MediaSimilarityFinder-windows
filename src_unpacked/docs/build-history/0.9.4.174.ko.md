## 1. 변경 필요성

- 사용자 지시(장편 광고 삽입 판독 실험): 시작 0–300초 3초 그리드 관용 탐색(3-of-4, ≤1 스킵) + 엔딩-우선 래더(거꾸로 1·3·10분 9초 대조) + 중앙·엔딩 고정 대표 2-of-3 + 오프셋 정제(±10 지지율 argmax) + 길이 밴드 후보 선별(숏폼 90초 / 장편 1.2). V2의 고정 상수(3.5초 프로브 span, 2.5초 케이던스, 5초 풀)가 1초 샘플링 전용이라 성긴 그리드에서 전멸하는 현상을 측정으로 확인했고, 간격 비례 일반화로 해소했다.
- 측정 근거: `docs/field-reports/longform-ad-capture-efficiency.ko.md` / `.en.md` §5.3–§5.4, §11–§12 (25편 전체 3초 캡처 + 1초 밀집 구간, 합성 moving 30/90/180초 + 검은리더, 동일 20쌍 + 교차 240쌍).
- V3는 V1/V2와 별도 오케스트레이션이다. V1·V2 함수 본문은 손대지 않는다.

## 2. 기존 구조

## 3. 변경 구조

- 신규 모듈 함수 (`src/temporal_anchor.{h,cpp}`, msf_core, V1/V2 동결):
  `anchorBandPass()` (숏폼 abs≤90초 / 장편 비율≤1.2),
  `orderedSearchTol()` (선두 need+skip 프레임 중 need 일치, ≤skip 스킵, 케이던스 상한),
  `refineOffsetBySupport()` (대표 지지율 ±10 argmax, 동점 최근접),
  `temporalAnchorSimilarityV3()` (밴드 게이트 → 관용 시작 탐색 → 엔딩-우선 탐색(끝 1200초) → 정제 → 거꾸로/중앙 래더 + 고정 대표 2-of-3 → DUP/UNCERTAIN/miss).
- 판정: DUP는 밴드 통과 + 엔딩 발견 + 거꾸로 래더≥2 + 중앙 래더≥2 + 고정 대표≥2 + 오프셋 일관 + score≥87.5를 모두 만족할 때만 (점수는 V2와 동일 매핑 `anchorVerdictScore` 재사용).
  엔딩만 있으면 UNCERTAIN, 근거 없으면 miss. 박약·어두움 입력은 UNCERTAIN으로 상한 (V2와 동일).
- 제품 연결: `VideoReadStrategy::TemporalAnchorV3 = 3`, GUI 콤보 index 3 + tr 키 1종,
  QSettings/IPC/backend 매핑 확장, `anchorStrategyId()=3`, ScanPipeline 훅에 strat==3 분기 (합산 텔레메트리만).
  armed 조건(`!= LegacyV3`)은 그대로라 union sweep·메모리 인덱스를 공유하고, disarmed 빌드는 바이트 동일.
- 테스트: `tests/video_temporal_anchor_v3_test.cpp` (합성 전용 7핀: 밴드 경계, 3-of-4 허용/2미스 거부, 정제 수렴, 엔딩-우선 DUP, 어두움 UNCERTAIN, 타작품 비DUP).

## 7. CI 재현성과 테스트 환경 대응 (GitHub Actions, 2026-11-20 → 11-22)

제품 판정·엔진·DB·스키마·캐시 버전은 **불변**이다. 이 절은 빌드/테스트 인프라 변경만 기록한다.

### 7.1 변경 필요성

- CPU/CUDA GitHub Actions 워크플로를 green으로 만드는 과정에서, 초기 실패는 제품 결함이 아니라
  **러너 이미지 드리프트 + vcpkg ffmpeg 기능 축소**였다.
- 임시 대응으로 환경 의존 테스트 4건을 `-CTestExclude`로 빼 두었는데, 그러면 스위트가 green이어도 그 4건은
  **아무도 검증하지 않는 상태**가 된다. 회귀 감시 구멍을 남기지 않도록 테스트가 스스로 판정하게 고쳤다.

### 7.2 기존 구조 (실측 실패 원인)

| 테스트 | 관측 메시지 | 원인 |
|---|---|---|
| `image_dim_test` | `Default encoder for format image2 (codec png) is probably disabled` | vcpkg ffmpeg에 PNG 인코더 없음 |
| `video_reencode_test` | `Unrecognized option 'crf'` | vcpkg ffmpeg에 libx264 없음 |
| `video_scan_e2e_test` | `Unrecognized option 'crf'` | 동일 |
| `reveal_window_test` | `fallback_open=FAIL`, `reuse_window=FAIL windows=1->1` | **2단계 원인**: ① 8.3 단축 경로 vs 긴 경로 문자열 비교 ② 정규화 후에도 러너 세션이 셸 **선택(selection)을 보고하지 않음** |

`reveal_window_test`는 처음에 "러너에 상호작용 Explorer 셸이 없다"로 판단했지만 **틀렸다**.
`windows=1->1`(A 단계에서 창 1개가 열리고 B 단계가 같은 창을 재사용)은 셸이 동작했다는 증거였다.
경로 정규화 후 진단 덤프가 원인을 확정했다 — 대상 폴더까지 **정확히 일치**하는데 뷰의 선택이 비어 있었다.

부수 원인:

- 러너 이미지 `20261103`(MSVC 14.51) → `20261116`(MSVC 14.52) 갱신으로 dav1d 1.5.4 빌드 실패
  (`include/compat/msvc/stdatomic.h`의 `__has_include_next`).
- vcpkg `builtin-baseline` 미고정 → 러너가 해석한 시점에 따라 의존성 버전이 흔들림.

### 7.3 변경 구조

- 네 테스트가 스스로 판정한다.
  - `image_dim_test`: PNG 픽스처를 **프로세스 안에서 조립**(시그니처 + IHDR + IEND, CRC-32). 이 프로브는 IHDR만
    파싱하므로 인코더가 필요 없다. JPEG 픽스처는 `-c:v mjpeg`를 명시. ffmpeg이 PATH에 없으면 exit 77.
  - `video_reencode_test`, `video_scan_e2e_test`: 재인코딩을 `-c:v mpeg2video -q:v 10`(+ scale)으로 바꾸고
    원본은 MPEG-4 유지 — 여전히 서로 다른 코덱이며 이 ffmpeg에 내장된 조합이다.
  - `reveal_window_test`: 세 층으로 나눴다.
    ① 탐색기 창 URL과 목표 폴더를 **정규화된 긴 경로**로 비교(`QFileInfo::canonicalFilePath`) — 8.3 단축명 해소.
    ② 실패 시 열린 셸 창 URL·대상 경로·선택 개수를 덤프.
    ③ 선택 판정이 실패하면 **제품 코드를 거치지 않는 대조 실험**(`explorer.exe /select,<control>`)을 먼저 돌린다.
       대조도 선택을 보고하지 못하면 `reveal_window=skipped (no interactive desktop selection)` exit 77,
       대조는 성공하는데 제품만 실패하면 **제품 회귀**로 보고 실패시킨다.
    `GetProcessWindowStation` 가시성 + `GetShellWindow()` 가드는 셸 자체가 없는 세션용으로 유지.
  - CMake: 네 테스트에 `SKIP_RETURN_CODE 77` → CTest가 `Skipped`로 집계한다(조용한 통과 아님).
- 워크플로: `-CTestExclude` 제거, 두 워크플로 모두 전체 스위트 실행.
- 재현성: `builtin-baseline` 고정(`afa249f12f`), Release 전용 overlay triplet, MSVC 19.52용 dav1d overlay 패치,
  바이너리 캐시(`vcpkg-v3` 345 MB + CUDA 29 MB), `-BuildParallelism 4`, `timeout-minutes: 240`.

### 7.4 해결된 상황

- CI가 전체 스위트를 실행한다. 네 테스트는 실제 수행되거나, 이유를 stdout에 남기고 `Skipped`가 된다.

### 7.6 향후 영향 및 한계

- `Skipped`는 검증이 아니다. CI green은 "실행 또는 정직한 skip"을 뜻하며, 네 건이 모두 수행됐다는 뜻이 아니다.
- `reveal_window_test`는 실제 상호작용 데스크톱(로컬 acceptance)에서만 수행된다 — 의도된 제약이다.
- 픽스처 **생성 방식**만 바뀌었고 단정은 그대로이므로, 실제 회귀는 여전히 실패한다.
- **트리거 정책: 수동(`workflow_dispatch`) 유지** (사용자 결정, 2026-11-22). push/PR 자동 실행은 비용 대비 효과를 보고 필요 시 추가한다.

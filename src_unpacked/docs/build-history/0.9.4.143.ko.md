# MediaSimilarityFinder v0.9.4.143 — 변경된 파일의 이전 쌍 제거 + 변경 스캔 후 인덱스 자동 재적용 + 최근 폴더 개수 설정

기준선 `0.9.4.142` → 본 빌드 `0.9.4.143`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.
단, **판정 결과의 저장 정합성**을 고치는 수정이므로 표시 전용이 아니다(스키마·프로토콜 불변, 엔진 버전 불변).

## 1. 변경 필요성

- 실기(S-4): 두 파일을 같은 그룹으로 확인한 뒤, 한 파일을 삭제하고 **이름은 같고 크기가 매우 비슷한 다른 이미지**로 교체했다. 빠른 검색(Fast/A)에서는 이전 그룹이 그대로 유지되어 서로 다른 파일을 같은 그룹으로 표시했고, Test Mode(새 스크래치 인덱스)에서는 정상 판정 + 인덱스 갱신 안내가 나왔다.
- 원인: 스캔이 저장된 쌍(quick-load)과 새로 찾은 쌍을 합쳐 **전부 다시 저장**했기 때문에, 재분석된 파일의 **더 이상 유효하지 않은 이전 쌍이 삭제되지 않았다.** Test Mode는 빈 인덱스에서 분석하므로 정상이었다.
- 추가 요청: 왼쪽 즐겨찾기의 최근 폴더가 2개까지만 표시됨. 기본 3개, 설정에서 1~20개까지 조절 가능하게.

## 2. 기존 구조

- `ScanWorker`가 quick-load한 저장 쌍과 스캔 중 방출된 쌍을 `allMatches_` 하나에 모아 `saveMatches()`로 통째 저장했다. 저장 함수는 "저장 집합에 없는 행"을 삭제하지만, **저장 집합 자체가 이전 쌍을 포함**하고 있었다.
- GUI의 union-find(`pathParent_`)도 스캔 시작 quick-load로 이전 쌍을 받아 유지하며, 스캔 결과 적용은 추가만 하므로 화면에도 이전 그룹이 남았다.
- 최근 폴더는 `beginScan`에서 `while (recent.size() > 2)`로 고정 2개만 유지했다.

## 3. 변경 구조

- **엔진**: `ScanControl::onChangedFile` 콜백 추가. 재분석(신규/수정/보류/재그리드) 대상 경로가 결정되는 즉시 워커에 전달한다.
- **워커**: 저장 쌍(`storedPairs_`)과 이번 스캔 방출분을 분리(`storedCount_` = 저장 접두 길이). 저장 시:
  - 재분석된 경로를 포함하는 **저장 쌍은 제외**,
  - 이번 스캔이 방출한 쌍은 모두 유지(중복 키는 방출분 우선).
  - 체크포인트와 최종 저장 모두 같은 집합을 사용하고, 상세 로그 카운터도 같은 집합을 센다.
- **GUI**: 결과 세트가 화면에 있는 상태에서 시작한 스캔이 재분석을 수행하면(`analyzed>0`, Test Mode 제외), 완료 후 **저장된 인덱스를 조용히 다시 읽어** 목록/미리보기를 재구성한다.
  - 스캔의 요약·상태(analyzed/unchanged/verify)를 유지하고, 정렬·선택(대표 경로/선택 파일)을 복원한다.
  - 로딩 팝업은 띄우지 않는다(`silentReload_`). 변경이 없는 스캔(analyzed=0)은 기존처럼 화면을 그대로 둔다.
- **최근 폴더**: `ui/recentFolderLimit`(기본 3, 범위 1~20) 추가. `beginScan`의 MRU 유지 개수가 이 값을 따르고, 설정 저장 시 기존 목록도 즉시 잘라내며 즐겨찾기를 갱신한다. 설정 → 일반에 "최근 폴더 표시 개수" 스핀박스 추가.

## 4. 해결된 상황

- 한 파일을 교체한 뒤 빠른 검색을 해도 이전 그룹이 남지 않는다. DB와 화면 모두 새 판정으로 갱신된다.
- Test Mode와 일반 스캔의 판정/인덱스 결과가 일치한다(스키마·프로토콜 불변).
- 즐겨찾기 최근 폴더를 기본 3개, 최대 20개까지 사용자가 설정할 수 있다.

## 6. 향후 영향 및 한계

- 스키마/프로토콜/엔진 버전 불변. DB에는 더 이상 유효하지 않은 쌍이 남지 않는다.
- 변경이 있는 스캔은 완료 후 저장 세트를 한 번 더 읽으므로 결과가 큰 데이터셋에서는 완료 시간이 약간 늘어난다(변경 없는 스캔은 영향 없음).
- Test Mode는 재적용 대상에서 제외한다(스크래치 인덱스 결과를 화면에 유지하고, 채택 여부는 기존 Yes/No가 결정).
- 최근 폴더 수를 줄이면 기존 목록은 즉시 줄어들고, 늘리면 이후 스캔부터 채워진다.

# MediaSimilarityFinder v0.9.4.10 — Node C2: Initial Calibration

Validation baseline for C2: short calibration when no profile exists or
none is reusable, activating writer, telemetry, and initial estimates.
Engine 1.5.0, DB 1.0.3, cache v9 unchanged; benchmark schema 1 → 2.

## Why the change was needed
- Through C1 the store, verdicts, and delivery API existed, but with no
  writer the live path stayed dormant. Without a first calibration the
  profile baseline would stay empty forever.

## Previous structure
- `CalibrationTelemetry` was structure only; the scheduler had only the
  `profileBaseline*` input fields.

## New structure
- New `src/calibration.h/.cpp` — `Calibrator::run(cfg, GpuBackend*)`:
  - CPU fingerprint: 300 synthetic 32x32 frames through the same
    `perceptual_hash_pair_32` the engine uses (single-thread clean unit;
    parallel scaling is worker topology, out of scope).
  - GPU fingerprint + batch: 64×6 batches plus one discarded warmup.
    Mirrors stay CPU-side in the engine, so only the `hashBatch` rate is
    claimed.
  - resize/conversion, CPU decode, transfer, queue, HW decode carry
    explicit states (not_measured/not_available). No user files scanned
    (deterministic synthetic input), per-phase budgets, 8 s total guard.
    Exceptions and failures never reach the scan.
- Probe rationale: 300 CPU + 64×6 GPU units run in ~0.1 s wall, far under
  the 8 s budget; the headroom absorbs slow machines.
- Confidence 0.8/0.5 (full/partial): conservative for a single run with
  no history. Live always wins, so over-trust is impossible.
- Engine: Missing/Hard verdicts run one calibration → writer saves →
  the estimate applies to the same scan. Writer failures ignored.
  Exact/Soft reuse without re-measuring (drift is C3's domain). The
  `videoGpu_` handle separates policy-off from no-device.
- Telemetry initial capacities use the profile tier (`baseCapacities()`
  helper) so a profile-fed scan reports profile numbers, not
  thread/SM counts.
- Schema v2: six calibration metric states added.

## Why this shape
- CPU decode is unmeasurable pre-walk (streaming walk/analysis leaves no
  file set; C3+ opportunistic candidate, documented). Resize is
  decoder-internal. Transfer has no kernel split (B5 finding). Estimating
  unmeasurable items is forbidden.
- CPU-only completes; GPU-off measures CPU then stays partial.
  Policy-off reads not_measured, no-device reads not_available.

## Resolved state
- First profiles are created and scheduler initial estimates are live.

## Accuracy impact
- None. Calibration and writer failures never reach scans. Identical
  `scan_workflow_test` on both trees; parity suites green.

## Compatibility impact
- Benchmark JSON additive extension (schema 2). Existing keys kept.

## Validation
- CPU Release build PASS, **CTest 66/66 PASS** (new `calibration_test`:
  CPU-only completion, reload Exact, partial, GPU policy/off, telemetry).
- GPU Release build PASS, **CTest 67/67 PASS** (real-device GPU
  measurement included).
- Scheduler precedence assertion added (live > profile).
- `--version` 0.9.4.10 and `--smoke` PASS on both.

## Future impact
- C3 needs a drift detector plus writer reuse. Resize/decode baselines
  need an opportunistic design. Measured bandwidth stays unresolved (C3
  blocker candidate).

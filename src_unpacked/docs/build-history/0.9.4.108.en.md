# MediaSimilarityFinder v0.9.4.108 — Detailed-log summary header (search method + folder)

Baseline `0.9.4.107` -> this build `0.9.4.108`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why the change was needed

User request: the detailed-log summary must state the **matching-verification mode (Stable/Fast/Auto = B/A/AB)** at the very top, and the **scanned folder path** as the second item — so the user never has to record the mode by hand.

Trigger: the 0.9.4.107 field run (`detailed-log-2026-10-16T041623.json`) was requested as Auto (AB) but its `analyze.mode` recorded **A (Fast)**. The summary showed the mode nowhere, so the user had no way to notice — the display gap was confirmed by measurement.

## 2. Previous structure

- `showDetailedLogDialog` (gui/mainwindow.cpp) parsed the telemetry JSON and built the `== 검색 요약 ==` block, but neither the mode (`analyze.mode`) nor the folder (`meta.root`) was displayed.
- The mode existed only in the Settings combo labels (`analyzeModeStable/Fast/Auto`); logs/reports had none.

## 3. New structure

- Two rows added right after the summary header:
  - `Search method: <Stable (verify after scan) | Fast (verify during scan) | Auto (hybrid)>` — the value maps the **record's `analyze.mode` (B/A/AB)** to the existing translation labels. It comes from the record, not the current settings, so an old log always shows its own mode; older records without the field show `-`.
  - `Search folder: <meta.root>` — the record's scan root; `-` when absent.
- Two translation keys added (`summaryMode`/`summaryFolder`), tr-keys **71 -> 73**; registered in the `ui_settings_test` key list.
- Display-only — verdicts, storage and protocol unchanged.

## 4. Resolved state

- The summary alone now tells which matching-verification mode produced a run (no hand annotation). The real-world "requested Auto, recorded Fast" mismatch becomes immediately visible on screen.
- The scanned folder path stays in the summary, so logs identify their source when several folders are in use.

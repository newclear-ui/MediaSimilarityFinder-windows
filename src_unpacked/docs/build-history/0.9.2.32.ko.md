# 0.9.2.32 — 대용량 Match 결과용 compact index streaming callback

## 중요 변경
**IMPORTANT:** 대량 검색 결과에서 매치마다 좌/우 전체 경로 문자열을 새로 구성하지 않아도 되도록 `SearchMatchRef` 기반 스트리밍 경로를 추가했다.

## 변경 필요성
0.9.2.31에서 전체 결과의 무제한 보관을 피하고 스트리밍 콜백을 도입했지만, 기존 `onMatch`는 `std::string` 경로를 포함한 `SearchMatch`를 전달한다. 수십만~수백만 결과에서는 동일한 파일 경로가 반복적으로 복사/할당될 수 있다. 향후 GUI 가상화 모델이 결과를 페이지 단위로 소비할 때 불필요한 문자열 생성 비용을 줄일 필요가 있었다.

## 이전 구조
`ScanPipeline`이 매치를 생성하면 `MediaSearchEngine`이 두 경로 문자열을 만들어 `SearchMatch`를 스트리밍하거나 `SearchReport.matches`에 저장했다.

## 새 구조
`ScanControl::onMatchRef`를 추가하고 `SearchMatchRef { leftIndex, rightIndex, percent }`를 전달한다. 인덱스는 해당 스캔 시점의 `MediaSearchEngine::files()`를 참조한다. 기존 `onMatch`와 `SearchReport.matches`는 그대로 유지한다.

## 선택 이유
경로 문자열은 파일 목록에서 이미 한 번 보관되고 있다. 결과마다 경로를 복제하는 대신 작은 정수 인덱스 두 개와 유사도만 전달하면 대용량 결과 소비자가 직접 파일 목록을 참조할 수 있다. 기존 API를 제거하지 않아 호환성을 유지한다.

## 해결된 상황
향후 Qt `QAbstractListModel/QTableView` 기반 가상화 결과 모델은 전체 경로 문자열을 매치마다 복제하지 않고 compact reference만 받아 필요한 행을 표시할 수 있는 기반을 확보했다. `retainMatches=false`와 함께 사용하면 전체 결과를 `SearchReport`에 저장하지 않는 기존 메모리 절약 경로도 유지된다.

## 정확성/호환성
매치 인덱스와 percent는 기존 `MediaMatch`와 동일한 값을 전달한다. 기존 `onMatch`, `SearchReport.matches`, CandidateIndex 및 SimilarityEngine 동작은 변경하지 않았다.

## 검증
- `search_report_test`: 기존 string callback + compact callback 인덱스 유효성 검증
- 전체 CTest: 36개 테스트 예상/실행
- Core Release build 수행

## 향후 영향
다음 단계에서 GUI 결과를 `SearchMatchRef` 기반으로 연결하고 페이지/가상화 표시를 구현할 수 있다. 필요 시 이후에는 compact 결과를 DB에 직접 저장하는 구조로 확장할 수 있다.

## Windows 공통 호환성 반영 — CUDA/CPU 공통 기준

Windows CPU 테스트에서 확인된 플랫폼 공통 문제를 CUDA 코드와 분리하여 공통 소스에 반영하였다. CUDA backend 알고리즘과 CUDA 메모리/커널 경로는 변경하지 않았다.

- SQLite vcpkg의 `unofficial-sqlite3` CMake 패키지 대응
- Windows Qt/WIC 및 `NOMINMAX` 호환성
- MSVC에서 `M_PI` 대신 C++20 `std::numbers::pi` 사용
- FFmpeg 9 `av_find_best_stream()` 호출 호환성
- `SystemLoadMonitor` 상태 멤버의 올바른 클래스 배치
- Windows UTF-8 filesystem 경계 통합
- `ReadDirectoryChangesW` overflow/resync 및 버퍼 경계 검증
- StableFileDetector 성공 후 상태 정리
- MSVC 테스트의 `std::popcount` 전환
- Windows SDK의 `SystemLoad` 심볼 충돌 회피
- Visual Studio 18 2026 CUDA 빌드 스크립트 및 프로젝트-local vcpkg 사용

이 공통 수정판은 공식 `0.9.2.32` 기준선을 덮어쓰지 않으며, CUDA/Windows 검증을 위한 다음 작업 기준판으로 `0.9.2.34`를 사용한다.

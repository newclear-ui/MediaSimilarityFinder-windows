# MediaSimilarityFinder v0.9.3.10 — Group-List Scroll Anchor Restoration

## Need for change
- During thumbnail catch-up and streaming refresh, rebuilding all group widgets could restore the selected group and repeatedly move a list scrolled down by the user back to group 1.

## Previous structure
- `fillPair()` saved only the pixel scrollbar value.
- While rebuilding, `setCurrentItem()` moved the viewport to the selected group before the old pixel offset was restored.
- Applying the offset before Qt completed item layout could cause it to be clamped again.

## New structure
- The group ID at the top of the tree/grid viewport is captured before rebuilding.
- After rebuilding, the same anchor group is restored with `PositionAtTop`, independently of selected-item restoration.
- The old pixel offset remains a fallback for an initial or empty viewport with no anchor.

## Resolved situation
- A list scrolled down no longer repeatedly jumps back to group 1 during catch-up refresh.
- The existing full-rebuild structure for search, sorting, and thumbnail refresh remains unchanged.

## Validation
- GUI target and thumbnail/UI regression targets Release build: PASS.
- No long-running automated real-list scroll test exists yet.

## Future impact
- If item-level icon updates later remove full rebuilds, this anchor correction remains a safe fallback.

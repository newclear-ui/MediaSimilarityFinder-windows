# MediaSimilarityFinder v0.9.2.79 — 기존 탐색기 창 재사용 + GPU 상태 3종 표기

## 변경 필요성
1. "탐색기에서 보기"가 `explorer.exe /select`로 새 창을 띄우면서 파일이 실제로 선택되지 않는 경우가 있었다. 이미 그 폴더가 열려 있는 창이 있으면 그 창에서 파일을 찾아야 한다.
2. 검색 요약의 "GPU 가속" 값이 항상 "GPU 가동"으로만 표시돼, 실제 가속 중인지·정지인지·CPU 구간 대기인지 구분되지 않았다.

## 기존 구조
- `revealSelected()`와 모니터 알림의 "탐색기에서 보기" 모두 `QProcess::startDetached("explorer.exe", /select, …)`로 새 프로세스/새 창을 발사
- 요약 GPU 행은 가속 조건일 때만 표시되고 값은 `GPU 가동` 고정. 일시정지·CPU-only 구간과의 구분 불가

## 변경 구조
- **기존 창 재사용**: `IShellWindows`로 열린 탐색기 창을 열거하고, 각 창의 `IPersistFolder2::GetCurFolder`(실패 시 `IWebBrowser2::LocationURL`)로 폴더 경로를 읽어 파일의 상위 폴더와 일치하는 창을 찾음
- **창 내 선택**: 일치 창을 최전면으로 가져온 뒤 `IFolderView`의 폴더 PIDL + `SHGetIDListFromObject(파일)`로 만든 자식 PIDL을 `IShellView::SelectItem`으로 선택. 새 창 발사 없음
- **결과 표시**: 선택 성공=무음(구버전과 동일), 창만 가져옴=파일 선택 실패 메시지, 일치 창 없음=창 없음 메시지, 파일/COM 실패=일반 실패 메시지 (ko/en 3종 키 추가)
- **GPU 3상태**: 엔진에 `gpuActive` 원자 플래그 추가 — `MediaPipeline::imageBatch`가 CUDA `hashBatch` 호출 구간에서만 true(실패 시 즉시 false, RAII 가드로 항상 해제). GUI는 `가속 중`(실제 배치 진행) / `정지`(일시정지) / `대기`(목록 작성·변경 없는 파일·영상 FFmpeg·최종 쌍 분석·GPU 꺼짐/CUDA 없음·검색 전후)로 표시
- 요약 GPU 행은 항상 표시되도록 변경(가속 중일 때만 숨기던 동작 제거)
- `media_pipeline_batch_test`에 activity 플래그 해제 검증, `search_engine_test`에 스캔 종료 후 `gpuActive()==false` 검증 추가
- 버전 표기 통일 → 0.9.2.79

## 해결된 상황
- 폴더가 미리 열려 있으면 새 창 없이 그 창에서 파일이 선택되고 포커스됨
- 검색 중 GPU 값으로 "지금 가속 중인지 / 일시정지(정지)인지 / GPU가 필요 없는 작업(대기)인지"를 구분해 볼 수 있음

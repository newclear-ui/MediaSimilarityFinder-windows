# MediaSimilarityFinder v0.9.2.59 — Blank Pane Recurrence Fix (List-Rebuild Livelock)

## Need for change
After v0.9.2.58 (placeholder cache), an 11k-group scan still showed a blank middle pane. Data existed (status bar 11084) and the scrollbar proved layout ran, but nothing painted. Deep analysis: rebuilding all 11k widgets every 600ms tick exceeded the interval, so timer timeouts backlogged behind each slow tick and the next tick always ran before the previous tick's paints — a livelock. Pause clicks were trapped behind the backlog too.

## Previous structure
- Every 600ms `uiTimer`, when dirty: full `rebuildGroups→refreshGroupList→refreshFileViews`. At 11k groups the widget churn + layout alone approaches a second
- While paused the worker emits nothing, so pre-pause matches sat undrained in `pending_`; the timer never drained, leaving paused views incomplete
- No headless regression test for the worker streaming→persistence path

## New structure
- **Adaptive refresh throttle** (`refreshStreaming()`): full list fills limited to 3× measured cost (600ms..3s). Counts stay live every tick; only heavy fills are spaced. Pause/finish/tab-switch/sort/search still refresh immediately
- **Signature skip**: fill skipped when `matchSeq_` matches the last fill (counts only). No redundant rebuilds of identical content
- **Timer drain**: each tick `drainMatches()` recovers pre-pause leftovers. Pause toggle drains immediately + marks dirty for a complete view within one tick
- **Worker regression test** (`scan_streaming_test`): real scan over 4 identical BMPs → `streamed=6 stored=6`. Proves streaming and quick-load persistence headlessly
- Version strings unified → 0.9.2.59

## Resolved situation
- Per-tick work stays capped at 11k scale, so paints, pause, and stop always get through. The group list renders and updates live every few seconds
- Stopping keeps every pair found so far in the DB; the next rescan quick-loads them (guaranteed by test)
- Paused views are complete up to the pause point

## ⚠ 중요 업데이트 예정: 실시간 미디어 중복 감시

다음 개발 묶음부터 기존 검색엔진/SQLite Index/fingerprint/Candidate Index를 기반으로 **메모리 상주형 실시간 중복 감시 기능**을 설계하고 구현한다.

### 목적

지정한 여러 드라이브/폴더를 감시하고 새 미디어 파일의 저장이 완료되면 기존 Index와 대조하여 동일 또는 높은 유사도 가능성이 있는 파일의 위치와 유사도를 사용자에게 보고한다.

### 핵심 방향

1. 파일 시스템 이벤트를 우선 활용하되, 복사/다운로드 중인 파일을 즉시 분석하지 않는다.
2. 파일 크기/쓰기 상태가 안정된 것을 확인한 뒤 분석한다.
3. 감시 대상과 비교 대상 Index를 여러 드라이브/폴더 단위로 지정할 수 있게 한다.
4. 기존 검색엔진과 DB를 재사용하여 별도의 중복 검색 엔진을 만들지 않는다.
5. 새 파일의 fingerprint 생성 → Candidate Index 후보 검색 → 정밀 similarity 비교 → 사용자 보고 순으로 처리한다.
6. DB와 Candidate Index는 파일 추가/변경/삭제에 맞춰 상시 갱신한다.

### ⚠ 최우선 설계 원칙: 시스템 부하 보호

실시간 감시는 **사용자 작업에 영향을 주지 않는 것이 성능보다 우선**이다.

- 게임 실행 중, 대규모 인코딩/렌더링 중, CPU/GPU 과부하 작업 중에도 감시 기능 때문에 시스템 부하가 급격히 상승하지 않아야 한다.
- 고정된 CPU/GPU 사용률만 사용하는 방식이 아니라 현재 시스템 부하를 지속적으로 관찰한다.
- CPU/GPU/메모리/IO 상태를 기준으로 작업량과 처리 빈도를 능동적으로 낮추거나 일시 정지한다.
- 여유 자원이 확보되었을 때만 분석 속도를 높인다.
- 시스템 부하가 높아지면 즉시 background analysis를 throttle/pause하고, 필요한 경우 파일 분석을 큐에 남긴다.
- 사용자에게는 분석 완료 여부와 함께 과부하 회피로 인한 지연도 명확하게 보고할 수 있어야 한다.

### 사용자 인터페이스 방향

새 파일과 기존 파일을 한 팝업에서 좌우 비교한다.

- 왼쪽: 새로 저장된 파일 미리보기
- 오른쪽: 기존 파일 미리보기
- 파일명 / 전체 경로 / 드라이브 / 크기 / 유사도 표시
- 클릭 시 Windows Explorer에서 해당 파일 위치 표시
- 새 파일을 휴지통으로 보내기
- 기존 파일을 휴지통으로 보내기
- Skip으로 이번 판단을 무시
- 동일 파일이 여러 위치에 존재하면 여러 후보를 표시

### 상주 방식

Windows 시스템 트레이에서 백그라운드로 동작하는 Monitor 모드를 고려한다. 메인 검색 기능과 실시간 감시 기능은 공통 Core/Index/Search Engine을 사용하도록 설계한다.

### 기록 원칙

이번 기능은 단순 기능 추가가 아니라 **검색엔진 사용 방식과 실행 모델을 확장하는 중요 설계 변경**으로 취급한다. 구현 과정에서 실제 구조가 확정되면 별도의 architecture 문서를 갱신한다.

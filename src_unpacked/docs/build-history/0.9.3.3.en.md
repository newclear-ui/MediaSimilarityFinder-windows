# MediaSimilarityFinder v0.9.3.3 — Progressive Group Thumbnails

## Need for change
- Only the first few groups showed thumbnails; later groups stayed file icons.
  Three stacked causes:
  1. `fillPair` attempted real thumbnails only for the first 60 rows mid-scan and
     hardcoded placeholders for the rest.
  2. The per-tick decode budget (4 heavy + 24 shell) can't cover a whole fill, yet
     after scan end only one fill ran, leaving over-budget rows as permanent placeholders.
  3. Transient mid-scan decode failures (file busy, etc.) were permanently recorded
     in `thumbFail_`, so later ticks never retried them.

## Previous structure
- 60-row cap + permanent mid-scan failure blacklist + single post-scan fill.

## New structure
- The 60-row cap is gone. Every row goes through `fileThumb`; budget exhaustion
  returns a placeholder without caching failure. Cache and disk-thumb hits cost no
  budget, so rows fill progressively across ticks. Per-fill work stays capped by the
  budget, preserving responsiveness.
- Mid-scan decode failures skip the blacklist and retry on later ticks (only
  post-scan failures are recorded).
- Budget exhaustion is tracked via `thumbStarved_`. While idle (after scan end), up
  to 12 catch-up fills run, one per tick. New matches reset the counter.
- Version strings unified → 0.9.3.3.

## Resolved situation
- Thumbnails attach progressively starting with newly arrived groups, even mid-scan.
- Leftover placeholders after scan end fill in automatically on idle ticks.

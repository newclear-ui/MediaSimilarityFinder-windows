# MediaSimilarityFinder v0.9.4.127 — Test Mode XMP 회귀 테스트 (실파이프라인 판정 검증)

기준선 `0.9.4.126` → 본 빌드 `0.9.4.127`.
CPU CTest **125/125**, GPU CTest **126/126** (신규 `test_mode_xmp_test` 1건 추가).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

- XMP 증거는 decode 수준까지만 닫혀 있었다. `xmp_orientation_test` 38 checks와 실파일 probe 23 checks는 transform 적용을 입증하지만, fallback이 실제 스캔 파이프라인에서 판정(pair/group)을 바꾸는지는 검증되지 않았다.
- Test Mode 격리 스캔은 `test_mode_test`가 4 BMP로만 검증했다. XMP bearing 실파일 성격(충돌·무효·EXIF 우선)의 Test Mode 회귀가 없었다.

## 2. 기존 구조

- `test_mode_test`: 4 동일 BMP로 생산 1회 + warm 1회 + Test Mode 1회를 실행하고 counts와 생산 index 바이트 불변을 단언한다. XMP 메타데이터가 없는 픽스처라 orientation 분기가 실행되지 않는다.

## 3. 변경 구조

- 신규 `tests/test_mode_xmp_test.cpp` (Windows 전용, 비Windows SKIP): WIC 인코딩 1회 + APP1 splicing으로 5 JPEG 생성 후 생산 스캔 1회 + Test Mode 스캔 1회.
  - a1/a2: EXIF 없음 + XMP=1 (동일 → pair, control)
  - b1: EXIF 없음 + XMP=6 (90CW → a와 무관)
  - c1: EXIF=6 + XMP=1 (EXIF 우선 → 90CW → a와 무관)
  - d1: EXIF 없음 + XMP=banana (무효 → identity → a와 pair)
  - `matchesBatch(LiveMatch)` 수집으로 pair verdict를 문자열 파싱 없이 단언한다.
- 판정 계약: a1-a2 pair 존재, b1-c1 pair 존재(서로 다른 source의 동일 회전 — end-to-end byte 동등성의 증거), rotated↔flat 교차 pair 없음, d1-a pair 존재, Test Mode verdict == 생산 verdict, 생산 index 3종 바이트 불변, scratch 내 index 생성.
- 구현 중 발견·수정(테스트 버그 2건, 제품 코드 무관):
  - APP1을 SOI 직후에 삽입했더니 WIC가 EXIF/XMP를 resolve하지 않아 전부 identity로 pair됐다. 카메라 순서(SOI + 선행 APP0 뒤 삽입)로 수정 — shared-WIC probe와 동일 레이아웃.
  - "b1/c1은 누구와도 pair 불가"라는 초기 단언이 잘못됐다. 둘은 동일 회전이라 서로 pair한다. 단언을 "b1-c1 pair 존재 + 교차 pair 없음"으로 정정했다.

## 4. 해결된 상황

- `test_mode_xmp_selfcheck=ok` 14 checks (생산 verdict 5 + Test Mode parity·격리 9).
- XMP 실측 확대의 decode 절반에 이어 판정 절반이 실파이프라인에서 닫혔다. 남은 것은 Brief 7절의 실 corpus full scan regression이다.

# MediaSimilarityFinder v0.9.4.9 — Node C1: Profile Foundation

Validation baseline for C1: profile data model, INI store, verdicts,
and initial-estimate delivery without calibration. Engine 1.5.0, DB
1.0.3, cache v9, schema 1 unchanged.

## Why the change was needed
- The scheduler started every scan from hardware proxies. With no
  long-term baseline store, C2 calibration had nowhere to land.

## Previous structure
- No performance-profile persistence. `CalibrationTelemetry` was
  structure only. Scheduler baselines wired straight to hardware proxies.

## New structure
- New `src/profile.h/.cpp` (Qt-free, in `msf_core`):
  `PerformanceProfile` (id, identity, confidence, timestamps, 6
  metrics), `ProfileMatch` (Missing/Exact/Soft/Hard/Stale),
  `ProfileStore` (load/save/classify/initialEstimate).
- Id is FNV-1a hex over the canonical identity (stable across restarts;
  verdicts use fields, never the id).
- Verdict order Missing → Hard → Stale → Soft → Exact. Stale fires only
  on caller-supplied maxAge (C1 sets no default age policy; C3 owns it).
- initialEstimate returns a pair only on Exact/Soft with both
  throughputs measured. Overriding one baseline would corrupt the ratio,
  so CPU-only machines never yield an estimate (their GPU path is
  fallback by construction — correct).
- Manual INI codec (escapes, ignore-unknown forward compat, strict
  numerics). Atomic save via same-directory temp + rename (remove +
  rename fallback). A profile is regenerable cache, so the crash window
  is a documented limit.
- QSettings not reused: non-atomic and stringly states conflict with the
  Node A measurement rule.
- Mapping to the brief §5 conceptual layout: C1 code fixes section/key
  spelling. Includes `gpuBatchThroughput`, `transferBandwidthMBps`
  (bandwidth per the brief concept, not cost), `driver`, and
  `benchmarkSchemaVersion` provenance; `[lastUpdate]` arrives with the C3
  update policy. Integer `profileVersion` 1 and the brief's "1.0" denote
  the same generation.
- Scheduler priority: live rates → profile baseline → hardware proxies,
  with a new `profile_baseline` reason. Policy (shares/hold/band/
  binding) untouched.
- Engine hook: loads the machine-wide
  `<appDir>/Index/PerformanceProfile.ini` and applies a usable estimate.
  Dormant in C1 live runs (no writer yet), so behavior is identical.

## Why this shape
- Fixing the live > profile > hardware priority in C1 means C2 only
  adds the writer. Locking verdict, unit, and atomicity rules first is
  all of C1.
- C2/C3 numbers (calibration durations, confidence adjustments, stale
  default age, re-measure thresholds) are deliberately undecided.
  Mechanism without policy.

## Resolved state

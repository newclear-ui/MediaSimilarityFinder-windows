# MediaSimilarityFinder v0.9.4.135 — Test Mode 차이 리포트 + Yes/No 인덱스 채택

기준선 `0.9.4.134` → 본 빌드 `0.9.4.135`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (판정 불변, CTest 등록 수 불변, kProtocol 1 불변 — 추가 명령/이벤트만).

## 1. 변경 필요성

- 사용자 제안: Test Mode는 처음부터 전체 재분석하므로 본 인덱스와의 차이를 발견할 수 있다. 차이가 감지되면 리포트를 보여주고 **Yes/No**로 기존 Index DB 업데이트 여부를 선택하게 한다.
- 자동 반영 대신 **명시적 확인**을 택한 이유: Test Mode의 격리 계약(본 index/캐시/프로필/썸네일 불변, 0.9.4.127 pin)을 유지하면서, 사용자가 테스트 결과를 본 인덱스로 승격할 수단을 제공한다.

## 2. 기존 구조

- Test Mode 완료 후에도 스크래치 결과와 본 인덱스의 차이를 알 수 없었고, 반영 수단도 없었다(본 인덱스는 항상 불변).

## 3. 변경 구조

- **차이 계산(백엔드, Test Mode 완료 시)**: 본 인덱스와 스크래치 인덱스를 열어 파일 행·매치 쌍을 비교한다.
  - `changed`: 같은 경로의 지문/미러/크롭/크기 불일치, `added`: 스크래치에만 존재, `removed`: 본 인덱스에만 존재하되 **테스트 스캔 범위(이미지/비디오) 안이고 무시 목록이 아닌** 행, `pairDiff`: 쌍 집합 대칭차. 취소된 스캔은 제외.
  - 결과 0이면 상태줄 "테스트 스캔 결과가 본 인덱스와 일치합니다."만 표시.
- **리포트(Yes/No)**: 차이가 있으면 비모달 QMessageBox(예/아니오)로 `내용 변경/신규/삭제(스캔 범위)/매치 A → B`를 보여준다. 아니오 → 아무 것도 변경하지 않는다.
- **채택(예)**: `APPLY_TEST_RESULT`(추가 명령) → 백엔드 워커 스레드(Load/재검증과 동일 규칙)에서 **단일 트랜잭션**으로 스크래치의 files/matches/thumbs/content_hash/file_trace/meta를 본 인덱스에 복사(ATTACH + DELETE/INSERT SELECT). 성공 시 본 인덱스는 완료된 테스트 스캔 상태와 정확히 동일해지고, 실패·취소 시 SQLite가 롤백해 **본 인덱스가 그대로 유지**된다(파일 스왑 없음 → WAL 부작용 없음). 채택 후 세션의 이후 경로(썸네일 저장소·forget 기준)를 본 인덱스로 재설정하고 썸네일 prune.
- 모달이 아닌 창으로 구현: 창이 계속 반응하고 자동화(e2e)가 버튼을 클릭할 수 있다. 스캔을 새로 시작하면 세션의 pending이 해제되어 이전 테스트 결과는 반영될 수 없다.

## 4. 해결된 상황

- 실기 흐름: 테스트 스캔으로 전체 재검증 → 차이 리포트(변경/신규/삭제/매치 수) → Yes로 본 인덱스 승격(또는 No로 보존). Test Mode 격리는 Yes 전까지 그대로다.

## 6. 향후 영향 및 한계

- 판정·저장·프로토콜(kProtocol 1)·engine/DB/schema/cache·journal schema 불변. 추가 IPC 명령 1개 + 이벤트 2종(양 끝 동봉).
- 채택은 테스트 스캔의 범위(이미지/비디오 선택·무시 목록)를 기준으로 한 **전체 채택**이다. 범위 밖 행은 대체되며 리포트의 "삭제(스캔 범위)"로 드러난다(무시 목록은 삭제 집계에서 제외).

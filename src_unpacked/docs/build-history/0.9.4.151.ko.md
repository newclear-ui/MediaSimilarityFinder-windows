# MediaSimilarityFinder v0.9.4.151 — 감사 지적 결함 수정 (채택 범위·취소/실패 일치·저장 실패)

기준선 `0.9.4.150` → 본 빌드 `0.9.4.151`.
CPU CTest **126/126**, GPU CTest **127/127** (신규 `ui_date_sort_test` 1건 추가).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` / `kProtocol 1` 불변 (판정·스키마 불변).

## 1. 변경 필요성

- 0.9.4.150 감사에서 확정 결함 4건이 입증됐다. (1) 부분 범위 Test Mode 채택이 범위 밖 행을 삭제한다(P0, 데이터 손실). (2) 재분석 승인 후 취소, (3) 분석실패 전용 완료 스캔에서 DB는 stale 쌍을 제거하는데 GUI는 예전 화면을 유지한다(P1). (4) 매치 저장 실패를 무시하고 "Scan complete"를 보고한다(P1). (5) 스캔 중 매치 체크포인트가 엔진 트랜잭션 안의 중첩 BEGIN 실패로 silent no-op이다(P2).

## 2. 기존 구조

- `adoptIndexDatabase()`는 6개 테이블 전체를 `DELETE + INSERT SELECT`로 교체했다. `publishTestDiff()`는 범위 밖·ignored를 `removed`에서 제외했지만 채택은 그 구분을 몰랐다.
- 조용한 재적용(`reloadIntent`)은 완료 경로 + `analyzed>0`에서만 스케줄됐다. `onChangedFile`은 변경 판정 시점에 발사되므로 실패·취소된 파일도 변경 집합에 남는데, 그 경우 재적용이 없었다.
- `persistMatchesSnapshot()`은 `void`라 `saveMatches()`의 `false`가 5곳 모두 버려졌다. 최종 실패해도 `results` + `Scan complete` + 성공 telemetry가 송출됐다.
- 5초·analyze 체크포인트는 스캔 트랜잭션 안에서 실행되므로 `BEGIN IMMEDIATE`가 항상 실패했다(SQLite 중첩 불가).

## 3. 변경 구조

- **A**: `AdoptScope{scanImages, scanVideos, ignored}`를 받아 범위 내 행만 교체한다. 삭제는 removed 경로(파일·매치·썸네일·해시·trace) + 양 끝점이 범위 내인 매치에 한정하고, scratch 전체는 `INSERT OR REPLACE`로 upsert한다. out-of-scope 행은 보존된다. meta는 키 단위 upsert(삭제 없음). 단일 트랜잭션 유지.
- **B**: worker가 변경 파일 수를 메시지에 싣는다(CANCELLED 4번째, 완료 7번째, 실패 `|msfChanged=N` suffix — 기존 위치 인덱스 유지, append-only). GUI는 `analyzed>0 || changed>0`에서 재적용하고, 실패 스캔도 suffix가 있으면 같은 재적용을 스케줄한다(에러 문구는 유지). 조용한 재적용은 더 이상 상태줄을 "로딩중"으로 덮지 않는다(`silentReload_` 가드).
- **C1**: `persistMatchesSnapshot()` → `bool`. 최종 실패 시 `failed("match index save failed...")`를 내보내고 `results`/`finished`를 내보내지 않는다(DB는 구 집합 유지). 체크포인트 실패는 로그만 남긴다.
- **C2**: `Database::txActive_` 추적 + `saveMatches()`의 SAVEPOINT 분기. 호출자 트랜잭션이 열려 있으면 savepoint로 원자성을 유지하므로 스캔 중 체크포인트가 실제로 동작한다(파일 행 체크포인트는 원래 정상).
- 회귀 핀: e2e `Test 1g2`(실패 전용 스캔 화면 일치), `Test 1h`(ignored+Yes 후 범위 밖 행·쌍 보존), `crash_diagnostics_test` §4 (`MSF_TEST_FAIL_PERSIST` 주입 시 `failed` + `finished` 미송출), `ui_date_sort_test`(신규 CTest, 생성 날짜 내림/오름 순서).

## 4. 해결된 상황

- 이미지 전용·비디오 전용·ignored 포함 Test Mode Yes가 범위 밖 files/matches/thumbs/content_hash/file_trace를 더 이상 삭제하지 않는다.
- 취소·실패·분석실패 전용 스캔 후 화면과 저장 쌍이 일치한다(둘 다 제거 반영).
- 저장 실패는 `failed`로 보고되고 성공 문구·telemetry가 나가지 않는다.
- 스캔 중 매치 체크포인트가 실제로 영속화된다(킬/크래시 내구성 주석이 참이 됐다).

## 6. 향후 영향 및 한계

- 판정·저장·프로토콜·engine/DB/schema/cache 불변. DB 버전 상향 없음(동일 테이블·동일 트랜잭션).
- 최종 저장 실패 시 파일 행은 커밋된 채 매치만 구 집합이 남을 수 있다. 다음 Sequential 스캔·재검증으로 회복 가능하며, 실패가 가시화되므로 조용한 불일치는 없다.
- `finished`/`failed` 메시지 필드 추가는 append-only이며 기존 위치 인덱스를 유지한다.

# MediaSimilarityFinder v0.9.2.42 — 검색 체감 개선 (워킹 표시, 버튼 통합, 상태 저장)

## 변경 필요성
실머신 보고: 검색 버튼을 눌러도 파일 카운터가 움직이지 않고 CPU/GPU가 0%로 보여 "검색이 안 된다"고 느껴졌다. 실측 결과 두 가지 정상 동작이 원인이었다. (1) 271,837개 폴더의 디렉토리 워킹에만 **23분**(초당 196파일)이 걸리는 동안 진행 콜백이 없어 디스크 읽기만 보였다. (2) 이미 인덱싱된 폴더의 재스캔은 분석할 게 없어 CPU가 0%인 게 정상인데, 그 구분이 UI에 없었다. 추가로 일시정지/계속 버튼 분리, 트리 더블클릭 선택, 창 크기 미저장이 지적됐다.

## 기존 구조
- `Scanner::scan()`은 진행 보고 없이 전체 워킹 후 반환. `ScanControl::progress`는 분석 단계에서만 호출
- 일시정지/계속 2개 버튼 상시 활성화. `pauseScan`/`resumeScan` 분리 슬롯
- 좌측 트리는 `itemActivated`(더블클릭/Enter)로 폴더 선택
- 메인 창·설정 팝업 지오메트리 미저장 (스플리터만 저장)

## 변경 구조
- `Scanner::scan()`에 선택적 `onProgress` 콜백 추가 (2000개마다 + 종료 시). `ScanControl::listing` 신설해 워킹 카운트 전달. 워커가 `listingProgress` 시그널로 중계, GUI는 프로그레스바 indeterminate + "파일 목록 작성 중… N개" 표시. 분석 시작(`scanProgress`)되면 확정 바로 복원. 기존 시그니처 호환 유지 (기본값 null)
- 일시정지/계속 단일 토글 버튼 (`pause_`, checkable). 클릭 시 텍스트·체크·상태 메시지 전환, 시작/종료 시 초기화. `togglePauseScan` + `scanPaused_`로 통합
- 액션 버튼 상태: 실행 중 `scan_` 비활성 + `pause_`/`cancel_` 활성·체크 하이라이트, 종료 시 복원. 모니터 일시정지 버튼도 체크 연동
- 트리 `itemClicked` 추가 (기존 `itemActivated` 유지 → Enter 키 동작 보존, 클릭은 idempotent라 중복 안전)
- `QSettings(ui/mainGeom)` 창 지오메트리, `ui/settingsGeom` 설정 팝업 저장/복원
- 버전 표기 통일 → 0.9.2.42. 목업B v4 갱신

## 해결된 상황
- 대용량 폴더 스캔 시작 후 즉시 카운터가 움직임. 재스캔 무변경 시 "이미 최신 상태" 메시지와 구분됨
- 버튼 1개 감소, 상태 표시 일관화

- Core Release 빌드 PASS, **CTest 39/39 PASS** (엔진 변경은 additive only), `--smoke` exit 0, `--version` 0.9.2.42
- 워킹 실측: 271,837개/23분/196파일·초 (사용자 폴더 직접 측정). 이 수치는 다음 대용량 스캔 시간 예측 기준

## 향후 영향
- `listing` 콜백은 스캔 취소/일시정지와 독립 (워킹 중 pause는 분석 단계에서 적용). 워킹 중 cancel은 기존처럼 스캔 루프 진입 후 반영 — 수십만 폴더에서 취소 지연이 체감될 수 있어, 필요하면 워킹 루프에도 cancel 체크 추가 (별도 버전)
- 추정 남은 시간(ETA) 표시는 카운트만으로 불가(전체 개수 미지). 전체 스캔 1회 후 인덱스 통계를 이용해 2회차부터 표시하는 방식으로 확장 가능

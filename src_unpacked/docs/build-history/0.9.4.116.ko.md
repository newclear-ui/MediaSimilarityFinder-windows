# MediaSimilarityFinder v0.9.4.116 — 삭제 파일 유령 그룹 수정 + GUI 자동 정리 (잔존 인덱스 행)

기준선 `0.9.4.115` → 본 빌드 `0.9.4.116`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 보고: indexDB 그룹 275(대표 `Keren1286444-2080011532100890711-01.jpg`) — 사용자가 이전 테스트에서 유사 파일을 모두 삭제해 더 이상 존재하지 않는 그룹인데도 목록에 남아 있고, 존재하지 않는 구성원 2개가 파일 목록에 계속 표시된다. 상세 정보에는 이름·경로·형식·유사도가 캐시값으로 보이지만 실제 파일 크기는 0 byte, 해상도 등은 공란이다. 추가 요청: GUI에서 이런 잔존 문제가 발견되면 인터페이스에서 자동으로 해결하는 방안.

## 2. 기존 구조와 결함

- **근본 원인**: 스캔의 삭제 파일 정리(`media_search_engine.cpp` walkCompleted 루프)가 `Database::remove()`를 사용한다. `remove()`는 **files 행만 삭제**하고 그 경로를 참조하는 **matches·thumbs 행은 남긴다**(database.cpp:137).
- 결과: 외부에서 삭제된 파일이 **유령 그룹 멤버**로 영구 잔존한다. files 행이 없어 크기 0·상세 공란이 되고, matches 행이 계속 목록(그룹 구성원)을 만들어낸다. **재스캔으로도 매치가 지워지지 않아** 계속 남는다.
- `.105`에서 추가된 `Database::forget()`(files+matches+thumbs, 1 트랜잭션)이 올바른 정리지만 스캔 경로가 쓰지 않았다. 스캔은 자체 외부 트랜잭션(`tx`) 안에서 돌기 때문에 자체 `BEGIN`을 여는 `forget()`을 직접 호출할 수 없다.
- 같은 결함이 **실시간 모니터 경로**(`MediaSearchEngine::removePath()` → monitor.cpp:297, 삭제 이벤트 감지 시 호출)에도 있었다 — `remove()`만 사용.
- **불러오기·스캔 quick-load는 DB 행을 무검증 표시** — 존재 검증/자동 정리 경로가 없었다(사용자 요청 항목).

## 3. 변경 구조

- **`Database` 리팩터**: 행 삭제를 `forgetRows()`로 추출하고, `forgetNoTransaction()`(호출자가 트랜잭션 소유)을 추가. 공개 `forget()`은 기존 계약(자체 트랜잭션) 유지.
- **스캔 삭제 정리**: 삭제 경로를 모아 스캔 트랜잭션 안에서 `db_.forgetNoTransaction(removedPaths)` — files+matches+thumbs 동시 정리. `removed` 카운트 의미 불변.
- **모니터 경로**: `removePath()`가 `db_.forget({path})` 사용.
- **자동 정리 API** `MediaSearchEngine::cleanupMissingOnDisk(root)`:
  - `root`가 디렉터리일 때만 동작(오프라인 드라이브는 무동작 — 인덱스 전체 삭제 방지).
  - 저장된 매치의 **엔드포인트 경로를 파일시스템 검증** → 사라진 경로를 `db_.forget` + `diskCleanup missing=N` 로그.
- **GUI 자동 해결 연결**: **불러오기**(`BackendSession::runLoadIndex`)와 **스캔 quick-load**(`scan_worker`)가 목록을 만들기 전에 `cleanupMissingOnDisk`를 자동 실행 → 유령 멤버가 표시되기 전에 정리된다(백엔드 로그로 확인 가능).
- **회귀 테스트**(`search_engine_test`): ① 외부 삭제 + 재스캔 시 매치 행 제거 — **수정 전 exit 29 FAIL 재현** → 수정 후 PASS ② `cleanupMissingOnDisk`가 사라진 엔드포인트를 정리하고 **오프라인 루트에서는 무동작**임을 검증(exit 30~33).

## 4. 해결된 상황

- 외부 삭제된 파일이 어느 경로(재스캔/불러오기/스캔 시작/모니터)에서도 유령 멤버로 남지 않는다.
- 이미 쌓여 있는 잔존 행은 **다음 불러오기 또는 스캔 시작 시 자동 정리**된다(사용자 조작 불필요, `diskCleanup missing=N` 로그).
- 상세의 0 byte·공란 표시는 원인(유령 항목) 제거로 함께 사라진다.

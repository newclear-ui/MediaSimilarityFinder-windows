# MediaSimilarityFinder v0.9.2.58 — Blank Group Pane Fix (Placeholder Icon Storm)

## Need for change
11,084 duplicate groups existed in data (status bar and tab counts correct) but the middle pane rendered completely blank (scrollbar only). The placeholder path introduced by the v0.9.2.56 decode budget was the culprit.

## Previous structure
- Over budget, `fileThumb()` did `return QFileIconProvider().icon(QFileInfo(path))` — a fresh provider plus a per-file SHGetFileInfo (milliseconds each). 11k groups × every 600ms tick = tens of seconds of GUI blockage per tick
- Placeholders were never cached (for retry), so the full storm repeated every tick. Paint-event starvation left a blank pane with only a scrollbar. Pause/stop clicks unprocessable

## New structure
- **Per-suffix placeholder cache** (`phCache_`, lowercase-suffix key): 11k files converge to ~10 distinct icons. Zero per-tick cost after warmup. Both failure fallbacks unified onto the same path (shared provider)
- **Shared provider** (`sharedIconProvider()`, function-local static): no per-call construction. GUI-thread only, safe
- `phCache_` is file-independent so it survives scan start (next scan pre-warmed). 64-entry guard retained
- Version strings unified → 0.9.2.58

## Resolved situation
- Per-tick GUI work capped at 4 budgeted decodes + cache hits. The group list actually renders, thumbnails fill in progressively. Pause/stop/window-move work
- Blank-pane-with-scrollbar eliminated at the source

## Validation
- Core+GUI Release build: PASS, **CTest 44/44 PASS**
- `--version` 0.9.2.58, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)

## Future impact
- Full widget rebuild per tick (11k items) still costs hundreds of ms. Incremental list sync (append-only) kept as the next candidate
- A cap for single giant groups remains a separate candidate

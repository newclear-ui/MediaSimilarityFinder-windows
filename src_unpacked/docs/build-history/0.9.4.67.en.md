# MediaSimilarityFinder v0.9.4.67 — P1 BackendCore boundary + Backend entry point

Baseline `0.9.4.66` -> this build `0.9.4.67`.
CPU CTest **111 to 114**, GPU CTest **112 to 115** (3 new backend tests).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged. No search semantic or behavior change.

## 1. Why the change

- Process-split P0 inventory plus the Brief supplement (G1–G13) are done.
  P1 "declares the BackendCore boundary in the same process and raises the
  entry point".
- Key finding: the existing `msf_core` target already IS BackendCore
  (engine, database, monitor, scanner, decoders; zero Qt linkage; zero Qt
  includes in `src/*.h`). So a boundary declaration without file moves
  suffices.

## 2. Previous structure

- `msf_core` STATIC lib (src/*), consumed fully in-process by the GUI exe.
- No Backend executable. Portable ships the GUI exe only.

## 3. New structure

- BackendCore boundary comment on `msf_core` (keep it Qt-free contract).
- New `src/backend_main.cpp` + `MediaSimilarityFinderBackend` target:
  links `msf_core` + `Qt6::Core` only (no Widgets/Gui, G13).
  Console subsystem so stdio works (`--help`/`--version` now, the
  line-oriented IPC channel in P3).
- `--help`/`--version` clean (exit 0). `--backend` refuses explicitly
  before P3 arrives (exit 2, contracted by a WILL_FAIL test).
- `package_portable.ps1` copies the Backend exe beside the GUI exe
  (the supervisor finds it via the application directory, no PATH search).
- GUI behavior unchanged (still in-process).

## 4. Resolved state

- BackendCore builds, links, and runs standalone (`--help`/`--version`).
  The portable package contains the Backend exe. Foundation for P2
  Loopback / P3 spawn.

## 5. Verification

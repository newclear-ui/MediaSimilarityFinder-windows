# MediaSimilarityFinder v0.9.4.120 — GUI-less 구성 복구 + 배지 비용 판정 기록 + 제품 acceptance 런북

기준선 `0.9.4.119` → 본 빌드 `0.9.4.120`.
CPU CTest **123/123**, GPU CTest **124/124**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성 (복수)

1. **`MSF_BUILD_GUI=OFF` + `MSF_BUILD_TESTS=ON` 구성 불가**(관찰 기록, 미수정): GUI 테스트 `msf_ui_detailed_log_test`가 GUI 게이트 밖의 테스트 블록(CMakeLists 456행)에서 `Qt6::Widgets`를 링크해, Widgets를 찾지 않는 GUI-less 구성에서 CMake 오류로 중단됐다.
2. **배지 확인 비용 후보(후보 2) 판정 필요**: 0.9.4.113의 전체 내용 SHA-256 확인은 실측 추가 읽기 약 1.5 GiB/전체 스캔(사용자 인덱스, 69.2 GB의 ~2.2%)으로 기록돼 있었고, "실기 체감 악화 시에만" 완화를 하기로 한 조건부 후보였다.
3. **제품 acceptance 런북 부재**: Search/Index/Comparison 최종 acceptance(NOT ACCEPTED)를 동일 절차로 수행할 실행 체크리스트가 없었다.

## 2. 기존 구조

1. CMakeLists: GUI 빌드/테스트는 `if(MSF_BUILD_GUI)`→`if(Qt6_FOUND)`→`if(MSF_BUILD_TESTS)`(675행~) 아래에 있는데, `msf_ui_detailed_log_test`만 상단 테스트 블록(451~460행)에 남아 있었다.
2. 배지 확인: `MediaSearchEngine::loadMatches`가 후보 게이트(크기+quick hash) 통과 쌍에 대해 파일당 1회 전체 SHA-256(메모)을 수행. 파일 단위 캡(512 MiB) 초과 시 배지 생략. 같은 패스에서 파일당 1회만 읽는다(.113 계약).

## 3. 변경 구조

- **① GUI-less 구성 복구(코드)**: `msf_ui_detailed_log_test`를 GUI 테스트 블록(다른 GUI 테스트와 동일 위치)으로 이동. GUI=OFF + tests=ON은 GUI 테스트를 건너뛰고 코어 테스트만 구성·빌드한다. GUI=ON 경로는 등록 수 불변(CPU 123/GPU 124).
- **② 배지 확인 비용 = LOW PRIORITY 판정(코드 변경 없음, 기록)**: 근거 — ① .113 실측: 전체 스캔 3,493쌍/5,296파일 확인에 약 1.5 GiB 읽기(69.2 GB의 ~2.2%, NVMe 기준 1초 미만) ② 실기(0.9.4.118 06:40 AB 세션): 후보 2쌍만 확인, 불러오기 체감 정상, 완화 요구 없음 ③ 부분 캡은 감사 B1이 기각한 **뒤 꼬리 오표기**를 재도입하므로 금지. 재검토 조건: 실기 불러오기 지연 보고, HDD 기반 dataset 이동, 동일 사본 수만 개 이상 확대.
- **③ 제품 acceptance 런북(문서)**: `docs/architecture/product-acceptance-runbook.{ko,en}.md` 신규 — Index/Search/Comparison 체크리스트, 기대값·판정 신호, 기록 형식(상세 로그 1:1 대조), crash 시 절차 참조.

## 4. 해결된 상황

- GUI 없이도 테스트 빌드가 가능해져 CI/헤드리스 검증 경로가 열렸다(구성 실패 → 성공, 헤드리스 트리 98 테스트 등록·샘플 타깃 빌드 확인).
- 배지 비용은 "추가 구현 없음"이 근거와 재검토 조건을 갖춘 결정으로 기록됐다(부분 캡 금지 원칙 포함).
- 제품 acceptance가 절차 문서를 갖게 되어 판정·기록이 반복 가능해졌다.

- **미검증/확인 필요**: 없음(런북은 문서, GUI-less 경로는 구성·빌드·등록 수 검증).

## 6. 향후 영향 및 한계

- 제품 동작 변화 없음: ①은 빌드 시스템 배치 이동, ②는 기록, ③은 문서. 판정·저장·프로토콜·engine/DB/schema/cache 불변.
- GUI-less 트리에는 실기 GUI 상호작용 테스트가 없다(설계) — GUI 검증은 GUI=ON 트리(기존 회귀 포함)에서 수행한다.
- 배지 비용은 재검토 조건 충족 시 재평가한다(부분 캡 재도입은 여전히 금지 — 전체 내용 확인 계약 유지).

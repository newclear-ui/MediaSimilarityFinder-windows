# MediaSimilarityFinder v0.9.4.85 — revalidation progress + count-first restored

Baseline `0.9.4.84` -> this build `0.9.4.85`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged. No verdict, schema or decode change.

## 1. Why it was needed

User report (0.9.4.84 detailed log): on an already-indexed folder
(`G:\Downloads\ss_twit`), "Search Update" sat for 2m23.9s with **총 파일 "-" and every
counter 0**, then was stopped.

The log pins the cause:
- `cancelledDuring=""`, `walkMs=0`, `walker.capacity=0` -> **the walk phase was never
  reached.**
- `revalidateMs=0` (not recorded on cancel), `procIoReadBytes=2.94 GB`,
  `readOps=758186`.
- The time was spent in the **engine-version gate `revalidateMatches`**, which
  re-verifies every stored pair and decodes images for the grey-zone ones. Because
  0.9.4.82 bumped `kEngineVersion` 1.5.0 -> 1.5.1, opening a DB stamped 1.5.0 triggers
  a full re-verification (one time).
- **0.9.4.83's reorder** compounded this: the count prepass moved after the gate, so
  even "총 파일" stayed "-" during the revalidation.

## 2. Previous structure (0.9.4.84)

`ScanWorker::run()` order: openIndex -> **revalidate** -> quick-load -> **count** ->
walk. Revalidation had no progress signal, so the UI looked frozen at 0, and count came
late so the total was missing too.

## 3. Change

- **(a) Restore count-first**: the count prepass runs before revalidation, so "총 파일"
  appears right after scan start.
- **(b) Revalidation progress**: new `ScanControl::revalidateProgress(done,total)`
  callback, called by `MediaSearchEngine::revalidateMatches` every 16 pairs (plus a
  final call) -> `ScanWorker` emits a throttled (150 ms) `revalidateProgress` signal ->
  `BackendSession` -> backend IPC (`kState`/`REVALIDATE_PROGRESS`) ->
  `BackendSupervisor` -> GUI status bar "Revalidating stored pairs N/M (engine version
  update)".

Order: openIndex -> **count (total)** -> **revalidate (progress)** -> quick-load
(groups) -> walk.

## 4. Result

- During revalidation the "총 파일" row and a status-bar progress line are visible, so a
  scan no longer looks frozen.
- Revalidation runs **once** after an engine-version bump; on completion the version is
  stamped and later scans skip it.

## 6. Impact and limits

- The revalidation cost itself (image decode for grey-zone pairs) is unchanged; it can
  take minutes on large datasets.
- **Stopping mid-revalidation does not stamp the version, so the next scan revalidates
  again.** One run must be allowed to finish; the progress display now makes that
  decision possible.
- 0.9.4.83's "index-first" assumed count could follow the gate; since the gate is the
  heavy step, **count was moved back to the front**. Groups (quick-load) still appear
  before the walk.

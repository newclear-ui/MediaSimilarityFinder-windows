# MediaSimilarityFinder v0.9.4.14 — C4.1 Build Recovery

Recovers the compile break found while validating the 0.9.4.13 sync.
Engine 1.5.0, DB 1.0.3, cache v9, schema 2 unchanged.

## Why the change was needed
- 0.9.4.13 declared `kDefaultMaxAgeDays` on `ProfileStore` while all 5
  use sites referenced `PerformanceProfile::`, breaking the build with
  C2039/C2065. Remote honestly marked validation pending, but without
  PASS figures C4.1 stays incomplete. The new profile_test case broke
  the same way.

## Previous structure
- Declaration site (`ProfileStore`) vs use sites (`PerformanceProfile::`)
  mismatch.

## New structure
- Constant moved to `PerformanceProfile` (as the uses intend). No
  behavior change, comments tidied.
- `msf::` prefix added to the bare `PerformanceProfile::` reference in
  the new profile_test case.

## Why this shape
- Moving the declaration to the uses is the minimal diff, and the
  constant's meaning (profile policy value) belongs to
  `PerformanceProfile` anyway.

## Resolved state
- Both-tree compile and full suites recovered.

## Accuracy impact
- None. Declaration site only; value and meaning identical.

## Compatibility impact
- None. INI/JSON keys unchanged.

## Validation
- CPU Release build PASS, **CTest 66/66 PASS**.
- GPU Release build PASS, **CTest 67/67 PASS**.
- `--version` 0.9.4.14 and `--smoke` PASS on both.

## Future impact
- The 0.9.4.13 validation figures should be read as established by
  this version. Remote syncs are now rule-bound to local builds
  (established this round). The CPU-only figure (64/64) is corrected
  to 66/66 per the 0.9.4.12 baseline.

# MediaSimilarityFinder v0.9.4.165 — 중단된 비디오 분석의 영구 실패 방지 (P1 회귀 수정)

기준선 `0.9.4.164` → 본 빌드 `0.9.4.165`.
CPU CTest **134/134**, GPU CTest **135/135** (신규 실행 파일 없음, `scan_cancel_video_test`에 결정적 시나리오 D 추가).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` 전부 불변.

## 1. 변경 필요성

- 0.9.4.163/164 GPU 스위트에서 `scan_cancel_video_test` 시나리오 A가 간헐적으로 실패했다 (동일 바이너리 단독 실행은 매번 통과). 원인 추적 결과 플레이크가 아니라 실제 제품 결함이 드러났다.
- 결함: 사용자가 스캔을 중단하면 진행 중이던 비디오 빌드가 `analysisFailed=true`(영구 실패)로 기록됐다. `pendingAnalysis`(fingerprint==0 && !analysisFailed) 규칙상 이 행들은 재스캔에서 영원히 건너뛰어진다 — 중단된 영상이 파일 변경 전까지 인덱스에서 누락된다. 0.9.4.158의 P0 수정(중단 시 위조 지문 저장 금지)은 저장 경로를 막았지만, 실패 카운트와 settled 표시는 그대로 두어 "취소됨"이 "실패함"으로 둔갑했다.
- 기존 테스트의 exact-count 단언(`failed==0`, 재스캔 पूर्ण 재사용)은 이 결함 때문에 타이밍에 따라 깨졌다. 결함을 고치면 단언이 타이밍과 무관하게 항상 성립한다.

## 2. 기존 구조

- 비디오 범위 수확: 빌드 실패 시 무조건 `fingerprint=0, analysisFailed=true` 저장 + 실패 카운트 + 실패 파일 텔레메트리. 취소 여부를 구분하지 않았다.
- `stopped(control)`은 일시정지 대기까지 포함하므로 취소 판별에 쓸 수 없다.

## 3. 변경 구조

- 수확 시점에 `control->cancel` 직접 확인(논블로킹, 일시정지 무시): 취소로 중단된 빌드는 admission skeleton(fp=0, !failed)을 그대로 두어 다음 스캔이 `pendingAnalysis`로 재시도한다. 실패 카운트·실패 파일 텔레메트리에서 제외한다. trace outcome은 `file_trace` 계약에 따라 `"cancelled"`로 기록한다(settled 아님을 명시).
- 진짜 실패(취소 없음)는 기존 settled 경로 그대로 유지한다.
- 회귀: 시나리오 D (tiny+4K 노이즈, ~40배 스윕 시간차로 mid-sweep 중단 확정). 구 코드에서 `failed==1`+재스캔 스킵으로 실패함을 확인한 뒤(FAIL-first), 수정 후 통과를 확인했다.
- adhoc 조회 경로와 이미지 배치는 취소 중단이 없으므로(배치는 끝까지 실행, reverify는 트랜잭션 롤백) 변경하지 않았다.

## 4. 해결된 상황

- 중단된 스캔이 영구 실패 행을 남기지 않는다. 완료분은 저장·재사용, 중단분은 다음 스캔에서 재시도, 진짜 실패만 settled가 된다.
- 시나리오 A의 exact-count 단언이 결정적으로 복원됐다 (어떤 interleaving에서도 `failed==0`, `unchanged==analyzed`, `analyzed+unchanged==kClips`).

## 6. 향후 영향 및 한계

- 판정·저장·프로토콜·버전·엔진 불변. 캐시 무효화 없음. 엔진 버전 불변(판정 변경이 아니라 취소 경로의 기록 정정이므로 재검증 불필요).
- 취소 스캔의 `failed` 집계 의미가 바뀐다: 이제 진짜 실패만 센다. 과거 취소 스캔의 실패 수는 과대계상이었다.

## 1. Purpose · Hypothesis · Target

- Purpose: v0.9.4.31에서 DEFERRED된 공유 decode 후보의 정확성 차이 원인을
  규명한다. 성능 이점은 이미 관찰됐으므로 이번 단계의 유일한 질문은 "왜
  출력이 달라지는가"다.
- Hypothesis: 차이는 1스텝 Fant와 2스텝 Fant 리샘플 체인의 구조적 차이에서
  오며, 특정 이미지 구조(bilevel·edge-heavy tiny 이미지)에서 증폭된다.
- Target: v0.9.4.31 이 보고한 flip 2건의 재현 시도·score 분해·리샘플 경로
  대조·R stability·pixel 통계. (flip 은 §2 에서 artifact 로 정정된다)

## 3. Implementation

- `tests/shared_decode_probe.cpp`에 `--flips <root>` 모드 추가 (측정 전용).
  **생산 알고리즘/동작 변경 없음.** 버전 문자열 갱신 파일은 §20 에 별도
  기재한다.

- score 분해: `ssimBuf`/`flipBuf`와 동일한 max 체인을 probe에 재현하고,

  (`decomp_mismatch=0`, `DECOMP-MISMATCH` 0건).
- `comparePixels`에 sumAbs 추가 → mean abs delta 통계.
- 공간 국소화: max-delta window의 양쪽 crop에 quadrant 평균 + argmax 보고
  (픽셀맵 덤프 없이 증거만).
- 캐시 분할: 공개 `verifyImagePair` 동일 파일 2회 호출로 miss/hit 분리.
- CMake: 기존 `msf_shared_decode_probe` 실행파일에 포함. CTest 미등록
  (decision-input 도구이며 dataset 경로 인자 필요 — `msf_dataset_baseline`
  과 동일 사유).

## 8. 리샘플 경로 대조 (소스 기준)

```text
baseline : 원본 → WIC Fant → 최종 GrayImage

candidate: 원본 → WIC Fant → 중간 8-bit GrayImage
                 → 다시 WIC Fant → 최종 GrayImage
```

f/a pixel divergence 를 만드는 핵심 구조는 다음 세 가지의 결합이다.

```text
1. 2단계 Fant resampling (1스텝 vs 2스텝 체인)
2. 중간 8-bit GrayImage 양자화 (중간 이미지가 8-bit 로 잘린 뒤 2번째 Fant 입력)
3. 서로 다른 resampling chain (Fant vs nearest)
```

- WIC 스케일러는 세 decode 경로 전부 Fant다
  (`src/image_decoder.cpp:220,294,344`).
- 후보는 중간 이미지를 8-bit GrayImage 로 양자화한 뒤 다시 리샘플하므로,
  두 번째 Fant 스텝은 양자화된 입력을 본다. 이것이 1스텝과 갈라지는
  구조적 지점이다 (§10 Case B 의 메커니즘).
- `centerCropResize` 는 f/a divergence 의 **최초 원인이 아니다.** scoring
  단계에서 사용되며 정수 nearest-neighbor
  (`y * ch / outSize`, `x * cw / outSize` — `src/crop_fingerprint.cpp:12`)로
  이미 발생한 입력 차이를 scoring crop 으로 그대로 전달한다.

- hpredict maxwin(a916-fullB): 전 R에서 argmax 가 좌상단 모서리 (0,0)/(1,0)에

  분포.
- 원인 단정 없음. edge/texture 연관 관찰 기록에 그친다.

## 14. EXIF / PGM / Cache

- EXIF: flip 4파일 전부 `orient=0`, 전수 집계 `orient_applied_files=0`.
  **현재 데이터셋에는 EXIF 방향 적용 fixture 가 없어 EXIF 경로는 미검증이다.**
  "EXIF 검증 완료"로 기록하지 않는다. flip 원인과 무관하므로 이번 조사에서
  신규 픽스처는 추가하지 않았다.
- PGM: `pgm_fallback_files=0`. **현재 데이터셋에는 PGM fallback 입력이 없어
  PGM 경로는 미검증이다.** "PGM 검증 완료"로 기록하지 않는다.
  `readPgmFile` 은 P5 전용·`maxv` 미정규화를 코드로 재확인
  (`src/image_decoder.cpp:88-91`).
- Cache: 공개 `verifyImagePair` 동일 파일 2회 호출 —
  miss `decodeMs=1.3457` (misses 2, score 94.9033),
  hit `decodeMs=0.0000` (hits 2, score 동일 94.9033).
  (CPU 재실행 2회에서 miss decodeMs 는 1.3491 / 1.4988 로 관찰됐다.
  점수·hit/miss 분리는 3회 모두 동일하다.)
  이 결과를 shared decode 후보의 **전체 성능 효과로 해석하지 않는다.**
  핵심 후보 비용 비교는 cache miss 경로다.

## 15. 전체 groups 타당성 조사 결론

전스캔 groups 비교에는 후보 버퍼를 `verifyImagePair`→`verifyBuffersFor`→스캔
경로에 넣어야 하며, 이는 생산 호출 경로 변경 또는 스캔 전체의 병렬 재구현을
요한다. 비용이 크고, sampled verdict(1691 sampled pairs, flip 0)가 DEFERRED
판정에 충분하므로 **구축하지 않는다**. 필요성 판단 완료로 기록한다.

실제로 비교한 범위를 명확히 하면 다음과 같다.

```text
verdict 비교는 해상도당 1691 sampled pairs 에서 수행했다
(sampled pairs = 1691, R128/192/256/384/512, flip 0)
전스캔 groups 비교는 수행하지 않았다
```

이 문서 어디에도 "groups 동일"이라는 주장을 하지 않는다.

## 16. 세 질문 답 + 판정

- Q1: f/a pixel divergence 발생 지점 = 2단계 Fant 체인 + 중간 8-bit
  양자화 + 서로 다른 resampling chain. 수치로 특정됨 (§7, §10, §12).
  scoring 단계의 `centerCropResize` 는 이 차이를 crop 으로 전달할 뿐 최초
  원인이 아니다.
- Q2: 알고리즘(Fant vs nearest) + 해상도(중간 업샘플 발명) + 스텝 수(2 vs 1)
  복합. 단일 원인 아님.
- Q3: R 경계 flip 은 artifact 였음. 순수 쌍에는 경계 없음.
- Q4: tiny bilevel/edge 이미지에서 증폭. EXIF 무관.
- Q5: **현재 조사한 범위**(R=128,192,256,288,320,352,384,512)에서는 byte
  parity 가 복원되지 않았다. 이 범위를 넘어선 해상도에서의 불가능성은
  증명되지 않았으며 기록하지 않는다.

## 17. DEFERRED 판정과 사유

성능 잠재력은 실측되었으나 production semantics 동등성이 아직 충분히 입증되지
않았다. 따라서 후보는 `DEFERRED`, production adoption 은 `NO` 다.

verdict flip 이 artifact 로 정정되었음에도 후보를 자동 ACCEPT 하지 않는다.
DEFERRED 사유는 다음과 같다.

```text
1. f/a byte parity 가 유지되지 않음
2. a geometry 차이가 일부 존재함 (R128 93건, R256 54건, R384 39건, R512 34건)
3. 실제 pixel divergence 가 존재함 (geometry 동일 구간에서도)
4. full-scan groups 동등성이 아직 측정되지 않음
5. EXIF orientation fixture 가 없어 해당 경로 미검증
6. PGM fallback coverage 가 없어 해당 경로 미검증
7. 현 단계에서 production semantics 동등성을 충분히 입증하지 못함
```

## 18. revisit 조건 (우선순위)

```text
1. full-scan groups 비교
2. 대표적인 near-threshold fixture 검증
3. EXIF 방향 fixture
4. PGM fallback fixture
5. production path 를 변경하지 않는 정확성 검증 구조
```

`verdict-band` 정책은 향후 near-threshold accuracy acceptance policy 를 정의할
필요가 있을 때 별도로 다룬다. flip 이 artifact 였으므로 필수 조건으로 취급하지
않는다.

## 21. 기존 스크립트 maintenance issue (기록만, 이번 작업에서 미수정)

`scripts/package_portable.ps1` 의 현재 기본값은 `BuildDir = build-windows-cuda`
이나 실제 이 저장소의 빌드 트리는 `build-windows-cpu` / `build-windows-gpu`
다. 이번 패키징은 `-BuildDir build-windows-gpu` 로 override 하여 수행했다.

또한 스크립트는 exe 존재 확인 후 출력 디렉터리를
`Remove-Item $OutputDir -Recurse -Force` 로 정리한다. 이번 작업에서는
`src_unpacked/portable-release` 를 건드리지 않기 위해 출력 디렉터리를 임시
경로로 지정했다. exe 확인이 출력 디렉터리 정리보다 먼저 수행된다는 점은
스크립트 순서 그대로다.

이번 작업은 **스크립트를 수정하지 않았다.** maintenance issue 로 기록만 한다.

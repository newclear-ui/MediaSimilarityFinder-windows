## 1. Purpose · Hypothesis · Target

- Purpose: v0.9.4.31에서 DEFERRED된 공유 decode 후보의 정확성 차이 원인을
  규명한다. 성능 이점은 이미 관찰됐으므로 이번 단계의 유일한 질문은 "왜
  출력이 달라지는가"다.
- Hypothesis: 차이는 1스텝 Fant와 2스텝 Fant 리샘플 체인의 구조적 차이에서
  오며, 특정 이미지 구조(bilevel·edge-heavy tiny 이미지)에서 증폭된다.
- Target: flip 2건의 재현·score 분해·리샘플 경로 대조·R stability·pixel 통계.

## 2. 정정 기록 — v0.9.4.31 flip 2건 무효 (가장 먼저 기록한다)

```text

오류 원인: 전체 측정의 neighbor 쌍이 혼합 버퍼였다. sBase 쪽에 이전 파일의

          기준선-후보 verdict 비교가 아니다.
수정된 값: 순수 쌍(양쪽 기준선 vs 양쪽 후보)으로 전수 재측정 — 전 해상도
```

v0.9.4.31 커밋 히스토리는 rewrite하지 않는다. 이 문서가 정정을 보존한다.

## 3. Implementation

- `tests/shared_decode_probe.cpp`에 `--flips <root>` 모드 추가 (측정 전용).
  생산 코드 변경 없음.
- flip 4파일 지정, R∈{128,192,256,288,320,352,384,512} 협소 sweep 포함.
- score 분해: `ssimBuf`/`flipBuf`와 동일한 max 체인을 probe에 재현하고,
  `verifyScorePlan` 총합과 비트 단위 일치를 자체 검증
  (`decomp_mismatch=0`, `DECOMP-MISMATCH` 0건).
- `comparePixels`에 sumAbs 추가 → mean abs delta 통계.
- 공간 국소화: max-delta window의 양쪽 crop에 quadrant 평균 + argmax 보고
  (픽셀맵 덤프 없이 증거만).
- 캐시 분할: 공개 `verifyImagePair` 동일 파일 2회 호출로 miss/hit 분리.
- CMake: 기존 `msf_shared_decode_probe` 실행파일에 포함. CTest 미등록
  (decision-input 도구이며 dataset 경로 인자 필요 — `msf_dataset_baseline`
  과 동일 사유).

## 8. 리샘플 경로 대조 (소스 기준)

```text
baseline : WIC decode → 직접 목표 크기 (Fant 1스텝)
candidate: WIC decode → 중간 해상도 (Fant) → 메모리 Fant → 최종 f/a
```

- WIC 스케일러는 세 decode 경로 전부 Fant다
  (`src/image_decoder.cpp:220,294,344`).
- `centerCropResize`는 정수 nearest-neighbor다
  (`src/crop_fingerprint.cpp:12`).
- 후보는 중간 이미지를 8-bit GrayImage로 양자화한 뒤 다시 리샘플하므로,
  두 번째 Fant 스텝은 양자화된 입력을 본다. 이것이 1스텝과 갈라지는
  구조적 지점이다 ( §9 Case B의 메커니즘).

## 10. Case 분리 결과

- Case A (geometry 차이 → pixel 차이): R별 0–93건(§9). 치수가 다르면 픽셀
  비교 자체가 무의미하므로 분리 집계했다.
- scoring crop(`centerCropResize`, 정수 nearest-neighbor): R당 2547개 중
  동일 것이 12~69개뿐 (R128 69, R192 12, R256 69, R384 12, R512 12).
  crop은 Fant 가 아닌 정확한 정수 연산이므로 이는 crop 단계가 독립적 오류
  원인이 아니라 앞서 발생한 pixel divergence의 결과임을 분리해 보인다.
- Case B (geometry 동일 → pixel 차이): 지배적. flip 4파일, 전체 sweep
  R∈{128,192,256,288,320,352,384,512}:
  hpredict f diff 2140~2676/4096 (52~65 %), max 124~216, mean 4.04~7.00;
  l1 f diff 3801~4054/4096 (93~99 %), max 63~107, mean 17.89~33.36.
  flip 파일에서는 R이 오를수록 diff 픽셀 수·mean이 단조 증가한다 (업샘플
  발명 → 다운샘플 별칭). 전체 dataset 집계 `f ident` 수치(§9/§11)가 이보다
  작은 것은 모든 형식을 합산하기 때문.

## 12. pixel 통계 요약

- hpredict 계열: 4096 픽셀 중 52~65 % 상이, max abs 124~216,
  mean abs 4.04~7.00 (flip 파일에서 R에 대해 단조 증가).
- l1 계열 (1-bit bilevel): 93~99 % 상이, max abs 63~107,
  mean abs 17.89~33.36.
- 그럼에도 score delta는 ≤0.05, verdict 불변 — SSIM-max 체인이 리샘플 차이에
  둔감하다는 증거다 (단, 임계값 근처 쌍 일반화는 별개 문제로 남는다).

## 13. spatial 증거

- hpredict maxwin(a916-fullB): 전 R에서 argmax 가 좌상단 모서리 (0,0)/(1,0)에
  고정. Aside TL mean 7.75~13.08 vs BR 0.61~0.98, Bside TL 13.60~24.11 vs
  BR 0.55~0.78. 차이는 좌상에 집중되고 R에 따라 커진다.
- l1 maxwin(a43-fullB, R=256의 fullA-b43): argmax가 중앙 (12,12)과 우하단
  (28,28) 사이를 이동하나 4사분면 mean은 17~34로 균일. bilevel 디더 양상 전역
  분포.
- 원인 단정 없음. edge/texture 연관 관찰 기록에 그친다.

## 14. EXIF / PGM / Cache

- EXIF: flip 4파일 전부 `orient=0`, 전수 집계 `orient_applied_files=0`.
  회전 JPEG 비교 미수행 유지. flip 원인과 무관하므로 신규 픽스처 추가 안 함.
- PGM: `pgm_fallback_files=0`. PGM 경로 미검증 유지. `readPgmFile`은 P5
  전용·`maxv` 미정규화를 코드로 재확인 (`src/image_decoder.cpp:88-91`).
- Cache: 공개 `verifyImagePair` 동일 파일 2회 호출 —
  miss `decodeMs=1.3457` (misses 2, score 94.9033),
  hit `decodeMs=0.0000` (hits 2, score 동일 94.9033).
  hit 비용을 후보 효과에 포함하지 않는다. 핵심 비교는 miss다.

## 15. 전체 groups 타당성 조사 결론

전스캔 groups 비교에는 후보 버퍼를 `verifyImagePair`→`verifyBuffersFor`→스캔
경로에 넣어야 하며, 이는 생산 호출 경로 변경 또는 스캔 전체의 병렬 재구현을
요한다. 비용이 크고, sampled verdict(1691쌍×5R, flip 0)가 DEFERRED 판정에
충분하므로 **구축하지 않는다**. 필요성 판단 완료로 기록한다.

## 16. 세 질문 답 + 판정

- Q1: 차이 발생 지점 = 2단계 Fant 체인 + 중간 8-bit 양자화 + nearest-neighbor
  crops. 수치로 특정됨 (§7, §10, §12).
- Q2: 알고리즘(Fant vs nearest) + 해상도(중간 업샘플 발명) + 스텝 수(2 vs 1)
  복합. 단일 원인 아님.
- Q3: R 경계 flip은 artifact였음. 순수 쌍에는 경계 없음.
- Q4: tiny bilevel/edge 이미지에서 증폭. EXIF 무관.
- Q5: 바이트 동등을 복원하는 해상도는 존재하지 않음 (체인 자체가 다름).
  verdict-band 정책 없이는 채택 불가.

# MediaSimilarityFinder v0.9.4.151 — Audit finding fixes (adoption scope, cancel/fail consistency, save failure)

Baseline `0.9.4.150` → this build `0.9.4.151`.
CPU CTest **126/126**, GPU CTest **127/127** (one new `ui_date_sort_test`).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` / `kProtocol 1` unchanged (judgement/schema unchanged).

## 1. Why the change was needed

- The 0.9.4.150 audit proved four confirmed defects. (1) Partial-scope Test Mode adoption deleted out-of-scope rows (P0, data loss). (2) Cancel after re-analysis approval and (3) analysis-failure-only completed scans pruned stale pairs in the DB while the GUI kept the old view (P1). (4) Match-save failures were ignored and still reported "Scan complete" (P1). (5) In-scan match checkpoints were silent no-ops inside the engine transaction (nested BEGIN failure, P2).

## 2. Previous structure

- `adoptIndexDatabase()` replaced all six tables wholesale (`DELETE + INSERT SELECT`). `publishTestDiff()` excluded out-of-scope/ignored rows from `removed`, but adoption did not know that distinction.
- The silent re-apply (`reloadIntent`) was scheduled only on the completion path with `analyzed>0`. `onChangedFile` fires at change-detection time, so failed/cancelled files stay in the changed set with no re-apply.
- `persistMatchesSnapshot()` was `void`, dropping `saveMatches()`'s `false` at all five call sites. A failed final save still emitted `results` + `Scan complete` + success telemetry.
- The 5 s / analyze checkpoints ran inside the scan transaction, so `BEGIN IMMEDIATE` always failed (SQLite forbids nesting).

## 3. New structure

- **A**: `AdoptScope{scanImages, scanVideos, ignored}` limits replacement to in-scope rows. Deletes cover only removed paths (files/matches/thumbs/hashes/traces) plus pairs with both endpoints in scope; every scratch row is upserted (`INSERT OR REPLACE`). Out-of-scope rows survive. Meta is key-wise upserted (no delete). Still one transaction.
- **B**: the worker reports the changed-file count in its messages (4th field on CANCELLED, 7th on completion, `|msfChanged=N` suffix on failure — existing positional indices kept, append-only). The GUI re-applies when `analyzed>0 || changed>0`, including after failed scans with the suffix (the error text stays). Silent re-applies no longer clobber the status line (`silentReload_` guard).
- **C1**: `persistMatchesSnapshot()` returns `bool`. A failed final save emits `failed("match index save failed...")` with no `results`/`finished` (the DB keeps the old set). Checkpoint failures are logged only.
- **C2**: `Database::txActive_` tracking plus a SAVEPOINT branch in `saveMatches()`. Inside a caller transaction the savepoint keeps the same all-or-nothing contract, so in-scan checkpoints actually persist (file-row checkpoints always worked).
- Regression pins: e2e `Test 1g2` (failure-only scan view consistency), `Test 1h` (ignored + Yes preserves out-of-scope rows/pairs), `crash_diagnostics_test` §4 (`MSF_TEST_FAIL_PERSIST` injection yields `failed`, never `finished`), `ui_date_sort_test` (new CTest, creation-date descending/ascending order).

## 4. Resolved state

- Images-only / videos-only / ignored Test Mode Yes no longer deletes out-of-scope files/matches/thumbs/content_hash/file_trace rows.
- Cancelled, failed, and failure-only scans leave the view consistent with the stored pair set (both reflect the pruning).
- Save failures report `failed` with no success message or telemetry.
- In-scan match checkpoints actually persist (the kill/crash durability comments are now true).

## 6. Impact and limits

- Judgement, storage, protocol, engine/DB/schema/cache unchanged. No DB version bump (same tables, same transaction).
- After a final-save failure, file rows may be committed while matches keep the old set. Recoverable via the next Sequential scan or re-verify, and the failure is now visible so no silent divergence remains.
- The `finished`/`failed` message field additions are append-only and keep existing positional indices.

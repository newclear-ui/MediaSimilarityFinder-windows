# MediaSimilarityFinder v0.9.2.73 — Accepted Audit Items (SSIM Gate, QuickLook, Docs)

## Need for change
Accepted items from the v0.9.2.68 comprehensive audit: (1) L3 SSIM ran even on failing cells and could promote them via blending (contradicting the "gate" comment, wasting CPU), (2) QuickLook first launch blocked GUI input up to 2.5s, (3) pipe wildcard could hit another session, (4) exe-path static cache went stale, (5) four doc drifts (llms version/count, STRUCTURE count, README.ko/en duplicate rows).

## Previous structure
- SSIM blend ran on every cell with no threshold pre-check. Failing cells were judged after blending
- QuickLook waited out launches in an `msleep` loop. First pipe match won. Empty paths cached forever

## New structure
- **Explicit SSIM gate**: only `sim>=threshold` cells run SSIM. Failing cells keep the legacy reject (zero cost, no promotion). Passing-cell blend unchanged
- **Async QuickLook**: post-launch `QTimer::singleShot` 100ms polling (max 25) + `quickLookStarting` status. No GUI block
- **SID match**: exact current-user pipe match, first-match fallback only when SID unavailable
- **Re-probe**: empty or stale exe cache re-probes every time (menu-open frequency makes cost irrelevant)
- **Docs**: llms 0.9.2.72/54 tests, STRUCTURE 54, README.ko/en duplicate 0.9.2.65 rows deleted
- Version strings unified → 0.9.2.73

## Resolved situation
- SSIM cost confined to passing cells. Failing-cell promotion removed (matches Grok's gate design)
- First QuickLook launches keep input alive. Cross-session mispick and restart requirements gone

## Validation
- Core+GUI Release build: PASS, **CTest 54/54 PASS**
- `--version` 0.9.2.73, `--smoke` exit 0 (offscreen), `quicklook_pipe=ok`
- CUDA algorithms unchanged (common layers only)
- Build lesson: the moc error (member misplaced into the slots section) slipped past the `Error C` grep. Full-build checks must use `(?i)error`

## Future impact
- Low-H/high-S pairs may now drop with recall slightly reduced. Intended; covered by e2e
- Remaining audit items (long-term observation, real-machine validation, GUI lifecycle test) stay next-cycle candidates

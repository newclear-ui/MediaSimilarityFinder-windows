# MediaSimilarityFinder 0.9.2.12 — 빌드 기록

**중요 변경**

0.9.2.13는 상주 실시간 모니터의 비교 경로와 Windows 이벤트 처리 안정성을 강화한 빌드이다.

## 변경 사항
1. **상주 CandidateIndex 비교**
   - `MediaSearchEngine::compareFingerprint()`가 매번 SQLite 전체 행을 선형 순회하지 않고 이미지/비디오별 resident CandidateIndex를 사용한다.
   - 임계값에서 허용되는 Hamming distance 범위만 후보로 가져온 뒤 기존 similarity 계산으로 최종 판정한다.
   - upsert/remove 시 resident index를 재구성하여 DB와 비교 캐시의 일관성을 유지한다.

2. **비교 루트 소유권 명확화**
   - 각 비교 엔진에 실제 comparison root를 함께 보관한다.
   - 비교 루트에 새 파일이 추가될 때 해당 파일을 모든 DB에 중복 기록하지 않고 실제 포함 루트의 index만 갱신한다.
   - 삭제도 동일한 root ownership 규칙을 적용한다.

3. **Windows 경로 변환 수정**
   - UTF-8 → UTF-16 변환 버퍼 크기를 실제 null terminator까지 포함하도록 수정했다.
   - 잘못된 버퍼 크기로 인한 경로 손상 가능성을 제거했다.

4. **ReadDirectoryChangesW overflow/resync**
   - 이벤트 버퍼 overflow 등으로 0-byte 결과가 발생하면 해당 root를 재귀 탐색하여 현재 존재하는 미디어를 다시 queue에 넣는다.
   - 실제 분석은 기존 안정 파일 검사와 load throttle을 거치므로 resync가 즉시 CPU/GPU 폭주로 이어지지 않는다.

5. **SystemLoadMonitor 인스턴스 독립화**
   - CPU/GPU 샘플링 상태를 static 공유 값에서 인스턴스 멤버로 변경했다.
   - 여러 monitor/load monitor 인스턴스가 서로의 샘플 상태에 영향을 주지 않는다.

6. **회귀 테스트 강화**
   - monitor test에 1,000개 비교 항목을 추가하고 CandidateIndex 기반 threshold 비교 결과를 검증했다.

## 검증
- Release core build: PASS
- 회귀 테스트: **26/26 PASS**
- real video decode: PASS
- CandidateIndex benchmark: N=6000, indexed 415.432 ms / linear 1542.9 ms / **3.71x**

## 알려진 제한
- 현재 환경에는 CUDA toolkit과 Qt6가 없어 실제 Windows/NVIDIA/Qt runtime 검증은 아직 수행하지 못했다.
- resident CandidateIndex는 upsert/remove 시 전체 resident index를 재구성한다. 상주 모니터의 일반적인 이벤트 빈도에서는 단순하고 안전한 방식이며, 초대형 index에서는 향후 삭제 가능한 BK-tree 또는 더 정교한 증분 index 구조를 검토할 수 있다.

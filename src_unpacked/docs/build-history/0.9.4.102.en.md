# MediaSimilarityFinder v0.9.4.102 — Synchronous detail-form activation

Baseline `0.9.4.101` -> this build `0.9.4.102`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

User measurement (0.9.4.101, two screenshots + `msf_scan.log`): after Load, group-then-file select shows the preview but all detail text is blank; some rows flash for <0.5s then vanish. The data path is healthy (9 rows, valid file, otherwise silent). So: presentational blank — rows exist but never paint.

## 2. Previous structure

- `refreshDetail()` rebuilt the form object and left geometry to the event loop's deferred activation.
- Under thumbnail-burst traffic (9000 groups, linear scans per arrival + `singleShot(0)` flush chains + 600ms ticks) the deferred activation can be postponed indefinitely. The fixed-size preview paints independently of layout, yielding blank text beside live art.
- Middle/right grids force their own layout passes for the same reason. The detail form was the only one that didn't.

## 3. New structure

- **Synchronous `detailForm_->activate()`** right after adding rows (cheap at 9 rows, idempotent). Guarantees committed geometry regardless of invalidation storms.
- **Tripwire gating**: log only while the main window is visible. Background fileMeta refreshes on a hidden window report `vis=0` normally and would drown the real signal.

## 4. Result

- Detail rows hold paintable geometry from construction. Later invalidations keep the last valid geometry instead of returning to blank.
- `detailAnomaly` now fires only on genuine visible-window anomalies.

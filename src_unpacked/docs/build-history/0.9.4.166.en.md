# MediaSimilarityFinder v0.9.4.166 — Timestamp-Trust Investigation + NOPTS Counting (P1)

Baseline `0.9.4.165` → this build `0.9.4.166`.
CPU CTest **135/135**, GPU CTest **136/136** (1 new CTest: video_timestamp_basis_test).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` all unchanged.

## 1. Why the change was needed

- Two external-review P1 items: (a) no `start_time` compensation, so per-container PTS bases can shift sample alignment; (b) NOPTS frames get the requested time substituted, putting assumed (not observed) times into fingerprints. Both would change verdicts, so measure first without touching production code.

## 2. Previous structure

- `open()`/`framesAt()`/`frameAtColor()`: seek with `seconds × AV_TIME_BASE`, compare raw `best_effort_timestamp × time_base`. No `start_time` reference.
- NOPTS fallback to `targets[next]` (3 sites: sequential sweep, drain, sparse executor). No counting.

## 3. New structure

- No product-code behaviour change (judgement/storage untouched). Instrumentation and pins only:
- `VideoDecoder::framesAt/framesAt96Plus32` gain `noptsOut` (defaulted null; existing callers unchanged). Counts NOPTS substitutions in the sequential sweep loop and drain. The sparse executor and CLI fallback are out of scope, documented.
- `VideoBuildStats.noptsFrames` → `TelemetryRecorder.addVideoNopts` → `videos.noptsFrames/State` (additive, reset in `start()`, measured zero on cache hit).
- Regression pin: new `video_timestamp_basis_test` — same testsrc muxed with start_time=0 vs +2.5 s; structural invariants asserted (build success, complete samples, monotonicity, range, zero NOPTS) and the shift printed as observation.
- `analyze_telemetry_test` measured/null contracts; `video_complete_test` baseline asserts `noptsFrames==0`.

## 4. Results (RTX 3080 Ti, identical 8 s testsrc)

| File | start_time | kept | first kept ts | last kept ts | nopts |
|---|---|---|---|---|---|
| clip0 | 0.0 | 2 | 0.0 | 5.0 | 0 |
| clipOff (+2.5 s) | 2.5 | 3 | 2.5 | 8.0 | 0 |

- The whole kept grid rides with the stream offset (first-shift = exactly 2.5). Identical visual content gets different sample sets (kept 2 vs 3 — the 8.0 endpoint is slack-excused on one side and exactly hit on the other).
- Conclusion: the same video with different container start offsets fingerprints differently and can miss as a duplicate. The review's concern is confirmed by measurement.

## 6. Impact and limits

- Judgement, storage, protocol, versions, engine unchanged. No cache invalidation. NOPTS fail-closed and start_time basis fixes will be decided in a separate build after observation data + user approval.
- VFR / edit-list / negative-PTS / trimmed-re-encode matrices need real files and stay user-dataset-gated.
- Time-axis representativeness of kept-frame selection stays a post-V2/V3-gate task, not in this build.

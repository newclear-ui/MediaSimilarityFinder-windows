# MediaSimilarityFinder v0.9.2.56 — Scan-Time UI Freeze Fix (Thumbnail Decode Budget)

## Need for change
The UI froze even on Balanced during scans (not responding, pause/stop dead, force-quit required). The v0.9.2.54 progress throttle (150ms) was not enough; the real cause was unbounded thumbnail decoding on the GUI thread every 600ms UI tick.

## Previous structure
- Every 600ms `uiTimer` ran `rebuildGroups→refreshGroupList→refreshFileViews`. `fillPair` called `fileThumb()` per group (uncached = shell COM, image decode, FFmpeg seek). Tens-to-hundreds of ms per video × hundreds of groups = multi-second blockage per tick
- `thumbCache_` did a full `clear()` past 3000 entries → a perpetual re-decode storm on large scans (thousands re-decoded every tick). The event loop starved so pause/cancel clicks were never processed
- `refreshGroupList` rebuilt widgets for the visible AND the hidden tab every time (tens of thousands of items + wasted decodes)

## New structure
- **Decode budget**: 4 fresh decodes per tick (`kThumbBudgetPerTick`, `thumbBudget_` member reset each tick). Cache hits always free. Over-budget items show a file-type icon without caching, retried on a later tick. The explicitly selected file (detail preview) uses `bypassBudget` and always decodes
- **Chunk eviction**: past 3000 entries, evict 750 instead of clearing all. 2250 hits survive, ending the re-decode storm
- **Visible tab only**: `refreshGroupList` fills just the current tab's `fillPair`. Tab switches refresh via `activateTab`, so the hidden side lazily stays consistent
- Version strings unified → 0.9.2.56

## Resolved situation
- Per-tick GUI blockage capped by the budget (hundreds of ms). Pause/stop/close always respond. As groups grow, placeholder icons appear first and thumbs fill in progressively
- No more cache storm past 3000 thumbnails

## Validation
- Core+GUI Release build: PASS, **CTest 44/44 PASS**
- `--version` 0.9.2.56, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)

## Future impact
- Budget 4, eviction 750, cap 3000 are tunable; lower the budget on weak machines
- A cap for single giant groups (10k+ files of widget churn) remains a candidate
- Background-thread thumbnails would need structural changes; kept as a next-step candidate

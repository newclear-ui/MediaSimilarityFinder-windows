# MediaSimilarityFinder v0.9.3.16 — crop-only 판정 분리·정지 응답성·컬러 미리보기

## 변경 필요성
- 서로 다른 두 영상(1:1 crop 유사도 87.5, full 유사도 42%, temporal 0)이 유사한 영상으로 판독됐다. crop-only L1 적중이 그대로 매치로 확정되는 구조가 원인이다.
- 정지 버튼을 눌러도 검색이 계속되고, 대기 팝업이 scanFinished 때늦게 떴다. 영상 분석 future 일괄 대기(`f.get()`)와 temporal chunk(4096쌍) 내부에 중단 폴링이 없기 때문이다.
- 툴바 GPU 체크박스가 "모니터 GPU"로 표시되면서 스캔 GPU까지 껐다. 스캔 GPU 활성 여부를 사용자가 알 수 없었다.
- 회색 engine 썸네일이 컬러 디코더보다 먼저 `pm`을 채워 `isNull` 게이트가 FFmpeg 컬러 디코딩을 영원히 건너뛰었다. 상세 미리보기가 흑백으로 고정된 직접 원인이다.

## 기존 구조
- `process()`·`bestAgainst()`·`addAndMatch()`가 crop 포함 최대값을 그대로 매치 확정했다.
- `cancelScan()`은 플래그만 세우고 팝업을 띄우지 않았다. 팝업은 `scanFinished`에서만 생성됐다.
- `processVideoRange`의 `f.get()` 루프와 `flushVideo` 청크 내부에 중단 체크가 없었다.
- `fileThumb()`이 영상 회색 썸네일을 먼저 채운 뒤 shell/FFmpeg를 시도했다.

## 변경 구조
- 영상 판정은 full-frame 적중(`bestFull`: normal+mirror)일 때만 short-circuit한다. crop-only 적중은 duration 게이트·anchor·temporal(DTW+SSIM, `crop_temporal_score` 포함)로 확인한다. 진짜 크롭 중복은 temporal이 잡고, 무관한 영상은 탈락한다.
- 라이브 스트리밍(`addAndMatch`)의 영상 경로는 full 적중만 즉시 송출하고, crop-only는 최종 temporal 판정까지 보류한다.
- `cancelScan()` 클릭 즉시 "정지 처리 중입니다…" 팝업을 띄우고, `scanFinished`/`onResults`가 이어받아 리포트 재구축 후 닫는다. 스캔 중 창 닫기 확인은 유지한다.
- `f.get()` 사이와 `flushVideo` 청크·pair 루프에 중단 체크를 넣어 정지 후 in-flight만 조인하고 신규 작업을 시작하지 않는다.
- 툴바 체크박스를 "GPU 가속"으로 바로잡고 스캔용 툴팁(`scanGpuTip`)을 분리했다. 모니터 설정 다이얼로그의 체크박스는 그대로 둔다.
- `fileThumb()` 영상 순서를 디스크(회색 제외) → shell → FFmpeg 컬러 → 회색 engine 폴백으로 바꿨다. 회색은 최후 수단이며 저장하지 않는다.
- 검색엔진 판정 버전을 1.3.0 → 1.4.0으로 상향했다. 저장 쌍은 다음 스캔에서 자동 재검증된다.
- `tests/video_degenerate_hash_test`에 crop-only 케이스를 추가했다.

## 해결된 상황
- 문제 쌍(c1 87.5/full 42%/temporal 0)이 매치되지 않는다. 동일 full 해시 쌍은 여전히 매치된다.
- 정지는 클릭 즉시 팝업과 함께 수렴하고, 일시정지 경유 없이 동작한다.
- 스캔 GPU on/off가 툴바에서 명확해졌다.
- FFmpeg 컬러 디코딩이 성공하는 영상은 상세 미리보기가 컬러로 표시된다.

## 향후 영향
- crop-only 적중은 이제 temporal 디코딩을 반드시 타므로, 크롭 변형이 많은 corpus에서는 temporal 부하가 늘어난다.
- 정지 수렴 시간은 in-flight 영상 분석 1개 분량으로 하한이 정해진다. 완전한 선점형 중단은 디코더 협력이 필요해 이번 단계 범위 밖이다.
- 미리보기는 shell/FFmpeg 실패 시 여전히 회색 폴백을 보여준다. 이는 의도된 최후 수단이다.

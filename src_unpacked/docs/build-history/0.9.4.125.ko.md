# MediaSimilarityFinder v0.9.4.125 — QuickLook 파이프 유실 방지 (overlapped+타임아웃) + color_thumb 현행 유지 판정

기준선 `0.9.4.124` → 본 빌드 `0.9.4.125`.
CPU CTest **124/124**, GPU CTest **125/125**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

- 우클릭 경로 외부 I/O 제거(.124) 후속: 메뉴 생성은 I/O-free가 됐지만, QuickLook 액션의 파이프 전송(`quickLookSendMessage`)은 여전히 **동기 `WriteFile`**이었다. 서버가 연결된 채 읽지 않는 wedged 상태면 GUI 스레드가 무한 대기한다. 실기 보고는 없으나, 미봉합 시 UI 응답성 계약에 구멍이 남는다.
- color_thumb production correction 결정이 .113(R1: no-FFmpeg SKIP) 이후 보류 중이었다. R1 이후 추가 증거 수집을 위해 현행 테스트·생산 경로를 대조했다.

## 2. 기존 구조

- `quickLookSendMessage`: 동기 `CreateFileW` + 동기 `WriteFile` + 즉시 close. 정상 서버에는 수십~수백 바이트라 즉시 반환하므로 문제가 드러나지 않았다.
- 테스트는 정상 서버 경로만 검증(정확 바이트 단언, `quicklook_pipe=ok`).

## 3. 변경 구조

- 송신을 overlapped I/O + 5초 대기로 변경. 타임아웃 시 `CancelIo` 후 실패 반환하며, 호출자(`previewSelectedQuickLook`/폴링)는 기존 실패 경로(상태 메시지)로 처리한다. open은 동기 유지(서버 없음/점유 중 즉시 실패).
- 회귀 테스트에 wedged 서버 케이스 추가: 연결됨·읽지 않음·64B inbound 버퍼 + 4MB 페이로드. 수정 전 해당 케이스에서 테스트 바이너리가 **60초 hang**(외부 kill로 FAIL 확인), 수정 후 **5.0초에 실패 반환**.
- color_thumb: 코드 변경 없음. 판정(확정 대기, 권장: 현행 유지) — 테스트가 생산 디코딩 함수(`decodeColorAspect`·`frameAtColor`)를 직접 가드하고 전체 스위트에서 PASS, 생산 경로(`ThumbnailStore::wicArt/ffmpegArt`)는 동일 함수를 사용, gray 엔진 art는 디스크에 영속화하지 않음(메모리 한정 폴백). 결함 증거 없음.

## 4. 해결된 상황

- 파이프 유실 시나리오가 bounded(최대 ~5초 후 실패 처리). 재현(구버전 hang)→수정→검증(5.0초 실패) 완료.
- color_thumb: "결정 대기" → "현행 유지 권장, 확정 대기"로 상태 명확화(작업 로그에 근거 기록).

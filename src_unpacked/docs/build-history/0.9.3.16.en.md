# MediaSimilarityFinder v0.9.3.16 — Crop-Only Verdict Split, Stop Responsiveness, Color Previews

## Need for change
- Two different videos (1:1 crop similarity 87.5, full similarity 42%, temporal 0) were reported as similar. A crop-only L1 hit was finalized as a match outright.
- Stop did not stop the search, and the wait popup only appeared late at scanFinished. The video-analysis future join loop (`f.get()`) and the temporal chunk internals (4096 pairs) had no stop polling.
- The toolbar GPU checkbox was labeled "Monitor GPU" while gating scan GPU too, so users could not tell scan GPU was off.
- The gray engine thumbnail filled `pm` before the color decoders, so the `isNull` gate skipped FFmpeg color decoding forever. This pinned detail previews to black and white.

## Previous structure
- `process()`, `bestAgainst()`, and `addAndMatch()` finalized the crop-inclusive maximum as a match.
- `cancelScan()` only set the flag with no popup; the popup was created in `scanFinished`.
- No stop checks inside the `processVideoRange` join loop or `flushVideo` chunks.
- `fileThumb()` filled the video gray thumb first, then tried shell/FFmpeg.

## New structure
- Video verdicts short-circuit only on a full-frame hit (`bestFull`: normal+mirror). Crop-only hits go through the duration gate, anchors, and temporal (DTW+SSIM, including `crop_temporal_score`). True cropped duplicates still match via temporal; unrelated videos are rejected.
- Live streaming (`addAndMatch`) emits full video hits immediately and withholds crop-only pairs for the final temporal verdict.
- `cancelScan()` shows the "Stopping…" popup on the click; `scanFinished`/`onResults` take it over and close it after the report rebuild. The mid-scan close confirmation is unchanged.
- Stop checks between future joins and inside `flushVideo` chunk/pair loops: after stop, in-flight analyses join but no new work starts.
- The toolbar checkbox now reads "GPU" with a scan tooltip (`scanGpuTip`); the monitor settings dialog keeps its own checkbox.
- `fileThumb()` video order is now disk (gray excluded) → shell → FFmpeg color → gray engine fallback. Gray is a last resort and is never persisted.
- Raised the engine verdict version 1.3.0 → 1.4.0. Stored pairs auto-revalidate on the next scan.
- Added the crop-only case to `tests/video_degenerate_hash_test`.

## Resolved situation
- The reported pair (c1 87.5 / full 42% / temporal 0) no longer matches. Identical full-hash pairs still match.
- Stop converges with an immediate popup, without needing pause first.
- Scan GPU on/off is now explicit in the toolbar.
- Videos whose FFmpeg color decode succeeds show color detail previews.

## Validation
- `video_degenerate_hash_test` with the new crop-only case PASS.
- CUDA Release build PASS, **CTest 62/62 PASS**.
- CPU-only Release build PASS, **CTest 61/61 PASS**.
- Portable v0.9.3.16 creation and smoke PASS, `--version` 0.9.3.16.

## Future impact
- Crop-only hits now always cost temporal decodes, so temporal load rises on corpora with many crop variants.
- Stop convergence is lower-bounded by one in-flight video analysis; fully preemptive cancellation needs decoder cooperation and is out of scope for this step.
- Previews still fall back to gray when shell/FFmpeg fail. That is the intended last resort.

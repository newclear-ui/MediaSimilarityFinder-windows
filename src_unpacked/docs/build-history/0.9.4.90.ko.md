# MediaSimilarityFinder v0.9.4.90 — 그룹 정렬에 "없음" 추가 + 스캔 중 정렬 잠금

기준선 `0.9.4.89` → 본 빌드 `0.9.4.90`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변(GUI 전용 변경).

## 1. 변경 필요성

그룹 목록 정렬은 `유사도 내림차순` / `이름 오름차순` 두 가지뿐이었다.
정렬이 켜져 있는 동안 스캔이 진행되면, 새로 인덱스된 파일이 만든 그룹을 **정렬 순서에 맞춰 목록에
계속 끼워 넣어야** 한다. 유사도순은 매치가 늘 때마다 기준값이 바뀌므로 그룹 순서가 계속 요동치고,
그 과정에서 GUI 목록이 오류(깜빡임/스크롤 튐/빈 목록 재발)를 일으켰다.

## 2. 기존 구조

- `sortBox_` 항목: `0=유사도`, `1=이름` 두 개.
- `rebuildGroups()`가 매 갱신마다 `groups_`를 유사도 또는 이름으로 정렬.
- 스캔 중에도 정렬 콤보가 활성 상태였고, 스트리밍 매치마다 정렬이 재적용됨.

## 3. 변경 구조

- `sortBox_`에 **`2=없음(None)`** 항목 추가. `없음`은 정렬하지 않고 **union-find 빌드 순서를 유지**
  → 새 그룹은 목록 끝에 **append**만 된다.
- **스캔 중에는 정렬을 `없음`으로 고정**하고 콤보를 **비활성화**한다
  (`setRunning(true)`에서 `preScanSort_`에 사용자 선택을 저장 후 `없음`으로 전환, `updateSortEnabled()`로 잠금).
- **인덱싱·후처리가 끝나면**(`setRunning(false)`) 콤보를 다시 활성화하고 **사용자의 사전 선택을 복원**
  → 이후 유사도순/이름순으로 변경 가능.
- `updateSortEnabled()`: 그룹 탭(사진/영상)이고 스캔 중이 아닐 때만 콤보 활성. `activateTab()`도 이 헬퍼를 사용.

## 4. 해결된 상황

- 스캔 중 그룹 목록은 정렬을 하지 않아 **재배치/끼워넣기가 사라짐** → 목록 요동·오류 제거.
- 스캔 중 정렬 변경 자체가 불가(콤보 비활성)하여 정의되지 않은 상태 전이를 차단.
- 스캔 완료 후 사용자가 유사도순/이름순(또는 없음)을 자유롭게 선택.

## 5. 검증

```text
CPU Release CTest 100% tests passed out of 122
GPU Release CTest 100% tests passed out of 123
GUI/Backend --version 0.9.4.90
```

- **사용자 육안 확인 필요**: 스캔 중 정렬 콤보가 비활성 + `없음`으로 표시되고, 완료 후 활성화되어
  유사도순/이름순 변경이 되는지, 스캔 중 목록이 더 이상 요동치지 않는지.

## 6. 향후 영향 및 한계

- GUI 전용 변경. 엔진/DB/schema/cache 불변.
- `없음`은 `QHash` 버킷 순서(런 내 안정)를 그대로 노출하므로 사용자에게 "의미 없는 순서"로 보일 수 있다.
  이는 스캔 중 목적(정렬 회피)에 부합하며, 완료 후 유사도순/이름순을 쓰는 것을 전제로 한다.
- 정렬 선택은 세션 간 저장하지 않는다(종전과 동일).

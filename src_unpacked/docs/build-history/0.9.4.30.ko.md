# MediaSimilarityFinder v0.4.30 — CPU 사용량 10~90% 자동 정규화

## 변경 필요성

CPU 사용량 스핀박스는 `1~100`을 허용했지만, 사용자 정의 정책은 CPU 값을
`5~100`으로만 정규화했다. 그래서 `1~4`를 입력하면 화면에는 입력값이 남고
내부 정책에는 `5`가 들어가는 불일치가 생겼다. 이번 요청은 이 불일치를 없애고
새로운 사용자 CPU 허용 범위를 `10~90`으로 고정한다.

## 기존 구조

- CPU 입력 위젯은 단일 `QSpinBox`이며 CPU 슬라이더는 없다.
- 범위: `1~100`.
- 사용자 입력은 `customResourceChanged()`를 통해 `ResourceMode::Custom` 정책으로
  전달된다.
- 사용자 정의 CPU는 `make_policy()`에서 `5~100`으로 고정되고, 사용자 정의 GPU는
  기존 내부 호환 범위를 유지한다.
- CPU 정책은 `QSettings`에 저장되지 않으며, 시작값은 기본 Balanced 정책의
  `55`이다.
- 스케줄러 내부 `cpuFloor`는 별도 안정성 하한이며 사용자 CPU 상한과 같은 값이
  아니다.

## 변경 구조

- `msf::kUserCpuPercentMin = 10`과 `msf::kUserCpuPercentMax = 90`을
  `resource_policy.h`에 단일 기준으로 선언했다.
- `msf::normalize_user_cpu_percent()`를 추가하고 사용자 정의 CPU 경로에서만
  사용했다.
- 사용자 정의 CPU 입력은 다음 규칙을 따른다.

```text
입력값 < 10   → 10
10 ≤ 입력값 ≤ 90 → 입력값 그대로
입력값 > 90   → 90
```

- `QSpinBox` 범위도 `10~90`으로 바꾸고, 핸들러에서 정규화된 값을 먼저 표시한
  뒤 정책을 만든다. 기존 `blockSignals` 패턴을 그대로 사용하므로 교정 쓰기가
  슬롯을 재귀 호출하지 않는다.
- 프리셋 값은 변경하지 않았다.

```text
Maximum  → 90
High     → 75
Balanced → 55
Gaming   → 25
Manual   → 사용자 입력의 10~90 정규값
```

- GPU 백분율, GPU ON/OFF, Adaptive Scheduler, worker/batch 계산식은 변경하지
  않았다.

## 해결된 상황

다음 경계가 모두 통과했다.

| 입력 | 화면 | 정책 |
|---:|---:|---:|
| -100 | 10 | 10 |
| -1 | 10 | 10 |
| 0 | 10 | 10 |
| 1 | 10 | 10 |
| 9 | 10 | 10 |
| 10 | 10 | 10 |
| 11 | 11 | 11 |
| 50 | 50 | 50 |
| 89 | 89 | 89 |
| 90 | 90 | 90 |
| 91 | 90 | 90 |
| 99 | 90 | 90 |
| 100 | 90 | 90 |
| 120 | 90 | 90 |

QSpinBox 범위 자체가 음수와 초과 입력을 허용하지 않으므로, 정책 함수는
`ScanWorker`처럼 위젯을 거치지 않는 호출 경로까지 같은 규칙으로 보호한다.

## 향후 영향

- 사용자 CPU 설정은 항상 `10~90`이며 화면값과 정책값이 같다.
- 앞으로 사용자 CPU 정책을 바꾸는 코드는 `normalize_user_cpu_percent()`를
  재사용해야 한다.
- 내부 스케줄러 하한은 사용자 정책과 분리된 채로 둔다.
- 이 변경은 D3 후속 최적화와 무관하며, 성능 향상을 주장하지 않는다.

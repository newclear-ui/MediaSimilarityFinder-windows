# MediaSimilarityFinder v0.9.4.10 — Node C2: Initial Calibration

C2 검증 기준점. Profile 없음·재사용 불가 시 짧은 calibration을
실행하고 writer·telemetry·initial-estimate를 활성화한다.
엔진 1.5.0·DB 1.0.3·캐시 v9 불변, benchmark schema 1→2.

## 변경 필요성
- C1까지 저장소·판정·전달 API가 있었으나 writer가 없어 live에서
  휴면이었다. 첫 calibration 없이는 profile baseline이 영원히 비었다.

## 기존 구조
- `CalibrationTelemetry`는 구조만, scheduler의 profile 입력은
  `profileBaseline*` 필드만 있었다.

## 변경 구조
- 신규 `src/calibration.h/.cpp` — `Calibrator::run(cfg, GpuBackend*)`:
  - CPU fingerprint: 합성 32x32 프레임 300개 단위 해시(엔진과 동일
    `perceptual_hash_pair_32`, 단일 스레드 순수 단위. 병렬 확장은
    worker 토폴로지라 범위 밖).
  - GPU fingerprint+batch: 64개×6배치 + 웜업 1회 폐기. mirror는 엔진
    측 CPU 담당이라 `hashBatch` rate만 주장한다.
  - resize/conversion·CPU decode·transfer·queue·HW decode는 명시
    상태(not_measured/not_available). 사용자 파일 스캔 금지(결정적
    합성 입력), phase별 budget, 전체 8초 guard. 예외·실패는 스캔에
    전파되지 않는다.
- Probe 수치 근거: CPU 300개·GPU 64×6은 0.1초대 wall로 budget 8초에
  한참 못 미친다. 여유는 저사양 머신의 편차를 흡수한다.
- confidence 0.8/0.5 (full/partial): 단일 실행·이력 없음이라 보수적.
  live가 항상 우선이라 과신 불가.
- 엔진: Missing/Hard 판정 시 1회 calibration → writer 저장 →
  당 스캔에 estimate 적용. writer 실패 무시. Exact/Soft는 재측정
  없이 재사용(C3 drift 영역). `videoGpu_` 핸들로 정책-off와
  무장치를 구분한다.
- telemetry 초기 용량은 profile tier(`baseCapacities()` 신설)로
  보고해 profile-fed 스캔이 스레드/SM 숫자를 가장하지 않는다.
- schema v2: calibration 6개 metric state 추가.

## 선택 이유
- decode는 walk/분석 스트리밍 구조상 스캔 전 파일 집합이 없어 측정
  불가(C3+ 기회관측 후보로 명시). resize는 디코더 내부라 분리 불가.
  transfer는 B5에서 커널 분할 부재 확정. 측정 불가 항목 추정은 금지.
- CPU-only 완전(completed), GPU-off는 CPU만 측정 후 partial.
  policy-off를 not_measured, 무장치를 not_available로 구분한다.

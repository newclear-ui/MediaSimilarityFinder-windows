# MediaSimilarityFinder v0.9.4.146 — 정렬 표시 일치 + 백엔드/GUI 단독·중복 실행 방지

기준선 `0.9.4.145` → 본 빌드 `0.9.4.146`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

- 실기(C-5): 검색을 시작하면 정렬 콤보가 "없음"으로 잠기지만 **목록은 마지막 정렬(크기/이름 등) 순서를 유지**해 콤보와 화면이 불일치했다. 검색이 끝나 이전 정렬로 복원되어도 목록이 다시 정렬되지 않았다.
- 백엔드 수명주기 요청:
  - 백엔드 단독 실행(더블클릭/직접 실행) 방지, GUI 없으면 자동 종료
  - GUI 종료 후 백엔드가 남는 문제 해결
  - 백엔드 중복 실행 방지
  - GUI도 복수 실행 방지

## 2. 기존 구조

- `setRunning(true)`가 `blockSignals`로 콤보를 None으로 바꾸고 재정렬하지 않았으며, `setRunning(false)`도 콤보만 복원하고 목록은 그대로 두었다.
- 백엔드는 `--backend --nonce`만 있으면 실행되었고, GUI와의 부모 관계/생존을 확인하지 않았다. GUI가 비정상 종료되면 백엔드가 남을 수 있었다.
- GUI는 단일 인스턴스 보호가 없었고, 백엔드도 중복 방지가 없었다.

## 3. 변경 구조

- **정렬**: 스캔 시작 시 None으로 잠글 때 목록을 None 순서로 1회 재구성하고, 스캔 종료 시 이전 정렬을 복원하면서 목록도 그 순서로 재구성한다(실제 스캔 종료에만 적용, `wasScanning` 가드). 0.9.4.142의 뷰 동결은 유지되어 중간 churn은 없다.
- **백엔드 실행 검증**:
  - 슈퍼바이저가 `--parent-pid <GUI PID>`와 환경변수 `MSF_BACKEND_LAUNCHED_BY_GUI=1`/`MSF_BACKEND_PARENT_PID`를 전달.
  - 백엔드는 세 값이 일치하고 부모 프로세스가 살아 있을 때만 서버 모드로 진입한다. 단독 실행은 안내 후 **exit 3**.
  - 부모 감시 타이머(1초)로 GUI가 사라지면 스스로 종료한다(Job Object와 별개의 2차 보호).
  - 사용자 세션당 백엔드 1개: 명명 뮤텍스(`Local\MediaSimilarityFinder.Backend.SingleInstance`)로 중복 실행을 **exit 4**로 거부.
- **GUI 단일 인스턴스**: `Local\MediaSimilarityFinder.Gui.SingleInstance` 뮤텍스. 두 번째 실행은 안내 후 종료(스모크/버전/도움말 모드는 예외).

## 4. 해결된 상황

- 정렬 콤보와 목록 순서가 항상 일치한다(검색 시작 None, 완료 후 이전 정렬 복원).
- 백엔드는 GUI가 실행한 경우에만 동작하며, GUI가 종료/급사하면 남지 않는다.
- 백엔드/GUI 모두 중복 실행이 차단된다.

## 5. 검증

- `backend_e2e_test`(checks=92): **백엔드 단독 실행 거부(exit 3)**, **중복 실행 거부(exit 4)**, no-job 부모 사망 시 워치독 자동 종료(기존 Job Object 단독 보호 가정을 새 2차 보호에 맞게 갱신).
- 실기: GUI 2회 실행 시 두 번째 안내 후 종료, GUI 종료 시 백엔드 프로세스 종료.

## 6. 향후 영향 및 한계

- 백엔드 실행 검증은 환경변수/부모 PID 기반이다(악의적 우회 방지가 아니라 정상 사용자 오실행 방지 목적).
- 테스트용 wedge 백엔드는 워치독 이전에 루프하므로 Job Object로 정리된다(프로덕션 경로 아님).
- 정렬 복원 재구성은 스캔 완료 시 1회 추가되며, 변경 없는 스캔에서도 사용자 정렬을 유지하기 위한 비용이다.

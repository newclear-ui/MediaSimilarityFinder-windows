# MediaSimilarityFinder v0.9.4.149 — 불러오기/재검증 단일 슬롯 통합

기준선 `0.9.4.148` → 본 빌드 `0.9.4.149`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` / `kProtocol 1` 불변 (표시 전용).

## 1. 변경 필요성

- 불러오기(Load)와 재검증(Re-verify)이 툴바에 각각 한 칸씩 차지했다(0.9.4.148에서 재검증이 레이아웃에 추가되며 두 칸 확정).
- 요청: 두 기능을 **한 칸으로 합치고 아래 화살표 메뉴로 선택**한다. 메뉴는 상단 불러오기/하단 재검증, 선택하면 상단 버튼이 바뀌고 누르면 그 기능이 실행되며, 재검증 앞에도 불러오기 스타일의 아이콘을 붙인다.

## 2. 기존 구조

- `refresh_`(QPushButton "📂 불러오기")와 `reverifyBtn_`(QPushButton) 두 버튼이 병렬로 존재했다.
  - 툴바 순서: Load > Re-verify > Scan (`ui_settings_test` 순서 단언).
  - `backend_e2e_test` Test 1b/1c가 각 버튼을 `findChild` 후 클릭했다.

## 3. 변경 구조

- `QToolButton(loadSplitBtn_)` 1개 + `MenuButtonPopup` + `QMenu` 2개 액션으로 통합했다.
  - 메뉴: 상단 `loadSplitLoadAct_`(불러오기), 하단 `loadSplitReverifyAct_`(재검증). 둘 다 checkable.
  - 메뉴 선택(`triggered` → `setLoadSplitMode`)은 상단 버튼의 라벨/툴팁만 바꾸고 `QSettings(ui/loadSplitAction)`에 저장한다. 실행하지 않는다.
  - 상단 버튼 클릭(`clicked` → `executeLoadSplit`)은 현재 모드에 따라 `loadIndex()`/`reverifyIndex()`를 호출한다.
- 아이콘: Load는 기존 📂 유지, Re-verify는 🔄(U+1F504). 메뉴 항목과 버튼이 같은 아이콘+라벨을 쓴다.
- 라벨 갱신은 `retextLoadSplit(UiLang)`으로 분리했다. `buildToolbar()` 시점에도 호출되므로 다른 위젯을 건드리는 전체 `applyStaticTexts()`를 호출하면 안 된다(초기 구현이 SEGFAULT를 냈고 분리로 해결).
- 툴바는 단일 슬롯: merged slot > Scan. 테스트도 함께 갱신했다.
  - `ui_settings_test`: 슬롯의 레이아웃 순서 + 메뉴가 정확히 [Load, Re-verify]인지 단언.
  - `backend_e2e_test` Test 1b/1c/1g: 액션 `trigger()`로 모드 선택 후 버튼 `click()`.

## 4. 해결된 상황

- 툴바 한 칸만 차지한다. 아래 화살표를 눌러 상단 불러오기/하단 재검증 중 선택하면 상단 버튼이 바뀌고, 누르면 선택된 기능이 실행된다.
- 재검증 앞에는 🔄 아이콘이 표시된다. 선택은 저장되어 재시작 후에도 유지된다.

# MediaSimilarityFinder v0.9.4.79 — Index lifecycle management (janitor)

Baseline `0.9.4.78` → this build `0.9.4.79`.
CPU CTest **121/121**, GPU CTest **122/122**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged. No search-verdict or schema change.

## 1. Why the change was needed

- Regression tests scan temporary media folders but resolve indexes under the
  executable directory (`appDir`). After the fixture roots are deleted, their
  index directories stay orphaned under `<appDir>/Index/<folderId>/`.
- Test Mode runs likewise accumulate `<appDir>/TestMode/<unique>/` scratch.
- Per the user request, locations are kept (so resolution and folderId
  contracts stay untouched) and a lifecycle manages them instead.

## 2. Previous structure

- No lifecycle management existed. Orphan indexes could only be removed by hand.

## 3. Changed structure

- New `src/index_janitor.{h,cpp}` (in msf_core). Removal requires ALL of the
  following (conservative by design):
  1. `metadata.json` parses and yields a `rootPath`,
  2. that root no longer exists on disk,
  3. the recorded `lastScan` is at least 7 days old,
  4. the directory mtime itself is at least 7 days old (metadata rewrites use
     atomic rename, so any live scan refreshes it).
- `TestMode` scratch leaves are always regenerable, so only the 7-day
  directory-mtime rule applies. Unparseable, fresh, or anything outside
  `Index/` and `TestMode/` is never touched.
- Runs once at `ScanWorker::run()` start. Bounded walk, never throws, never
  fails a scan; the outcome is one backend-log line
  (`janitor removed index/scratch`).
- Stale roots with non-ANSI names are widened before existence checks, so the
  0.9.4.77 throw class cannot break the sweep.

## 4. Resolved state

- Every scan start now collects orphan indexes and scratch meaningless for
  7+ days.
- Indexes whose roots are alive are never deleted (condition 2).

- Test residue no longer accumulates, so `Index/` holds only roots in use.
- The 7-day rule and conditions live in `kJanitorStaleMs` and the decision
  functions, so policy changes stay easy.

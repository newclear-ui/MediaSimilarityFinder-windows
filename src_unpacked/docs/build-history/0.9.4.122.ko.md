# MediaSimilarityFinder v0.9.4.122 — 우클릭 경로 외부 I/O 제거 (QuickLook 탐색 negative 캐시)

기준선 `0.9.4.121` → 본 빌드 `0.9.4.122`.
CPU CTest **124/124**, GPU CTest **125/125**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

실기 보고: 가운데 유사그룹 선택 후 우측 파일 목록 우클릭 시 시스템 전체 일시 정지(마우스 부동 + 브라우저 재생 지속 + CPU 무점유). 메뉴 경로 전수 조사 결과:

- 메뉴 생성 시점의 유일한 외부 호출 = `quickLookTarget()`(파이프 열거 + exe 존재 확인 + Uninstall 레지스트리 열거). QuickLook 미설치 상태에서는 **매 우클릭마다 레지스트리 재탐색**(수~수십ms, GUI 스레드 동기).
- 코드베이스에 전역 입력 차단 수단 전무(`BlockInput`/그랩/후크/브로드캐스트 없음) + 메뉴 경로 GPU 작업 제로 → 메뉴 코드가 OS 커서를 멈출 수단이 없음. 증상 서명은 GPU TDR 또는 타사 전역 후크 교착에 해당하며, 우클릭은 방아쇠일 뿐 원인 코드가 아니다.
- 그럼에도 클릭 경로의 동기 외부 I/O를 제거해 용의선상에서 완전히 제외하고, 매 클릭 레지스트리 비용을 제거한다. 전제("QuickLook 사용에 문제없을 것")가 사용자 확인으로 충족됨.

## 2. 기존 구조

`quickLookTarget()` = 파이프 live 확인 → `quickLookExePath()`(캐시 적중 / 5곳 경로 확인 / 레지스트리 열거). negative 결과는 캐시되지 않아 QL 부재 시 매번 전체 탐색을 반복했다.

## 3. 변경 구조

- `quickLookExePath()`의 Uninstall 레지스트리 탐색에만 **120초 negative 캐시**(`lastRegProbeMs`). 경로 5곳 확인·캐시 적중은 종전대로 매 호출 수행하고, 파이프 확인은 손대지 않아 QuickLook 시작/중지가 즉시 반영된다. 설치 중 탐색도 최대 120초 지연으로 발견된다.
- 전송 경로(`previewSelectedQuickLook` → `quickLookSendMessage`)와 폴링은 불변. QL 동작(파이프/실행/폴링) 의미 변화 없음.

## 4. 해결된 상황

- 우클릭 시 레지스트리 탐색이 최대 120초에 1회로 감소. 파이프·실행파일 확인의 즉시성은 유지된다.
- 메뉴 생성 시점의 비용 큰 외부 I/O가 제거되어, 시스템 정지 원인 후보에서 제품 측이 제외된다.

- **미검증/확인 필요**: 실기 — 우클릭 시 시스템 정지 재현 여부. 확증 절차(이벤트 뷰어 Display/nvlddmkm 4101, 후크/셸 분리 테스트)는 조사 보고서에 기록.

## 6. 향후 영향 및 한계

- QL 미설치 환경에서 메뉴가 가벼워진다. 설치 환경은 캐시 적중 경로로 기존과 동일하게 동작한다.
- 파이프 `WriteFile` 동기 전송은 액션 경로에만 존재하며 이번 변경 범위 밖이다(필요 시 overlapped+타임아웃 후보로 기록).
- 시스템 정지의 진원 규명은 실기 확증 절차(이벤트 로그·분리 테스트)에 달려 있다.

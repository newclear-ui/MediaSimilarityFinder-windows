# MediaSimilarityFinder v0.9.4.58 — Stop 시 드레인 + 지문 실행 시점 재배치

기준선 `0.9.4.57` → 본 빌드 `0.9.4.58`.
CPU CTest **106/106**, GPU CTest **107/107** (기존 105/106 + 신규 1).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변.

## 1. 변경 필요성

Stop은 "새 파일 읽기 중단"이지 "읽은 작업 폐기"가 아니다. 기존에는 취소 시
admitted-but-unanalyzed 이미지 배치를 버렸으므로, 수 시간 스캔을 중단하면
인덱스가 0으로 남았다. 사용자가 20분 검색 후 Stop을 눌렀으나 인덱스 없이
즉시 정지만 된 것이 이 구조다.

## 2. 기존 구조

소비 루프 종료 후 trailing batch·video range는 `!cancelled` 조건이라 취소 시
통째로 건너뛰었다. 배치에 있던 최대 256개 이미지는 스켈레톤으로 남아 다음
스캔에서 처음부터 다시 읽어야 했다.

## 3. 변경 구조

취소 시 admitted 이미지 배치를 끝까지 분석한 뒤 종료한다 (drain).

- 이미지 배치만 드레인. 최대 1개 배치, 수 초 내 완료. bounded라 Stop 응답성 유지
- 비디오는 기존 drop 유지. 단건 비디오 디코드는 unbounded라 드레인하면 Stop이
  수 분 걸릴 수 있다. 문서화된 의도적 비대칭
- 드레인 결과는 정상 분석과 동일하게 fingerprint 기록 + DB 저장 + analyzed 계수
- DB 오류 시 기존 실패 경로 그대로. checkpoint가 드레인분까지 commit

### 지문 실행 시점 재배치 (동일 빌드, 선행 작업)

- telemetry 전용 전체 해시가 walk 앞에 있어 수 시간 dataset에서 생산 작업이
  시작조차 못 했다. 지문을 match/group 이후, `finishScan` 직전으로 이동
- telemetry OFF면 기존대로 생략. 취소/실패 시에도 생략하므로 Stop·에러가
  즉시 보고된다. 생략 시 `not_available` 유지
- 선행 취소는 어떤 phase에도 진입하지 않으므로 `cancelledDuring`이 빈 문자열.
  "fingerprint에서 취소됨"이 아니라 "시작 전 중단"이 정확한 기록.
  `cancel_fingerprint_test` 기대치가 이에 맞춰 갱신됨

## 4. 해결된 상황

- Stop 후에도 읽은 이미지는 인덱싱되어 남는다
- 재스캔은 드레인분을 unchanged로 보고 나머지만 처리한다
- 수 시간 작업 중단 시에도 처리분 인덱스 보존. 즉시 정지만 되던 구조 해소
- 지문 재배치로 생산 작업이 해시에 막히지 않는다. 취소·실패·telemetry OFF면
  지문 생략 후 즉시 반환

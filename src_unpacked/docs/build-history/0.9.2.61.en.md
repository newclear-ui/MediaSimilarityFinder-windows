# MediaSimilarityFinder v0.9.2.61 — Uniform Preview Sizes + Wider Shell Lane

## Need for change
Lists rendered but preview sizes were inconsistent (small thumbs mixed with giant icons in one view mode; same in the right file list). Render probe verdict: in a single IconMode view, cells varied 90x91..262x283 with source pixmap size. Cells follow sources, so uniformity requires unifying sources.

## Previous structure
- `fileThumb(rep, 64x64)` fixed request + path-only cache key. 64px, 160px, and variable shell pixmaps mixed in one view
- Single decode budget 4/tick. Shell COM (~1-3ms) shared the budget with hundred-ms FFmpeg decodes, so even shell-cached thumbs filled slowly

## New structure
- **Square normalization** (`squareFittedPixmap`, transparent padding, never distorted): every display icon fitted to the exact requested rect. Render probe confirms uniform 262x283 cells. `thumb_layout_test` permanently guards (exact size, centered content, transparent padding, no distortion)
- **View-size requests**: `fillPair` passes `grid->iconSize()` (crisp 256 in XL, light 64 in M). Cache key carries size (`path|WxH`); removals drop variants too (`dropThumbCache`)
- **Split budgets**: shell lane 24/tick + heavy decodes 4/tick. Shell hits fill ~10x faster; heavy bound preserved. Pause/stop responsiveness kept
- Version strings unified → 0.9.2.61

## Resolved situation
- Uniform cells in XL/L icon modes and the right file list. Explorer-like uniform tiles
- Shell-first + self-generate-on-miss order unchanged (existing behavior), just fills faster

## Validation
- Core+GUI Release build: PASS, **CTest 48/48 PASS** (incl. new `thumb_layout_test`)
- `--version` 0.9.2.61, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)

## Future impact
- Zoom-slider sizes generate progressively on demand (within budget). Cache cap/eviction unchanged
- Filename-length wrap variance is inherent IconMode behavior (Explorer behaves the same)
- Background-thread thumbnails remain the next candidate

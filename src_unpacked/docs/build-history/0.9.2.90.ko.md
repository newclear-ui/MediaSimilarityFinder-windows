# MediaSimilarityFinder v0.9.2.90 — 외부 리포트 잔여 항목 개선

## #1 동영상 샘플링 경계 (다이아딕 간격 + 비교 시 솎기 + 1회 재분석)

### 변경 필요성
- 길이 구간별 간격(1/2/5/10/15/30초) 탓에 재인코딩본이 경계 근처면 전혀 다른 시점을 뽑았다
  (59.98초→31프레임 vs 60.02초→14프레임). DTW timePenalty가 셀마다 최대 20점을 깎았다.

### 기존 구조
- `sampling_interval`/`make_sample_plan`이 6개 밴드에 비(非)중첩 간격을 썼고,
  비교는 격자 차이 그대로 DTW에 넣었다.

### 변경 구조
- 간격을 1·2·4·8·16·32초 다이아딕으로 변경(`sampling.cpp`, `video_sampling.cpp` 공통).
  t=0 시작이라 성긴 격자가 촘촘한 격자에 포함된다.
- 비교 시(`video_similarity`, `crop_temporal_score`) 격자 비율이 정수면 성긴 쪽을
  공통 타임스탬프로 솎아 비교한다. 비내포 격자(구 데이터)는 기존 전체 DTW로 폴백한다.
- DB `meta.sampling_generation`(현행 "2")을 도입해 구 격자 비디오는 다음 완전 스캔에서
  1회 재분석한다. 엔진 버전 1.0.1→1.1.0(신 규칙), 영상 캐시 v6→v7.
- 59.98/60.02, 9.99/10.02 경계가 모두 내포 관계가 되고, 299.9/300.1은 동일 격자가 된다.

### 해결된 상황
- 동일 내용·경계 straddle 재인코딩 쌍의 유사도가 100에 수렴한다(회귀 테스트).

### 검증
- `video_sampling_test`(격자+커버리지), `video_similarity_test`(경계 59.98/60.02),
  `core_test`·`media_analyzer_test`(밴드 기대치), `database_test`(generation round-trip),
  `match_revalidate_test`(1.1.0), 전체 58/58 PASS.

### 향후 영향
- 업그레이드 후 첫 완전 스캔에서 비디오 전체가 1회 재분석된다(무변경 파일 포함).
  취소된 스캔은 스탬프를 남기지 않아 다음 스캔이 차분을 다시 강제한다(정확 우선).

## #3 image_verify crop 기하 + #6 디코드 캐시

### 변경 필요성
- 검증이 64×64 찌그러뜨림에서 영역을 잘라 지문(비율 유지 디코드에서 crop)과 기하가 달랐다.
  SSIM도 같은 영역끼리만 봐서 crop-vs-full 진짜 중복이 탈락할 수 있었다.
- 후보 쌍이 많은 파일이 쌍마다 반복 디코드됐다.

### 기존 구조
- squashed 64×64 1회 디코드, full+3영역 SSIM, 캐시 없음.

### 변경 구조
- 비율 유지 64px 디코드를 추가하고 영역 비교를 `centerCropResize`로 통일(지문과 동일 기하).
  full-32 대 영역(crop-vs-full) 비교를 양방향으로 추가했다. blend·임계는 그대로다.
- 경로+크기+mtime 키의 32항목 LRU로 full/aspect 디코드를 공유한다(스레드 안전).

### 해결된 상황
- 와이드 사진 중앙 crop 쌍이 grey zone에서 통과한다(신규 테스트). 기존 rejection 테스트 유지.

### 검증
- `image_verify_test`(crop-vs-full 신규 케이스 포함), 전체 58/58 PASS.

### 향후 영향
- 없음. 거부력은 full-64 비교 유지로 보존된다.

## #5 후보 색인 (4분할 16비트 + 반경 2)

### 변경 필요성
- 9분할(7~8비트)은 질의당 전체의 약 7%를 훑어 10만 장 규모에서 부담이 됐다.

### 기존 구조
- 8+7×8=64비트 9분할, 정확 일치 분할 조회(D≤8 비둘기집).

### 변경 구조
- 16비트 4분할 + 반경 2 이하 이웃 열거(분할당 137회 조회). 오차 8이 4조각에 나뉘면
  어느 한 조각은 2 이하이므로 exactness가 유지된다. 질의당 검증량이 약 7%→0.8%로 준다.
  엔트리당 저장 참조는 9→4개로 준다. D=0 정확 조회·D>8 폴백·그룹 dedup 의미는 그대로다.
- bit63 미사용 지적은 확인했으나, 분모 변경은 전역 판정 변경이라 손대지 않고 기록만 한다.

### 해결된 상황
- `candidate_pairs_test`(전수 선형 대조)가 그대로 통과해 exactness가 입증된다.

### 검증
- 후보 계열 테스트 + 파이프라인/e2e 포함 전체 58/58 PASS.

### 향후 영향
- 대용량 라이브러리의 후보 검증량이 약 8배 감소한다.

## #7 동영상 2차 단계 (병렬 + 디코드 절감 + 캐시 상한)

### 변경 필요성
- 쌍 루프 단일 스레드, 캐시 미스 시 최대 3회 디코드, crop 영속 없음, 메모리 캐시 무제한이었다.

### 기존 구조
- `analyze()`가 쌍마다 `build`+`buildCropAware`를 순차 호출하고 `baseCache`/`cropCache`를
  무제한으로 쌓았다. 엔진 메모리 캐시도 무제한이었다.

### 변경 구조
- `buildFull()` 신설: 32px+96px 1회씩만 디코드하고 base와 per-frame crop을 함께 계산한다.
  crops는 base와 같은 keep[] 필터로 인덱스가 1:1 정렬된다(기존 `buildCropAware`의
  미스얼라인 해소). `buildCropAware`는 호출자가 없어져 삭제했다.
- per-frame crop을 캐시 v7에 영속화했다. 적중 시 디코드 0회다.
- 엔진 메모리 캐시를 64항목 LRU로 상한했다. `analyze()`의 로컬 무제한 맵을 제거하고
  엔진 캐시에 일원화했다.
- temporal 검증 쌍을 4096개 버퍼에 모아 청크(64) 단위로 병렬 검증한다(워커 2~16).
  청크마다 중단점을 폴링하고, 결과는 순서대로 합쳐 기존과 동일한 순서·개수로 방출한다.

### 해결된 상황
- 캐시 미스 3회→2회 디코드, 적중 1회→0회. 매 스캔 반복되던 crop 디코드가 사라진다.

### 검증
- `video_cache_test`(v7 레이아웃+`buildFull` 단언), e2e 포함 전체 58/58 PASS.

### 향후 영향
- 비디오 매치는 청크 단위로 스트리밍되어 라이브 표시가 약간 뭉친다(순서는 동일).

## #2 XOR 구조 (재작성 기각)

- 프레임 XOR+앵커 게이트+temporal 구조를 per-frame 색인+투표 구조로 바꾸는 제안은
  후보 생성·MediaFile 흐름 전반의 재작성이라 회귀 위험이 크다.
- 보고된 드리프트의 직접 원인(격자 불일치)은 #1(다이아딕+솎기+재분석)이 제거했고,
  동일 격자에서는 앵커(any-to-any 최대값)가 recall을 담당한다. e2e가 녹색이다.
- 따라서 재작성은 하지 않고 현 구조를 유지한다. 반대 의견이 있으면 별도 버전으로 다룬다.

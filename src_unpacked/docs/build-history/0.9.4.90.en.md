# MediaSimilarityFinder v0.9.4.90 — group sort "None" + sort lock during a scan

Baseline `0.9.4.89` -> this build `0.9.4.90`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged (GUI-only change).

## 1. Why

The group list had only two sort orders: `Similarity` / `Name`. While a scan ran with a
sort active, every newly indexed file formed a group that had to be **inserted into the
sorted list**. Similarity order changes as matches accumulate, so the group order kept
churning, which made the GUI list misbehave (flicker / scroll jumps / blank-list recurrence).

## 2. Previous structure

- `sortBox_` items: `0=similarity`, `1=name`.
- `rebuildGroups()` re-sorted `groups_` by similarity or name on every update.
- The sort combo stayed active during a scan, and the sort was reapplied on every streamed match.

## 3. New structure

- Added **`2=None`** to `sortBox_`. `None` does not sort and keeps the **union-find build
  order**, so new groups only **append**.
- **During a scan the sort is locked to `None`** and the combo is **disabled**
  (`setRunning(true)` saves the user's choice to `preScanSort_`, switches to `None`, and
  `updateSortEnabled()` locks it).
- **When indexing + post-processing finish** (`setRunning(false)`) the combo is re-enabled and
  the **user's pre-scan choice is restored** -> similarity/name is selectable again.
- `updateSortEnabled()`: the combo is active only on a group tab (photos/videos) and only when
  no scan is running. `activateTab()` uses the same helper.

## 4. Result

- During a scan the group list is never re-sorted, so **re-placing / inserting is gone** ->
  the list no longer churns or errors.
- The sort cannot be changed mid-scan (combo disabled), removing undefined state transitions.
- After the scan, the user freely picks similarity/name (or none).

## 6. Impact and limits

- GUI-only change. engine/DB/schema/cache unchanged.
- `None` exposes the `QHash` bucket order (stable within a run), which may look "unordered" to the
  user. That fits the mid-scan goal (avoid sorting) and assumes similarity/name is used afterwards.
- The sort choice is not persisted across sessions (unchanged from before).

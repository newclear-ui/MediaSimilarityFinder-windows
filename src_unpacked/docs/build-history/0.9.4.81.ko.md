# MediaSimilarityFinder v0.9.4.81 — 매칭 검증 모드 선택 + B 1000 슬라이스

기준선 `0.9.4.80` → 본 빌드 `0.9.4.81`.

`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변(의도). 판정(임계·SSIM·temporal)은 세 모드 모두 동일.

## 1. 변경 필요성

- 파일이 1만~10만 개를 넘으면 후작업(쌍매칭 검증)이 오래 걸린다. 검증을 "언제·어떤
  단위로" 수행할지 사용자가 골라 최종 테스트에서 비교할 수 있어야 한다.
- 검증이 단일 블록으로 끝까지 돌아 중단/크래시 시 진행이 사라지고, 진행률도 거칠다.
  **1000 파일 단위 슬라이스**로 나눠 진행·체크포인트·재개가 가능해야 한다.

## 2. 기존 구조

- 스캔 후 전역 `analyze()` 1회가 모든 쌍을 한 번에 검증. 중간 진행/체크포인트 없음.
- 어떤 모드였는지 로그로 구분할 수단이 없었다.

## 3. 변경 구조

**(A) 설정 옵션 `매칭 검증 방식`** (설정 → 일반 탭, QSettings `ui/analyzeMode`):
1. **안정형 (스캔 후 검증)** = `B` (기본) — 스캔 후 전역 검증.
2. **고속형 (스캔 중 검증)** = `A` — 최종 검증을 "이번 스캔에서 변경된 파일이 낀 쌍"으로 제한.
3. **자동 (혼합 검증)** = `A+B` — A에 더해, 양쪽 모두 변경된 이미지 쌍은 라이브 스트리밍이
   이미 방출했으므로 최종 패스에서 생략.
- 새 `src/analyze_mode.h`(`msf::AnalyzeMode`, `analyzeModeKey` = `B`/`A`/`AB`).

**(B) B 1000 슬라이스 + 프론티어 재개** (`ScanPipeline::analyze` 확장):
- 이미지(phase 0) / 비디오(phase 1) / 크롭(phase 2) 검증 패스를 **그룹 경계 기준 1000 파일
  윈도우**로 처리. 윈도우마다 `onSlice(phase, done, total)` 호출, 윈도우 사이 stop 확인.
- 비디오 윈도우는 `flushVideo()`로 temporal 디코드를 즉시 수행(진행 실측 + 중단 반응).
- 윈도우마다 **매치 체크포인트**(worker가 누적 매치 저장) 후, 이미지 phase(0)만 **재개
  프론티어**를 DB meta `analyze_frontier`에 기록.
- 프론티어 키 = `engineVersion|maxDistance|파일수|파일셋해시`. 같은 파일셋 재스캔일 때만
  적용되며, **완료 스캔은 프론티어를 비운다**(일반 재스캔은 여전히 전역 패스).
- 배선: GUI 설정 → `BackendScanConfig.analyzeMode` → `START_SCAN(analyzeMode)` →
  `BackendSession` → `ScanWorker::setAnalyzeMode` → `ScanControl.analyzeMode` → `scan`.
  체크포인트는 `ScanControl.analyzeCheckpoint`(worker 스레드에서 매치 스냅샷 저장).

**(C) 로그 식별**: 스캔 시작 시 `msf_scan.log`에 `scanAnalyzeMode=<B|A|AB>` 1줄, 슬라이스마다
`analyzeSlice phase=<0|1|2> <done>/<total>`, 재개 시 `analyzeResume fromGroups=<n>`. 상세 로그
JSON의 `analyze.mode`. `finished`/`results` 메시지 형태는 불변.

## 4. 해결된 상황

- 사용자가 세 방식을 선택할 수 있고, 최종 테스트가 `scanAnalyzeMode=`/`analyze.mode`만 보고
  어떤 모드였는지 구분한다.
- B는 검증을 1000 파일 단위로 나눠 진행률을 보고, 윈도우마다 저장하며, 중단 시 마지막
  체크포인트 윈도우부터 재개한다.
- A/AB는 변경 파일이 낀 쌍만 재검증해 증분 스캔의 불필요한 재계산을 줄인다.

- parity: 슬라이스/필터는 판정 코드를 바꾸지 않으며, 슬라이스 결과가 비슬라이스와 동일한
  쌍 집합을 냄을 테스트로 고정.
- 스키마: `analyze.mode`는 가산 키라 `kBenchmarkSchemaVersion` **9 유지**.

## 6. 향후 영향 및 한계 (명시)

- **프론티어 재개는 이미지 full phase(0)에만 적용**된다. 비디오/크롭 윈도우는 체크포인트만
  하고, 재개 시 처음부터 다시 검증한다(정확성 유지, 시간만 미절약).
- **A/AB의 증분 정확성은 persisted match 집합에 의존**한다: unchanged-vs-unchanged 쌍은
  이전 완료 스캔이 저장한 쌍을 신뢰한다(엔진 버전 상향 시 `revalidateMatches`가 재검증).
  콜드 스캔과 완료 증분 스캔에서는 B와 동일하다.
- AB의 "양쪽 변경 이미지 생략"은 라이브 스트리밍 실행 시에만 적용된다(`liveMatch` 가드).
- 비디오 검증이 여러 윈도우로 나뉘면서 `videoRange` 계측 개수가 달라질 수 있다(판정 불변).
- 다음 후보: 비디오/크롭까지 프론티어 확장, A/AB 요약 카운트 정합, 실제 대량 dataset 실측.

# MediaSimilarityFinder v0.9.2.84 — 빌드 산출물 즉시 실행(Qt 플러그인 빌드 내장 배포)

## 변경 필요성
- 사용자가 `build-windows-cuda\Release\MediaSimilarityFinder.exe`를 직접 실행했고, 0.9.2.83의 자가진단 대화상자가 정상 표시됐다. 즉 빌드 산출물에는 Qt 플러그인이 원래부터 없었다.
- 배포용 zip뿐 아니라 빌드 출력도 바로 실행돼야 한다.

## 기존 구조
- Qt 플러그인은 `vcpkg_installed/.../Qt6/plugins`에만 있었고, 빌드 출력 디렉터리에는 복사되지 않았다.
- `ffmpeg.exe`/`ffprobe.exe`(영상 해상도 최후 폴백)도 빌드 출력에 없었다.

## 변경 구조
- `CMakeLists.txt`의 `MediaSimilarityFinder` 타깃에 POST_BUILD 배포를 추가했다: 존재하는 플러그인 카테고리(`platforms`, `styles`, `imageformats`, `generic`)를 출력 디렉터리 루트에 복사하고, `ffmpeg`/`ffprobe`를 `copy_if_different`로 복사한다. 존재하지 않는 카테고리(`iconengines` 등)는 건너뛰어 구성을 깨지 않는다.
- GUI 테스트용 `QT_PLUGIN_PATH` 계산은 타깃 정의부로 이동해 재사용한다.
- 판정 로직·CUDA 알고리즘 변경 없음. 버전 표기 통일 → 0.9.2.84.

## 해결된 상황
- `build-windows-cuda\Release\MediaSimilarityFinder.exe`가 깨끗한 환경(최소 PATH·플러그인 경로 미설정)에서 `--smoke` exit 0으로 실행된다.
- 포터블 패키지도 동일 버전으로 재생성했다.

## 검증
- Core+GUI Release 빌드: PASS, **CTest 56/56 PASS**
- 빌드 산출물 실행 검증: `--smoke` exit 0 (깨끗한 환경)
- `MediaSimilarityFinder-v0.9.2.84-Portable-Windows-x64.zip` 생성

## 향후 영향
- 빌드할 때마다 플러그인이 자동 배치되므로 빌드 출력 직접 실행이 계속 동작한다.
- 새 빌드 디렉터리에서도 동일하게 적용된다.

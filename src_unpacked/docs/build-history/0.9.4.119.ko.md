# MediaSimilarityFinder v0.9.4.119 — 처리량 표기 의미 명확화 (분석 단계 라벨 + 전체/신규 요율)

기준선 `0.9.4.118` → 본 빌드 `0.9.4.119`.
CPU CTest **123/123**, GPU CTest **124/124**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

0.9.4.118 실기 대조(06:40 세션, 177,781파일 AB 스캔)에서 상세 로그 요약의 두 "처리량" 표기가 서로 다른 기준인데 이름이 비슷해 혼선을 만들었다.

- 이미지/비디오 라인 `처리량: 39.8 files/sec` = analyzed ÷ 분석 단계 시간(`imageStageMs`)
- 파일 라인 `(0.0 files/s)` = analyzed ÷ 전체 wall(`filesPerSec`) — 177,781개를 스캔했는데 "0.0 files/s"로 읽힘

두 값 모두 정의상 맞지만 기준이 표기에 드러나지 않아 오해를 유발했다(대조 보고에서 기록).

## 2. 기존 구조

`showDetailedLogDialog`(gui/mainwindow.cpp)의 요약 생성이 두 숫자를 기준 표기 없이 출력했다. `summary.filesPerSec` 등 JSON 필드는 계측 계약이므로 변경 대상이 아니다(의미 유지).

## 3. 변경 구조

- 이미지/비디오 라벨: `처리량` → **`처리량(분석 단계)`** / `throughput (analysis stage)`.
- 파일 라인: `(전체 X files/s · 신규 Y files/s)` — **전체** = scanned/wall(스캔 실질 속도), **신규** = analyzed/wall(`filesPerSec`, 신규 분석 기준). 새 번역 키 2개(`detailLogRateOverall`/`detailLogRateNew`, 목록 총 **75**).
- 회귀 핀: `scan_detailed_log_acceptance_test`가 실제 다이얼로그의 렌더 텍스트를 캡처해 ① 분석 단계 라벨 ② 전체/신규 라벨 ③ `files/s` 등장 수 ≥4(이미지/비디오의 `files/sec` 접두 2건 + 새 파일 라인 2건)를 검증한다. 수정 전 텍스트는 라벨 부재·카운트 3으로 두 단언 모두 실패한다(by construction).

## 4. 해결된 상황

- 표기만으로 기준이 드러난다: 예) 이미지 `처리량(분석 단계): 39.8 files/sec`, 파일 `(전체 507.8 files/s · 신규 0.0 files/s)`.
- JSON·판정·엔진 의미는 불변이다(표시 전용).

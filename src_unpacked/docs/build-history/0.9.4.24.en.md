# MediaSimilarityFinder v0.9.4.24 — QSettings Organization Name Change

Changes the portable UI settings identity from a personal handle to a
product-based name, and **safely migrates** existing user settings once.
Engine 1.5.0, DB 1.0.3, cache v9 **unchanged**; search-verdict semantics
**unchanged**.

---

## 1. Why the change was needed

`QCoreApplication::setOrganizationName()` becomes the settings directory
name, so it is a **user-visible artifact** of the portable distribution.
The old value `newclear-ui` is the GitHub account (owner) name, so a
personal identifier ships in the product.

```
before: <appDir>\newclear-ui\MediaSimilarityFinder.ini
after:  <appDir>\MediaSimilarityFinder-ui\MediaSimilarityFinder.ini
```

A plain string replacement alone would make existing users' window geometry,
splitter, headers, and view mode look reset. Migration is therefore the core
of this work.

## 2. Previous structure

`gui/mainwindow.cpp::initAppSettings()`:

```cpp
QCoreApplication::setOrganizationName("newclear-ui");
QCoreApplication::setApplicationName("MediaSimilarityFinder");
QSettings::setDefaultFormat(QSettings::IniFormat);
QSettings::setPath(QSettings::IniFormat, QSettings::UserScope, portableDir);
```

`gui/main.cpp` calls `initAppSettings(QCoreApplication::applicationDirPath())`
once. The `MainWindow` constructor immediately reads
`QSettings().value("ui/ignored")`, so migration must complete right after the
identity is set.

There was exactly **one** active-code occurrence of `newclear-ui`. The rest
are the GitHub repository owner label (`development-chat-handoff.*`) and
historical build-history documents — not change targets.

## 3. New structure

```
Organization : newclear-ui              → MediaSimilarityFinder-ui
Application  : MediaSimilarityFinder    → (unchanged)
Executable   : MediaSimilarityFinder.exe→ (unchanged)
CMake target : MediaSimilarityFinder    → (unchanged)
```

The `setDefaultFormat` / `setPath` combination is **kept exactly as it was**.
The only purpose here is the organization name.

Both names are now `kSettingsOrganization` / `kSettingsApplication` constants,
removing the hardcoded string, and the legacy value is retained solely for
migration so it can never become the active identity again.

## 4. Migration strategy

Runs inside `initAppSettings()`, immediately after the identity is set.

| Case | Situation | Behavior |
| --- | --- | --- |
| A | only the new location exists | do nothing (no migration) |
| B | only legacy exists | copy → verify → remove legacy |
| C | both exist | **new location wins, legacy preserved** (never overwritten) |
| D | copy / directory creation fails | **legacy is not deleted**, the error is contained and startup continues |
| E | new INI verification fails | treat the new file as unusable and remove it, preserve legacy |

### Deletion policy (strict order)

```
legacy INI exists
   → copy to new INI
      → open the new INI through a real QSettings
         → assert status() == NoError
            → assert key presence (ui/mainGeom, ui/splitter)
               → only on success remove the legacy INI
                  → rmdir the legacy directory only if it is empty
```

If an unexpected file remains inside the legacy directory, the directory is
not removed (`isEmpty()` is checked before `rmdir`).

On verification failure the freshly copied file is removed so the new
location is left with no settings, and the legacy file stays. Therefore
**no failure path can lose a user's existing settings.**

Because of Case C (new wins), the migration is **idempotent**: a second run
early-returns instead of overwriting again.

## 5. Resolved state

- A personal identifier no longer ships in the distribution
- The risk of existing users losing UI state is removed by migration
- No data loss is possible on any failure path (cases D/E)

## 6. Deliberately not touched

The QuickLook uninstall lookup at `mainwindow.cpp:2641` uses
`QSettings(root, QSettings::NativeFormat)` — an **explicit path with
NativeFormat**, unrelated to the organization name — so it was **not**
modified.

The packaging scripts do not handle `newclear-ui` or `.ini` directly, so they
are unaffected.

## 7. Tests

Cross-process migration regression was added to
`tests/ui_settings_test.cpp`. Each phase is a separate process because a
same-process read-back would be served from QSettings' in-memory cache and
could pass even if disk persistence were broken.

| Test | What it verifies |
| --- | --- |
| `ui_settings_migrate_plant` | plants the legacy INI as a real file (no QApplication) |
| `ui_settings_migrate_verify` | migration creates the new location, removes legacy, preserves 5 values, checks the organization, and is a no-op on re-run |
| `ui_settings_migrate_both_plant` | plants different values in both locations |
| `ui_settings_migrate_both_verify` | **new location wins + legacy survives** |
| `ui_settings_migrate_none_verify` | no legacy → nothing is invented, only the new INI appears |

The existing cross-process round-trip (`ui_settings_write` /
`ui_settings_verify`) is preserved and keeps passing under the new identity.

## 8. Real execution validation (temporary portable directory)

The `build-windows-gpu\Release` output plus its Qt plugins were copied into a
temporary directory and `--smoke` was run for real.

### Case B — legacy only

```
before: portable-test\newclear-ui\MediaSimilarityFinder.ini  (11 keys)
after:  portable-test\MediaSimilarityFinder-ui\MediaSimilarityFinder.ini
        legacy directory removed
        all 11 keys preserved with identical values
        (lastFolder / language / kindMask / groupView spot-check passed)
```

### Case C — both present

```
legacy preserved        : True
new location wins       : language=en  (not legacy's ko)
```

### Case A — new only

```
legacy directory created: False (not created)
new INI created         : True
```

## 10. Future impact

- The portable distribution's directory name becomes `MediaSimilarityFinder-ui`.
- Users who ran a build older than 0.9.4.24 go through a one-time automatic
  migration on first start.
- The migration tests continuously prove that `newclear-ui` is no longer the
  active runtime identity.
- Engine / DB / verdict semantics are unaffected by this change.

# MediaSimilarityFinder v0.9.2.72 — Engine/DB Version Split (semver)

## Need for change
The v0.9.2.71 engine version was a bare integer, unable to express the magnitude of verdict changes, and no DB schema version existed at all. Engine-verdict generations and DB-schema generations needed independent tracking, decoupled from build numbers: patch = tuning, minor = new stage/rule (engine) / migration-needing change (DB), major = architecture replacement / breaking change.

## Previous structure
- `kEngineVersion = 1` (int), `engineVersion()/setEngineVersion(int)`. No DB version

## New structure
- **New `src/semver.h`** (header-only): `parseSemver`·`compareSemver`·`semverLess`. Missing/malformed components count as 0 ("", "abc" < "0.0.1"). Numeric, so "1.0.10" > "1.0.2"
- **Engine version as string**: `kEngineVersion = "1.0.1"`. `revalidateMatches` compares with `semverLess`. Legacy DBs (no version row) read "0.0.0" and upgrade
- **New DB version**: `Database::kDatabaseVersion = "1.0.1"`, `meta.db_version`. Stamped by `initialize()` after migrations (idempotent, so post-open schema is always current). `dbVersion()/setDbVersion()` provided
- `match_revalidate_test` extended: 5 semver-ordering assertions + db stamp check. Version strings unified → 0.9.2.72
- Version rules recorded as AGENTS.md item 4: engine patch/minor/major criteria, DB patch/minor/major criteria, independent of build numbers, bump-only-when-needed, bumped builds noted in history

## Resolved situation
- Verdict changes get the revalidation path with a one-line engine bump. Schema changes start tracked (grounds for a future wipe+rescan gate on breaking changes)
- Legacy DBs auto-upgrade as "0.0.0". No stored-data loss

## Validation
- Core+GUI Release build: PASS, **CTest 54/54 PASS** (incl. semver + stamp assertions)
- `--version` 0.9.2.72, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)

## Future impact
- Next verdict-changing build bumps engine minor/major + notes it in history. Breaking schema changes add a `dbVersion()` wipe+rescan gate
- Build numbers stay independent for feature releases. A historic 3-version (build·engine·DB) table is a candidate

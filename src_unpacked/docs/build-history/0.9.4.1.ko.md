# MediaSimilarityFinder v0.9.4.1 — MainWindow 스캔 workflow 회귀 테스트

0.9.4.0 완료 후 점검에서 발견된 검증 간극을 닫는다. 엔진 1.5.0·DB
1.0.3·비디오 캐시 v9·benchmark schema 1은 불변이다.

## 변경 필요성
- CTest·`--smoke`는 통과했지만, 실제 `MainWindow` 슬롯 경로(폴더 →
  `startScan()` → 워커 스레드 → `drainMatches` → 그룹/그리드 렌더 →
  `scanFinished`)를 실행하는 테스트가 없었다. `--smoke`는 창만 띄우고,
  `scan_streaming_test`는 `ScanWorker` 수준에서 멈춘다.
- 대화식 조작(마우스/키보드/화면 확인)은 자동화 환경에서 불가능하므로,
  슬롯 수준까지 자동화로 검증하는 드라이버가 필요했다.

## 기존 구조
- 스캔 완료 시 벤치마크 요약이 모달(`dlg.exec()`)로 뜬다. 펌프 루프가
  `processEvents()` 안에서 모달에 빨려들면 영원히 hang된다(초기 구현이
  10분 hang으로 이 사실을 입증).
- `folder_`·`benchTgl_`·`groupTitle_`·`imgTree_`에 조회용 이름이 없어
  외부에서 상태를 단언할 수 없었다.

## 변경 구조
- 신규 `tests/scan_workflow_test.cpp` (offscreen, `QSettings` 격리):
  실제 `MainWindow`를 띄우고 `ui/lastFolder`로 폴더를 주입한 뒤 `scan`
  버튼을 클릭하고, 스캔 버튼 재활성화(`setRunning(false)`, 사용자가 보는
  idle 상태)까지 펌프한 뒤 이미지 트리 1개 그룹 + 타이틀 `(1)` +
  벤치마크 요약 다이얼로그 출현을 단언한다.
- 모달 대응: 같은 스레드 타이머는 모달 루프 안에서도 발화하므로,
  250ms closer가 `activeModalWidget()`을 닫는다. 강제 종료가 아니라
  정상 `close()`이며, 다이얼로그 출현 자체를 검증 항목으로 삼는다.
- 제품 변경은 조회용 `objectName` 5개뿐이다(`folder`·`benchTgl`·
  `gpuToggle`·`groupTitle`·`imgTree`): 동작 변경 없음, 향후 UI 자동화의 갈고리다.
- 기본 구성 그대로(GPU 체크·벤치마크 ON) 실행하므로 CPU 트리에서는 CPU
  fallback, GPU 트리에서는 CUDA 경로로 같은 1그룹에 도달한다. UI 경로의
  CPU/GPU parity까지 함께 본다.

## 선택 이유
- 모달을 피하려고 벤치마크를 끄는 대신(첫 시도), 기본 구성을 유지하고
  closer로 닫는 쪽을 택했다. 사용자가 실제로 보는 경로와 동일해야
  회귀 가치가 있다.
- `QSettings`를 임시 dir로 격리해 실사용자 설정을 오염시키지 않는다
  (`ui_settings_test`와 동일 패턴).

## 해결된 문제
- `--smoke`와 `ScanWorker` 테스트 사이에 있던 검증 공백이 닫혔다.
- 남은 수동 검증은 인간 요소(픽셀·조작성)뿐이다. 슬롯 경로는 자동화됐다.

## 정확성 영향
- 없음. 지문·유사도·임계·캐시 경로 무변경. 제품 diff는 objectName 5줄이다.

## 호환성 영향
- 없음. 테스트·CMake만 추가, 기존 키·동작 유지.

- GPU Release 빌드 PASS, **CTest 64/64 PASS** (`scan_workflow_test` 1.35초).
- `--version` 0.9.4.1은 최종 빌드 후 확인한다.

- 인간 조작 검증(실제 클릭·화면 판독)은 여전히 별도 세션 몫이다.

## 1. 변경 필요성

GUI 에서 검색 시작 후 정지 버튼을 눌러도 "정지 처리중" 메시지만 표시되고 실제
검색이 10분 이상 계속되며 디스크 읽기 I/O 가 지속되었다.

"Stop 을 눌렀다" 와 "실제 검색 작업이 정지했다" 는 다르다. UI 메시지는 요청의
시작만 의미한다.

## 2. 기존 구조

Stop 버튼은 `MainWindow::cancelScan()` → `ScanWorker::cancel()` →
`control_.cancel.store(true)` 로 정상 설정되었다. 문제는 그 뒤였다.

`MediaSearchEngine::scan()` 시작 단계에서 다음이 무조건 실행되었다.

```cpp
telemetry_.setDatasetFingerprint(msf::computeDatasetFingerprint(root));
```

`computeDatasetFingerprint()` 는 **모든 파일을 처음부터 끝까지 전부 읽어**
SHA-256 manifest 를 만든다. cancellation 파라미터가 없어 Stop 요청을 전혀
보지 않았다. 대용량 dataset 에서는 수백 GB 읽기로 10분 이상 걸린다.

호출 경로별 cancellation 상태:

| 구간 | Stop 반영 |
|---|---|
| `computeDatasetFingerprint` (스캔 시작) | **없음** — 이번 수정 대상 |
| `Scanner::count` pre-walk | 있음 (파일마다 검사) |
| `scan_stream` walker | 있음 (파일마다 검사) |
| walk 소비 루프 / batch / video range | 있음 |
| `imageBatch` 내부 | 없음 (단, batch 크기로 bounded) |
| video FFmpeg 단건 decode | 없음 (단건 파일로 bounded) |
| 최종 `pipe.analyze` | 있음 (`stopCheck` 전달됨) |

10분 현상의 지배 원인은 첫번째 행이다. 나머지는 bounded 되거나 이미 검사한다.

## 3. 변경 구조

### `computeDatasetFingerprint` 에 cancellation 전달

```cpp
// before
DatasetFingerprint computeDatasetFingerprint(const std::string& root);
// after
DatasetFingerprint computeDatasetFingerprint(const std::string& root,
                                             const std::atomic_bool* cancel = nullptr);
```

- 파일마다, 그리고 대용량 파일 읽기 중에도(64 KiB 청크마다) 검사한다.
- 취소 시 부분 manifest 를 반환하지 않고 `state="cancelled"` 로 즉시 반환한다.
  부분 지문은 거짓 identity 이므로 만들지 않는다.
- `"cancelled"` 는 telemetry 전용 새 상태다. `dataset.state` 는 JSON 직렬화만
  되며 분기하는 소비자가 없어 안전하다 (S6 계열은 hash 문자열만 사용).
- 기본 인자라 기존 호출 20여 곳은 재컴파일 없이 그대로 동작한다.

### scan() 에서 전달

```cpp
telemetry_.setDatasetFingerprint(
    msf::computeDatasetFingerprint(root, control ? &control->cancel : nullptr));
```

fingerprint가 취소되면 walk는 다음 파일에서 즉시 종료되고, batch·video는 진행된 것이 없어 건너뛰며, post-walk는 빈 DB에 대해 빠르게 처리된다.
Stop 지연은 수 분/10분 단위에서 **초 단위**로 축소된다.

## 4. 해결된 상황

- Stop 요청 → fingerprint 즉시 중단 (`state="cancelled"`) → walk 즉시 종료 →
  worker 반환 → GUI idle 복귀
- 정상 완료와 취소가 구분된다 (`completed=false`, 리포트는 그대로)
- 취소 후 DB 는 손상되지 않고 재스캔이 정상 완료된다
- 정상 파일의 `added`/`modified`/`analyzed`/`failed` 의미 불변

## 5. 검증

### 신규 회귀 테스트 `cancel_fingerprint_test` (11 checks, CPU·GPU PASS)

production 경로(`openIndexForRoot` + `scan`) 로 구동한다.

- cancel 사전 설정 시 fingerprint 가 `state="cancelled"`, hash 없음, 0파일로
  즉시 반환 (0.3 ms). 구 코드는 무시하고 전부 읽었을 것이다
- cancel 없이 20개 정상 측정 (`measured`, 64-hex)
- cancel 사전 설정 스캔은 `completed=false`, 분석 0
- 취소 후 DB 재오픈 및 정상 스캔 완료 (`scanned=20 analyzed=20`)

타이밍 단언은 없다. 상태(`cancelled` vs `measured`) 로 판정하므로 결정적이다.

### 기존 테스트와의 관계

`scan_cancel_test` (6개 작은 파일) 는 flag 설정→미완료→재개를 검증하지만
fingerprint 단계를 거치지 않아 이 버그를 잡지 못했다. 새 테스트가 그 공백을
메운다. 둘은 상호 보완이며 어느 쪽도 대체하지 않는다.

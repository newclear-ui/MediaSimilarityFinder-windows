# MediaSimilarityFinder v0.9.4.1 — MainWindow Scan-Workflow Regression Test

Closes the validation gap found in the post-0.9.4.0 review. Engine 1.5.0,
DB 1.0.3, video cache v9, and benchmark schema 1 are unchanged.

## Why the change was needed
- CTest and `--smoke` were green, but no test exercised the real
  `MainWindow` slot path: folder → `startScan()` → worker thread →
  `drainMatches` → group/grid render → `scanFinished`. `--smoke` only shows
  the window; `scan_streaming_test` stops at the `ScanWorker` level.
- Interactive operation (mouse/keyboard/screen reading) is impossible in
  automation, so a driver validating up to the slot level was needed.

## Previous structure
- The end-of-scan benchmark summary is modal (`dlg.exec()`). A pump loop
  swallowed by the modal inside `processEvents()` hangs forever (the first
  implementation proved this with a 10-minute hang).
- `folder_`, `benchTgl_`, `groupTitle_`, and `imgTree_` had no lookup names,
  so outside observers could not assert on state.

## New structure
- New `tests/scan_workflow_test.cpp` (offscreen, isolated `QSettings`):
  shows the real `MainWindow`, injects the folder via `ui/lastFolder`,
  clicks `scan`, pumps until the button re-enables (`setRunning(false)`,
  the user-visible idle state), then asserts 1 rendered image-tree group,
  the `(1)` title, and the benchmark summary dialog appearance.
- Modal handling: same-thread timers fire inside modal loops, so a 250 ms
  closer dismisses `activeModalWidget()`. A normal `close()`, never a kill;
  the dialog appearance itself is an assertion.
- Product diff is 5 lookup-only `objectName` lines (`folder`, `benchTgl`,
  `gpuToggle`, `groupTitle`, `imgTree`): no behavior change, hooks for
  future UI automation.
- Default configuration (GPU checked, benchmark on), so the CPU tree
  reaches the group via CPU fallback and the GPU tree via CUDA — UI-path
  CPU/GPU parity in the same run.

## Why this shape
- Instead of dodging the modal by disabling benchmark (first attempt), the
  default path is kept and closed gracefully. Regression value requires
  the same path the user sees.
- `QSettings` is isolated to a temp dir (`ui_settings_test` pattern), so
  the real user config is never polluted.

## Resolved state
- The gap between `--smoke` and `ScanWorker` tests is closed. Only
  human-factor validation (pixels, operability) remains manual.

## Accuracy impact
- None. Fingerprint, similarity, threshold, and cache paths untouched. The
  product diff is 5 objectName lines.

## Compatibility impact
- None. Test + CMake only; existing keys and behavior kept.

## Validation
- CPU Release build PASS, **CTest 63/63 PASS** (`scan_workflow_test` 0.75 s).
- GPU Release build PASS, **CTest 64/64 PASS** (`scan_workflow_test` 1.35 s).
- `--version` 0.9.4.1 verified after the final build.

## Future impact
- Every post-Node-B scheduler change gets UI-path regression from this test.
- Human-operation validation (real clicks, screen reading) still belongs
  to a separate session.

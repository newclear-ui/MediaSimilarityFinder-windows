## 1. Why the change was needed

- Load and Re-verify each occupied one toolbar slot (two slots confirmed in 0.9.4.148 when Re-verify joined the layout).
- Request: merge both into **one slot with a drop-down arrow menu**. The menu lists Load on top and Re-verify below; picking one switches the top button, pressing it runs that function, and Re-verify gets a Load-style icon in front.

## 2. Previous structure

- `refresh_` (QPushButton "📂 Load") and `reverifyBtn_` (QPushButton) existed side by side.
  - Toolbar order: Load > Re-verify > Scan (pinned by `ui_settings_test`).
  - `backend_e2e_test` Tests 1b/1c found each button via `findChild` and clicked it.

## 3. New structure

- One `QToolButton(loadSplitBtn_)` + `MenuButtonPopup` + a `QMenu` with two actions.
  - Menu: `loadSplitLoadAct_` (Load) on top, `loadSplitReverifyAct_` (Re-verify) below. Both checkable.
  - Menu pick (`triggered` → `setLoadSplitMode`) only switches the top button label/tooltip and persists to `QSettings(ui/loadSplitAction)`. It executes nothing.
  - Top-button press (`clicked` → `executeLoadSplit`) calls `loadIndex()`/`reverifyIndex()` per the current mode.
- Icons: Load keeps 📂, Re-verify gets 🔄 (U+1F504). Menu entries and the button share the same icon+label.
- Relabeling lives in `retextLoadSplit(UiLang)` so it is safe to call from `buildToolbar()` (calling the full `applyStaticTexts()` there SEGFAULTed on widgets that do not exist yet; the split fixed it).
- Toolbar is now one slot: merged slot > Scan. Tests updated together.
  - `ui_settings_test`: pins the slot layout order plus the exact menu [Load, Re-verify].
  - `backend_e2e_test` Tests 1b/1c/1g: select the mode via action `trigger()`, then `click()` the button.

## 4. Resolved state

- One toolbar slot. The arrow menu offers Load on top / Re-verify below; the pick switches the top button, and pressing it runs the selected function.
- Re-verify shows the 🔄 icon. The selection persists across restarts.

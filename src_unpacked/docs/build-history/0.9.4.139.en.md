# MediaSimilarityFinder v0.9.4.139 — Embedded EXE icons + group sort overhaul (group size, direction, unlocked after Load)

Baseline `0.9.4.138` → this build `0.9.4.139`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged (display/packaging only).

## 1. Why

- Request (1): the GUI and Backend executables have no app icon (Explorer/Task Manager show the generic one). Adopt candidate E2 (`candidate_E2_photo_video_lens`) for the GUI and G (`candidate_G_split_cards`) for the backend: embed **GUI=`app.ico`, Backend=`backend.ico`** and use the same art for the window/taskbar icon.
- Request (2): sorting (a) was locked after Load, (b) only offered similarity/name, (c) had no ascending/descending choice. A "number of files in the group" order was also requested.

## 2. Previous structure

- Sort: a single `sortBox_` (None/Similarity/Name) with the direction baked into the labels (`Similarity`/`Name`; KO read "descending/ascending"). A `loadLockSort_` flag made `updateSortEnabled()` disable the combo after Load/re-verify, and a scan also reset it to None.
- `rebuildGroups()` handled only `kSortName` (paths[0] ascending) and `kSortSim` (best descending).
- Icons: GUI had `WIN32_EXECUTABLE TRUE` only; Backend was a console exe. No .rc/.qrc resources.

## 3. New structure

- **Icons**: added `resources/app.ico` (E2 at 256px, 16/24/32/48/64/128/256 PNG entries), `resources/backend.ico` (G at 256px), `app_icon.rc`/`backend_icon.rc` (`IDI_APPICON`/`IDI_BACKENDICON`), `icons.qrc` (`:/icons/app.ico`). CMake: GUI target gets the `.rc` + `.qrc` and `AUTORCC ON`; Backend target gets its `.rc`. `gui/main.cpp` calls `QApplication::setWindowIcon(QIcon(":/icons/app.ico"))` so the window/taskbar icon matches the exe.
- **Sort**: type (`sortBox_`) + direction (`sortDirBox_`) combos. Constants `kSortNone=0, kSortSize=1, kSortSim=2, kSortName=3`; menu order **None → Group size → Similarity → Name**. Direction combo is **Descending(0)/Ascending(1)**.
  - Group size = number of files in the group (`paths.size()`), default descending (largest first). Similarity defaults to descending, name to ascending; switching type applies that default and the user can flip it immediately.
  - `rebuildGroups()` comparators honor the direction; equal metrics fall back to ascending path for stability. The direction combo is disabled for `None`.
  - **Load/re-verify lock removed**: `loadLockSort_` deleted. Load still starts from the stored order (None) but the user can re-sort immediately. A scan still locks to None (streaming append) and restores the previous choice at scan end.
- Translation keys `sortSize`/`sortDesc`/`sortAsc` added; `sortSim`/`sortName` labels no longer contain a direction. `sortBox`/`sortDirBox` objectNames added as automation hooks.

## 4. Result

- Explorer and Task Manager show each exe with its own art (E2/G); the window/taskbar icon uses the same art.
- The sort can be changed right after Load, and the group-size order plus ascending/descending selection work.

## 6. Impact and limits

- Display/packaging only (verdicts, storage, protocol, engine/DB/schema/cache unchanged).
- Group size means file count (a disk-bytes total would be a separate option).
- The direction default is re-applied when the type changes (keeping the previous direction would need a follow-up).
- Icon source/generator scripts live in the work scratch; the repository carries only the final `.ico`/`.png`/`.rc`/`.qrc`.

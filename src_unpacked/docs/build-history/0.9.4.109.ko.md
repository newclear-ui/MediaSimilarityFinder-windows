# MediaSimilarityFinder v0.9.4.109 — 보기 모드 전환 겹침 재발 수정 (웜 캐시 아이콘 재적용)

기준선 `0.9.4.108` → 본 빌드 `0.9.4.109`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 보고: 가운데 유사그룹 목록에서 보기 모드(리스트/자세히/타일 → 아주 크게/크게)를 바꾸면 이미지가 서로 겹치거나 다른 보기 방식과 겹쳐 보인다. "과거 있었던 문제의 재발생" — 0.9.4.66(보기 전환 후 이미지 겹침 수정)이 완전히 해결되지 않은 채 P3 이후 다시 열린 것이다.

## 2. 기존 구조 (0.9.4.66 → P3)

- 0.9.4.66의 수정 핵심: `thumbCatchUpVisible()`이 **실제로 아이콘을 교체하고**(cache hit 또는 신규 디코드 결과를 `setIcon`) 교체가 있으면 `doItemsLayout()`을 강제했다. `uniformItemSizes` 아래에서 아이콘 교체만으로는 layout pass가 실행되지 않아, 작은 셀에 큰 그림이 그려지는 겹침(0.9.4.66 근본 원인)을 이 경로로 막았다.
- **P3(0.9.4.69~.71) 비동기 전환**: GUI 디코드가 백엔드로 이동하면서 `thumbCatchUpVisible()`이 "요청 펌프"로 바뀌었다 — `fileThumb()`의 **반환값을 무시**하고, 아이콘 적용은 `onThumbReady`(백엔드 도착)만 담당하게 되었다.
- **놓친 부분**: `fileThumb()`은 메모리 캐시 적중 시 저장된 아이콘을 반환하고 **백엔드 요청을 만들지 않는다**. 따라서 캐시 적중 항목은 도착(arrival)이 영원히 오지 않아 아이콘이 옛 크기 픽스맵으로 남는다. 모드 전환 직후 `groupViewChanged`의 `doItemsLayout()`은 셀만 재계산하므로, 캐시가 따뜻한 상태에서 XL→L→XL 같은 왕복을 하면 **항목은 128px 픽스맵을 유지한 채 셀만 256 기준으로 재계산되어 겹침**이 재현된다. (미캐시 항목만 도착으로 치유되므로 부분 겹침이 된다.)
- 프로브가 못 잡은 이유: `view_mode_probe`의 catchup 시나리오는 `testDropThumbCache()`로 캐시를 비운 뒤 구동해 **전부 miss → 도착 → 치유** 경로만 검증했다. 웜 캐시(캐시 적중) 경로는 테스트가 없었다.

## 3. 변경 구조

- **`thumbCatchUpVisible()`**(gui/mainwindow.cpp): 캐시 적중 항목은 그 자리에서 적용한다.
  - `thumbCache_`에서 현재 `iconSize` 키(`path|WxH`)를 직접 조회해 적중 시 `item->icon().cacheKey()`와 다르면 `setIcon`(순수 메모리 쓰기 — 디코드·요청·리빌드 없음).
  - miss는 종전대로 `fileThumb()`로 **요청만** 한다(placeholder를 덮어쓰지 않음 — 실제 아이콘을 placeholder로 훼손하지 않기 위해 반환값을 적용하지 않는 규칙 유지).
  - 교체가 있었으면 도착과 같은 **코얼레스 layout pass**(`thumbLayoutPending_` + `singleShot(0) flushThumbLayout`)를 예약 — 스크롤 게이트 계약(제스처 중 지연/재시도) 불변.
- **`groupViewChanged()`**: delegate/크기 교체 뒤 기존 `doItemsLayout()`에 이어 `thumbCatchUpVisible()` 호출 — 모드 전환 즉시 웜 캐시 아이콘이 재적용되고 miss는 요청된다(다음 틱 대기 불필요).
- **테스트**: `ui_scroll_regression_test` phase 21(웜 캐시 왕복) + 훅 `testCachedThumb(path,size)`. XL(256)과 L(128)을 실제 도착 경로로 워밍한 뒤 XL→L→XL 왕복에서 항목 아이콘이 **캐시의 정확한 아이콘(cacheKey)** 으로 복원되는지 검증. 수정 전 `XL icon restored=0` **FAIL** 재현, 수정 후 PASS.

## 4. 해결된 상황

- 캐시가 따뜻한 상태의 모든 보기 전환(리스트/자세히/타일 ↔ XL/L/M/S)에서 항목 아이콘이 현재 크기로 즉시 복원되고, 교체 후 layout pass가 보장되어 셀과 그림 크기가 일치한다 — 겹침이 생기지 않는다.
- 0.9.4.61 스크롤 계약(캐치업은 리빌드 없음, 스크롤 불변) 유지: 캐시 적용은 아이콘 교체뿐이고 layout은 코얼레스/게이트 경로 그대로다.

## 6. 향후 영향 및 한계

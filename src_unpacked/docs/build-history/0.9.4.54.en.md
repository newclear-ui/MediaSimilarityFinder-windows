## 1. Why the change was needed

Two symptoms were reported:

1. Disk I/O happens and files are actually read, but the read-complete counter
   does not move
2. After Stop, the "writing search report" popup appears but never completes

## 2. Cause 1: the panel never read live values

- Fingerprint phase: no panel updates at all, frozen at 0. `onFingerprintProgress`
  only touched the status message.
- `sumValIndexed_` was written only from the post-scan snapshot. "-" all scan.
- `updateStatusCounts()` overwrote `sumValDone_` with the walked "X / Y" shape
  during scans, conflicting with the new plain-number meaning.

## 3. Cause 2: `scanFinished` had no exception exit

Popup close and `setRunning(false)` sat unprotected at the function end. Any
throw among the dozen calls leaves the popup open forever with no way back to
idle. Flush (bounded ≤1000), prune (single DELETE), and the walker
(cancel-aware, bounded waits) were verified by code, so the remaining risk is
this exception path.

## 4. New structure

### Live read counter

- `onFingerprintProgress` also updates `sumValDone_` (hashed file count)
- New engine `analyzedCount()` atomic accessor, incremented at the same sites
  as `r.analyzed`, so live and final agree by construction
- `updateStatusCounts` writes `sumValDone_` (plain) and `sumValIndexed_`
  (live engine analyzed) during scans, matching post-scan format

### scanFinished hardening

Body wrapped in try/catch guaranteeing popup close and idle return. Exceptions
go to scanLog with state preserved. This does not fix a hang; it guarantees no
stranded popup on the exception path.

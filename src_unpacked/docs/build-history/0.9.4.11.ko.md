# MediaSimilarityFinder v0.9.4.11 — Node C3: Opportunistic Recalibration

C3 검증 기준점. 정상 profile 존재 실행에서 live 관측이 반복적으로
baseline과 어긋날 때만 짧게 재측정한다. 엔진 1.5.0·DB 1.0.3·캐시
v9·schema 2 불변.

## 변경 필요성
- C2까지 profile은 최초 1회 쓰고 고정됐다. 하드웨어·드라이버·부하
  환경이 바뀌면 baseline이 현실과 어긋나는데도 갱신 경로가 없었다.

## 기존 구조
- Missing/Hard에서만 calibration, Exact/Soft는 영구 재사용.

## 변경 구조
- `DeviationTracker` (calibration.h/.cpp): 스캔당 live pair vs
  feeding baseline 비교. 어느 한쪽 25% 초과 이탈이 3연속일 때만
  발화, 발화 후 카운터 리셋(다음 발화는 새 3연속 필요). profile 교체
  시 카운터 리셋, 무효 입력은 발화 대신 리셋.
- 고정 정책 수치: threshold 25%·repetitions 3·consistency 40%·
  confidence ±0.1(상한 0.95·하한 0.1). 잠정치임을 명시한다.
- 후보 일관성: fresh candidate가 발화 live 관측과 40% 이내로 맞아야
  교체. 불일치면 metrics 유지 + confidence 하향. 실패면 파일
  무수정(기존 profile 보존).
- `[lastUpdate]` 영속화(reason·old/new id·confidence, 부재=미갱신).
  id는 identity 기반이라 보통 old==new이며 연속성 표시다.
- 엔진 `finishScan`: 완료 스캔 + profile-fed + 양쪽 live rate 실측일
  때만 trigger 평가. 발화 시 bounded 재측정 후 위 규칙 적용. 전체
  try/catch — 재측정은 스캔을 실패시킬 수 없다. 취소 스캔은 제외.
- CPU-only 스캔은 GPU live 관측이 없어 trigger 평가 자체에 안 들어간다
  (profile도 pair를 안 주므로 정합).

## 선택 이유
- 단일 outlier 금지는 카운터 리셋 한 줄로 강제된다. 복잡한 통계
  검정이 아니라 반복 규칙이다.
- 후보 일관성은 "새 측정이 live와 맞는가" 하나만 본다. 하드웨어가
  바뀌는 중인 측정은 버리고 기존값을 깎는 게 안전하다.
- confidence 조정은 ±0.1 고정 스텝. C2의 0.8/0.5와 같은 보수 체계다.

## 해결된 문제
- profile lifecycle이 닫혔다: 생성(C2)→재사용→drift 감지→갱신/유지.

## 정확성 영향

  `scan_workflow_test` 동일, parity 스위트 통과.

  부재로 로드, forward-compat 무시 규칙과 정합).

Baseline `0.9.4.69` -> this build `0.9.4.70`.

## 1. Why the change

- At the end of P3 two decoder remnants stayed in the GUI (detail-pane
  resolution/duration probes). Per directive §3 (no direct FFmpeg calls in
  the GUI), P4 moves them to Backend requests.
- Check the §15 15-item checklist against evidence, prove G13 at binary
  level, and lock the numbers.

## 2. Previous structure

- `fileResolution()` ran VideoDecoder/QImageReader/WIC/ffprobe directly.
  The duration fallback opened `VideoDecoder` directly.

## 3. New structure

- New `src/file_meta.*` (`FileMeta`, std `ffprobeSize`).
- `BackendSession::requestFileMeta`: engine records first, then one
  Backend-side decode chain (video info / dimensionsFast / ffprobe).
- IPC `GET_FILE_META`/`FILE_META` plus supervisor forwarding plus GUI
  `requestFileMeta`/`onFileMetaReady` (pending map, stale-drop, arrival
  repaints detail/fileGrid). Same Type B pattern as thumbnails.
- Remaining QtGui use in the GUI is presentation-only (QIcon display,
  EXIF text tags — never pixel decode).

## 4. Resolved state

- The GUI process performs no media pixel decode at all.
  WIC/FFmpeg/CUDA/native decode all live in the Backend.

## 5. Verification

### §15 checklist against evidence

1. No direct index-DB thumbnail open/write: `thumbDb_` member, open, put,
   prune, and flush all deleted (grep: zero hits). Backend is the sole writer.
2. No thumbnail path collision: GUI requests plus memory cache only;
   creation is Backend-only.
3. No GUI thumbnail fallback: shell/QImageReader/WIC/VideoDecoder branches
   all deleted. EXIF text tags remain (string metadata).
4. No synchronous wait API on BackendClient: none in the interface (verified).
5. No waitFor/blocking read on the GUI thread: supervisor uses QTimer
   escalation only. Sole exception: the 3s bounded msleep loop in
   `shutdown()` (app-exit path, documented G3 exception, no event pumping).
6. Scan independent of IPC speed: async Qt-buffered backend writes, chunked
   matches, GUI never blocks (E2E scan completions prove it).
7. MATCHES/FINISHED/FAILED lossless: chunking, no drop path in code. E2E
   rescans prove full delivery.
8. No spawn while the old backend lives: guards in both `spawn()` and
   `onRestartTimeout()` (code) plus only sequential PIDs observed in E2E.
9. Non-blocking escalation: QTimer-based (outside the documented shutdown
   exception).
10. No orphans: Job Object KILL_ON_JOB_CLOSE (code) plus backend stdin-EOF
    self-exit (measured via the SHUTTING_DOWN path when pipes close).
11. UTF-8/framing: `backend_ipc_test`, 7 checks (UTF-8 path round-trip,
    malformed/oversize/protocol rejects).
12. Stale nonce drop: code plus normal operation through the E2E restart storm.
13. Backend Qt dependencies: **measured with dumpbin — Qt6Core.dll plus
    turbojpeg only. No Qt6Widgets/Qt6Gui.**
14. Loopback/real split: unit GUI tests pass unmodified on the loopback
    default; only `backend_e2e_test` uses real processes.
15. P1→P4 independently verified: each version released after full CPU/GPU
    CTest (.67: 114/115, .68: 114/115, .69: 116/117, .70: 116/117).

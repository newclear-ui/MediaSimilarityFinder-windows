# MediaSimilarityFinder v0.9.4.67 — P1 BackendCore 경계 + Backend 진입점

기준선 `0.9.4.66` → 본 빌드 `0.9.4.67`.
CPU CTest **111 → 114**, GPU CTest **112 → 115** (신규 backend 3종).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 검색 의미·동작 변경 없음.

## 1. 변경 필요성

- 프로세스 분리 P0 인벤토리 + Brief 보완(G1–G13) 완료. P1은 "동일
  프로세스에서 BackendCore 경계를 확정하고 진입점을 세우는" 단계다.
- 핵심 발견: 기존 `msf_core` 타겟이 이미 BackendCore 그 자체다
  (engine·database·monitor·scanner·decoder 전부, Qt 링크 없음,
  `src/*.h`의 Qt include 0건). 따라서 파일 이동 없는 경계 선언이면 된다.

## 2. 기존 구조

- `msf_core` STATIC lib (src/*) + GUI exe가 in-process로 전량 사용.
- Backend 실행 파일 없음. portable에는 GUI exe만 복사.

## 3. 변경 구조

- `msf_core`에 BackendCore 경계 주석 명시 (Qt 무의존 유지 계약).
- 신규 `src/backend_main.cpp` + `MediaSimilarityFinderBackend` 타겟:
  `msf_core` + `Qt6::Core`만 링크 (Widgets/Gui 없음, G13).
  콘솔 subsystem이라 stdio가 동작한다 (`--help`/`--version` 확인,
  향후 P3 line-oriented IPC 채널용).
- `--help`/`--version` 정상 (exit 0). `--backend`는 P3 도착 전이므로
  명시적 거부 (exit 2, WILL_FAIL 테스트로 계약화).
- `package_portable.ps1`이 Backend exe를 GUI 옆에 복사
  (supervisor가 application directory에서 찾는다, PATH 탐색 없음).
- GUI 동작 변경 없음 (여전히 in-process).

## 4. 해결된 상황

- BackendCore가 독립 빌드·독립 링크·독립 실행(^help/^version)된다.
  portable에 Backend exe가 포함된다. P2 Loopback/P3 spawn의 토대가 됨.

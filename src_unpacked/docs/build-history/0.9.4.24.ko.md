# MediaSimilarityFinder v0.9.4.24 — QSettings Organization 이름 변경

portable UI settings identity를 개인 식별자에서 제품명 기반으로 바꾸고,
기존 사용자 설정을 **안전하게 1회 마이그레이션**한다.
Engine 1.5.0·DB 1.0.3·cache v9 **불변**, search verdict 의미 **불변**.

---

## 1. 변경 필요성

`QCoreApplication::setOrganizationName()` 값은 설정 디렉터리 이름이 되어
**portable 배포물에서 사용자에게 보이는 산출물**이다. 기존 값 `newclear-ui` 는
GitHub 계정(owner) 이름이라 개인 식별자가 그대로 배포된다.

```
기존: <appDir>\newclear-ui\MediaSimilarityFinder.ini
변경: <appDir>\MediaSimilarityFinder-ui\MediaSimilarityFinder.ini
```

단순 문자열 치환만 하면 기존 사용자의 window geometry·splitter·헤더·view mode가
사라진 것처럼 보이게 된다. 그래서 migration 이 이 작업의 핵심이다.

## 2. 기존 구조

`gui/mainwindow.cpp::initAppSettings()`:

```cpp
QCoreApplication::setOrganizationName("newclear-ui");
QCoreApplication::setApplicationName("MediaSimilarityFinder");
QSettings::setDefaultFormat(QSettings::IniFormat);
QSettings::setPath(QSettings::IniFormat, QSettings::UserScope, portableDir);
```

`gui/main.cpp` 가 `initAppSettings(QCoreApplication::applicationDirPath())` 로
1회 호출. `MainWindow` 생성자는 곧바로 `QSettings().value("ui/ignored")` 를
읽으므로, migration 은 identity 설정 **직후**에 완료되어야 한다.

활성 코드 내 `newclear-ui` 사용처는 이 **1곳뿐**이었다. 나머지는 GitHub
repository owner 표기(`development-chat-handoff.*`)와 역사 build-history
문서로, 변경 대상이 아니다.

## 3. 변경 구조

```
Organization : newclear-ui              → MediaSimilarityFinder-ui
Application  : MediaSimilarityFinder    → (변경 없음)
Executable   : MediaSimilarityFinder.exe→ (변경 없음)
CMake target : MediaSimilarityFinder    → (변경 없음)
```

`setDefaultFormat` / `setPath` 조합은 **그대로 유지**했다. 이번 변경의
목적은 Organization Name 뿐이다.

organization/app 이름은 `kSettingsOrganization` / `kSettingsApplication`
상수로 분리해 문자열 하드코딩을 없앴고, legacy 값은 migration 전용으로만
남겼다 (활성 identity 로 되돌아갈 수 없도록).

## 4. 마이그레이션 전략

`initAppSettings()` 내부에서, identity 설정 직후 실행한다.

| Case | 상황 | 동작 |
| --- | --- | --- |
| A | 새 위치만 존재 | 아무것도 하지 않음 (migration 수행 안 함) |
| B | legacy 만 존재 | 복사 → 검증 → legacy 제거 |
| C | 양쪽 모두 존재 | **새 위치 승리, legacy 보존** (덮어쓰지 않음) |
| D | 복사/디렉터리 생성 실패 | legacy **삭제하지 않음**, 오류 무시하고 계속 |
| E | 새 INI 검증 실패 | 새 파일을 사용 불가로 처리하고 제거, legacy 보존 |

### 삭제 정책 (엄격한 순서)

```
legacy INI 존재
   → 새 INI 복사
      → 새 INI를 실제 QSettings로 open
         → status() == NoError 확인
            → 핵심 key 존재 확인 (ui/mainGeom, ui/splitter)
               → 검증 성공 시에만 legacy INI 제거
                  → legacy 디렉터리가 비었을 때만 rmdir
```

legacy 디렉터리 안에 예상 못한 파일이 남아 있으면 디렉터리 전체는
삭제하지 않는다 (`isEmpty()` 확인 후에만 `rmdir`).

검증 실패 시 새로 복사한 파일을 `remove` 하여 "설정이 없는 새 위치"로
되돌리고, legacy 는 그대로 남긴다. 따라서 어떤 실패 경로에서도
**기존 사용자 설정이 사라질 수 없다.**

Case C(new wins) 덕분에 이 migration 은 **idempotent** 하다: 두 번째 실행은
early-return 하여 재 덮어쓰기가 없다.

## 5. 해결된 문제

- 개인 식별자가 배포물에 노출되던 문제 해결
- 기존 사용자의 UI 상태가 사라지는 위험을 migration 으로 제거
- migration 실패 시에도 데이터 손실이 없는 구조 (D/E 케이스)

## 6. 해결하지 않은 것 (의도적 범위 제한)

`mainwindow.cpp:2641` 의 QuickLook uninstall 탐색은
`QSettings(root, QSettings::NativeFormat)` — **명시적 path + NativeFormat**
이므로 organization 이름과 무관하며 **수정하지 않았다.**

패키징 스크립트는 `newclear-ui` 나 `.ini` 를 직접 다루지 않아 영향이 없다.

## 7. 테스트

`tests/ui_settings_test.cpp` 에 cross-process migration 회귀를 추가했다.
같은 프로세스 read-back 은 QSettings 인메모리 캐시로 인해 **디스크
영속성이 깨져도 통과할 수 있으므로** 각 phase 를 별도 프로세스로 분리했다.

| 테스트 | 검증 내용 |
| --- | --- |
| `ui_settings_migrate_plant` | legacy INI 를 실제 파일로 생성 (QApplication 없이) |
| `ui_settings_migrate_verify` | 신규 migration → 새 위치 생성, legacy 제거, 값 5종 보존, organization 확인, 재실행 no-op |
| `ui_settings_migrate_both_plant` | 양쪽 위치에 서로 다른 값 생성 |
| `ui_settings_migrate_both_verify` | **새 위치 승리 + legacy 보존** |
| `ui_settings_migrate_none_verify` | legacy 없음 → 아무것도 창작되지 않고 새 INI 만 생성 |

기존 cross-process round-trip(`ui_settings_write` / `ui_settings_verify`)은
그대로 유지되며, 새 organization identity 아래에서 계속 통과한다.

## 8. 실제 실행 검증 (임시 portable 디렉터리)

`build-windows-gpu\Release` 산출물 + Qt plugin 을 임시 디렉터리에 복제해
실제 `--smoke` 실행으로 확인했다.

### Case B — legacy 만 존재

```
시작 전: portable-test\newclear-ui\MediaSimilarityFinder.ini  (11 keys)
실행 후: portable-test\MediaSimilarityFinder-ui\MediaSimilarityFinder.ini
         legacy 디렉터리 제거됨
         11개 key 전부 보존, 값 동일
         (lastFolder/language/kindMask/groupView spot-check 통과)
```

### Case C — 양쪽 공존

```
legacy 보존됨      : True
새 위치 값 사용됨  : language=en  (legacy 의 ko 가 아님)
```

### Case A — 새 위치만 존재

```
legacy 디렉터리 생성되지 않음 : False (미생성)
새 INI 생성됨                 : True
```

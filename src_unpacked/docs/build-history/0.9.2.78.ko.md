# MediaSimilarityFinder v0.9.2.78 — 고정 사전 카운트·선택 필터 정합화

## 변경 필요성
사전 카운트가 전체 파일을 세는 반면 엔진은 미디어 확장자만 본다. 결과: 총 파일(전부) vs 검색 완료(엔진 스트리밍값) 두 숫자가 서로 다른 universe라 분모가 또 흔들렸다. 이전 보고서의 “고정 분모”는 카운트 위치만 고쳤고 실제 선택 규칙까지 공유하지 않아, 이미지 검색·무시 목록·Index 제외에서 계속 어긋났다.

## 기존 구조
- 사전 워크: 확장자 무관 전부 계수, Index 제외 없음, 무시목록 대충 비교

## 변경 구조
- **단일 선택 기준**: `Scanner::isMediaPath/isVideoPath`와 `Scanner::count`를 추가해 목록 확장자·대소문자 규칙을 스캔과 사전 카운트가 공유
- **고정 분모**: 이미지/영상 선택 및 무시 경로를 반영한 전체 미디어 수를 스캔 시작 전에 1회 계산. 0개도 유효한 값으로 추적
- **진행 수 분리**: 엔진의 분석 완료 수와 디렉터리 walker의 선택 대상 통과 수를 `walked` 콜백으로 분리. 요약·상태바·진행률은 고정 전체를 분모로 사용
- **저장 결과 필터**: 빠른 재로딩과 최종 파일 목록도 현재 이미지/영상 선택 및 무시 경로를 동일하게 적용
- `scan_streaming_test`에 비미디어·영상·무시 BMP를 추가하고 이미지 선택 target==4를 검증
- 버전 표기 통일 → 0.9.2.78

## 해결된 상황
- 이미지 검색이면 그림 파일 수, 영상이면 영상 수, 둘 다면 미디어 합이 먼저 고정 표시. "몇개중 몇개"가 전 구간 일정
- 분석이 끝난 수와 파일 목록을 통과한 수를 분리해, 디코딩 지연·변경 파일·증분 재검색 중에도 표시 숫자가 실제 walker 진행을 따름

## 향후 영향
- 심볼릭링크·권한 거부 등 극단 케이스는 엔진과 1~2개 차이 가능. 허용 오차로 문서화

# MediaSimilarityFinder v0.9.4.66 — 보기 모드 전환 후 이미지 겹침 수정

기준선 `0.9.4.65` → 본 빌드 `0.9.4.66`.
CPU CTest **111/111**, GPU CTest **112/112** (view_mode_probe 대폭 확장).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변.
엔진·DB·schema·cache·scheduler·GPU backend 미접촉. Test Mode 미접촉.

## 1. 변경 필요성

- 0.9.4.63 manual acceptance에서 발견된 회귀 (0.9.4.63 기록은 소급 수정하지
  않음): 가운데 유사 그룹 목록을 다른 보기 모드로 바꿨다가 Extra Large
  (256 Icon)로 돌아오면 사진이 서로 겹친다. 최초 표시는 정상이고,
  List/Grid/스크롤/scrollbar/Home/End는 모두 정상이다.
- 0.9.4.61 scroll 회귀와는 다른 문제로 분리한다.

## 2. 기존 구조

- `groupViewChanged(int)`: 같은 QListWidget item을 유지한 채 viewMode,
  iconSize, gridSize, delegate를 연속 변경. 전환 자체는 layout을 예약한다.
- `thumbCatchUpVisible()`: 틱마다 보이는 item의 thumb를 현재 iconSize로
  재생성해 in-place 교체. layout·scroll·rebuild를 건드리지 않는 것이
  0.9.4.61 계약이다.
- thumb 캐시 키는 `path|WxH`이라 보기 모드 전환 후 catch-up이 새 크기의
  thumb를 전달한다.

## 3. 변경 구조 (근거: probe 실측)

재현 체인 (view_mode_probe `catchup` 모드로 확정, 수정 전 FAIL 확인):

1. List → 256 전환 직후 layout은 이전(작은) thumb 기준으로 셀을 잡는다
   (probe: 254x71 셀).
2. catch-up이 256px thumb를 `setIcon()`으로 교체한다.
3. `setUniformItemSizes(true)` + `Batched`에서 icon 교체는 layout pass를
   실행하지 않는다 (60회 펌프 후에도 frozen, 강제 `doItemsLayout()` 시에만
   282x295로 재계산됨).
4. 작은 셀에 큰 그림이 그려져 겹쳐 보인다. rect 자체는 겹치지 않아
   단순 `intersects()` 검사로는 안 잡힌다.

적용한 최소 수정 (`gui/mainwindow.cpp` 2곳 + 테스트 hook 1개):

- `thumbCatchUpVisible()`: 실제로 icon이 바뀐 경우에만 마지막에
  `grid->doItemsLayout()` 1회. loop·budget·in-place 의미·scroll은 그대로.
  (`scheduleDelayedItemsLayout()`는 protected라 public인 동기 버전을 쓴다.
  변경이 있을 때만 실행되고 index 계산만 하므로 widget churn이 없다.)
- `groupViewChanged()` grid 분기 끝: delegate/size 교체 후
  `grid->doItemsLayout()` 1회. item 재생성 없음, scroll 미접촉.
- `testThumbCatchUp()` public hook 추가 (기존 `testUiTick` 패턴과 동일).
  제품 코드는 호출하지 않으며, probe가 실제 catch-up 경로로 thumb 전달을
  구동하게 한다.

하지 않은 것 (지시 8항 준수): `refreshGroupList()`/`fillPair()` 호출 없음,
scroll anchor·gate·catch-up 구조·thumbnail cache·engine·Test Mode 미접촉,
제품 코드에 `processEvents()` 없음.

## 4. 해결된 상황

- 보기 전환 후 thumb가 도착해도 셀이 재계산되어 겹침이 생기지 않는다.
- scroll 회귀 테스트가 강제하는 0.9.4.61 계약
  (catch-up tick은 rebuild하지 않음)은 그대로 PASS.

## 5. 검증

### `view_mode_probe` (CPU·GPU PASS, 201 checks)

- 기존 GRID/DELEGATE round-trip 유지.
- 신규: 실제 MainWindow + 41그룹 fixture + viewBox 직접 구동.
  6개 경로(→List/128/64/Tiles/Details→256) × 3개 모드
  (settled/rapid/catchup) = 18 시나리오.
- 판정: 개수 유지 + 면적 겹침 0 + 수렴(snapshot == 강제 layout) +
  catch-up icon 교체 확인 + 전수 커버리지 + vbar 축소(256 모드).
- 수정 전 FAIL (frozen vbar + 미수렴), 수정 후 PASS를 양쪽 빌드에서 확인.
- headless 한계: thumb가 null/placeholder라 절대 크기 대신 수렴·개수·
  겹침·vbar 변화를 본다. 실제 사진 육안은 사용자 재검증 항목으로 남긴다.

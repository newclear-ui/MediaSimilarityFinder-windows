기준선 `0.9.4.152` → 본 빌드 `0.9.4.153`.
CPU CTest **128/128**, GPU CTest **129/129** (신규 `ui_cancel_consistency_test` 1건).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` / `kProtocol 1` 불변 (판정·스키마·버전 상향 없음).

## 1. 변경 필요성

- P1-A: `.152`의 부분 채택은 baseline을 "유지"했다. 기준선이 이미 유효한 상태의 부분 채택은 범위 밖 미검증 쌍을 남긴 채 다음 A/AB의 전체 검증을 생략한다. 무효화가 정답이다.
- P1-B: 취소·예외·엔진 실패 보고에서 변경 파일이 반영됐는데 baseline이 유효한 채 남으면, 불완전한 매치 집합을 완전한 것으로 오인한다. 최종 저장 실패 경로(`.151`/`.152`)는 이미 무효화하므로 나머지 종료 경로를 같은 규칙으로 맞춘다.

## 2. 기존 구조

- 부분 채택: meta 전체 유지(`.152`). 취소: 변경분 persist+GUI 재적용은 있었으나 baseline 유지. 예외 catch: persist+failed 보고는 있었으나 baseline 유지. 엔진 실패 보고(`!r.completed`, 비상vexception): "Scan complete"로 보고됐다.

## 3. 변경 구조

- **P1-A**: 부분 채택 트랜잭션 안에서 `match_baseline` 키를 삭제한다(전체 범위 채택은 scratch meta 전체 upsert 유지). 삭제 실패 시 전체 롤백(기존 원자성 그대로). 다음 A/AB는 강제 전체 검증을 1회 수행하고 restamp한다.
- **P1-B**: 취소·표준 예외·비표준 예외 경로에서 `changedFiles_`가 비어 있지 않으면 baseline을 무효화한다(가드된 try/catch, 기존 no-throw 계약 유지). 엔진 실패 보고(`!r.completed` + 미취소)는 `failed|msfChanged=N`을 내보내고 results를 내보내지 않는다(append-only 계약 유지, 위치 인덱스 불변). 사용자 취소가 실패로 분류되지 않는다(취소 분기 우선).
- 회귀: e2e `Test 1h3`(신규, 유효 baseline+부분 채택 → 무효화 → 강제 전체 검증 실측 → restamp + 쌍 보존/제거). `crash_diagnostics_test` §5(신규, 변경 승인 후 취소 → CANCELLED + 무효화 + 강제 전체 검증 + 쌍 정합), §6(신규, 예외 경로 무효화), §4 확장(저장 실패 무효화 주장). `ui_cancel_consistency_test`(신규): 루프백 인프로세스에서 진행 신호 기반 결정적 취소 → GUI==DB 완전 집합 일치 검증 → 강제 전체 검증 → restamp (고정 sleep은 스캔 꼬리와 경합함을 확인하고 진행 신호 대기로 확정). `MSF_TEST_ENGINE_FAIL`(신규 seam, 엔진 실패 보고 결정적 재현). 테스트 읽기 busy_timeout 적용(일시적 SQLITE_BUSY "" 오독 방지; 진짜 불일치는 그대로 검출).

## 4. 해결된 상황

- 유효 baseline 상태의 부분 채택이 다음 검색의 전체 검증을 생략하지 않는다.
- 취소·예외·엔진 실패 후에도 불완전한 집합이 완전한 것으로 오인되지 않는다. GUI는 기존 재적용 경로로 DB와 일치한다.
- 진짜 DB 저장 실패·엔진 실패는 성공으로 보고되지 않는다.

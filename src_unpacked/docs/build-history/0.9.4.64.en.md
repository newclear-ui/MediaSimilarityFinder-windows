# MediaSimilarityFinder v0.9.4.64 — Display option folded into the settings dialog general tab

Baseline `0.9.4.63` -> this build `0.9.4.64`.
CPU CTest **111/111**, GPU CTest **112/112** (no new tests, all existing PASS).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged.
`src/media_search_engine.cpp`, scheduler, color_thumb, NVDEC, and sparse untouched.

## 1. Why the change

- 0.9.4.63 put "Settings" (monitor settings) and "Display settings" (Show
  Detailed Logs) side by side in the ☰ menu. A whole extra dialog for one
  checkbox splits the settings entry point in two.
- User correction: drop the separate display-settings dialog and move the
  option into the general tab of the existing settings dialog. One settings
  entry point.

## 2. Previous structure

- ☰ menu: `monSettingsAct_` ("Settings" -> `configureMonitor`) plus a
  separate action ("Display settings" -> a separate `QDialog`).
- Separate dialog objectName `displaySettingsDlg`, action `displaySettingsAct`,
  geometry key `ui/displaySettings`.
- Checkbox string key `displaySettings`.

## 3. New structure

- Separate dialog, action, and the `ui/displaySettings` key all removed.
- `configureMonitor()` general tab gains the "Show Detailed Logs" `QCheckBox`
  (objectName `showDetailLogBox`, string key `showDetailLog`).
- Dialog objectName `settingsDlg` and ☰ action `settingsAct` added
  (automation hooks, same pattern as the existing `folder_`).
- The persist key stays `ui/showDetailLog`. OFF hides the toolbar checkbox
  via `logTglAct_` only; the checked state and telemetry wiring stay intact,
  so re-showing restores the existing UI (0.9.4.63 behavior kept).
- The tr-key pin in `ui_settings_test.cpp` moved from `displaySettings` to
  `showDetailLog`.

## 4. Resolved state

- One settings entry point again. The home for display options is the
  settings dialog general tab (the Test Mode follow-up Settings decision
  belongs to the same family).
- Round-trip behavior unchanged: OFF persist plus hide plus state kept, then
  ON persist plus re-show.

## 5. Verification

### `ui_usability_test` (13 checks, PASS on CPU and GPU)

- Driver moved from `displaySettingsDlg`/`displaySettingsAct` to
  `settingsDlg`/`settingsAct`. Same checks, same count.
- Test-owned race fixed: the benchmark-summary closer closed *every* modal,
  sometimes closing the settings dialog first in Phase A (the ON round-trip
  failed flakily — the second trigger reached the slot, but the closer shut
  the dialog immediately). The closer now starts only for the scan phase
  (Phase C); debug markers removed. This race is test-only, not a product
  change.

# MediaSimilarityFinder v0.9.3.19 — PDH 디스크 카운터 수정·통합 프롬프트 검토 반영

## 변경 필요성
- 0.9.3.18 벤치마크에서 `diskVolume:"G:"`는 잡혔으나 `diskAvailable:false`였다. 첫 `PdhCollectQueryData`가
  rate 카운터 특성상 `PDH_NO_DATA`를 내는 경우가 있는데 이를 치명 오류로 간주해 쿼리를 닫아버린 것이 원인이다.
- 외부 통합 프롬프트 문서(v0.9.3.14 기준 작성)의 메타·제약·일정이 실제 릴리스(0.9.3.15~18)와 어긋나 있었다.

## 기존 구조
- 카운터 추가 + 첫 수집이 모두 성공해야 `diskAvailable=true`가 됐다.
- 통합 문서는 기준선 d806e5f·엔진 1.2.0·캐시 v8·CTest 61/60을 전제로 했다.

## 변경 구조
- 첫 수집은 best-effort로 바꾸고 카운터 추가 성공만으로 available을 판단한다.
  틱 샘플링은 실패를 허용하고 성공분만 기록한다(기존 로직 그대로).
- 통합 문서에 §0-1 검토 상태를 추가했다. §8 버전 매핑은 폐기하고 실제 이력으로 대체,
  항목별 상태(P0-1 미착수~P3-4 유효)를 표로 정리, CTest 63/63·허용 오차 1e-6·캐시 v9로 갱신했다.
- 리포 잔여 문서 수정: `video-gpu-hash` 한·영에 temporal MSSIM GPU 한정 명시,
  `candidate-index` 한·영에 fold 식별자 주석, `BUILD_STATUS.md` 깨진 `??` 대시 복구,
  `AGENTS.md` 판정-의미 문구로 교체, `llms.txt` 캐시 v8 잔재 수정.

## 해결된 상황
- 카운터가 존재하는 볼륨에서는 첫 틱부터 디스크 I/O가 기록된다.
  카운터 자체가 없으면 종전대로 `diskAvailable:false`다.
- 통합 문서가 현재 상태를 가리킨다.

## 검증

- CPU-only Release 빌드 PASS, **CTest 62/62 PASS**.
- Portable v0.9.3.19 생성 및 smoke PASS, `--version` 0.9.3.19.

## 향후 영향
- 판정·엔진 버전 불변이므로 재검증이 필요 없다.
- 네트워크·가상 드라이브처럼 LogicalDisk 카운터가 없는 볼륨은 계속 false다.
  필요하면 프로세스 누적 I/O(`procIo*`, 항상 기록)를 대용으로 본다.

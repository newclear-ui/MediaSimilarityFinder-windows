# MediaSimilarityFinder v0.9.2.64 — Direct Stop Delivery + Video Diagnostic Counters

## Need for change
Runtime audit verdict: pause/stop buttons could never act mid-scan. Their QueuedConnection slots wait behind `run()`, which occupies the worker thread's event loop for the whole scan. Only button cosmetics changed while flags stayed unset, neutralizing StopCheck, checkpoints, and the CANCELLED UI together and forcing force-quits. There was also no way to localize where a "3 hours, 0 results" video scan loses pairs (index vs candidate vs temporal vs match).

## Previous structure
- `togglePauseScan`/`cancelScan` invoked worker slots via `invokeMethod(..., QueuedConnection)`, which can never fire while `run()` blocks the loop
- No per-stage video counters in `SearchReport`/`ScanStats`

## New structure
- **Direct calls**: `worker_->pause()/resume()/cancel()` invoked directly. All three only store atomics, so thread-safe. The destructor's direct `worker_->cancel()` is precedent. Fixes the structural defect
- **Diagnostic counters**: `ScanStats.videoCandidates/videoTemporalChecks`, `SearchReport.indexedVideos/videoCandidatePairs/videoTemporalChecks/videoMatches`. One `videoStats` line into `msf_scan.log` at scan end (complete and cancelled). The `finished` message format (parsed positionally) is untouched
- Version strings unified → 0.9.2.64

## Resolved situation
- Pause/stop take effect immediately mid-scan. CANCELLED path, partial saves, and partial display actually work
- A video zero-result case is localizable to a stage from one log line

## 1. 변경 필요성

사용자 지적: 동일 사진의 파생본 3장(원본/워터마크+크롭/스티커, `D:\Temp\OpenCodeWork\100`)이 모두 100%로 표시되어 "동일 파일"로 오해된다. 감사 결과:

- 100.0%는 **해시 거리 0**(전체/미러/크롭 variant 중 하나가 비트 동일)에서만 나오며(블렌드 최대 99.2), 그 순간 `verifyImagePair`의 fast path(≥97)가 **SSIM을 생략**한다. 실측(프로브): 3장의 3쌍 모두 거리 0, SSIM을 강제 실행하면 99.34/99.82/99.69%.
- 사용자 데이터(ss_twit 인덱스 177,594파일/15,187쌍) 실측: 100.0% 쌍 11,817 중 **내용 동일(크기+quick_hash) 3,511 / 비동일 파생본 8,306**(관련 파일 11,995). 비동일 8,306쌍을 A안(항상 SSIM 블렌드)으로 검증하면 G: 드라이브 디코드 실측(중앙값 43ms, 평균 66ms; C: 기준선 4.1ms) 기준 **직렬 +8.0~12.3분**(재스캔 verify 592s 대비 +80~125%) → **A안은 비용이 크다**.
- 결정: **B안(표시 의미 명확화) 먼저** — 판정·수치·검증 비용을 바꾸지 않고, 100.0% 옆에 "무엇이 100인지"를 표시한다. A안(정직 수치)은 비용 근거와 함께 재검토 조건으로 보류.

## 2. 기존 구조

- GUI는 매치 percent만 받았다(`matchRows` 3필드 `left\tright\tpercent`, `BackendMatch` 4필드). 파일의 quick_hash는 인덱스 DB 내부 값이며 GUI에 도달하지 않았다.
- 그룹 기준 파일은 관례상 "100% · 기준"으로 표시되고, 나머지 파일은 percent 그대로(100.0% 포함) 표시됐다.
- 엔진 `MediaFile`에는 quick_hash가 없었고, 최종 분석 패스의 `files_`는 DB 재구성(크기/수정/지문/크롭만)이었다.

## 3. 변경 구조

- **엔진**: `MediaFile.quickHash` 추가(라이브 분석/비디오/재검증 toMedia/최종 DB 재구성 4경로 모두 채움). `MediaMatch.contentIdentical`·`SearchMatch.contentIdentical` 추가, `ScanPipeline::sameContent()`(크기 동일 && quick_hash 비어있지 않고 동일)로 판정. 병렬 이미지 패스·순차 패스·비디오 패스·`addAndMatch` 라이브 패스 전부에서 설정.
- **최종 패스 재구성 버그 수정**: `scan()`이 DB에서 `files_`를 재구성하는 지점(line 1015-1021)에 quickHash 전달 누락 → 이 수정이 없으면 모든 100.0%가 "지각 동일"로 잘못 표시됨(테스트에서 검출).
- **전송**: `LiveMatch` → `BackendMatch`(identical 필드) → IPC `matchJson(identical)`/supervisor 디코드 → `matchRows` 4번째 필드(`0/1`, 구 3필드도 허용). `loadMatches()`와 `BackendSession::loadIndex`는 DB의 quick_hash로 동일성을 계산(추가 I/O 없음: loadIndex는 이미 읽은 states 재사용, loadMatches는 open 시점 스냅샷 `candidateStates_` 재사용).
- **GUI**: `contentFlag_`(bit1=동일 내용 100% 쌍 존재, bit2=지각 동일 100% 쌍만 존재). `pctText()`가 100.0%에서 배지를 붙임: `100.0% · 동일 내용` / `100.0% · 지각 동일`(EN: identical content / perceptual match). 그리드·리스트·상세 유사도 행 전부 동일 규칙. 기준 파일의 "100% · 기준" 관례는 불변.
- **비용**: 표시 전용 — 디코드/SSIM/판정/그룹/percent/저장 쌍 전부 불변. quick_hash 비교는 메모리 문자열 비교뿐.
- 번역키 2개 추가(`identicalContent`/`perceptualMatch`), tr-keys 69 → **71**.

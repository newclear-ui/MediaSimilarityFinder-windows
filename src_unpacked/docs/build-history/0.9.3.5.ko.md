# MediaSimilarityFinder v0.9.3.5 — 엔진 썸네일 재사용 + 스크롤 점프 수정

## 변경 필요성
1. 미리보기가 느린 근본 원인은 중복 디코드였다. 스캔 워커가 모든 이미지를 2회,
   모든 비디오 프레임을 2회 디코드하는데 GUI가 표시용으로 같은 파일을 또 디코드했다.
2. 스캔 중단 후 로그 팝업 전 스크롤이 멈추고 목록이 최상단으로 계속 돌아갔다.
   팝업 후에는 정상이었다. 유휴 추적 fill이 `clear()`+전체 재생성으로 스크롤을 리셋한 탓이다.

## 기존 구조
- `fileThumb`: 메모리→디스크→실패 skip→버짓→셸→QImageReader/WIC/FFmpeg.
- `fillPair`: clear 후 전체 재생성, 스크롤 위치 미보존.

## 변경 구조
- 스캔 워커가 손에 쥔 픽셀을 표시용으로 함께 넘긴다.
  이미지: crop 패스에서 128px 컬러를 추가 디코드해 결과에 포함(지문용 그레이 경로는 불변).
  엔진이 512항목 LRU(최대 ~25MB, 뮤텍스 보호)에 보관한다.
- 비디오는 기존 48px `thumb48`(메모리+영속 캐시, 디코드 없음)를 그대로 쓴다.
- GUI `fileThumb`는 디스크 캐시 다음·셸/헤비 디코드 이전에 엔진을 조회한다.
  적중분은 기존 경로로 JPEG 영속화까지 되므로 다음 재스캔에도 남는다.
- `fillPair`가 재생성 전후로 트리·그리드 스크롤 값을 저장·복원한다(범위 초과분은 자동 클램프).
- 버전 표기 통일 → 0.9.3.5.

## 해결된 상황
- 스캔된 파일의 미리보기는 GUI 스레드 디코드 없이 DB·메모리 조회로 즉시 표시된다.
- 미스캔 파일은 기존 폴백 체인 그대로다.
- 추적 fill이 스크롤을 최상단으로 되돌리지 않는다.

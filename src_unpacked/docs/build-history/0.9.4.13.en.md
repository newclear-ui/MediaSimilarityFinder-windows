# MediaSimilarityFinder v0.9.4.13 — Node C4.1: Calibration Lifecycle Fix

**GPT Fix — follow-up defect correction**

This patch closes the Calibration/Profile lifecycle gaps identified after the v0.9.4.12 C4 gate. The preserved 0.9.2.32 baseline, GPU abstraction, CUDA implementation, and CPU fallback remain unchanged.

## Why the change was needed
- A CPU-only/partial profile created while GPU was OFF could remain Exact when GPU was enabled later.
- The documented 30-day stale policy did not match the live scan path, which used a never-stale age.
- CPU-model and GPU-driver fields existed but were not populated by the engine identity builder.
- Incomplete calibration retries needed to preserve the existing profile consistently with the C4 gate rule.

## Previous structure
- Initial calibration was driven mainly by Missing/Hard verdicts.
- The scan path passed -1 for stale age.
- CPU model and driver identity could remain empty.
- An incomplete retry could be saved even when an existing profile was present.

## New structure
- profileNeedsCalibration() requests recalibration when a throughput metric required by the current execution conditions is missing, including Exact/Soft profiles.
- The default stale age is now 30 days; -1 remains an explicit diagnostic never-stale value.
- CPU model is collected best-effort and CUDA driver version is exposed by the GPU backend and included in profile identity. Unknown values remain unknown.
- An incomplete/failed retry does not overwrite an existing profile. A new profile may retain an intentional GPU-OFF partial state, and GPU-ON later triggers metric-gap calibration.
- Regression tests cover GPU OFF→ON lifecycle, stale age, and metric completeness.

## Resolved state
- GPU OFF→ON requests a fresh GPU baseline when the stored profile lacks measured GPU throughput.
- Profiles older than 30 days enter the stale path.
- Available CPU/GPU identity information participates in profile matching.
- Failed retries preserve the existing usable profile.

## Accuracy impact
- Search algorithms, thresholds, candidate indexing, and match semantics are unchanged.
- Profile data remains an initial scheduler estimate; live throughput precedence remains unchanged.

## Compatibility impact
- Profile INI schema/version is unchanged.
- CUDA abstraction and CPU fallback remain intact.
- Official baseline 0.9.2.32 is untouched.

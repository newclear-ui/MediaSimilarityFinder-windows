# MediaSimilarityFinder v0.9.4.93 — "Load" (index load-only) + popup separation

Baseline `0.9.4.92` -> this build `0.9.4.93`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

- Separate search (scan) from index lookup. The previously unused Refresh button becomes **"Load" (불러오기)**:
  select a folder and press it to load the **index content (similar-group list + previews) without scanning**.
- On load the sort is auto-set to **None** and locked.
- Popup separation: a load must never show "Writing search report"; that wording belongs to scan completion/stop only.
- The Load button is disabled after one press (no repeat clicks) with a "Loading index list" notice.

## 2. Previous structure

- The toolbar Refresh button only rebuilt the left folder tree (`refreshFolders`); it had nothing to do with results.
- Index loading (quick-load) ran **only at scan start** (`ScanWorker::run`'s `loadMatches`).
- `ThumbnailStore` lookup (`requestThumb`) returned a miss without `worker_` -> no thumbnails with no scan running.
- The wait popup (`showReportWaitPopup`) hard-coded the title `repWaitTitle` ("Writing search report").

## 3. New structure

- **IPC**: added the `LOAD_INDEX` command (`backend_ipc.h`), payload `{root, appDir}`.
- **Engine**: `MediaSearchEngine::storedFiles()` = `db_.all()` (stored file rows).
- **Session**: `BackendSession::loadIndex(root, appDir)` opens the index, reads `storedFiles()` + `loadMatches()`,
  and reports through the existing `results()`/`quickLoaded()` signals (reusing the scan's GUI population path).
  No walk, no analysis.
- **Backend server**: `LOAD_INDEX` -> `session_->loadIndex(...)`.
- **GUI client**: `BackendClient::loadIndex(root, appDir)` (loopback/supervisor implementations).
- **GUI**: Refresh button -> `📂 Load` (`load` key), click -> `MainWindow::loadIndex()`. It clears the view state,
  forces sort to `None` (`loadLockSort_`, released on the next scan), and sends `LOAD_INDEX`. A `loading_` guard
  limits it to one press, disables the button, and shows a NON-modal "Loading index list..." notice.
- **Popup separation**: `showReportWaitPopup(..., textKey, titleKey)` separates the title.
  - Load: title `loadWaitTitle` ("Loading index") / body `loadWait` ("Loading index list...").
  - Scan completion: title `repWaitTitle` ("Writing search report") / body `repWait` (original).
  - Scan stop: title `repWaitTitle` / body `stopWait` (original).
  - `onResults()` branches on `loading_` -> a load closes only its own notice and **never shows** the report popup.
- **Thumbnails**: removed the `worker_` requirement from `BackendSession::requestThumb`, so a load-only view
  serves the persistent disk thumbnails (`thumbs` table) or a WIC/FFmpeg decode (engineFetch stays optional).

## 4. Result

- Search and index lookup are separated; Load shows stored groups/previews without scanning.
- No report popup during a load; the two popups have separate titles, bodies and triggers.
- One press per load + a non-modal notice (the window stays movable).

## 6. Impact and limits

- Adds `LOAD_INDEX` to the GUI/backend IPC (`kProtocol` unchanged: both ends deploy together).
- Load returns empty when there is no index (the index directory is created as a side effect). The sort lock
  lasts until the next scan.
- The scroll jump (large-icon view, jumps to the top after scrolling far enough) and the CUDA-unavailable cause
  are handled in the **next build**.

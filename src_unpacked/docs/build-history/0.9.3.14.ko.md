# MediaSimilarityFinder v0.9.3.14 — 영상 MSSIM CUDA row-batch 가속

## 변경 필요성
- 영상 temporal 검증의 `thumb48` 기반 MSSIM(`frame_ssim`)이 CPU에서만 실행되어 후보군이 수만 개로 늘어나면 2차 검증 단계가 병목이 됐다.
- DTW 행 의존성과 Hamming gate 의미를 바꾸지 않고 이 단계만 가속하는 것이 필요했다.

## 기존 구조
- `video_similarity()`가 Hamming gate 통과 pair마다 `frame_ssim()`을 CPU에서 호출했다.
- `GpuBackend`는 32x32 pHash batch(`hashBatch`)만 제공했고 SSIM batch API가 없었다.
- `ScanPipeline` temporal 검증과 `compareFingerprint()` live 경로는 SSIM GPU backend를 공유하지 않았다.

## 변경 구조
- `GpuBackend::ssimBatch()`를 추가해 48x48 grayscale pair 배열과 결과 배열을 받는다.
- CUDA kernel이 pair별 36개 8x8 window MSSIM을 계산하고 CPU와 동일한 C1/C2·평균 규칙을 적용한다.
- `video_similarity()`는 DTW 행마다 gate 통과 pair만 packing해 batch 처리하고, 전체 행렬은 GPU에 만들지 않는다.
- 8 미만 소규모 행, batch 실패, CUDA 미지원은 `frame_ssim()`으로 fallback한다.
- normal/mirror 두 방향을 하나의 batch에 함께 넣어 호출·전송 비용을 줄인다.
- `ScanPipeline::setVideoGpuBackend()`로 temporal 검증 경로에 공유 backend를 연결하고, `MediaSearchEngine`의 scan/revalidate/live 경로가 같은 backend를 사용한다.
- `tests/video_gpu_benchmark_test.cpp`로 pHash 1024프레임·MSSIM 2048pair·DTW 32프레임의 CPU/GPU 시간과 정확도를 측정한다.

## 해결된 상황
- L3 SSIM 검증 단계가 CUDA row-batch로 가속된다.
- 판정식은 `0.4*Hamming + 0.6*SSIM` 그대로이며, SSIM은 Hamming reject를 승격시키지 않는다.
- 엔진 판정 버전(1.2.0)과 DB 스키마(1.0.3)는 그대로라 저장 쌍 재검증이 필요 없다.
- CUDA가 없는 환경과 runtime 실패는 기존 CPU 경로로 계속 동작한다.

## 검증
- RTX 3080 Ti 실측: pHash 1024프레임 CPU 7.32ms → GPU 1.80ms(약 4.1배), MSSIM 2048pair CPU 7.18ms → GPU 2.36ms(약 3.0배), DTW 32프레임 CPU 7.22ms → GPU 5.34ms.
- GPU/CPU SSIM 최대 오차 0(RTX 3080 Ti 실측, 허용 오차 1e-6; 다른 SM 세대에서는 재확인 필요), pHash 비트 일치, DTW 점수 오차 0.2 이내.
- CUDA Release 빌드 PASS, **CTest 61/61 PASS**.
- CPU-only Release 빌드 PASS, **CTest 60/60 PASS**(CUDA 전용 테스트 제외, CPU fallback 경로).
- `video_ssim_test` GPU 동등성 회귀 PASS, `video_gpu_benchmark_test` 신규 PASS.

## 향후 영향
- DTW 행 단위 호출과 전송 비용 때문에 작은 후보군에서는 가속폭이 제한된다.
- 다음 후보는 crop fingerprint batch, temporal pair batch, NVDEC 검토다.
- 대규모 실제 영상 corpus에서 후보 수별 wall time과 VRAM을 추가로 측정해야 한다.

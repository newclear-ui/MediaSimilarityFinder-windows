# MediaSimilarityFinder v0.9.4.150 — 날짜 정렬(생성 날짜) 추가

기준선 `0.9.4.149` → 본 빌드 `0.9.4.150`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` / `kProtocol 1` 불변 (판정 불변).

## 1. 변경 필요성

- 정렬 콤보가 없음/그룹 크기/유사도/이름 4종이라, 가장 최근에 추가된 파일이 있는 그룹을 위로 올리는 기준이 없었다.
- 요청: 날짜 기준 정렬을 추가해 최근 추가 파일이 위로 오게 한다. 기준 시각은 생성 날짜로 확정(사용자 선택).

## 2. 기존 구조

- `rebuildGroups()`가 `kSortNone/Size/Sim/Name`(0~3) 4개 모드를 분기했다. 그룹당 날짜 키가 없었고, 번역키 `sortDate`도 없었다.
- `fileSizeCached()`처럼 필요 시 통계를 읽어 캐시하는 패턴이 있었으나 날짜용은 없었다.

## 3. 변경 구조

- 정렬 모드 `kSortDate = 4` 추가. 콤보 마지막에 `sortDate`(날짜/Date) 항목을 붙였다. 기존 0~3 인덱스는 그대로라 스크롤/스캔잠금 테스트에 영향이 없다.
- 그룹 키 = 구성원 중 가장 큰 생성 날짜(`QFileInfo::birthTime()`; 무효면 `lastModified()`로 대체, 없는 파일은 0). 내림차순(기본)이면 최근 추가 파일이 위로 온다. 동점은 경로 오름차순(기존 모드와 동일한 tie-break).
- `fileDateCached()` 신설: `fileDate_` 해시에 캐시하고, 새 결과 세트가 화면을 교체할 때(`onResults`/불러오기/재검증) 함께 비운다. 백엔드/IPC 변경 없이 로컬 stat만으로 해결한다(0.9.4.117의 FILE_META 폭풍 교훈 준수).
- 방향 기본값: 날짜는 내림차순(0). 이름만 오름차순이던 기존 규칙(`idx == kSortName ? 1 : 0`) 그대로라 코드 변경이 필요 없었다.
- None 기준선(`noneOrder_`)은 None 모드에서만 갱신되므로 날짜 정렬이 기준선을 건드리지 않는다.

## 4. 해결된 상황

- 정렬 콤보에서 날짜를 고르면 최근에 추가된 파일이 속한 그룹이 위로 온다(내림차순 기본). 오름차순으로 바꾸면 가장 오래된 것부터 보인다.

## 6. 향후 영향 및 한계

- 생성 날짜는 파일시스템이 제공하지 않으면 수정 날짜로 대체된다(네트워크 드라이브 등). 복사된 파일은 복사 시점이 생성 날짜가 되므로 "추가된 순서"와 일치한다.

# MediaSimilarityFinder v0.9.4.94 — 완료 경로 중복 제거 + 스크롤 점프 수정

기준선 `0.9.4.93` → 본 빌드 `0.9.4.94`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 보고 2건:

1. **검색 완료 후 로그 생성이 완료되지 않는 것처럼 보인다.** 완료 처리는 되지만 "검색 리포트 작성 중" 단계가 길게 멈춰 보이거나, 손상된 상세 로그 기록이 다이얼로그도 없이 사라진다.
2. **GUI에서 키보드·마우스로 일정 수준 아래로 스크롤하면 보기가 최상단으로 점프한다.** 0.9.4.93에서 "다음 빌드"로 예고된 스크롤 점프와 동일 건이다.

## 2. 기존 구조

- **완료 경로 이중 재구축**: 정상 완료 시 `ScanWorker`가 `results → telemetryReady → finished` 순으로 방출하고, GUI는 `onResults()`와 `scanFinished()`에서 **같은 전체 재구축**(`rebuildGroups + refreshGroupList + refreshFileViews + refreshDetail`)을 두 번 실행했다. 그룹 수천 개에서 GUI 스레드가 두 번 묶이므로 리포트 팝업이 두 번 길게 뜨고, 중간에 상세 로그 모달까지 끼어 "리포트가 끝나지 않는다"로 보인다.
- **상세 로그 파싱 침묵 실패**: `showDetailedLogDialog()`는 JSON 파싱 실패 시 `return` 한 줄로 끝났다. 다이얼로그도 없고 메시지도 없으므로 손상된 기록은 "로그가 생성되지 않음"과 구별되지 않는다.
- **Batched 레이아웃 클램프**: 중간 `imgGrid_/vidGrid_`는 `QListView::Batched`였다. `doItemsLayout()` 호출은 배치 0부터 다시 시작하므로 스크롤바 최대값이 첫 배치 수준으로 **붕괴**했다가 이후 배치에서 다시 커진다. 깊은 위치에서 복원된 값은 작은 최대값에 클램프된 채 남으므로, 이후 최대값이 회복돼도 보기는 상단 근처에 머문다. 얕은 스크롤은 당시 최대값 안에 들어 복원에 성공하므로 "일정 수준을 넘어갈 때만" 점프한다. 실측(회귀 테스트, 120 그룹): `scrollToBottom → doItemsLayout` 반복 30회에도 값 14461 대 최대값 17491로 수렴하지 않았다.
- **우측 무앵커 재생성**: `refreshFileViews()`는 `grid_->clear(); list_->clear();` 후 스크롤 저장/복원이 전혀 없어, 스트리밍 refill·완료·줌 때마다 파일 목록이 0으로 갔다.

## 3. 변경 구조

- **완료 중복 제거** (`gui/mainwindow.cpp`, `gui/mainwindow.h`): `onResults()` 스캔 분기가 재구축을 마치면 `resultsApplied_ = true`를 세운다(불러오기 분기는 세우지 않는다). `scanFinished()`는 `resultsApplied_ && !CANCELLED`이면 4종 재구축을 건너뛰고 요약/상태 갱신만 수행한다. 취소 경로는 `onResults`를 거치지 않으므로 항상 재구축한다. 플래그는 스캔 시작(`setRunning(true)`)과 불러오기 시작 시 해제된다.
- **상세 로그 실패 보고**: 파싱 실패 시 상태바에 `detailLogParseFail`("상세 로그 열기 실패 (기록 손상)" / "Could not open the detailed log (record damaged)")을 표시하고 `msf_scan.log`에 오프셋·사유를 남긴다. 번역키와 `ui_translation_keys_test` 키 목록에 추가했다.
- **SinglePass 전환**: 중간 두 그리드를 `Batched`에서 `SinglePass`로 변경했다. 균일 셀 레이아웃은 저렴하므로 동기 전체 패스가 합리적이며, 이후 모든 명시적 `doItemsLayout()`(append·재구축·썸네일 flush·델리게이트 전환)이 최종 지오메트리를 본다. 자발적 재배치(resize 등)도 값을 여러 번 건드리지 않는다. `fillPair`의 앵커 복원 로직 자체는 그대로 두었다(이제 정확한 최대값을 본다).
- **우측 스크롤 보존** (`refreshFileViews()`): 재생성 전 양쪽 스크롤바 값을 저장하고, `doItemsLayout()` 후 서명(`currentGroup_|파일 수|첫 경로|끝 경로`)이 같으면 복원한다. 그룹이 바뀌면 서명이 달라져 기존처럼 최상단부터 보인다.

## 4. 해결된 상황

- 정상 완료 시 "리포트 작성" 재구축이 1회로 줄고, 팝업 1개 + 요약 갱신만 남는다. 취소·실패·불러오기 경로의 동작은 그대로다.
- 손상된 상세 로그는 상태 메시지와 스캔 로그로 보고된다. 자동 저장 기대와 달리 저장은 기존처럼 다이얼로그의 저장 버튼(수동)이다.
- 깊은 스크롤에서 전체 재구축·스트리밍 refill·줌을 해도 위치가 유지된다. 그룹 전환 시 우측이 최상단부터 보이는 동작은 유지된다.

## 6. 향후 영향 및 한계

- 스캔 완료 신호 순서(`results → telemetryReady → finished`)와 IPC는 그대로다. `kProtocol` 불변.
- `resultsApplied_`는 스캔 1회에만 유효한 일회성 표시다. 백엔드 재시작·자동 재개는 새 스캔이므로 플래그가 리셋된다.
- SinglePass 전환으로 대용량 refill의 동기 레이아웃 비용이 배치 분산분만큼 한 틱에 몰린다. 아이템 생성이 지배적이므로(11k 그룹 약 1s 기록 유지) 허용 범위이며, 스크롤 게이트·어펜드 경로는 그대로다.
- 완료 후행 지문(fingerprint tail, 캐시 미스 시 장시간)은 설계대로 유지된다. 진행률 표시(`fingerprintProgress` → 상태바 파일/GB)가 이미 있어 멈춤으로 오인되지 않는다.
- CUDA 미가용 원인은 계속 다음 빌드에서 다룬다.

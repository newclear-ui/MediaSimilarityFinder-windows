## 1. Why the change

- User directive (long-form ad-insertion reading experiment): start 0–300 s at 3 s grid with tolerant search (3-of-4, ≤1 skip) + ending-first ladders (backward 1/3/10 min 9 s checks) + fixed center/ending reps 2-of-3 + offset refinement (±10 support argmax) + duration-band candidate gating (shorts 90 s / long-form 1.2). Measurement showed the fixed constants (3.5 s probe span, 2.5 s cadence, 5 s pool) are 1 s-sampling-only and collapse on coarser grids (start search 0/20 at I≥2); interval-proportional generalization fixed it.
- Evidence: `docs/field-reports/longform-ad-capture-efficiency.ko.md` / `.en.md` §5.3–§5.4, §11–§12 (25 videos, full 3 s capture + dense 1 s zones, synthetic moving 30/90/180 s ads + black leaders, 20 same pairs + 240 cross pairs).
- V3 is a separate orchestration from V1/V2. V1/V2 function bodies untouched.

## 2. Previous structure

- V2 (`temporalAnchorSimilarityV2`): bidirectional ends, length policy, segment splits, unified verdict. Experimental opt-in, report-only.
- ScanPipeline flush-worker anchor comparison hook (strategy opt-in + `MSF_VIDEO_ANCHOR=1` + in-memory indexes). V3 verdicts are not reflected in product verdicts.
- GUI video-tab strategy combo index 0/1/2 (LegacyV3/V1/V2), QSettings `video/readStrategy`, IPC JSON, backend parsing.

## 3. New structure

- New module functions (`src/temporal_anchor.{h,cpp}`, msf_core, V1/V2 frozen):
  `anchorBandPass()` (shorts abs≤90 s / long-form ratio≤1.2),
  `orderedSearchTol()` (first need+skip probe frames, need hits, ≤skip skips, cadence bound),
  `refineOffsetBySupport()` (±10 support argmax, ties keep closest),
  `temporalAnchorSimilarityV3()` (band gate → tolerant start → ending-first search (last 1200 s) → refinement → backward/center ladders + fixed reps 2-of-3 → DUP/UNCERTAIN/miss).
- Verdict: DUP only with band pass + ending found + backward ladder≥2 + center ladder≥2 + fixed reps≥2 + consistent offset + score≥87.5 (score reuses V2's `anchorVerdictScore` mapping).
  Ending-only is UNCERTAIN; no evidence is a miss. Thin/dark inputs cap at UNCERTAIN (same as V2).
- Product wiring: `VideoReadStrategy::TemporalAnchorV3 = 3`, GUI combo index 3 + 1 tr key,
  QSettings/IPC/backend mapping extended, `anchorStrategyId()=3`, strat==3 branch in the ScanPipeline hook (additive telemetry only).
  The armed condition (`!= LegacyV3`) is unchanged, so V3 shares the union sweep and memory indexes; disarmed builds stay byte-identical.
- Tests: `tests/video_temporal_anchor_v3_test.cpp` (7 synthetic pins: band boundaries, 3-of-4 pass / 2-miss reject, refinement convergence, ending-first DUP, dark UNCERTAIN, stranger non-DUP).

## 6. Future impact and limits

- Verdicts unchanged: LegacyV3 default, V3 path is report-only telemetry. Engine/DB/schema/cache unchanged — no stored-pair re-verification.
- **No gate PASS, no default promotion**: L01-class weak-evidence rule (4×81.2), dark main content, real broadcast ads, 60–90 min / 120+ min bands, and threshold calibration remain unvalidated/follow-up. The user-specified round also confirmed shorts holds only on synthetic patterns.
- Known limits: fixed-rep boundary fragility (scene cuts, flat tails), probe-position sensitivity (grid-dependent probe placement), start search as a single point of failure (multi-probe unmeasured).
- Rollback: select LegacyV3 in the GUI (the default) + unset `MSF_VIDEO_ANCHOR`.

## 7. CI reproducibility and test-environment handling (GitHub Actions, 2026-11-20 → 11-22)

Product verdicts, engine/DB/schema/cache versions are **unchanged**. This section records build/test
infrastructure only.

### 7.1 Why

- Getting the CPU/CUDA GitHub Actions workflows green showed the first failures were **not product defects**
  but runner-image drift plus a reduced vcpkg ffmpeg feature set.
- The stopgap was `-CTestExclude` for four environment-dependent tests, which leaves a green suite that
  **verifies nothing** for those four. They were fixed to decide for themselves instead.

### 7.2 Previous structure (measured failure causes)

| Test | Observed message | Cause |
|---|---|---|
| `image_dim_test` | `Default encoder for format image2 (codec png) is probably disabled` | vcpkg ffmpeg has no PNG encoder |
| `video_reencode_test` | `Unrecognized option 'crf'` | vcpkg ffmpeg has no libx264 |
| `video_scan_e2e_test` | `Unrecognized option 'crf'` | same |
| `reveal_window_test` | `fallback_open=FAIL`, `reuse_window=FAIL windows=1->1` | **two-stage cause**: (1) 8.3 short path vs long path string compare, (2) even after normalisation the runner session does not report the shell **selection** |

`reveal_window_test` was first blamed on "the runner has no interactive Explorer shell" — that was **wrong**.
`windows=1->1` (case A opened one window, case B reused it) proved the shell worked. After path normalisation
the diagnostic dump pinned it down: the target folder matched **exactly**, but the shell view reported no selection.

Contributing factors:

- Runner image `20261103` (MSVC 14.51) → `20261116` (MSVC 14.52) broke dav1d 1.5.4
  (`include/compat/msvc/stdatomic.h` `__has_include_next`).
- No vcpkg `builtin-baseline`, so dependency versions tracked whatever the runner resolved.

### 7.3 Change

- The four tests now decide for themselves:
  - `image_dim_test`: the PNG fixture is assembled in-process (signature + IHDR + IEND, CRC-32) because the
    probe only parses the IHDR; the JPEG fixture names `-c:v mjpeg` explicitly; no ffmpeg on PATH → exit 77.
  - `video_reencode_test`, `video_scan_e2e_test`: re-encodes use `-c:v mpeg2video -q:v 10` (+ scale) while the
    sources stay MPEG-4 — still a different codec, and built into this ffmpeg.
  - `reveal_window_test` is split into three layers:
    1. Explorer location URL vs target folder compared as **canonical long paths**
       (`QFileInfo::canonicalFilePath`) — resolves 8.3 short names.
    2. On failure it dumps the open shell-window URLs, the wanted path and the selection count.
    3. If the selection check fails, it first runs a **control reveal that bypasses product code**
       (`explorer.exe /select,<control>`). If the control cannot report a selection either, the test prints
       `reveal_window=skipped (no interactive desktop selection)` and exits 77; if the control succeeds while the
       product does not, that is a **product regression** and the test fails.
    The `GetProcessWindowStation` visibility + `GetShellWindow()` guard stays for sessions with no shell at all.
  - CMake: `SKIP_RETURN_CODE 77` for all four → CTest reports `Skipped`, never a silent pass.
- Workflows: `-CTestExclude` removed; both run the full suite.
- Reproducibility: `builtin-baseline` pinned (`afa249f12f`), Release-only overlay triplet, dav1d overlay
  patch for MSVC 19.52, binary caches (`vcpkg-v3` 345 MB + CUDA 29 MB), `-BuildParallelism 4`,
  `timeout-minutes: 240`.

### 7.4 Resolved

- CI runs the whole suite. The four tests either execute or print a reason and report `Skipped`.
- The three un-excluded tests genuinely pass on both CPU and CUDA (see §7.5).
- `reveal_window_test` is `Skipped` on the runner: the window opens and the folder matches, but even the
  product-independent control (`explorer.exe /select,<control>`) reports no selection → session limitation.
- Cache hit runs: CPU **17.8–22 min** / CUDA **18.4 min** versus 112 min / 82.8 min cold.

# MediaSimilarityFinder v0.9.2.88 — Reveal Root Fix (CLSCTX_ALL)

## Need for change
- "Reveal in Explorer" never opened the path in any situation: only a status message, never a new window.
- A temporary probe driving `revealPath` against real Explorer windows exposed two causes.

## Previous structure
- `revealInOpenExplorer()` created `IShellWindows` with `CLSCTX_INPROC_SERVER`.

## New structure
- `CLSCTX_INPROC_SERVER` → `CLSCTX_ALL`. ShellWindows is registered out-of-proc (local server), so INPROC always failed with `REGDB_E_CLASSNOTREG` and `revealInOpenExplorer()` unconditionally returned `Failed`. Neither window reuse nor the `NoWindow` fallback (open a new window) could ever run.
- The temporary probe is promoted to the regression test `reveal_window_test`: fallback on a fresh folder (window opens, file selected) and reuse with the window already open (window count unchanged, same HWND, selection kept), verified against real Explorer windows. Windows-only.
- Version strings unified → 0.9.2.88.

## Resolved situation
- `reveal_window_test` PASS: fallback opens a new window with the file selected; re-invocation reuses the same window.
- The reported "button does nothing" was also partly version skew: pre-.87 builds showed the failure dialog even with plugins present (self-check path bug).

## Validation
- Core+GUI Release build: PASS, **CTest 58/58 PASS** (new `reveal_window_test` included)
- Portable `--smoke` exit 0, `MediaSimilarityFinder-v0.9.2.88-Portable-Windows-x64.zip` produced

## Future impact
- `CLSCTX_ALL` is the standard for Explorer enumeration; later COM calls follow it.

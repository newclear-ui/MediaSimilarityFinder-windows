## 1. 변경 필요성

- 지시 `지시/GUI 동영상 설정 탭 및 비교 프로파일 구현.md`가 설정 창의 동영상 탭과 숏폼/중간/롱폼 비교 프로파일 구현을 요구했다. 기준 설계 문서(`architecture/video-similarity-search`, `implementation-briefs/V-video-content-matching`)는 V0~V4 정확도 Gate 이후의 V5를 전제하지만, 지시 §5는 실제 연결되는 부분과 선행 Gate가 필요한 부분을 구분해 구현하도록 명시했다.

## 2. 기존 구조

- 샘플 계획은 고정 구간(`make_sample_plan`: 1/2/4/8/16/32초)이었고 kept 선택은 저분산 필터만 있었으며, 설정 전달 경로에 동영상 항목이 없었다.
- `VideoBuildStats.decodedFrames`는 0.9.4.155에서 실제 디코드 수로 교정되어 있어 Probe/Kept/Decoded 분리 계측의 분모가 확보된 상태였다.

## 3. 변경 구조

- **설정 UI**: 설정 대화상자에 동영상 탭 추가 (모드 콤보+숏폼/중간/롱폼 그룹+불확실 보강+부분 클립). QSettings `video/*` 15개 키, INI round-trip, 범위 외 값 clamp.
- **전파**: `BackendScanConfig.videoPolicy` → IPC `video` 객체 → `BackendSession::startScan` → `ScanWorker::setVideoPolicy` → 엔진 저장 (run snapshot). 미지정 시 Auto 권장값.
- **샘플링**: 숏폼(≤60초)에만 사용자 간격 적용(기본 5초). 중형·장편은 균일 sweep 유지 — 국소 정밀 창이 없으므로 long-form 간격은 저장·전달만 하고 적용하지 않는다(명시적 pending).
- **kept soft target**: G1~G8 (5/8/9/12/11/10/12/14). 분산 순위 상위 유지+시간순 복원, floor(30% 미만이면 전체 유지) 우선. 8s fixture 실측 kept=2/decoded=80/sampled=3.
- **캐시 분리**: `video_fingerprint_cache`에 `policy` 컬럼 추가 + 조회·저장에 포함(마이그레이션, 버전 불변). `sampling_generation`에 정책 ID 접미사(`3:v1`) → 정책 변경 시 1회 전체 재분석. 메모리 캐시도 정책 키로 구분.
- **pending 명시**: 불확실 보강(기본 ON)·부분 클립(기본 OFF)은 엔진 no-op + 로그 1줄. 가짜 동작 없음.

## 4. 해결된 상황

- 단편(≤60s)은 새 권장 정책으로 동작한다. 장편은 균일 sweep + kept 예산만 적용된다.
- 서로 다른 정책의 지문이 혼합되지 않는다 (캐시 키 + generation 접미사 + 메모리 키).

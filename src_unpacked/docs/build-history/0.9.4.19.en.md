# MediaSimilarityFinder v0.9.4.19 — D3-Minimal Walker Queue Safety

D3-Minimal validation baseline: bounded backpressure on the unbounded
walker queue. Safety hardening, not optimization. Engine 1.5.0, DB
1.0.3, cache v9 unchanged; schema 5 → 6.

## Why the change was needed
- The queue between the fast producer (directory walk) and the slow
  consumer (DB + analysis) was unbounded: large trees could grow memory
  without limit.
- Measured imbalance is unconfirmed, so topology optimization is out of
  scope; a safety device is in scope.

## Pre-register (recorded before code changes)
- Expected: little throughput change on normal trees, bounded memory,
  cancel escape while full, identical results.
- Rollback criterion: parity break, deadlock, termination delay, cancel/
  pause regression, build regression, existing CTest regression, or clear
  throughput regression on normal workloads → rework/revert the queue
  hunk. Telemetry stays.

## Previous structure
- `std::queue` + mutex/cv, unbounded, unconditional producer push.

## New structure
- New `src/walker_queue.h/.cpp` — capacity + cancel-aware backpressure
  only (~90 lines). No worker pools, policy, or routing.
  Capacity 4096 (safety bound, never claimed optimal).
- Full producer blocks on a 100 ms bound. Cancel/shutdown escape at
  once; a dropped file was never analyzed, so the next scan sees it as
  new — identical to an unwalked file on cancel.
- Pause is not a queue concept: the scanner stalls upstream without
  locks before onFile, so a paused producer never reaches push. A pause
  landing mid-block resolves on resume (nobody sleeps holding the mutex).
- Consumer notifies after pop; one `shutdown()` before join covers every
  exit path. A producer blocked at that point wakes within ≤100 ms plus
  shutdown.
- `ScanControl::walkerQueueCapacity` (0 = default) plus worker setter —
  documented test hook, unused in production.
- Telemetry: `walker.capacity` (config, sampleMs precedent) +
  `walker.blockedTicks` (waits entered while full). Schema v6.

## Why this shape
- Deterministic block/resume/cancel tests need the mechanism separated;
  inline would leave timing to luck.
- Engine loop walkDone/cancel/starved semantics stay exactly as they were.

## Resolved state
- Unbounded-memory path closed. Next: Full D3 call on measured evidence.

## Accuracy impact
- None. Completion, maxDepth bound, and parity proven by tests on both
  trees. Completion and agreement hold under pause toggles.

## Compatibility impact
- Benchmark JSON additive extension (schema 6). Existing keys kept.
- Test counts +1 (walker_queue_test; CPU 67/GPU 68).

- CPU Release build PASS, **CTest 67/67 PASS** (new unit groups:

  parity; pause-toggled 12-file completion with 66-pair agreement).
- GPU Release build PASS, **CTest 68/68 PASS**.
- `--version` 0.9.4.19 and `--smoke` PASS on both.

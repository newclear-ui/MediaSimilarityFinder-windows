# MediaSimilarityFinder v0.9.4.101 — Open-path detail sync

Baseline `0.9.4.100` -> this build `0.9.4.101`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

User report (0.9.4.100, two screenshots + `msf_scan.log`): after Load, selecting group then file shows the preview but every detail text row stays `-`. The rows themselves are healthy (`rows=9`); only values are missing.

## 2. Previous structure

- Every `currentFile_` writer refreshed the detail pane right after selection. **Sole exceptions**: the two double-click open paths (right grid `fileActivated`, right list lambda) set `currentFile_` with no refresh.
- That allowed stale `-` rows with a later thumbnail arrival painting only the preview (blank text + live preview). The `detailAnomaly` tripwire (`vis=0` measured) pointed the same way.

## 3. New structure

- **Single funnel**: new `showFileDetails(path)` — set + refresh in one place. Both `fileActivated` and the list double-click lambda go through it.
- Audited every other `currentFile_` writer (select/clear/load/scan-start/prune all refresh alongside).
- Test: phase 15 (invoke the open path with no view selection change → filename shown).

## 4. Result

- Every `currentFile_` transition, including double-click opens, moves with the detail rows. The stale-`-`-rows-plus-live-preview combination is closed.

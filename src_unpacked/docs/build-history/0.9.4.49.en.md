## 1. Why the change was needed

Detailed Logs carried plenty of benchmark/diagnostic internals but no summary a
normal user could understand. In particular **the duplicate-file total existed
nowhere.**

The required at-a-glance summary:

```
Search Duration       : 12m 34.5s
Images  scanned       : 12,438  analyzed : 12,401  throughput : 16.4 files/sec
        duplicate groups : 183   duplicate files  : 527   duplicate pairs : 412
Videos  ... (same shape)
Total   scanned / analyzed / duplicate groups / duplicate files
```

`duplicate files` and `duplicate groups` are different things (members vs
clusters) and must stay separate. Time is split as Total / Image processing /
Video processing / Matching rather than a single `wallMs`.

## 2. Previous structure

- `SearchReport.groups` counted matched **pairs** (`ScanPipeline` increments per
  pair at or above threshold). Not clusters.
- telemetry `matches.groups` counted distinct union-find roots (**clusters**),
  which is what the GUI rebuilds and the user sees.
- No per-kind split existed anywhere. The internal candidate indexes are split
  by kind, but telemetry only carried the sums.
- `images.count` / `videos.count` are analyzed counts; per-kind scanned did not
  exist.

## 3. New structure

### Fixed meanings

- duplicate pairs = verified matches at or above threshold, per kind
- duplicate groups = distinct linkage clusters, per kind
- duplicate files = files participating in any pair (members), per kind
- A cluster never spans kinds (image and video indexes are separate), so the
  per-kind groups partition the total exactly.

### Engine (10 `SearchReport` fields)

`imgScanned/imgAnalyzed/vidScanned/vidAnalyzed` (counted in processOne and at
outcome), `imgPairs/vidPairs` (in the onMatch callback, counted only when both
sides agree on kind), `imgGroups/vidGroups/imgDupFiles/vidDupFiles` (roots and
members aggregated per kind in the cluster block). Early-return points also
carry the per-kind scanned/analyzed values.

### Telemetry (`matches` + `images`/`videos`)

Added `images.scanned` / `videos.scanned`, and in `matches`
`imagePairs/imageGroups/imageDuplicateFiles` plus
`videoPairs/videoGroups/videoDuplicateFiles`.
`breakdownState` / `scannedState` follow the measured/not_measured rule.

### GUI (`showDetailedLogDialog`)

The summary block renders first in the dialog. Duration is formatted as
`12m 34.5s`. Throughput is analyzed count divided by measured stage ms (both
inputs are measured, so the derivation is legitimate). All existing detail rows
are kept.

Nine translation keys added (`detailLogSummary`, `detailLogDuration`,
`detailLogDupGroups`, `detailLogDupFiles`, `detailLogDupPairs`,
`detailLogThroughput`, `detailLogTotal`, `detailLogTimeSplit`,
`detailLogMatching`) and registered in the tr-keys gate.

## 4. Resolved situation

# MediaSimilarityFinder v0.9.4.19 — D3-Minimal Walker Queue Safety

D3-Minimal 검증 기준점. unbounded walker queue에 bounded
backpressure를 적용한다. 최적화가 아니라 안전 강화다.
엔진 1.5.0·DB 1.0.3·캐시 v9 불변, schema 5→6.

## 변경 필요성
- producer(디렉토리 열거, 빠름)와 consumer(DB+분석, 느림) 사이의
  queue가 무계한이었다. 대용량 트리에서 메모리 무한 증가 가능.
- 실측 imbalance는 미확인. 따라서 topology 최적화가 아니라 안전
  장치가 범위다.

## Pre-register (코드 변경 전 기록)
- 예상 효과: 정상 트리 처리량 큰 변화 없음, 메모리 상한 보장,
  full 상태 취소 탈출 가능, 결과 동일.
- 롤백 기준: parity break·deadlock·종료 지연·중단 회귀·빌드 회귀·
  기존 CTest 회귀·정상 workload throughput 회귀 중 하나면 queue 변경
  hunk 재검토/revert. telemetry는 유지.

## 기존 구조
- `std::queue` + mutex/cv 무계한, producer 무조건 push.

## 변경 구조
- 신규 `src/walker_queue.h/.cpp` — capacity + cancel-aware
  backpressure 전용 (~90줄). worker pool·정책·라우팅 없음.
  capacity 4096 (안전 bound, 최적값 주장 금지).
- producer full 시 100ms bound 대기로 block. cancel/shutdown 시
  즉시 탈출 (drop된 파일은 미분석이라 다음 스캔에서 새 파일로
  처리 — cancel 시 unwalked와 동일).
- pause는 queue 개념 아님: scanner가 upstream에서 락 없이 stall하므로
  producer는 push에 도달하지 않는다. block 중 pause가 걸려도
  재개 후 consumer가 비우면 진행 (mutex를 잡고 자는 곳 없음).
- consumer pop 후 notify, 종료 전 `shutdown()` 1곳 (모든 exit 경로
  통과). failed/cancel 종료 시 block producer는 ≤100ms+shutdown에
  깨어난다.
- `ScanControl::walkerQueueCapacity` (0 = 기본값) + worker setter —
  문서화된 테스트 후크, production 미사용.
- telemetry: `walker.capacity` (설정값, sampleMs 선례) +
  `walker.blockedTicks` (full 대기 진입 수). schema v6.

## 선택 이유
- block/resume/cancel을 결정론적으로 테스트하려면 메커니즘 분리가
  필요했다. 인라인이면 타이밍 운에 맡긴다.
- engine 스캔 루프의 walkDone/cancel/starved 의미는 그대로 둔다.

## 해결된 문제
- 메모리 무계한 증가 경로 차단. 다음은 실측 기반 Full D3 판단.

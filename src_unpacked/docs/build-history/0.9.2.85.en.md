# MediaSimilarityFinder v0.9.2.85 — Self-Check Path Bug Fix (GetModuleFileNameW)

## Need for change
- The 0.9.2.83 self-check showed the failure dialog even with plugins intact. `--smoke` exited 0 while a no-argument launch exited 1.
- A temporary file log proved `QCoreApplication::applicationDirPath()` returns an empty string when called before `QApplication` exists. The probe path became `/platforms/qwindows.dll`, always missing.

## Previous structure
- `platformPluginPresent()` relied on `QCoreApplication::applicationDirPath()`.

## New structure
- The executable path comes straight from Win32 `GetModuleFileNameW(nullptr, ...)`, with the directory resolved via `QFileInfo::absolutePath()`. Always exact, independent of Qt instance state.
- No matching-logic or CUDA algorithm changes. Version strings unified → 0.9.2.85.

## Resolved situation
- A no-argument launch (double-click conditions) stays alive past 10 seconds, confirming normal startup.
- A plugin-less directory still takes the exit-1 guard path as before.

## Validation
- Core+GUI Release build: PASS, **CTest 56/56 PASS**
- Positive: no-argument run survives 10s (normal startup), package `--smoke` exit 0
- `MediaSimilarityFinder-v0.9.2.85-Portable-Windows-x64.zip` produced

## Future impact
- Startup path resolution no longer depends on Qt initialization, so results do not vary by launch method (cmd, double-click, shortcut).

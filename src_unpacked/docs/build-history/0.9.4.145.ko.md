# MediaSimilarityFinder v0.9.4.145 — 검색 요약 "합계" 줄에 실패 파일 수 표시

기준선 `0.9.4.144` → 본 빌드 `0.9.4.145`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (텔레메트리 additive key).

## 1. 변경 필요성

- 0.9.4.144에서 상세 로그에 실패 파일 목록/사유를 추가했지만, 사용자가 보는 **검색 요약의 "합계" 줄**에는 scanned/analyzed/그룹/중복만 있어 실패 건수를 한눈에 알 수 없었다.
- 요청: `합계 scanned: 39 analyzed: 38 중복 그룹: 0 중복 파일: 0 실패 파일: 1`처럼 합계 줄에 실패 수를 표시.

## 2. 기존 구조

- 텔레메트리 `summary`에는 `scanned/analyzed/unchanged`만 있었고 실패 수는 저장되지 않았다(파일별 목록만 0.9.4.144에서 추가).
- 다이얼로그 합계 줄은 총계/그룹/중복 파일만 표시했다.

## 3. 변경 구조

- `TelemetryRecorder`에 **총 실패 수**(`failedCount_`) 추가. 파일별 목록 상한(종류별 50건)과 무관하게 모든 실패를 센다.
- JSON `summary.failedFiles` (additive, 스키마 9 유지).
- 상세 로그 합계 줄에 `실패 파일: N` 추가(번역 키 `detailLogFailedShort`).
- 파일별 "실패한 파일 (img/vid)" 섹션(0.9.4.144)은 그대로 유지.

## 4. 해결된 상황

- 검색 요약 한 줄에서 실패 건수를 바로 확인할 수 있고, 아래 "실패한 파일" 섹션에서 파일명·사유를 확인할 수 있다.
- JSON 소비자는 `summary.failedFiles`(총계)와 `images/videos.failedFiles`(상세, 최대 50)를 함께 사용할 수 있다.

## 5. 검증


- `analysis_failure_state_test`: `summary.failedFiles == 1`과 파일 경로/사유를 확인.

- 실기: `broken.jpg` 스캔 시 합계 줄에 `실패 파일: 1`, 상세 섹션에 `empty file — D:\...\broken.jpg`.

## 6. 향후 영향 및 한계

- 실패 수는 파일별 실패 분기에서 증가한다(목록 상한과 별개).
- 사유는 0.9.4.144와 동일한 휴리스틱이며, 스키마/프로토콜/엔진 버전은 불변이다.

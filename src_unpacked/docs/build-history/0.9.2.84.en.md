# MediaSimilarityFinder v0.9.2.84 — Build Output Runs Out of the Box (In-Build Qt Plugin Deploy)

## Need for change
- The user ran `build-windows-cuda\Release\MediaSimilarityFinder.exe` directly, and the 0.9.2.83 self-check dialog appeared correctly — proving raw build outputs never had Qt plugins.
- Both the portable zip and the build output should launch directly.

## Previous structure
- Qt plugins lived only under `vcpkg_installed/.../Qt6/plugins` and were never copied to the build output directory.
- `ffmpeg.exe`/`ffprobe.exe` (last-resort video resolution probe) were also absent from build outputs.

## New structure
- `CMakeLists.txt` gains POST_BUILD deployment on the `MediaSimilarityFinder` target: existing plugin categories (`platforms`, `styles`, `imageformats`, `generic`) are copied to the output directory root, and `ffmpeg`/`ffprobe` via `copy_if_different`. Missing categories (`iconengines`, etc.) are skipped so configure never breaks.
- The `QT_PLUGIN_PATH` computation for GUI tests moved up to the target definition for reuse.
- No matching-logic or CUDA algorithm changes. Version strings unified → 0.9.2.84.

## Resolved situation
- `build-windows-cuda\Release\MediaSimilarityFinder.exe` runs in a clean environment (minimal PATH, no plugin path): `--smoke` exit 0.
- The portable package was regenerated at the same version.

## Validation
- Core+GUI Release build: PASS, **CTest 56/56 PASS**
- Build-output launch validation: `--smoke` exit 0 (clean environment)
- `MediaSimilarityFinder-v0.9.2.84-Portable-Windows-x64.zip` produced

## Future impact
- Every build auto-deploys plugins, so direct build-output runs keep working, including fresh build directories.

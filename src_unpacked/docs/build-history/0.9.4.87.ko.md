# MediaSimilarityFinder v0.9.4.87 — 백엔드 셸 썸네일 경로 제거 (IThumbnailCache 크래시 수정)

기준선 `0.9.4.86` → 본 빌드 `0.9.4.87`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 판정·스키마·디코드 의미 변경 없음.

## 1. 변경 필요성

사용자 리포트: 대규모 스캔(`G:\Downloads\ss_twit`) 중 **백엔드가 반복 크래시**
(`backend process exited unexpectedly — scan aborted`, exit code 62097/-1073741819),
재시작해도 2~3초 만에 같은 서명으로 재크래시.

덤프·이벤트 로그로 원인 특정:
- 덤프(`%LOCALAPPDATA%\CrashDumps\MediaSimilarityFinderBackend.exe.*.dmp`)를 0.9.4.86
  PDB로 분석 → 예외 **`0xC0000005`**, fault IP가 **언로드된 셸 DLL**
  (`Windows.FileExplorer.Common.dll+0x2395e`), 크래시 스레드 스택이 그 언로드 DLL
  주소로 채워지고 `combase`/레지스트리 프레임 동반 → **셸 COM 코드 실행 중 모듈이
  언로드**되어 다음 복귀에서 폴트(`FAILURE_BUCKET ... INVALID_POINTER_EXECUTE`).
- 이벤트 뷰어 Event 1000: faulting module이 매번 **언로드 셸/URL DLL**
  (`Windows.FileExplorer.Common.dll_unloaded`, `urlmon.dll_unloaded`, `ntdll`), 모두 `0xc0000005`.
- 코드상 백엔드의 유일한 셸 사용처 = `ThumbnailStore::shellArt`
  (`src/thumbnail_store.cpp`): `SHCreateItemFromParsingName` +
  `CoCreateInstance(CLSID_ThumbnailCache)` = **Windows 셸 썸네일 캐시(`IThumbnailCache`)**.
  이 API가 정확히 위 셸 DLL들을 로드한다.
- 호출 시점: 디스크 캐시 미스 + 엔진 in-memory art 없음 → **스캔 중 사용자가 그룹/
  썸네일을 볼 때** 다수 호출.

## 2. 기존 구조

`ThumbnailStore::fetch` 순서:
disk 캐시 → engine art → **shellArt(셸 IThumbnailCache)** → WIC(이미지) / FFmpeg(비디오).

## 3. 변경 구조

- **`shellArt` 제거**. `fetch` 순서: disk → engine art → **WIC(`decodeColorAspect`)**
  (이미지) / **FFmpeg(`frameAtColor`)** (비디오).
- `shobjidl.h`·`thumbcache.h`·`windows.h` 의존 제거, `CLSID_ThumbnailCache` 사용 삭제.
- 백엔드 썸네일 경로에서 **COM/셸 의존이 완전히 사라짐**(이미지 WIC은 `decodeColorAspect`
  내부에서 COM 수명을 자체 관리).

## 4. 해결된 상황

- 셸 썸네일 COM 경로가 사라져, 크래시 클래스(언로드 셸 DLL 실행)가 제거된다.
- 이미지/비디오 썸네일은 기존과 동일하게 WIC/FFmpeg에서 생성된다.

## 6. 진단 기록 (실험, AGENTS 9항)

- **Experiment**: P-0.9.4.86-shell-thumbnail-crash
- **증상**: 대규모 스캔 중 백엔드 반복 크래시(`0xC0000005`).
- **방법**: WER LocalDumps(백엔드 exe, full) + WinDbg(`!analyze -v`, `dps`) + Event 1000.
- **증거**: fault IP가 언로드 셸 DLL, 스택이 그 DLL 주소로 채워짐, code path =
  `ThumbnailStore::shellArt`(IThumbnailCache).
- **판정**: 원인 특정(셸 썸네일 COM 모듈 수명 UAF). 수정: 셸 경로 제거.
- **재검토**: 셸 전용 코덱(예: 일부 heic/webp 셸 확장) 썸네일이 필요해지면, 셸 COM 대신
  프로세스-외부(별도 helper) 또는 WIC/FFmpeg 확장으로 재검토한다.

## 7. 향후 영향 및 한계

- 셸 전용 코덱으로만 썸네일을 만들 수 있는 형식은 썸네일이 placeholder가 될 수 있다
  (썸네일은 표시 전용이라 판정·인덱스·검색 결과에는 영향 없음). 해당 파일은 이미
  WIC decode 실패 시 `analysis_failed`로 settle된다.
- GUI의 `SHCreateItemFromParsingName`(탐색기에서 보기)은 사용자 동작 경로로 그대로 둔다
  (백엔드 크래시와 무관).

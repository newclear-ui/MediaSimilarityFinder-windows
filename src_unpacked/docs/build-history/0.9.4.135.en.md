## 1. Why the change was needed

- User proposal: Test Mode re-analyzes everything from scratch, so it can detect differences against the main index. When differences are found, show a report and let the user choose Yes/No whether to update the existing index DB.
- Explicit confirmation instead of automatic adoption keeps the Test Mode isolation contract (main index/cache/profile/thumbnails stay untouched unless confirmed; the 0.9.4.127 pin remains valid) while still offering promotion of the test result.

## 2. Previous structure

- After a Test Mode run there was no way to learn how the scratch result differed from the main index, and no way to apply it (the main index was always immutable from Test Mode).

## 3. Changed structure

- **Difference computation (backend, on Test Mode completion)**: opens both indexes and compares file rows and match pairs.
  - `changed`: same path with a different fingerprint/mirror/crop/size; `added`: only in the scratch; `removed`: only in the main index but **inside the test scan's scope and not ignored**; `pairDiff`: symmetric difference of the pair sets. Cancelled scans are skipped.
  - Zero differences -> only the status line "The test scan matches the main index."
- **Report (Yes/No)**: on differences a non-modal QMessageBox shows `changed / new / removed (in scan scope) / pairs A -> B`. No changes nothing.
- **Adoption (Yes)**: `APPLY_TEST_RESULT` (additive command) -> backend worker thread (same rule as Load/re-verify) copies the scratch files/matches/thumbs/content_hash/file_trace/meta into the main index in **one transaction** (ATTACH + DELETE/INSERT SELECT). On success the main index equals the completed test scan exactly; on failure/cancel SQLite rolls back so the **main index stays as it was** (no file swap -> no WAL side effects). After adoption the session's follow-up paths (thumbnail store, forget base) point back at the main index and thumbnails are pruned.
- Non-modal dialog: the window stays responsive and the e2e can click the buttons. Starting a new scan clears the pending state, so an old test result cannot be adopted later.

## 4. What was resolved

- Field flow: full re-verification via Test Mode -> difference report (changed/new/removed/pairs) -> Yes promotes it to the main index (or No keeps it). Test Mode isolation holds until Yes.

## 6. Impact and limitations

- Verdicts, storage, protocol (kProtocol 1), engine/DB/schema/cache and the journal schema unchanged. One additive IPC command + two events (both ends ship together).
- Adoption is **wholesale** with respect to the test scan's scope (image/video selection and the ignore list). Out-of-scope rows are replaced and surface as "removed (in scan scope)" in the report (ignored paths are excluded from that count).
- The JPEG thumbnail cache is keyed by (path, mtime, size), so a size+mtime-preserving content change may still show the previous thumbnail after adoption (a pre-existing cache-key limitation, the same class as fast rescan). Engine-DB colour thumbs, fingerprints and pairs are adopted.

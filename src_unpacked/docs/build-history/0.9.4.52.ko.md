## 1. 변경 필요성

이미지 검색 프로세싱 구간(`MediaPipeline::imageBatch` → `ImageDecoder` →
fingerprint/crop 경로)을 전수 추적해 내제 문제를 확정했다.

## 2. 수정 1: `mbstowcs` 로케일 의존 제거

`src/image_decoder.cpp` XMP `VT_LPSTR` 분기가 `std::mbstowcs`로 변환했다.
`mbstowcs`는 스레드 C 로케일에 의존하고, 기본 "C" 로케일은 ASCII만 받는다.
`VT_LPSTR`은 정의상 ACP 인코딩이므로 명시적 `MultiByteToWideChar(CP_ACP, ...)`로
교체했다. 파싱 대상이 ASCII 숫자("1"-"8")라 결과는 동일하고, 그 외 입력에
대해서는 로케일에 따라 달라지던 동작이 확정적으로 바뀐다. 실패는 기존대로
graceful (`ok=false`).

## 3. 수정 2: `parallelFor` catch 의도 명시

`src/media_pipeline.cpp`의 `catch(...) {}`는 워커 스레드 종료 방지용으로
load-bearing이다. 예외가 나면 해당 슬롯이 `ok=false`가 되어 분석 실패 상태
모델이 settled `failed`로 처리한다. 동작은 그대로 두고, 왜 지우면 안 되는지
주석으로 고정했다. 원인별 진단은 `DecodeTelemetry` 영역이며 fan-out에서
구분하지 않는다.

## 4. 검증으로 sound함을 확정한 항목 (수정 없음)

- **fingerprint 0 불가능**: `bits_from`는 median 비교라 유효 입력에서 0을
  반환할 수 없다 (median 자체가 값 중 하나라 최소 1비트 설정). 따라서
  fingerprint 0은 항상 "미산출"이며, 0.9.4.46 상태 모델과 모순되지 않는다.
  `perceptual_hash`의 invalid→0 반환은 실패 모델로 정확히 흘러간다.
- **PGM fallback 경로**: 이미 `path_from_utf8` wide 경로 사용. 안전.
- **crop 0 처리**: 빈 입력 가드로 0과 미산출 구분. 안전.
- **GPU/CPU mirror 일관성**: mirror는 항상 CPU에서 계산되므로 GPU 성공 여부와
  무관하게 일관. 중복 연산 아님.
- **`parseOrientationText`**: 1-8 엄격 판정, 후행 garbage 거부. 안전.

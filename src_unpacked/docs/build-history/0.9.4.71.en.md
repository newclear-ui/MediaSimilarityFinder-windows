# MediaSimilarityFinder v0.9.4.71 — Backend defect fixes + ThumbnailStore

Baseline `0.9.4.70` → this build `0.9.4.71`.
CPU CTest **116/116**, GPU CTest **117/117**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged. No change to search semantics or behavior.

## 1. Why this change

- Fix the seven defects confirmed by the second independent review after the
  P3/P4 process split. The two largest are (a) after the split the GUI resource
  mode (Maximum etc.) was never delivered over IPC, so the worker always ran
  with `make_policy(Custom)`, and (b) the backend thumbnail path only read the
  engine `thumbMap_`, with no disk DB or decode fallback, so most previews were
  empty after the split.
- Restore the `onFileMetaReady` in-place contract (violated since it called
  `refreshFileViews()`, recreating all widgets and destroying the selection on
  every fileMeta arrival — the 0.9.4.66 pattern).
- One additional regression surfaced during verification: the GUI decoded JPEG
  via the Qt plugin, but the plugin's dependent DLL is not in the deployed set,
  so no thumbnail ever painted (the test suite caught it).

## 2. Previous structure

- `ScanWorker::run()` computed worker count with `make_policy(Custom)` and no
  `resourceMode_`. The mode was absent from the `START_SCAN` payload.
- GUI "Index Complete" showed only `analyzedCount_`, so reused (unchanged)
  files were missing and the label stayed at 0/short even when finished.
- The summary panel's CPU/RAM labels were overwritten alternately by
  `updateSysLabels()` (GUI process, every UI tick) and `onMonitorSnapshot()`
  (system-wide, 1s) → MB/% values oscillated.
- The slowest-file list mixed cache-hit video rebuilds (~0ms) and failed
  decodes (0ms), hiding genuine algorithmic outliers.
- `ScanWorker::allMatches_` stayed resident for the process lifetime even after
  the final persist.
- Backend thumbnails queried only the engine `thumbMap_`; no disk cache or
  WIC/FFmpeg/shell decode was wired (`thumbDb_` was deleted on the GUI side and
  never migrated).
- `onFileMetaReady` recreated all widgets via `refreshFileViews()`.
- loopback and supervisor decoded JPEG with `QImage::fromData`.

## 3. New structure

- **Execution policy delivery (two independent axes kept)**: new
  `ExecutionPolicy` `{cpuMode, cpuPercent, gpuPercent, strategy, gpuEnabled}`.
  `BackendScanConfig.exec` → `START_SCAN` payload → `ScanWorker::setResourceMode`
  → `make_policy(resourceMode_)` in `run()`. Live refresh is the
  `UPDATE_RESOURCE_POLICY` command plus the `POLICY_APPLIED` reply
  (partial=true = monitor applies now / engine at the next scan). GUI
  `resourceChanged`/`customResourceChanged` now call `updateResourcePolicy`.
  The scalar cpu/gpu fields stay for backward-compatible readers.
- **Index Complete**: engine `unchangedCount_` atomic added (incremented at the
  same place as nUnchanged), carried as `BackendStatus.unchanged`, GUI
  `liveAnalyzed = analyzed + unchanged`.
- **Single summary meaning**: `updateSysLabels()` writes only the GPU state;
  CPU/RAM are written only by the working-process status snapshot
  (`onStatusSnapshot`). `backend_sysinfo.*::sampleOwnProcess` samples the
  Backend process CPU%/WorkingSet; loopback samples the GUI process.
- **Slowest-file list**: `addImage` excludes `decodeMs+hashMs+cropMs<=0`;
  `addVideo` excludes entries with the `cacheHit` flag (engine
  `VideoBuildStats.cacheHit`). A caller that omits the flag is a real analysis
  and stays listed.
- **Memory release**: `allMatches_.clear()` + `shrink_to_fit()` after the final
  `persistMatchesSnapshot()`. On the normal path and both catch handlers
  (`shrink_to_fit` is wrapped in try/catch to honor the no-throw handler rule).
- **ThumbnailStore**: new `src/thumbnail_store.{h,cpp}` — persistent SQLite
  (`IndexManager::resolve`) + small memory LRU (256) + decode chain (engine art
  → shell `IThumbnailCache` → WIC → FFmpeg → gray). Serves JPEG end-to-end and
  is independent of the `ScanWorker` lifetime. `backend_thumb` (JPEG encoder)
  moved into msf_core with `libjpeg-turbo` linked `msf_core PUBLIC`.
  `BackendSession::requestThumb` returns `msf::JpegThumb`; the re-encode in
  `backend_main::serveThumbnail` is removed.
- **fileMeta in-place**: `fileMetaPending_` changed from `QSet<QString>` to
  `QMap<quint64,QString>` (id-based dedup + requestId stale-drop).
  `onFileMetaReady` updates only the matching grid cell / list row via
  `refreshFileMetaRow`, and calls `refreshDetail` only for the current file.
  No widget recreation.
- **Shared JPEG decode (regression fix)**: new `msf::decodeJpegArgb32`
  (`backend_thumb`, libjpeg-turbo) returns ARGB32 memory-order (BGRA) bytes.
  loopback and supervisor use it, removing the Qt JPEG plugin dependency.

## 4. Resolved

- The GUI's chosen resource mode now reaches the real worker budget (Maximum
  degradation fixed).
- Previews that were empty after the split are filled from engine art, disk
  cache, and decode fallbacks. The GUI process still performs no media pixel
  decode.
- FileMeta arrival no longer destroys selection or scroll.
- The summary CPU/RAM labels are fixed to one meaning (working process) and no
  longer oscillate.
- Index Complete shows the real indexed amount.
- The slowest-file list shows only files that did real work.
- The backend releases the match set after the final persist.
- Thumbnails actually paint (independent of the deployment dependency set).

## 5. Verification

### Per-defect response

1. Execution policy: mode is delivered on the scan path (code path) + full
   CPU/GPU CTest passes. GPU MAX share boost is a documented gap (no silent
   upgrade).
2. Index Complete: `unchanged` push wired + GUI sum. Full suite passes.
3. Summary labels: `updateSysLabels` GPU-only, `onStatusSnapshot` single
   CPU/RAM writer.
4. Slow files: `benchmark_test` keeps real analysis entries after excluding
   cache hits.
5. Memory: clear + shrink on both normal and failure paths.
6. ThumbnailStore: `ui_scroll_regression_test` ("thumbnails painted on
   arrival") and `view_mode_probe` ("arrivals painted through the product
   path") pass.
7. fileMeta in-place: the `ui_scroll_regression_test` selection widget identity
   check passes (zero recreation).
8. JPEG regression: `QImageReader::supportedImageFormats()` lacks jpeg;
   `dumpbin imageformats/qjpeg.dll` → `jpeg62.dll` (not in the deployed set).
   Replaced with the shared libjpeg-turbo decode; both GUI tests then pass.

## 6. Future impact

- Manual GUI acceptance is still required (preview display, selection, UI guard
  on kill, recovery after restart, Tiles/ListMode, large-dataset traversal).
- The GPU MAX GPU share boost remains unimplemented (behavioral gap documented).
- The exact split of the backend 400MB needs a VMMap/heap snapshot (code alone
  cannot determine the ratio; allocator Working Set return caveat).
- `ExactnessPolicy::RefuseAll` stays; Node E remains terminated.
- 0.9.5 (ImageWorker/VideoWorker/MonitorService) is separate design scope.

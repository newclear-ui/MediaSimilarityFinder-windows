## 1. Why the change was needed

An images-only scan still hashed videos. On a video-heavy dataset that meant
hundreds of gigabytes before any walk, so indexing was never reached. Stopping
early (correctly) left walk unstarted, repeating "no indexing" forever.

## 2. Previous structure

`computeDatasetFingerprint(root)` hashed every regular file regardless of
scope. `scanImages`/`scanVideos` applied only to walk/analysis.

## 3. New structure

`computeDatasetFingerprint(root, cancel, progress, scanImages=true,
scanVideos=true)` takes the scope. Defaults keep all ~20 existing callers
working unchanged.

- Unrestricted scope: byte-identical all-files behavior, non-media included
- Restricted scope: only in-scope media via the single classifier
  (`Scanner::isMediaPath`/`isVideoPath`), no duplicated rules
- A restricted scope yields a different (scope-specific) fingerprint value,
  which is correct: scope is already a separate S6 grouping axis, and no valid
  real-dataset fingerprints exist yet (cancels record null)
- `scan()` passes `control->scanImages/scanVideos` (null control means true)

## 4. Resolved situation

- Images-only scans hash images and proceed to walk
- Video-heavy datasets can now reach indexing
- Full-scope behavior and values unchanged

# MediaSimilarityFinder v0.9.2.82 — 포터블 실행 불가 수정(Qt 플러그인 배치+CRT 동봉)

## 변경 필요성
- 포터블 패키지 실행 시 `no Qt platform plugin could be initialized` 오류로 시작 실패했다.
- 원인 2가지: (1) vcpkg에 `windeployqt.exe`가 없어 스크립트의 수동 폴백만 동작했는데, 플러그인을 Qt가 검색하지 않는 `Qt6\plugins` 중첩 경로에 복사했다. (2) VS 2026 툴체인 산출물은 타 PC의 구형 시스템 CRT와 불일치할 수 있다.

## 기존 구조
- `package_portable.ps1`은 `windeployqt`가 있으면 위임하고, 없으면 `Qt6\plugins` 전체를 패키지 내 중첩 복사했다.
- VC++ 런타임은 동봉하지 않았다.

## 변경 구조
- 플러그인 카테고리 디렉터리(`platforms/`, `styles/`, `imageformats/`, `iconengines/` 등)를 패키지 루트에 복사한다. 실행 파일 디렉터리 자체가 플러그인 검색 경로이므로 이 배치가 `windeployqt` 표준 레이아웃과 동일하게 동작한다. 중첩 `Qt6\plugins` 복사는 제거했다.
- VS Redist의 `Microsoft.VC145.CRT`에서 `vcruntime140(dll/_1)`, `msvcp140(dll/_1/_2)`, `concrt140`을 앱 로컬로 동봉한다. UCRT는 Windows 10+ 내장이므로 제외한다.
- 판정 로직·CUDA 알고리즘 변경 없음. 버전 표기 통일 → 0.9.2.82.

## 해결된 상황
- 재생성한 포터블 패키지를 최소 PATH·`QT_PLUGIN_PATH` 미설정 환경에서 실행해 `--smoke`·`--version` exit 0을 확인했다. 중첩 `Qt6` 디렉터리는 패키지에 더 이상 없다.

## 검증
- Core+GUI Release 빌드: PASS, **CTest 56/56 PASS**
- 포터블 패키지 실행 검증: 깨끗한 환경에서 `--smoke` exit 0, `--version` exit 0
- `MediaSimilarityFinder-v0.9.2.82-Portable-Windows-x64.zip` 생성

## 향후 영향
- vcpkg에 `windeployqt`가 생기면 스크립트의 위임 블록이 동작하지만, 수동 배치와 공존해도 무해하다.
- 타 PC 실행 조건: Windows 10 이상. VC++ 재배포 패키지 별도 설치 불필요(CRT 동봉).

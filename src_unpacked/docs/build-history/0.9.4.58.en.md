## 1. Why the change was needed

Stop means "read no new files", not "discard work already read". Previously a
cancel dropped the admitted-but-unanalyzed image batch, so stopping a long scan
kept zero new index rows. A 20-minute search stopped cleanly with no index at
all under that structure.

## 2. Previous structure

Trailing batch and video ranges after the consume loop were gated on
`!cancelled`, skipping everything on cancel. Up to 256 admitted images stayed
skeleton rows, re-read from scratch next scan.

## 3. New structure

On cancel, the pending image batch drains to completion before exit.

- Images only. At most one batch, seconds of work, so Stop stays responsive
- Videos keep drop behavior. A single video decode is unbounded, and draining
  it could stall Stop for minutes. Documented intentional asymmetry
- Drained results get fingerprints, DB rows, and analyzed counts like normal
  analysis. A DB error during drain follows the existing failure path, and
  checkpoints commit through the drain

### Fingerprint timing relocation (same build, prior work)

- A telemetry-only full-dataset hash ran ahead of the walk, so on huge datasets
  productive work never started. The fingerprint now runs after match/group,
  right before `finishScan`
- Still skipped when telemetry is off, and skipped on cancel/failure so a stop
  or an error is reported promptly. A skip leaves `not_available`
- A pre-set cancel enters no phase, so `cancelledDuring` is empty. "Stopped
  before anything began" is the truthful record, not "cancelled in
  fingerprint". `cancel_fingerprint_test` expectations updated accordingly

## 4. Resolved situation

- Stopping keeps indexes for read images
- Rescans report drained rows unchanged and process the rest
- Hours of work stopped midway now preserve their processed index instead of
  stopping clean with nothing
- Relocation unblocks productive work from the hash. Cancel, failure, or
  telemetry-off skips the fingerprint and returns promptly

## 6. Future impact

- Stop semantics fixed as "stop reading, finish what was read". Partial
  progress preservation is complete together with checkpoints
- Undrained video is a documented limit. Revisit if single-decode cancel lands
- The fingerprint is now a post-production telemetry step, not a precondition.
  S6 dataset-identity consumers must treat `not_available` as normal
- Next: S4 screen acceptance, `color_thumb` R1

# MediaSimilarityFinder v0.9.4.79 — 인덱스 생명주기 관리 (janitor)

기준선 `0.9.4.78` → 본 빌드 `0.9.4.79`.
CPU CTest **121/121**, GPU CTest **122/122**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 검색 판정·스키마 변경 없음.

## 1. 변경 필요성

- 회귀 테스트는 임시 미디어 폴더를 스캔하면서 인덱스 저장 위치(`appDir`)는
  실행 파일 디렉터리를 그대로 쓴다. 테스트용 임시 폴더가 삭제된 뒤에도 그
  인덱스 디렉터리가 `<appDir>/Index/<folderId>/` 아래에 고아로 남는다.
- Test Mode 실행 때도 `<appDir>/TestMode/<고유값>/` scratch가 매 실행마다
  쌓인다.
- 산발 고아 폴더는 관리가 어렵다는 사용자 지적에 따라, 위치를 옮기지 않고
  수명주기를 관리하기로 했다 (해석 위치·folderId 계약을 건드리지 않기 위해).

## 2. 기존 구조

- 수명주기 관리가 없었다. 고아 인덱스는 수동으로만 치울 수 있었다.

## 3. 변경 구조

- 신규 `src/index_janitor.{h,cpp}` (msf_core 편입). 삭제는 다음 셋을 모두
  만족할 때만 일어난다 (보수적 설계):
  1. `metadata.json`이 파싱되고 `rootPath`가 나오고,
  2. 그 루트가 디스크에 존재하지 않고,
  3. 기록된 `lastScan`이 7일 이상 지났고,
  4. 디렉터리 자체 mtime도 7일 이상 지났다 (metadata 재기록이 atomic rename이라
     살아있는 스캔은 mtime을 갱신한다).
- `TestMode` scratch leaf는 항상 재생성 가능하므로 디렉터리 mtime 7일 규칙만
  적용한다. 파싱 불가·신규·`Index/`·`TestMode/` 밖은 절대 손대지 않는다.
- `ScanWorker::run()` 시작 시점에 1회 수행한다. bounded 순회, 예외 불가,
  스캔 실패 없음. 결과는 backend 로그 1줄 (`janitor removed index/scratch`).
- narrow UTF-8 경로도 wide 구성으로 처리해 0.9.4.77 계열 throw가 swee프를
  깨지 않는다.

## 4. 해결된 상황

- 매 스캔 시작 때 의미 없어진 지 7일 이상인 고아 인덱스와 scratch가 정리된다.
- 실제 루트가 살아있는 인덱스는 절대 지워지지 않는다 (조건 2).

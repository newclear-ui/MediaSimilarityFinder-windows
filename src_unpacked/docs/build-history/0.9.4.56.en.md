## 1. Why the change was needed

The "writing search report" popup reportedly never closes after Stop. The
engine was measured to return promptly (`finishedAt` equals Stop time), and
flush (bounded ≤1000) / prune (single DELETE) / walker (cancel-aware bounded)
were verified by code. The only unobserved section left is inside GUI-thread
`scanFinished`, which headless sessions cannot observe.

## 2. New structure

Two `scanLog` trace lines at `scanFinished` entry/exit. No behavior change.

- Entry: `scanFinished enter: <first 80 chars of msg>`
- Exit: `scanFinished exit` (after popup close + idle return)

The next hang is classifiable from `msf_scan.log`:
- no enter → worker never returned (engine side)
- enter without exit → stall inside scanFinished (GUI side, localizable)
- both present → problem past the popup close (separate path)

## 3. Why indexing did not happen (no code change, explanation)

The attached log is a fingerprint-phase cancellation (`cancelledDuring=
fingerprint`, 71s, 11GB, scanned=0). It stopped before walk/analysis, so no
indexing is correct behavior.

Verified workaround: **uncheck [Detailed Logs]** → `telemetryEnabled=false` →
fingerprint skipped (0.9.4.51) → walk starts immediately. The checkbox defaults
to ON. The fingerprint is telemetry-only, so disabling it does not affect scan
behavior.

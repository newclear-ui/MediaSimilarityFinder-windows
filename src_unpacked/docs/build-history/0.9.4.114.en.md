## 2. Previous structure and defect (a regression of the 0.9.4.113 B1 fix)

- The 0.9.4.113 full-content confirmation in `MediaSearchEngine::loadMatches()` (the quick-load path) implemented the per-file hash memo as a **reference into the map**:
  ```cpp
  const auto fullHex=[&](const std::string& p)->const std::string&{
    ...
    return fullMemo.emplace(p,std::move(hex)).first->second;  // reference into the map
  };
  ...
  const std::string& ha=fullHex(m.left); const std::string& hb=fullHex(m.right);
  if(!ha.empty()&&ha==hb) ...   // the second call's emplace/rehash invalidates ha -> UAF
  ```
- **Cause**: an `unordered_map` insert can rehash and **invalidate every reference**. The second `fullHex` call inserted a new key, rehashing the map, so `ha` pointed into freed bucket memory — a dangling comparison (use-after-free) leading to heap corruption/crash.
- **Both symptoms share one cause**: `loadMatches` runs on Load (`backend_session.cpp:347`) and on scan quick-load (`scan_worker.cpp:135`).
- **Why CI missed it (latent)**: with small test sets (hundreds of pairs) the freed bucket array is not reused, so the dangling reference happens to read valid data. On the user's dataset (5,296 candidate files / 3,493 pairs, long paths, heavy heap reuse) it crashes deterministically.

## 3. New structure

- **`fullHex` returns by value (std::string)** and `ha`/`hb` are values (`media_search_engine.cpp`). The lifetime problem is removed at the source. Cost: string copies (a few KB, negligible).
- **Regression test** (`search_engine_test`): a **field-scale** case — 3,000 mutually distinct noise BMP pairs (6,000 files) -> scan -> `saveMatches` -> `loadMatches` -> every stored pair must be `contentIdentical=true` (6,000 memo inserts force many rehashes). Return codes 20-24.
- Honest record: running this test against the neutralized (reference-returning) version **still passed** — in a synthetic environment the freed memory is not reused, so the UAF is nondeterministic. The field crash (62097) is the reproduction; the test pins the large-load contract.

## 4. What is fixed

- The dangling reference is gone, resolving the backend crash on Load and Start Scan (cause-fix match: both paths run this function).
- The badge contract (full-content SHA-256 equality) and the other 0.9.4.113 changes stay intact (the scan-pipeline memo already returned by value).
- The user's index DB is undamaged (SQLite crash safety; the crash happened during load processing, with no writes).

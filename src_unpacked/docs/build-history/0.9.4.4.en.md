# MediaSimilarityFinder v0.9.4.4 — Node B3: Live Load Awareness

Validation baseline for B3: the brief §7 inputs (CPU/GPU load, VRAM,
queue state, external load). Engine 1.5.0, DB 1.0.3, cache v9, schema 1
unchanged.

## Why the change was needed
- Through B2 the scheduler assumed idle hardware. External load (a game,
  another job) left shares detached from reality.

## Previous structure
- `SchedulerHardware` had no load inputs; `SystemLoadMonitor` served only
  the monitor path.

## New structure
- `SchedulerHardware` gains system-load inputs (cpuLoad, gpuLoad,
  memPressure plus known flags). Queue-depth fields ride along reserved
  for D1 and are ignored by B3 evaluation (no producer yet, documented).
- Headroom rule (`effectivePair`): CPU `(100-sysCpu)/100` floored at 0.05
  (never fully zero our own share on self-loaded systems); GPU with no
  floor (system GPU% is external-dominated, so full contention rightly
  converges to CPU). memPressure is recorded input (B6 policy use). A full
  GPU kill yields reason `external_load_throttle` plus an edge count.
- Engine holds one `SystemLoadMonitor` per scan and refreshes at decide /
  re-evaluation points (first CPU delta is 0; GPU% cached 3 s, so the 2 s
  cadence spawns no extra nvidia-smi).
- `externalLoadThrottling` is filled from the scheduler edge counter.
  `throttlingEvents` stays 0 (B4+).
- No smoothing or hysteresis (B4). No transfer/workload cost (B5).

## Why this shape
- Precise external attribution (self separation) is B4+ runtime
  accounting. B3 reflects headroom signals with honest floors.
- Taking queue inputs without an observer would be fiction, so reserved
  fields plus explicit ignore prevent interface churn with D1.

## Resolved state
- The scheduler sees live load. B4 only needs to shape transitions.

## Accuracy impact
- None. Gates and verdict paths untouched; unknown-load stretches behave
  as B2. Parity via identical `scan_workflow_test` on both trees.

## Compatibility impact
- Benchmark JSON keys unchanged, schemaVersion kept (no extension).
  `current*Capacity` may carry load-adjusted values.

## Validation
- CPU Release build PASS, **CTest 64/64 PASS**.
- GPU Release build PASS, **CTest 65/65 PASS**.
- B3 `scheduler_test` additions (load scaling, GPU kill + edge, unknown
  fallback, mem no-effect) green on both.
- `--version` 0.9.4.4 and `--smoke` PASS on both.

## Future impact
- B4: smoothing, hysteresis, minimum hold. B6 Gaming policy may consume
  memPressure. D1 fills the queue fields.
- Load-driven share jitter is B3's honest record; B4 damps it.

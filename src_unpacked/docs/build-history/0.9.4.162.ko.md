# MediaSimilarityFinder v0.9.4.162 — 매칭 경로 MSSIM 시간 분리 집계 (P1)

기준선 `0.9.4.161` → 본 빌드 `0.9.4.162`.
CPU CTest **134/134**, GPU CTest **135/135** (신규 CTest 없음, 기존 테스트에 단언 추가).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` 전부 불변.

## 1. 변경 필요성

- P1 측정 분할의 나머지 절반: 빌드 경로(decode/pHash)는 0.9.4.161에서 분리됐으나, 매칭 경로의 MSSIM 시간(GPU 실행 vs CPU fallback)은 `VideoSimilarityStats`에 `stats`를 넘기는 호출부가 없어 어디에도 집계되지 않았다.

## 2. 기존 구조

- `video_similarity()`의 CPU fallback `frame_ssim` 호출은 시간을 재지 않았다.
- `AnalyzeTelemetry`에는 `ssimEvals`/`frameSsimEvals` 카운터만 있고 시간 분할이 없었다.
- `scan_pipeline` temporal worker는 `stats` 없이 `video_crop_similarity`를 호출했다.

## 3. 변경 구조

- `VideoSimilarityStats.cpuMs`: CPU fallback `frame_ssim` 쌍 계산 시간. GPU 시간은 기존 `gpuMs`에 그대로 누적된다.
- `AnalyzeTelemetry`에 `videoMatchGpuMs`/`videoMatchCpuMs`/`videoMatchSubmitted`(게이트 통과 제공 수)/`videoMatchCompleted`(GPU 실제 실행 수) 추가. 기존 merge(`addAnalyzeTelemetry`)·ScanStats 복사·`analyze` 섹션 JSON 키에 동일 패턴으로 편입(additive).
- `scan_pipeline` temporal worker가 워커-로컬 `VideoSimilarityStats`로 호출하고, 순차 harvest에서만 `tel`에 합산한다(worker는 공유 텔레메트리를 만지지 않는다 — 기존 async pool 경합 회피 원칙 유지).
- 회귀: `video_sim_perf_test`에 `cpuMs>0`(CPU 경로, fallback 확인) / GPU 경로 `cpuMs==0`(전량 GPU 확인) 단언. `analyze_telemetry_test`에 merge 합산 단언(D3 스타일).
- adhoc 조회 경로(`media_search_engine` loadTemporal)는 `tel`이 없어 제외하고 문서에 명시한다. 생산 매칭 경로는 `scan_pipeline` temporal flush다.

## 4. 해결된 상황

- 이후 실스캔 로그의 `analyze` 섹션에서 매칭 MSSIM 비용을 `videoMatchGpuMs + videoMatchCpuMs`로, GPU/CPU 전환율을 `videoMatchCompleted / videoMatchSubmitted`로 읽을 수 있다.

## 6. 향후 영향 및 한계

- 판정·저장·프로토콜·버전 전부 불변. 캐시 무효화 없음. JSON additive라 구 리더와 호환된다.
- GPU batch 임계값(8)은 실측 근거 없이 미변경. 프레임 선택의 시간축 대표성은 V2/V3 gate 이후 과제이며 본 빌드에 포함하지 않는다.

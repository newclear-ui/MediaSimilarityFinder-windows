# MediaSimilarityFinder v0.9.3.1 — Search Benchmark Log (JSON)

> Renumbering: this release is content-identical to what was built, verified, and pushed
> as `v0.9.2.91`. The benchmark is promoted to a major feature, so only the number moves
> to the new minor line `0.9.3.x`. Follow-up fix builds go `0.9.3.2` → `0.9.3.3`.

## Need for change
- Comparing and improving search performance needs per-stage timings, per-file
  decode/hash costs, video scan time per play-minute and per GB, and measured
  CPU/GPU utilization.
- Completion and cancellation both need a human-readable summary plus a
  machine-parseable original.

## Previous structure
- No stage timers, resource sampler, or result log existed. GPU activity was a
  status-display flag only.

## New structure
- New `src/benchmark.{h,cpp}`. `BenchmarkRecorder` collects:
  - Stage times: walk / revalidate / image / video / analyze.
  - Per image: decode, hash, and crop ms, GPU flag, bytes, path (aggregates + slowest 20).
  - Per video: build ms, play seconds, frames, bytes, path (aggregates + slowest 20).
  - Total GPU batch time.
  - 250ms resource samples: process CPU%, system CPU%, working-set MB, GPU flag
    (capped at 50k points, truncation flagged).
- `MediaPipeline::imageBatch` takes a recorder and records from worker threads
  (atomics for sums, mutex for slowest lists). `steady_clock`-based; overhead is
  negligible next to millisecond-scale decodes.
- Engine `scan()` records the config (root, distance, workers, batch, kinds, CUDA
  availability, all three versions) and starts the sampler. A `finishScan` lambda
  finalizes on every return path (failures and cancels included), so cancelled scans
  still log with `completed:false`. `ScanControl` gains `revalidateMs`/`buildVersion`.
- GPU utilization comes from the existing `gpuActive_` atomic flag's duty cycle:
  active-sample ratio (`gpuDutyPct`), longest continuous idle (`gpuLongestIdleMs`),
  and the raw series (`[tMs, cpuProc, cpuSys, memMB, gpu]`). No external
  dependencies or spawns.
- CPU usage uses per-sample deltas from `GetProcessTimes` (process, normalized by
  core count) and `GetSystemTimes` (system busy). Mean, max, and stddev (jitter
  metric) are recorded together.
- Dependency-free hand-rolled JSON in 7 sections: `meta` (build, engine, DB,
  timestamp, completion, root), `config`, `summary` (stage times, scanned/analyzed/
  unchanged counts, filesPerSec), `images`, `videos`, `resources`, `matches`.
  Paths are JSON-escaped.
- `ScanWorker::benchmarkReady(QString)` → `MainWindow::onBenchmark` popup.
  Parses with `QJsonDocument`, shows a KO/EN summary (status, elapsed, files, images,
  videos, CPU, memory, GPU, matches, 5 slowest each), and offers a JSON save button
  (default `benchmark-<timestamp>.json`). Shown on completion and cancellation,
  not on hard failure.
- Version strings unified → 0.9.3.1, 59 tests (`benchmark_test`: JSON keys,
  aggregates, zero duty, series structure).

## Resolved situation
- Images: count, bytes, GPU/CPU hash split, mean decode/hash, GPU batch time, slowest 20.
- Videos: count, play seconds, frames, mean build, sec/play-min, sec/GB, slowest 20.
- Resources: CPU mean/max/stddev, system mean, peak memory, GPU duty%, longest idle,
  plus the raw series.
- The popup shows the slowest 5; the JSON carries all 20.

## Validation
- Core+GUI Release build: PASS, **CTest 59/59 PASS**.
- Existing scan tests pass unchanged, proving the timing hooks don't affect scans.
- Portable `--smoke` exit 0, `--version` 0.9.3.1,

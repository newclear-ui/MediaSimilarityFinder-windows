# MediaSimilarityFinder v0.9.4.96 — Resource-policy UI rework (Minimum rename + Custom removal + Settings move)

Baseline `0.9.4.95` -> this build `0.9.4.96`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

User directive: keep the execution strategy (AUTO/CPU-only/GPU-max) untouched; keep Maximum/High/Balanced presets; rename Gaming to Minimum; delete Custom. Hide the toolbar's CPU usage % display + fine-edit box, with a Settings > General checkbox selecting the display. Move the GPU acceleration checkbox from beside the monitor icon to Settings > General too.

## 2. Previous structure

- Toolbar: strategy combo + preset combo (Maximum/High/Balanced/Gaming/Custom) + `CPU %` spinbox (display+edit in one; editing forced Custom) + monitor button + GPU acceleration checkbox.
- The policy layer (`ResourceMode`, scheduler Gaming branches, monitor Gaming reserve, backend Custom defaults) is woven through engine and tests.

## 3. New structure

- **4 presets**: combo renames `Gaming` to `Minimum` (same 25/25 values) and drops `Custom`. The index-based mapping (`i+1`) holds, so `resourceChanged()` is untouched. Enum/values in policy layer, scheduler, monitor, and tests all unchanged.
- **Read-only + hidden CPU box**: no spin buttons, read-only field. Visibility through the toolbar action from `ui/showCpuPercent` (default OFF). Deleted `customResourceChanged()` (definition, declaration, connection) — unreachable and its index-4 reference is now invalid.
- **GPU acceleration to Settings**: toolbar checkbox removed, replaced by the stored switch `gpuOn_` (`ui/gpuEnabled`, default ON). The CPU-only forced-OFF / AUTO·GPU-max forced-ON overwrite semantics are preserved. A `GPU acceleration` checkbox (reused `monitorGpu` label) in Settings > General applies to the backend immediately on save.
- **Settings > General**: new `Show CPU usage %` checkbox (`showCpuPercent` key) + `GPU acceleration` checkbox, saved/applied through the existing save flow.
- Translation key `showCpuPercent` (+ `monitorGpu` coverage). `ui_translation_keys_test` 63 -> 65 keys.

## 4. Result

- Execution strategy trio untouched. Maximum/High/Balanced values untouched. Minimum 25/25.
- Slimmer toolbar (strategy + preset + monitor + log); CPU % display and GPU acceleration are opt-in via Settings.
- Policy layer untouched, so engine/backend/CLI/existing policy tests are unaffected.

- Unrelated to the Fast/Auto measurements (§7.3 planned).

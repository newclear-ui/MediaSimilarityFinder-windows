# MediaSimilarityFinder v0.9.2.90 — External Report Follow-ups

## #1 Video Sampling Edges (Dyadic Intervals + Compare-Time Thinning + One-Time Re-analysis)

### Need for change
- Per-band intervals (1/2/5/10/15/30s) sampled completely different timestamps for
  re-encodes near a boundary (59.98s→31 frames vs 60.02s→14 frames). DTW timePenalty
  docked up to 20 points per cell.

### Previous structure
- `sampling_interval`/`make_sample_plan` used six bands with non-nesting intervals,
  compared as-is through DTW.

### New structure
- Dyadic 1/2/4/8/16/32s intervals (`sampling.cpp`, `video_sampling.cpp` together).
  From t=0, coarser grids nest inside finer ones.
- `video_similarity`/`crop_temporal_score` thin the finer side to shared timestamps
  when the grid ratio is integral. Non-nesting grids (legacy data) use legacy full DTW.
- New DB `meta.sampling_generation` ("2") forces one re-analysis of old-grid videos on
  the next completed scan. Engine 1.0.1→1.1.0 (new rule), video cache v6→v7.
- 59.98/60.02 and 9.99/10.02 now nest; 299.9/300.1 share one grid.

### Resolved situation
- Same-content boundary-straddling re-encode pairs score ~100 (regression-tested).

### Validation
- `video_sampling_test` (grids+coverage), `video_similarity_test` (59.98/60.02 boundary),
  `core_test`/`media_analyzer_test` (band expectations), `database_test` (generation
  round-trip), `match_revalidate_test` (1.1.0), full 58/58 PASS.

### Future impact
- The first completed post-upgrade scan re-analyzes all videos once (including
  unchanged files). Cancelled scans stamp nothing, so the next scan re-forces the
  remainder (correctness first).

## #3 image_verify Crop Geometry + #6 Decode Cache

### Need for change
- Verification cropped regions out of a squashed 64x64 decode, diverging from the
  fingerprint crop geometry (aspect-preserved decode). SSIM compared same-regions
  only, so true crop-vs-full duplicates could be dropped.
- Popular files were re-decoded per candidate pair.

### Previous structure
- One squashed 64x64 decode, full + 3-region SSIM, no cache.

### New structure
- Added an aspect-preserved 64px decode; region comparisons use `centerCropResize`
  (same geometry as the fingerprints). Crop-vs-full pairings added both ways.
  Blend and thresholds unchanged.
- 32-entry LRU over both decodes, keyed by path+size+mtime, thread-safe.

### Resolved situation
- A wide-photo center-crop pair passes in the grey zone (new test). Existing
  rejection tests hold.

### Validation
- `image_verify_test` (incl. new crop-vs-full case), full 58/58 PASS.

### Future impact
- None. Rejection power is preserved by the unchanged full-64 comparison.

## #5 Candidate Index (4x16-bit Parts + Radius 2)

### Need for change
- 9 parts of 7-8 bits scanned ~7% of entries per query, heavy past 100k images.

### Previous structure
- 8+7x8=64-bit 9-part index with exact-partition lookup (D<=8 pigeonhole).

### New structure
- Four 16-bit parts with radius-2 neighbor enumeration (137 lookups per part). Error 8
  across four parts leaves one part at <=2, so exactness holds. Verifications drop
  from ~7% to ~0.8% of entries; stored refs per entry drop 9 to 4. D=0 exact lookup,
  D>8 fallback, and group-dedup semantics unchanged.
- The bit63 observation is acknowledged but left alone: changing the scoring
  denominator would alter every verdict globally.

### Resolved situation
- `candidate_pairs_test` (exhaustive linear cross-check) still passes, proving exactness.

### Validation
- Candidate family tests plus pipeline/e2e, full 58/58 PASS.

### Future impact
- ~8x fewer candidate verifications on large libraries.

## #7 Video Second Stage (Parallel + Fewer Decodes + Cache Caps)

### Need for change
- Single-threaded pair loop, up to 3 decodes on cache miss, memory-only crops,
  unbounded memory caches.

### Previous structure
- `analyze()` called `build`+`buildCropAware` sequentially per pair with unbounded
  `baseCache`/`cropCache`; the engine memory cache was also unbounded.

### New structure
- New `buildFull()`: one 32px + one 96px decode computing base and per-frame crops
  together. Crops share base's keep[] filter, so indices align 1:1 (fixes the old
  `buildCropAware` misalignment). `buildCropAware` removed with no remaining callers.
- Per-frame crops persisted in cache v7. Full hits decode nothing.
- Engine memory cache capped at a 64-entry LRU. `analyze()` local unbounded maps
  removed in favor of the engine cache.
- Temporal pairs buffered (4096) and verified in parallel (2-16 workers, 64-pair
  chunks with stop polling); results merged in order, preserving existing order/counts.

### Resolved situation
- Misses decode twice instead of three times; hits decode zero times. The recurring
  per-scan crop decode is gone.

### Validation
- `video_cache_test` (v7 layout + `buildFull` assertions), e2e included, full 58/58 PASS.

### Future impact
- Video matches stream per chunk, so live display clumps slightly (order unchanged).

## #2 XOR Structure (Rewrite Declined)

- Rewriting frame-XOR + anchor gate + temporal into a per-frame index + voting
  structure would rework candidate generation and MediaFile flow with high
  regression risk.
- The reported drift's direct cause (grid mismatch) is removed by #1 (dyadic +
  thinning + re-analysis); same-grid recall rides on anchors (any-to-any max).
  E2E tests are green.
- The rewrite is therefore declined and the current structure kept. Revisit in a
  separate version on counter-instruction.

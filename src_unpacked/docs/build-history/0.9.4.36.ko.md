## 1. 변경 필요성

v0.9.4.35 까지 I-2 구조는 probe 안에만 존재했다. product 코드는 여전히
파일마다 WIC 파이프라인을 두 번 만들고 있었다.

```text
src/image_verify.cpp:82-83  verifyBuffersFor()
  dec.decode(path, kDim, kDim, f)             <- 파이프라인 1회
  dec.decodePreserveAspect(path, kDim, a)     <- 파이프라인 1회
```

COM 초기화, factory, `CreateDecoderFromFilename`, `GetFrame(0)`, metadata
reader, EXIF orientation source, `GetSize` 가 전부 두 번 실행되었다. 두 결과를
**동시에** 필요로 하는 production 경로가 이것 하나뿐이라, 통합 이득은 전적으로
여기에 몰린다.

## 2. 기존 구조

`decodeWicFile()` 과 `decodeWicFileAspect()` 이 서로 거의 동일한 두 몸통이었다.
timing 버킷 경계도 같았고, EXIF query helper 만 v0.9.4.35 에서 공유되고 있었다.
호출자는 두 API 를 순차 호출해야 했고, 두 번째 decode 의 비용은 D3 가
49.60 % 로 계측한 바 있다.

## 3. 변경 구조

### 단일 source of truth

`decodeWicBranches()` 를 만들고 세 개의 public 진입점이 모두 그것을 호출한다.

```text
decodeWicBranches(path, fw, fh, maxDim, wantFixed, wantAspect, f, a, telF, telA)
  CoInitializeEx                1회
  WIC factory                   1회
  CreateDecoderFromFilename     1회
  GetFrame(0)                   1회
  EXIF orientation source       1회   (exifOrientationToTransform 재사용)
  GetSize                       1회
  shared IWICBitmapSource
    ├─ scaler -> converter -> CopyPixels -> f
    └─ scaler -> converter -> CopyPixels -> a
  모든 COM 해제 -> CoUninitialize
```

- 중간 `GrayImage` 없음. 각 출력은 기존과 동일한 **1단계 Fant** 체인이다.
- `decode()` / `decodePreserveAspect()` 는 시그니처·반환값·semantics 그대로.
  내부만 공유 헬퍼로 바뀌었으므로 단독 호출자(`media_pipeline`,
  `monitor`)는 영향받지 않는다.
- `decodeBoth()` 신규. 두 결과를 함께 요구하는 경로 전용.
- EXIF query path 는 재설계하지 않고 `exifOrientationToTransform` 을 재사용한다.
- 실패 시 기존 `decodePgm` / `decodePgmAspect` 를 **그대로** 호출한다. 새
  fallback 을 만들지 않았으므로 실패 경로는 byte 동일하다.
- 표시(color) 경로는 `decodeWicFileAspectColor` 로 그대로 두었으나, 이미
  동일한 `exifOrientationToTransform` 을 공유하므로 분석 경로와 표시 경로의
  방향이 갈라질 수 없다. UI 는 개편하지 않았다.

### telemetry 배분

D3 불변식을 유지하기 위해 각 버킷을 정확히 하나의 accumulator 에 넣는다.

```text
공통 (COM/factory/open/metadata/orient/GetSize) -> telFixed
fixed branch (scaler/convert/copy)              -> telFixed
aspect branch (scaler/convert/copy)             -> telAspect
```

`mergeDecodeTelemetry` 가 두 struct 를 더하므로, `totalMs` 는 실제 wall clock
한 번만 나누어 넣었다.

```text
telFixed.totalMs  = (전체 경과) - aspect branch 경과
telAspect.totalMs = aspect branch 경과
```

전체 시간을 양쪽에 넣으면 두 배로 세어져 `decodeSplitOverMs` 가 깨지므로,
`decodeWicBranches` 가 aspect branch 경과를 out-param 으로 돌려준다. 음수가
될 수는 없지만 merge 를 망가뜨리지 않으므로 0 으로 clamp 한다.

D1 의 OS file-open reference probe 는 이제 파이프라인당 1회가 아니라 호출당
1회다. 일을 한 번만 하므로 그에 따른 결과이며, `osFileOpenProbeCount` 는
paired path 에서 감소하지만 "reference probe 를 몇 번 돌렸는가" 라는 의미는
그대로다.

## 4. 해결된 상황

production verify miss 경로에서 파이프라인 중복이 제거되었다. 단독 decode
호출자는 이전과 완전히 동일하게 동작한다.

### Gate F — 성능 (production 기준)

이전 버전까지는 probe 측정값이었다. 이번에는 production entry point 를
직접 측정했다. `--production` 은 매 파일마다 baseline 과 candidate 를 둘 다
실행하므로 medians 를 각각 비교한다.

5회 실행 (CPU Release, 3341 파일):

| run | baseline 2-call median | production decodeBoth median | aspect branch median |
|---|---|---|---|
| 1 | 0.494900 ms | 0.311400 ms | 0.067800 ms |
| 2 | 0.481800 ms | 0.304900 ms | 0.065400 ms |
| 3 | 0.489500 ms | 0.310400 ms | 0.068600 ms |
| 4 | 0.475500 ms | 0.298900 ms | 0.061200 ms |
| 5 | 0.472400 ms | 0.297200 ms | 0.059400 ms |

```text
baseline median of medians   = 0.481800 ms
candidate median of medians  = 0.304900 ms
absolute delta               = -0.176900 ms
ratio                        = 0.6328  (candidate/baseline)
reduction                    = 36.72 %
```

5회 모두 candidate < baseline 이므로 측정 오차 범위 차이가 아니라 실제
개선이다. 단독 실행 decode 는 통합 대상이 아니므로 이 수치에 포함되지 않는다.

전체 코퍼스 sweep wall clock 은 23.45 / 23.97 / 24.12 s 였다. 다만 이 실행은
baseline 과 candidate 를 **둘 다** 돌리므로 순수 full-scan production 수치가
아니며, 비교용 production-only 값으로 해석하면 안 된다.

**Known limitation**: full scan elapsed 를 baseline 빌드와 candidate 빌드로
나누어 별도 실행한 값은 이번 버전에서 측정하지 않았다. 위 감소율은 decoder
수준 production 측정이다. `verifyBuffersFor` 는 cache hit 시 decode 를 하지
않으므로 실제 full-scan 효과는 miss 비율에 비례한다.

## 6. 판정

```text
PRODUCTION ADOPTION = YES
```

Gate A~F 전부 충족. exactness 는 3341/3341 byte 동일, 전수 5,579,470쌍 무변화,
EXIF 8/8, CPU/GPU 전 테스트 통과, production 측정 36.72 % 감소.

## 7. 향후 영향

- `verifyBuffersFor` 가 decode 캐시 miss 시 두 결과를 얻는 비용이 줄었다.
- `decode()` / `decodePreserveAspect()` 단독 호출자는 변화 없음.
- I-2 probe 는 여전히 독립 reference 로 유지된다. 삭제하지 않는다.
- I-1 (중간 GrayImage + resize 2회) 은 여전히 `DEFERRED`. I-2 와 병존하지 않는다.
- I-2 의 probe 기반 측정은 이제 production 측정으로 대체되었으므로, probe
  수치는 구조 reference 용도로만 인용한다.
- D1 `osFileOpenProbeCount` 는 paired path 에서 이전 버전보다 작다. 회귀가
  아니라 중복 제거의 결과다.

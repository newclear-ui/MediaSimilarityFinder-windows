# MediaSimilarityFinder v0.9.4.17 — D1b Gate (walker/video observability)

D1b validation baseline: walker-queue and video-range observability.
Engine 1.5.0, DB 1.0.3, cache v9 unchanged; schema 3 → 4.

## Why the change was needed
- D1a covered only the image synchronous path. The walker
  worker/consumer handoff and video async range granularity were
  unobserved.

## Previous structure
- Walker queue unmeasured; video ranges existed only as summed wall
  time (`videoStageMs`).

## New structure
- `recordWalkerEnqueue/Dequeue(size)` (exact queue.size passed),
  `noteWalkerStarved()` (50 ms timeout + empty + walker alive only;
  spurious wakeups and drained exit excluded),
  `recordVideoRange(files)`.
- JSON: `walker{queued,dequeued,maxDepth,starvedTicks,state}` plus
  videos `ranges/rangeFiles/rangeState`. No producer-block counter
  (unbounded by construction — documented).
- Schema v4 (new-key rule followed).

## Why this shape
- Four hooks, no topology change. The engine passes exact depths; the
  recorder only accumulates.
- No video-range timing split (range walls already live in
  `videoStageMs`). D1b adds granularity (counts, admitted files) only.

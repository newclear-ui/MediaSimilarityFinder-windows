## 1. 변경 필요성

GUI Detailed Log와 CLI benchmark 로그 감사에서 다음 공백이 확인됐다.

- GUI 로그에 **종료 시각이 없음** (CLI journal의 `run_finished.completedAt`와 달리)
- 취소 시 **어느 단계에서 멈췄는지** 알 수 없음 (`completionReason=cancelled`만)
- **fingerprint 소요 시간·읽은 바이트**가 없어 75GB 사건의 주체를 로그로 증명 불가
- `images.bytes`+`videos.bytes`는 있으나 **합산 total** 없음
- `series`에 **절대 시각**이 없어 실행 간 timeline 비교 불가
- 프로세스 최대 메모리(`memMBMax`)는 있으나 **시스템 총량**이 없어 저용량 판단 불가

## 2. 기존 구조

- `meta.startedAt`은 `localTimeStr()` 로 기록. 종료 시각 필드 없음
- `completionReason`은 있으나 phase 개념 없음
- `DatasetFingerprint`는 hash/fileCount/totalBytes만. 소요·읽은량 없음
- `series`는 `[tMs,cpuProc,cpuSys,memMB,gpu,ioReadBps,ioWriteBps]` 7개 positional
- `memMBMax`는 있으나 시스템 총량 없음

## 3. 변경 구조 (Phase-A 6종, 전부 additive)

| 필드 | 위치 | 의미 |
|---|---|---|
| `meta.finishedAt` | finalize()에서 `localTimeStr()` 기록 | 절대 종료 시각. `wallMs` 역산 아님. `startedAt`과 같은 관례 |
| `meta.cancelledDuring` | `fingerprint`/`walk`/`analyze` | 취소 시점 phase. 취소 없으면 빈 문자열. cancel 설정 후 phase 전진 금지로 고정 |
| `dataset.durationMs` | fingerprint 전체 소요 | walk+hash 실측 |
| `dataset.bytesRead` | 실제 해시한 바이트 | 성공 시 totalBytes와 동일. 취소/실패 시 더 작음. 부분 청크는 미계수 |
| `summary.totalScannedBytes` | `images.bytes + videos.bytes` 확정값 | `dataset.totalBytes`(fingerprint 대상)와 구분 |
| `series[].wallTime` | 샘플마다 절대 시각 | `tMs` 유지. positional 8번째 요소 |
| `resources.memSystemMB` | `GlobalMemoryStatusEx` 총 물리 RAM | 프로세스 최대와 대비용. 0은 미캡처 |

### phase 고정 설계

phase는 진입 시 기록되지만, **cancel이 설정된 뒤에는 전진하지 않는다.**
사전 설정 cancel이면 `fingerprint`에서 멈추고, walk 중 cancel이면 `walk`에서
멈춘다. finalize 때점이 아니라 cancel 시점을 기록하는 것이 목적이다.

### 빠른 스캔의 series 보장

250ms 샘플러보다 빨리 끝나는 스캔은 series가 비어서 wallTime 검증이
불가능했다. `finalize()`에서 샘플이 0개면 종료 시점에 1회 동기 측정한다.
실측값(그 시점 CPU·메모리·IO)이지 채움값이 아니다.

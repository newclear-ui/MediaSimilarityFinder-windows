# MediaSimilarityFinder 0.9.2.13 — Build History

**IMPORTANT CHANGE**

0.9.2.13 hardens the resident real-time monitor comparison path and Windows event handling.

## Changes
1. **Resident CandidateIndex comparison**
   - `MediaSearchEngine::compareFingerprint()` no longer scans the entire SQLite table for every comparison.
   - Separate resident CandidateIndex structures are maintained for images and videos.
   - Threshold-derived Hamming distance is used for candidate pruning, followed by the existing exact similarity calculation.
   - Upsert/remove operations rebuild the resident comparison cache to keep it consistent with SQLite.

2. **Explicit comparison-root ownership**
   - Each comparison engine now stores its corresponding comparison root.
   - Comparison-root files are synchronized only into the index that owns the path instead of being inserted into every comparison database.
   - Removal follows the same ownership rule.

3. **Windows path conversion fix**
   - UTF-8 to UTF-16 conversion buffers now include the null terminator.
   - This removes a buffer-size/path-corruption risk in `ReadDirectoryChangesW` watcher setup and event path construction.

4. **ReadDirectoryChangesW overflow/resync**
   - A zero-byte result, such as an event-buffer overflow condition, now triggers a recursive resynchronization pass for the affected root.
   - Actual fingerprinting still passes through stable-file detection and system-load throttling, preventing an immediate analysis spike.

5. **Instance-local SystemLoadMonitor state**
   - CPU/GPU sampling state moved from shared static variables to instance members.
   - Separate load-monitor instances no longer interfere with one another's sampling history.

6. **Regression coverage**
   - The monitor test now seeds 1,000 comparison entries and verifies threshold-filtered CandidateIndex results.

## Validation
- Release core build: PASS
- Regression tests: **26/26 PASS**
- Real video decode: PASS
- CandidateIndex benchmark: N=6000, indexed 415.432 ms / linear 1542.9 ms / **3.71x**

## Known limitations
- CUDA toolkit and Qt6 are unavailable in the current environment, so real Windows/NVIDIA/Qt runtime validation remains pending.
- Resident CandidateIndex structures are rebuilt on upsert/remove. This is intentionally simple and consistent for the current monitor event rate; a deletable BK-tree or more advanced incremental index can be considered for very large indexes later.

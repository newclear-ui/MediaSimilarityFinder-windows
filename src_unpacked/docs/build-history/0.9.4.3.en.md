# MediaSimilarityFinder v0.9.4.3 — Node B2: Runtime Throughput Feedback

Validation baseline for B2: the brief §6 inputs (CPU/GPU recent
throughput plus effective capacity). Engine 1.5.0, DB 1.0.3, cache v9,
schema 1 unchanged.

## Why the change was needed
- B1 capacities were static proxies: shares never moved when actual speed
  diverged mid-run. Observation-based effective capacity is B2's scope.

## Previous structure
- `SchedulerHardware` had no throughput inputs; `current*Capacity` echoed
  the baselines.

## New structure
- `ThroughputWindow` (30 s recent window, unknown below 2 samples or on
  full expiry, no smoothing — B4's scope).
- `SchedulerHardware` gains `cpuRateKnown/cpuRate/gpuRateKnown/gpuRate`
  (image-path images/sec; unknown is never zero).
- Decision rule: both sides recently observed and positive → observed
  ratio, reason `observed_throughput`; otherwise the baseline path. A
  one-sided unknown falls back to baseline, never zero.
- Engine: each image batch attributes completed images to the hashing
  backend, pushes the window, and refreshes rates before re-evaluation.
  Video excluded (decode side belongs to C/E, documented).
- `currentCapacities()`: observed rates when both known, baselines
  otherwise. B4 smooths the transitions.
- Tests extend `scheduler_test` in place (no new binary, counts unchanged).

## Why this shape
- Observed ratios share one unit (images/sec), so no normalization magic.
  A plain switch between baseline and observed is all of B2; blending and
  smoothing belong to B4.
- Videos take seconds each (poor recent signal) and entangle CPU/decoder
  attribution. Image-path scoping keeps B2 inside its boundary.

## Resolved state
- The scheduler takes live observation as input. B3 only adds load signals.

## Accuracy impact
- None. Gate positions and verdict paths untouched; below-observation
  stretches behave exactly as B1. Parity proven by identical
  `scan_workflow_test` results on both trees.

## Compatibility impact
- Benchmark JSON keys unchanged; scheduler `current` capacities may carry
  observed units (unit formalization is telemetry design, Node C).

## Validation

- GPU Release build PASS, **CTest 65/65 PASS**.
- Extended `scheduler_test` (window math, expiry, observed ratio, partial
  fallback, adjustment transition, effective capacities) green on both.
- `--version` 0.9.4.3 and `--smoke` PASS on both.

## Future impact
- B3 adds load/VRAM/queue/external-load inputs. B4 smooths transitions.
- Video throughput belongs to C (decode baseline) / E (planner).

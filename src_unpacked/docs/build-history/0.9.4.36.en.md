```text

```

## 1. Why the Change Was Needed

Through v0.9.4.35 the I-2 structure existed only inside the probe. The product
still built the WIC pipeline twice per file:

```text
src/image_verify.cpp:82-83  verifyBuffersFor()
  dec.decode(path, kDim, kDim, f)             <- one pipeline
  dec.decodePreserveAspect(path, kDim, a)     <- one pipeline
```

COM initialization, the factory, `CreateDecoderFromFilename`, `GetFrame(0)`,
the metadata reader, the EXIF orientation source and `GetSize` all ran twice.
Exactly one production path needs both results at once, so the entire
integration benefit lands on this one call site.

## 2. Previous Structure

`decodeWicFile()` and `decodeWicFileAspect()` were two near-identical bodies.
The timing bucket boundaries matched, and only the EXIF query helper was
shared after v0.9.4.35. Callers had to invoke the two APIs sequentially, and
D3 had measured the second decode at 49.60 % of the pair.

## 3. New Structure

### Single source of truth

`decodeWicBranches()` is now the single source of truth called by all three
public entry points:

```text
decodeWicBranches(path, fw, fh, maxDim, wantFixed, wantAspect, f, a, telF, telA)
  CoInitializeEx                once
  WIC factory                   once
  CreateDecoderFromFilename     once
  GetFrame(0)                   once
  EXIF orientation source       once   (reuses exifOrientationToTransform)
  GetSize                       once
  shared IWICBitmapSource
    ├─ scaler -> converter -> CopyPixels -> f
    └─ scaler -> converter -> CopyPixels -> a
  release all COM objects -> CoUninitialize
```

- No intermediate `GrayImage`. Each output uses the same **one-step Fant**
  chain as before.
- `decode()` and `decodePreserveAspect()` keep their signatures, return values
  and semantics. Only their internals moved behind the shared helper, so
  single-output callers (`media_pipeline`, `monitor`) are unaffected.
- `decodeBoth()` is new and reserved for the path that needs both results.
- The EXIF query path is not redesigned; `exifOrientationToTransform` is reused.
- On failure the **unchanged** `decodePgm` / `decodePgmAspect` are called. No
  new fallback was invented, so the failure path stays byte-identical.
- The display (color) lane stays in `decodeWicFileAspectColor`, but it already
  shares the same `exifOrientationToTransform`, so the analysis and display
  lanes cannot diverge in orientation. The UI is not refactored.

### Telemetry Allocation

Each bucket lands in exactly one accumulator so the D3 invariants hold:

```text
shared (COM/factory/open/metadata/orient/GetSize) -> telFixed
fixed branch (scaler/convert/copy)                 -> telFixed
aspect branch (scaler/convert/copy)                -> telAspect
```

Because `mergeDecodeTelemetry` adds the two structs, `totalMs` receives the
wall-clock time exactly once, split:

```text
telFixed.totalMs  = (total elapsed) - (aspect branch elapsed)
telAspect.totalMs = (aspect branch elapsed)
```

Adding the total to both would count it twice and break `decodeSplitOverMs`,
so `decodeWicBranches` returns the aspect branch elapsed time through an
out-parameter. It cannot be negative, but it is clamped to zero rather than
trusted, so the merge cannot be corrupted.

The D1 OS file-open reference probe now runs once per call instead of once per
WIC pipeline. That is the honest consequence of doing the work once;
`osFileOpenProbeCount` drops on the paired path while keeping its meaning ("how
many reference probes were run").

## 4. What This Resolves

The pipeline duplication on the production verify-miss path is gone.
Single-output decode callers behave exactly as before.

### Gate F — performance (production based)

Previous versions measured the probe. This version measures the production
entry point directly. `--production` runs both the baseline and the candidate
per file, so the two medians are compared:

5 runs (CPU Release, 3341 files):

| run | baseline two-call median | production decodeBoth median | aspect branch median |
|---|---|---|---|
| 1 | 0.494900 ms | 0.311400 ms | 0.067800 ms |
| 2 | 0.481800 ms | 0.304900 ms | 0.065400 ms |
| 3 | 0.489500 ms | 0.310400 ms | 0.068600 ms |
| 4 | 0.475500 ms | 0.298900 ms | 0.061200 ms |
| 5 | 0.472400 ms | 0.297200 ms | 0.059400 ms |

```text
baseline median of medians   = 0.481800 ms
candidate median of medians  = 0.304900 ms
absolute delta               = -0.176900 ms
ratio                        = 0.6328  (candidate/baseline)
reduction                    = 36.72 %
```

The candidate is below the baseline in all 5 runs, so this is a real
improvement rather than a difference inside measurement error. Single-output
decode calls are not integration targets and are not included in this figure.

The full-corpus sweep wall clock was 23.45 / 23.97 / 24.12 s. That run executes
the baseline **and** the candidate, so it is not a pure full-scan production
figure and must not be read as one.

**Known limitation**: full scan elapsed was not measured this version as two
separate baseline-build and candidate-build runs. The reduction above is a
decoder-level production measurement. Since `verifyBuffersFor` decodes nothing
on a cache hit, the real full-scan effect scales with the miss ratio.

## 6. Verdict

```text
PRODUCTION ADOPTION = YES
```

All of gates A–F are satisfied. Exactness is byte-identical at 3341/3341, the
exhaustive 5,579,470 pairs are unchanged, EXIF is 8/8, both CPU and GPU test
suites pass, and the production measurement shows a 36.72 % reduction.

## 7. Future Impact

- `verifyBuffersFor` costs less to obtain both results on a decode cache miss.
- Single-output `decode()` / `decodePreserveAspect()` callers are unchanged.
- The I-2 probe is kept as an independent reference and is not deleted.
- I-1 (intermediate GrayImage + two resamples) remains `DEFERRED` and does not
  coexist with I-2.
- I-2 probe measurements are now superseded by production measurements, so
  probe figures are cited only as structural reference.
- D1 `osFileOpenProbeCount` is lower on the paired path than in the previous
  version. That is a result of removing duplication, not a regression.

# MediaSimilarityFinder v0.9.2.37 — UI Feedback Round (In-Settings Language, Group Views, Keyboard Mark)

## Need for change
The v0.9.2.36 UI review raised 4 items. The Language combo sat on the toolbar, the middle pane lacked Explorer-style view switching, the 3-pane splitter sizes were not persisted, and arrow-key + Space marking did not work in the results pane (file pane only).

## Previous structure
- Language combo always visible on the toolbar; settings popup was a single page mixing the language row with monitor items
- Middle group pane = `QTreeWidget` details-only, no checkboxes
- `QSplitter` sizes fixed (no restore)
- Space shortcut = file marking only

## New structure
- Language combo removed from the toolbar. Settings popup split into `QTabWidget` (General/Monitor) with language selection on the **General** tab. Saving applies instantly
- Middle-pane view switcher: **Extra large (256) / Large (128) / Medium (64) / Small (32) icons / List / Details**. Icon/list modes use `QListWidget` (representative thumbnail + group name·file count·similarity%); details keeps the `QTreeWidget`. `QStackedWidget` switching with selection sync, persisted in `QSettings(ui/groupView)`
- Checkboxes on group rows/items (all marked = Checked, partial = PartiallyChecked). Toggling marks every file in the group
- Focus-aware Space: toggles the **whole group mark** when the middle pane has focus, file marks otherwise. Arrow keys use native widget navigation
- `QSplitter` resizable with save/restore (`QSettings(ui/splitter)`). Top-bar compute selectors (preset/CPU·GPU spins/GPU checkbox) unchanged
- Mockups updated: `uimock/mockup-A-ko-grid.html` (view combo + settings popup mock), `mockup-C-en-grid.html` (toolbar language removed + view combo)

## Resolved situation
- No language UI outside Settings. View switching, splitter persistence, and group marking all work
- Version strings unified → 0.9.2.37

## Validation
- Core Release build: PASS, **CTest 36/36 PASS**, `--smoke` exit 0
- Mockups refreshed for browser review. On-machine click/keyboard behavior needs user-side confirmation

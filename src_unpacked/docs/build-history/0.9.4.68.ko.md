# MediaSimilarityFinder v0.9.4.68 — P2 BackendClient + Loopback

기준선 `0.9.4.67` → 본 빌드 `0.9.4.68`.
CPU CTest **114/114**, GPU CTest **115/115** (신규 테스트 없음, 전수 유지).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 검색 의미·동작 변경 없음.

## 1. 변경 필요성

- P1에서 BackendCore 경계와 진입점을 세웠다. P2는 "GUI가 Backend API를
  통해 동작하도록" 바꾸되 동일 프로세스에서 실제 BackendCore를 사용한다
  (Loopback은 fake가 아님).
- P0 인벤토리 19개 접점 중 MainWindow 측이 대상이다.
  `ScanWorker` 클래스 자체는 손대지 않는다.

## 2. 기존 구조

- `MainWindow`가 `QThread`+`ScanWorker`+`MediaMonitor`를 직접 소유.
  matches는 `matchesArrived` 시그널 + `takePending()` pull로 전달.
  tick이 `scanEngine()`/`monitor_->status()`를 직접 읽음.

## 3. 변경 구조

- 신규 `gui/backend_client.h`: command는 fire-and-forget만 (동기 wait API
  없음, G3). tick 값은 push snapshot, 썸네일·detail은 requestId 부여
  Type B. 전 타입 plain value struct (QObject·위젯·native handle 없음).
- 신규 `gui/backend_loopback.*`: QThread+ScanWorker+MediaMonitor 소유.
  worker 시그널을 전달하고, `matchesArrived` 때마다 `takePending()`을
  비워 `matchesBatch` push로 바꾼다. pause() 안에서도 동기 drain되어
  pause-time completeness 유지. `thumbDb_` 등 표현 캐시는 GUI에 그대로.
- `MainWindow`: `worker_/thread_/monitor_` 제거 → `backend_` 1개.
  fileThumb 엔진 분기는 `requestThumb`으로, tick은 snapshot 캐시로,
  monitor는 `startMonitor/stopMonitor/refreshMonitor` + snapshot으로.
  onResults는 `BackendFile` 수신. terminal 전환(finished/failed/results)
  시 loopback이 straggler를 먼저 비운다.
- GUI decode fallback·thumbDb_ persistence·VideoDecoder duration probe는
  동일 프로세스라 그대로 두되 P3 이전 대상으로 기록한다 (G1.3 최종은 P3).
- `testThumbCatchUp()` 등 테스트 hook 불변. 스캔 GUI 테스트 전부 무수정 통과.

## 4. 해결된 상황

- GUI는 `MediaSearchEngine`/`ScanWorker`/`MediaMonitor`를 직접 소유·호출하지
  않는다. 모든 경로는 `BackendClient`를 통한다. 동일 프로세스라 동작은
  이전과 같다. P3는 transport만 교체하면 된다.

## 6. 향후 영향

- P3: 실 spawn + Supervisor + IPC + crash injection. 인터페이스는 그대로,
  Loopback 자리에 IPC client가 들어간다.
- P3 이전 대상 (기록): `thumbDb_` persistence Backend 이동, GUI decode
  fallback 제거, `VideoDecoder` duration probe Backend 요청화.
- P4: hardening + final acceptance.

## 1. 변경 필요성

E-1 은 89.81배 낭비를 측정했지만, sparse seek 의 이득을 **산술로만** 추정하고
스스로 "실측이 아니다"라고 기록했다. E-2A 의 임무는 그것을 측정하는 것이며,
production sampling policy 를 교체하지 않는다.

## 2. E-1 기록의 정정

E-1 은 HEVC/AV1/VP9 를 `NOT_AVAILABLE_IN_CURRENT_ENVIRONMENT` 로 기록했다.
**그것은 생성에 대한 진술이었다.** 이 머신에는 실제 인코딩된 HEVC·AV1 콘텐츠가
존재한다.

```text
원 기록  : HEVC/AV1/VP9 = NOT_AVAILABLE_IN_CURRENT_ENVIRONMENT
원인     : 번들 FFmpeg 9.0.1 에 해당 software ENCODER 없음 (h264_mf 만 동작)
정정     : 생성은 불가하나 실제 인코딩된 콘텐츠는 존재한다. E-2A 가 사용한다.
```

**새로 발견된 별개 제약** — 이것은 생성이 아니라 **디코딩** 제약이다.

```text
AV1 = NOT DECODABLE IN THIS BUILD
  "Your platform doesn't support hardware accelerated AV1 decoding"
  "Error submitting packet to decoder: Function not implemented"
```

`-decoders` 가 `av1` 을 나열하지만 네이티브 구현이 동작하지 않는다.
E-1 은 알 수 없었던 사실이다.

### 6.1 원인

두 전략 모두 제품과 동일한 predicate(`frame_t + 0.05 >= target`, `video_decoder.cpp:127`)를
쓴다. 그런데 그 predicate 는 **target 보다 이틀 수 있는 프레임도 허용**한다.
0.05 s 는 30 fps 에서 프레임 주기 1.5배이므로, 순차 스윕은 target 보다
**한 프레임 앞선** 프레임을 고를 수 있다.

```text
target = 2.0 s, 30 fps
frames ... 1.9667 s, 2.0 s, 2.0333 s ...
1.9667 + 0.05 = 2.0167 >= 2.0   ->  TRUE
```

순차 스윕은 1.9667s 프레임을 고른다. sparse seek 는 target 이전 keyframe 에
 착지하므로 1.9667s 프레임에 도달할 수 없고, 착지점 이후 처음 predicate 를
 만족하는 프레임을 고른다. `tsLater` 가 그 증거다.

**이는 결함이 아니라 전략의 구조적 차이다.** decoder 오류가 아니다.

### 6.2 E-2B 에 대한 의미

sparse seek 는 **빠르지만 현재 sampling 결과를 재현하지 않는다.**
fingerprint 가 달라질 수 있고 매칭 결과가 바뀔 수 있다.
따라서 **drop-in 교체는 불가능**하다. 선택지는:

```text
(a) predicate 를 target 이상으로 좁혀 두 전략을 일치시킨다 (sampling 의미 변경)
(b) sparse seek 는 "다른 샘플"을 허용하는 전략으로 명시하고 정확도 비용을 측정한다
(c) GOP < 샘플 간격 인 조건에서만 sparse seek 를 쓰고 결과를 비교 검증한다
```

**E-2A 는 어느 것도 선택하지 않는다.** 지시 §45 에 따라 실측만 한다.

## 9. Planner 후보 판단 (지시 §46)

threshold 는 확정하지 않는다(지시 §28). 관측된 분류만 기록한다.

```text
Sequential Preferred
  - GOP >= 샘플 간격인 경우. 실측 3건에서 sparse 가 6.4~136.8 % 느렸다.
  - 4K(고 per-frame cost) + 긴 GOP 조합이 특히 위험하다.
  - 실측 근거: gop250, real GOP225, real 4K

Sparse Seek Candidate
  - GOP 가 샘플 간격보다 명확히 작고 wasteRatio 가 큰 경우.
  - 실측 10건에서 35.6~99.0 % 개선.
  - 최대 효과: intra-only(-g 1) 97.2 %, GOP30 270초 99.0 %

Unsupported / Fallback
  - GopUnavailable 또는 GopEstimated 인 파일. 이 경우 sparse seek 후보를
    생성하지 않고 순차로 fallback 한다. 실측 근거: 4K 파일(불일치 11).

Sparse Seek Required Evidence Missing
  - pixel parity 가 깨지는 현재 predicate 하에서는 "같은 결과"를 보장할 수 없다.
  - exactness 해결 없이는 production 채택 불가.
```

## 10. 미해명 / 한계

1. **pixel parity 실패가 해결되지 않았다.** 10/14 파일에서 다른 프레임이
   선택된다. 원인은 §6.1 로 규명했으나 **해결책은 E-2B 몫**이며 여기서는
   선택하지 않는다.
2. **AV1 은 이 빌드에서 디코드 불가**하다. 실제 콘텐츠를 확보했지만 쓸 수 없다.
3. **4K 파일의 GOP 은 `GopEstimated`** 이며 packet key 와 I-frame 이 11건
   어긋난다. 원인은 조사하지 않았다.
4. **실제 콘텐츠는 8편이고 전부 세로/가로 smartphone 계열이다.**
   10분 이상 장편, 다중 오디오 트랙, 10-bit/HDR, VFR 은 dataset 에 없다.
   (VFR 소스 후보는 존재했으나 대표성 판단으로 제외했다.)
5. **반복 수가 1회**로 측정되어 median 이 실질적으로 단일 샘플이다. 추세는
   명확하지만 run-to-run 분산은 충분히 표현되지 않았다.
6. **sampling spacing 96/128/192/256/384/512 exploratory benchmark(지시 §22)**
   는 미실행. production plan 이 쓰는 값이 아니라 별도 탐색 대상이며,
   이번 버전 범위 밖으로 남겼다.
7. `interval = 32` 버킷(>3840초) 실측 없음. 최장 270.5초다.

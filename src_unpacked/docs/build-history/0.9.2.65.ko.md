# MediaSimilarityFinder v0.9.2.65 — 비디오 L1 멀티앵커 + variant dedup 수정

## 변경 필요성
외부 검토(ChatGPT)가 구조적 결함으로 지목했고 코드 대조로 확정: (1) 동영상 전체 프레임 해시를 XOR 64비트 하나로 축약해 후보 단계에서 재인코딩 유사 영상이 탈락, (2) `CandidateIndex`가 거리 검사 전에 그룹을 seen 처리해 미러/크롭 변형 매치가 누락. "3시간 0건"의 직접 원인이다.

## 기존 구조
- `MediaFile.fingerprint` 단일 XOR → `videoIdx_` 1엔트리. 재인코딩으로 XOR이 벌어지면 후보 자체가 없음
- `forEachCandidatePair`가 실패 변형에서도 그룹 seen → 같은 버킷의 통과 변형 스킵
- 크롭 시드도 거리 무관하게 전부 삽입 → 크롭 전용 쌍을 crop 단계에서 제외

## 변경 구조
- **프레임 앵커**: `MediaFile.anchors`(캐시 읽기 전용 `loadPersistent`, 디코드 없음, 16개 stride 상한). 스캔 시 `files_` 구성 단계에서 부착, `analyze()`가 `videoIdx_`에 동일 index로 추가 등록. 판정은 기존 `best()`+temporal 그대로라 오탐 구조 불변
- **앵커 게이트**: `best()` 미달 시 앵커-앵커 최대 유사도가 trigger 이상이면 temporal 검증 수행. temporal이 threshold를 통과해야만 매치이므로 검증기 권한은 그대로
- **dedup 순서 수정**: 거리 통과 후 mark (실패 시 미표시). 시드 삽입도 거리 통과분만. 동일 쌍 재평가는 `best()` 결정성상 무의미하므로 제거해도 verdict 동일
- 자잘 정리: 미사용 `ScanCancelled` 헤더 제거, `saveMatches` 주석 union 의미로 정정, 데드 멤버 3개(`matches_`, `lastDone_`, `lastTotal_`) 제거
- 버전 표기 통일 → 0.9.2.65

## 해결된 상황
- 재인코딩 쌍: 앵커 충돌로 후보 enumeration → 앵커 게이트로 temporal → temporal 통과 시 매치. XOR 게이트 단독 탈락 해소
- 미러 변형: 실패 변형이 그룹 마킹을 막지 못함. 음성대조(수정 전 exit 30 → 수정 후 통과)로 증명
- 크롭 전용 쌍: 시드 과다삽입 해소로 crop 단계에서 정상 평가

- 캐시 미스 비디오는 앵커 없이 XOR 전용으로 graceful degradation. 캐시 버전 상향 시 전체 재빌드로 앵커 복원
- 앵커 16 상한·1024 폴링 간격은 튜닝 가능

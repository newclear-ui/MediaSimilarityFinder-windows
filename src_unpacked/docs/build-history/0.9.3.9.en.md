# MediaSimilarityFinder v0.9.3.9 — Search Freshness, Video Fingerprint, Benchmark, and Monitor Hardening

## Need for change
- Review of v0.9.3.8 found size/mtime-only incremental detection, retained stale matches, XOR-zero video rejection, a long-video duration gate, and an incorrect GUI streaming benchmark pair count.
- Monitor startup failure, ignored GPU configuration, and FIFO deferral could also diverge from actual state or expected processing order.

## Previous structure
- File quickHash was stored in the database but not used for change detection.
- Old matches involving changed or deleted files survived revalidation.
- Video frame hashes were aggregated with XOR and a zero result was treated as failure.
- Temporal candidates were blocked when the duration ratio exceeded 4, even when anchors existed.
- Benchmark `matches.pairs` used the retained report-vector size, which is intentionally empty in GUI streaming mode.

## New structure
- Incremental change detection now includes `quickHash`.
- Previous matches for missing/changed files are removed during revalidation and can be recreated by the next scan.
- Video aggregation uses a non-reversible fold; sampling generation is 3 and engine verdict version is 1.2.0.
- A strong frame-anchor match can admit a candidate to temporal verification despite the duration ratio gate.
- Benchmark separates streamed match count from retained pair count.
- Monitor applies the GPU setting to its policy, reports comparison-index open failure from `start()`, and uses a due-time priority queue.
- GUI scan failure drains streamed matches into the current view and equal-score groups receive deterministic ordering.

## Resolved situation
- Replaced files with preserved size and timestamp are less likely to reuse stale fingerprints.
- Valid videos are not rejected solely because their aggregate equals zero.
- Anchored subclip candidates can reach temporal verification.
- GUI streaming benchmark pair counts reflect actual streamed matches.

## Validation
- Release compilation: PASS.
- The first CTest run failed only because `match_revalidate_test` expected the old engine version; the test was updated to 1.2.0.
- Full CTest: **59/59 PASS**, Portable smoke: exit 0.
- Large real-video subclip Recall/Precision and cold/warm benchmark values have not yet been measured.

## Future impact
- The video fingerprint change causes existing videos to be reanalyzed at sampling generation 3.
- A labeled Ground Truth corpus, cold/warm repetitions, and H2D/kernel/sync/D2H GPU timing remain follow-up Benchmark Engine work.

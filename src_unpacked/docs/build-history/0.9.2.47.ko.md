# MediaSimilarityFinder v0.9.2.47 — 중단해도 저장되는 스캔 (체크포인트)

## 변경 필요성
중단(취소)된 스캔은 트랜잭션 롤백으로 파일 목록까지 전부 버려졌다. 대용량 폴더에서 수 시간 작업이 한 번의 중단으로 증발하는 구조라, 중단해도 로그 인덱스(특히 파일 이름 목록)가 남도록 변경이 요청됐다. 삭제된 파일의 정리와 추가·삭제 업데이트 규칙도 함께 정의했다.

## 기존 구조
스캔 전체가 단일 트랜잭션. 취소/실패 시 전체 롤백, `SearchReport`에 완료 여부 없음. 분석 안 된 파일은 DB에 행 자체가 없었음.

## 변경 구조
- 체크포인트 커밋: 분석 500개마다 + 워킹 1000개마다 커밋 후 새 트랜잭션. 중단·크래시해도 마지막 체크포인트까지 보존
- 파일 목록 선기록: changed 파일은 분석 전 스켈레톤 행(fingerprint=0)으로 먼저 upsert. 매칭·후보 인덱스는 fp==0 행을 이미 제외하므로(기존 가드 확인) 결과 오염 없음. fp==0 + 동일 스탬프는 다음 스캔에서 분석 대상으로 판정 → 크래시 후 재개 보장
- 삭제 정리는 워킹이 완전히 끝난 스캔에서만 수행 (seen 집합이 완전할 때). 무시된 행은 유지
- 취소/실패 시: 열린 청크를 커밋하고 `completed=false` 부분 리포트 반환 (이전 전체 롤백과 반대). DB 오류 시에도 확정 청크는 유지
- `SearchReport::completed` 신설. GUI 취소 메시지에 스캔/분석 카운트 표시 ("부분 저장됨")
- `scan_cancel_test` 추가 → 총 40종. 취소 후 completed=false + DB 행 잔존 + 전체 재스캔 완료를 검증 (구동작에서는 롤백으로 실패)

## 해결된 상황
- 중단해도 파일 목록+체크포인트가 남고, 다음 스캔이 이어서 완성. 삭제 정리는 완전 스캔에서만이라 부분 상태에서 지워지는 일 없음

## 검증
- Core Release 빌드 PASS, **CTest 40/40 PASS** (신규 `scan_cancel_test` 포함)
- 기존 스캔 경로 테스트 전부 녹색 = 카운터·매칭 의미 보존. `--smoke` exit 0, `--version` 0.9.2.47
- 디버깅 교훈: 체크포인트의 재-BEGIN이 마지막에 열린 트랜잭션으로 남아 다음 스캔의 BEGIN을 실패시키고 빈 리포트를 반환했다. 최종 커밋으로 닫는 구조로 수정 후 재스캔 정상화 (스캔2: scanned=2 analyzed=0 unchanged=2). 미발견 시 "검색이 전혀 안 된다"는 증상으로 보였을 것

## 향후 영향
- 취소 의미 변경(전체 취소→부분 저장)을 릴리스 노트에 명시. `completed` 플래그로 호출자 구분
- 체크포인트 간격(500/1000)은 상수. 디스크가 느린 환경에서 커밋 비용이 체감되면 조정 (WAL 기준 수십 ms 수준)
- ETA 표시는 다음 후보: 체크포인트 통계를 이용해 남은 분석량 추정 가능

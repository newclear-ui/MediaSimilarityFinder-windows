# MediaSimilarityFinder v0.9.4.84 — 라이브 "인덱스 완료" 카운터 수정 (match 비의존)

기준선 `0.9.4.83` → 본 빌드 `0.9.4.84`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 판정·스키마·디코드 변경 없음.

## 1. 변경 필요성

사용자 보고(0.9.4.83 후속): 인덱스가 완성된 폴더에서 "검색 업데이트"를 누르면
**"인덱스 완료"가 0에 머문다.** (0.9.4.83의 인덱스 우선 표시로 유사/중복 그룹은
스캔 시작 직후 표시되지만, 라이브 카운터는 여전히 문제였다.)

원인(코드 확정):
- GUI의 "인덱스 완료"는 `backendStatus_.analyzed + .unchanged`이고, 이 값은
  `kStatus` 이벤트로만 온다.
- `kStatus`를 보내는 `BackendSession::pushStatusSnapshot()`은
  **`onMatchesArrived()`에서만** 호출된다(`src/backend_session.cpp`).
- 변경 파일이 없어 **새 match가 스트리밍되지 않는 증분 재스캔**에서는
  `matchesArrived`가 발생하지 않아 `analyzed`/`unchanged`가 0에 머문다.
- 또한 완료 후 `MainWindow::refreshSummary()`는 "인덱스 완료"를 `analyzed`만으로
  표시하므로, 전부 unchanged인 재스캔은 완료 후에도 0으로 보인다.

## 2. 기존 구조

- `pushStatusSnapshot()`: match 도착 시에만 호출 → 카운터가 match 스트림에 종속.
- `refreshSummary()`: `sumValIndexed_ = lastStats_[1]` (= analyzed)만 표시.

## 3. 변경 구조

- **`BackendSession`에 500ms `QTimer`(`statusTimer_`) 추가**: `startScan`에서 시작,
  `onFinished`/`onFailed`/`teardownWorker`에서 정지. 타임아웃마다
  `pushStatusSnapshot()`을 호출해 `analyzed`/`unchanged`/`gpu` 카운터를 **match와
  무관하게** 주기적으로 GUI에 push한다. 카운터는 엔진의 atomic이라 동시 관찰 안전.
- **`refreshSummary()`**: "인덱스 완료" = `analyzed + unchanged`(인덱스 행을 보유한
  파일 수)로 변경. 라이브 공식(`updateStatusCounts`)과 일치시켜, 전부 unchanged인
  재스캔도 완료 후 전체 인덱스 수를 표시한다.

## 4. 해결된 상황

- 인덱스된 폴더를 재스캔할 때, 새 match가 없어도 "인덱스 완료"가 진행 중 갱신된다.
- 완료 후 "인덱스 완료"가 0이 아니라 인덱스된 파일 수를 표시한다.

## 6. 향후 영향 및 한계

- "읽기 완료"는 `walkedCount`(엔진 `readProgress`)가 담당하며 이번 변경과 별개다.
  만약 재스캔에서 "읽기 완료"가 계속 0이면 walk 이전 단계(count prepass /
  `revalidateMatches` 엔진버전 게이트)에 머무는 구간일 수 있으므로,
  `msf_scan.log`의 `scanPhase=count begin/done`·heartbeat(`walked=`)로 구간을
  확인해야 한다(추가 진단 대상).
- 엔진 판정·스키마·캐시 불변.

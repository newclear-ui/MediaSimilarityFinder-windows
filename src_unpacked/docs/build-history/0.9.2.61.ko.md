# MediaSimilarityFinder v0.9.2.61 — 미리보기 크기 균일화 + 셸 레인 확대

## 변경 필요성
목록은 표시되나 미리보기 크기가 일정하지 않았다(같은 보기 모드에서 작은 썸네일과 거대 아이콘 혼재, 우측 파일 리스트도 마찬가지). 렌더 프로브로 확정: 동일 IconMode 뷰에서 원본 픽스맵 크기에 따라 셀이 90x91~262x283으로 제각각이었다. 셀은 소스를 따라가므로, 소스를 통일하지 않으면 균일화가 불가능하다.

## 기존 구조
- `fileThumb(rep, 64x64)` 고정 요청 + 캐시 키 경로 단일. 64px·160px·셸 가변 크기 픽스맵이 한 뷰에 혼재
- 디코드 예산 단일 4/틱. 셸 COM(약 1~3ms)과 FFmpeg 수백ms가 같은 예산을 써서 셸 캐시분마저 느리게 충전

## 변경 구조
- **정사각형 정규화**(`squareFittedPixmap`, 투명 패딩·무왜곡): 모든 표시 아이콘을 요청 크기로 정확히 맞춤. 렌더 프로브에서 전 셀 262x283 균일 확인. `thumb_layout_test`로 영구 보장(정확한 크기·중심 색·투명 패딩·무왜곡)
- **뷰 크기 요청**: `fillPair`가 `grid->iconSize()` 전달(XL은 256 선명, M은 64 경량). 캐시 키에 크기 포함(`path|WxH`), 제거 시 변형까지 함께 삭제(`dropThumbCache`)
- **예산 분리**: 셸 레인 24/틱 + 헤비 디코드 4/틱. 셸 히트분 충전이 약 10배 빨라지고, 무거운 디코드는 상한 유지. 일시정지·중지 응답성 유지
- 버전 표기 통일 → 0.9.2.61

## 해결된 상황
- 아주 큰/큰 아이콘과 우측 파일 리스트에서 균일한 셀. 탐색기식 균일 타일과 같은 외관
- 셸 썸네일 우선 + 미스 시 자체 생성 순서는 그대로(기존 동작), 충전만 빨라짐

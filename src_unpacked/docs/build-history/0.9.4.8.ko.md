# MediaSimilarityFinder v0.9.4.8 — Execution Binding + Node B7 Gate

외부 Node B 리뷰(v0.9.4.7 기준)의 핵심 지적을 반영하고 B7 최종
게이트를 닫는다. 엔진 1.5.0·DB 1.0.3·캐시 v9·schema 1 불변.

## 변경 필요성
- 리뷰가Verified: `schedUseGpu` const가 스캔 시작 판단을 고정시켰다.
  재평가는 shares를 갱신했지만 실행은 초기값을 계속 썼다. mid-scan
  flip 시 telemetry와 실제 실행이 어긋날 수 있다.

## 기존 구조
- `decide()` 1회 → `const bool schedUseGpu` → 이미지/비디오 게이트가
  스캔 내내 같은 값 사용.

## 변경 구조
- `schedUseGpuNow()` 람다(현재 발표 판단 읽기)로 교체. 이미지 배치는
  재평가 직후 fresh read, 비디오 구간도 구간 진입 시 1회 fresh read 후
  async 람다에 값 캡처. stale const 삭제(grep 검증).
- B4 hold + B6 kill-band를 통과한 발표만 바뀌므로 실행이 요동치지
  않는다. 2초 미만 스캔은 재평가 미발화로 기존과 바이트 동일.
- `scan_streaming_test`에 엔진 수준 scheduler 기록 단언 추가
  (`scheduler.measured` + `selectedBackend`, 제품 변경 없음).
- B7 커버리지 감사 결과:
  - 기능(OFF/ON/fallback/모드/Manual) — 기존 스위트 + scheduler_test로
    커버. 저사양 실기·부하 중 Gaming의 엔진 수준 실행은 결정론적
    재현 불가라 단위 + parity로 대체(명시).
  - 안정성(hold/밴드/장시간) — 단위 합성 틱으로 커버. wall-clock 장기
    테스트는 CTest에 부적합이라 미실시(명시).
  - 정확성 — 양쪽 parity 스위트.
  - 성능 — benchmark JSON에 wall/filesPerSec 기록, 비교 게이트는
    환경 의존이라 미설정(명시). `video_gpu_benchmark_test` 존재.
  - 관측성 — scheduler 섹션 실측 + 스트리밍 테스트 단언.

## 선택 이유
- D 선행 없이 B 안에서 닫힌다. worker/queue/barrier는 그대로다.
- binding은 읽기 위치 3곳의 문제라 더 작은 수정은 없다.

# MediaSimilarityFinder v0.9.3.7 — 엔진 조회 버짓 제외 + 비디오 단위 수정

## 변경 필요성
- v0.9.3.5의 P0(엔진 산출물 재사용)에도 첫 행만 썸네일이 떴다. 스크린샷: 902개 그룹 중
  첫 행 4개만 실썸네일, 나머지는 파일 아이콘. 우측 상세창(버짓 우회)은 정상이라
  디코더·파일 문제가 아님을 확정했다.
- 결정적 원인: 무료인 엔진 조회가 유료인 디코드 버짓 게이트 뒤에 있었다.
  한 틱에 미캐시 행 4개가 버짓을 소진하면 이후 행은 엔진 LRU 적중 여부와 무관하게
  플레이스홀더로 잘렸다. 틱당 4개 행진이라 첫 행에서 멈춘 것처럼 보였다.
- 부수 확정: 비디오 조회가 단위 불일치로 항상 미스였다. GUI는 1970년 기점 밀리초,
  엔진 캐시는 1601년 기점 100ns 틱을 쓴다.

## 기존 구조
- `fileThumb` 순서: 캐시→디스크→실패 skip→버짓 게이트→엔진→셸→헤비 디코드.
- 비디오 조회에 호출자가 size/mtime을 전달.

## 변경 구조
- 엔진 조회를 버짓 게이트 앞으로 이동했다. 적중은 버짓을 전혀 쓰지 않는다.
- 비디오 조회는 경로 단일 키로 변경하고 엔진이 직접 stat한다. 단위 불일치 원천 제거.
- 컬러 LRU를 512→2048항목으로 상향했다. 정렬 선두(가시 영역)가 오래된 순으로
  먼저 쫓겨나던 문제를 완화한다.
- 버전 표기 통일 → 0.9.3.7.

## 해결된 상황
- 스캔된 파일은 행 위치와 무관하게 엔진 적중 즉시 표시된다. LRU 밖·미스캔분은
  기존 버짓 점진 채움으로 처리된다.

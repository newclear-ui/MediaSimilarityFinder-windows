# MediaSimilarityFinder v0.9.4.81 — Selectable matching-verification mode + B 1000-slice

Baseline `0.9.4.80` → this build `0.9.4.81`.

`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged (intended). Verdicts (thresholds, SSIM,
temporal) are identical across all three modes.

## 1. Why the change was needed

- Beyond 10k-100k files, post-processing (candidate-pair verification) takes too
  long. The user must be able to choose when/in what units verification runs and
  compare the choices in a final test.
- Verification ran as one block, so a stop/crash lost all progress and the
  progress signal was coarse. It must run in **1000-file slices** so progress,
  checkpointing and resume are possible.

## 2. Previous structure

- One global `analyze()` after the scan verified every pair at once, with no
  mid-pass progress or checkpoint. The active mode was not recorded.

## 3. Changed structure

**(A) Settings option "Matching verification"** (Settings → General, QSettings
`ui/analyzeMode`):
1. **Stable (verify after scan)** = `B` (default) — post-scan global pass.
2. **Fast (verify during scan)** = `A` — restrict the final verification to pairs
   touching a file changed this scan.
3. **Auto (hybrid)** = `A+B` — like A, plus image pairs where BOTH sides changed
   are dropped because the live streaming pass already emitted them.
- New `src/analyze_mode.h` (`msf::AnalyzeMode`, `analyzeModeKey` = `B`/`A`/`AB`).

**(B) B 1000-slice + resume frontier** (`ScanPipeline::analyze` extension):
- The image (phase 0) / video (phase 1) / crop (phase 2) verification passes run
  in **group-boundary windows of 1000 files**, invoking
  `onSlice(phase, done, total)` after each window and honoring stop between
  windows.
- A video window calls `flushVideo()` so temporal decode happens immediately
  (real progress + responsive stop).
- Each window checkpoints the accumulated match set (via the worker), and the
  image full phase (0) writes a **resume frontier** to DB meta `analyze_frontier`.
- Frontier key = `engineVersion|maxDistance|fileCount|fileSetHash`. It is honored
  only when the same file set is re-scanned, and a completed scan clears it (a
  normal rescan still does the full pass).
- Wiring: GUI settings → `BackendScanConfig.analyzeMode` → `START_SCAN` →
  `BackendSession` → `ScanWorker::setAnalyzeMode` → `ScanControl.analyzeMode` →
  `scan`. Checkpoint runs through `ScanControl.analyzeCheckpoint` (worker thread).

**(C) Log identity**: `scanAnalyzeMode=<B|A|AB>` at scan start, `analyzeSlice
phase=<0|1|2> <done>/<total>` per slice, `analyzeResume fromGroups=<n>` on resume,
plus `analyze.mode` in the detailed-log JSON. Message shapes unchanged.

## 4. Resolved state

- The user can pick any scheme; a final test distinguishes them from
  `scanAnalyzeMode=`/`analyze.mode` alone.
- B splits verification into 1000-file slices: reports progress, checkpoints each
  window, and resumes from the last checkpointed window after a stop/crash.
- A/AB re-verify only pairs touching a changed file, cutting incremental work.

- Parity: slicing/filtering do not change verdict code; the sliced pass is pinned
  to produce the same pair set as the unsliced pass.
- Schema: `analyze.mode` is additive, so `kBenchmarkSchemaVersion` stays **9**.

## 6. Future impact and limits (explicit)

- **The resume frontier covers the image full phase (0) only.** Video/crop windows
  checkpoint but re-verify from the start on resume (correct, just not skipped).
- **A/AB incremental correctness depends on the persisted match set**:
  unchanged-vs-unchanged pairs trust the pairs a prior completed scan saved
  (`revalidateMatches` re-checks after an engine bump). Cold and completed
  incremental scans match B.
- AB's "skip both-changed images" applies only when the live streaming pass ran
  (`liveMatch` guard).
- Video verification is now split into windows, so the `videoRange` telemetry
  count can differ (verdict unchanged).
- Next candidates: extend the frontier to video/crop, A/AB summary-count
  reconciliation, real large-dataset measurement.

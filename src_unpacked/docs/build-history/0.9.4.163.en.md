Baseline `0.9.4.162` → this build `0.9.4.163`.
CPU CTest **134/134**, GPU CTest **135/135** (no new executables; sweep sections added to `video_gpu_benchmark_test`).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` all unchanged.

## 1. Why the change was needed

- External review P2: GPU batch size and CPU/GPU crossover cost must be set from measurement. The switch threshold (`map.size()>=8`) and pHash chunk size (256) were chosen without measured evidence.

## 2. Previous structure

- MSSIM: gated pairs ≥8 go to `ssimBatch`, fewer fall back to CPU `frame_ssim`.
- pHash: `hashBatch` in `recommendedBatchSize(256)` chunks. `processVideoFrames` already trims to kept targets (≤16), so chunking almost never triggers in real scans.

## 3. New structure

- No product-code change. Measurement sections in `video_gpu_benchmark_test`:
  - SSIM sweep: per-pair GPU vs CPU cost at batches 1/2/4/8/16/32/64/128 + agreement within 1e-6 at every size (failure otherwise).
  - pHash chunk sweep: same 1024 frames at chunks 64/128/256/512/1024 with bit-exactness assertion.

## 5. Resolved state and verdicts

- **SSIM gate stays at 8 (change NOT ACCEPTED).** The crossover sits at 32–64, but real per-row gated pairs are capped by kept targets (≤16), so 64+ effectively never occurs. Moving the gate would save only a slice of match-stage MSSIM (~0.1% of a scan) while forcing, per AGENTS.md 5, an engine patch bump → one-time full stored-pair re-verification (minutes to hours). Net loss. Revisit if `.162`'s `videoMatchGpuMs/CpuMs/Submitted/Completed` shows a different distribution in field logs.
- **pHash chunk stays at 256 (nothing to change).** Real-scan packing fits one chunk under the kept cap regardless of the value. The sweep stays as backend characterization + exactness pin.
- Both thresholds stand as measured cases of the P2 principle "don't touch without evidence".

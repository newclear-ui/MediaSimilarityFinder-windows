# MediaSimilarityFinder v0.9.4.78 — 스캔 추적·워치독·비디오 취소·supervisor 확정

기준선 `0.9.4.77` → 본 빌드 `0.9.4.78`.
CPU CTest **120/120**, GPU CTest **121/121**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 엔진·판정 불변. DB는 `file_trace` 추가 테이블만 생긴다.

## 1. 변경 필요성

실측 `backend lost` 2건(07:53:17, 07:54:15)을 로그·이벤트와 대조한 결과,
크래시가 아니라 supervisor 워치독의 오진이었다.

- 07:53:17은 analyze 매치 burst 와중(같은 초에 groups 0→8852)에 health가
  10초 넘게 끊겨 멀쩡한 backend를 kill했다. Backend 송신은 메인 스레드 동기
  `flush`이고 health도 같은 스레드라, MATCHES 홍수 + GUI 9천 위젯 재구축이
  겹치면 health가 굶는다. 예전에 미확정으로 남긴 stdout backpressure 가설이
  이번에 로그로 확정됐다.
- 07:54:15는 갓 뜬 지 15초 된 backend를 startup flood
  (8894 그룹 quick-load + walk 시작) 와중에 또 죽였다.
- 이후 stale escTimer가 재기동 2초 만에 새 backend를 kill했고,
  `spawn()`이 `escStage_`를 리셋하지 않아 무한 FAILED 루프(3초 간격,
  40분 이상)가 돌았다. 08:00 이후 Event 1000이 없어 AV는 없었다.

## 2. 기존 구조

- 파일 추적은 admission 스켈레톤(`files` 행)까지만 있었고 시간 정보가 없었다.
- 워치독은 supervisor health 타임아웃 단일 발(10초)뿐이라 burst에 오진했다.
- `VideoFingerprintEngine::build()`는 cancel을 받지 않아 Stop이 mid-sweep에
  먹지 않았다.
- `spawn()`은 에스컬레이션 상태를 리셋하지 않았고, `enterFailed`는 wedged
  프로세스 앞에서 terminate를 반복해 로그만 spam했다.

## 3. 변경 구조

- **추적 테이블** — 신규 `file_trace(path, admitted/started/finished_ms,
  outcome)`. admission·시작·완료를 같은 트랜잭션에 함께 기록한다.
  outcome은 `analyzed`·`failed`·`skipped-unchanged`·`ignored`.
  finished가 비면 미확인(죽음/정체)이다. DB 1.0.4→1.0.5 (additive table).
- **저속 파일 로그** — 30초 초과 파일은 `slowFile kind/path/admitted/started/
  finished/elapsed/outcome`을 `msf_scan.log`에 남긴다. 실패는 항상 기록.
- **워치독** — 순수 판정 유닛 `StallWatchdog`: 10분 무완료면 진단 로그(phase·
  큐·walker·현재 배치/range 내용). 이미지 배치 정체 2연속 때만 자동 cancel.
  비디오·analyze는 진단만 한다 (정당한 장시간 작업을 죽이지 않기 위해).
  producer 정체(빈 큐 + walker 생존 + admission 무진행)는 별도 walker snapshot.
- **비디오 취소** — `build()`·`framesAt`·`framesAt96Plus32`에 cooperative
  cancel 전달. 프레임 경계에서 멈춘다.
- **Supervisor** — spawn 시 에스컬레이션 리셋. kill 실패 latch 후에는
  terminate 재시도 금지 + 수동 kill 안내. 살아있는 backend 위로 재기동 금지.
  health 3연속 미스 룰 (버스트 1회는 살려준다).

## 4. 해결된 상황

- 죽기 전 파일들의 admitted/started/finished가 DB에 남는다. 다음 죽음부터는
  poison 후보를 경로 목록으로 좁힐 수 있다.
- 정체 10분이 지나면 현재 배치/range 내용이 로그에 남는다 (재현 가능).
- Stop이 비디오 sweep 중간에 먹는다.
- health 오진으로 멀쩡한 backend를 죽이지 않는다 (30초 룰).
- kill 불가 backend 앞에서 무한 FAILED 루프를 돌지 않는다.

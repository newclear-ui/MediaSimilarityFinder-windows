# MediaSimilarityFinder v0.9.4.62 — 크래시 대응 3종 (덤프 안내·방어·관측)

기준선 `0.9.4.61` → 본 빌드 `0.9.4.62`.
CPU CTest **110/110**, GPU CTest **111/111** (기존 109/110 + 신규 1).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 제품 VERSION만 bump.

## 1. 변경 필요성

대규모 스캔 중 0xC0000409 fail-fast 강제종료가 2회 연속 발생했으나 제품에
남은 기록이 없었다. `ScanWorker::run`은 `std::exception`만 잡았고, Qt
메시지는 어디에도 저장되지 않았으며, heartbeat는 walk/count 단계를
구분하지 못했다.

## 2. 기존 구조

- worker catch는 `std::exception`만. 비표준 예외는 프로세스 종료
- Qt 메시지 핸들러 미설치 (0.9.2.48 문서의 debug 전용 제안만 존재)
- heartbeat `alive ... lastPct lastPath groups marked` — 열거 단계가 안 보임

## 3. 변경 구조

1. **덤프 수집 안내 (코드 없음)**: WER LocalDumps 레지스트리 설정으로 다음
   발생 시 스레드·스택 확보. 재현·분석 절차의 일부
2. **방어**: `ScanWorker::run`에 catch-all 추가. 부분 매치 checkpoint 후
   `failed` 보고로 전환하여 기록된 실패로 격하. MSVC 기본 `/EHsc`에서는
   SEH 액세스 위반은 catch(...)를 통과하지 않으므로 실제 메모리 손상은
   계속 fail-fast (마스킹 없음). 테스트용 `MSF_TEST_THROW_NONSTD` seam
   포함 (제품 코드는 설정하지 않음)
3. **관측**: `installQtMessageLog()` — Qt 메시지 파일 싱크. 메시지별
   open/append/close + mutex라 크래시 안전·스레드 안전. fatal은 기록 후
   Qt가 기존대로 abort (fail-fast 유지). main()의 3개 경로(GUI/headless/
   benchmark)에 설치. heartbeat에 `walked`/`listed` 추가 — 재스캔 초반
   0%가 저속 열거인지 hang인지 구분 가능

## 4. 해결된 상황

- 비표준 예외는 더 이상 무기록 종료가 아니라 checkpoint + failed 보고
- Qt fatal/warning/critical은 `%TEMP%\msf_qt.log`에 최종 기록이 남음
- heartbeat으로 열거 단계 진행 확인 가능

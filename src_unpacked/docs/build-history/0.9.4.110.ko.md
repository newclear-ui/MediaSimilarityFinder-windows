## 1. 변경 필요성

사용자 보고: 리스트/자세히/타일 등으로 보다가 다시 아주 크게/크게/보통/작게 아이콘 모드로 돌아오면 **마우스 휠 스크롤이 매우 느려진다** — "리스트 보기의 휠 속도에서 아이콘 보기의 속도로 돌아오지 못하는 것 같다". 한 번 리스트를 거치면 앱을 재시작하기 전까지 아이콘 모드 전체에서 지속된다.

## 2. 기존 구조 (Qt itemview 스크롤 step 메커니즘)

- 휠 1노치의 스크롤량 = scrollbar `singleStep() × wheelScrollLines(기본 3)`. 앱 코드는 스크롤 모드/singleStep을 전혀 설정하지 않으므로 Qt 기본 동작이 그대로 쓰인다.
- Qt 6.11 itemview는 스크롤바 step을 **자동 관리**한다: `QAbstractItemViewPrivate`의 `viewMayChangeSingleStep`(초기 true)이 켜져 있는 동안, 뷰가 `itemviewChangeSingleStep(...)`으로 모드에 맞는 step을 밀어 넣는다.
  - **아이콘 모드**(`QCommonListViewBase::updateVerticalScrollBar`): `itemviewChangeSingleStep(셀 높이 + spacing)` — 1노치 = 1셀.
  - **리스트 모드**(`QListModeViewBase::updateVerticalScrollBar`, ScrollPerItem·TopToBottom·비래핑): **public** `verticalScrollBar()->setSingleStep(1)` — 항목 단위 스크롤.
- **결함 메커니즘**: `QAbstractSlider::setSingleStep(step)`은 `viewMayChangeSingleStep = (step < 0)`으로 **잠근다**. 따라서 리스트 모드의 `setSingleStep(1)` 이후 아이콘 모드의 자동 step 갱신은 전부 무시되고, scrollbar step은 1에 머문다. `singleStep(-1)`만이 자동 관리를 다시 허용한다.
- 실측(회귀 테스트, 수정 전): XL 아이콘 모드 step=**175**(256px 아이콘 셀), List 방문 후 다시 XL로 복귀해도 step=**1** — 휠 1노치가 3px. 사용자 보고와 정확히 일치.

## 3. 변경 구조

- **`groupViewChanged()`**(gui/mainwindow.cpp): delegate/크기 교체 직후, 기존 `doItemsLayout()` 직전에 그리드 스크롤바 두 개에 `setSingleStep(-1)`을 호출한다.
  - `-1`은 자동 step 관리를 재허용하고, 이전에 뷰가 밀어 둔 `singleStepFromItemView` 값을 즉시 재적용한다.
  - 이어지는 `doItemsLayout()` → `updateGeometries()`가 **현재 선택된 모드의** step을 다시 밀어 넣는다(아이콘 모드=셀 크기, 리스트 모드=항목 단위 1 — 리스트 모드 자체 동작은 불변).
- **테스트**: `ui_scroll_regression_test` phase 22 — XL→List→XL 왕복에서 `verticalScrollBar()->singleStep()`이 아이콘 모드 값으로 복원되는지 검증. 수정 전 `xl=175 list=1 back=1` **FAIL** 재현, 수정 후 `back=175` PASS(checks=88).

## 4. 해결된 상황

- 리스트/자세히/타일을 거친 뒤 어떤 아이콘 모드로 돌아와도 휠 1노치 = 1셀(모드별 정상 속도)로 즉시 복원된다. 앱 재시작 없이 모든 전환에서 유지된다(전환마다 `-1` 재적용).
- 리스트 모드 자체의 휠(3항목/노치)과 트리(자세히) 모드는 종전과 동일하다. 스크롤 위치·선택·캐치업 계약(0.9.4.61)·아이콘 재적용(0.9.4.109) 불변.

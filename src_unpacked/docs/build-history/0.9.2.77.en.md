# MediaSimilarityFinder v0.9.2.77 — Button Style Unification + Detail/Grid Intrusion Fixes

## Need for change
Screenshot feedback: (1) ☰ and Photos+Videos buttons' bottom arrows look alien next to combos, (2) the fixed 430 detail width blocks the splitter — the ask was stability against text-length jumps, not a fixed size, (3) right-pane text invades neighbor photo cells, (4) broken filename/path display in details, (5) unexplained "619: 116" footer.

## Previous structure
- QToolButton InstantPopup: text "▾" plus its own drawn arrow, doubled
- Right detail pane capped at 430. Filename/path labels grew without bound
- Right grid spacing 10, heterogeneous cell sizes. Footer used terse "N: M"

## New structure
- **Unified arrows**: kindBtn_ and utilBtn_ → MenuButtonPopup (combo-style side arrow) with click-to-open wiring
- **Splitter free again**: 430 cap removed. Filename/path labels use word-wrap + horizontal Ignored policy, wrapping inside allotted width (removes the jumps at the source)
- **Right grid**: spacing 10→2, uniform item sizes (single layout pass, long/short names align). Elision stays icon-width based
- **Detail display**: filename wraps with tooltip, path shows the folder only (no filename repeat)
- **groupFoot_**: new `updateGroupFoot()` — explicit "Total 619 · Selected 116" (3 call sites unified)
- Version strings unified → 0.9.2.77

## Resolved situation
- Buttons (preset/view/kind/menu) share one language. Splitter moves freely with width-stable text. Rows align, footer readable

## Validation
- Core+GUI Release build: PASS, **CTest 55/55 PASS**
- `--version` 0.9.2.77, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)
- Two self-fixes during build: member lambda captures (`[this]`), duplicate declaration from an edit round-trip

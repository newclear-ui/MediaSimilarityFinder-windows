# MediaSimilarityFinder v0.9.4.121 — 상세 정보창 폭주 수정 (유사도 라벨 래핑 + 값 행 규율 + 파일 썸네일 재시도)

기준선 `0.9.4.120` → 본 빌드 `0.9.4.121`.
CPU CTest **124/124**, GPU CTest **125/125** (신규 `detail_layout_probe` 포함).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 실기(0.9.4.120, 그룹 280) 3건:

1. 하이라이트된 파일 선택 시 상세정보 창이 텍스트 길이와 무관하게 넓어지고, 세로 스플리터바로 우측 비율을 좁힐 수 없다.
2. 그룹 상세 내역(파일 목록)과 상세 정보가 가운데 그룹 목록을 필요 이상으로 침범한다. 합의: 사용자가 수동으로 넓히지 않는 한 가로는 이미지 3개 폭을 유지한다.
3. 불러오기에서는 모든 썸네일이 표시되는데 검색 시작 후 대표 이미지만 남고 그룹 내 나머지 썸네일이 사라진다.

## 2. 기존 구조와 결함

신규 프로브 `detail_layout_probe`로 실측·재현했다(수정 전 FAIL):

1. **유사도 탭 `simLabel_`가 전체 best-match 경로를 표시하면서 `wordWrap` 미설정** — 탭 최소너비가 경로 픽셀폭 그대로(실측 **2034px**, 180자 경로) → `detailTabs`(2038) → 우측 팬(2038) 강제 + 스플리터 잠금(좁히기 요구 60 → 2038 유지). 결정적 함정: 공백 없는 경로는 "단어" 1개라 **wrap만으로는 최소너비가 줄지 않는다**(wrap 적용 후에도 실측 1812).
2. **상세 폼 값 행 7종**(크기/형식/수정/생성/해상도/재생시간/유사도)이 wrap·Ignored 없이 최소너비를 요구. 이름/경로 행의 기존 규율(우측 팬은 라벨을 안쪽에서 감싸며 절대 넓히지 않는다는 1115-1117 설계 의도)과 불일치.
3. **파일 목록 썸네일이 행 생성 시 1회 요청에만 의존.** 중간 목록은 catch-up 펌프가 매 틱 재요청하지만 파일 목록·프리뷰는 재시도 경로가 없어, 유실된 답변(스캔 시작 시 바쁜 백엔드, 재시작 시 pending clear, 상한 거부)이 영구 플레이스홀더로 남는다. 대표는 중간 행을 통해서도 재요청되므로 살아남아 "대표만 남음"으로 관측된다. 참고로 `.105` 주석은 "다음 가시 tick이 재시도한다"고 가정했지만 그 tick은 중간 목록만 담당했다.

## 3. 변경 구조

- `simLabel_`: `wordWrap` + 좌상단 정렬 + **수평 `Ignored`**. 표시 텍스트에는 구분자 뒤 zero-width space로 시각적 접힘 제공(저장 경로·툴팁은 원문 유지).
- 값 행 7종: `wrapVal` 람다(wrap + `Ignored`)로 통일. 짧은 값은 종전과 동일 렌더, 긴 값은 팬을 넓힐 수 없다.
- `thumbCatchUpVisible` 확장: 파일 목록 가시 창(±4행) 재요청 + 캐시 적중 직접 적용(중간과 동일 규율) + 선택 프리뷰(220x190) 재요청. 진행 중 중복 방지(dedup), 재빌드 없음, 스크롤 무접촉. 파일 목록은 `onThumbReady`와 동일한 직접 `doItemsLayout`.
- 회귀 프로브 `detail_layout_probe`(CTest 등록, 총 **125**): A1 래핑 여부, A2 탭 최소 ≤640, A3 우측 최소 ≤700(고정 헤더/툴바/탭 내용만), C 재빌드 가드 + 요청 델타 ≥4(중간 3행만으로는 도달 불가). 수정 전 3종 FAIL 재현(A1/A2/C), 수정 후 5/5 PASS.

## 4. 해결된 상황

# MediaSimilarityFinder v0.9.4.162 — Match-Path MSSIM Time Split Aggregation (P1)

Baseline `0.9.4.161` → this build `0.9.4.162`.
CPU CTest **134/134**, GPU CTest **135/135** (no new CTest; assertions added to existing tests).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` all unchanged.

## 1. Why the change was needed

- The remaining half of the P1 measurement split: the build path (decode/pHash) was split in 0.9.4.161, but match-path MSSIM time (GPU-executed vs CPU fallback) was aggregated nowhere — no caller passed `stats` to `video_similarity()`.

## 2. Previous structure

- `video_similarity()` never timed its CPU-fallback `frame_ssim` calls.
- `AnalyzeTelemetry` had only `ssimEvals`/`frameSsimEvals` counters, no time split.
- `scan_pipeline` temporal workers called `video_crop_similarity` without `stats`.

## 3. New structure

- `VideoSimilarityStats.cpuMs`: CPU-fallback `frame_ssim` pair time. GPU time keeps accumulating in the existing `gpuMs`.
- `AnalyzeTelemetry` gains `videoMatchGpuMs`/`videoMatchCpuMs`/`videoMatchSubmitted` (gated pairs offered)/`videoMatchCompleted` (GPU-executed pairs), folded through the existing merge (`addAnalyzeTelemetry`), ScanStats copy, and `analyze`-section JSON keys (additive).
- `scan_pipeline` temporal workers call with a worker-local `VideoSimilarityStats` and merge into `tel` only in the sequential harvest (workers never touch shared telemetry — the existing async-pool no-contention rule).
- Regression pins: `video_sim_perf_test` asserts `cpuMs>0` (CPU path, fallback confirmed) and `cpuMs==0` on the GPU path (all-GPU confirmed). `analyze_telemetry_test` asserts the merge folds (D3 style).
- The adhoc query path (`media_search_engine` loadTemporal) has no `tel` and stays excluded, documented here. The production match path is the `scan_pipeline` temporal flush.

## 4. Resolved state

- Future field-scan logs read match-stage MSSIM cost as `videoMatchGpuMs + videoMatchCpuMs` and the GPU/CPU transition rate as `videoMatchCompleted / videoMatchSubmitted` in the `analyze` section.

## 6. Impact and limits

- Judgement, storage, protocol, versions all unchanged. No cache invalidation. JSON additive, compatible with old readers.
- GPU batch threshold (8) untouched without measurement evidence. Time-axis representativeness of kept-frame selection stays a post-V2/V3-gate task, not in this build.

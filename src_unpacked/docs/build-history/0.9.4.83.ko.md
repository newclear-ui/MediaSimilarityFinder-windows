# MediaSimilarityFinder v0.9.4.83 — 인덱스 우선 표시 (스캔 시작 시 기존 결과 먼저)

기준선 `0.9.4.82` → 본 빌드 `0.9.4.83`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 판정·스키마·디코드 변경 없음.

## 1. 변경 필요성

사용자 보고: **인덱스가 이미 완성된 폴더**에서 "검색 업데이트 시작"을 누르면,
재스캔이 끝날 때까지(대규모 데이터셋에서 2시간 이상) 화면에 **기존 결과가 전혀
보이지 않는다.** 사용자 요청: "인덱스가 완료된 파일들의 정보를 먼저 읽고 썸네일을
GUI에 먼저 표기한 뒤, 남은 잔여 파일 작업으로 넘어가게" 해 달라.

## 2. 기존 구조

`ScanWorker::run()`의 순서:

1. `openIndexForRoot`
2. **count prepass** (전체 디렉터리 열거) → `targetCount`
3. **엔진버전 게이트** (`revalidateMatches`) → 통과분만 저장
4. **quick-load** (저장된 match 복원) → `quickLoaded` + `matchesArrived`
5. walk + analyze

quick-load가 count와 revalidate **뒤**에 있어, 저장된 그룹은 스캔이 상당히 진행된
뒤에야 GUI에 도달한다. 대규모 폴더에서는 이 지연이 분 단위가 된다.

## 3. 변경 구조

`ScanWorker::run()`의 순서를 바꿔 **엔진버전 게이트와 quick-load를 count prepass
앞으로 이동**했다.

1. `openIndexForRoot`
2. **엔진버전 게이트** (`revalidateMatches`) — 같은 버전이면 즉시 no-op
3. **quick-load** → 저장된 그룹/파일이 스캔 시작 직후 GUI에 표시
4. count prepass → `targetCount`
5. walk + analyze

썸네일은 `ThumbnailStore`(디스크 영속)에 이전 스캔 결과가 있어 **재디코드 없이**
표시된다. GUI는 그룹/파일을 받으면 visible 항목부터 `fileThumb()`으로 요청하고,
도착분은 `onThumbReady`가 그린다(기존 경로 그대로).

revalidate를 quick-load보다 먼저 두는 이유: `revalidateMatches`가 통과분만
`saveMatches`로 저장하므로, 그 뒤에 `loadMatches`를 호출해야 **오탐(false positive)이
화면에 남지 않는다.**

## 4. 해결된 상황

- 인덱스된 폴더 재스캔 시, 스캔 시작 직후 **기존 유사/중복 그룹과 파일, 썸네일이
  먼저 표시**된다.
- 이후 count와 walk가 진행되며 새 결과가 증분 반영되고, 완료 시 최종 결과로 대체된다.

## 6. 시도 및 기각 (실험 기록, AGENTS 9항)

- **시도 A (기각)**: `results` 메시지에 `preliminary` 플래그를 추가해, 인덱스된
  파일 목록을 스캔 시작 시 `allPaths_`로 선전송.
  - **기각 사유**: GUI의 파일 뷰(`refreshFileViews`)는 **선택된 그룹**만 렌더하고
    `allPaths_`는 표시에 소비되지 않는다(쓰기만 됨). 또한 `revalidateMatches`가
    통과분만 저장하므로, revalidate 이전에 저장 match를 보여주면 오탐이 남는다.
  - 결과적으로 IPC 시그니처 변경만 늘고 목표를 달성하지 못해 되돌렸다.
- **채택**: quick-load를 count 앞으로 이동(순서 변경만). IPC/시그니처 변경 없음.
- **Future revisit**: 인덱스 파일 목록 자체를 별도 뷰(전체 파일 목록)로 보여주는
  기능이 필요해지면, `results`와 별개의 파일-목록 스냅샷 경로를 검토한다.

## 7. 향후 영향 및 한계

- 순서 변경은 walk/analyze의 판정·집계에 영향을 주지 않는다(표시 타이밍만 변경).
- **미수정(후속)**: "인덱스 완료" 라이브 카운터가 `analyzed`+`unchanged`인데, 이
  상태는 `BackendSession::pushStatusSnapshot()`이 **match 도착 시에만** push한다.
  변경 파일이 없는 증분 재스캔에서는 이 값이 0에 머문다(별도 결함, 다음 빌드 대상).
- Test Mode/프로필/썸네일 DB 바이트는 이 변경과 무관하다.

## 1. 변경 필요성

"검색 완료" 행이 무엇을 세는지 모호했다. 코드는 `r.scanned`(파이프라인에
들어온 파일 수)를 표시했으나, 이름은 인덱싱 완료처럼 읽혔다.

## 2. 기존 구조

- `sumValDone_` = `lastStats_[0]` = `r.scanned`, `"완료 / 전체"` 형식
- `r.scanned`는 walk에서 admitted된 파일 수. 인덱스 기록 완료가 아니다
- `r.analyzed`는 fingerprint 기록 + DB 저장된 파일 수. 실제 인덱싱 수다

## 3. 변경 구조

행 구조를 총 파일 / 읽기 완료 / 인덱스 완료 3행으로 분리했다.

| 행 | 값 | 의미 |
|---|---|---|
| 총 파일 | targetTotal_ | pre-walk 카운트 |
| 읽기 완료 | `r.scanned` (`lastStats_[0]`) | walk에서 admitted된 파일 수 |
| 인덱스 완료 | `r.analyzed` (`lastStats_[1]`) | fingerprint 기록 + DB 저장된 수 |

- 기존 `"완료 / 전체"` 결합 형식을 버리고 각 행은 단일 숫자로 표시
- 번역 키 `readDone`(읽기 완료/Read complete), `indexDone`(인덱스 완료/Index complete) 신설
- 기존 `"scanned"` 키("검색 완료")는 CANCELLED 메시지 경로에서 계속 사용하므로 유지
- tr-keys gate 등록 (`checked=59`)

## 4. 해결된 상황

- "읽기 완료"와 "인덱스 완료"가 분리되어, 분석 실패·미분석 파일이 있어도
  숫자의 의미가 명확하다
- fingerprint 단계에서는 둘 다 0이며, 상태 메시지의 지문 진행 표시와 함께 읽는다

# MediaSimilarityFinder v0.9.2.35 — Windows CPU 빌드/테스트 하드닝

## 변경 필요성
v0.9.2.34 source-ready를 실제 검증 환경(Visual Studio 18 2026 + project-local vcpkg `sqlite3`/`ffmpeg`/`qtbase` 31패키지)에서 빌드했더니 CMake configure는 PASS했지만 링크·컴파일 실패와 CTest 8/36 실패가 발생했다. 기존 Linux 검증은 `GUI OFF`라 Qt 관련 문제가 드러나지 않았고, POSIX 가정(열린 파일 삭제, rename-덮어쓰기)이 Windows에서 그대로 통하지 않았다.

## 기존 구조
- `msf_core` 정적 라이브러리의 FFmpeg include/link를 `PRIVATE`로 선언
- `MediaMonitor::emit()` — Qt의 `emit` 빈 매크로와 이름 충돌
- `MainWindow`에 `QCheckBox* gpuEnabled_` 멤버 선언 누락, `QClipboard` include 누락
- WIC 디코더가 `CoUninitialize()`를 `ComPtr` 해제보다 먼저 호출
- Windows WIC 경로에 PGM 리더 없음 (테스트 픽스처는 `.jpg` 이름의 PGM)
- `Database`/`MediaSearchEngine`에 `close()` 없음. 테스트가 열린 DB 파일을 삭제
- `updateLastScan()`이 `ifstream`을 열어둔 채 rename, 테스트도 `meta` 핸들 유지
- applocal DLL 복사만으로 배포 — vcpkg Qt 레이아웃(`<prefix>\Qt6\plugins`) 미포함

## 변경 구조
- `CMakeLists.txt`: FFmpeg compile definitions/include/link를 `PUBLIC`로 변경. 정적 라이브러리 소비처(테스트·GUI)가 링크 단계에서 상속받는다. `MSF_HAS_FFMPEG`도 `PUBLIC`으로 통일해 `video_decoder.h` 인터페이스 일관성 보장
- `src/monitor.h`·`monitor.cpp`: `emit()` → `emitEvent()`로 개명 (Qt 매크로 충돌 회피, 호출 6곳 포함)
- `gui/mainwindow.h`: `QCheckBox* gpuEnabled_` 멤버 추가. `mainwindow.cpp`: `#include <QClipboard>` 추가
- `src/image_decoder.cpp`: WIC 작업을 static helper(`decodeWicFile`/`decodeWicFileAspect`)로 분리해 모든 `ComPtr`이 `CoUninitialize()` 전에 파괴되도록 보장. PGM 리더를 공용 helper(`decodePgm`/`decodePgmAspect`)로 분리해 Windows는 WIC 실패 시 fallback, Linux는 기존 동작 유지
- `src/database.h`·`database.cpp`: `Database::close()` 추가 (`open()`도 재사용). `src/media_search_engine.h`·`.cpp`: `MediaSearchEngine::close()` 추가 (DB + video fingerprint cache 함께 닫음)
- 테스트 4종(`database`, `database_performance`, `search_engine`, `search_report`, `integration_v37`, `index_manager`)은 정리 전에 `close()` 호출
- `src/index_manager.cpp` `updateLastScan()`: 리더를 스코프로 닫은 뒤 rename. 테스트의 metadata 리더도 스코프화
- `scripts/package_portable.ps1`: windeployqt가 없을 때 project-local `vcpkg_installed\x64-windows\Qt6\plugins`를 `Qt6\plugins`로 미러링. 버전 표기 0.9.2.35로 통일

## 해결된 상황
- Core Release 빌드 PASS (msf_core + 테스트 36종 + Qt6 GUI 실행파일)
- `MediaSimilarityFinder.exe --version` exit 0 (`Qt6\plugins` 배치 후)
- 버전 표기 통일: `CMakeLists`/`vcpkg.json`/`main.cpp kVersion`/윈도우 타이틀/`package_portable.ps1`/`kApplicationVersion` → 0.9.2.35

## 검증
- Windows CPU 전체 파이프라인: `scripts/build_windows_cpu.ps1` → configure PASS → Release 빌드 PASS → **CTest 36/36 PASS**
- 수정 전: LNK1181 36건, C2146/C2065/C2027 GUI 컴파일 에러, 28/36 (WIC teardown AV 6건 + remove-while-open failfast 2건)
- 프로브로 원인 입증: `probe_wic`(종료 후 AV) vs `probe_wic2`(해제순서 수정 후 exit 0), `probe_rm`(remove-while-open throw 확인), Qt6Core-in-CWD bisect → `Qt6\plugins` 부재 확정
- Linux 동작 변경 없음 (PGM 리더 동일 로직, CUDA 알고리즘 불변)

## 향후 영향
- 다음 단계는 CUDA 빌드 검증 (`nvcc` 필요 — 현재 환경에 없음)
- CI 워크플로(`windows-cpu.yml`/`windows-cuda.yml`)는 여전히 VS17 2022 지정 + 구 문서명 참조 — VS18 2026 기준으로 갱신 필요
- vcpkg에 `windeployqt.exe`가 없으므로 portable 패키징은 스크립트 내 미러링 경로 사용. 정식 Qt 배포 검증은 패키징 단계에서 수행
- 이후 Windows 테스트는 "열린 파일 삭제/rename 금지" 규칙 준수. `close()` API가 경계로 제공됨

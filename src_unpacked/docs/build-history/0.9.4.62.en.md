## 1. Why the change was needed

Two consecutive 0xC0000409 fail-fast crashes during a large scan left no
product record. `ScanWorker::run` caught only `std::exception`, Qt messages
went nowhere, and the heartbeat could not tell a slow walk from a hang.

## 2. Previous structure

- Worker catch covered `std::exception` only. Non-standard exceptions
  terminated the process
- No Qt message handler installed (only a debug-only suggestion in a 0.9.2.48 doc)
- Heartbeat `alive ... lastPct lastPath groups marked` showed nothing about
  enumeration phases

## 3. New structure

1. **Dump collection guide (no code)**: WER LocalDumps registry setup to
   capture thread plus stack on the next occurrence. Part of the
   reproduce-and-analyze procedure
2. **Defense**: catch-all in `ScanWorker::run`. Checkpoints partial matches
   and reports failed instead, downgrading silent death to a recorded
   failure. SEH access violations still crash: MSVC builds without /EHa do
   not unwind those through catch(...), so real memory corruption keeps
   failing fast instead of being masked. Includes the
   `MSF_TEST_THROW_NONSTD` test seam (never set by production code)
3. **Observability**: `installQtMessageLog()` — Qt message file sink.
   Per-message open/append/close under a mutex: crash-safe (no buffered
   loss) and thread-safe. Installed on all three main() paths (GUI,
   headless, benchmark). Heartbeat gains `walked`/`listed` so a rescan
   showing 0% for many minutes reads as slow enumeration, not a hang

## 4. Resolved situation

- Non-standard exceptions are no longer record-less exits: checkpoint plus
  failed report
- Qt fatal/warning/critical last words land in `%TEMP%\msf_qt.log`
- Enumeration progress is now visible in the heartbeat

## 1. 변경 필요성

필드 관찰(0.9.4.115 세션): 불러오기 완료 시점에 GUI 이벤트 루프가 길게 멈췄다(supervisor 로그 `health quiet 1/3` = 10초+; 이후 분석에서 수 분 가능성). 사용자 체감 직결 항목으로 "다음 빌드 후보 1(GUI 대량 목록 재구축 성능)"로 채택.

**베이스라인 실측(신규 프로브 `group_fill_probe`, 사용자 규모 그대로 9,055그룹/18,110파일 합성 적용)**:
- 동기 `onResults` 1회 = **609,668 ms(10분 9초)**, 이벤트 루프 틱 1회(전면 프리즈).
- 단계 분해(1,000그룹): maps 1ms / matches 3ms / **rebuild 65,856ms** / fill 1,926ms / tail 5ms.

## 2. 기존 구조와 결함 (복수)

1. **`rebuildGroups()`의 메타 요청 폭풍(지배 원인)**: 동률(best% 동일) 그룹마다 정렬용 `filePixels()`를 호출했고, `filePixels→fileResolution`은 **캐시 미스 시 백엔드 FILE_META 요청**을 발행한다. 사용자 인덱스에는 동률 100.0% 그룹이 수천 개 → 적용 1회에 **경로당 1건의 요청**(합성 1,000그룹=2,000 요청 → 65.9초). 루프백(엔진 내장)에서는 요청이 동기 실행되어 `dimensionsFast` 실패 시 **ffprobe 프로세스 폴백**까지 경로마다 발생.
2. **`fillPair()`의 동기 대량 채우기**: 그룹 1개당 tree+grid 위젯 아이템 2개(텍스트·체크·툴팁 포함)를 동기 루프로 생성 → 9,055그룹이면 수십 초 블록.
3. **`thumbCatchUpVisible()`의 전 행 순회**: `visualItemRect()`를 **모든 행**에 호출(9,000+회) — 대량 적용 시 추가 정지 요인.

## 3. 변경 구조

- **① `filePixels` 캐시 전용**(mainwindow.cpp): 동률 정렬은 이미 캐시된 해상도만 사용하고, 없으면 크기/경로 순으로 자연 강등된다. **rebuild 중 백엔드 요청·ffprobe 폴백이 완전히 제거**된다(파일별 상세 요청은 종전대로 표시 중인 열/상세 경로에서만 발생).
- **② 대형 채우기 지연(청크)**: `fillPair`의 전체 재구축이 800행 초과면 **`GroupFillJob`으로 지연**된다. 이벤트 루프 턴마다 100행씩 추가(청크별 `setUpdatesEnabled`/`blockSignals` 가드) → UI가 계속 반응한다. **세대 카운터(`fillGen_`)** 가 새 채우기(추가/재구축/탭 전환/정렬/검색) 시작 시 잔여 작업을 취소하고, 지연 작업이 진행 중일 때 도착한 append는 전체 재구축으로 강등된다. 완료 시 앵커 복원·`thumbCatchUpVisible`·`groupFill done rows=N ms=M` 로그.
- **③ `thumbCatchUpVisible` 가시 창 한정**: `itemAt`으로 가시 행 범위를 구해 그 창(±4행)만 검사한다. 해석 불가 시에만 전 범위 폴백.
- **④ 결과 적용 단계 계측(영구 진단)**: `resultsApply files=… rows=… groups=… maps/matches/rebuild/fill/tail ms` 로그 + `groupFill done` 완료 로그(`%TEMP%\msf_scan.log`).
- **회귀 프로브 `group_fill_perf_probe`(CTest `group_fill_probe`)**: 9,055그룹을 실제 `onResults` 경로에 투입해 ① 호출이 신속히 반환(≥1500ms 실패) ② 채우기 동안 타이머 틱 ≥3 ③ 두 페인의 최종 행 수 = 9,055 를 검증. **수정 전 FAIL 재현**(applyMs=609,668ms, ticks=1).

## 4. 해결된 상황

- 결과 적용의 **동기 블록 제거**: applyMs **609.7s → 84ms**(9,055그룹), rebuild **65.9s → 3ms**(1,000그룹), 채우기는 18.1초 동안 **비동기로 진행**(틱 91회 = UI 반응 유지).
- 필드의 "불러오기 후 수 초~수 분 프리즈"가 "리스트가 잠깐에 걸쳐 채워지는(반응하는)" 동작으로 바뀐다. 스캔 종료/정렬/탭 전환의 대량 재구축에도 동일하게 적용된다.

## 6. 향후 영향 및 한계

- 표시(성능) 전용: 판정·저장·프로토콜·engine/DB/schema/cache 불변.

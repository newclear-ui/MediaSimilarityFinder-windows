## 1. Why the change was needed

- S3 always declared the journal authoritative with `summary.json` a regenerable derivative, and `BenchmarkSession::regenerateSummary()` existed "for recovery". But no CLI entry point ever called it, so a force-killed suite — or a deleted `summary.json` — could never produce a summary even with a fully intact journal.
- Concrete case: headless suite `XMP-REAL-001` (user dataset, 273,773 files, 7 cases x 3 modes = 21 mode_results, all SUCCESS) was left without `summary.json` after a force-stop. The 29-record journal was intact through `case_complete`, but the S5 measurement evidence stayed open without a summary.
- The normal Ctrl+C cancellation path is untouched. This change only exposes the post-abnormal-termination recovery path; the execution/cancellation/aggregation contracts (S2/S3) are unchanged.

## 2. Previous structure

- Only `finalize()` wrote the terminal record and called `regenerateSummary()`. A process dying earlier never produced a summary.
- `replay()` scopes to `cfg_.runId`; an empty string replays every run in the suite (the `replayJournal` contract).
- `BenchmarkSuiteLock` is an OS handle released on process death. A leftover 0-byte `suite.lock` file is not a lock.

## 3. Changed structure

- New entry point `--benchmark-recover <log-dir> --suite <id> [--run <id>]` (parser + help + dispatch + execution function).
  - `--log-dir` is the storage-root locator (positional, same shape as `--benchmark <folder>`), `--suite` is mandatory, `--run` is optional (omitted = replay every run in the journal).
  - Combinations with `--mode` / `--media` / `--log` / `--scan` / `--benchmark` are rejected. Recovery performs no scan, so options without a consumer are refused rather than silently ignored.
- `runConsoleBenchmarkRecover()`: suite-id safety check -> `runs.jsonl` existence check -> refuse while a live run holds the lock (avoids publishing a partial view) -> lock-free `regenerateSummary()` -> exit 0/1.
  - Never writes to the journal (read-only replay). No fingerprint recomputation, no scan, no index change.
- Tests: 17 parser checks (`command_line_test`), 6 recovery behaviour checks (`console_benchmark_cli_test`: empty request, hostile id, missing journal, corrupt journal, busy-lock refusal, clean regeneration).

## 4. Resolved state

- Ran `--benchmark-recover` with the new binary on the real `XMP-REAL-001` journal -> exit 0, `summary.json` produced (7 committed cases, all SUCCESS, `runFinished:false` — killed, so no terminal record exists, and recovery correctly does not invent one).
- Journal confirmed unchanged (29 lines). A nonexistent suite exits 1.
- `command_line_test` 117 checks, `console_benchmark_cli_test` 32 checks PASS.

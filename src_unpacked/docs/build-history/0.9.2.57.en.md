# MediaSimilarityFinder v0.9.2.57 — Unstoppable Final-Analyze Fix + Recent-Folders Favorites

## Need for change
(1) Stop did nothing once the final analyze phase began. Walk/analysis stages poll cancel, but `analyze()` — grinding through millions of candidate pairs plus a video re-decode per video pair — had no cancel check, so stop/pause hung until it finished. Users force-quit, and since `saveMatches` runs at scan end, every streamed match was lost — the cause of both "stopped-scan contents not shown" and "previous results not shown". (2) Request: pin the 2 most-recently scanned folders in the left favorites.

## Previous structure
- No stop condition in `ScanPipeline::analyze()` candidate-pair loops (via `forEachCandidatePair`). Called at the end of `MediaSearchEngine::scan`, so stop waited for its return
- Checkpoints required 25 new matches + 5s, delaying the first-match save. Force-quit lost small results
- Favorites showed only 6 fixed locations

## New structure
- **Cooperative `StopCheck` cancellation**: 3-arg `analyze()` overload. Polls every 1024 pairs (pause-aware); on fire it is caught internally and partial stats return — nothing propagates out of analyze(). The engine marks the report incomplete through the existing `control->cancel` channel. The worker still saves streamed partial matches and finishes `CANCELLED`, so the middle pane shows partial groups
- **First-match prompt save**: count gate removed; checkpoint whenever matches exist past 5s. Always the full accumulation, so no conflict with wholesale DELETE
- **Recent-folders favorites (max 2)**: scan start updates `ui/recentFolders` (deduped, ordered); `refreshFolders()` lists existing dirs by full path. Clicks flow through the existing `folderActivated` path. Tree refreshes only when the list changed
- `scan_pipeline_test` extended with the cancel case (200 identical fingerprints → partial stats). Version strings unified → 0.9.2.57

## Resolved situation
- Stop/pause now react within ~1024 pairs even at the tail of analysis. No more force-quits
- Stopping keeps every same-file pair found so far saved and displayed; next rescan quick-loads them
- Two recent folders selectable straight from favorites

## Validation

## Future impact
- 1024-pair poll interval is tunable. A single giant video decode still runs to completion (decoder has no abort) — noted as residual risk
- 5s checkpoint cadence kept as the cost-vs-safety trade-off on huge scans
- 2-item limit and full-path display adjustable on request

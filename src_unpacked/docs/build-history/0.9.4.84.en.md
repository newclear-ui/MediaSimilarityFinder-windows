# MediaSimilarityFinder v0.9.4.84 — live "Index complete" counter fixed (match-independent)

Baseline `0.9.4.83` -> this build `0.9.4.84`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged. No verdict, schema or decode change.

## 1. Why it was needed

User report (0.9.4.83 follow-up): on an already-indexed folder, pressing "Search
Update" leaves **"Index complete" stuck at 0.** (0.9.4.83's index-first display
shows similar/duplicate groups right after scan start, but the live counter was
still wrong.)

Root cause (pinned in code):
- The GUI's "Index complete" is `backendStatus_.analyzed + .unchanged`, and that
  value only arrives via the `kStatus` event.
- The only emitter, `BackendSession::pushStatusSnapshot()`, is called **only from
  `onMatchesArrived()`** (`src/backend_session.cpp`).
- On an incremental rescan with no changed files, **no new matches stream**, so
  `matchesArrived` never fires and `analyzed`/`unchanged` stay 0.
- Also, after completion `MainWindow::refreshSummary()` shows "Index complete" as
  `analyzed` only, so an all-unchanged rescan shows 0 even when finished.

## 2. Previous structure

- `pushStatusSnapshot()`: called only when matches arrive -> the counter depends on
  the match stream.
- `refreshSummary()`: `sumValIndexed_ = lastStats_[1]` (= analyzed) only.

## 3. Change

- **Added a 500 ms `QTimer` (`statusTimer_`) to `BackendSession`**: started in
  `startScan`, stopped in `onFinished`/`onFailed`/`teardownWorker`. On each timeout
  it calls `pushStatusSnapshot()`, so `analyzed`/`unchanged`/`gpu` are pushed to the
  GUI **independently of matches**. The counters are engine atomics, safe to observe
  concurrently.
- **`refreshSummary()`**: "Index complete" is now `analyzed + unchanged` (files
  holding an index row), matching the live formula in `updateStatusCounts()` so a
  fully-unchanged rescan shows the full indexed count on completion.

## 4. Result

- Rescanning an indexed folder updates "Index complete" during the scan even when no
  new match streams.
- After completion, "Index complete" shows the indexed file count, not 0.

## 6. Impact and limits

- "Read complete" is driven by `walkedCount` (engine `readProgress`) and is separate
  from this change. If "Read complete" still stays 0 on a rescan, the scan may be
  stuck in a pre-walk phase (count prepass / the `revalidateMatches` engine-version
  gate); the `msf_scan.log` `scanPhase=count begin/done` and the heartbeat
  (`walked=`) lines pin the phase (further diagnosis target).
- Engine verdicts, schema and cache unchanged.

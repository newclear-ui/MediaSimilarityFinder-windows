# MediaSimilarityFinder v0.9.3.8 — Thumbnail Catch-up Scheduler After Scan Completion

## Need for change
- v0.9.3.7 still stopped `uiTimer_` when scanning finished, leaving decoded thumbnails behind.
- When no new match arrived, `groupsDirty_` became false and starvation catch-up stopped. The `thumbFollowUps_ < 12` limit also prevented large result sets from completing.

## Previous structure
- `setRunning(false)` stopped the UI timer.
- Thumbnail follow-up depended on new group changes and a 12-cycle limit.

## New structure
- Scan-state and thumbnail-scheduler lifecycles are separated by keeping `uiTimer_` alive after scan completion.
- When `thumbStarved_` is true, the next tick calls `refreshStreaming()` independently of `groupsDirty_`.
- The fixed 12-cycle limit is removed. Small batches continue until starvation clears. Once success, failure, and cache paths leave no pending work, `thumbStarved_` becomes false and the scheduler becomes effectively idle.
- The per-tick thumbnail budget of 4 and the existing failure cache are preserved.

## Resolved situation
- Scan completion and thumbnail completion are now separate states.
- Remaining thumbnails continue in small batches even when no new match arrives.
- Search algorithms, grouping, DB schema, benchmark, and CUDA algorithms were not changed.

## Validation
- Visual Studio 18 2026 x64 Release build: PASS.
- CTest: **59/59 PASS**.
- Automated tests do not provide a long-running visual validation of the GUI scheduler.

## Future impact
- The UI timer remains alive after scanning, but thumbnail work runs only when `thumbStarved_` is set.
- Large lists still use the existing full UI rebuild path; item-level icon replacement can be considered separately.

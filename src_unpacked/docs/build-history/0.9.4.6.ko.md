# MediaSimilarityFinder v0.9.4.6 — Node B5: Transfer / Workload Cost

B5 검증 기준점. brief §9의 transfer/workload 비용을 total-cost 규칙으로
반영한다. 엔진 1.5.0·DB 1.0.3·캐시 v9·schema 1 불변.

## 변경 필요성
- B4까지 GPU 실측 throughput은 계산 시간만 봤다. 유닛당 전송 비용이
  크면 빠른 GPU도 전체 이득이 줄어드는데, 그 항이 없었다.

## 기존 구조
- effective 용량은 관측 rate를 그대로 썼다.

## 변경 구조
- total-cost 규칙: 관측 GPU rate가 있을 때만(단위 images/sec가 있어야
  초를 더할 수 있음) `effGpu = 1/(1/effGpu + transferSecPerUnit)`을
  적용한다. baseline 경로(미관측)는 손대지 않는다.
- 전송량(`transferBytesPerUnit` 1032B)은 패킹 레이아웃에서 확정된 값.
  대역폭은 12000MB/s coarse 기본값이며 Node C가 실측으로 교정한다.
  bytes 0이면 항 전체가 꺼진다.
- workload-specific 비용은 관측 rate 안에 이미 내재되어 있다(워크로드별
  속도차가 그대로 rate에 반영됨). 명시적 workload 모델은 Node E 몫.
- `GpuBackend::kTransferBytesPerUnit` 상수 신설 + 기존 VRAM 예산
  1032 매직넘버를 이 상수로 통일. `MediaPipeline` 1줄 전달, 엔진은
  스캔 시작 시 1회 주입.

## 선택 이유
- 동일 단위(images/sec)라 정규화 매직 없이 초 단위 합산이 성립한다.
  baseline에 초를 더할 수 없으므로 관측 경로에만 적용한 것은 단위
  정직성의 결과다.
- 커널 내부를 뜯어 전송 시간을 직접 재지 않았다. brief B의 제외 원칙
  (대규모 CUDA 변경 없음)과 일치하며, 대역폭 가정은 C의 측정 대상이다.

## 해결된 문제
- B5 입력이 구조로 존재한다. B6는 모드 정책만 얹으면 된다.

## 향후 영향

- 정직한 부기: 실측값(1032B @ 12000MB/s ≈ 86ns)은 계산 시간(ms) 옆에서
  사실상 0이다. B5는 오늘의 배분을 바꾸지 않고, C의 교정이 가중치를
  결정할 구조를 마련한 버전이다.

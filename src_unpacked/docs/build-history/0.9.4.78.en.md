Baseline `0.9.4.77` → this build `0.9.4.78`.
CPU CTest **120/120**, GPU CTest **121/121**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /

`file_trace` table.

## 1. Why the change was needed

Two measured `backend lost` events (07:53:17, 07:54:15) turned out to be
supervisor watchdog false positives, not crashes, when matched against logs
and the event journal.

- At 07:53:17, health starved for 10s+ during an analyze match burst (groups
  0→8852 in the same second) and a healthy backend was killed. Backend sends
  run on the main thread with a synchronous per-message flush, and health
  shares that thread, so a MATCHES flood plus a 9k-widget GUI rebuild starves
  health. The stdout-backpressure hypothesis left unconfirmed in 0.9.4.74 is
  now confirmed by logs.
- At 07:54:15, a 15-second-old backend died the same way during the startup
  flood (8894 quick-loaded groups plus walk start).
- Afterwards a stale escTimer killed the respawned backend 2 seconds after
  spawn, and `spawn()` never resets `escStage_`, producing the infinite FAILED
  loop (3s cadence, 40+ minutes). No Event 1000 after 08:00, so no AV.

## 2. Previous structure

- Tracing stopped at admission skeleton rows (`files`) with no timing.
- The only watchdog was the supervisor health timeout (single 10s shot),
  which misfires on bursts.
- `VideoFingerprintEngine::build()` took no cancel: Stop did nothing mid-sweep.
- `spawn()` did not reset escalation state, and `enterFailed` re-terminated in
  front of a wedged process, spamming the log.

## 3. Changed structure

- **Trace table** — new `file_trace(path, admitted/started/finished_ms,
  outcome)`. Admission, start, and settlement ride the same transaction.
  Outcomes: `analyzed`, `failed`, `skipped-unchanged`, `ignored`. A blank
  finished means unobserved (died/stalled).
- **Slow-file log** — files over 30s log `slowFile kind/path/admitted/started/
  finished/elapsed/outcome` to `msf_scan.log`. Failures always log.
- **Watchdog** — pure `StallWatchdog` unit: 10 minutes of zero completions
  logs a snapshot (phase, queue, walker, current batch/range contents).
  Auto-cancel only on a second consecutive image-batch stall. Video/analyze
  stalls only ever diagnose (never kill legitimate long work). Producer-side
  stalls (empty queue, live walker, no admissions) get their own snapshot
  branch. Pause resets the clock.
- **Video cancel** — `build()`, `framesAt`, and `framesAt96Plus32` take a
  cooperative cancel flag, polled at entry and between frames.
- **Supervisor** — escalation state resets on spawn. After kill proves
  ineffective, the latch stops re-arming (terminal FAILED with a manual-kill
  note). No respawn onto a live backend. Health needs 3 consecutive misses
  (single bursts survive).

## 4. Resolved state

- Pre-death files keep admitted/started/finished rows in the DB. The next
  death narrows poison candidates to a path list.
- A 10-minute stall leaves the current batch/range contents in the log
  (reproducible).
- Stop works mid video sweep.
- Healthy backends are no longer killed on bursts (30s rule).
- No infinite FAILED loop in front of an unkillable backend.

## 6. Future impact

  plus GUI intake structure survives bursts is now measured, not assumed.

  per-pair metering can be added if needed.

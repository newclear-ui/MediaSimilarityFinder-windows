# 0.9.2.18 — Mirror Candidate Index Optimization

## IMPORTANT CHANGE

Removed the separate mirror-only BK-trees. Each image/video CandidateIndex now stores both the normal fingerprint and the mirrored fingerprint.

### Changes
- Image/video CandidateIndex instances contain normal + mirror fingerprints.
- Comparison performs at most two candidate-index queries: one for the normal query and one for its mirrored query.
- Duplicate candidates are deduplicated by file index before exact similarity evaluation.
- The final four-way normal/mirror similarity semantics are preserved.
- Existing SQLite mirror fingerprint data remains compatible.
- Added an engine regression test for mirrored candidate lookup.

## Rationale
The mirror-only indexes duplicated mirror fingerprints and required additional candidate queries. A single transform-aware BK-tree containing both representations covers normal→normal, normal→mirror, mirror→normal, and mirror→mirror combinations with two index queries.

# MediaSimilarityFinder v0.9.3.6 — 썸네일 DB 경합 제거 + 정체구간 fill

## 변경 필요성
- 스캔 중 미리보기가 멈추는 직접 원인을 특정했다. GUI `thumbDb_`와 워커 엔진 `db_`가
  같은 `index.sqlite`를 쓰는데, 워커는 스캔 대부분 시간 쓰기 트랜잭션을 열어 둔다.
  새로 디코드된 썸네일마다 GUI 스레드에서 `putThumb()`을 호출해 쓰기 락을 기다리느라
  최대 5초씩 GUI가 멈췄다.
- 매치가 안 나오는 구간(비디오 분석·리스팅 중)에는 fill 자체가 안 열려 목록이 얼어 있었다.

## 기존 구조
- 디코드 즉시 `putThumb()` 동기 호출. `refreshStreaming`은 매치 도착 때만 fill.

## 변경 구조
- 스캔 중 영속화를 연기한다. JPEG 바이트를 1000개 상한 큐에 쌓았다가
  스캔 종료(`scanFinished`, 워커 기록 확정 후)와 다음 스캔 시작 전(워커 기동 전)에
  1회 플러시한다. 메모리·디스크 조회는 그대로라 표시는 즉시, 블로킹만 제거.
- `thumbStarved_`를 `refreshStreaming` 게이트에 포함시켜 매치 없는 구간에도
  기존 adaptive 주기(600ms~3s) 안에서 버짓만큼 점진 채움한다.
- 썸네일 출처 카운터(메모리/디스크/엔진/셸/디코드/플레이스홀더/실패)를 달고
  스캔 종료 시 `scanLog`에 요약한다. 렌더 추적 부재 해소.
- 버전 표기 통일 → 0.9.3.6.

## 해결된 상황
- 스캔 중 GUI 프리즈의 직접 원인이 제거됐다.
- 정체 구간에도 미리보기가 점진적으로 채워진다.
- 썸네일이 어디서 나왔는지 로그로 확인된다.

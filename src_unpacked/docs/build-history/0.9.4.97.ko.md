# MediaSimilarityFinder v0.9.4.97 — 설정 GPU 개명 + 불러오기 썸네일 수정

기준선 `0.9.4.96` → 본 빌드 `0.9.4.97`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 요청 2건:

1. 설정 일반 탭의 `GPU 가속` 체크박스 이름을 `모니터링 GPU가속`으로 변경한다 (기능 불변, 라벨만).
2. 불러오기로 인덱스 목록은 불러와지지만 썸네일이 표시되지 않는다.

## 2. 기존 구조

- `onThumbReady()`는 도착한 썸네일을 중간 그룹 그리드(`imgGrid_/vidGrid_`)와 미리보기(220x190)에만 그렸다. 우측 파일 그리드(`grid_`)는 다음 수동 갱신(그룹 선택 변경) 때 메모리 캐시로 치유된다는 주석만 있었고, 도착 즉시 그리지 않았다. 불러오기 후 클릭 없이 보면 우측은 플레이스홀더로 남는다.
- `fileThumb()`은 어떤 크기로든 백엔드에 요청했다. 상세/트리 보기에서는 중간 그리드의 `iconSize`가 설정되지 않은 채(-1x-1)라, 표시 불가능한 아트를 위해 백엔드 WIC 디코드를 태웠다.

## 3. 변경 구조

- **우측 도착 즉시 그리기** (`gui/mainwindow.cpp::onThumbReady`): `grid_`의 행을 저장 경로 + 현재 아이콘 크기로 대조해 일치하면 그린다. 그룹 전환이 행을 재생성하므로 늦은 도착이 엉뚱한 파일을 칠할 수 없다. 그리면 `doItemsLayout()` 1회. 미리보기·중간 경로 불변.
- **무효 크기 요청 억제** (`fileThumb`): 크기가 유효하지 않으면 백엔드 요청 없이 플레이스홀더를 반환한다. 보이는 그리드는 fill/catch-up으로 유효 크기로 재요청한다.
- **개명**: `monitorGpu` 키 문구만 변경("GPU 가속"→"모니터링 GPU가속" / "GPU"→"Monitoring GPU acceleration"). 기능·키·저장 위치 불변. 모니터 탭의 별도 `allowGpu`와 무관.
- 회귀: `ui_scroll_regression_test` phase 11(두 번째 창 + 스캔 없는 불러오기 → 중간 120개 그리기 + 우측 선택 후 실제 아트 확인).

## 4. 해결된 상황

- 불러오기 직후 중간 목록과 우측 파일 목록 모두 썸네일이 표시된다. 클릭 없이도 우측이 채워진다.
- 상세/트리 보기에서 표시 불가능한 썸네일 요청이 백엔드까지 가지 않는다.
- 설정 일반 탭의 체크박스 이름이 `모니터링 GPU가속`이다.

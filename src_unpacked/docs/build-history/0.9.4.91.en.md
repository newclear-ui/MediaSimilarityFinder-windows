# MediaSimilarityFinder v0.9.4.91 — group sort "None" top/default + append-only list during a scan

Baseline `0.9.4.90` -> this build `0.9.4.91`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged (GUI-only change).

## 1. Why

0.9.4.90 added `None` to the group sort and locked it during a scan, but the list was still
**fully rebuilt** on every refresh (`clear()` + repopulate). The user asked to:
- move `None` to the **top** of the sort list and make it the **default**;
- lock to `None` on scan start;
- keep the current group list (and thumbnails) **fixed** during a scan and **append only new items at the bottom**.

## 2. Previous structure

- Sort items: `0=similarity, 1=name, 2=none`. Default similarity.
- `fillPair()` cleared the tree/grid and repopulated every refresh, recreating every thumbnail/scroll row each tick.
- Changing the sort combo only called `refreshGroupList()` (no re-sort trigger).

## 3. New structure

- Sort order is now **`0=none (default), 1=similarity, 2=name`**. Default index 0 = `None`.
- **Append-only list during a scan**:
  - `rebuildGroups()` in `None` mode builds a **stable order**: groups already listed keep their
    position; new groups (or ones whose union-find root changed by a merge) are appended at the bottom
    in root order (`noneOrder_` preserves the display order).
  - `fillPair(..., append=true)`: if the current (root, signature) list is a **prefix-extension** of the
    previously shown list, only the **new rows are appended at the bottom**; existing rows/thumbnails are
    never recreated. If the prefix breaks (merge/removal/order change) it **falls back to a full rebuild**
    for that tick.
  - `groupSig()` = (file count, best similarity). A changed existing group fails the prefix check and
    triggers a full rebuild.
  - `imgShown_`/`vidShown_` hold the per-kind (root, signature) rows; reset on a full rebuild.
- `refreshStreaming()` calls `refreshGroupList(scanning_ && sort==None)` during a scan. The full-rebuild
  cost is measured inside the timer (including `rebuildGroups()`) so the throttle reflects it.
- Changing the sort combo now calls `rebuildGroups()` then `refreshGroupList()`, so sorting applies
  immediately (fixes the earlier missing re-sort).

## 4. Result

- During a scan the list is not recreated; only new groups are appended at the bottom, so thumbnails and
  scroll stay fixed.
- `None` is top and default, so append-only is the default behavior at scan start.
- A full rebuild happens only on merge/content change (safe fallback), preserving correctness.
- After the scan, selecting similarity/name re-sorts immediately.

## 6. Impact and limits

- GUI-only. engine/DB/schema/cache unchanged.
- Append-only applies only with `None` + empty group search + a running scan. Otherwise the list is
  rebuilt as before.
- A group whose root changed by a merge moves to the bottom and triggers a full rebuild that tick
  (intended fallback).
- `None` exposes the root append order, so the order among new groups is not meaningful.

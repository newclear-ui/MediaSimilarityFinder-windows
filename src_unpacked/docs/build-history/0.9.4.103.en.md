# MediaSimilarityFinder v0.9.4.103 — Checked-first file actions + file-bar separator

Baseline `0.9.4.102` -> this build `0.9.4.103`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

Two user requests (detail-text stays deferred to the next build):

1. Checking multiple files then pressing copy/cut/paste/move/recycle acts only on the highlighted file. When checked files exist, they take priority. Open/reveal stay single-file.
2. Add a separator after reveal in the detail top menu (1px like the top menu's gray bars). Final order: open, reveal, separator, copy, cut, paste, move, recycle.

## 2. Previous structure

- Copy/cut/move/recycle read only `selectedFiles()` (highlight/selection) and ignored checkboxes (`marked_`). Paste is clipboard-based either way.
- The file bar held 7 actions with no separator.

## 3. New structure

- **New `actionFiles()`**: the whole checked set (sorted for determinism) when any box is checked, else the existing highlighted selection. Used by copy/cut (including `cutPaths_)/move/recycle. Open/reveal/paste/toggle/ignore/analyze paths untouched (open/reveal stay single-file, paste stays clipboard-based).
- **Separator**: `addSeparator()` after reveal; file-bar style `1px #8c8c8c` (same gray as the top). Order as directed.
- Test hook `testActionFiles()`.

## 4. Result

- With checks present, copy/cut/move/recycle act on all checked files, and cut→paste carries the checked set. Without checks, behavior is identical.
- The file bar shows open/reveal separated from the rest.

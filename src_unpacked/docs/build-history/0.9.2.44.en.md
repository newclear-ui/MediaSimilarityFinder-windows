# MediaSimilarityFinder v0.9.2.44 — Large-Scan Live Verification + Streaming Switch

## Need for change
The on-machine report "duplicate search does nothing at all" was verified by full source review plus a worker-path replica probe. Engine, match pipeline, and streaming are all correct. A 3,000-image probe delivered 641,358 matches identically through streaming and retention. The real problem is scale. A 272k-file folder can produce millions of matches, while the old structure retained two path strings per match in the result vector, rebuilt all views every 600 ms, and re-decoded every group thumbnail each time — hundreds of MB to GB plus UI freezes that look like "nothing happens". The silent 23-minute walk plus hours of analysis add to the same impression.

## Previous structure
- The worker kept the default (`retainMatches=true`), materializing every match in `SearchReport` before handing it to the GUI
- `fileThumb()` re-decoded images through WIC every call (only videos cached)

## New structure
- Worker `control_.retainMatches=false` (streaming-only). The GUI already holds identical data via `drainMatches` union-find accumulation, so behavior is unchanged with hundreds of MB saved. The `finished`-message counts are unaffected
- `fileThumb()` caches everything with a 3000-entry cap (cleared on overflow). No more re-decodes on group-list refresh
- Version strings unified → 0.9.2.44

## Resolved situation
- Memory no longer scales with match volume on huge scans. UI refresh cost drops to cache-hit thumbnail display

## Validation
- Worker replica probe (3,000 files, `openIndexForRoot`+streaming): 641,358/641,358 streaming-vs-retained agreement confirmed before switching. Post-switch equivalence is structural (same callback path)
- Core Release build: PASS, **CTest 39/39 PASS**, `--smoke` exit 0, `--version` 0.9.2.44
- Full 272k-folder scan wall time (hours scale) remains hardware/codec-bound. Mitigated by progress display (.42) and incremental rescans

## Future impact
- No GUI code depends on a populated `SearchReport.matches` (verified). A future virtualized model uses the same stream
- If tens of thousands of groups make the 600 ms full rebuild heavy, incrementalize `rebuildGroups` or switch to a virtualized table (structure stays)

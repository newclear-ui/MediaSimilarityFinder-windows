# MediaSimilarityFinder v0.9.4.133 — 시스템 CPU 지표 공식 교정 (GetSystemTimes idle-in-denominator)

기준선 `0.9.4.132` → 본 빌드 `0.9.4.133`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (판정 불변, CTest 등록 수 불변).

## 1. 변경 필요성

- 실기 보고: "CPU 사용량 매우 상이함"(Maximum 설정, 검색 외 작업 없음). 상세 로그 `시스템 avg 66.7%`가 작업 관리자 총 CPU(35~50%)와 크게 어긋나고, 앱 프로세스 1.7%와도 모순되어 보였다.
- 원인 확정: `TelemetryRecorder::sampleOnce`의 GetSystemTimes 계산이 **커널 시간에 idle이 포함**된다는 의미를 무시하고 분모에 idle을 가산했다.
  - 구 공식: `sys = 1 − Δidle/(Δidle+Δkernel+Δuser)` — 수학적으로 항상 `1/(2−u)`(u=실사용률)를 보고하므로 **완전 유휴 기계에서도 50%**로 표시된다.
  - 실측 증명(유휴 근처 5초 창, 동시 비교): 구 공식 **55.8%**, 교정 공식 20.6%, Windows 성능 카운터 17.1~23.8%.
  - 실기 로그 정정: 66.7% → 실제 u = 2 − 1/0.667 ≈ **50%**.
- `monitor.cpp`(SystemLoadMonitor)는 처음부터 올바른 공식(`(Δk+Δu−Δi)/(Δk+Δu)`)을 사용 — 오류 지점은 telemetry recorder 한 곳뿐임을 전수 확인.

## 2. 기존 구조

- `sampleOnce`가 샘플마다 `tot = Δidle+Δkernel+Δuser; cpuSys = 100*(1 − Δidle/tot)`로 계산. `monitor.cpp`의 같은 종류 계산과 결과가 서로 달랐다.

## 3. 변경 구조

- 신규 헤더 인라인 `msf::systemBusyPercent(Δidle, Δkernel, Δuser)` = `(Δkernel+Δuser − Δidle)/(Δkernel+Δuser)`, 빈 구간 0, idle>tot clamp. `sampleOnce`가 이를 호출한다.
- 공식을 헤더로 옮겨 **단위 테스트 대상**으로 만들었다: `benchmark_test`에 5건(빈 구간 / 완전 유휴=0% / 완전 사용=100% / 혼합 40.909% / 역전 clamp=0%) 추가.

## 4. 해결된 상황

- 시스템 CPU가 실제값을 보고한다. 프로브 동시 측정(20초 창): telemetry `cpuSysMean 17.5%` vs 성능 카운터 평균 15.4%(max 24.5) — 일치.
- 앱 프로세스 지표(프로세스 트리)는 원래 정확했다: 걷기 전용 실측에서 프로브 1.66%(=실기 로그 1.7%, 작업 관리자 2%와 일치).

  - **Windows Defender(MsMpEng) 평균 31.0%**(피크 37.3%) — 파일 오픈마다 실시간 검사.
  - 시스템 총 평균 65.2%(유휴 베이스라인 20.1%: opencode/chrome 세션 포함).

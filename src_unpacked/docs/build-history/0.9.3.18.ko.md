# MediaSimilarityFinder v0.9.3.18 — Benchmark 디스크 I/O·재생시간 직접 폴백·팝업 가독성

## 변경 필요성
- 실측 벤치마크에서 영상 분석이 wall의 97%를 차지하는데 CPU 17%·GPU duty 0.2%라 병목이 디코더인지 디스크인지 구분할 수 없었다. 스캔 폴더가 있는 디스크의 I/O를 같이 기록해야 느린 파일의 원인을 비교할 수 있다.
- 상세정보 재생시간이 라이브·취소 스캔에서 계속 "-"였다. 엔진 파일 목록에도 없는 경우(스캔 종료 후 워커가 없거나 경로 키 불일치)가 있어 폴백이 한 겹으론 부족했다.
- 정지 팝업 문구가 고정 360px 창에 잘렸다. CJK 글리프는 같은 폭에서 더 잘린다.

## 기존 구조
- Benchmark `resources`는 CPU·메모리·GPU만 기록했다.
- 재생시간은 `fileDur_` → 엔진 목록 순으로만 찾았다.
- 대기 팝업은 고정 크기였다. `newName:` 호출은 키 오타로 양 언어에서 원문 키가 그대로 보였다.

## 변경 구조
- `BenchmarkRecorder`가 스캔 루트의 볼륨(예 `G:`)에 PDH LogicalDisk 읽기·쓰기 Bytes/sec 카운터를 연다(영문 카운터명이라 표시 언어와 무관). 250ms 샘플마다 드라이브 전체 read/write Bps와 프로세스 누적 I/O(GetProcessIoCounters)를 기록한다.
- Benchmark JSON `resources`에 `diskVolume`·`diskAvailable`·`ioReadBpsMax/Mean`·`ioWriteBpsMax/Mean`·`procIoReadBytes/WriteBytes/Ops`를 추가하고, `series` 항목을 7원소로 확장했다. 검색 로그 다이얼로그에 디스크 I/O 줄을 추가했다(`benchIo` 한·영).
- 재생시간이 여전히 비면 컨테이너에서 직접 읽는다(`VideoDecoder::open`+`info`, 약 30ms, 캐시). 이미지에는 적용하지 않는다.
- 대기 팝업을 워드랩+최소폭 460+내용 맞춤으로 바꿨다. `newName:` 오타를 `newName`으로 수정해 한·영 정상 표기로 복원했다(감사 결과 사용 119키 중 유일한 누락, 빈 영문 0건).

## 해결된 상황
- 느린 파일의 `buildMs`와 같은 구간 드라이브 I/O를 로그에서 바로 대조할 수 있다.
- 스캔 상태와 무관하게 영상 재생시간이 표시된다.
- 팝업 문구가 2줄로 온전히 보인다.

## 검증
- `benchmark_test`에 `diskVolume`·`ioReadBpsMax`·`procIoReadBytes` 키 assertion 추가 후 PASS.
- CUDA Release 빌드 PASS, **CTest 63/63 PASS**.
- CPU-only Release 빌드 PASS, **CTest 62/62 PASS**.
- Portable v0.9.3.18 생성 및 smoke PASS, `--version` 0.9.3.18.

## 향후 영향
- PDH 카운터 실패(권한·볼륨 부재) 시 I/O는 0으로 기록되고 `diskAvailable:false`가 남는다. 판정·엔진 버전은 불변이므로 재검증이 필요 없다.
- `series` 포맷이 7원소로 늘었다. 외부 파서가 있으면 갱신이 필요하다.

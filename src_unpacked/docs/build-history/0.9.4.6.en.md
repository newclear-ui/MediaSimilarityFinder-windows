# MediaSimilarityFinder v0.9.4.6 — Node B5: Transfer / Workload Cost

Validation baseline for B5: the brief §9 transfer/workload cost as a
total-cost rule. Engine 1.5.0, DB 1.0.3, cache v9, schema 1 unchanged.

## Why the change was needed
- Through B4 the observed GPU throughput counted compute time only. A
  large per-unit transfer cost shrinks a fast GPU's total win, and no
  term captured it.

## Previous structure
- Effective capacities used observed rates verbatim.

## New structure
- Total-cost rule, observed path only (seconds can only join rate units):
  `effGpu = 1/(1/effGpu + transferSecPerUnit)`. The unobserved baseline
  path is untouched.
- Transfer volume (`transferBytesPerUnit`, 1032 B) is fixed by the packing
  layout. Bandwidth is a coarse 12000 MB/s default for Node C to calibrate
  by measurement. Zero bytes disables the term.
- Workload-specific cost is already embedded in observed rates (per-workload
  speed differences show up in the rates). An explicit workload model
  belongs to Node E.
- New `GpuBackend::kTransferBytesPerUnit` constant; the existing VRAM
  budget magic 1032 now references it. One-line `MediaPipeline` forward;
  the engine injects once per scan.

## Why this shape
- Shared units (images/sec) make second-level addition exact with no
  normalization magic. Restricting it to the observed path follows from
  unit honesty: nothing to add seconds to without rate units.
- No kernel teardown to time transfers directly, per the B exclusion rule
  (no large CUDA changes); the bandwidth assumption is Node C's
  measurement target.

## Resolved state
- B5 inputs exist as structure. B6 only adds mode policies.

## Accuracy impact
- None. Gates and verdict paths untouched. Identical
  `scan_workflow_test` on both trees.

## Compatibility impact
- Benchmark JSON keys unchanged, schemaVersion kept.

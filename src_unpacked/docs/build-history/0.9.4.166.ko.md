기준선 `0.9.4.165` → 본 빌드 `0.9.4.166`.
CPU CTest **135/135**, GPU CTest **136/136** (신규 CTest 1건: video_timestamp_basis_test).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` 전부 불변.

## 1. 변경 필요성

- 외부 리뷰 P1 지적 2건: (a) `start_time`을 보정하지 않아 컨테이너별 PTS 기준점 차이로 샘플 대응이 밀릴 수 있다. (b) PTS가 없는 프레임에 요청 시각을 대입하면 관측이 아닌 가정 시각이 지문에 들어간다. 둘 다 판정 변경 수반 사안이므로 생산 코드 수정 없이 먼저 측정한다.

## 2. 기존 구조

- `open()`/`framesAt()`/`frameAtColor()`: `seconds × AV_TIME_BASE`로 seek, `best_effort_timestamp × time_base`를 그대로 비교. `start_time` 참조 없음.
- NOPTS 시 `targets[next]` 대입 (3곳: 순차 스윕, drain, sparse executor). 카운트 없음.

## 3. 변경 구조

- 제품 코드 변경 없음(판정·저장 불변). 계측·핀만 추가:
- `VideoDecoder::framesAt/framesAt96Plus32`에 `noptsOut` 추가(기본값 null, 기존 호출부 무변경). 순차 스윕 본루프+drain에서 NOPTS 대체 시 계수. sparse executor·CLI fallback은 대상 경로가 아니라 제외하고 명시.
- `VideoBuildStats.noptsFrames` → `TelemetryRecorder.addVideoNopts` → `videos.noptsFrames/State` (additive, `start()` 리셋, 캐시 히트는 측정된 0).
- 회귀: `video_timestamp_basis_test` 신규 — 동일 testsrc를 start_time=0 vs +2.5s로 mux한 쌍의 구조적 불변식(빌드 성공·완전 샘플·단조성·범위·NOPTS 0) 단언 + shift 관측 출력. `analyze_telemetry_test`에 measured/null 계약, `video_complete_test` baseline에 `noptsFrames==0` 단언.

## 4. 측정 결과 (RTX 3080 Ti, 동일 testsrc 8s)

| 파일 | start_time | kept 수 | 첫 kept ts | 끝 kept ts | nopts |
|---|---|---|---|---|---|
| clip0 | 0.0 | 2 | 0.0 | 5.0 | 0 |
| clipOff(+2.5s) | 2.5 | 3 | 2.5 | 8.0 | 0 |

- kept 그리드 전체가 start_time만큼 이동한다 (first-shift = 2.5 정확히). 동일 시각 콘텐츠도 다른 샘플 집합이 선택된다 (kept 2 vs 3 — 종단점 8.0이 한쪽은 허용오차로 탈락, 다른 쪽은 정확히 적중).
- 결론: 동일 영상이라도 컨테이너 시작 오프셋이 다르면 지문이 달라져 중복이 누락될 수 있다. 리뷰의 우려가 실측으로 확정됐다.

## 6. 향후 영향 및 한계

- 판정·저장·프로토콜·버전·엔진 불변. 캐시 무효화 없음. NOPTS fail-closed 전환과 start_time 기준점 수정은 관측 데이터+사용자 승인을 거쳐 별도 빌드에서 결정한다.

- 프레임 선택의 시간축 대표성은 V2/V3 gate 이후 과제이며 본 빌드에 포함하지 않는다.

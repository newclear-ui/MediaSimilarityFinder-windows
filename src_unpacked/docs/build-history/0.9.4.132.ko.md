# MediaSimilarityFinder v0.9.4.132 — 불러오기(Load) 후 검색 요약 채움

기준선 `0.9.4.131` → 본 빌드 `0.9.4.132`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (판정 불변, CTest 등록 수 불변).

## 1. 변경 필요성

- 실기 보고: **불러오기(Load) 후 좌측 하단 "검색 요약"이 전부 "-"** (그룹 목록과 상태줄은 정상: 유사 그룹 9070, 저장 매치 15135건).
- 원인 추적: Load는 `onResults(wasLoad)` 경로로 목록만 채우고 `refreshSummary()`를 호출하지 않는다. Load 시작 시 `hasReport_=false`로 초기화되고 `lastStats_`가 없으며 이전 스캔의 `targetKnown_`이 남아 있어, 요약은 플레이스홀더("-") 상태로 방치됐다.
- 부수 문제 2건: ① 완료 후 상태줄이 스캔 경로용 문구("저장된 매칭 N건을 불러왔습니다 — 누락된 파일만 검색 중…")를 그대로 남겼다 — Load는 스캔을 시작하지 않는데도 스캔이 이어지는 것처럼 읽힌다. ② 진행률이 0%로 남았다.

## 2. 기존 구조

- Load 완료 = `onResults`의 wasLoad 분기: `rebuildGroups`/목록/뷰/`updateStatusCounts`(하단 상태바)까지만 수행. 좌측 요약(`sumVal*`)은 스캔 완료(`scanFinished`) 또는 `refreshSummary()` 호출로만 채워졌다.

## 3. 변경 구조

- Load 완료 시 좌측 요약을 **적재 세트 기준**으로 채운다(`gui/mainwindow.cpp`):
  - 총 파일 / 읽기 완료 / 인덱스 완료 = 로드된 파일 수(600 예), 유사 그룹 = `groups_.size()`, 중복 파일 = 목록 기준 합(0.9.4.131 규칙 그대로),
  - 쌍검증 = `- / N`(N = 저장 쌍 수; 이번 세션에서 검증한 것이 없음을 명시), 검색 시간 = 로드 소요 시간.
- Load 시작 시 `targetKnown_`을 비워(스캔 목표 잔존 제거) `loadStartMs_`를 기록하고, 완료 시 `loadedSummary_`를 켠다. 이 상태는 다음 스캔 응답(`onResults` 스캔 분기)과 `scanFinished`에서 해제된다.
- 상태줄: 신규 키 `loadDone` = "인덱스 불러오기 완료 — 파일 %1 · 매치 %2" / "Index load complete — %1 files · %2 matches". 완료 시 진행률 100%.
- 요약 값 라벨(sumValTotal 등)에 objectName을 부여해 자동화 검증이 가능하도록 했다(표시 전용).

## 4. 해결된 상황

- Load 직후 좌측 요약: 총 파일/읽기/인덱스/유사 그룹/중복 파일/쌍검증("- / N")/검색 시간 모두 채워진다. 상태줄은 스캔 오해 문구 대신 Load 완료 문구.
- 표시 전용 변경이다: 목록·저장·판정·엔진 경로 불변.

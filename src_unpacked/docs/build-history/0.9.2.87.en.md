# MediaSimilarityFinder v0.9.2.87 — CUDA Kernel 1e-7 Snap (CPU/GPU Flat-Image Agreement)

## Need for change
- The 0.9.2.86 fast CPU pHash snaps sub-1e-7 coefficients to zero, making flat images deterministic, but the CUDA kernel lacked the same snap.
- Flat images could hash deterministically on CPU and noisily on GPU. A synthetic lattice pattern diverged by 19 bits.

## Previous structure
- The kernel stored coefficients verbatim: `coeff[tid]=sum*c_norm[v]`.

## New structure
- One kernel line now snaps `|c|<1e-7` to zero, the same criterion as CPU `bits_from()`. DCT math, tables, and sorting are untouched (approved exception to the CUDA-invariance rule).
- `cuda_backend_test` returns to the product bound (D≤8) with the comment updated to the measured result (lattice ham=0).
- Version strings unified → 0.9.2.87.

## Resolved situation
- All 56 natural images and all 8 synthetic patterns are now bit-exact CPU vs GPU, including lattice pattern #5.
- Flat images yield the same deterministic hash (0x7fff…) on both paths.

## Validation
- Core+GUI Release build: PASS, **CTest 57/57 PASS**
- Portable `--smoke` exit 0, `MediaSimilarityFinder-v0.9.2.87-Portable-Windows-x64.zip` produced

## Future impact
- GPU hash semantics fully match CPU, so CPU/GPU path selection no longer changes results for flat-like files.
- FMA-combining differences remain theoretically possible but measured zero divergence on this toolchain (sm_86, CUDA 13.4, VS18).

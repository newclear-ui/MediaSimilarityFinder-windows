# MediaSimilarityFinder v0.9.3.15 — Degenerate-Hash False-Positive Fix, Report-Wait UI, Video GPU Activity Wiring

## Need for change
- Five clearly different videos were all reported as identical files. Measurement showed degenerate (sparse, popcount 2-4) crop pHashes scoring 87-96% similarity, matching immediately through the L1 short-circuit (temporal scores were all 0 and never consulted).
- Video search appeared to use no GPU at all. Three causes: (a) L1 short-circuit pairs never reach temporal, the only SSIM GPU path; (b) the SSIM batch never raised the GPU-active flag, so the status bar and sampler missed it; (c) monitor video analysis built fingerprints CPU-only with no GPU backend.
- There was no wait notice while the finished-scan report was being written, so users quit mid-rebuild; file-selection highlight was too faint; video previews rendered in black and white.

## Previous structure
- `bestMatch()` / `bestAgainst()` / `anchorSim()` compared every nonzero hash with no degenerate-hash rejection.
- `VideoSimilarityOptions` had no GPU-activity channel, so `gpuActive_` stayed false during SSIM batches.
- `MediaMonitor` fingerprinted videos CPU-only.
- Scan completion had no notice popup (the success path is modal-free), and selection highlight depended on the native OS theme.
- Gray engine thumbnails persisted by older builds stayed in the disk cache and pinned every later view to black and white.

## New structure
- Added a `hash_usable()` guard in `similarity.h` (popcount below 8, or 0, is excluded from comparison; a healthy median-split pHash sets ~32 bits).
- Applied the guard in `bestMatch()`, `anchorSim()`, and `bestAgainst()`. Indexes (candidate enumeration) are untouched, so enumeration semantics are unchanged and only verdicts change.
- Raised the engine verdict version 1.2.0 → 1.3.0. Stored pairs auto-revalidate on the next scan, dropping the old false groups (no full rescan needed).
- Added `VideoSimilarityOptions::gpuActivity`, raised around the SSIM batch, and connected it via `ScanPipeline::setVideoGpuActivity()` on the scan, revalidate, and live paths.
- Added a `videoGpu_` backend to `MediaMonitor`, used for video analysis when the policy (`policy_.gpuEnabled`) allows it.
- On scan completion (`scanFinished` / `onResults`), a small non-modal "Writing the search report. Please wait a moment…" popup appears first and closes when the report views are rebuilt. Closing the window mid-scan now asks for confirmation.
- Applied a high-contrast selection style (active #2b6cb0, inactive #7aa7d9, white text) to the six result/file views.
- Gray disk-cache entries are skipped in favor of the color decoders, and gray-only engine thumbs are never persisted.
- Added the grid x-dimension upper bound (`count>2147483647ULL`) to `msf_cuda_backend_ssim_batch` for consistency with `hashBatch`.
- Added `tests/video_degenerate_hash_test` (guard contract, degenerate-crop pair rejection, healthy-pair match).

## Resolved situation
- End-to-end scan of the five sample videos yields 0 groups (previously all one identical group). They are rejected at L1 without needing temporal.
- SSIM GPU usage now shows correctly in the status bar and Benchmark sampler.
- The 1.3.0 engine revalidation drops previously stored false pairs on the next scan.
- Users now wait for report generation instead of quitting mid-rebuild.

## Validation

- `match_revalidate_test` engine expectation updated to 1.3.0, PASS.

## Future impact
- The degeneracy cutoff (popcount 8) is an empirical floor; adjust it if large-corpus results show healthy-pair drops (false negatives).
- Degenerate hashes still enter indexes (enumeration cost only, verdicts reject); consider index-stage exclusion if needed.
- The 0.9.3.14 conclusion stands: per-row DTW calls and transfer costs bound speedups on small candidate sets. Re-measure the benchmark under real concurrent load with image batch hashing and video SSIM sharing one scan.
- SSIM "max error 0" is an RTX 3080 Ti measurement (tolerance 1e-6); re-verify on other SM generations.

## 1. Why the change was needed

The "검색 완료" row was ambiguous about what it counted. The code displayed
`r.scanned` (files admitted to the pipeline), but the name read like indexing
completion.

## 2. Previous structure

- `sumValDone_` = `lastStats_[0]` = `r.scanned`, in "done / total" shape
- `r.scanned` counts walked-and-admitted files. Not index-write completion
- `r.analyzed` counts fingerprinted + DB-written files. The actual indexed count

## 3. New structure

Panel rows split into total / read-complete / index-complete, in that order.

| Row | Value | Meaning |
|---|---|---|
| Total files | targetTotal_ | pre-walk count |
| Read complete | `r.scanned` (`lastStats_[0]`) | files admitted from the walk |
| Index complete | `r.analyzed` (`lastStats_[1]`) | fingerprinted + DB-written count |

- Dropped the combined "done / total" shape; each row shows a single number
- New keys `readDone` (읽기 완료/Read complete), `indexDone` (인덱스 완료/Index complete)
- The existing `"scanned"` key ("검색 완료") stays for the CANCELLED message path
- Registered in the tr-keys gate (`checked=59`)

## 4. Resolved situation

- Read-complete and index-complete are separated, so the numbers stay meaningful
  even with analysis failures or unanalyzed files
- During fingerprint both read 0; read together with the status-line
  fingerprint progress

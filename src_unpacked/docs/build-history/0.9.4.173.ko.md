# MediaSimilarityFinder v0.9.4.173 — TemporalAnchorV2 양방향 시간 앵커 판독 경로 (실험 opt-in, LegacyV3 기본값 유지)

기준선 `0.9.4.172` → 본 빌드 `0.9.4.173`.
CPU CTest **144/144**, GPU CTest **145/145** (신규 CTest 3건: video_temporal_anchor_v2_test, video_anchor_file_test, video_anchor_scan_test).
`kEngineVersion 1.5.2` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 11` / `kProtocol 1` (모두 불변).

## 1. 변경 필요성

- 사용자 지시(`지시/TemporalAnchorV2 — 양방향 시간 앵커 기반 동영상 비교 알고리즘 개선.md`): V1의 정방향 탐색을 유지하면서 **역방향 엔딩 탐색**을 추가한다. 본편 종료점에서 역산한 앵커와 정방향 앵커를 교차 검증하고, 중간 삽입으로 오프셋이 바뀌면 구간별 시간축으로 분리한다. 단순 점수 보정이 아니라 시간 구조를 이용한 동일 영상 판별이다.
- V1에서 승계하지 않기로 한 결함(지시 §2): ScanPipeline 미연결, 별도 전체 디코딩 중복, 유효 프레임 1개로 확정 가능, 저정보 프레임의 증거 포함, 장편 고정 앵커 간격, estimatedContent 미활용, PreCredits 미할당, 점수-판정 불일치, 어두운 장면 성급한 DIFF.
- V3는 production default로 유지한다. V2는 검증 완료 전까지 실험 경로다.

## 2. 기존 구조

- V1(`src/temporal_anchor.{h,cpp}`, 0.9.4.172): 정방향 시작점 탐색, 중간 앵커 비교, 연속 프레임 검증, 저정보 필터링. V1 함수들은 본 빌드에서 동작을 바꾸지 않는다(동결).
- V3(DTW) segmented kept가 production 기본값. 엔진/DB/스키마/캐시 불변.

## 3. 변경 구조

- V2 API(`temporalAnchorSimilarityV2`, `TemporalAnchorV2Result`, `findLeadingOffsetV2`, `findEndingProbe`, `anchorCentersForDuration`, `anchorVerdictScore/For`): V1과 같은 인덱스 타입을 공유하되 오케스트레이션이 분리되어 V1 결과와 비교 가능하다.
- 양방향 탐색: 정방향 오프닝 프로브 + 역방향 엔딩 탐색(어둠만으로 크레딧 판정 금지, HDR 야간/페이드아웃 오인 방지 — edge 상승 증거가 있어야 PreCredits), 종료점 역산 중간 앵커, 정방향/역방향 오프셋 일치 확인.
- 길이 정책: micro ≤13 s(시작/중간/끝), ≤60 s(3등분), ≤25 min(시작/중앙/후반/엔딩), 장편(정방향 5/10/15분 + 역방향 5/10/15분).
- 구간 분리: 기본 1구간, 드리프트 검증 시 최대 2구간. 부분 일치로 DUP를 강제하지 않는다.
- 통합 판정(단일 정의, 코드·테스트·문서 공유): score = 40·min(validMain,2) + 10·consistent + 10·endingSupport (상한 100). DUP는 validMain≥2 + 오프셋 일관 + covered-failed 없음 + 드리프트 없음 + content-ratio 플래그 없음 + score≥87.5를 모두 만족할 때만. 저정보 프레임은 증거에서 제외(비저정보 ≥2 프레임 필수). 반대 증거 없는 어두움은 DIFF가 아니라 UNCERTAIN.
- 단일 sweep 통합(§7): V3 플랜에 앵커 플랜을 합친 merged sweep 1회로 V3 지문과 앵커 인덱스를 함께 만든다. V3는 자기 타임스탬프만 소비하므로 armed/un refugié 모두 V3 지문 바이트 동일이 파일 테스트로 단언된다. 영속 캐시 포맷 불변(앵커는 메모리 전용).
- 실제 제품 경로 연결(§8): ScanPipeline flush 워커에서 armed(전략 opt-in + `MSF_VIDEO_ANCHOR=1`)이고 양쪽 인덱스가 메모리에 있을 때만 비교하고, 결과는 가산 텔레메트리(`videoAnchor*`)로만 기록한다. V3 판정은 그대로이므로 armed 스캔도 매치 집합이 바이트 동일함이 스캔 테스트로 단언된다.
- GUI: 동영상 탭 전략 콤보에 TemporalAnchorV2 항목 추가(기본값 LegacyV3 불변), QSettings/IPC/backend 매핑, tr 키 1종 추가.
- 테스트: 합성 13핀(V2 매핑표, 단일 프레임 비증거, 저정보 제외, 길이 정책, 크레딧 탐지/비탐지, 양방향 리더 DUP, 중간 삽입 UNCERTAIN+2구간, 어두움 UNCERTAIN, 공유 엔딩 비확정, 비율 플래그, 중복 계산 금지), 실디코딩 파일 테스트(union==separate, V2 DUP/오프셋, stranger 비DUP, disarmed 무인덱스), 스캔 경로 테스트(LegacyV3 vs armed V2 매치 집합 동일).

## 4. 해결된 상황

- V1 동결 증거: V1 13핀이 전부 그대로 PASS하고, 동일 필드셋에서 V1 수치(아래 §5)가 재현된다. V1 함수 본문은 손대지 않았고, V2 엄격 탐색은 별도 함수(`findLeadingOffsetV2`)로 분리했다.
- 미니셋 핵심 입증: **L04+중간 30초 삽입 — V1 DUP 85(오판) → V2 UNCERTAIN 80 + 2구간 분리(정답)**. 지시 §4의 요구사항이 실측으로 확인됐다.
- GoT 동일 회차 판정: L02-lead vs L03-orig/reenc/flip이 V1 85 / V2 90 DUP. 3개 시점(t=300/600/900 vs +3초) 프레임을 직접 대조해 동일 장면임을 시각 검증했으므로 V2의 DUP는 정탐이고, V3의 0.00 DIFF가 miss였다.

산술 정정(지시 §9 요구): 동일 50쌍의 내역은 verdict 기준 **DUP 1 + UNCERTAIN 44 + DIFF 5 = 50**이다. 기존 보고서의 "11"은 score≥50 개수(내역: DUP 1 + UNCERTAIN 10)이며 verdict와 혼합된 지표였다. 본 보고서부터 점수와 verdict를 분리 표기한다.

TP/FP/FN/TN (동일=positive, GoT 동일회차는 positive로 집계):
- L 15쌍: V2 TP=12, FN=3(전부 UNCERTAIN, 성급한 DIFF 0). 교차 138쌍: FP=0, TN=138.
- f 50쌍: V2 TP=5, FN=45(UNCERTAIN 35 + DIFF 10). 교차 4900쌍: FP=0, TN=4900.
- V1 대비: L TP 동률(12)이지만 L02-lead의 DIFF가 UNCERTAIN으로 교정됐고, f TP 1→5, f FN의 DIFF 5→10은 점수 상승분(≥87.5 0→10)이 verdict 문턱에서 UNCERTAIN으로 걸러진 결과다. DUP 0 FP 정책(오탐=비가역 삭제 위험)을 유지한다.

성능(§7): 앵커 인덱스는 merged sweep의 부산물이므로 **중복 전체 디코딩 없음**(V1의 별도 sweep 제거). 비교 자체는 메모리 내 연산이다. 측정 wall: L 20파일 인덱스+380쌍×2전략 약 61분(대형 30~93분 파일 디코드 지배), f 100파일 인덱스+9900비교 약 8분, 미니 6파일 약 10분. 파일별 디코드/비교 시간은 TSV BUILD 행에 기록된다.

## 6. 향후 영향 및 한계

- 판정 불변: 기본 경로 바이트 동일, 엔진/DB/schema/cache 불변 — 저장 쌍 재검증 없음. armed 스캔도 매치 집합이 동일하다.
- **Gate PASS 선언 안 함, 기본값 승격 없음**: HDR 동일 콘텐츠(L02-lead), 180초 리더 경계, 평탄 오프닝, 2구간 초과 중간 삽입, 실파일 PreCredits, 임계값 교정이 미검증/후속이다. 미검증 부분은 진단/opt-in으로 남는다.
- 알려진 한계: 어두운 오프닝/HDR pHash 불안정, 단일 프레임 87.5 strictness, ending은 NoCredits/Uncertain 위주(PreCredits는 edge 증거 있을 때만), 180초 리더는 양쪽 모두 미탐.
- 롤백: GUI에서 LegacyV3 선택(기본값) + `MSF_VIDEO_ANCHOR` 미설정. 앵커 산출물은 메모리 전용이라 잔류물이 없다.

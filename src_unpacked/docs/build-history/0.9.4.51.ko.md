`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변.

## 1. 변경 필요성

fingerprint 단계는 수 분간 전체 파일을 읽으면서 UI에 아무것도 보고하지
않았다. 사용자는 디스크 I/O만 발생하고 모든 카운터가 0인 화면을 봤다
(`images.count`는 분석 단계 전용이라 fingerprint 중에는 원래 안 움직임).

경로 추적에서 내제 문제 2건을 추가로 확정했다.

- **telemetry OFF여도 fingerprint가 돈다.** `setDatasetFingerprint()` 호출이
  무조건이라 Detailed Logs 체크 해제 시에도 전체 해시 I/O를 지불한다.
  fingerprint 결과는 스캔 동작에 쓰이지 않으므로 완전한 낭비다.
- scope-blind hashing (이미지 전용 스캔에서도 비디오까지 해시)은 fingerprint
  정의를 바꾸는 일이라 손대지 않고 별도 과제로 둔다.

## 2. 기존 구조

- `computeDatasetFingerprint(root, cancel)` — progress 파라미터 없음
- `ScanControl`에 fingerprint 콜백 없음
- `scan()`은 telemetry on/off와 무관하게 항상 fingerprint 실행

## 3. 변경 구조

### 진행 보고 (기존 percent 로직 불변)

- `ScanControl::fingerprintProgress(filesHashed, bytesHashed, path)` 신설
- `computeDatasetFingerprint(root, cancel, progress)` — 해시한 파일마다 호출.
  내부 스로틀 없음, UI가 스로틀
- `scan()`에서 control 콜백으로 전달
- GUI는 별도 signal `fingerprintProgress(qulonglong,qulonglong,QString)`로
  받는다. walk/analysis percent 계산을 건드리지 않는다

### GUI 표시

- 150ms 스로틀 (walk 콜백과 동일). 수천 파일/초 해시에도 이벤트 루프 보호
- indeterminate 바 + `지문 생성 중: N files, X.X GB — path` 표시
- 경로 72자 초과 시 뒤 69자만 (`...` prefix)
- 번역 키 `fpProgress` 추가, tr-keys gate 등록 (`checked=57`)

### telemetry OFF 스킵

```cpp
if (telemetryOn) { setPhase; setDatasetFingerprint(...); }
```

telemetry OFF면 fingerprint를 실행하지 않고 `not_available` 그대로 둔다.
control null이어도 안전 (기존 ternary 유지).

## 4. 해결된 상황

- fingerprint 중 실시간 진행 표시 (파일 수 + GB)
- Detailed Logs 해제 시 수 분의 해시 I/O 절약
- 정상 완료·취소·의미 불변

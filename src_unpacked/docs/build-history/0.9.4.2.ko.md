# MediaSimilarityFinder v0.9.4.2 — Node B1: Minimal Adaptive Allocation

B1 최초 검증 기준점. brief의 B1 테이블(GPU OFF→CPU 100%, 유효
GPU→분배, 느린 GPU→CPU 중심 가능, unavailable→fallback, parity)을
구현한다. 엔진 1.5.0·DB 1.0.3·캐시 v9·benchmark schema 1 불변.

## 변경 필요성
- 0.9.4.1까지 GPU 사용 여부는 `policy_.gpuEnabled` boolean 하나로
  결정됐다. 배분율·판단 근거·재평가라는 개념이 없어 Node B의 나머지
  단계(B2~B6)가 올라갈 구조가 없었다.

## 기존 구조
- 이미지 배치와 비디오 빌드가 `policy_.gpuEnabled`를 직접 참조.
- `SchedulerTelemetry`는 구조만 있고 항상 `not_measured`였다.

## 변경 구조
- 신규 `src/scheduler.h/.cpp` — `CpuGpuScheduler`:
  입력(CPU 스레드 수·GPU ON/OFF·가용성·SM 수)과 출력(CPU/GPU share·
  backend·reason·gpuUsed). 용량 단위는 상대값이며 비율만 쓴다.
  reason 코드: `gpu_off` / `gpu_unavailable` / `no_gpu_capacity` /
  `proportional_baseline`. 고정 분할 없음 — 저사양 GPU는 비례식으로
  CPU 중심에 수렴한다.
- 재평가: `maybeReevaluate(hw, tick)` + 기본 2000ms 주기. 이미지 배치와
  비디오 구간 진입점(기존 람다, 구조 변경 없음)에서 호출한다. 안정
  입력에는 조정 카운터가 오르지 않는다.
- 엔진 배선: 스캔 시작 시 1회 `decide()`하고, 두 게이트를
  `schedUseGpu`로 교체한다. ON+가용이면 기존과 동일하게 GPU를 쓰고,
  OFF/비가용이면 CPU로 간다 — 판정 동작 불변.
- Telemetry: `finishScan`에서 scheduler 섹션을 `measured`로 기록한다
  (초기=현재 용량, shares, backend, 조정 횟수, 이미지+비디오 fallback
  합). `BenchmarkRecorder::videoGpuFallbacks()` getter 1개 추가.
- `GpuBackend::computeUnits()` (CUDA SM 수, additive) +
  `MediaPipeline::gpuComputeUnits()` 전달 1줄.
- B2 이후 항목(moving average·hysteresis·transfer/workload cost·외부
  부하)과 D의 pipeline/queue 변경은 손대지 않았다.

## 선택 이유
- B1은 얇게가 원칙이라, 기존 게이트 위치를 그대로 쓰고 판단 구조만
  얹었다. 판정 경로에 손을 대지 않았으므로 parity는 구조적으로 보존된다.
- SM 수 vs 스레드 수 비율은 B1의 출발 프록시임을 주석·문서에 명시했다.
  실측 throughput(B2)과 calibration(C)이 교체한다.

## 해결된 문제
- 스케줄러 판단이 구조+테스트+telemetry로 존재한다. B2는 입력만
  늘리면 된다.

## 정확성 영향
- 없음. 게이트 교체는 ON+가용→GPU / 그 외→CPU로 기존과 동일하다.
  `scan_workflow_test`가 양쪽 트리에서 동일 1그룹으로 이를 입증한다.
  `search_engine_test`·`video_scan_e2e_test`·`match_revalidate_test`·
  `fingerprint_fast_test`·`video_decode_parity_test`·`scan_pipeline_test`
  양쪽 통과.

## 호환성 영향
- Benchmark JSON은 기존 키 유지, scheduler 섹션이 실측으로 채워진다.
- `MSF_ENABLE_CUDA` 별칭·`ScanWorker` 구 생성자 등 기존 호환 유지.

## 향후 영향
- B2는 throughput 입력 + `SchedulerHardware` 확장만으로 진입한다.
- B1 용량 프록시는 잠정치이며 B2/C에서 교체된다. 공유합 100 규칙과
  reason 코드는 유지한다.

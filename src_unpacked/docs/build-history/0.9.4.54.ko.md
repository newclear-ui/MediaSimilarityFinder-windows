# MediaSimilarityFinder v0.9.4.54 — 읽기 카운터 실시간화 + 리포트 팝업 hang hardening

기준선 `0.9.4.53` → 본 빌드 `0.9.4.54`.
CPU CTest **105/105**, GPU CTest **106/106**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 테스트 수 불변.

## 1. 변경 필요성

두 증상이 보고됐다.

1. 디스크 I/O가 발생하고 파일이 실제로 읽히는데 "읽기 완료" 카운터가 안 움직임
2. 검색 정지 후 "검색 리포트 작성중" 팝업이 뜨지만 완료되지 않음

## 2. 원인 1: 패널이 live 값을 안 읽었다

- fingerprint 단계: 패널 업데이트 콜백이 전혀 없어 0 고정. `onFingerprintProgress`
  는 statusMsg만 건드렸다.
- `sumValIndexed_`는 스캔 종료 후 스냅샷에서만 기록. 스캔 중 내내 "-"였다.
- `updateStatusCounts()`는 스캔 중 `sumValDone_`를 walked "X / Y" 형식으로
  덮어써, 새 plain-number 의미와 충돌했다.

## 3. 원인 2: `scanFinished`에 예외 탈출구가 없었다

팝업 close와 `setRunning(false)`가 함수 끝에 무방비로 있었다. 본문 10여 개
호출 중 하나라도 던지면 팝업이 영원히 열려 있고 GUI는 idle로 못 돌아간다.
flush/prune/walker는 bounded임을 코드로 확인했으므로, 남는 위험은 이
예외 경로다.

## 4. 변경 구조

### 읽기 완료 실시간화

- `onFingerprintProgress`가 `sumValDone_`도 함께 갱신 (해시한 파일 수)
- 엔진에 `analyzedCount()` atomic 접근자 추가. `r.analyzed` 증가 지점과
  동일 위치에서 증가하므로 live 값과 최종 리포트가 구조상 일치
- `updateStatusCounts`는 스캔 중 `sumValDone_`(읽기, plain number)와
  `sumValIndexed_`(엔진 live analyzed)를 갱신. post-scan 형식과 통일

### scanFinished hardening

본문을 try/catch로 감싸 팝업 close + idle 복귀를 보장. 예외는 scanLog에
기록하고 상태는 보존한다. hang 자체를 고치는 게 아니라, 예외 시에도 팝업이
남지 않게 하는 방어다.

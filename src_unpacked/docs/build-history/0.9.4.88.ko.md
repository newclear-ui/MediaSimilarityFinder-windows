# MediaSimilarityFinder v0.9.4.88 — 통합 CPU 표기 (GUI + 백엔드 + 백엔드 자식)

기준선 `0.9.4.87` → 본 빌드 `0.9.4.88`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변.

## 1. 변경 필요성

사용자 보고: 스캔 중 대량의 CPU를 소모하는데 검색 요약 패널은 ≤10%로 표기.

조사 결과, 종전 표기는 **"작업 프로세스 1개"(프로덕션=백엔드)** 만 측정했다.
이 프로그램이 실행하는 다음 CPU 소비자는 합산되지 않았다:
- **자식 프로세스**: `nvidia-smi`(스케줄러/모니터 GPU 샘플, `monitor.cpp:60`) — **모든 스캔 중 3초마다**, `ffprobe`(해상도 조회, `file_meta.cpp:19` ← `BackendSession::requestFileMeta`), `ffmpeg`(비디오 디코드, FFmpeg 미링크 빌드 한정).
- **GUI 프로세스** 자체(그룹/썸네일 렌더링 등).

이들은 모두 `captureSilent`(`CreateProcessA`)로 별도 프로세스라 백엔드의
`GetProcessTimes(GetCurrentProcess())`에 잡히지 않는다.

## 2. 기존 구조

- `sampleOwnProcess` = **현재 프로세스** CPU(0–100, 전체 코어 기준). 백엔드는 자기만, GUI는 표시 시 `backendCpu`만 사용.
- 텔레메트리 `cpuProc`(상세 로그)도 `GetProcessTimes(GetCurrentProcess())` = 백엔드 단독.

## 3. 변경 구조

- **(A) 백엔드 = 프로세스 트리**: `backend_sysinfo.cpp::sampleProcessTree` 추가. 백엔드를 **Job Object**에 자기 등록하면 이후 자식(captureSilent spawn)이 상속되고, `QueryInformationJobObject(JobObjectBasicAccountingInformation)`의 `TotalUserTime/TotalKernelTime`이 **이미 종료된 단명 자식까지 누적**한다. Job 생성 실패 시 백엔드 단독으로 폴백. `backend_main::onHealthTick`이 이걸 사용.
- **(B) GUI = 자기 자신 + 백엔드**: GUI에 `cpuTimer_`(1초)로 `sampleOwnProcess`(GUI 프로세스) 샘플 → `guiCpu_`. `onStatusSnapshot`에서 `clamp(guiCpu_ + st.backendCpu, 0, 100)` 표기.
- **(C) 상세 로그 일관성**: `TelemetryRecorder::sampleOnce`의 `cpuProc`도 `processTreeCpuTicks`(공유 Job, 호출자별 prev)로 변경 → GUI 패널과 상세 로그가 같은 통합 기준.
- **(D) loopback 이중계산 방지**: `BackendClient::separateProcess()`(supervisor=true, loopback=false). loopback에서 `guiCpu_=0`(GUI=작업 프로세스).
- **제외(의도)**: 사용자 동작 spawn(`explorer.exe` 탐색기에서 보기, 기본앱 열기)과 Defender/OS 등 프로그램과 무관한 프로세스는 트리/표시에 포함하지 않는다.

## 4. 해결된 상황

- 요약 패널과 상세 로그의 CPU가 **GUI + 백엔드 + 백엔드 자식(nvidia-smi/ffprobe)** 을 포함한다.
- 사용자 동작/무관 프로세스는 제외.

## 5. 검증

```text
CPU Release CTest 100% tests passed out of 122
GPU Release CTest 100% tests passed out of 123
GUI/Backend --version 0.9.4.88
```

- **GUI 육안/repro 확인 필요**: 실제 스캔에서 패널 CPU가 백엔드 단독보다 높게(자식 포함) 표기되는지.

## 6. 주의: `cpuProc` 의미 변경 (AGENTS 9항)

- **`cpuProc`(상세 로그) 정의가 "이 프로세스 CPU" → "프로세스 트리 CPU"로 바뀌었다.**
  이전 빌드(`0.9.4.87` 이하)의 `cpuProcMean/Max`와 **직접 비교 불가**하다. 이후 측정의
  새 기준으로 삼는다. 상태: SUPERSEDED(이전 정의).

## 7. 향후 영향 및 한계

- Job Object는 측정 전용(제한·kill-on-close 없음)이라 수명/종료 동작을 바꾸지 않는다.
  이미 다른 Job에 속한 환경(중첩 Job 미지원)에서는 백엔드 단독으로 폴백할 수 있다.
- nvidia-smi/ffprobe의 존재 자체를 없애는 최적화(스폰 감소)와는 별개다. 이번 빌드는
  "표기 정확성"을 다룬다.

# MediaSimilarityFinder v0.9.4.150 — Date sort (creation date) added

Baseline `0.9.4.149` → this build `0.9.4.150`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` / `kProtocol 1` unchanged (judgement unchanged).

## 1. Why the change was needed

- The sort combo had four modes (None/Group size/Similarity/Name); there was no way to bring groups with the most recently added files to the top.
- Request: add a date-based sort so recently added files come up. Creation date chosen as the key (user decision).

## 2. Previous structure

- `rebuildGroups()` branched on `kSortNone/Size/Sim/Name` (0-3). No per-group date key existed, and no `sortDate` translation key.
- The on-demand cached-stat pattern (`fileSizeCached()`) existed but had no date counterpart.

## 3. New structure

- New sort mode `kSortDate = 4`, appended last in the combo as `sortDate` (날짜/Date). Indices 0-3 are untouched, so scroll/scan-lock tests are unaffected.
- Group key = newest member creation date (`QFileInfo::birthTime()`; `lastModified()` when birthTime is unavailable, 0 for missing files). Descending (the default) puts the most recently added files first. Ties break by ascending path (same as the other modes).
- New `fileDateCached()`: cached in the `fileDate_` hash, cleared whenever a new result set replaces the view (`onResults`/Load/Re-verify). Local stat only, no backend/IPC change (per the 0.9.4.117 FILE_META-storm lesson).
- Default direction: descending (0) for Date. The existing rule (`idx == kSortName ? 1 : 0`) already yields that, so no change was needed.
- The None baseline (`noneOrder_`) refreshes in None mode only, so Date sorting never touches it.

## 4. Resolved state

- Picking Date in the sort combo brings groups holding the most recently added files to the top (descending default). Ascending shows the oldest first.

## 6. Impact and limits

- Display-only change (judgement, storage, protocol, engine/DB/schema/cache unchanged).
- When the filesystem provides no creation date, modification date is used instead (e.g. network drives). Copied files get the copy time as creation date, which matches "added order".

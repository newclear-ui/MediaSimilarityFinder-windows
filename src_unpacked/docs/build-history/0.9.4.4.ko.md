# MediaSimilarityFinder v0.9.4.4 — Node B3: Live Load Awareness

B3 검증 기준점. brief §7의 입력(CPU/GPU 부하·VRAM·queue 상태·외부
부하)을 배선한다. 엔진 1.5.0·DB 1.0.3·캐시 v9·schema 1 불변.

## 변경 필요성
- B2까지 스케줄러는 하드웨어가 비어 있다고 가정했다. 게임 같은 외부
  부하가 걸리면 배분이 현실과 어긋난다.

## 기존 구조
- `SchedulerHardware`에 부하 입력이 없고, `SystemLoadMonitor`는
  모니터 경로에서만 쓰였다.

## 변경 구조
- `SchedulerHardware`에 시스템 부하 입력 추가(cpuLoad·gpuLoad·
  memPressure + known 플래그). queue depth 필드는 D1 예약으로
  함께 두되 B3 판단에서는 무시한다(생산자 부재 명시).
- headroom 규칙(`effectivePair`): CPU는 `(100-sysCpu)/100`에 하한
  0.05(자기 부하로 자신을 0에 수렴시키지 않음), GPU는 하한 없음
  (시스템 GPU%는 외부 지배라 완전 경합 시 CPU 수렴이 정답).
  memPressure는 기록용(B6 정책 몫). 완전 GPU kill 시 reason
  `external_load_throttle` + edge 카운트.
- 엔진은 스캔당 `SystemLoadMonitor` 1개를 두고 decide/재평가 지점에서
  갱신한다(첫 CPU 델타는 0, GPU%는 3초 캐시라 2초 주기에 추가
  nvidia-smi 비용 없음).
- `externalLoadThrottling`을 스케줄러 edge 카운터로 채운다.
  `throttlingEvents`는 0 유지(B4+ 몫).
- 스무딩·hysteresis 없음(B4). transfer/workload 없음(B5).

## 선택 이유
- 정밀한 외부 부하 귀속(자기분 분리)은 B4+ 런타임 회계의 몫이다.
  B3는 headroom 신호를 정직한 하한과 함께 반영하는 데 그친다.
- queue는 관측자(D1) 없이 입력만 받는 게 거짓이므로, 필드 예약 +
  무시 명시로 D1과의 인터페이스 churn을 막았다.

## 해결된 문제
- 스케줄러가 live 부하를 본다. B4는 전이만 다듬으면 된다.

## 정확성 영향
- 없음. 게이트·판정 경로 무변경. 부하 미상 구간은 B2와 동일하다.
  양쪽 `scan_workflow_test` 동일 결과.

## 호환성 영향
- Benchmark JSON 키 불변, schemaVersion 유지(확장 없음).
  `current*Capacity`에 부하 반영값이 들어간다.

# MediaSimilarityFinder v0.9.4.108 — 상세 로그 요약 헤더 (검색 방법 + 검색 폴더)

기준선 `0.9.4.107` → 본 빌드 `0.9.4.108`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 요청: 상세 로그 팝업의 검색 요약 **최상단에 검색 방법(안정/고속/자동 = B/A/AB)을 표기**하고, **두 번째 항에 검색한 폴더 경로**를 추가할 것 — 모드를 사용자가 따로 기록하지 않아도 되게.

계기: 0.9.4.107 실측 run(`detailed-log-2026-10-16T041623.json`)은 사용자가 AB(자동)로 요청했지만 기록의 `analyze.mode`는 **A(고속형)**였다. 요약 화면에는 모드가 어디에도 없어 사용자가 확인할 방법이 없었다 — 표시 개선의 필요성이 실측으로 확인됐다.

## 2. 기존 구조

- `showDetailedLogDialog`(gui/mainwindow.cpp)가 텔레메트리 JSON을 파싱해 `== 검색 요약 ==` 블록을 만들지만, 모드(`analyze.mode`)와 폴더(`meta.root`)는 표시하지 않았다.
- 모드는 설정 콤보(`analyzeModeStable/Fast/Auto` 라벨)에만 존재했고 로그/리포트에는 없었다.

## 3. 변경 구조

- 요약 헤더 직후 첫 두 항으로 추가:
  - `검색 방법: <안정형 (스캔 후 검증) | 고속형 (스캔 중 검증) | 자동 (혼합 검증)>` — 값은 **기록의 `analyze.mode`(B/A/AB)** 를 기존 번역 라벨로 매핑. 현재 설정이 아니라 기록 기반이므로 과거 로그도 자신의 모드를 정확히 표시한다. 모드 필드가 없는 구버전 기록은 `-`.
  - `검색 폴더: <meta.root>` — 기록의 스캔 루트. 없으면 `-`.
- 번역키 2개 추가(`summaryMode`/`summaryFolder`), tr-keys **71 → 73**. `ui_settings_test` 키 목록 등록.
- 표시 전용 — 판정·저장·프로토콜 불변.

## 4. 해결된 상황

- 검색 요약만 보면 어떤 매칭 검증 방식으로 돌린 run인지 즉시 알 수 있다(수기 기록 불필요). 실측에서 발생한 "AB로 요청했지만 A 기록" 같은 불일치를 사용자가 화면에서 바로 확인할 수 있다.
- 검색 폴더 경로가 요약에 남아 여러 폴더를 운용할 때 로그만으로 출처가 명확해진다.

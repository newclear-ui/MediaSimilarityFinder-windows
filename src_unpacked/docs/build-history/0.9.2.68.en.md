# MediaSimilarityFinder v0.9.2.68 — QuickLook Integration Resume

## Need for change
A QuickLook preview entry in the file context menu was requested. The work implemented and verified on the `quicklook-paused` branch (0.9.2.64 dev) was re-applied onto the current baseline (0.9.2.67). The audit-flagged `_wgetenv` null guard went in with the resume.

## Previous structure
- File menu top was "Open" (full application launch). No QuickLook entry

## New structure
- **Detection**: ProgramFiles/ProgramFiles(x86)/LocalAppData/Scoop + Uninstall registry (machine+user). Live-pipe presence doubles as detection (Store edition has no launchable exe, so it integrates only while running)
- **Trigger**: QuickLook's native pipe protocol verbatim (`Toggle|<path>|\n`, UTF-8). Launches the exe and waits up to 2.5s when installed-but-idle. Menu entry on top when either signal is present, hidden otherwise
- **Guard**: `_wgetenv` null maps to empty (audit follow-up)
- `quicklook_pipe_test`: exact-bytes check against a fake pipe server (60B incl. Korean + space)
- Version strings unified → 0.9.2.68

## Resolved situation
- On QuickLook PCs, right-click → top preview entry opens media instantly. PCs without it never see the entry, no confusion

## Validation
- Core+GUI Release build: PASS, **CTest 52/52 PASS** (incl. `quicklook_pipe_test`)
- `--version` 0.9.2.68, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)

## Future impact
- Store-edition + idle hides the entry (run-prompt copy is a candidate)
- The pipe protocol tracks QuickLook versions. A protocol change breaks the test first, so it self-reports

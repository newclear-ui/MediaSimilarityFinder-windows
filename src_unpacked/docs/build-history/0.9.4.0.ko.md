# MediaSimilarityFinder v0.9.4.0 — Node A: Foundation / Terminology / Instrumentation

0.9.4 개발선 Node A의 검증 기준점. 상위 GPU 용어 정리, GPU ON/OFF 구조,
build 명칭 정리, benchmark instrumentation 공통 기반을 구현한다.
엔진 1.5.0·DB 1.0.3·비디오 캐시 v9는 불변이다.

## 변경 필요성
- 0.9.3.19까지 GPU라는 말이 제품 전반에서 NVIDIA CUDA를 가리켰고,
  사용자에게 GPU 25/50/75/100% 수동 조절 UI가 노출되어 있었다.
  Adaptive Scheduler(Node B)와 calibration(Node C)이 쓸 계측 구조도 없었다.
- 미측정 값이 숫자 0으로 저장되어(`resources.samples = 0`,
  `diskAvailable: false` + 볼륨 문자열 등) "실제 0"과 "측정 안 됨"을
  구분할 수 없었다(Roadmap A 종료 조건 위반).

## 기존 구조
- `MSF_ENABLE_CUDA` 단일 옵션, `build-windows-cuda` 트리,
  `GpuBackend`가 CUDA 구현을 직접 감쌈(상위 추상 명칭 없음).
- `ResourcePolicy.gpuPercent` + 툴바 `GPU %` 스핀박스(사용자 직접 입력).
- Benchmark JSON에 스키마 버전 없음, `completed` 단일 boolean,
  `frames` 단일 카운트, scheduler/calibration 기록 구조 없음.

## 변경 구조
- GPU 추상화: `GpuBackendKind { Auto, Cuda, Cpu }` + `backendName()`.
  Auto는 CUDA 장치 존재 시 CUDA, 아니면 CPU fallback으로 귀결된다.
  미구현 backend(Vulkan/HIP/Level Zero)는 코드·표시 어디에도 두지 않았다.
- CMake: `MSF_ENABLE_GPU` + `MSF_GPU_BACKEND`(AUTO/CUDA/CPU)가 정식 개념.
  `MSF_ENABLE_CUDA`는 deprecated 호환 별칭으로 유지,
  `MSF_HAS_GPU`를 `MSF_HAS_CUDA`와 함께 정의한다.
  `windows-gpu` 프리셋 + `scripts/build_windows_gpu.ps1` 신설,
  `build-windows-gpu`를 clean configure로 생성. 기존
  `build-windows-cuda` 트리·프리셋·스크립트는 손대지 않고 보존한다.
- UI: 툴바 `GPU %` 스핀박스 제거. GPU는 ON/OFF 체크박스만 남는다.
  CPU 프리셋 값·Custom CPU 입력·monitor 게이트 의미는 그대로이며,
  내부 `gpuPercent` cap도 Node B까지 deprecated 상태로 동결했다.
- Benchmark: `schemaVersion: 1` + `runId` 독립 관리.
  `measured / not_measured / not_available / partial / failed / fallback`
  상태를 `MeasureState`로 구분하고, 미기록 수치는 `null` + 상태로
  내보낸다. `decodedFrames`/`sampledFrames` 분리(캐시 히트는 decode 0을
  측정값으로, sample plan 미상은 미측정으로 기록),
  stage 객체(`enumeration … revalidation`, 미기록은 `not_measured`),
  `scheduler`/`calibration` 구조체(Node B/C가 채움, 지금은
  `not_measured`), `cancelled / paused / failed / failedStage /
  completionReason / files{started,completed,remaining}` 추가,
  디스크 가용성은 샘플링 기간 값으로 래치한다.
  기존 키는 모두 유지하므로 구 파서는 깨지지 않는다.
- About 문구의 `(CPU/CUDA)`를 `(CPU/GPU)`로 수정(CUDA는 일반명이 아님).

## 선택 이유
- 동작 변경이 아니라 기반 마련이 목표이므로, 검색 판정에 닿는 코드는
  건드리지 않고 구조·계측만 additive로 추가했다.
  `gpuPercent` 내부 cap을 당장 삭제하지 않은 것도 같은 이유다(삭제는
  Node B 스케줄러와 함께).
- 새 GPU 트리를 clean configure로 만든 것은旧 트리 이름 변경 재사용이
  CMake 캐시 오염을 일으킨다는 로드맵 경고를 따른 것이다.

## 해결된 문제
- Node A 종료 조건 8항(용어 분리·ON/OFF 구조·미측정=0 제거·CPU
  fallback·회귀 통과·build/CMake 정리·버전 일치)을 모두 충족한다.
- `diskAvailable: false` + 유효 볼륨 증상은 원인(첫 수집 실패를 치명
  오류로 간주, 0.9.3.19에서 수정)과 함께, 이제 `diskState` 래치로
  재발을 구분할 수 있다.

## 정확성 영향
- 없음. 지문·유사도·임계·캐시·타임스탬프 경로 무변경.
  `benchmark_test`·`search_engine_test`·`video_scan_e2e_test`·
  `match_revalidate_test`·`scan_pipeline_test`가 양쪽 트리에서 통과한다.
- Benchmark ON/OFF가 판정을 바꾸지 않음은 기존 설계 그대로이며,
  추가된 계측은 읽기 전용 누적 + JSON 직렬화뿐이다.

## 호환성 영향
- Benchmark JSON은 additive 확장이다. 기존 키 유지, 신규 키 추가.
  `schemaVersion`은 엔진/DB 버전과 독립적으로 1에서 시작한다.
- `MSF_ENABLE_CUDA`·`windows-cuda` 프리셋·`build_windows_cuda.ps1`·
  `ScanWorker` 구 생성자는 deprecated 호환으로 유지한다.

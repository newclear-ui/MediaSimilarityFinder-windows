# MediaSimilarityFinder v0.9.4.134 — 빠른 재스캔 모드(설정) + 강제 재검증(중복 파일만)

기준선 `0.9.4.133` → 본 빌드 `0.9.4.134`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (판정 불변, CTest 등록 수 불변).

## 1. 변경 필요성

- 실측(0.9.4.133): 무변경 재스캔이 걷기에서만 5분(177,887파일, 21.2GB 읽기)이고 앱 CPU는 1.66% — **파일 열기 I/O가 지배**하며 백신(Defender 31%)이 따라붙는다. 변경 감지를 위해 파일마다 64KiB quick-hash를 다시 읽는 비용이 대부분이다.
- 사용자 결정: ① 재스캔 무결성 모드 분리(엄격/빠름) ② 불러오기에 강제 재검증(중복 파일만)을 적용. ③ Test Mode의 차이 리포트 + Yes/No 채택은 다음 빌드로 이월(설계 확정, 이번 범위 아님).

## 2. 기존 구조

- 걷기는 모든 미디어 파일의 64KiB 해시를 매번 계산하고, `processOne`이 `(size, mtime, quickHash)` 3중 비교로 변경을 판정했다(media_search_engine.cpp:964). 저장 쌍은 재검증 경로(engine bump)에서만 갱신됐고, 사용자가 임의로 중복 구성원을 재확인할 수단은 없었다.

## 3. 변경 구조

### ① 빠른 재스캔 (설정 → 일반 → "빠른 재스캔 (크기·수정시각만 비교)", 기본 OFF=엄격)

- `ScanControl.fastRescan` + `ScanWorker/BackendScanConfig/supervisor START_SCAN payload/backend_main` 전달 경로. 상세 로그 `config.fastRescan`에 provenance 기록(JSON 키 추가, additive).
- 걷기: `Scanner::ScanCallbacks.skipQuickHash` 술어 신설. 엔진이 **저장 행이 있고 (size,mtime)가 일치하며 재분석이 필요 없는 파일에 한해** true를 반환하면 해시를 읽지 않는다. 재분석 예정 파일(pendingAnalysis)·stat 불일치·video regrid는 반드시 해시를 계산해 새 행에 기록한다(배지·지문 캐시 키 보존). 해시 계산은 단일 구현 `Scanner::quickHash64k`로 통일.
- 변경 판정: 빠름 모드에서도 quick-hash 항을 비교하지 않도록 `changed` 조건 분기. 빈 해시를 "불일치"로 오인하지 않는다(엄격 모드 불변).
- 보완(사용자 요청 반영): 기본값은 **엄격**(기존 동작·판정 불변), 도움말에 잔여 위험(크기·수정시각 보존 변경 미감지)과 재검증 권장을 명시.

### ② 강제 재검증 (툴바 "재검증", 중복 구성원만)

- `MediaSearchEngine::reverifyStoredDuplicates`: 저장 쌍의 **구성원 경로만** stat+64KiB 해시를 다시 읽어 저장값과 비교(걷기 없음). 불일치 구성원만 재분석(이미지 배치/비디오 단일) 후, 변경 파일에 닿는 쌍만 **A/AB와 동일한 targeted 파이프라인 패스**(d=8)로 재검증·재발견한다. 변경과 무관한 저장 쌍은 그대로 유지.
- 원자성: 행 갱신·쌍 저장·매치 세트 교체가 **하나의 트랜잭션**에서 수행된다(`Database::saveMatchesNoTransaction` 신설, saveMatches는 내부 공용 구현으로 분리). 취소·실패 시 행/쌍 모두 롤백 — 부분 반영 없음.
- IPC `REVERIFY_INDEX`(additive 명령) → 백엔드 워커 스레드에서 실행(로드와 동일 규칙) → `results()`로 화면 갱신 + `REVERIFY_FINISHED` 카운터 이벤트. GUI: 툴바 "재검증" 버튼, 로드형 흐름(팝업/요약 채움), 상태줄 `재검증 완료 — 확인 N · 변경 M · 재분석 K · 매치 A → B`.
- 한계(문서화): 대상은 저장된 중복 구성원뿐이며, 새로 중복이 생기는 경우는 일반 스캔 몫이다. 이미지 거리 8 고정(GUI 스캔과 동일).

## 4. 해결된 상황

- 무변경 재스캔: 파일 열기가 사라져 걷기 시간이 I/O 지연이 아닌 열거 비용으로 수렴하고, 백신 개입도 급감(사용자 환경의 Defender 31% 소비 경로 제거).
- 빠름 모드의 사각지대(크기·수정시각 보존 변경)는 "재검증" 버튼으로 **저렴하게**(구성원만) 주기 확인 가능. 실측: 6개 동일 파일(15쌍)에서 1개를 크기·mtime 보존 상태로 변조 → 재검증이 검출(변경 1, 재분석 1)하고 쌍 15→10, DB 반영.

# MediaSimilarityFinder v0.9.2.91 — Search Benchmark Log (JSON)

## Need for change
- Comparing and improving search performance needs per-stage timings, per-file
  decode/hash costs, video scan time per play-minute and per GB, and measured
  CPU/GPU utilization.
- Completion and cancellation both need a human-readable summary plus a
  machine-parseable original.

## Previous structure
- No stage timers, resource sampler, or result log existed. GPU activity was a
  status-display flag only.

## New structure
- New `src/benchmark.{h,cpp}`: `BenchmarkRecorder` collects stage times
  (walk/revalidate/image/video/analyze), per-image decode/hash/crop times with GPU
  flags, per-video build time/play length/frames, 250ms resource samples (process
  and system CPU, memory, GPU flag), slowest top-20s, and match stats into a single
  hand-rolled dependency-free JSON (paths escaped).
- `MediaPipeline::imageBatch` records per-image times; the engine finalizes on
  every return path (cancels included). `ScanControl` gains `revalidateMs`/`buildVersion`.
- GPU utilization comes from the existing `gpuActive_` atomic flag's duty cycle
  (active-sample ratio, longest idle). No external dependencies or spawns.
- `ScanWorker::benchmarkReady` → `MainWindow::onBenchmark` popup: QJson parsing,
  KO/EN summary, JSON save button (default `benchmark-<timestamp>.json`). Shown on
  completion and cancellation, not on hard failure.
- Version strings unified → 0.9.2.91, 59 tests (`benchmark_test`).

## Resolved situation
- Images: count, bytes, GPU/CPU hash split, mean decode/hash, GPU batch time, slowest 20.
- Videos: count, play seconds, frames, mean build, sec/play-min, sec/GB, slowest 20.
- Resources: CPU mean/max/stddev (jitter metric), system mean, peak memory, GPU duty%,
  longest idle, plus the raw series.
- The popup shows the slowest 5; the JSON carries all 20.

## Validation
- Core+GUI Release build: PASS, **CTest 59/59 PASS** (`benchmark_test`: JSON keys,
  aggregates, zero duty, series structure).
- Existing scan tests pass unchanged, proving the timing hooks don't affect scans.
- Portable `--smoke` exit 0, `MediaSimilarityFinder-v0.9.2.91-Portable-Windows-x64.zip` produced.

## Future impact
- NVML-grade SM occupancy stays a separate version if needed (current metric is
  batch duty cycle).
- Full per-file rows only need a `slowest` expansion (current default: aggregates + top 20).

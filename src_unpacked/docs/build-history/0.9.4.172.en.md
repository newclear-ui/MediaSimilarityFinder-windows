## 1. Why the change

- User directive (Korean-only file on temporal-anchor reading: preserve V3, compare in parallel): preserve current V3 (DTW) as LegacyV3 and add an independent reading path `TemporalAnchorV1` that tolerates leading insertions (ads/intros/black leaders). Not a score tweak: an independent path from main-start search to long-term anchor verification.
- Evidence: field report `lead-prefix-discrimination` §11 — V3 misses leader pairs via unabsorbed start offset (Miss C1) and flat shared-print false alarms (False Alarm C1).

## 2. Previous structure

- `video_similarity()` current DTW comparison; V3 segmented kept is the production default.
- V2 structure probe and V4 coverage keep their diagnostic/verification lineage.
- `video_sampling.*`, `video_decoder.*`, `video_policy.h` are the sampling/policy entry points.

## 3. New structure

- New module `src/temporal_anchor.{h,cpp}` (msf_core): `TemporalAnchorIndex` (compact time print), `buildTemporalAnchorPlan()` (dense 1 fps, single sequential sweep — sparse windows provably cannot cover mid offsets like a 45 s leader, so the search substrate is dense; decoding still reads the whole file anyway), `makeTemporalAnchorIndex()` (32x32 pHash+mirror+mean/sd/delta), `findLeadingOffset()` (order-preserving, mirror-tolerant, single frames rejected, flat frames never overused, search from first textured run, bidirectional, multiple candidates plus the (0,0) default hypothesis), `temporalAnchorSimilarity()` (§3.2-§3.6 + §5 verdict: DUP needs multiple independent main anchors plus consistent offset; ending/credits alone never confirm; thin evidence stays UNCERTAIN).
- Strategy IDs: `LegacyV3` (default) / `TemporalAnchorV1` (experimental opt-in). `VideoPolicy.readStrategy` + GUI video-tab combo + QSettings `video/readStrategy` + IPC JSON + backend parsing + scan snapshot. 4 new trStr keys (ko/en).
- Engine: `VideoFingerprintEngine::buildAnchorIndex()` (independent sweep, no persistent cache). `build()` runs the extra anchor sweep only under `readStrategy==TemporalAnchorV1 && MSF_VIDEO_ANCHOR==1`; otherwise byte-identical (V3 prints and caches unchanged).
- Telemetry (additive, report-only): `VideoBuildStats.anchorBuilt/anchorFrames/anchorMs` + full `TemporalAnchorResult` (§6 list: strategyId, probe, start, offset, anchors, drift, ending, verdict, decode/compare times).
- Tests: `tests/video_temporal_anchor_test.cpp` (13 synthetic pins: plan, leader search both directions, single/reversed rejection, mirror, DUP gate, different Diff, flat UNCERTAIN, ending-only non-confirmation, shared-leader non-confirmation, drift detection without forcing, shorts UNCERTAIN, real index build).

## 6. Future impact and limits

- Verdicts unchanged (default path byte-identical; engine/DB/schema/cache unchanged — no stored-pair re-verification).
- **No Gate PASS declared**: leading-ad recall improved on long-form (2/5 DUP + 2 UNCERTAIN) but shorts stay UNCERTAIN-heavy (0 DUP), and same-content HDR pairs, drift/trim/rate matrices, mid-roll branch, and credits classification are unmeasured/unimplemented. No default promotion.
- Known limits: unstable pHash on dark openings/main content (L02), single-frame 87.5 strictness, ending classifies NoCredits/Uncertain only (PreCredits reserved), anchor JSON aggregation is follow-up (result struct + worklog recorded).
- Rollback: select LegacyV3 in the GUI (the default) + leave `MSF_VIDEO_ANCHOR` unset. V3 rows and anchor artifacts carry different identities and never mix.

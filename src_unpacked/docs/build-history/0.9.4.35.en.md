## 1. The Product Defect

Up to and including v0.9.4.34, the product had **never applied an EXIF
rotation.**

```text
product path  /app1/ifd/exif/{ushort=274}  -> 8/8 BADPROPERTYKEY (0x88982F40)
working path  /app1/ifd/{ushort=274}        -> 8/8 S_OK
```

The standard dataset's `orient_applied_files = 0` was the result of this
defect, not a coverage gap. It is still 0 after the fix, but for a different
reason: the **dataset contains no rotated image at all** (§6).

## 2. Production Usage Survey

Exactly **three** sites in `src/image_decoder.cpp`, all with the identical
literal and identical logic:

| Site | Function | Role |
|---|---|---|
| (was :194) | `decodeWicFile` | fingerprint fixed |
| (was :267) | `decodeWicFileAspect` | fingerprint aspect |
| (was :321) | `decodeWicFileAspectColor` | display (color) path |

The display path is corrected too: a rotated photo shown differently from its
fingerprint would make the screen disagree with the matching result. A
repository-wide search confirmed these were the only production
`GetMetadataByName` calls.

## 3. The Correction (minimal)

Not three line edits, but **one shared helper** used by all three sites:

```cpp
inline WICBitmapTransformOptions exifOrientationToTransform(IWICMetadataQueryReader* meta) {
  static const wchar_t* const kPaths[] = {
      L"/app1/ifd/{ushort=274}",  // JPEG
      L"/ifd/{ushort=274}",       // TIFF
  };
  ...
}
```

- No new container branch. The two paths are tried in order and the function
  **stops at the first one that yields a value**, so JPEG and TIFF are both
  handled without knowing the container.
- The helper returns immediately on a VT_UI2 value, so a JPEG never pays the
  second query.
- Orientation 1 is the identity and does not increment `orientApplied`
  (existing meaning preserved).
- **No XMP fallback, no new metadata framework, no new orientation
  architecture** (pre-register §11).
- All three call sites are now the single line
  `xform=exifOrientationToTransform(meta.Get());`.

## 8. Cost (measurement-only probe)

Full corpus, 3,341 files. The cost impact of the fix itself is measured
separately.

### 8-A. What the Fix Costs

```text

  one_path   0.01678 ms
  two_paths  0.04547 ms
  delta_per_file 0.02870 ms
```

Because the helper returns on the first VT_UI2 value, **a JPEG does not pay
this delta.** Only a file with no EXIF at all tries the second query.

Baseline bucket means (run 1, per file):


`metadata` carries part of the cost, and it is confirmed that the EXIF fix

## 9. Regression Test Added

An EXIF regression was added to the dataset-free, fast `--selfcheck` mode and
**registered in CTest** (unlike the corpus modes, `--selfcheck` needs no
dataset argument).

```text
orientation 1 fixture -> applied == 0 (identity)
orientation 6 fixture -> applied != 0 (90 degree rotation)
verify the rotation actually changes pixels (not just a counter moving)
verify baseline vs candidate f/a byte identity on the rotated file
```

```text
selfcheck: 11 checks -> 16 checks
CTest:     CPU 80/80 -> 81/81, GPU 81/81 -> 82/82
```

Without this test the EXIF defect could silently return.

# MediaSimilarityFinder v0.9.3.13 — 영상 pHash CUDA batch 가속 1단계

## 변경 필요성
- 영상 검색은 FFmpeg 디코드뿐 아니라 샘플 프레임의 pHash 계산도 CPU에서 수행해 CUDA 사용률이 낮았다.
- 영상 검색 시간을 줄이되, 이번 단계에서는 디코더와 temporal 판정 의미를 바꾸지 않는 것이 필요했다.

## 기존 구조
- `VideoFingerprintEngine::build()`가 32x32 프레임의 normal/mirror pHash를 CPU에서 계산했다.
- CUDA backend는 이미지 batch hash 경로에서만 사용됐다.
- 영상 worker가 병렬로 실행되어도 GPU 사용량과 fallback이 Benchmark에 표시되지 않았다.

## 변경 구조
- FFmpeg 디코드는 기존 CPU 경로를 유지하고, 유효한 32x32 영상 프레임을 batch로 모아 CUDA pHash를 수행한다.
- 동일 프레임에서 normal/mirror 입력을 준비하고 기존 `GpuBackend::hashBatch()`를 사용한다.
- CUDA 실패·미지원 환경에서는 프레임별 기존 CPU pHash로 즉시 fallback한다.
- `VideoFingerprintEngine` GPU 호출을 mutex로 보호해 여러 영상 worker가 하나의 backend를 안전하게 공유한다.
- Benchmark JSON에 영상 GPU 사용 영상 수, fallback 영상 수, GPU hash 시간과 resource sampler active 상태를 추가했다.

## 해결된 상황
- 영상 fingerprint의 pHash 단계도 CUDA를 사용할 수 있다.
- FFmpeg 디코드, crop fingerprint, temporal verification은 이번 단계에서 동작을 유지하므로 정확도 의미가 바뀌지 않는다.
- CUDA가 없는 환경과 runtime failure는 기존 CPU 경로로 계속 동작한다.

## 검증
- CUDA backend 실제 장치: RTX 3080 Ti, SM86, `cuda_backend=ok`.
- 실제 FFmpeg 영상 회귀: 8 frames, similarity 100, `gpu_video_hash=yes`.
- 전체 Release 빌드: PASS.
- CTest: **60/60 PASS**.
 - Portable v0.9.3.13 생성 및 smoke: PASS.
- 다국어 실제 영상 경로 회귀: 일본어·중국어·아랍어·한국어·러시아어·히브리어·태국어 7개 경로와 공백/괄호 파일명에서 FFmpeg 디코드와 fingerprint 비교 PASS.
- CPU-only Release 빌드 및 CTest: **59/59 PASS**.
- CUDA Release 빌드 및 CTest: **60/60 PASS**.
- MSVC C++ UTF-8 옵션과 SQLite 최신 target을 적용했고, vcpkg 후처리 잠금 회피를 위해 Windows 빌드 스크립트 기본 병렬도를 1로 조정했다.

## 향후 영향
- 영상 디코드와 96x96 crop/temporal 비교는 여전히 CPU이며, 영상 전체 가속은 아니다.
- 다음 단계 후보는 crop fingerprint batch, temporal pair batch, NVDEC 검토다.
 - GPU batch 크기와 CPU↔GPU 전송 비용은 실제 대규모 영상 corpus Benchmark로 조정해야 한다.
 - `thumb48` 기반 MSSIM은 현재 CPU 경로다. GPU 확장은 48x48 쌍을 행 단위로 batch 처리하고 실패 시 CPU로 fallback하는 별도 단계로 검토한다.
 - GPU MSSIM의 10배 이상 향상은 후보 수·전송 비용·GPU별 결과를 측정한 뒤에만 목표로 확정한다.

# MediaSimilarityFinder v0.9.3.12 — Explorer Reuse and Freshness Follow-ups

## Need for change
- Selecting a file in an already-open Windows Explorer folder failed, and several lower-level freshness APIs and GUI group anchors did not fully handle replacement files or reordered groups.

## Previous structure
- The target file was converted to an absolute PIDL and passed to `ILFindChild()` against the current folder PIDL.
- Incremental/Database unchanged checks compared only path, size, and modification time.
- The video memory thumbnail fast path did not check quick identity.
- Group selection and scroll anchors used transient vector indices.

## New structure
- Enumerate child PIDLs returned by the active Explorer view, compare their absolute paths, and select the matching child PIDL. Native Windows paths are used for Shell parsing.
- Include quickHash in Incremental/Database unchanged checks.
- Include quick identity in video thumbnail memory hits and preserve persistent crop data when `build()` loads a crop-bearing cache row.
- Re-map group selection and viewport anchors through representative path identity after rebuilds.
- Populate basic benchmark counters before returning failed scans.

## Resolved situation
- An already-open Explorer window can retain focus while selecting the target file.
- Same-metadata replacements are not silently reused by the lower-level unchanged/cache paths.
- Selection and scroll restoration continue to refer to the same representative group after sorting or streaming refresh.

## Future impact
- Explorer view enumeration is proportional to item count and may be slower in very large folders.
- Quick identity remains based on the first 64 KiB of the file.
- CUDA batching/NVDEC for video analysis requires separate design and benchmarking.

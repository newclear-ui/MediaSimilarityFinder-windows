# 0.9.2.32 — Compact index-based match streaming callback

## IMPORTANT change
Added `SearchMatchRef` streaming so large-result consumers can receive two file indices plus similarity instead of constructing full path strings for every match.

## Why
0.9.2.31 introduced streaming and bounded report retention, but the existing `onMatch` callback still creates a `SearchMatch` containing two path strings. With hundreds of thousands or millions of results, repeated string construction can add allocation and memory pressure.

## Previous structure
Each match created path strings before being delivered through `onMatch` or retained in `SearchReport.matches`.

## New structure
`ScanControl::onMatchRef` receives `SearchMatchRef { leftIndex, rightIndex, percent }`. Indices refer to the current scan's `MediaSearchEngine::files()`. Existing `onMatch` and `SearchReport.matches` remain available.

## Rationale
File paths are already stored once in the file list. Passing compact indices lets a future virtualized Qt result model resolve paths only for visible rows, avoiding per-match path duplication while preserving the existing API.

## Resolved situation
Large-result consumers now have a low-allocation callback path. Combined with `retainMatches=false`, the scan can avoid materializing the full result set in `SearchReport`.

## Compatibility
Match indices and similarity values are unchanged. CandidateIndex, SimilarityEngine, existing string callback behavior, and report retention semantics are preserved.

## Verification
- `search_report_test` validates both callback forms and index bounds.
- Core Release build performed.
- Full 36-test suite run/validated.

## Future impact
The next GUI result model can use compact references with paging/virtualization. A later stage can persist compact result records directly to SQLite if needed.

## Windows common compatibility fixes — shared CUDA/CPU baseline

Windows CPU testing exposed platform-common issues. These fixes are now applied to the shared source while keeping the CUDA backend algorithms, memory path, and kernels unchanged.

- vcpkg `unofficial-sqlite3` CMake package handling
- Windows Qt/WIC and `NOMINMAX` compatibility
- C++20 `std::numbers::pi` instead of MSVC-incompatible `M_PI`
- FFmpeg 9 `av_find_best_stream()` compatibility
- Correct `SystemLoadMonitor` state-member placement
- UTF-8 filesystem boundary handling on Windows
- `ReadDirectoryChangesW` overflow/resync and buffer-bound checks
- StableFileDetector state cleanup after successful stabilization
- `std::popcount` for MSVC test portability
- Avoidance of the Windows SDK `SystemLoad` symbol collision
- Visual Studio 18 2026 CUDA build script and project-local vcpkg use

The official `0.9.2.32` baseline remains untouched. This shared-fix validation line uses `0.9.2.34` as the next CUDA/Windows build baseline.

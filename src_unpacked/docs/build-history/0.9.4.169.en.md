## 1. Why the change was needed

- Synthesized external reviews: (a) coverage counted pre-SSIM Hamming cells, disagreeing with score evidence; (b) the coverage-only gate shared the verdict threshold so it could not be raised; (c) no conclusive clip05 diagnosis; (d) BUILD_STATUS / V-brief / architecture docs lagged implementation; (e) safe_remove.ps1 hardcoded the C: recycle-bin path and misbehaved on D:.
- Record correction: field evidence 2's "Hamming gate (similarity 60)" was wrong. The harness used the struct default 50; the production default is distance 8 → threshold 87.5. No path uses 60.

## 2. Previous structure

- Coverage marked rows/columns on the first-loop Hamming `sim>=threshold`. Scores were decided after the second-loop blend (`0.4*ham+0.6*ssim`).
- One `threshold` served cell gating, coverage, and the final verdict.

## 3. New structure

- Coverage marking moved after the blend: only `sim>=covGate` cells set `rowCovered/colCovered`. Old Hamming-only values preserved as `rawCovShort/rawCovLong` for per-pair comparison.
- Split `coverageGate`: `max(threshold, coverageGate)`, `<0` means threshold. Coverage-only; never changes score or verdict. Strict-gate thresholds (0.5/0.2/1) unchanged, default OFF.
- `MSF_VIDEO_DUMP_MATRIX=<file>`: per-pair tx/ty + ham/ssim/final matrix TSV dump. Fully off unless set (zero perf/behavior impact).
- New sim_perf pins: hash-identical / unrelated-thumb pair gives raw=1/1, verified=0/0, score=0, plus coverageGate floor test.
- `safe_remove.ps1`: bin root derived from the item's drive (C: hardcode removed). Verified on a D: scratch dir (recycled with no warning).
- Docs: BUILD_STATUS line 19 (0.9.4.167 residue under the 0.9.4.168 label) fixed; V-brief header to baseline 0.9.4.169 with status split (V3 adopted / V4 diagnostic-unvalidated / V2 runner-up); architecture implementation-status note.

## 1. Why it was needed

Active Build Queue priority 2 (S4) remaining gap: "final screen + save acceptance for GUI Detailed Logs — verify the real Search/Update -> Detailed Logs -> **save**/exit path". The existing `scan_detailed_log_acceptance_test` covered generation, display (dialog opened) and telemetry content, but the **save path (JSON file write), its failure branch, and the exit path were unverified**. The doc status conflict (brief: "GUI visible UI PASS (user-confirmed)" vs progress: "final screen acceptance open") also needed reconciliation.

## 2. Previous structure and defects

- The save was inlined in the dialog's Save-button lambda: `QFileDialog::getSaveFileName` -> file write -> status message, so it could not be unit-verified.
- **Real defect (false success report)**: the write condition was `f.write(json.toUtf8()) >= 0` — a **zero/partial write could be reported as success** ("Detailed log saved" could lie).
- Exit path: dialog close -> app exit with no crash was only indirectly covered.

## 3. New structure

- **`MainWindow::saveDetailedLogTo(path, json)`** (gui/mainwindow.cpp, private): the save logic as a single unit, split out of the dialog. It requires the **exact byte count** (`f.write(bytes) == bytes.size()`), sets `detailLogSaved + path` on success or `detailLogSaveFail` on failure, and returns bool. The Save-button lambda now only handles the file picker.
- **Test hook `testSaveDetailedLog(path)`** (gui/mainwindow.h): saves `lastTelemetryJson_` through the same unit — for the failure-branch check.
- **`scan_detailed_log_acceptance_test` extension** (real-button E2E): the modal timer (1) clicks the detailed-log dialog's **real Save button** (via a zero-delay singleShot to bypass a timer re-entrancy limit — Qt does not re-enter the same timer while its handler is on the stack, so the closer could never handle the file dialog opened by a click inside its own emission), (2) in the file picker sets the target path **directly on the name edit** (`selectFile` skips the name when the name edit has focus) and accepts only once the dialog reports that path, (3) captures the status label **right after the save returns** (same callstack, before later scan-finish messages overwrite it). Assertions: file exists + **saved record == telemetry record (JSON equality)** + status shows the path + **an unwritable path fails (false)** + the dialog/app exit proceeds.
- **Doc reconciliation**: the S4 brief (ko/en) current-state section updated — the functional acceptance (generate -> display -> save -> exit) is automated PASS; the on-screen visual check stays recorded as "not done" (headless); S4 final CLOSED remains tied to the product-acceptance recheck per the §10 exit condition.

## 4. What is fixed

- The save path is verified end to end (real button -> file picker -> file write -> status), and the **partial/zero-write false-success report is removed**. The failure branch reports failure.
- The doc conflict is reconciled: what is automatable (generate/display/save/exit) is recorded PASS; the headless limitation (real-screen visual) stays explicitly "not done".

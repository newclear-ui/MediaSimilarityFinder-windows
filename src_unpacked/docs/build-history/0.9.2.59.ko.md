# MediaSimilarityFinder v0.9.2.59 — 빈 그룹창 재발 수정(리스트 재구축 라이브락)

## 변경 필요성
v0.9.2.58(placeholder 캐시) 후에도 11k 그룹 스캔에서 가운데 창이 비었다. 데이터는 존재(상태바 11084)하고 스크롤바도 있어 레이아웃은 돌았는데 페인트가 안 됐다. 심층 분석 결과, 틱당 11k개 위젯 전체 재생성이 600ms 주기를 초과해 타이머 타임아웃이 큐에 끝없이 밀리고, 각 틱의 페인트보다 먼저 다음 틱이 실행되는 라이브락이었다. 일시정지 클릭도 밀린 타임아웃 뒤에 갇혔다.

## 기존 구조
- `uiTimer` 600ms마다 dirty면 `rebuildGroups→refreshGroupList→refreshFileViews` 전체 수행. 11k개면 위젯 재생성+레이아웃만으로 수백ms~1s
- 일시정지 중 워커가 emit을 안 해서, 정지 직전 스트리밍분이 `pending_`에 그대로 남음. 타이머가 drain을 안 해서 일시정지 화면이 불완전
- 워커 스트리밍→영속 경로에 headless 회귀테스트 없음

## 변경 구조
- **적응형 refresh 스로틀**(`refreshStreaming()`): 전체 리스트 fill을 측정 비용×3(600ms~3s)으로 제한. 카운트는 매 틱 갱신이라 실시간 감각 유지, 무거운 fill만 간격 조절. 일시정지·종료·탭전환·정렬·검색은 기존대로 즉시 갱신
- **서명 스킵**: `matchSeq_`가 마지막 fill과 같으면 fill 생략(카운트만). 같은 내용 반복 재구축 제거
- **타이머 drain**: 틱마다 `drainMatches()`로 정지 직전분까지 회수. 일시정지 토글 시 즉시 drain+dirty로 600ms 내 완결 화면
- **워커 회귀테스트**(`scan_streaming_test`): 동일 BMP 4개 실스캔 → `streamed=6 stored=6` 확인. 스트리밍과 quick-load 영속을 headless로 증명
- 버전 표기 통일 → 0.9.2.59

## 해결된 상황
- 11k 그룹에서도 틱당 작업이 상한 이하라 페인트·일시정지·중지가 항상 처리. 그룹 목록이 실제로 표시되고 2~3초 간격으로 실시간 갱신
- 정지해도 그때까지 찾은 쌍이 DB에 있어 다음 재검색에서 quick load로 복원(테스트로 보장)
- 일시정지 화면이 정지 시점까지 완전

# MediaSimilarityFinder v0.9.4.100 — Detail remote diagnostics + filename hardening

Baseline `0.9.4.99` -> this build `0.9.4.100`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

User report: all detail-pane text blanks after select+check actions. Every local reproduction path (grid/tree/Load/repeated cycles) stays healthy, so machine-side evidence was needed. A backup-rotation sort defect at three-digit versions was found along the way.

## 2. Previous structure

- `refreshDetail()` left no trace in `msf_scan.log` on anomaly.
- Detail name/path labels relied on rich-text auto-detection, so filenames carrying `<>&` could mangle or blank rows.
- Backup rotation sorted lexically by name while its comment assumed zero-padding that versions never had.

## 3. New structure

- **Remote-diagnosis tripwire** (end of `gui/mainwindow.cpp::refreshDetail`): logs one `detailAnomaly file=… rows=… box=WxH vis=… tab=…` line to `msf_scan.log` only on row-count divergence (>24), a collapsed/invisible/uninstalled form box, or an unexpected tab. Healthy runs stay silent.
- **Filename hardening**: `Qt::PlainText` on the name/path value labels (identical rendering, no HTML misread).
- **Backup rotation fix** (`scripts/backup_src.ps1`): numeric dotted-tuple sort. Removes the defect where `v0.9.4.100` sorts before `v0.9.4.99` lexically and the newest backup would be recycled first (verified by measurement).
- Test hook `testDetailRowCount()` (permanent row-bound pin).

## 4. Result

- A reproduced detail blank now resolves to row count, geometry, visibility, and tab in one log line.
- Filename HTML misreads are eliminated at the source.
- Rotation discards oldest-first at three-digit versions too.

# MediaSimilarityFinder v0.9.2.51 — 동영상 장면전환 검색 + GPU 상태 가시화 + 캐시 v4 + duration 게이트

## 변경 필요성
v0.9.2.50까지 동영상 검색은 프레임 단위 해시로 비교해 장면 전환 지점을 구분하지 못했다. 동영상 내 장면 전환부 근처의 프레임이 다음 장면의 프레임과 매칭되어 부정확한 유사도가 보고되는 문제가 있었고, 검색 결과의 의미론을 명확히 하기 위해 장면전환 감지과 장면 전용 보너스 스코어를 추가했다. 또한 (1) 캐시 형식 3→4로의 마이그레이션이 명시적이지 않았고, (2) GPU 백엔드 사용량이 사용자에게 보이지 않아 CUDA 활용 여부를 알 수 없었으며, (3) 초당 1프레임 미만의 매우 짧은 클립이나 4배 이상 비율로 늘어난 영상은 검색 의미가 적어 필터링이 필요했다.

## 기존 구조
- 캐시 형식: `kCacheFormatVersion=3`, 저장 페이로드에 장면 수 정보 없음. `openPersistentCache`가 하드코딩 `cache_version != 3`으로 오래된 버전 행을 삭제했으나 v4 로직은 미구현.
- 동영상 유사도: `video_similarity()`가 모든 유지 프레임 쌍에 동일 `sceneBonus=0` 적용. 장면 경계 정보 없음.
- GPU 상태: `media_search_engine` 내부 `gpuImagesProcessed_` 카운터 존재하나 GUI에 노출되지 않음.
- Duration 게이트: 스캔 파이프라인에서 동영상 지속시간 기반 필터링 없음. 너무 짧거나 비현실적으로 긴 영상이 검색에 포함됨.

## 변경 구조
- **캐시 v4**: `kCacheFormatVersion=4`로 상향. `openPersistentCache` DELETE 조건을 `!= 4`로 변경(기존 v3 행 완전 폐기). `loadPersistent`/`savePersistent`가 v4 페이로드 파싱/기록 — 프레임·미러·6 crops·`sceneCount`·장면 타임스탬프 순. `headNeed` 검증으로 잘못된 크기 페이로드 거부.
- **장면전환 감지**: `build()`에서 저분산 프레임 필터(`kMinVariance=6.0`, 제외 시 >70%면 전부 유지하는 `kFloorRatio=30`) 이후, 연속 유지 프레임 간 `hash_similarity < 25.0`인 지점을 `sceneChanges`에 기록. `sceneFlags()` 헬퍼 + `video_similarity()`에 `sceneBonus` 적용. `crop_temporal_score()`에도 동일 보너스 적용.
- **GPU 상태 가시화**: `media_search_engine`에 `gpuImagesProcessed_`(atomic) + `gpuImagesProcessed()` getter 추가. `gui/mainwindow`에 `gpuLbl_` 상태바 위젯 + `updateGpuLabel()` — 스캔 중 "GPU 처리 N", 정지 시 on/off 표시. `ScanWorker`가 GPU 가용 탐지(`GpuBackend().available()`) 후 진행률 lambda에서 카운터를 atomic에 기록.
- **Duration 게이트**: `scan_pipeline.cpp`에 `durationGate()`(`kMinDurationSeconds=1.0`, `kMaxDurationRatio=4.0`, duration<=0이면 통과). 동영상 temporal 비교 호출을 `video_crop_similarity(...,{threshold,8,2,2.0})`로 변경.
- 버전 표기 통일 → 0.9.2.51

## 해결된 상황
- 동영상 내 장면전환 부근의 부정확한 매치가 `sceneBonus` 덕분에 구분되어 보고됨. 장면전환 자체가 `sceneChanges`에 기록되어 검색 UI에서 활용 가능.
- 오래된 v3 캐시 행이 명시적으로 폐기되고 v4 로드가 정상 동작.
- GUI 상태바에 GPU 처리량이 표시되어 CUDA 활용 여부를 실시간 확인 가능.
- 초단편·비현실적 길이 영상이 duration 게이트로 자동 제외.
- **CTest 42/42 PASS** (신규 `video_reencode_test` 포함 — libx264 재인코딩 후 동영상 유사도 ≥85 검증).

## 향후 영향
- `sceneChanges`는 현재 읽기 전용. UI에서 장면 전환 지점을 시각화하면 동영상 검색 탐색성이 향상
- `sceneBonus` 값은 튜닝 가능한 옵션(`VideoSimilarityOptions.sceneBonus`)으로 노출하면 사용자가 장면전환 민감도를 조정 가능
- duration 게이트의 임계값은 동영상 유형(쇼츠 vs 장편)에 따라 별도 설정 가능
- `IThumbnailCache` 연동은 v0.9.2.50에 기록된 다음 빌드 후보로 유지

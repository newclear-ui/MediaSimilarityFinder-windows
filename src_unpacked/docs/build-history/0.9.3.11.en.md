# MediaSimilarityFinder v0.9.3.11 — Cache Quick-Identity Validation

## Need for change
- Replaced files with preserved size and modification time could still reuse stale video fingerprints, image verification buffers, and thumbnails.

## Previous structure
- Search DB change detection used quickHash, but individual cache keys were primarily path/size/mtime.

## New structure
- Video memory/SQLite cache, image verification LRU, and persistent thumbnail cache now include a 64KB-prefix FNV quick identity.
- Video cache adds `quick_hash` and moves to cache format v8.
- Thumbnail DB schema version moves to `1.0.3`.

## Resolved situation
- A replacement with the same path, size, and timestamp no longer reuses the old fingerprint, SSIM buffer, or thumbnail unchanged.
- Existing rows miss on quick-identity mismatch and are replaced with fresh results.

## Validation
- GUI/Core and all Release targets compile: PASS.
- CTest: **59/59 PASS**.
- Portable `--smoke`: window created/event loop ok, exit 0.

## Future impact
- Each first cache lookup reads up to 64KB from the file.

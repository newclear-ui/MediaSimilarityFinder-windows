# MediaSimilarityFinder v0.9.4.18 — D2 Barrier Review (video completion order)

D2 검증 기준점. D1a/D1b 증거를 인용해 barrier 후보를 지명하고,
pre-register 순서(계측→정량→변경→parity→게이트)로 집행한다.
엔진 1.5.0·DB 1.0.3·캐시 v9 불변, schema 4→5.

## 변경 필요성
- video range의 index-order join이 느린 head 뒤의 완료 결과를
  대기시킨다(head-of-line). 파일 시간 편차가 큰 실데이터에서
  구조적 대기다.

## Pre-register (코드 변경 전 기록)
- 측정 병목: range wall에 느린 파일 1개가 지배적일 때 완료분 대기.
  `maxRangeFileMs` 신설로 JSON 단독 정량화.
- 예상 이득: 편차 큰 범위에서 (max−min) 수준, 균일 시 0.
- 롤백 기준: parity 깨짐 또는 회귀 발생 시 join hunk revert
  (telemetry는 유지).

## 기존 구조
- `for(f:futs) f.get()` 순서 join. 스레드 수·topology 동일.

## 변경 구조
- completion-order harvest (동일 스레드·동일 join, 순서만 변경).
  idle 시 5ms bound (수초 빌드 대비 무시 수준). 중단 의미 유지
  (post-stop 완료분도 join 후 폐기).
- `recordVideoRange(files, maxFileMs)` + `maxRangeFileMs` (range 최대).
  실패 range는 미기록 (문서화).
- schema v5 (신규 키 규칙 준수).

## 선택 이유
- 의존성 검사: DB upsert·progress·files 누적 순서 무관, live 순서만
  변경 (정확성 계약 아님). image phase join·walker poll·DB 직렬은
  의존성 실재라 제외 (분석 기록).

# MediaSimilarityFinder v0.9.3.8 — 검색 완료 후 thumbnail catch-up scheduler 수정

## 변경 필요성
- v0.9.3.7에도 검색 종료 시 `uiTimer_`가 중지되어 남은 thumbnail을 처리하지 못하는 경로가 남아 있었다.
- 새 match가 없으면 `groupsDirty_`가 false가 되어 starvation 후속 처리가 중단되었고, `thumbFollowUps_ < 12` 제한으로 대규모 그룹을 끝까지 처리하지 못할 수 있었다.

## 기존 구조
- `setRunning(false)`가 UI timer를 중지했다.
- thumbnail 후속 처리는 새 그룹 변경 및 12회 제한에 의존했다.

## 변경 구조
- 검색 상태와 thumbnail scheduler의 lifecycle을 분리하여 검색 완료 후에도 `uiTimer_`를 유지한다.
- `thumbStarved_`가 true이면 `groupsDirty_`와 무관하게 다음 tick에서 `refreshStreaming()`을 실행한다.
- 고정 12회 제한을 제거하고, budget 처리 후 starvation이 해소될 때까지 반복한다. 성공·실패·캐시 경로가 더 이상 pending을 만들지 않으면 `thumbStarved_`가 false가 되어 scheduler가 실질적으로 종료된다.
- tick당 thumbnail budget 4개와 기존 실패 cache는 유지했다.

## 해결된 상황
- 검색 완료와 thumbnail 업데이트 완료를 분리했다.
- 새 match가 없는 구간에도 남은 thumbnail이 작은 batch 단위로 계속 처리된다.
- 검색 알고리즘, grouping, DB schema, benchmark, CUDA 알고리즘은 변경하지 않았다.

## 검증
- Visual Studio 18 2026 x64 Release 빌드: PASS.
- CTest: **59/59 PASS**.
- 자동 테스트에는 GUI scheduler의 실제 장시간 시각 검증이 포함되지 않는다.

## 향후 영향
- UI timer는 검색 완료 후에도 살아 있으나 실제 thumbnail 처리는 `thumbStarved_`가 설정된 경우에만 진행된다.
- 대규모 목록은 기존처럼 전체 UI 재구축 방식이므로, 별도 후속 과제로 항목 단위 icon 갱신을 검토할 수 있다.

# MediaSimilarityFinder 0.9.2.22

## IMPORTANT CHANGE
Video Crop-Aware matching is now connected to the actual search candidate-generation and final-comparison flow.

### 1. Video Crop CandidateIndex
- The existing normal/mirror fingerprint indexes remain the fast first stage.
- Video analysis now also produces lightweight aggregate fingerprints for 4:3, 1:1, and 9:16 center crops plus their mirror variants.
- Dedicated per-ratio CandidateIndexes allow crop-based candidates to be discovered even when full-frame fingerprints differ.
- Cross-ratio crop-to-crop candidate matching remains disallowed.

### 2. Actual temporal second-stage integration
- If the first-stage fingerprint comparison already exceeds the threshold, processing finishes immediately.
- Only near-threshold video candidates proceed to temporal crop-aware analysis, reusing the existing timestamps.
- 4:3, 1:1, and 9:16 are evaluated independently with mirror variants.
- Existing temporal alignment and gap/time penalties are reused through `video_crop_similarity()`.

### 3. Persistent cache extension
- The video fingerprint cache payload now stores six crop aggregate fingerprints.
- Older payloads are automatically treated as invalid when their size does not match the new format and are rebuilt.
- The cache unit test was updated to validate the new payload fields.

### 4. Real-time Monitor protection
- `MediaSearchEngine` now supports an expensive-second-stage guard.
- The Monitor rechecks current CPU/GPU/memory conditions immediately before temporal crop analysis.
- If the foreground-workload protection gate is not satisfied, the expensive second stage is skipped.
- Existing stable-file detection, pause/resume, retry, and exponential backoff policies remain intact.

## Limitations
- The current validation environment has no CUDA/NVIDIA or Windows Qt6 runtime, so actual Windows GUI and CUDA execution remain unverified.
- Video crop aggregates use lightweight XOR-based candidate fingerprints; final accuracy is provided by temporal second-stage analysis.
- FFmpeg seeking cost for long videos remains a future optimization target.

## Next step
0.9.2.23 should focus on temporal second-stage performance optimization, per-candidate load/latency measurements in the real-time Monitor, and UI diagnostics showing whether a result was established by normal, mirror, crop, or temporal analysis.

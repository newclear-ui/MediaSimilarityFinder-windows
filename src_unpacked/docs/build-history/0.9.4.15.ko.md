# v0.9.4.15 — Node D1a Image-Path Observability

## Status
Implementation complete; validation **PASS** (0.9.4.16에서 확정).

Baseline: v0.9.4.14. Official preserved baseline v0.9.2.32 unchanged.

## Scope
Instrument the existing MediaPipeline::imageBatch() synchronous boundary using existing BenchmarkRecorder telemetry.

Recorded D1a observations:
- image batch count
- total batch items
- active batch depth
- image packing duration
- CPU hash duration
- existing GPU batch duration remains available

No new CPU/GPU execution queue is introduced.

## Guardrails
Scheduler share policy, Profile/Calibration, CUDA backend architecture, video, similarity, DB/cache, and CPU fallback semantics are unchanged.

Transfer timing remains **not_measured** until backend-internal timing hooks exist. The elapsed time of hashBatch() is not labeled as transfer time.

## Validation
CPU Release 빌드 PASS, **CTest 66/66 PASS**. GPU Release 빌드 PASS,
**CTest 67/67 PASS** (전체 로그 보관). 양쪽 `--version`은 0.9.4.16
sweep 후 확인, `--smoke` PASS.

검증 중 발견·확정된 사항 (0.9.4.16 게이트 기록):
- packMs는 decode 이후부터 측정되어 decode 미포함 (ed6f335에서 보정됨).
- cpuHashMs는 실행된 CPU hash 작업 시간이다. CPU 경로에서는 결과
  결정 해시, GPU 경로에서는 mirror 전용 작업을 포함한다. 별도 필드라
  기존 imgHashMs와 단일 필드 내 중복은 없다.
- batchMaxDepth는 현재 아키텍처상 항상 1이다 (recorder당 동시 batch
  1개). stub이 아니라 구조적 사실로 기록하며, D3 queue 도입 시
  카운터가 의미를 갖는다.
- batchItems는 시도된 입력 수 (디코드 실패 포함 가능) — 처리 완료 수와
  구분해서 읽는다.
- transfer는 계속 not_measured. schema는 키 6개 추가에 따라 v3로
  상향 (0.9.4.16).

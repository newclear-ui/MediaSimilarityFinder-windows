# MediaSimilarityFinder v0.9.4.88 — combined CPU display (GUI + Backend + Backend children)

Baseline `0.9.4.87` -> this build `0.9.4.88`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.5` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged.

## 1. Why it was needed

User report: during a scan the machine uses a lot of CPU but the summary panel shows <=10%.

Investigation: the old display measured only ONE "working process" (Backend in
production). These CPU consumers were NOT added:
- **Child processes**: `nvidia-smi` (scheduler/monitor GPU sample, `monitor.cpp:60`)
  — every 3 s during every scan; `ffprobe` (dimensions, `file_meta.cpp:19` via
  `BackendSession::requestFileMeta`); `ffmpeg` (video decode, FFmpeg-unlinked builds only).
- The **GUI process** itself (group/thumbnail rendering).
All are separate processes spawned via `captureSilent` (`CreateProcessA`), invisible
to the Backend's `GetProcessTimes(GetCurrentProcess())`.

## 2. Previous structure

- `sampleOwnProcess` = **this process** CPU (0–100 of all cores). The Backend measured
  itself only; the GUI displayed `backendCpu` alone.
- The detailed-log telemetry `cpuProc` also used `GetProcessTimes(GetCurrentProcess())`
  = Backend alone.

## 3. Change

- **(A) Backend = process tree**: new `backend_sysinfo.cpp::sampleProcessTree`. The
  Backend assigns itself to a **Job Object**; later children (captureSilent spawns)
  inherit it, and `QueryInformationJobObject(JobObjectBasicAccountingInformation)`'s
  `TotalUserTime/TotalKernelTime` accumulate **even already-exited short-lived
  children**. Falls back to Backend-only if the job can't be created.
  `backend_main::onHealthTick` uses it.
- **(B) GUI = itself + Backend**: the GUI samples its own CPU with a 1 s `cpuTimer_`
  (`sampleOwnProcess`) -> `guiCpu_`; `onStatusSnapshot` shows
  `clamp(guiCpu_ + st.backendCpu, 0, 100)`.
- **(C) Detailed-log consistency**: `TelemetryRecorder::sampleOnce`'s `cpuProc` also
  uses `processTreeCpuTicks` (shared job, caller-owned prev) so the panel and the
  detailed log use the same combined basis.
- **(D) No loopback double-count**: `BackendClient::separateProcess()`
  (supervisor=true, loopback=false); loopback keeps `guiCpu_=0` (GUI IS the working process).
- **Excluded (intended)**: user-action spawns (`explorer.exe` reveal, default-app open)
  and unrelated OS processes (Defender) are not in the tree/display.

## 4. Result

- The summary panel and detailed log now include **GUI + Backend + Backend children
  (nvidia-smi/ffprobe)**.
- User actions and unrelated processes are excluded.

## 6. Note: `cpuProc` semantics changed (AGENTS rule 9)

- **`cpuProc` (detailed log) changed from "this process CPU" to "process-tree CPU".**
  It is **not directly comparable** to `cpuProcMean/Max` from `0.9.4.87` and earlier.
  It is the new basis going forward. Status: SUPERSEDED (old definition).

## 7. Impact and limits

- The Job Object is measurement-only (no limits, no kill-on-close), so it does not
  change lifecycle/shutdown behavior. In an environment already inside another job
  (nested jobs unsupported), it may fall back to Backend-only.
- This build addresses **display accuracy**, separate from any optimization that would
  reduce the nvidia-smi/ffprobe spawns themselves.

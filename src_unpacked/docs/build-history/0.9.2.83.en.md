# MediaSimilarityFinder v0.9.2.83 — Startup Self-Check (Platform Plugin Pre-Flight)

## Need for change
- Packaging was fixed in 0.9.2.82 and verified in a clean environment, yet the `no Qt platform plugin` error was still reported on the user's PC.
- With the local package healthy, the failure is most likely environmental (old binary, running from inside the zip, exe-only copy). Previously Qt aborted inside the `QApplication` constructor, leaving no room for guidance.

## Previous structure
- `main()` constructed `QApplication` before parsing arguments, so a missing plugin ended in Qt's fatal dialog with no guidance.
- Even `--version` went through the `QApplication` constructor and failed without plugins.

## New structure
- A lightweight pre-check runs before `QApplication`: proceed if `platforms/qwindows.dll` (new layout) or `Qt6/plugins/platforms/qwindows.dll` (old layout) exists.
- Otherwise emit a `missing-platform-plugin` marker when a console exists, show a KO/EN dialog with cause and remedy (fully extract, copy and run the whole folder, never run from inside the zip), and exit 1.
- `--version`/`--help` are handled before Qt, so they always work regardless of plugins.
- No matching-logic or CUDA algorithm changes. Version strings unified → 0.9.2.83.

## Resolved situation
- Missing plugins now produce an actionable remedy dialog instead of the cryptic Qt error.
- Full-package runs still exit 0.

## Validation
- Core+GUI Release build: PASS, **CTest 56/56 PASS**
- Positive: full-package `--smoke` exit 0 (minimal PATH, no plugin path set)
- Negative: exe+DLL-only directory `--smoke` exits 1 (not a Qt abort code). The session is non-interactive so no dialog rendered, but the exit path went through the guard.
- `MediaSimilarityFinder-v0.9.2.83-Portable-Windows-x64.zip` produced

## Future impact
- If the error recurs on the user PC, first confirm the run came from a fully extracted `MediaSimilarityFinder-v0.9.2.83-Portable-Windows-x64.zip` (old zips or raw build outputs are unsupported).

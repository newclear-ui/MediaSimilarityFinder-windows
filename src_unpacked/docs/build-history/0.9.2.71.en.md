# MediaSimilarityFinder v0.9.2.71 — Engine Version Stamp + Stored-Match Revalidation

## Need for change
Verdict-logic changes (anchors, SSIM, image gate) left stored DB pairs untouched. Catching old false positives required a full rescan (prohibitive at 100GB) or DB deletion. An upgrade path was needed: stamp which engine produced a DB, and re-verify only the stored high-similarity pairs with current logic instead of rescanning everything.

## Previous structure
- No version concept on the `matches` table. Old false positives reappeared via quick-load after every logic fix
- Video temporal used an analyze-local engine (no cache open), decoding everything every time

## New structure
- **Version stamp**: `MediaSearchEngine::kEngineVersion=1` (bump on verdict changes). `meta` table (`engine_version`, 0 = pre-versioning). Checked automatically at scan start
- **`revalidateMatches`**: re-runs stored pairs through the current pipeline verdict (`analyze(8)` — same L1+anchor+temporal+SSIM code). No walk, no re-analysis. Changed/missing files are kept (union); fingerprint-less rows dropped; only verdict failures on fresh fingerprints are dropped, survivors re-saved with fresh percents. Cancel-checked every 32 pairs. Stamps the version on success (unstamped on cancel → retried next scan)
- **Shared temporal engine**: `ScanPipeline::setSharedTemporalEngine` — cache hits skip re-decode (identical verdicts). Applied to the main scan path too for the same speedup
- GUI runs it automatically at scan start before quick-load, reporting kept/dropped counts
- New `match_revalidate_test` (true-pair kept, bogus dropped, version stamped, second call no-op). Version strings unified → 0.9.2.71

## Resolved situation
- Legacy false positives (85%-class) drop at the next scan start; true detections stay. No full rescan or DB deletion
- Revalidation scales with stored pairs, not files; one-time per bump; cancelable

## Validation
- Core+GUI Release build: PASS, **CTest 54/54 PASS** (incl. new `match_revalidate_test`)
- `--version` 0.9.2.71, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)

## Future impact
- Verdict-changing builds get the upgrade path with a one-line `kEngineVersion` bump. Fingerprint-format changes split off as a separate version
- Video temporal decodes during revalidation skip on cache hit, occur once on miss (main scan path gains the same)
- A `fresh()` unit trap surfaced in testing: scanner stamps are milliseconds; raw-count comparison mismatches forever. Same pattern as the thumbnail mtime case, documented

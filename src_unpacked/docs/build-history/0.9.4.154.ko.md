# MediaSimilarityFinder v0.9.4.154 — 킬 내구성 D1 crash marker 구현

기준선 `0.9.4.153` → 본 빌드 `0.9.4.154`.
CPU CTest **128/128**, GPU CTest **129/129** (신규 CTest 등록 없음; §7은 기존 바이너리 내 신규 섹션).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` / `kProtocol 1` 불변 (판정·스키마·버전 상향 없음).

## 1. 변경 필요성

- 스캔 중 매치 체크포인트(5초·analyze-slice)는 스캔 트랜잭션 안에서 SAVEPOINT로 기록된다. 강제 종료는 커밋되지 않은 트랜잭션을 롤백하므로, 마지막 엔진 커밋 이후의 체크포인트는 소실된다.
- baseline이 유효한 채 남으면 다음 A/AB가 전체 검증을 생략하고, 소실된 매치는 `unchanged` 판정으로 영원히 복구되지 않는다(파일 행은 살아 있으므로 변경 감지도 동작하지 않는다).

## 2. 기존 구조

- `.151` SAVEPOINT: 중첩 저장은 정합되나 킬 내구성을 보장하지 않는다(미입증 선언).
- `.152`/`.153`: settled 종료 경로(완료·취소·실패 보고)의 baseline 무효화.

## 3. 변경 구조

- `meta.scan_dirty` 키 추가(스칼라 upsert/삭제, 스키마 불변).
- `ScanWorker::run()` 시작(인덱스 open 직후)에 autocommit으로 `'1'` 기록, 함수 스코프 RAII 가드(`SettledExit`, noexcept+내부 try/catch)가 모든 settled 종료(정상·취소·보고된 실패·예외 unwind 포함)에서 삭제한다. 강제 종료만 소멸자를 건너뛰어 키가 남는다.
- `MediaSearchEngine::scan()` 시작 시 키가 살아 있으면 baseline 값과 무관하게 1회 강제 전체 검증(`dirty=1` 로그) 후 stamp. 정상 종료 시 가드가 키를 지우므로 크래시 1회당 전체 검증도 정확히 1회다. 스캔은 키를 직접 읽지 않는다(worker가 세운 마커를 보면 매번 전체 검증이 되므로, worker가 스캔 전 값을 `ScanControl::forceFullPass`로 전달한다 — walker_queue case H로 퇴행 방지).
- 회귀: `crash_diagnostics_test` §7(신규, 15개): 완료 후 마커 없음 → 수동 식재(강제 종료 상태 재현) → 다음 A/AB가 `forceFullPass dirty=1` 수행 → restamp + 마커 소멸 + 변경 쌍 제거·무변경 쌍 유지.
- `ui_cancel_consistency_test` 확정(고정 sleep의 스캔 꼬리 경합을 진행 신호 대기로 교체 — 결정적 취소).
- 테스트 읽기 견고화: e2e sqlite 핸들에 busy_timeout(10s). 간헐 Test 1e 실패(초반 3회 실패 후 10회 연속 통과; 실패 시 DBG rowBefore="" 확인)의 1차 용의자(일시적 SQLITE_BUSY "" 반환) 대응. 진짜 불일치는 그대로 검출된다. 확정 근거 전까지 INSUFFICIENT EVIDENCE 유지, 추측성 제품 수정 없음.
- Test Mode 채택에는 영향 없음(완료된 scratch에는 마커가 남지 않으므로 upsert 대상이 아니다; 부분 채택은 meta를 건드리지 않는다).

## 4. 해결된 상황

- 강제 종료 후 다음 A/AB가 저장 집합 완전성을 더 이상 신뢰하지 않는다.
- 마커가 남는 경우는 프로세스 강제 종료뿐이다(모든 settled 경로는 소멸자·명시 삭제로 정리).

# MediaSimilarityFinder v0.9.4.141 — Keep the loaded list, selection and preview during a scan (apply results on completion)

Baseline `0.9.4.140` → this build `0.9.4.141`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged (display only).

## 1. Why

- 0.9.4.140 kept the thumbnail cache, but starting a scan still **blanked the right-side preview/detail ("—") and cleared the file grid** (field report).
- The cause was not the cache but the view reset in `beginScan()`: it set `currentGroup_ = -1`, cleared `currentFile_` and called `refreshFileViews()`/`refreshDetail()`, intentionally wiping the selection and preview.
- User proposal: keep the loaded list/preview while the update runs, apply on completion, and leave everything as-is when nothing changed.

## 2. Previous structure

- `beginScan()` also cleared `bestPct_`/`resCache_`/`pathKind_`/`fileMetaAsked_`/`contentFlag_`/`allPaths_`/`matchRows_`/`fileSize_`, dropped the selection and redrew both panes at scan start.
- Results were applied in `onResults()`; until then the screen showed the reset state.

## 3. New structure

- **Scan start (`beginScan`)**: only the live progress state (`hasReport_`) and the match accumulators (`bestPct_`/`pathKind_`/`contentFlag_`) reset. The list, selection (`currentGroup_`/`currentFile_`), preview, thumbnail cache and the file size/path maps are **kept**, and the panes are not redrawn.
  - The accumulators still start empty: the quick-load stream re-emits every stored pair immediately, and a changed pair must take the new value (a max-merge would keep an older, higher percentage).
- **Result apply (`onResults`)**: the final result is applied and `rebuildGroups()` restores the selection by representative path. Match state is NOT reset here - Hybrid's live pairs are delivered only through `onMatch` and never appear in the final rows, so resetting would drop their percentages and identity badges.
  - No changes (`analyzed == 0`): the append-first list matches, so the screen does not change; the preview, resolution and other displayed values stay as-is (metadata caches kept).
  - Changes (`analyzed > 0`): on scan completion the thumbnail/metadata caches are invalidated and only the visible surfaces are re-requested/repainted.
- New groups streamed during the scan still append at the bottom (existing behavior).

## 4. Result

- Pressing Search no longer makes the loaded list or the right-side preview disappear.
- An unchanged rescan keeps the loaded state; a changed one updates only on completion.

## 6. Impact and limits

- Display only (verdicts, storage, protocol, engine/DB/schema/cache unchanged).
- Deleting/moving files during a scan can remove the selected group; the selection then clears as before.
- The match union-find (`pathParent_`) still is not cleared at scan start (only match/metadata state is reset when the answer is applied), preserving the behavior since 0.9.4.81.

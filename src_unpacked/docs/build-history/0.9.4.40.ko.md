### 0.1 과정 기록 — pre-register 순서 이탈 (정직 기록)

pre-register 문서(`E-exact-sparse-seek.*.md`)는 **구현 이후**에 커밋되었다
(`d8bb2b3` 에 brief 와 probe 수정이 함께 들어감). 즉 brief 를 먼저 읽고 구현한
후에 문서화한 순서가 되었다. 지시 §39 와 이 프로젝트의 pre-register 관행에
대한 **절차 이탈**이며, 결과물 내용에는 영향이 없으나 순서는 잘못되었다.
기록해 둔다.

## 1. 변경 필요성

E-2A 는 sparse seek 가 빠르지만 **production 과 다른 프레임을 선택한다**는
것을 확인했다(pixel parity 4/14, tsLater 발생). 지시 §1 의 순서대로
**exactness 부터** 해결한다. production predicate · tolerance · target 은
**어떤 것도 변경하지 않는다.** candidate 의 seek 목표만 바꾼다.

## 2. Exactness 원인 규명

제품 predicate 는 `video_decoder.cpp:127` 의

```text
ft + 0.05 >= target     ⇔  pts >= target - 0.05 인 첫 프레임
```

E-2A 의 candidate 는 `target` 으로 seek 했다.

```text
착지 keyframe K <= target
K > target - 0.05 이면
  제품이 고른 프레임은 K 보다 "앞"에 있다 → 도달 불가 → tsLater
```

## 3. 해결 — seek 목표를 `target - 0.05` 로

```text
기존  av_seek_frame(fmt, s, pts(target),           BACKWARD)
수정  av_seek_frame(fmt, s, pts(target - 0.05),    BACKWARD)
```

착지 keyframe `K'` 이 `K' <= target - 0.05` 를 만족한다. 제품이 선택하는
프레임은 `pts >= target - 0.05 >= K'` 이므로 **착지점 이후에 반드시 존재**하고,
동일한 predicate 를 그대로 적용하면 **동일한 프레임**이 선택된다.

```text
( target - 0.05, target ] 구간에 keyframe 이 없는 일반적인 경우
  → K' == K, 비용 변화 없음
해당 구간에 keyframe 이 있는 드문 경우에만
  → 한 keyframe 더 뒤로 물러난다. 정확성을 위한 정당한 비용이다.
```

**predicate · tolerance · target 은 변경하지 않았다.** selfcheck 가
`kProductPredicateToleranceSec == 0.05` 을 검증한다.

## 5. 잔여 실패 — HEVC 1080p, 그리고 그것을 감지하는 방법

`real_hevc_1920x1080` 에서 17개 샘플 중 2개가 여전히 늦다(tsLater=2).

지시 §8 이 요구한 **seek 후 decoder state 검증**이 원인을 잡았다.

```text
정확한 재현의 필요조건:
  제품이 고르는 프레임은 pts >= target - 0.05
  따라서 "첫 디코드 프레임" 이 "요청한 seek 지점" 이하여야 한다
  firstDecodedPts > seekRequestPts  →  제품의 프레임에 도달 불가
```

이 조건을 위반한 target 개수를 `landingAfterSeekRequest` 로 계측했다.
**이 파일에서 위반이 검출되었고, pixel parity 실패와 정확히 동일한 파일이다.**

지시 §34 에 따라 해결을 강요하지 않고 `SequentialPreferred` 로 분류한다.
HEVC 는 IDR 외에 CRA picture 를 쓰기 때문에 `av_seek_frame` 의 착지점이
요청 지점보다 뒤로 갈 수 있으며, 이는 구조적 특성이다.

## 8. 4K GOP mismatch 조사 (지시 §33)

```text
codec=h264 High level 6.0, 3840x2160
has_b_frames = 2
avg_frame_rate = 18045/301   ← VFR (정확히 60 아님)
time_base = 1/15360
keyPkts 11 / iFrames 10 / mismatch 11
```

packet pts 와 frame `best_effort_timestamp` 계열이 통째로 어긋나 있어
mismatch 가 11 로 누적된다. VFR 컨테이너의 edit list 관련 정황은 있으나
**원인을 확정하지 못했다.** 지시 §33 에 따라 **새 codec parser 를 작성하지
않고** `GopEstimated` 로 분류하여 planner 가 보수적으로 sequential 을
선택하도록 했다.

## 9. 회귀

```text
CPU build PASS   CPU CTest 83/83
GPU build PASS   GPU CTest 84/84
probe selfcheck 29 checks PASS
production code 변경  없음
image dataset 변경   없음
```

selfcheck 에 지시 §36 이 요구한 fallback 을 자동화했다.

```text
av1-style undecodable -> unavailable        GopEstimated -> conservative sequential
GopUnavailable -> unavailable              seek landing violation -> sequential
tsLater > 0 -> sequential                   pixel mismatch -> sequential
long GOP (250) -> sequential                intra-only (GOP 1) -> candidate
short GOP + exact -> candidate
product predicate tolerance is unchanged at 0.05 s
```

```text
E-2B STATUS = CONDITIONAL
PRODUCTION ADOPTION = NO

```

| Gate | 결과 |
|---|---|
| A exactness | **CONDITIONAL** — 13/14 bit-identical, 잔여 1건은 HEVC |
| B performance + fallback | **PASS** — 승리군 포착, 패배군 7/7 회피 |
| C planner | **PASS** — 3상태 재현 가능, 사용 입력 기록 |
| D E/F 경계 | **PASS** — planner 는 분류만, executor 는 실행만, hardware 미구현 |

**production 채택하지 않는 이유**

1. 잔여 exactness 실패(HEVC 1080p)가 있다. 지시 §35 의
   "No unexplained pixel mismatch" 조건을 아직 fully 충족하지 못한다.
   원인은 규명했으나(seek landing) **해결하지 않았다.**
2. planner 가 이 실패를 런타임에 감지하고 fallback 하는 것은 입증했지만,
   이는 **탐지 후 회피**이지 exactness 해결이 아니다.
3. production default 변경은 지시 §2 가 금지한다.

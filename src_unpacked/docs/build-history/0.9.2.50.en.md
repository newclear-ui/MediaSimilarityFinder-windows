# MediaSimilarityFinder v0.9.2.50 — Match Persistence (Quick Load) + Preview WIC Fallback

## Need for change
Field report: (1) image search shows results but the previews (thumbnails) are blank, (2) after restarting the app and re-scanning the same folder, the previous match groups do not reappear. The former traced to thumbnail loading, the latter to match groups being memory-only. Each fixed at its cause.

## Previous structure
- **Preview**: `fileThumb()` relied only on `QImageReader` (Qt image-format plugins). The portable deployment ships only `qgif/qico/qjpeg.dll`, so without `qpng.dll` etc. PNG/JPEG thumbnails never rendered. (The search engine is WIC-based, so per-format search worked normally)
- **Match groups**: `ScanWorker::onMatch` streamed groups to the GUI, but results existed only in memory — a re-scan after restart recomputed everything. `retainMatches` was deliberately off to bound memory on million-match scans

## New structure
- **Match persistence**: `media_search_engine::saveMatches(SearchMatch vector)` / `loadMatches()`. Backed by `database::matches(left_path, right_path, percent, PRIMARY KEY(left,right))`, stored as a wholesale replacement (upsert + DELETE of vanished pairs). Pairs are ordered via `pairKey` (lexicographic normalization) before insert. Indexes `idx_matches_left/right`, BEGIN IMMEDIATE transaction, reuses existing SQLite WAL/busy_timeout
- **Scan-button integration (quick load)**: `ScanWorker::run()` right after index open calls `loadMatches()`, injects the stored pairs into `pending_`+`allMatches_`, and emits `quickLoaded(n)`+`matchesArrived`. The incremental scan then analyzes only files missing since — previous groups restore instantly and stale groups are preserved
- **Save point**: at scan end (including cancel) `allMatches_` (loaded + new) is saved wholesale via `saveMatches()`. A partial set on cancel keeps the last completed checkpoint, matching scan-side checkpoint semantics
- **Preview fallback**: `fileThumb()` falls back to `msf::ImageDecoder::decodePreserveAspect(path, 256)` grayscale when Qt cannot read. Same WIC decoder the engine uses, so previews work even when format plugins are absent from the deployment
- Version strings unified → 0.9.2.50

## Resolved situation
- Re-scanning the same folder after restart restores stored duplicate groups immediately and appends only new files. Deleted/replaced files are excluded by the wholesale rewrite
- PNG-style previews restored (via WIC even in deployments lacking Qt format plugins)

## Validation
- Core Release build: PASS, **CTest 41/41 PASS** (new `match_store_test` covers ordered save/load and wholesale replacement)
- `--version` 0.9.2.50, `--smoke` exit 0 (offscreen)

## Future impact
- Real-time monitor matches could reuse the same `saveMatches` path if persistence is wanted
- Quick load runs once at scan start. Surfacing stored groups in the results UI would be a separate action if desired
- WIC fallback is grayscale-only. `IThumbnailCache` integration recorded as next-build candidate

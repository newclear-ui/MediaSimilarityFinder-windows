# MediaSimilarityFinder v0.9.2.51 — Video Scene-Changes Search + GPU Status Visibility + Cache v4 + Duration Gate

## Need for change
Through v0.9.2.50 video search compared frame-by-frame hashes without distinguishing scene boundaries, so frames near a scene change could match the next scene's frames and report an inaccurate similarity. The scene-change points needed detection and a scene-specific bonus score. Additionally: (1) the cache format 3→4 migration was implicit with no v4 logic, (2) GPU backend usage was invisible to the user so CUDA utilization could not be confirmed, and3) very short clips (<1 fps) or videos stretched >4× had little search meaning and should be filtered.

## Previous structure
- **Cache format**: `kCacheFormatVersion=3`, payload had no scene-count field. `openPersistentCache` hardcoded `cache_version != 3` to delete old rows but had no v4 logic.
- **Video similarity**: `video_similarity()` applied the same `sceneBonus=0` to all kept-frame pairs. No scene-boundary information.
- **GPU status**: `media_search_engine` had an internal `gpuImagesProcessed_` counter but it was never exposed to the GUI.
- **Duration gate**: No duration-based filtering in the scan pipeline. Too-short or unrealistically-stretched videos were included in search.

## New structure
- **Cache v4**: `kCacheFormatVersion=4`. `openPersistentCache` DELETE changed to `!= 4` (v3 rows fully retired). `loadPersistent`/`savePersistent` parse/record the v4 payload — frames·mirrors·6 crops·`sceneCount`·scene timestamps in order. `headNeed` validation rejects malformed payloads.
- **Scene-change detection**: After the low-variance frame filter (`kMinVariance=6.0`, `kFloorRatio=30`), `build()` records pairs of consecutive kept frames with `hash_similarity < 25.0` into `sceneChanges`. The `sceneFlags()` helper applies `sceneBonus` in `video_similarity()`; `crop_temporal_score()` gets the same bonus.
- **GPU status visibility**: `gpuImagesProcessed_` (atomic) + `gpuImagesProcessed()` getter added to `media_search_engine`. `gui/mainwindow` has `gpuLbl_` status-bar widget + `updateGpuLabel()` — "GPU processing N" while scanning, on/off when stopped. `ScanWorker` detects GPU availability (`GpuBackend().available()`) and the progress lambda records the counter into an atomic.
- **Duration gate**: `durationGate()` added to `scan_pipeline.cpp` (`kMinDurationSeconds=1.0`, `kMaxDurationRatio=4.0`, duration<=0 passes). Video temporal calls changed to `video_crop_similarity(...,{threshold,8,2,2.0})`.
- Version strings unified → 0.9.2.51

## Resolved situation
- Scene-change-adjacent inaccurate matches are now distinguished by `sceneBonus`. The scene-change points themselves are recorded in `sceneChanges` for search-UI use.
- Stale v3 cache rows are explicitly retired and v4 loading works correctly.
- The GUI status bar shows GPU throughput so CUDA utilization is confirmable in real time.
- Sub-second and >4× stretched videos are automatically excluded by the duration gate.
- **CTest 42/42 PASS** (new `video_reencode_test` — ffmpeg testsrc → libx264 re-encode, video_similarity≥85, frames≥7).

## Validation

## Future impact
- `sceneChanges` is currently read-only. Visualizing scene-change points in the UI would improve video-search navigability.
- Exposing `sceneBonus` as a tunable option (`VideoSimilarityOptions.sceneBonus`) would let users adjust scene-change sensitivity.
- Duration-gate thresholds could become per-content-type (short-form vs long-form).
- `IThumbnailCache` integration remains the next-build candidate recorded in 0.9.2.50.

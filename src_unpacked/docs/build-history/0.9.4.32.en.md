## 1. Purpose · Hypothesis · Target

- Purpose: investigate the accuracy divergence of the candidate DEFERRED in
  v0.9.4.31. The performance gain is already observed, so this step asks only
  "why do the outputs differ".
- Hypothesis: the divergence comes from the structural difference between
  one-step and two-step Fant resampling chains, amplified on tiny
  bilevel/edge-heavy images.
- Target: attempt to reproduce the 2 flips reported in v0.9.4.31, score
  decomposition, resampling-path audit, R stability, pixel statistics.
  (The flips are corrected to an artifact in §2.)

## 8. Resampling-Path Audit (source-based)

```text
baseline : source → WIC Fant → final GrayImage

candidate: source → WIC Fant → intermediate 8-bit GrayImage
                → WIC Fant again → final GrayImage
```

The structural combination that produces the f/a pixel divergence:

```text
1. two-step Fant resampling (1-step vs 2-step chain)
2. intermediate 8-bit GrayImage quantization (the intermediate image is cut to
   8-bit before becoming the second Fant step's input)
3. different resampling chains (Fant vs nearest)
```

- The WIC scaler is Fant in all three decode paths
  (`src/image_decoder.cpp:220,294,344`).
- The candidate quantizes the intermediate image to 8-bit GrayImage and then
  resamples again, so the second Fant step sees quantized input. That is the
  structural point where the chains diverge (§10 Case B mechanism).
- `centerCropResize` is **not the origin of the f/a divergence.** It is used in
  the later scoring stage and, being integer nearest-neighbor
  (`y * ch / outSize`, `x * cw / outSize` — `src/crop_fingerprint.cpp:12`),
  simply carries the already-existing input difference into the scoring crops.

## 10. Case Split Results

- Case A (geometry differs → pixels differ): 0–93 files per R (§9). Compared
  separately since pixel comparison across geometries is meaningless.
- Scoring crops (`centerCropResize`, integer nearest-neighbor): only

  R384 12, R512 12). The crop stage is exact integer arithmetic, so it does not
  introduce a new error; it carries the f/a pixel divergence that already

- Case B (geometry equal → pixels differ): dominant. Flip files, full sweep
  R∈{128,192,256,288,320,352,384,512}:

## 16. Answers to Three Questions + Verdict

- Q1: the f/a pixel divergence arises from the two-step Fant chain + the
  intermediate 8-bit quantization + different resampling chains. Specified
  numerically (§7, §10, §12). `centerCropResize` in the scoring stage only
  carries that difference into the crops; it is not the origin.
- Q2: algorithm (Fant vs nearest) + resolution (intermediate upsampling
  invention) + step count (2 vs 1) combined. No single cause.
- Q3: the R-boundary flips were artifacts; pure pairs show no boundary.
- Q4: amplified on tiny bilevel/edge images (32×32, 100×100 1-bit); EXIF
  uninvolved.
- Q5: **within the range actually investigated** (R=128, 192, 256, 288, 320,
  352, 384, 512) byte parity was not restored. Impossibility beyond that range
  is not proven and is not claimed.

## 17. DEFERRED Verdict and Reasons

The performance potential is measured, but production-semantics equivalence is
not yet sufficiently demonstrated. Candidate = `DEFERRED`, production adoption
= `NO`.

The verdict flip having been corrected to an artifact does **not** auto-accept
the candidate. The DEFERRED reasons are:

```text
1. f/a byte parity is not maintained
2. some a geometry differences exist (R128 93, R256 54, R384 39, R512 34)
3. real pixel divergence exists (even where geometry matches)
4. full-scan groups equivalence has not been measured
5. no EXIF orientation fixture → that path is unverified
6. no PGM fallback coverage → that path is unverified
7. production-semantics equivalence is not sufficiently demonstrated at this
   stage
```

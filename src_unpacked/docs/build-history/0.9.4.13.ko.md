# MediaSimilarityFinder v0.9.4.13 — Node C4.1: Calibration Lifecycle Fix

**GPT Fix — 후속 결함 수정**

v0.9.4.12 C4 게이트 이후 확인된 Calibration/Profile lifecycle 미비점을 수정합니다. 공식 기준선 0.9.2.32, CUDA/GPU abstraction, CPU fallback은 유지합니다.

## 변경 필요성
- GPU OFF에서 생성된 CPU-only/partial profile이 GPU ON 다음 실행에서 identity상 Exact로 남을 수 있었습니다.
- 문서상 30일 stale 정책과 실제 scan 경로의 never-stale 호출이 불일치했습니다.
- CPU model과 GPU driver 필드는 존재했지만 실제 engine identity에 채워지지 않았습니다.
- 불완전한 재보정 후보가 기존 profile을 덮어쓸 가능성을 C4의 보존 원칙과 일치시킬 필요가 있었습니다.

## 기존 구조
- 초기 calibration은 Missing/Hard verdict 중심으로만 시작되었습니다.
- scan path는 stale age를 -1로 전달했습니다.
- CPU model/driver identity가 빈 상태일 수 있었습니다.
- 기존 profile이 있는 retry에서도 incomplete candidate가 저장될 수 있었습니다.

## 변경 구조
- profileNeedsCalibration()을 추가해 현재 실행 조건에 필요한 throughput이 없으면 Exact/Soft profile도 재보정 대상으로 만듭니다.
- 기본 stale age를 30일로 적용합니다. -1은 명시적인 진단용 never-stale 호출로만 남깁니다.
- CPU model을 best-effort로 수집하고 CUDA driver version을 GPU backend에서 profile identity로 전달합니다. 확인할 수 없는 값은 추측하지 않습니다.
- 기존 profile이 있는 상태에서 incomplete/failed retry는 저장하지 않습니다. 신규 profile은 GPU-OFF처럼 의도된 partial 상태를 보존할 수 있으며 GPU-ON에서 다시 보정됩니다.
- GPU OFF→ON lifecycle, stale, metric-gap regression test를 추가했습니다.

## 해결된 문제
- GPU OFF→ON 전환 후 GPU throughput baseline이 없으면 자동으로 calibration 대상이 됩니다.
- 30일 이상 지난 profile은 stale로 분류됩니다.
- 가능한 CPU/GPU identity 정보가 profile matching에 반영됩니다.
- 실패한 retry가 기존 usable profile을 파괴하지 않습니다.

## 정확성 영향
- 검색 알고리즘, threshold, candidate index, match semantics는 변경하지 않습니다.
- profile은 scheduler initial estimate에만 사용되고 live throughput 우선순위는 유지됩니다.

## 호환성 영향
- Profile INI schema/version은 변경하지 않습니다.
- CUDA abstraction과 CPU fallback을 유지합니다.
- 공식 기준선 0.9.2.32는 수정하지 않습니다.

## 검증
- Source-level regression tests를 추가했습니다.
- **Windows CPU/GPU Release build + full CTest: PENDING.** 현재 사용자의 CPU/GPU 트리에서 재빌드하기 전까지 PASS 수를 주장하지 않습니다.
- **GPT Fix validation:** 0.9.4.13 version, CTest, smoke, GPU 실기 calibration을 CPU/GPU 트리에서 확인해야 합니다.

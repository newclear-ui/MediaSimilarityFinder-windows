## 2. Splitter middle-first policy (0.9.4.63)

- Cause: stretch factors `(0,0,1)` sent every window-growth pixel to the
  right detail pane. Defaults `{200,330,950}` were right-heavy too.
- Change: stretch `(0,1,0)` — growth is absorbed by the similar-group pane.
  Defaults `{200,720,560}` (right fits about 4 preview images at 4x128).
- Saved states are never deleted. After restore, only a middle minimum is
  enforced (320), borrowed from the right (minimum 360) then the left
  (minimum 140).
- Measured (offscreen 1500->1850->2200): `200/720/560` -> `200/1070/560` ->
  `200/1420/560`. Right growth 0, middle absorbs everything.

## 4. Test Mode design review outcome — DEFERRED

- Name fixed: KO `테스트 모드` / EN `Test Mode` (usable).
- The old GUI benchmark worker/storage was deleted for cause in the S4 reset
  (`docs/architecture/legacy/S4_GUI_BENCHMARK_REMOVAL.ko.md`). Not revived.
- The current S2/S5 `BenchmarkRunner` is a suite, journal, and mode execution
  model — the wrong abstraction for comparing one user search. Reusing it in
  the GUI would resurrect exactly the GUI benchmark runner S4 forbids.
- The honest minimal shape is a scratch-AppDir real scan (a separate index
  directory, so the real index is untouched by construction, plus telemetry
  and timing). A `TelemetryPurpose` distinction mechanism exists.
- Not forced into this build because it needs a UI surface, a scratch
  lifecycle (cleanup policy), a telemetry distinction decision, and
  acceptance tests — beyond the small-and-certain mandate.
- Resume conditions: those four decisions plus a separate version. The
  Settings home follows up in the new display-settings dialog family.

## 5. Visible-range traversal review outcome — DEFERRED

- Current shape: full walk with a rect-intersection check per row (decodes
  only for visible rows). At the 11k-group scale it costs milliseconds per
  tick, so it is not a correctness blocker.
- An indexAt-based range fails silently (permanent placeholders) under async
  Batched layout, the three view modes, or an unlaid-out viewport. Silent
  failure cannot be proven safe by test.
- So the full walk stays. Its risk is recorded as a performance cost, to be
  remeasured on a large dataset and revisited in a follow-up build.

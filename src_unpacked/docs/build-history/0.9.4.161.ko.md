# MediaSimilarityFinder v0.9.4.161 — 디코드 단계별 비용 분리 측정 (P1)

기준선 `0.9.4.160` → 본 빌드 `0.9.4.161`.
CPU CTest **134/134**, GPU CTest **134/135 + 무관한 타이밍 플레이크 1건 재시도 통과** (신규 CTest 없음, 기존 테스트에 단언 추가).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` 전부 불변.

## 1. 변경 필요성

- 외부 리뷰 P1 지적: 파일별 decoded/sampled/kept는 있으나 디코드 시간·grayscale 변환 시간·pHash 시간·MSSIM 시간의 분리 계측이 없어, 55분 스캔 같은 디코드-바운드 실행에서 실제 비용 귀속을 판단할 수 없었다.

## 2. 기존 구조

- `VideoBuildStats`: decoded/sampled/kept + cacheHit + planner + gpuMs만 보유. 스윕 wall time과 CPU pHash 시간은 어디에도 기록되지 않았다.
- `TelemetryRecorder::addVideo`: 파일 수·바이트·프레임·빌드 시간만 집계. 단계 분리는 이미지(D4a per-boundary)에만 있었다.

## 3. 변경 구조

- `VideoBuildStats`에 `decodeMs`(스윕 wall time: 디코드+grayscale 변환, sparse/sequential 양 경로 포함) + `phashCpuMs`(CPU pHash 계산 시간만, GPU 커버 시 0) 추가. 캐시 히트는 둘 다 0으로 기록한다(측정된 0, `decodedFrames`와 동일 계약).
- `TelemetryRecorder::addVideoStages(decodeMs, phashCpuMs)` 신설(기존 `addVideo` 시그니처 불변) + `videos.decodeMs`/`decodeMsState`·`phashCpuMs`/`phashCpuMsState` JSON 키 추가(additive, 스키마 불변). `start()`에서 리셋하므로 run 간 inherited 없음.
- `media_search_engine` analyze 경로에서 `telemetryOn` 시 매 파일 호출.
- 회귀: `analyze_telemetry_test`에 측정/미측정 계약 단언 추가(값 기록 시 measured, 미호출 시 null+not_measured). `video_complete_test` baseline에 `decodeMs>0`·`phashCpuMs>=0`·prime 미히트 단언 추가(실엔진 end-to-end).
- MSSIM 매칭 경로(CPU fallback/GPU)의 쌍 단위 시간 집계는 미포함 — 해당 경로는 `stats` 플러밍이 없어 호출부 2곳의 변경이 필요하므로 별도 작업으로 남긴다.

## 4. 해결된 상황

- 이후 실스캔 로그에서 파일별 `buildMs`를 `decodeMs + phashCpuMs + 나머지(GPU·DTW·오버헤드)`로 분해할 수 있다.

- 판정·저장·프로토콜·버전 전부 불변. 캐시 무효화 없음. JSON additive라 구 리더와 호환된다.

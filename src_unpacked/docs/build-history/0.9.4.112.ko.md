# MediaSimilarityFinder v0.9.4.112 — S4 GUI 상세 로그 저장/종료 acceptance (저장 단위 분리 + 실버튼 E2E)

## 1. 변경 필요성

Active Build Queue 우선순위 2(S4)의 남은 공백: "GUI Detailed Logs 최종 화면 + 저장 acceptance — 실제 Search/Update → Detailed Logs → **저장**/종료 경로를 확인". 기존 `scan_detailed_log_acceptance_test`는 생성·표시(다이얼로그 열림)·텔레메트리 내용까지 검증했지만 **저장 경로(JSON 파일 기록)와 저장 실패 분기, 종료 경로가 미검증**이었다. 또 문서 상태 충돌(brief의 "GUI visible UI PASS(사용자 확인)" vs 진행 문서의 "최종 화면 acceptance 미완료")을 정리해야 했다.

## 2. 기존 구조와 결함

- 저장은 다이얼로그의 Save 버튼 → `QFileDialog::getSaveFileName` → 파일 기록 → 상태 메시지의 익명 람다에 인라인되어 있어 단위 검증이 불가능했다.
- **실결함(저장 성공 오판)**: 기록 조건이 `f.write(json.toUtf8()) >= 0` — **0바이트/부분 기록도 성공으로 표시**될 수 있었다("Detailed log saved"가 거짓이 될 수 있음).
- 종료 경로: 다이얼로그 닫기 → 앱 종료 후 크래시 없음이 회귀에 명시적으로 없었다(간접 확인만 존재).

## 3. 변경 구조

- **`MainWindow::saveDetailedLogTo(path, json)`** (gui/mainwindow.cpp, private): 저장 로직을 다이얼로그에서 분리한 단일 단위. `f.write(bytes) == bytes.size()`로 **정확한 바이트 수를 요구**하고, 성공 시 `detailLogSaved + path`, 실패 시 `detailLogSaveFail` 상태 메시지를 설정하고 bool을 반환한다. Save 버튼 람다는 파일 피커만 담당한다.
- **테스트 훅 `testSaveDetailedLog(path)`** (gui/mainwindow.h): `lastTelemetryJson_`을 같은 저장 단위로 기록 — 실패 분기 검증용.
- **`scan_detailed_log_acceptance_test` 확장** (실버튼 E2E): 모달 타이머가 ① 상세 로그 다이얼로그의 **실제 Save 버튼**을 클릭(0지연 singleShot으로 타이머 재진입 한계 우회 — Qt는 같은 타이머 핸들러가 스택에 있는 동안 그 타이머를 재진입시키지 않아, 클릭이 파일 다이얼로그의 중첩 exec을 열면 closer가 처리할 수 없었다) ② 파일 다이얼로그에서 목표 경로를 **이름 에디트에 직접 설정**(`selectFile`은 이름 에디트가 포커스를 가지면 이름을 건너뛰는 Qt 동작)하고 다이얼로그가 그 경로를 보고할 때만 accept ③ 저장 직후(같은 호출 스택) 상태 라벨에서 저장 경로를 캡처(이후 스캔 종료 메시지가 덮어쓰기 전). 검증: 파일 존재 + **저장 레코드 == 텔레메트리 레코드(JSON 동등)** + 상태에 경로 표시 + **쓰기 불가 경로는 실패(false)** + 다이얼로그/앱 종료 후 정상 진행.
- **문서 상태 정리**: S4 brief(ko/en) 현재 상태 갱신 — 기능 acceptance(생성→표시→저장→종료)는 자동화 PASS, 화면 렌더링 육안은 headless로 "하지 않음" 기록 유지, S4 최종 CLOSED는 §10 종료 조건에 따라 product acceptance 재확인과 연계 유지.

## 4. 해결된 상황

- 저장 경로가 실제 버튼 → 파일 피커 → 파일 기록 → 상태 표시까지 end-to-end로 검증되고, **부분/0바이트 기록이 성공으로 표시되던 오판이 제거**됐다. 실패 분기도 실패로 보고된다.
- 문서 상태 충돌이 정리됐다: 자동 검증 가능한 부분(생성·표시·저장·종료)은 PASS로 기록, headless 한계(실제 화면 렌더링 육안)는 "하지 않음"으로 명시 유지.

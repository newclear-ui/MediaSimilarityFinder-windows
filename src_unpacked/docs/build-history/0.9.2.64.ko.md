# MediaSimilarityFinder v0.9.2.64 — 정지 직접 전달 + 비디오 진단 카운터

## 변경 필요성
런타임 감사에서 확정: 일시정지/중지 버튼의 QueuedConnection 슬롯은 `run()`이 worker 스레드 이벤트루프를 점유하므로 스캔 중 절대 실행되지 않았다. 버튼 표시만 바뀌고 실제 플래그가 서지 않아, StopCheck·체크포인트·CANCELLED UI가 함께 무력화되고 강제종료로 이어졌다. 또한 "3시간 0건" 같은 비디오 스캔의 탈락 지점을 추정(timeout/후보/temporal/매치 단계 구분 불가)할 수단이 없었다.

## 기존 구조
- `togglePauseScan`/`cancelScan`이 `invokeMethod(..., QueuedConnection)`으로 worker 슬롯 호출. `run()` 실행 중에는 이벤트루프가 돌지 않아 영원히 대기
- `SearchReport`/`ScanStats`에 비디오 단계별 카운터 없음

## 변경 구조
- **직접 호출 전환**: `worker_->pause()/resume()/cancel()` 직접 호출. 세 함수 모두 atomic store만 하므로 스레드 안전. 소멸자의 직접 `worker_->cancel()`이 선례. Queued 슬롯 방식의 구조적 결함 해소
- **진단 카운터**: `ScanStats.videoCandidates/videoTemporalChecks`, `SearchReport.indexedVideos/videoCandidatePairs/videoTemporalChecks/videoMatches`. 스캔 종료(완료·중단 공통) 시 `msf_scan.log`에 `videoStats` 1줄 기록. `finished` 메시지 포맷(위치 파싱)은 불변
- 버전 표기 통일 → 0.9.2.64

## 해결된 상황
- 스캔 중 일시정지·중지가 즉시 반영. CANCELLED 경로·부분 저장·부분 표시가 실제로 동작
- 비디오 0건 발생 시 로그 한 줄로 탈락 단계 특정 가능 (인덱싱/후보/temporal/매치)

# MediaSimilarityFinder v0.9.2.42 — Search Feel Fixes (Walk Progress, Merged Buttons, State Save)

## Need for change
On-machine report: after pressing scan, the file counter never moved and CPU/GPU stayed at 0%, feeling like "search does nothing". Measurement showed two correct behaviors behind it. (1) Walking a 271,837-file folder alone takes **23 minutes** (196 files/s) with no progress callback — only disk reads visible. (2) Re-scanning an indexed folder legitimately uses ~0% CPU, but the UI never distinguished it. Also flagged: split pause/resume buttons, double-click tree selection, unsaved window sizes.

## Previous structure
- `Scanner::scan()` returned after the full walk with no progress reports. `ScanControl::progress` fired only during analysis
- Separate pause/resume buttons, always enabled. Split `pauseScan`/`resumeScan` slots
- Left tree selected folders via `itemActivated` (double-click/Enter)
- Main window and settings popup geometries not saved (splitter only)

## New structure
- Optional `onProgress` callback on `Scanner::scan()` (every 2000 files + at end). New `ScanControl::listing` carries the walk count. The worker relays it as a `listingProgress` signal; the GUI shows an indeterminate bar plus "Listing files… N". First analysis progress restores the determinate bar. Existing signatures keep working (null default)
- Single pause/resume toggle (`pause_`, checkable). Click swaps text/check/message; reset on start/finish. Unified `togglePauseScan` + `scanPaused_`
- Action button states: while running, `scan_` disabled with `pause_`/`cancel_` enabled and checked highlights; restored on finish. Monitor pause button checked in sync
- Tree `itemClicked` added (`itemActivated` kept → Enter key still works; clicks are idempotent so duplicates are safe)
- `QSettings(ui/mainGeom)` window geometry, `ui/settingsGeom` settings popup save/restore
- Version strings unified → 0.9.2.42. Mockup B v4 updated

## Resolved situation
- Counter moves immediately on huge-folder scans. Unchanged re-scans show the "already up to date" message distinctly
- One fewer button, consistent state display

## Validation
- Core Release build: PASS, **CTest 39/39 PASS** (engine changes are additive-only), `--smoke` exit 0, `--version` 0.9.2.42
- Walk measured: 271,837 files / 23 min / 196 files·s⁻¹ (user folder, direct measurement). Use as the baseline for large-scan time estimates

## Future impact
- The `listing` callback is independent of pause/cancel (pause applies at the analysis stage). Cancel during the walk takes effect when the scan loop starts — noticeable on 100k+ folders; add a cancel check inside the walk loop if needed (separate version)
- ETA display needs a total count, unknowable upfront. Can be estimated from the second scan on using stored index statistics

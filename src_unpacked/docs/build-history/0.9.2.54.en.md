# MediaSimilarityFinder v0.9.2.54 — Folder H-Scroll, XL Default View, UI-State Restore, Progress Throttle, High Mode, Multicore Fixes

## Need for change
Six field reports: (1) no horizontal scrollbar in the left folder explorer, hiding long paths, (2) group view starts at Large icons instead of Extra-large, (3) resized window/pane layout not restored after restart, (4) only some cores get work, (5) Maximum freezes the UI (not responding, can't move/pause/quit), (6) a middle step between Maximum and Balanced wanted (75% CPU/GPU target).

## Previous structure
- Folder tree (`folders_`): hidden header + single column stretched to the viewport, so the default `stretchLastSection` suppressed the horizontal scrollbar forever
- Group view default `QSettings("ui/groupView", 1)` = Large icons
- Persisted UI state: window geometry + main splitter only. Tree/list column widths not saved
- Image CPU-fallback hash loop (`media_pipeline.cpp`) ran serially on the batch thread. Decode worker cap 16
- `control_.progress` emitted per analyzed file → queued signals → `scanProgress` ran setText/setValue/`updateStatusCounts` (full group walk) per file. At Maximum speed the GUI event loop drowned and froze
- Four resource modes (Maximum 90 / Balanced 55·60 / Gaming 25 / Custom). Combo index+1 = enum mapping

## New structure
- **Folder h-scroll**: `header()->setStretchLastSection(false)` + `ResizeToContents` → column sizes to contents, scrollbar appears on overflow
- **XL default view**: `ui/groupView` default 1→0, invalid-value clamp to 0 as well
- **UI-state save/restore expanded**: new `saveUiState()`/`restoreUiState()`. Besides geometry+splitter, imgTree/vidTree/list header states persist. Saved in the destructor, restored after `buildUi+applyStaticTexts`
- **Progress throttle**: worker thread keeps latest done/total/path in members and emits at most every 150ms. Final values flushed when the scan returns. Pause/cancel/close stay responsive
- **High mode**: enum reordered (Maximum=1, High=2, Balanced=3, Gaming=4, Light=4, Custom=5) + `make_policy` High→75/75. "High" added to the combo after Maximum, Balanced default index 2, Custom index 4. Existing i+1 mapping preserved. `resource_policy_test` extended with High assertions (75/75, 16 threads→12 workers, batch 64→48)
- **Multicore**: decode worker cap 16→32, CPU-fallback pHash+mirror loops parallelized via `parallelFor`
- Version strings unified → 0.9.2.54

## Resolved situation
- Long folder paths scrollable horizontally. Starts at extra-large icons. Window/splitter/column widths restore
- Progress display capped at ~7Hz keeps the UI responsive even on Maximum. CPU hashing without GPU and decoding on 32-thread machines now use all cores

## Validation
- Core+GUI Release build: PASS, **CTest 42/42 PASS** (incl. High coverage in `resource_policy_test`)
- `--version` 0.9.2.54, `--smoke` exit 0 (offscreen)
- CUDA algorithms unchanged (common layers only)

## Future impact
- Enum reorder could shift a stored preset index, but the preset index is never persisted — no impact
- Throttle interval (150ms) and checkpoints are tunable if needed
- Fixed tile size (320×76) remains a zoom-slider candidate

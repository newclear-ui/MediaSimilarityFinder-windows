# MediaSimilarityFinder v0.9.4.102 — 상세 폼 동기 활성화

기준선 `0.9.4.101` → 본 빌드 `0.9.4.102`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 실측(0.9.4.101, 스크린샷 2장 + `msf_scan.log`): 불러오기 후 그룹→파일 선택 시 미리보기는 표시되지만 상세 텍스트가 전부 비고, 일부는 0.5초 미만으로 떴다 사라진다. 데이터 경로는 멀쩡하다(행 9개, 유효 파일, `detailAnomaly` 1건 제외 무음). 즉 presentational blank다: 행은 있으나 그려지지 않는다.

## 2. 기존 구조

- `refreshDetail()`은 폼 객체를 교체한 뒤 지오메트리 계산을 이벤트 루프의 지연 활성화에 맡겼다.
- 썸네일 버스트 트래픽(9000 그룹, 도착마다 선형 순회 + `singleShot(0)` flush 체인 + 600ms 틱)에서는 지연 활성화가 무기한 연기될 수 있다. 고정 크기 미리보기는 레이아웃과 무관하게 그려지므로, 텍스트만 비고 미리보기는 살아있는 화면이 된다.
- 중간/우측 그리드는 같은 이유로 명시적 레이아웃 패스를 강제한다. 상세 폼만 강제하지 않았다.

## 3. 변경 구조

- **`detailForm_->activate()`**를 행 추가 직후에 동기 호출한다 (9행이라 저렴, 멱등). 무효화 폭풍과 무관하게 확정 지오메트리를 보장한다.
- **트립와이어 보정**: 메인 창이 보일 때만 기록한다. 숨은 창의 백그라운드 fileMeta 갱신은 `vis=0`이 정상이라 실신호를 묻는다.

## 4. 해결된 상황

- 상세 행은 구축 즉시 그릴 수 있는 지오메트리를 갖는다. 이후 무효화는 마지막 유효 지오메트리를 유지하므로 공백으로 돌아가지 않는다.
- `detailAnomaly`는 보이는 창의 진짜 이상에만 발화한다.

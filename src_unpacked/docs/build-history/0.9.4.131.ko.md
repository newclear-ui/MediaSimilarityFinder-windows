# MediaSimilarityFinder v0.9.4.131 — 표시 결과 세트 기준 카운터 통일 (요약 패널 + 상세 로그)

기준선 `0.9.4.130` → 본 빌드 `0.9.4.131`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (판정 불변, CTest 등록 수 불변).

## 1. 변경 필요성

- 0.9.4.130 자가치유로 결과는 정상 표시되지만, 남은 표시 공백: 전부 무변경인 재스캔에서는 A/AB가 아무것도 재계산하지 않으므로
  - 좌측 요약 패널 "유사 그룹"이 완료 메시지의 `r.groups`(그 스캔이 계산한 쌍 수)로 덮여 **0**,
  - 상세 로그의 `매치: candidates 0, pairs 0, groups 0` — 목록에는 저장 세트(예: 9070 그룹/15135 쌍)가 표시되는데도 기록은 0.
  사용자는 결과를 상세 로그로 판단해 온 흐름이므로(0.9.4.127~130 보고 연속) 이 불일치는 계속 오해를 만든다.
- 추가로 요약 패널은 **이중 기준**이었다: 스캔 중에는 `groups_.size()`(화면 목록의 클러스터 수)를 쓰다가, `refreshSummary()`가 종료 시 `lastStats_[3]`(쌍 수!)로 교체 — 값의 의미 자체가 바뀌었다.

## 2. 기존 구조

- 완료 메시지 `r.groups` = 이번 스캔의 쌍 수(st.groups + 라이브 소유) — GUI 패널이 이를 그룹 수처럼 표시.
- 텔레메트리 `matches` 카운터 = 엔진이 이번 스캔에서 방출/집계한 것(quick-load 저장 세트는 집계 밖).

## 3. 변경 구조

- `gui/mainwindow.cpp`: 요약 패널 "유사 그룹" = `groups_.size()`(화면에 보이는 목록의 클러스터 수)로 통일 — 스캔 중/종료 후 동일 기준. 중복 파일 수는 기존부터 목록 기준이었다.
- `src/scan_worker.cpp`: 엔진 스캔 직후, 표시 스트림 `allMatches_`(= quick-load 저장 쌍 + 이번 스캔 방출, 스코프/무시 필터 반영)에서
  - 중복 제거된 쌍 수(128비트 경로쌍 키: 시드 2종 FNV-1a — 표시/텔레메트리 전용, 판정 무관),
  - 경로 키 union-find(압축 포함)로 종류별 그룹 수·중복 파일 수를 계산해
  `MediaSearchEngine::applyDisplayedResultStats()` → `TelemetryRecorder::setDisplayedResultStats()`로 전달한다.
- `src/benchmark.{h,cpp}`: 표시 세트 오버라이드가 설정되면 JSON의 `matches.pairs/groups`와 `image*/video*` 필드가 표시 세트 기준으로 직렬화된다. `candidates`·`reductionPct`는 스캔 작업 지표로 유지. CLI 스캔은 이 경로를 호출하지 않으므로 저널은 스캔 자체 계산 기준을 유지한다(0.9.4.126 계약 불변).

## 4. 해결된 상황

- 무변경 재스캔에서도 상세 로그의 `매치`와 요약의 그룹/중복 파일이 **화면 목록과 일치**한다. 실측(18건 세트, AB 무변경 재스캔): `pairs=8, groups=3`(수정 전 0). 요약 패널도 3.
- 좌측 요약의 "쌍검증 (전체/확정)" 행은 `candidates`(스캔)/`pairs`(표시 세트)를 함께 보여준다: 신규·자가치유 스캔은 `19187 / 15135`처럼, 무변경 재스캔은 candidates 0이라 `-`로 표시된다(의도된 구분).

## 6. 향후 영향 및 한계

- 판정·저장·프로토콜·engine/DB/schema/cache·journal schema 불변. CTest 등록 수 불변(125/126).
- 표시 세트 통일은 GUI(ScanWorker) 경로에만 적용된다. CLI/저널의 카운터는 스캔 자체 계산 기준을 유지하며, 이 차이는 의도된 계약이다(저널은 배치 측정 기록, GUI 로그는 사용자 결과 기록).
- 128비트 쌍 키는 텔레메트리 카운트 전용이다(판정·저장·표시 목록 무관, 충돌 시에도 목록은 경로 기반 union-find가 지배).
- 요약 패널 "유사 그룹"은 이제 항상 클러스터 수다. 과거 로그/스크린샷의 같은 행이 쌍 수를 보여주던 시기와 숫자가 다를 수 있다(의미 교정).

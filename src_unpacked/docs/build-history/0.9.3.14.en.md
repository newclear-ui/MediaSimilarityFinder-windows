# MediaSimilarityFinder v0.9.3.14 — CUDA Row-Batch Acceleration for Video MSSIM

## Need for change
- The `thumb48`-based MSSIM stage (`frame_ssim`) in video temporal verification ran only on the CPU, bottlenecking second-stage verification as candidate counts grow into the tens of thousands.
- Only this stage needed acceleration, without changing DTW row dependencies or Hamming-gate semantics.

## Previous structure
- `video_similarity()` called CPU `frame_ssim()` for every Hamming-passing pair.
- `GpuBackend` exposed only the 32x32 pHash batch (`hashBatch`); no SSIM batch API existed.
- The `ScanPipeline` temporal stage and the `compareFingerprint()` live path did not share an SSIM GPU backend.

## New structure
- Added `GpuBackend::ssimBatch()` accepting paired 48x48 grayscale arrays and an output array.
- The CUDA kernel computes 36 8x8-window MSSIM values per pair with the same C1/C2 and averaging rules as the CPU.
- `video_similarity()` packs only gate-passing pairs per DTW row and never materializes the full matrix on the GPU.
- Rows smaller than 8, batch failures, and unsupported CUDA fall back to `frame_ssim()`.
- Normal and mirrored directions share one batch to cut call and transfer overhead.
- `ScanPipeline::setVideoGpuBackend()` connects the shared backend to temporal verification; scan, revalidate, and live paths in `MediaSearchEngine` use the same backend.
- `tests/video_gpu_benchmark_test.cpp` measures CPU/GPU time and accuracy for 1024 pHash frames, 2048 MSSIM pairs, and 32-frame DTW.

## Resolved situation
- The L3 SSIM verification stage is now CUDA row-batch accelerated.
- The verdict formula stays `0.4*Hamming + 0.6*SSIM`, and SSIM never promotes a Hamming reject.
- Engine verdict version (1.2.0) and DB schema (1.0.3) are unchanged, so no stored-pair revalidation is needed.
- Environments without CUDA and runtime failures continue through the CPU path.

## Validation
- RTX 3080 Ti measurements: 1024-frame pHash CPU 7.32ms → GPU 1.80ms (~4.1x); 2048-pair MSSIM CPU 7.18ms → GPU 2.36ms (~3.0x); 32-frame DTW CPU 7.22ms → GPU 5.34ms.
- GPU/CPU SSIM max error 0, pHash bit-exact, DTW score diff within 0.2.
- CUDA Release build PASS, **CTest 61/61 PASS**.
- CPU-only Release build PASS, **CTest 60/60 PASS** (CUDA-only test excluded; CPU fallback path).
- `video_ssim_test` GPU-equivalence regression PASS; new `video_gpu_benchmark_test` PASS.

## Future impact
- Per-row DTW calls and transfer costs bound the speedup on small candidate sets.
- Next candidates are crop-fingerprint batching, temporal pair batching, and NVDEC evaluation.
- Candidate-count wall time and VRAM still need measurement on a large real-video corpus.

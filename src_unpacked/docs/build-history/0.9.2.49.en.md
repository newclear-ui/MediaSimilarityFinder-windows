# MediaSimilarityFinder v0.9.2.49 — Selective Scan + Live Matching + Multicore

## Need for change
Large-scale field report: (1) no image/video-only scan option, (2) listing and matching separated so results appear only at the end, (3) progress percentage moving backwards, (4) hour-long stall at 99%, (5) ~0% GPU, (6) no live counters, (7) load concentrated on a few cores. Each addressed by cause.

## Previous structure
No scan-kind filter. `pipe.analyze` ran once after all analysis. Progress denominator (walked-so-far) grew mid-scan so percent dipped. Image decode strictly serial. Long single files froze the display.

## New structure
- **Selective scan**: `ScanControl::scanImages/scanVideos` (default true). Filtered kinds join the seen set (no-delete) but skip counting/analysis. GUI `Scan target ▾` dropdown (checked persistence, `ui/kindMask`). Passed to the worker
- **Incremental live matching**: new `ScanPipeline::addAndMatch()`. Running indexes promoted to members, `best()` extracted to a shared static. Each analyzed file compares against prior ones immediately and streams via `onMatch`. The final `analyze()` still runs (temporal second stage, unchanged pairs, retained vector). Stream duplicates are idempotent in the GUI union-find
- **Monotonic progress**: bar never decreases; message shows real `analyzed D / walked W (P%)` counts
- **Parallel image decode**: `imageBatch` decode + crop passes fan out over a hardware-thread cap (4–16). Index-ordered writes keep results deterministic; per-task exception isolation. GPU hash batching unchanged
- **Stall visibility**: the 600 ms timer recomposes the message with live elapsed. A long file shows frozen filename + growing time ("working" vs "dead")
- Open-source cross-check: our DCT pHash matches `aetilius/pHash`'s `ph_dct_imagehash` family (D<=8 aligns with the pHash ≤10 guide). Recorded as future candidates: `Pengfei-Kou/viddup`'s 3-stage pipeline (exact hash → duration prefilter → pHash), `akamhy/videohash` collage approach, `commonsmachinery/blockhash`
- Version strings unified → 0.9.2.49

## Resolved situation
- Image-only / video-only scans work. Matches display as analysis proceeds (final pass backfills temporal and unchanged pairs)
- Backward progress eliminated. Multicore image stage. Stall files identifiable

## Validation
- Core Release build: PASS, **CTest 40/40 PASS** (all scan paths green)
- Equivalence probe (280 real media files): live 19 = final 19, fully identical (down to integer percents). `--smoke` exit 0, `--version` 0.9.2.49
- On near-zero GPU readings: hash kernels run milliseconds per batch, invisible to nvidia-smi by design. Real usage is proven by the `gpuImages` counter (probe: 255/255). NVDEC/nvJPEG-grade hardware decode is a separate-project scale and out of scope

## Future impact
- `addAndMatch` skips the temporal stage (final pass covers it). Fully incremental matching needs a temporal streaming design (separate work)
- Recorded next efficiency candidates: exact-copy fast path (xxHash-style, cf. viddup L1), duration prefilter (L2), low-variance frame exclusion. All additive on the current structure
- `ScanControl` kind flags default true: existing callers unaffected

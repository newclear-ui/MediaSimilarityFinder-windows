`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /

## 1. Why the change was needed

The fingerprint phase reads everything for minutes while reporting nothing to
the UI. Users see disk I/O with all counters at 0 (`images.count` only moves
during analysis, by design).

Path tracing confirmed two more embedded problems:

- **The fingerprint runs even with telemetry OFF.** The
  `setDatasetFingerprint()` call was unconditional, so unchecking Detailed Logs
  still paid the full-hash I/O. The fingerprint result is never used for scan
  behavior, so that is pure waste.
- Scope-blind hashing (hashing videos on an images-only scan) would change the
  fingerprint definition, so it stays a separate task.

## 2. Previous structure

- `computeDatasetFingerprint(root, cancel)` — no progress parameter
- No fingerprint callback in `ScanControl`
- `scan()` always ran the fingerprint regardless of telemetry

## 3. New structure

### Progress reporting (existing percent math untouched)

- New `ScanControl::fingerprintProgress(filesHashed, bytesHashed, path)`
- `computeDatasetFingerprint(root, cancel, progress)` — fired per hashed file.
  No internal throttling; the UI throttles
- Forwarded from `scan()` through the control callback
- The GUI receives a separate `fingerprintProgress(qulonglong,qulonglong,QString)`
  signal so walk/analysis percent math is untouched

### GUI display

- 150 ms throttle (same as walk callbacks), protecting the event loop at
  thousands of files per second
- Indeterminate bar + `Fingerprinting: N files, X.X GB — path`
- Paths over 72 chars show the last 69 with a `...` prefix
- Translation key `fpProgress` added and registered in the tr-keys gate
  (`checked=57`)

### Telemetry-OFF skip

```cpp
if (telemetryOn) { setPhase; setDatasetFingerprint(...); }
```

With telemetry off the fingerprint does not run and stays `not_available`.
Null-control safe (existing ternary kept).

## 4. Resolved situation

- Live progress during fingerprint (file count + GB)
- Minutes of hash I/O saved when Detailed Logs is off
- Normal completion, cancellation, and meanings unchanged

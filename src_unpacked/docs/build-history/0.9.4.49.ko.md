# MediaSimilarityFinder v0.9.4.49 — Detailed Logs 사용자 요약 추가

기준선 `0.9.4.48` → 본 빌드 `0.9.4.49`.
CPU CTest **105/105**, GPU CTest **106/106** (기존 104/105 + 신규 1).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변.

## 1. 변경 필요성

Detailed Logs 에는 벤치마크·진단용 내부 계측이 많지만, 일반 사용자가 검색 결과를
이해하는 요약이 없었다. 특히 **중복 파일 총개수가 어디에도 없었다.**

요구된 한눈 요약:

```
Search Duration       : 12m 34.5s
Images  scanned       : 12,438  analyzed : 12,401  throughput : 16.4 files/sec
        duplicate groups : 183   duplicate files  : 527   duplicate pairs : 412
Videos  ... (동일 형식)
Total   scanned / analyzed / duplicate groups / duplicate files
```

여기서 `duplicate files` 와 `duplicate groups` 는 다른 것이다 (멤버 수 vs
클러스터 수). 반드시 분리한다. 시간도 전체 `wallMs` 하나가 아니라
Total / Image processing / Video processing / Matching 으로 나눈다.

## 2. 기존 구조

- `SearchReport.groups` 는 매치된 **쌍 수**를 셌다 (`ScanPipeline` 이 threshold
  이상 pair 마다 `++groups`). 클러스터 수가 아니다.
- telemetry `matches.groups` 는 union-find distinct root 수 (**클러스터 수**)를
  셌다. GUI 가 같은 방식으로 재구축하므로 사용자에게 보이는 것과 일치한다.
- 종류별 분리는 어디에도 없었다. 내부 candidate index 는 이미지/비디오가
  분리되어 있으나 telemetry 에는 합산만 담겼다.
- `images.count` / `videos.count` 는 analyzed 수이며, scanned 종류별 수는 없었다.

## 3. 변경 구조

### 의미 고정

- duplicate pairs = threshold 이상 verified match 쌍 수 (종류별)
- duplicate groups = distinct linkage cluster 수 (종류별)
- duplicate files = pair 에 참여한 파일 수, 즉 멤버 수 (종류별)
- 클러스터는 종류를 넘지 않는다 (이미지·비디오 인덱스가 분리). 종류별 groups 는
  전체를 정확히 분할한다.

### 엔진 (`SearchReport` 10개 필드)

`imgScanned/imgAnalyzed/vidScanned/vidAnalyzed` (processOne·outcome 시점 계수),
`imgPairs/vidPairs` (onMatch 콜백에서 left 기준, 양쪽 종류 일치 시에만 계수),
`imgGroups/vidGroups/imgDupFiles/vidDupFiles` (cluster 블록에서 root·멤버를
종류별로 집계). 조기 반환 지점에도 scanned/analyzed 종류별 값을 반영했다.

### Telemetry (`matches` + `images`/`videos`)

`images.scanned` / `videos.scanned`, 그리고 `matches` 에
`imagePairs/imageGroups/imageDuplicateFiles` +
`videoPairs/videoGroups/videoDuplicateFiles` 를 추가했다.
`breakdownState` / `scannedState` 는 measured/not_measured 규칙을 따른다.

### GUI (`showDetailedLogDialog`)

대화창 최상단에 요약 블록을 먼저 보여준다. Duration 은 `12m 34.5s` 형식.
throughput 은 측정된 analyzed 수 ÷ 측정된 stage ms 로 계산한다 (두 입력 모두
실측이므로 파생이 정당하다). 기존 상세 행은 그대로 유지한다.

번역 키 9개 추가 (`detailLogSummary`, `detailLogDuration`, `detailLogDupGroups`,
`detailLogDupFiles`, `detailLogDupPairs`, `detailLogThroughput`, `detailLogTotal`,
`detailLogTimeSplit`, `detailLogMatching`). tr-keys gate 에 등록했다.

## 4. 해결된 상황

- Images/Videos/Total 행에 scanned/analyzed/throughput 표시
- duplicate groups/files/pairs 를 종류별로 분리 표시
- 시간 배분 Total/Image/Video/Matching 표시
- 중복 파일 총개수 공백 해소

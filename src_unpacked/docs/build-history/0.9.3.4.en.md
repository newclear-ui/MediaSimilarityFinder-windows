# MediaSimilarityFinder v0.9.3.4 — Always-On Benchmark Log, Log Button, Scroll Fix

## Need for change
1. With the toggle off, no log existed at all — no popup, no later review.
   The result log must be viewable regardless of the toggle.
2. Cancelling during revalidation (before the scan starts) showed no popup.
3. A manual button was needed for cases where the popup never appears.
4. Post-scan group-pane scrolling stuttered with missing thumbnails.

## Previous structure
- Toggle OFF never started the recorder, so `hasBenchmark()` stayed false.
- Revalidation ran before the recorder started, leaving early cancels with
  nothing to finalize.
- Group grids (`imgGrid_`/`vidGrid_`) lacked uniform sizes and batched layout
  (the file grid already had them).

## New structure
- Every scan records at least the skeleton (counts, stage times). Detail
  (sampler, per-item entries, slowest lists) is skipped when off. JSON marks
  `config.detail`, and the popup notes detail-off. Off-mode overhead is ~zero.
- The worker pre-starts the recorder before revalidation. Early cancels call
  `abortBenchmark()` (zero-filled finalize) and pop up when the toggle is on.
- Toolbar "Search Log" button: enabled and highlighted when a log exists,
  disabled (grey) when empty. Reopens the last log.
- Group grids get `setUniformItemSizes(true)` + `setLayoutMode(Batched)` to cut
  relayout cost while scrolling thousands of rows.
- Version strings unified → 0.9.3.4.

## Resolved situation
- Result logs are viewable after any scan, toggle on or off.
- Revalidate-phase cancels pop a finalized stopped log instead of silence.
- Scrolling renders in batches with less stutter.

## Validation
- Core+GUI Release build: PASS, **CTest 59/59 PASS**
  (`search_engine_test` toggle assertions updated to the new semantics: off-mode
  still records with `detail:false`; `benchmark_test` gains reset/abort coverage).
- Portable `--smoke` exit 0, `MediaSimilarityFinder-v0.9.3.4-Portable-Windows-x64.zip` produced.

## Future impact
- None. Off-mode default (results only) is unchanged, and the 1.0 removal plan stands.

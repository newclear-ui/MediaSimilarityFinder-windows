# MediaSimilarityFinder v0.9.3.9 — 검색 신선도·영상 fingerprint·Benchmark·Monitor 안정성 개선

## 변경 필요성
- v0.9.3.8 검토에서 size/mtime만 사용하는 incremental 판정, stale match 보존, XOR-zero 영상 제외, 긴 비디오 duration gate, GUI streaming benchmark pair 수 오류가 확인되었다.
- Monitor 시작 실패·GPU 설정 무시·지연 FIFO도 실제 상태와 UI/처리 순서를 어긋나게 할 수 있었다.

## 기존 구조
- 파일 quickHash가 DB에 저장되지만 변경 판정에는 사용되지 않았다.
- 변경/삭제 파일의 과거 match가 revalidate 단계에서 유지되었다.
- 영상 frame hash를 XOR 집계하고 결과가 0이면 실패 처리했다.
- 영상 temporal 후보가 duration 비율 4 초과이면 anchor가 있어도 차단됐다.
- Benchmark의 `matches.pairs`는 GUI가 retain하지 않는 report vector 크기를 사용했다.

## 변경 구조
- incremental 변경 판정에 `quickHash`를 추가했다.
- missing/changed 파일의 이전 match는 revalidate에서 제거하고 다음 스캔에서 재생성한다.
- 영상 aggregate를 비가역 fold로 바꾸고 sampling generation을 3, engine verdict version을 1.2.0으로 올렸다.
- duration gate를 통과하지 못해도 충분한 frame anchor가 있으면 temporal 검증 후보로 허용한다.
- Benchmark에 streamed match counter와 retained pair 수를 분리했다.
- Monitor GPU 설정을 policy에 반영하고, 비교 index open 실패를 start 실패로 반환하며, pending queue를 due-time priority queue로 바꿨다.
- GUI scan failure 시 이미 streaming된 match를 현재 화면에 반영하고 동점 그룹 정렬을 결정적으로 만들었다.

## 해결된 상황
- 같은 크기·시각으로 교체된 파일이 stale fingerprint를 계속 재사용할 가능성을 줄였다.
- 정상 영상의 aggregate가 0이라는 이유로 검색에서 제외되지 않는다.
- subclip 후보가 anchor를 가진 경우 temporal stage에 도달할 수 있다.
- GUI streaming scan의 benchmark pair 수가 실제 streamed match를 반영한다.

## 검증
- Release 컴파일: PASS.
- 기존 CTest 실행 중 `match_revalidate_test`가 새 engine version 기대값 때문에 처음 실패했으며 테스트를 1.2.0으로 갱신했다.
- 갱신 후 전체 CTest: **59/59 PASS**, Portable smoke: exit 0.
- 실제 대규모 영상 subclip Recall/Precision과 cold/warm benchmark 수치는 아직 측정하지 않았다.

## 향후 영향
- 영상 fingerprint 형식 변경으로 기존 영상은 sampling generation 3에서 재분석된다.
- Ground Truth corpus, cold/warm 반복 측정, H2D/kernel/sync/D2H GPU 계측은 후속 Benchmark Engine 확장 대상이다.

Baseline `0.9.4.64` -> this build `0.9.4.65`.
CPU CTest **111/111**, GPU CTest **112/112** (crash_diagnostics 5 to 7 checks).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged.
`src/media_search_engine.cpp`, scheduler, color_thumb, NVDEC, and sparse untouched.

## 1. Why the change

- Third `0xC0000409` crash on 2026-10-07 04:30. This time a WER LocalDumps
  mini dump (`MediaSimilarityFinder.exe.11104.dmp`) pinned the fault thread
  and stack (procedure: `docs/architecture/crash-response-runbook.en.md`).
- Established: exception code `0xC0000409` with parameter `0x7` is the
  `int 29h` fail-fast inside ucrtbase `abort()` (`abort+0x4E`). Not a Qt
  fatal (no `msf_qt.log`). Not heap corruption (no `0xC0000005`).
- The fault thread is the scan worker. The top of its stack is the
  `catch (std::exception&)` handler region of `ScanWorker::run` (a
  `persistMatchesSnapshot` call plus an `e.what()` virtual call plus
  `emit failed`, identified by PDB-less reverse lookup).
- Structural defect: `run()` is a Qt slot (wired straight to
  `QThread::started`), so an exception escaping a handler travels through
  Qt internals into `terminate()` -> `abort()`. The 0.9.4.62 catch-all
  catches the first exception, but if `persist` or `emit` inside the
  handler throws again, the process dies with the same signature. The dump
  points exactly at that path.

## 2. Previous structure

```cpp
} catch (const std::exception& e) {
  persistMatchesSnapshot();   // a throw here escapes the handler
  emit failed(e.what());
} catch (...) {
  persistMatchesSnapshot();   // same
  emit failed("unhandled non-standard exception in scan worker");
}
```

## 3. New structure

- `persist` and `emit` in both handlers are each wrapped in their own
  `try/catch(...)`. If persist fails, the `failed` report is still
  attempted, and vice versa. No path lets an exception leave the handler.
- Regression seam: `persistMatchesSnapshot()` throws on entry when
  `MSF_TEST_THROW_PERSIST` is set (test-only, never set in production).
  Combined with `MSF_TEST_THROW_NONSTD` it deterministically replays the
  dump's death chain (persist throwing inside the handler).

## 4. Resolved state

- A scan failure now always ends as a recorded `failed` with the process
  alive. SEH access violations still fail fast (no masking, keeping the
  0.9.4.62 principle).
- The dump cannot reveal the FIRST exception's origin (it died after being
  caught). With the handler alive, the next occurrence leaves a `failed`
  message behind.

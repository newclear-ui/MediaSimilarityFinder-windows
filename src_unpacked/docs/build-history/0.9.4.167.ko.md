# MediaSimilarityFinder v0.9.4.167 — start_time 기준 정규화 + V2/V3/V4 진단 본구현

기준선 `0.9.4.166` → 본 빌드 `0.9.4.167`.
CPU CTest **138/138**, GPU CTest **139/139** (신규 CTest 3건: video_structure_test, video_structure_e2e_test, video_kept_select_test).
`kEngineVersion 1.5.1 → 1.5.2` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10 → 11` / `kProtocol 1`.

## 1. 변경 필요성

- 외부 리뷰 P1 지적(0.9.4.166에서 실측 확정): `start_time != 0`인 컨테이너는 샘플 그리드 전체가 밀린다(측정: first-shift 2.5 s, kept 2 vs 3). 동일 콘텐츠가 서로 다른 지문이 되어 중복이 누락될 수 있다. 사용자 승인(a)으로 수정한다.
- 사용자 지시: V2/V3/V4를 구현해 두고 검증을 나중에 수행한다. 기본 동작은 변경하지 않는다.

## 2. 기존 구조

- `VideoDecoder::open()`은 start_time을 읽지 않았다. `framesAt`/`frameAtColor`/sparse executor는 요청 시각(영상 시간 0 기준)을 스트림 PTS에 그대로 대입했다.

## 3. 변경 구조

- `VideoInfo::startOffsetSec` 추가. `open()`에서 `start_time × time_base`를 기록(유한값만, 아니면 0). seek 시각에 더하고(+), 디코드된 PTS에서 뺀다(−). NOPTS 대체·tail 허용오차·완전성 계약은 video-time 기준으로 그대로 동작한다.
- 동일 시각 동일 콘텐츠는 동일 지문이 된다(0.9.4.166의 offset 파일 kept {2.5,5,8} → 본 빌드 {0,5}로 정규화, zero-start와 바이트 동일).
- V2: `probeVideoStructure()` (밝기·dark 비율·에지·프레임간 변화, median+3·MAD 경계, 구간 분할, confidence). 순수 함수 + 단위 테스트 + env 게이트(`MSF_VIDEO_STRUCTURE=1`) 실엔진 e2e. 캐시·영속·판정에 닿지 않는다.
- V3: `selectKeptSegmented()` (시간 구간별 최소 1장 + 전역 분산 채움, 시간순 정렬). `MSF_VIDEO_KEPT=segmented`에서만 사용, 기본 경로는 0.9.4.156과 바이트 동일.
- V4: 매칭 쌍별 `covShort/covLong/covSegments` 상시 계산(판정 불변) + `MSF_VIDEO_STRICT_COVERAGE=1` diagnostic 차단(미검증 임계값 명시). `AnalyzeTelemetry.videoMatchCov*` 합산 + JSON(가산).
- 엔진 1.5.1→1.5.2: offset 파일의 판정이 바뀌므로 저장 쌍을 1회 재검증한다. 캐시 10→11: 구 지문 1회 재구축. 관련 테스트 상수 갱신(match_revalidate, video_cache, crash_diagnostics).
- I-XMP CONDITIONAL → CLOSED, 현장 GUI acceptance → ACCEPTED (사용자 결정 2026-11-02).

## 4. 해결된 상황

- start_time이 0이 아닌 파일도 0 기준 파일과 동일한 샘플·동일 지문을 만든다(테스트로 고정).
- P1 V2/V3/V4 본구현이 들어갔고 기본 동작은 불변이다. 정확도 Gate 검증은 사용자 데이터셋 대기.

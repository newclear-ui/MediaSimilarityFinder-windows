# MediaSimilarityFinder v0.9.4.142 — 검색 중 화면 동결 (완료 시 한 번만 반영, 썸네일 재구성 churn 제거)

기준선 `0.9.4.141` → 본 빌드 `0.9.4.142`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변 (표시 전용).

## 1. 변경 필요성

- 실기(S-1 반복 확인): Load로 목록·미리보기를 채운 뒤 검색을 시작하면,
  - 이미 방문해 캐시된 페이지의 미리보기는 유지되지만,
  - **검색 시작 후 스크롤한 페이지의 미리보기가 채워지지 않고**,
  - 검색 중 그룹을 선택하면 오른쪽 파일 목록에 **대표 이미지 하나만** 보인다.
- 사용자 관찰대로 검색 시작 이후 목록 재구성/썸네일 채움이 멈춘 것처럼 보인다.
- 원인: 검색 중 빠른 로드/스트리밍 배치가 도착할 때마다 `refreshStreaming()`이 목록과 파일 패널을 다시 만들고, 새로 만든 행의 썸네일 요청이 **바쁜 백엔드 스캔 뒤로 밀려** 자리표시자로 남았다. 9,070그룹 규모에서는 재구성 자체도 churn이었다.

## 2. 기존 구조

- `refreshStreaming()`이 데이터 변화(`groupsDirty_`/`matchSeq_`)마다 `rebuildGroups()` + `refreshGroupList()` + `refreshFileViews()`를 수행.
- 스캔 중에도 이 경로가 돌아 목록이 다시 채워졌고, 새 행의 썸네일은 백엔드가 스캔으로 바쁜 동안 도착하지 못했다. 스크롤로 새 페이지가 보이면 그 행들은 계속 자리표시자였다.

## 3. 변경 구조

- 신규 `holdViewDuringScan_`: **검색 시작 시점에 화면에 결과 세트가 있으면**(`!groups_.isEmpty()`) 검색이 끝날 때까지 뷰를 동결한다.
  - `refreshStreaming()`은 동결 중 재구성/재채움을 하지 않고, 가시 영역 썸네일 캐시 적중만 적용(`thumbCatchUpVisible`)한 뒤 상태 카운트만 갱신한다.
  - 데이터는 계속 맵에 누적되며(퀵로드/라이브), `onResults()`가 도착하면 **한 번만** 목록/선택/미리보기에 반영한다.
  - 결과 적용(`onResults`), 정상 종료(`scanFinished`), 실패(`scanFailed`)에서 플래그를 해제한다.
- `beginScan`은 `viewHold=1/0`을 `msf_scan.log`에 기록해 현장 진단이 가능하다.
- 0.9.4.141의 원칙 유지: 선택/미리보기 유지, 매치 누적은 시작 시 초기화, `analyzed>0`일 때만 종료 후 썸네일/메타 무효화.

## 4. 해결된 상황

- 검색을 시작해도 로드된 목록·선택·미리보기가 재구성으로 흔들리지 않는다.
- 검색 중 목록 churn이 사라져, 스크롤 시 캐시된 페이지는 즉시 표시된다.
- 검색 완료 시 한 번에 새 결과가 반영되고, 변경이 있으면 가시 영역 썸네일이 갱신된다.

## 6. 향후 영향 및 한계

- 표시 전용(판정·저장·프로토콜·engine/DB/schema/cache 불변).
- **검색 중 처음 보는 페이지**의 썸네일은 여전히 백엔드가 생성해야 한다. 스캔이 디스크를 사용 중이면 생성이 느릴 수 있으며, 이 경우 완료 후 채워진다(캐시 적중 페이지는 즉시). 백엔드 썸네일 우선순위/프리페치는 후속 후보.
- 실기(2026-10-20, 사용자 확인): 캐시된 페이지는 검색 중에도 미리보기가 유지되지만, 검색 시작 후 처음 스크롤한 페이지는 여전히 미표시(완료 후 채움). 기능 빌드 우선 원칙에 따라 **DEFERRED**로 후순위 백로그에 등록(`development-progress` — 검색 중 새 페이지 썸네일 우선순위/프리페치).
- 첫 검색(화면에 결과 세트 없음)은 기존처럼 라이브 스트리밍으로 채워진다(동결 대상 아님).

# MediaSimilarityFinder v0.9.2.50 — 매치 영속화(빠른 불러오기) + 미리보기 WIC 폴백

## 변경 필요성
실사용 보고: (1) 이미지 검색 결과는 나오는데 미리보기(썸네일)가 보이지 않음, (2) 같은 폴더로 프로그램 재시작 후 재검색하면 이전 매치 그룹이 다시 나타나지 않음. 전자는 UI 썸네일 로딩, 후자는 매치 그룹이 메모리 전용이었기 때문으로 원인을 각각 규명 후 수정했다.

## 기존 구조
- 미리보기: `fileThumb()`이 `QImageReader`(Qt 이미지 포맷 플러그인)에만 의존. 포터블 배포에 포함되는 Qt6 plugins는 `qgif/qico/qjpeg.dll`뿐이라 `qpng.dll` 등이 없으면 PNG/JPEG 계열 썸네일이 무표시. (검색 엔진은 WIC 기반이라 특정 포맷 검색은 정상)
- 매치 그룹: `ScanWorker::onMatch`가 스트리밍으로 GUI에 전달되지만 그룹 결과는 메모리에만 존재 → 재시작 후 같은 폴더 재스캔 시 처음부터 다시 계산. `retainMatches`는 대용량 메모리 절감을 위해 의도적으로 꺼져 있었음.

## 변경 구조
- **매치 영속화**: `media_search_engine::saveMatches(SearchMatch 벡터)` / `loadMatches()`. 내부는 `database::matches(left_path, right_path, percent, PRIMARY KEY(left,right))` 테이블로 전체 교체 저장(upsert + 사라진 쌍 DELETE). 쌍은 `pairKey`(사전순 정규화)로 정렬해 DB에 기록. 인덱스 `idx_matches_left/right`, BEGIN IMMEDIATE 트랜잭션, 기존 SQLite WAL/busy_timeout 재사용
- **검색 버튼 통합(빠른 불러오기)**: `ScanWorker::run()`이 인덱스 오픈 직후 `loadMatches()`로 저장된 쌍을 `pending_`+`allMatches_`에 주입하고 `quickLoaded(n)`+`matchesArrived` emit. 그 후 증분 스캔이 "누락된 파일만" 분석하므로 이전 결과가 즉시 복원되고 오래된 그룹은 그대로 유지
- **저장 시점**: 스캔 종료 시(중단 포함) `allMatches_`(불러온 쌍 + 신규)를 통째로 `saveMatches()`. 중단 시 부분 집합 저장이라 마지막 완료 체크포인트가 유지되는 점은 스캔측 체크포인트 의미론과 일치
- **미리보기 폴백**: `fileThumb()`이 Qt 읽기 실패 시 `msf::ImageDecoder::decodePreserveAspect(path,256)` 그레이스케일을 사용. 검색 엔진이 쓰는 동일 WIC 디코더이므로 배포에 포맷 플러그인이 없어도 미리보기 확보
- 버전 표기 통일 → 0.9.2.50

## 해결된 상황
- 재시작 후 같은 폴더 검색 시 저장된 중복 그룹이 즉시 복원되고 신규 파일만 추가 검색됨. 사용자가 파일을 삭제/교체해도 갱신된 결과로 전체 교체 저장
- PNG 등 미리보기 복구 (Qt 플러그인 누락 환경에서도 WIC 경유)

## 향후 영향
- 스캔이 아닌 실시간 모니터 경유 매치도 저장 원하면 같은 `saveMatches` 경로 재사용 가능
- 빠른 불러오기는 스캔 시작 시 1회 수행. 저장된 그룹을 목록 UI에도 통합 표시하려면 별도 액션 추가 가능
- WIC 폴백은 흑백 미리보기. `IThumbnailCache` 연동을 다음 빌드 후보로 기록

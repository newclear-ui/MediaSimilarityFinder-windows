# MediaSimilarityFinder v0.9.2.72 — 엔진/DB 버전 체계 분리 (semver)

## 변경 필요성
v0.9.2.71의 엔진 버전이 정수 1개라 판정 변경의 크기를 표현할 수 없었고, DB 스키마 버전이 아예 없었다. 빌드 번호(0.9.2.x)와 무관하게 엔진 판정 세대와 DB 스키마 세대를 각각 추적하는 체계가 필요했다. 형식: patch=튜닝, minor=단계·규칙 추가(엔진) / 마이그레이션 필요 변경(DB), major=아키텍처 교체 / 파괴적 변경.

## 기존 구조
- `kEngineVersion = 1` (int), `engineVersion()/setEngineVersion(int)`. DB 버전 없음

## 변경 구조
- **`src/semver.h` 신설** (헤더 온리): `parseSemver`·`compareSemver`·`semverLess`. 결측·비정상은 0으로 ("", "abc" < "0.0.1"). 숫자 비교라 "1.0.10" > "1.0.2"
- **엔진 버전 문자열화**: `kEngineVersion = "1.0.1"`. `revalidateMatches`는 `semverLess` 비교. 기존 DB(버전 행 없음)는 "0.0.0"으로 승격 대상
- **DB 버전 신설**: `Database::kDatabaseVersion = "1.0.1"`, `meta.db_version`. `initialize()` 마이그레이션 완료 후 스탬프 (멱등이므로 open 후 항상 현행). `dbVersion()/setDbVersion()` 제공
- `match_revalidate_test` 확장: semver 순서 단언 5종 + db 스탬프 확인. 버전 표기 통일 → 0.9.2.72
- AGENTS.md에 버전 규칙(4번) 기록: 엔진 patch/minor/major 기준, DB patch/minor/major 기준, 빌드 번호와 분리·필요 시만 상향·상향 빌드는 history 명시

## 해결된 상황
- 판정 변경은 엔진 patch/minor/major 1줄 상향으로 재검증 경로 확보. 스키마 변경은 DB 버전으로 추적 개시 (파괴적 변경 시 게이트 근거 마련)
- 기존 DB는 "0.0.0"으로 자동 승격 대상. 저장 데이터 손실 없음

## 검증
- Core+GUI Release 빌드 PASS, **CTest 54/54 PASS** (semver·스탬프 단언 포함)
- `--version` 0.9.2.72, `--smoke` exit 0 (offscreen)
- CUDA 알고리즘 불변 (공통 계층만 수정)

## 향후 영향
- 다음 판정 변경 빌드는 엔진 minor/major 상향 + history 명시. DB 파괴적 변경 시 `dbVersion()` 게이트로 wipe+재스캔 분기 추가
- 빌드 번호는 기능 릴리즈용으로 독립 유지. 버전 3종(빌드·엔진·DB)의 historic table 후보

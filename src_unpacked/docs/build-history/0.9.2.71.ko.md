# MediaSimilarityFinder v0.9.2.71 — 엔진 버전 스탬프 + 저장 매치 재검증

## 변경 필요성
판정 로직이 바뀌어도(앵커·SSIM·이미지 게이트) 기존 DB의 저장 쌍은 그대로였다. 오탐을 잡으려면 전체 재스캔(100GB 규모에서 곤란)이나 DB 삭제뿐이었다. 엔진 버전을 기록하고, 구버전 DB는 전체 재스캔 대신 저장된 고유사도 쌍만 현행 로직으로 재검증하는 승격 경로가 필요했다.

## 기존 구조
- `matches` 테이블에 버전 개념 없음. 판정 변경 시 기존 오탐이 quick-load로 계속 표시
- 비디오 temporal은 analyze 내부 로컬 엔진(캐시 미오픈)이라 매번 전체 디코드

## 변경 구조
- **버전 스탬프**: `MediaSearchEngine::kEngineVersion=1` (판정 변경 시 상향). `meta` 테이블(`engine_version`, ancestries: 0=버전 이전). 스캔 시작 시 자동 확인
- **`revalidateMatches`**: 저장 쌍을 현행 파이프라인 판정(`analyze(8)`, L1+앵커+temporal+SSIM 동일 코드)으로 재실행. 워크·재분석 없음. 변경 파일·소실 파일은 유지(union), 지문 없음은 제외, 판정 실패만 제외 후 퍼센트 갱신 저장. 32쌍마다 취소 확인. 완료 시 버전 스탬프 (취소 시 미스탬프 → 다음 스캔 재시도)
- **공유 temporal 엔진**: `ScanPipeline::setSharedTemporalEngine` — 캐시 적중 시 재디코드 스킵 (판정 동일). 스캔 본경로에도 적용해 동일 속도 개선
- GUI는 스캔 시작·quick-load 전에 자동 실행, 유지/제외 건수 상태 표시
- `match_revalidate_test` 신설(진성 유지·bogus 제외·버전 스탬프·2회차 no-op). 버전 표기 통일 → 0.9.2.71

## 해결된 상황
- 구버전 오탐(85%급)은 다음 스캔 시작 시 재검증에서 제외, 진검출은 유지. 전체 재스캔·DB 삭제 불필요
- 재검증은 저장 쌍 수에 비례(파일 수가 아님), 1회성. 취소 가능

## 향후 영향
- 판정 변경 빌드는 `kEngineVersion` 상향 1줄로 승격 경로 확보. 지문 형식 변경(해시 자체)은 별도 버전으로 분리
- 재검증 중 비디오 temporal 디코드는 캐시 적중 시 스킵, 미적중 시 1회 발생 (스캔 본경로도 동일 개선 수혜)
- 테스트 중 `fresh()` 단위 함정 발견: 스캐너 stamp는 밀리초, raw count 비교 시 영구 불일치. 썸네일 mtime 건과 동일 패턴으로 문서화

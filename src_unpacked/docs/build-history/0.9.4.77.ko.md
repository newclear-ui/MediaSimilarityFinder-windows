# MediaSimilarityFinder v0.9.4.77 — ANSI 코드페이지 밖 파일명 크래시 수정

기준선 `0.9.4.76` → 본 빌드 `0.9.4.77`.
CPU CTest **118/118**, GPU CTest **119/119**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 검색 판정 의미 변경 없음. 스키마 변경 없음.

## 1. 변경 필요성

- 실제 사용자 스캔(`G:\Downloads\ss_twit`, 89% 지점)이 모달과 함께 죽었다:
  `No mapping for the Unicode character exists in the target multi-byte code page.`
- 이 문구는 narrow `std::string`이 `std::filesystem`으로 들어갈 때 MSVC가
  ANSI 코드페이지로 재해석하다 던지는 `filesystem_error::what()`이다
  (0.9.4.47의 `dataset_fingerprint` 건과 같은 종류).
- 데이터셋 전수 조사 결과 파일 273,169개 중 **1,778개**의 파일명이 CP949로
  매핑 불가였다. 분석 단계에서 그 중 하나에 닿자마자 worker 스레드에서 예외가
  나고 `ScanWorker` catch를 거쳐 `failed` → 모달로 보고됐다. 화면의 마지막
  파일명(ASCII)은 “마지막 완료 파일”일 뿐 범인이 아니다.
- 기존 `unicode_path_test`는 한글 파일명만 썼는데, 한글은 CP949에 들어가서
  이 버그를 잡지 못했다.

## 2. 기존 구조

- `path_from_utf8`/`path_to_utf8` 규칙이 있었으나 스캔 hot path에 narrow 잔재가
  남아 있었다. `std::ifstream f(path)`, `file_size(path, ec)`,
  `p.extension().string()`처럼 narrow UTF-8 바이트가 그대로 들어가면, `ec`를
  받아도 변환 단계에서 먼저 던진다.
- 잔재 위치: `database.cpp` 썸네일 quick-hash, `image_verify.cpp` verify key
  블록, `video_fingerprint.cpp` quickIdentity, `video_decoder.cpp` no-FFmpeg
  분기, `scanner.cpp`·`monitor.cpp` 확장자 판정.

## 3. 변경 구조

- 위 6곳을 전부 `path_from_utf8` / `path_to_utf8` 경유로 교체했다. 열기 실패는
  기존대로 `false`/스킵으로 흐르고, 예외를 던지지 않는다.
- `unicode_path_test`에 ACP 매핑 불가 픽스처(U+20000, CJK Extension B)를
  추가했다: walker 탐색, grey-zone `verifyImagePair` 디코드, 썸네일
  quick-hash roundtrip, 엔진 전체 스캔(2파일 분석 + 1쌍 저장)까지.
- 판정·매칭·스캔 의미 변경 없음. 실패 파일은 기존처럼 `analysis_failed`로
  기록되고 다음 스캔에서 재시도 정책이 그대로 적용된다.

## 4. 해결된 상황

- ANSI 밖 파일명이 있어도 스캔이 죽지 않고 해당 파일 단위로 실패/스킵 처리된다.
- 썸네일 서빙·검증·비디오 identity·확장자 판정이 모두 wide 경로를 탄다.

## 6. 향후 영향

- CP949 밖 파일명은 이제 스캔 blocker가 아니다. `ffprobe` CLI 자식 호출
  (`file_meta.cpp`, no-FFmpeg 분기)은 ACP 자식 프로세스라 매핑 불가 이름에서
  조용히 실패할 수 있는데, 죽지 않고 스킵되므로 별도 후속으로 둔다.
- 다음 `0xC0000005` 재현 시 fingerprint-0 프론티어와 LocalDumps를 함께 본다.

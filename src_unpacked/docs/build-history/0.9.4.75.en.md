# MediaSimilarityFinder v0.9.4.75 — Test Mode reintroduction and scroll/thumbnail follow-up

Baseline `0.9.4.74` → this build `0.9.4.75`.
CPU CTest **117/117**, GPU CTest **118/118**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — all unchanged. No search-verdict change.

## 1. Why the change was needed

- The old GUI Benchmark was removed by the S4 reset, and Test Mode stayed
  DEFERRED in `0.9.4.63` because UI surface, scratch lifecycle, telemetry
  separation, and acceptance were still open. The user then explicitly asked
  for a `Test` button next to Settings that reruns full processing even when
  an index exists, without touching the stored index.
- The required shape was the existing search path with only its storage
  location isolated—not a revived separate benchmark runner.
- A report remained that large-icon plus similarity-descending lists could
  jump back toward the top after scrollbar drag/wheel input. The confirmed
  code-level gaps were input coverage, duplicate thumbnail requests, layout
  frequency per arrival burst, and large-icon anchor measurement.
- The GUI-1% plus Backend-6–70% oscillation report was narrowed from code
  alone, without a user dataset/log. No scheduler-defect evidence was found,
  so worker sizing was not touched merely to chase utilization.

## 2. Previous structure

- `MainWindow::beginScan()` collected settings into `BackendScanConfig` and
  sent them through loopback or Supervisor JSON `START_SCAN`.
- `BackendSession::startScan()` passed the received `appDir` directly to
  `ScanWorker`; engine, video cache, profile, and thumbnails all opened under
  that `appDir`.
- The scroll gate watched `sliderPressed/sliderReleased` plus wheel/keys on
  views/viewports. Track clicks, gutter pages, arrow buttons, and wheel/keys
  focused on the scrollbar itself did not arm it.
- A thumbnail miss could be rerequested on consecutive ticks before the
  backend answered, and every arrival called `doItemsLayout()` directly.
- `fillPair()` captured the grid anchor at `(2,2)` and restored it with
  `scrollToItem(PositionAtTop)`. In wrapped large-icon layouts, that corner
  probe could miss, and partial-cell offsets were not preserved.

## 3. Changed structure

- **Test Mode toggle**
  - Added a checkable `Test` button immediately left of Settings.
  - Its state persists in `ui/testMode`, is restored after relaunch, and is
    highlighted when checked.
  - It is disabled during a scan so it cannot be mistaken for affecting the
    run already in progress.
  - It applies to the next scan start; crash auto-resume reuses the saved
    `BackendScanConfig`, preserving the same mode.
- **Isolated scratch execution**
  - `BackendScanConfig.testMode` travels in Supervisor `START_SCAN` JSON, and
    `BackendSession` uses the same worker/engine path with a fresh unique
    `<appDir>/TestMode/<folderId>-<timestamp>-<nonce>` instead of `appDir`.
  - Index DB, video cache, profile, and thumbnail DB all live under scratch,
    so the existing `<appDir>/Index` tree is never opened for writing by a
    test scan.
  - Missing JSON fields default to `false` for compatibility with older senders.
- **Wider scroll gate**
  - Connected `sliderMoved` and `actionTriggered`, so track clicks, gutter
    pages, and arrow-button moves arm the cooldown. Programmatic `setValue`
    does not emit those signals.
  - Installed the event filter on scrollbars too, treating wheel events over a
    scrollbar and focused scrollbar keys as user navigation.
- **Thumbnail-burst cleanup**
  - Identical path/size in-flight requests are not duplicated.
  - Arrival bursts schedule one zero-delay layout instead of one per arrival.
    While the scroll gate is active, layout stays deferred and retries after
    the cooldown, so Batched geometry does not move mid-gesture. The 0.9.4.66
    layout guarantee is preserved.
- **Stronger anchor restoration**
  - Grid anchors are measured at the viewport center, with exact pre/post
    content offsets restored.
  - Batched layout is settled before rebuilt anchor rectangles are measured;
    the old pixel fallback remains when no anchor is found.
- **CPU**
  - Scheduler, worker counts, decode parallelism, and I/O policy are untouched.
  - Policy-blind decode-pool width remains a lower-priority throughput-backlog
    item.

## 4. Resolved state

- The next scan with Test ON fully reprocesses into scratch even when an
  index exists, while existing `index.sqlite`, `video_cache.sqlite`, and
  `metadata.json` bytes remain unchanged.
- The next scan with Test OFF normally updates the existing index.
- Scrollbar drag, track clicks, and wheel input over scrollbars defer a wider
  rebuild/layout range.
- Thumbnail bursts no longer disturb an active drag, and large-icon anchors
  return to the same position including partial cells.
- Low/oscillating CPU alone does not prove a scheduler defect, and this build
  did not risk throughput on that assumption.

`view_mode_probe` failed once immediately after introducing coalesced layout.
Deferring arrival layout only to the next tick broke the 0.9.4.66 guarantee on
a path where the test stops timers. Changing it to one zero-delay layout plus
retry-after-scroll-gesture restored PASS. `ui_scroll_regression_test` also
flickered once on its dragged-position assertion under full-suite timing, and
was stabilized by settling the held position before arming the synthetic
press. Both failures were regressions observed during the fix and are covered
by the final full PASS.

## 6. Future impact

- Test Mode scratch directories are created per run and are not deleted
  automatically. Retention is intentional for inspection/comparison; a space
  rotation policy needs a separate follow-up decision.
- Test result screens do not yet carry an explicit mode label. The next-scan
  setting plus toggle highlight currently identifies the mode.
- User-dataset phase logs and real-Windows UI acceptance remain, especially
  large-icon, similarity-descending, large-group behavior.
- Low GPU duty and CPU oscillation are not targets by themselves. Follow-up
  performance work opens only on end-to-end throughput and queue
  starvation/backpressure evidence.

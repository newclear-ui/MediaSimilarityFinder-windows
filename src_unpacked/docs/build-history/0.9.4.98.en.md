# MediaSimilarityFinder v0.9.4.98 — Test-button visibility setting

Baseline `0.9.4.97` -> this build `0.9.4.98`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

User directive: put a Test-button show/hide setting in Settings > General, ordered Detailed Logs → CPU usage display → Monitoring GPU acceleration → Test button display, with the matching-verification mode last.

## 2. Previous structure

- The Test button (far right of the toolbar) was always visible with no way to hide it.
- General-tab order was language → detailed logs → CPU display → GPU acceleration → matching-verification mode.

## 3. New structure

- **New checkbox** (`gui/mainwindow.cpp` settings dialog): `Show Test button` (`showTestButton` key, `ui/showTestButton`, default ON). Placed after Detailed Logs / CPU display / GPU acceleration and before the matching-verification mode. Saved/applied through the existing save flow.
- **Toolbar wiring**: visibility through `testBtnAct_` (`applyTestButtonVisibility()`, same action pattern as the other switches). The toggle state (`ui/testMode`) is untouched; a hidden button keeps its checked state so re-showing restores behavior.
- Translation key `showTestButton`. `ui_translation_keys_test` 65 -> 66 keys.

## 4. Result

- The Test button can be hidden from the toolbar (default ON, so the current screen is unchanged).
- General-tab order is language → detailed logs → CPU display → GPU acceleration → Test button → matching-verification mode, as directed.

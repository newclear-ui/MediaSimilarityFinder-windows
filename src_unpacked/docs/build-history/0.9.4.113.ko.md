# MediaSimilarityFinder v0.9.4.113 — 독립 감사 B1~B3·B7 반영 (동일 내용 배지 전체 확인 + 분석 모드 round-trip + no-FFmpeg SKIP)

기준선 `0.9.4.112` → 본 빌드 `0.9.4.113`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

독립 감사(지시서 기반, 0.9.4.112 기준) 결과를 우선순위대로 반영:
- **B1 (FAIL 재현)**: "동일 내용" 배지가 크기+앞 64 KiB quick hash만 비교 — 크기와 앞부분이 같고 뒤가 다른 파일이 `identical=true`로 표시됨(감사 프로브로 재현).
- **B2 (테스트 공백)**: 설정 UI → QSettings → BackendScanConfig → IPC → 엔진 → telemetry 경로가 코드상 완결이지만 설정→실행 round-trip 검증이 없었고, `.107`의 "AB 요청/A 기록" 원인은 미확정.
- **B3 (R1 위험)**: `color_thumb_test`가 FFmpeg 유무와 무관하게 등록되어 no-FFmpeg 구성에서 실패로 끝날 수 있음(brief R1).
- **B7 (문서 정합성)**: matrix S4 행·progress 체인의 "S4 final acceptance" 표현이 .112 완료 상태와 불일치.

## 2. 기존 구조와 결함

- `sameContent()`(scan_pipeline.cpp): `size == && quickHash ==` — quick hash는 앞 64 KiB(scanner.cpp:61)라 뒤가 다른 파일을 구분하지 못함. 빠른 로드 경로(`MediaSearchEngine::loadMatches`, media_search_engine.cpp:74-76)도 같은 규칙을 중복 보유.
- 감사 재현(0.9.4.112): 크기 120,566 B·앞 64 KiB 동일·꼬리 512 B만 다른 BMP 쌍 → 백엔드 IPC `identical=true`. 대조: 완전 동일=true, 크기 다른 교차쌍=false.
- 분석 모드: 체인(콤보→저장→cfg→IPC→session→worker→엔진→telemetry)은 완결이나 설정→기록 round-trip 테스트 없음. 과거 불일치 원인 미확정 유지.
- color_thumb: CMakeLists.txt:470-472 무조건 등록, no-FFmpeg 구성에서 `frameAtColor`가 설계상 false → exit 6 실패.

## 3. 변경 구조

- **B1 — 배지 계약 강화**: `ScanPipeline::sameContent()`가 quick hash를 **후보 게이트로만** 사용하고, 통과 쌍은 **전체 내용 SHA-256 동일성**으로 확인한다(`dataset_fingerprint.h`에 `sha256FileHex` 노출 — 기존 자체 SHA-256 재사용, 스트리밍). 파일당 1회 메모(`fullHashCache_`)로 라이브/최종 패스가 공유. 512 MiB 초과 파일은 확인 생략(배지 미표시 — 거짓 음성 허용, 거짓 양성 금지). `loadMatches()`(빠른 로드)도 동일 규칙 + 로드 단위 메모로 수정.
  - **비용 실측**(사용자 ss_twit 인덱스, 읽기 전용 조회): 후보 그룹 2,444 / 후보 쌍 3,493 / 대상 파일 5,296 / **추가 읽기 약 1.5 GiB(전체 스캔 1회당, 파일당 1회)**, 512 MiB 초과 0건.
  - **검증 중 발견·수정한 실결함(데이터 레이스)**: 메모를 처음에는 무잠금 `unordered_map`으로 구현 → 최종 B 패스의 16개 샤드 스레드가 동시 삽입하며 맵이 손상되어 `analyze()`가 행(행 발생 시 `analyzeSlice`·`analyzeShards` 로그 없이 정지; 계측을 넣으면 타이밍이 바뀌어 사라지는 전형적 Heisenbug). `std::mutex`(I/O는 락 밖)로 수정. `backend_e2e_test` 3회 연속 + 전체 122/122 PASS로 확인.
- **B2 — 설정→기록 round-trip 검증**: `backend_e2e_test` Test 1이 `ui/analyzeMode=1`(Fast)로 스캔 후 **실제 수신한 텔레메트리**(`MainWindow::testLastTelemetryJson` 훅)의 `analyze.mode == "A"`를 단언, Test 4가 0(Stable)으로 `"B"`를 단언. checks 37→39. 과거 `.107` 원인은 재현 전까지 미확정 유지.
- **B3 — color_thumb R1**: 테스트가 빌드 구성(`MSF_HAS_FFMPEG`, msf_core PUBLIC 정의)에 따라 엄격/스킵을 구분한다. no-FFmpeg 빌드에서 생성·open·frameAtColor 중 어느 단계라도 불가하면 **SKIP(exit 0)** + 명시 메시지, 전체 빌드는 기존 엄격 동작. 실제 no-FFmpeg 구성(외부 빌드 디렉터리, `-DMSF_ENABLE_FFMPEG=OFF`)에서 `color_thumb=ok wic=ok ffmpeg_lane=skip` exit 0 확인.
- **B7 — 문서 정합화**: matrix S4 행을 .112 기능 acceptance 완료로 갱신, progress 체인/현재 단계의 "S4 final acceptance" 단계 표현 정리(최종 CLOSED는 product acceptance 연계).

## 4. 해결된 상황

- "동일 내용" 배지는 이제 전체 내용 해시 동일성만 표시한다 — 감사에서 재현된 오표기(뒤가 다른 파일)가 불가능해졌고, 빠른 로드 재생 경로까지 같은 계약이다. 거짓 음성(대용량·읽기 실패)은 배지 생략으로 안전하게 처리된다.
- 설정→실행→기록 불일치 클래스에 대해 상시 회귀 테스트가 생겼다(A/B 각각).
- no-FFmpeg 구성이 "제품 결함"으로 오분류되던 R1 위험이 닫혔다(지원 구성은 SKIP, 전체 구성은 엄격).

## 6. 향후 영향 및 한계

- 판정·그룹·수치·프로토콜·DB 스키마·engine/cache 불변. 배지 플래그의 산출 규칙만 강화(표시 전용).

- 관찰(미수정): `MSF_BUILD_GUI=OFF` + 테스트 ON 조합은 Widgets 테스트 타깃 때문에 configure 실패(기존 제약, 이번 범위 아님). no-FFmpeg 검증은 GUI ON 구성으로 수행.

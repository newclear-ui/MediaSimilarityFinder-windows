## 1. Why the change

- Through P2 the GUI used the Backend API in-process. P3 is the real OS
  process split plus supervisor plus IPC plus crash-injection acceptance.
- The thumbnail path (G1) cannot complete without it: GUI decode fallbacks
  must go, with the Backend authoritative.

## 2. Previous structure

- `MainWindow` + `LoopbackBackendClient` (real BackendCore, same process).
- `ScanWorker` declared/defined in `mainwindow.cpp`. `thumbDb_` opened and
  written from the GUI. fileThumb returned synchronously.

## 3. New structure

- `ScanWorker` + `LiveMatch`/`GuiFile` moved to `src/scan_worker.*`
  (msf_core, QtCore only). Shared `backend_log.*` file logger.
- New `src/backend_session.*`: owns thread/worker/monitor plus every
  signal plus `stateChanged`. Loopback shrank to a thin forwarder (same
  implementation the backend process drives — no drift possible).
- New `src/backend_ipc.*` + `backend_main --backend` serving:
  stdin commands / stdout JSONL events (flushed per message) / stderr
  diagnostics. HELLO→HELLO_ACK→READY, STATE/HEALTH (1s)/STATUS/
  MONITOR_STATUS, chunked MATCHES_BATCH and RESULTS_PAGE, THUMBNAIL
  (JPEG base64, 200KB cap), bounded 8s SHUTDOWN plus stdin-EOF self-exit.
- New `gui/backend_supervisor.*` (a `BackendClient`): QProcess spawn
  (nonce/argv, no shell assembly) + Job Object KILL_ON_JOB_CLOSE +
  async terminate→kill escalation + bounded restart (3 attempts,
  2s/5s/10s, success only by HELLO/READY) + health/READY watchdogs.
  Old nonces and stale events dropped, RESULTS_PAGEs assembled, JPEG
  thumbnails decoded.
- `MainWindow`: async fileThumb (miss → request + placeholder; arrivals
  repaint in onThumbReady with stale-size drop). `thumbDb_` persistence,
  shell/QImageReader/WIC/VideoDecoder branches, and the VideoDecoder
  duration probe removed (Backend-owned now). Production MainWindow takes
  an injected supervisor; tests and smoke keep the loopback default.
- `MainWindow` constructor takes `BackendClient*` (null = loopback).
  `backendConnection` guard (Start disabled + in-scan failure path).
- `MSF_TEST_BACKEND_FAIL_FAST/SILENT` seams (deterministic E2E fault
  injection).

## 4. Resolved state

- GUI PID != Backend PID (measured in E2E). Forced kill: GUI survives,
  bounded restart, new PID, READY, same-DB rescan. Repeated failures go
  FAILED and stay silent.
- Thumbnails are Backend-authoritative with a GUI memory cache. No GUI
  decoding left.

# MediaSimilarityFinder v0.9.4.69 — P3 실 spawn + Supervisor + IPC

기준선 `0.9.4.68` → 본 빌드 `0.9.4.69`.
CPU CTest **114 → 116**, GPU CTest **115 → 117** (backend_ipc + backend_e2e 신규).
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 검색 의미·동작 변경 없음.

## 1. 변경 필요성

- P2까지 GUI는 Backend API를 통하지만 동일 프로세스였다. P3는 실제 OS
  프로세스 분리 + supervisor + IPC + crash-injection acceptance다.
- P0 인벤토리와 보완 지시(G1–G13)가 계약이며, 특히 썸네일 경로(G1)가
  P3 없이는 완성되지 않는다 (GUI decode fallback 제거).

## 2. 기존 구조

- `MainWindow` + `LoopbackBackendClient` (동일 프로세스 실제 BackendCore).
- `ScanWorker`가 `mainwindow.cpp`에 선언·정의. `thumbDb_`가 GUI에서
  index DB를 직접 open/write. fileThumb이 동기 반환.

## 3. 변경 구조

- `ScanWorker`+`LiveMatch`/`GuiFile`를 `src/scan_worker.*`로 이동
  (msf_core, QtCore only). `backend_log.*` 공용 파일 로그.
- 신규 `src/backend_session.*`: 스레드·워커·모니터 소유 + 전 시그널 +
  `stateChanged`. Loopback은 thin forwarder로 축소 (동일 구현, drift 불가).
- 신규 `src/backend_ipc.*` + `backend_main --backend` serving:
  stdin 명령 / stdout JSONL 이벤트(매 메시지 flush) / stderr 진단.
  HELLO→HELLO_ACK→READY, STATE/HEALTH(1s)/STATUS/MONITOR_STATUS,
  MATCHES_BATCH·RESULTS_PAGE chunking, THUMBNAIL(JPEG base64, 200KB cap),
  SHUTDOWN bounded 8s + stdin EOF 자진 종료.
- 신규 `gui/backend_supervisor.*` (`BackendClient` 구현):
  QProcess spawn(nonce/argv, shell 조립 없음) + Job Object
  KILL_ON_JOB_CLOSE + 비동기 terminate→kill 에스컬레이션 + bounded
  restart(3회, 2s/5s/10s, HELLO/READY로만 성공 판정) + health/READY watchdog.
  오래된 nonce/stale event 폐기, RESULTS_PAGE 조립, THUMBNAIL 디코드.
- `MainWindow`: fileThumb 비동기화 (miss→요청+placeholder, 도착 시
  onThumbReady가 repaint+layout; stale size는 그리지 않음). `thumbDb_`
  persistence·shell/QImageReader/WIC/VideoDecoder 분기·VideoDecoder duration
  probe 삭제 (Backend 소유로). `testThumbCatchUp`은 요청 펌프 역할 유지.
  생산 MainWindow는 supervisor 주입, 테스트·smoke는 loopback 기본.
- `MainWindow` 생성자에 `BackendClient*` 주입 (null이면 loopback).
  `backendConnection` 가드 (Start 비활성화 + 스캔 중단은 failed 경로).
- `MSF_TEST_BACKEND_FAIL_FAST/SILENT` seam 2종 (E2E 결정적 실패 주입).

## 4. 해결된 상황

- GUI PID ≠ Backend PID (E2E 실측). 강제 종료 시 GUI 생존 + bounded
  restart + 새 PID + READY + 동일 DB rescan. 반복 실패는 FAILED 후 정지.
- 썸네일은 Backend authoritative + GUI memory cache. GUI decode 불필요.

## 5. 검증

### 신규 (CPU·GPU PASS)

- `backend_ipc_test` 7 checks: round-trip(UTF-8 경로) + reject 4종.
- `backend_e2e_test` (Windows, 실프로세스): Test 1 정상 스캔(PID 분리),
  Test 2 kill→실패 보고→restart(새 PID)→rescan(DB reopen),
  Test 3a instant-exit 3회→FAILED+무한루프 없음,
  Test 3b SILENT→READY-timeout 3회→FAILED. 총 16초.

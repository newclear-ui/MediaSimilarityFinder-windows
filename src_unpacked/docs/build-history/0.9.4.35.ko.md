## 1. 제품 결함

v0.9.4.34 까지 제품은 EXIF 회전을 **한 번도 적용하지 않았다.**

```text
제품 사용 경로  /app1/ifd/exif/{ushort=274}  -> 8/8 BADPROPERTYKEY (0x88982F40)
동작하는 경로    /app1/ifd/{ushort=274}        -> 8/8 S_OK
```

표준 dataset 의 `orient_applied_files = 0` 은 coverage 부족이 아니라 이 결함의
결과였다. 수정 후에도 0 인데, 그것은 **dataset 에 실제 회전 이미지가 없기
때문**이라는 별도의 사실이다(§6).

## 2. production 사용처 조사

`src/image_decoder.cpp` 에 정확히 **3곳**, 모두 동일 리터럴·동일 로직이었다.

| 지점 | 함수 | 역할 |
|---|---|---|
| (수정 전 :194) | `decodeWicFile` | fingerprint fixed |
| (수정 전 :267) | `decodeWicFileAspect` | fingerprint aspect |
| (수정 전 :321) | `decodeWicFileAspectColor` | 표시(color) 경로 |

세 번째(표시) 경로도 함께 고쳤다. 회전 사진을 지문과 다르게 표시하면 화면과
매칭 결과가 어긋난다. 저장소 전체 검색으로 `GetMetadataByName` production
호출은 이 3곳뿐임을 확인했다.

## 3. 수정 내용 (최소)

행 단위 수정 3번이 아니라 **공유 헬퍼 1개**로 통합했다.

```cpp
inline WICBitmapTransformOptions exifOrientationToTransform(IWICMetadataQueryReader* meta) {
  static const wchar_t* const kPaths[] = {
      L"/app1/ifd/{ushort=274}",  // JPEG
      L"/ifd/{ushort=274}",       // TIFF
  };
  ...
}
```

- 컨테이너 분기를 새로 만들지 않았다. 두 경로를 순서대로 시도하고 **값이 나온
  첫 번째에서 멈춘다.** 컨테이너를 몰라도 JPEG/TIFF 가 모두 처리된다.
- 해상도가 나온 즉시 `return` 하므로 JPEG 는 두 번째 쿼리를 지불하지 않는다.
- Orientation 1 은 항등 변환이므로 `orientApplied` 를 증가시키지 않는다
  (기존 의미 유지).
- **XMP fallback · 새 metadata framework · 새 orientation architecture 는
  추가하지 않았다.** pre-register §11 준수.
- 세 call site 는 모두 `xform=exifOrientationToTransform(meta.Get());` 한 줄.


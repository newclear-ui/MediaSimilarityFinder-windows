# MediaSimilarityFinder v0.9.4.75 — Test Mode 재도입, 스크롤/썸네일 후속 수정

기준선 `0.9.4.74` → 본 빌드 `0.9.4.75`.
CPU CTest **117/117**, GPU CTest **118/118**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 검색 판정 의미 변경 없음.

## 1. 변경 필요성

- 기존 GUI Benchmark는 S4 reset으로 제거되었고, Test Mode는 UI 표면·scratch
  수명주기·telemetry 구분·acceptance가 필요하다는 이유로 `0.9.4.63`에서
  DEFERRED였다. 사용자는 설정 옆 `Test` 버튼과 “인덱스가 있어도 전체 처리를
  다시 수행하되 저장된 인덱스를 건드리지 않는” 동작을 명시적으로 요청했다.
- 별도 benchmark runner를 부활하지 않고, 기존 검색 경로 그대로 실행하면서
  저장 위치만 격리하는 방식이 필요했다.
- 큰 아이콘 + 유사도 내림차순에서 스크롤바 드래그/휠 뒤 뒤늦게 목록이 위로
  돌아가는 보고가 남았다. 코드상 확정된 간극은 입력 커버리지, 썸네일 요청
  중복, 도착 burst당 layout 횟수, 큰 아이콘 앵커 측정이었다.
- GUI 1% + Backend 6~70% 진동 보고는 별도 사용자 dataset 로그 없이 코드로만
  좁혔다. 스케줄러 결함의 증거는 찾지 못했으므로 utilization만을 목표로
  worker를 건드리지 않았다.

## 2. 기존 구조

- 스캔 설정은 `MainWindow::beginScan()`에서 `BackendScanConfig`로 모아
  loopback 또는 Supervisor JSON `START_SCAN`으로 Backend에 전달됐다.
- `BackendSession::startScan()`은 받은 `appDir`을 그대로 `ScanWorker`에
  넘겼고, 엔진·비디오 캐시·프로파일·썸네일은 모두 그 `appDir` 아래에 열렸다.
- 스크롤 gate는 `sliderPressed/sliderReleased`와 뷰/뷰포트 wheel·키만 봤다.
  트랙 클릭·거터 페이지·화살표, 스크롤바 자체에 포커스된 wheel/키는 gate에
  들어오지 않았다.
- 썸네일 miss는 도착 전 같은 tick에서 반복 요청될 수 있었고, 도착마다
  `doItemsLayout()`을 직접 호출했다.
- `fillPair()`는 grid 앵커를 `(2,2)`로 잡고 `scrollToItem(PositionAtTop)`으로
  복원했다. 큰 아이콘 wrap에서는 코너 프로브가 빗나갈 수 있고, 부분 셀
  오프셋도 보존되지 않았다.

## 3. 변경 구조

- **Test Mode 토글**
  - Toolbar Settings 바로 왼쪽에 checkable `Test` 버튼 추가.
  - 상태는 `ui/testMode`에 저장되고 재시작 후 복원되며, 체크 시 하이라이트된다.
  - 스캔 중에는 비활성화되어 진행 중 실행에 영향을 주는 오해를 막는다.
  - 다음 스캔 설정에만 적용되며, 저장된 `BackendScanConfig`를 그대로 쓰므로
    Backend 재시작 자동 재개도 같은 모드를 유지한다.
- **격리된 scratch 실행**
  - `BackendScanConfig.testMode`가 Supervisor `START_SCAN` JSON으로 전달되고,
    `BackendSession`이 같은 worker/engine 경로를 사용하되 매 실행마다 고유한
    `<appDir>/TestMode/<folderId>-<timestamp>-<nonce>`를 `appDir` 대신 사용한다.
  - 인덱스 DB, 비디오 캐시, 프로파일, 썸네일 DB가 모두 scratch 아래에
    생기므로 기존 `<appDir>/Index`는 읽기조차 쓰기 목적으로 열리지 않는다.
  - 구 sender와 호환되도록 JSON 필드가 없으면 `false`가 기본값이다.
- **스크롤 gate 확장**
  - `sliderMoved`와 `actionTriggered`를 연결해 트랙 클릭·거터·화살표 이동도
    cooldown을 건다. 프로그램matic `setValue`는 이 신호들을 내지 않는다.
  - 스크롤바 자체에도 event filter를 걸어 스크롤바 위 wheel과 포커스된 키를
    사용자 탐색으로 취급한다.
- **썸네일 burst 정리**
  - 같은 경로·크기의 in-flight 요청은 중복 발행하지 않는다.
  - 도착 burst는 0-delay layout 1회로 합친다. 스크롤 gate가 살아 있는 동안은
    layout을 뒤로 미루고 cooldown 뒤 재시도하므로, 드래그 중 Batched geometry가
    움직이지 않는다. 0.9.4.66의 layout 보장은 유지된다.
- **앵커 복원 강화**
  - grid 앵커는 viewport 중앙으로 측정하고, 재구축 전후 content offset을
    그대로 복원한다.
  - 복원 전에 Batched layout을 확정하고, 없으면 기존 픽셀 fallback을 쓴다.
- **CPU**
  - 스케줄러·worker 수·decode 병렬도·I/O 정책을 바꾸지 않았다.
  - 정책과 무관한 decode pool 폭은 후순위 throughput 백로그로 남긴다.

## 4. 해결된 상황

- Test ON 다음 스캔은 기존 인덱스가 있어도 scratch에서 전체 처리를 수행하고,
  기존 `index.sqlite`·`video_cache.sqlite`·`metadata.json` 바이트가 그대로 남는다.
- Test OFF 다음 스캔은 기존 인덱스를 정상 업데이트한다.
- 스크롤바 드래그·트랙 클릭·스크롤바 위 wheel이 rebuild/layout을 미루는 범위가
  넓어졌다.
- 썸네일 도착 burst가 드래그 중 스크롤을 흔들지 않고, 큰 아이콘 앵커는 부분
  셀까지 같은 위치로 돌아온다.
- 낮은/진동 CPU만으로는 스케줄러 결함을 단정하지 않으며, 이번 빌드는 그 추정으로
  throughput을 해치지 않았다.


`view_mode_probe`는 coalesced layout 도입 직후 1회 실패했다. 도착 layout을
다음 tick으로만 미뤄 테스트가 타이머를 멈춘 경로에서 0.9.4.66 보장이 깨진
것이다. 이를 0-delay 1회 + 스크롤 중 재연기로 고쳐 PASS를 회복했다.
`ui_scroll_regression_test`도 전체 suite 타이밍에서 드래그 위치 단언이 1회
흔들려, held 위치를 먼저 확정하고 synthetic press를 거는 형태로 안정화했다.
두 실패는 수정 과정에서 확인된 회귀이며 최종 전수 PASS에 포함된다.

## 6. 향후 영향

- Test Mode scratch는 실행마다 새로 생기고 자동 삭제하지 않는다. 검사·비교용으로
  남기 위한 선택이며, 공간 회전 정책은 별도 후속 결정이 필요하다.
- Test 결과 화면에 모드 표시를 덧붙이는 것은 아직 하지 않았다. 다음 스캔 설정과
  하이라이트가 모드를 구분한다.
- 사용자 dataset의 phase 로그와 실제 Windows UI acceptance가 남았다. 특히 큰
  아이콘·유사도 내림차순·대규모 그룹에서의 체감이 최종 확인 대상이다.
- 낮은 GPU duty와 CPU 진동 자체는 목표가 아니다. end-to-end throughput과
  queue starvation/backpressure 증거가 있을 때만 후속 성능 작업을 연다.

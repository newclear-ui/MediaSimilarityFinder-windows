## 1. Why it was needed

Applying the independent audit (based on the instruction document, at 0.9.4.112) in priority order:
- **B1 (FAIL reproduced)**: the "identical content" badge compared size + the 64 KiB quick hash only — a file with the same size and same head but a different tail was reported `identical=true` (reproduced with an audit probe).
- **B2 (test gap)**: the settings UI -> QSettings -> BackendScanConfig -> IPC -> engine -> telemetry chain was complete in code, but had no settings-to-execution round-trip test, and the `.107` "requested AB / recorded A" cause stayed unconfirmed.
- **B3 (R1 risk)**: `color_thumb_test` was registered regardless of FFmpeg and could end as a failure in a no-FFmpeg configuration (brief R1).
- **B7 (doc consistency)**: the matrix S4 row and the progress chain still read "S4 final acceptance", inconsistent with the .112 completion.

## 2. Previous structure and defects

- `sameContent()` (scan_pipeline.cpp): `size == && quickHash ==` — the quick hash covers the first 64 KiB (scanner.cpp:61), so differing tails were indistinguishable. The quick-load path (`MediaSearchEngine::loadMatches`, media_search_engine.cpp:74-76) duplicated the same rule.
- Audit reproduction (0.9.4.112): two BMPs (120,566 B) with an identical first 64 KiB and a 512 B tail differing -> backend IPC `identical=true`. Controls: truly identical = true, size-mismatched cross pairs = false.
- Analyze mode: the chain (combo -> save -> cfg -> IPC -> session -> worker -> engine -> telemetry) was complete, but no round-trip test existed. The past mismatch cause remains unconfirmed.
- color_thumb: unconditionally registered (CMakeLists.txt:470-472); in a no-FFmpeg build `frameAtColor` returns false by design -> exit 6 failure.

## 3. New structure

- **B1 — badge contract hardened**: `ScanPipeline::sameContent()` uses the quick hash as a **candidate gate only**; passing pairs are confirmed by **full-content SHA-256 equality** (`sha256FileHex` exposed in `dataset_fingerprint.h`, reusing the existing streaming SHA-256). A per-file memo (`fullHashCache_`) is shared by the live and final passes. Files above 512 MiB stay unconfirmed (badge omitted — false negatives allowed, false positives not). `loadMatches()` (quick load) uses the same rule with a per-load memo.
  - **Measured cost** (user ss_twit index, read-only query): 2,444 candidate groups / 3,493 candidate pairs / 5,296 target files / **~1.5 GiB extra reads per full scan (one read per file)**, 0 files above the cap.
  - **Real defect found and fixed during verification (data race)**: the memo was first implemented as an unsynchronized `unordered_map` — 16 shard threads of the final B pass inserted concurrently, corrupting the map and hanging `analyze()` (no `analyzeSlice`/`analyzeShards` lines; instrumentation changed the timing and hid it — a classic Heisenbug). Fixed with `std::mutex` (I/O outside the lock). Confirmed by 3 consecutive `backend_e2e_test` runs + the full 122/122 suite.
- **B2 — settings-to-record round-trip test**: `backend_e2e_test` Test 1 scans with `ui/analyzeMode=1` (Fast) and asserts the **received telemetry** (`MainWindow::testLastTelemetryJson` hook) has `analyze.mode == "A"`; Test 4 asserts `"B"` with 0 (Stable). Checks 37 -> 39. The `.107` cause stays unconfirmed until reproduced.
- **B3 — color_thumb R1**: the test now distinguishes strict vs skip by build config (`MSF_HAS_FFMPEG`, a PUBLIC msf_core definition). In a no-FFmpeg build, if generation/open/frameAtColor is unavailable the lane is **SKIPped (exit 0)** with an explicit message; full builds keep the strict behavior. Verified in an actual no-FFmpeg configure (external build dir, `-DMSF_ENABLE_FFMPEG=OFF`): `color_thumb=ok wic=ok ffmpeg_lane=skip`, exit 0.
- **B7 — documentation reconciliation**: the matrix S4 row updated to the .112 functional acceptance; the progress chain / current-phase wording drops the stale "S4 final acceptance" step (final CLOSED stays tied to product acceptance).

## 4. What is fixed

- The "identical content" badge now claims full-content hash equality only — the reproduced mislabel (differing tails) is impossible, and the quick-load replay path uses the same contract. False negatives (oversized/unreadable) degrade to badge omission, safely.
- The settings-to-execution mismatch class now has a standing regression test (A and B each).
- The R1 risk (no-FFmpeg configuration misclassified as a product defect) is closed (supported config = SKIP, full config = strict).

# MediaSimilarityFinder v0.9.2.40 — CUDA 실기 검증 (RTX 3080 Ti)

## 변경 필요성
0.9.2.34부터 예고된 CUDA 빌드 검증을 처음 실기했다. 한 번도 켜져본 적 없는 CUDA 백엔드(`cuda_backend.cu`, 3개 아키텍처 75;86;89)와 `build_windows_cuda.ps1` 스크립트를 RTX 3080 Ti + CUDA Toolkit 13.4 + VS18 환경에서 검증해야 했다. 결과 3건의 플랫폼·테스트 문제를 발견했다.

## 기존 구조
- `build_windows_cuda.ps1`: 툴체인 파일 미지정(수동 `-D`만 전달), nvcc 존재 확인만 하고 `CUDA_PATH_V*` 미처리
- `check_language(CUDA)` 실패 시 조용히 CPU 폴백. CUDA 툴킷 13.4의 VS MSBuild 통합(`CUDA 13.4.targets`)은 `CudaToolkitDir`를 `CUDA_PATH_V13_4`에서 읽는데, 툴킷 설치 전에 뜬 셸은 이 변수가 없어 ID 컴파일이 실패했다
- `cuda_backend_test`: CPU/GPU 완전 일치 요구. 합성 패턴 5번에서 불일치 발생

## 변경 구조
- 스크립트: `CMAKE_TOOLCHAIN_FILE` 추가(CPU 스크립트와 동일 기준 → manifest 모드 + applocal DLL 배포. 기존 15건의 `0xC0000135` 해결). 머신 레벨 `CUDA_PATH*`를 프로세스 환경으로 가져오는 fallback 추가. `CoUninitialize`식 순서 문제가 아니라 환경 문제였음을 주석으로 명시
- 테스트: 완전 일치 요구를 데이터 조건별 주장으로 변경. 56개 랜덤 이미지는 완전 일치 요구, 8개 합성 패턴은 `ham <= 8` 허용. 이유는 코드 주석에 기록
- 버전 표기 통일 → 0.9.2.40. CUDA 알고리즘·커널은 불변

## 해결된 상황
- `CMAKE_CUDA_COMPILER=nvcc 13.4`, `msf_cuda.lib` + `msf_cuda_backend_test.exe` 빌드 PASS
- **CTest 38/38 PASS** (신규 `cuda_backend_test` 포함, 실 GPU 실행)
- GUI는 CPU 빌드와 동일 소스. `--version` 0.9.2.40

## 검증
- 원인 입증 프로브: `probe_tie2`(5번 이미지의 AC 계수 30개가 median 1e-12 이내 → 노이즈 타이), `probe_gpuh`(64개 중 63개 완전일치, 불일치 1건 ham=8)
- 전체 파이프라인 `build_windows_cuda.ps1` → configure(CUDA 감지) → Release 빌드 → CTest 38/38
- 자연 이미지(random 56) 완전 일치는 비트 정확성의 증거. 합성 패턴의 8비트 차이는 반올림 노이즈 타이 범위 내

## 향후 영향
- CUDA 알고리즘 변경 없이 검증만으로 1.0.0 목표의 GPU 라인 조건 충족. 커널 fused-order 재작성 등 비트 완전일치 강화는 인덱스 호환성 분석과 함께 별도 버전에서 결정할 것 (현재 제품은 Hamming 허용 설계라 불필요)
- CI `windows-cuda.yml`은 여전히 VS17 지정 — VS18 + CUDA_PATH 전파 조건으로 갱신 필요
- 툴킷 설치 후 뜬 셸에서는 스크립트의 환경 fallback 없이도 동작. 단, 첫 configure는 반드시 툴체인 포함 fresh configure여야 함 (기존 캐시에 사후 추가 불가)

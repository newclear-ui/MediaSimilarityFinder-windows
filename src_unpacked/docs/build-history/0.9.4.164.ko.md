# MediaSimilarityFinder v0.9.4.164 — MSSIM 타이밍 귀속 정밀화 + 디코드 오류 집계 (P2)

기준선 `0.9.4.163` → 본 빌드 `0.9.4.164`.
CPU CTest **134/134**, GPU CTest **134/135 + 동일 타이밍 플레이크 2회 (아래 검증 참조)**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` 전부 불변.

## 1. 변경 필요성

- 외부 리뷰 P2 지적 2건: (a) `gpuMs`가 `map.size()>=8` 검사 이전부터 측정되어 작은 배치가 GPU를 쓰지 않았는데도 시간이 반영된다. (b) 디코더가 조용히 건너뛰는 오류(send_packet 거부·비EOF 읽기 오류)에 계측이 없다.

## 2. 기존 구조

- `gpuMs` 타이머가 게이트 검사·출력 버퍼 할당을 감쌌다. fallback은 성공/실패 구분 없이 `gpuFallback` 하나만 섰다.
- `framesAt()`은 실패한 패킷을 세지 않았다. EAGAIN 드롭(재시도 없이 패킷 폐기)도 구분 없이 버려졌다.

## 3. 변경 구조

- `gpuMs`는 실제 `ssimBatch` 호출 구간만 측정한다. 미달 배치(`map.size()<8`)와 실패 배치는 `smallBatchPairs`/`failedBatchPairs`로 분리 집계한다. `gpuActivity` 플래그도 실제 호출 구간에만 선다(측정 정확도 수정).
- `VideoSimilarityStats.cpuMs`는 CPU fallback `frame_ssim` 쌍 시간(0.9.4.162에서 추가, 본 빌드에서 단언으로 고정).
- `VideoDecoder::framesAt/framesAt96Plus32`에 `errorOut` 추가: 거부된 입력 패킷(EAGAIN 포함, 명시적 주석) + 비EOF demuxer 읽기 오류를 센다. EAGAIN on receive는 정상 흐름 제어로 세지 않는다.
- `VideoBuildStats.decodeErrors` → `TelemetryRecorder.addVideoDecodeErrors` → `videos.decodeErrors/State` (additive, `start()` 리셋, 캐시 히트는 측정된 0).
- `AnalyzeTelemetry` merge·`ScanStats` 복사·JSON에 `videoMatchSmallBatch`/`videoMatchBatchFailed` 편입.
- 회귀: `video_sim_perf_test`에 2x2 핸드메이드 쌍 단언(submitted=4·completed=0·small=4·failed=0·cpuMs>0·gpuMs==0, ssimBatch 미호출이라 GPU 없이도 결정적). `analyze_telemetry_test`에 merge 합산 + measured/null 계약 단언. `video_complete_test` baseline에 `decodeErrors==0` 단언.
- adhoc 경로(loadTemporal)의 `stats` 미부착은 유지하고 문서화한다(생산 매칭 경로는 `scan_pipeline` temporal flush).

## 4. 해결된 상황

- 이후 실스캔 로그에서 매칭 MSSIM 비용이 `gpuMs + cpuMs`로, 전환율이 `completed/submitted/small/batchFailed`로 읽힌다. 디코드 오류는 파일별 0이 아닌 값으로 드러난다.

- 플레이크 판정 근거 (제품 회귀 아님):
  - .164 제품 변경 중 시나리오 A 실행 경로는 카운터 추가뿐이며(수 ns), MSSIM/temporal 변경은 후보 쌍이 없어 미실행이다. .162 동일 경로 135/135 통과.
  - 동일 바이너리 단독 실행은 매번 통과(CWD 변경 포함). GPU 벤치마크와 동시 실행 시 1회 실패·1회 통과 — 부하 의존적 비결정성.
  - 메커니즘: 0.9.4.158의 저장 직전 cancel 재확인(P0 수정)이 시나리오 A의 경합창을 좁혔다. 정지 시점에 비행 중인 빌드는 저장 대신 실패로 집계되므로(의도된 P0 동작) exact-count 단언이 부하에 민감하다. .161·.163에서도 동일 테스트 플레이크 기록.
  - 후속 과제: wall-clock 경합이 아닌 결정적 취소 주입(예: N개 완료 후 취소)으로 테스트를 고정하는 작업. 제품 동작 수정이 아니다.

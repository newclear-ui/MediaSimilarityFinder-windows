# MediaSimilarityFinder v0.9.4.140 — Keep preview thumbnails across a scan (refresh only when files changed)

Baseline `0.9.4.139` → this build `0.9.4.140`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged (display only).

## 1. Why

- Field check (0.9.4.139 S-1): after a Load showed thumbnails, starting a Search made **every preview disappear and stay blank until the scan finished**.
- This is not a functional defect but a UX one: the backend is busy scanning, so re-issued thumbnail requests queue behind the scan.

## 2. Previous structure

- `beginScan()` cleared the whole in-memory presentation thumbnail cache (`thumbCache_.clear()`).
- Rows rebuilt after the clear started as placeholders and re-requested art for visible rows. During a scan those requests were not served, so the grid stayed blank for the whole walk.
- The backend thumbnail store looks up its disk cache by `(path, mtime, size)`, so a changed file yields fresh art on a new request. But a GUI cache hit issued no request, so stale art could persist.

## 3. New structure

- **Scan start**: `thumbCache_.clear()` removed. Existing art is reused immediately even when rows are rebuilt; `scanLog("thumbCache kept=N")` records the state.
- **Scan end**: only when the finished/cancelled message reports `analyzed > 0` (files were actually re-read) the cache is invalidated and `thumbCatchUpVisible()` re-asks **visible rows, the file grid and the selected preview** while the backend is idle.
  - Rows keep painting their previous icons until fresh arrivals replace them, so nothing blanks out; changed files get new art.
  - `analyzed == 0` (all unchanged) keeps the cache untouched - no content changed, so no re-request is needed.
- `scanLog("thumbCache invalidated analyzed>0")` records the invalidation.

## 4. Result

- Rescanning an already-indexed folder no longer blanks the previews.
- If files really changed, the visible parts refresh right after the scan (no blank during the walk).

## 5. Verification

```text
CPU Release CTest 100% tests passed out of 125
GPU CTest 100% tests passed out of 126
GUI/Backend --version 0.9.4.140
```

- `msf_scan.log` now carries `thumbCache kept=N` (scan start) and `thumbCache invalidated analyzed>0` (when content changed).
- Field visual check: Load -> Search keeps the thumbnails; a rescan including a modified file refreshes them after completion (user check).

## 6. Impact and limits

- Display only (verdicts, storage, protocol, engine/DB/schema/cache unchanged).
- The GUI memory cache cap (3000 entries) and the per-size key (path|WxH) are unchanged.
- A file modified during a scan may still show its previous art until the scan finishes (refreshed when analyzed>0). No live replacement mid-scan.
- Load/re-verify still rebuild their view and clear the cache (their result set changes by design).

# MediaSimilarityFinder v0.9.4.57 — fingerprint scope 인식

기준선 `0.9.4.56` → 본 빌드 `0.9.4.57`.
CPU CTest **105/105**, GPU CTest **106/106**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 테스트 수 불변.

## 1. 변경 필요성

이미지 전용 스캔이어도 fingerprint가 비디오까지 전부 해시했다.
비디오 위주 dataset에서는 walk 시작 전에 수백 GB를 읽어, 인덱싱에 영원히
도달하지 못했다. 취소하면 walk 미시작이 정상이므로, "인덱스가 안 됨"이
무한 반복됐다.

## 2. 기존 구조

`computeDatasetFingerprint(root)`는 scope와 무관하게 모든 regular file을
해시했다. `scanImages`/`scanVideos`는 walk/분석에서만 적용됐다.

## 3. 변경 구조

`computeDatasetFingerprint(root, cancel, progress, scanImages=true,
scanVideos=true)`로 scope를 전달한다. 기본값이라 기존 호출 20여 곳은 그대로
동작한다.

- 무제한 scope: 기존 all-files 동작과 바이트 단위 동일 (비미디어 포함)
- 제한 scope: 단일 분류기(`Scanner::isMediaPath`/`isVideoPath`)로 in-scope
  미디어만 해시. 중복 규칙 없음
- 제한 scope의 fingerprint 값은 달라진다. scope가 이미 S6 별도 grouping
  축이므로 정당하고, 유효한 real-dataset fingerprint가 아직 존재하지 않아
  (취소는 null 기록) 깨지는 비교가 없다
- `scan()`에서 `control->scanImages/scanVideos` 전달 (null control은 true)

## 4. 해결된 상황

- 이미지 전용 스캔은 이미지만 해시하고 walk로 진행한다
- 비디오 위주 dataset에서도 인덱싱에 도달 가능해졌다
- 전체 스캔 동작·값은 불변

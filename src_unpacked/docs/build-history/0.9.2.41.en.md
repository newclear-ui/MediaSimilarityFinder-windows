# MediaSimilarityFinder v0.9.2.41 — Non-ASCII (Korean) Filename Crash Fix

## Need for change
Sample testing with the user's real media folder (`G:\Downloads\ss_twit`, 272,183 files) killed whole scans with `0xC0000409` on 4 Korean-named videos. 15 ASCII videos scanned fine, narrowing it to a filename-encoding boundary. Probes pinned the crash to a `std::filesystem::exists()` call inside `VideoFingerprintEngine::build()`.

## Previous structure
Narrow UTF-8 strings were passed directly, e.g. `std::filesystem::exists(p, ec)`. On Windows, narrow-to-path conversion uses the process ANSI code page (CP949), so names outside it (Korean, etc.) make **the conversion itself throw** — `error_code` only covers the query, not the conversion. The exception escaping the scan worker's `std::async` task terminated the whole process. The same pattern existed in 2 `video_fingerprint` spots, 4 `monitor` spots (`isStable`, `enqueuePath`, post-analysis stat, `fileKey`), the `image_decoder` PGM fallback, `index_manager` tmp paths, `media_search_engine` DB/exclusion paths, and the `scanner` timestamp.

## New structure
- UTF-8→`fs::path` conversion unified on `path_from_utf8()` (`video_fingerprint`, `monitor`, `image_decoder`, `index_manager`, `media_search_engine`); reverse direction uses `path_to_utf8()` (SQLite takes UTF-8 directly)
- `fileKey()` signature changed from `const fs::path&` to `const std::string&` (UTF-8) with internal conversion. Call sites cleaned up
- `Scanner::stamp()` gained an `error_code` (race with mid-scan deletions can no longer throw)
- `index_manager` tmp paths stay `fs::path` operations (dropped `.string()+".tmp"`)
- New `unicode_path_test` → 39 tests total. Verifies Korean BMP decode, PGM fallback, no-throw video build, scanner discovery, and SQLite on Korean paths. Filenames use UTF-8 byte escapes so the test is source-encoding independent

## Resolved situation
- All 19 Korean videos analyze (found one 100% duplicate pair + one 90.6% similar pair). 280-file mixed sample: 275 scanned, 274 analyzed, 19 groups, 255 GPU images, incremental rescan clean
- 5 unscanned files are non-media extensions (`.jpe`/`.part`/3 extensionless) — correctly skipped

## Validation
- Core Release build: PASS, **CTest 39/39 PASS** (including new `unicode_path_test`)
- Measured on user-folder samples with ASCII/Korean contrast probes. Non-Windows path behavior unchanged (`path_from_utf8` passes through)

## Future impact
- Rule: every narrow path boundary on Windows goes through `path_from_utf8()`. New file-I/O code ships with a non-ASCII filename test case
- GUI is `QString`-based and unaffected. Non-ASCII test fixture names stay byte-escaped

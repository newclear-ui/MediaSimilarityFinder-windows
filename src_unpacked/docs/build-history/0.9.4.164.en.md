# MediaSimilarityFinder v0.9.4.164 — MSSIM Timing Attribution + Decode Error Accounting (P2)

Baseline `0.9.4.163` → this build `0.9.4.164`.
CPU CTest **134/134**, GPU CTest **134/135 + same timing flake twice (see verification)**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` all unchanged.

## 1. Why the change was needed

- Two external-review P2 items: (a) `gpuMs` was timed from before the `map.size()>=8` check, so sub-threshold batches added packing/branch time without ever touching the GPU. (b) Silently skipped decoder errors (rejected send_packet, non-EOF read errors) had no accounting.

## 2. Previous structure

- The `gpuMs` timer wrapped the gate check and output-buffer allocation. Fallback set a single `gpuFallback` flag regardless of success or failure.
- `framesAt()` counted no rejected packets. EAGAIN drops (packet discarded without draining) were indistinguishable from clean runs.

## 3. New structure

- `gpuMs` wraps only the actual `ssimBatch` call. Sub-threshold and failed batches are attributed separately as `smallBatchPairs`/`failedBatchPairs`. The `gpuActivity` flag now spans only real calls (measurement correction).
- `VideoSimilarityStats.cpuMs` times CPU-fallback `frame_ssim` pairs (added in 0.9.4.162, pinned by assertions here).
- `VideoDecoder::framesAt/framesAt96Plus32` gain `errorOut`: rejected input packets (incl. EAGAIN, explicitly commented) + non-EOF demuxer read errors. EAGAIN on receive stays uncounted (normal flow control).
- `VideoBuildStats.decodeErrors` → `TelemetryRecorder.addVideoDecodeErrors` → `videos.decodeErrors/State` (additive, reset in `start()`, measured 0 on cache hit).
- `AnalyzeTelemetry` merge, `ScanStats` copy, and JSON gain `videoMatchSmallBatch`/`videoMatchBatchFailed`.
- Regression pins: `video_sim_perf_test` asserts a hand-built 2x2 pair (submitted=4, completed=0, small=4, failed=0, cpuMs>0, gpuMs==0; ssimBatch never reached, so deterministic without CUDA). `analyze_telemetry_test` asserts merge folds + measured/null contracts. `video_complete_test` baseline asserts `decodeErrors==0`.
- The adhoc path (loadTemporal) stays without `stats`, documented: the production match path is the `scan_pipeline` temporal flush.

## 4. Resolved state

- Future field-scan logs read match-stage MSSIM cost as `gpuMs + cpuMs` and the transition as `completed/submitted/small/batchFailed`. Decode errors surface as nonzero per-file values instead of silence.

## 5. Verification

```text
GPU CTest 134/135 + scan_cancel_video_test timing flake (same 3 checks failed in the first run and the identical-binary full rerun; standalone passes every time)
video_sim_perf_test small-batch assertions green (both trees)
analyze_telemetry_test 92+ checks green (incl. merge + measured/null)
GUI/Backend --version 0.9.4.164 (all 4 binaries)
```

- Flake verdict (not a product regression):
  - The .164 product changes on scenario A's path are counter-only (nanoseconds); the MSSIM/temporal changes never execute (no candidate pairs). Same paths were 135/135 green in 0.9.4.162.
  - Identical binary passes standalone every time (incl. a different CWD); fails intermittently only in-suite / under concurrent GPU load — load-dependent nondeterminism.
  - Mechanism: 0.9.4.158's pre-store cancel recheck (the P0 fix) narrowed scenario A's race window. Builds in flight at the stop now count as failed instead of storing (intended P0 behavior), so the exact-count assertions are load-sensitive. Same test flaked in 0.9.4.161 and 0.9.4.163.
  - Follow-up: pin the test with deterministic cancel injection (e.g. cancel after N completions) instead of the wall-clock race. Not a product-code change.

## 6. Impact and limits

- Judgement, storage, protocol, versions, engine all unchanged. No cache invalidation. JSON additive, compatible with old readers.
- Timestamp basis (start_time), NOPTS substitution, variance selection, and DTW coverage are not in this build (gated / need validation; see the audit directive below).

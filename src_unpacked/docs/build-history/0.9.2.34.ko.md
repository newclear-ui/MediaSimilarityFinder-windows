# MediaSimilarityFinder v0.9.2.34 — Windows 공통 호환성 반영판

## 목적
v0.9.2.32 공식 기준선은 보존하면서 Windows CPU 테스트에서 발견된 CPU/CUDA 공통 호환성 문제를 공통 소스에 반영하였다. CUDA backend의 알고리즘, 메모리 경로 및 커널 구현은 변경하지 않았다.

## 변경 내용
- SQLite vcpkg `unofficial-sqlite3` CMake target 대응
- Windows WIC/Qt 및 `NOMINMAX` 처리
- `M_PI` → C++20 `std::numbers::pi`
- FFmpeg 9 `av_find_best_stream()` 인자 호환
- `SystemLoadMonitor` 내부 상태 멤버 위치 수정
- Windows UTF-8 filesystem 변환 유틸리티 추가 및 주요 경계 적용
- `ReadDirectoryChangesW` overflow/resync 및 버퍼 경계 검증
- StableFileDetector 성공 후 상태 정리
- MSVC 테스트 `__builtin_popcountll` → `std::popcount`
- Windows SDK `SystemLoad` 심볼 충돌 회피를 위한 명시적 `msf::` 사용
- Visual Studio 18 2026 CUDA 빌드 스크립트 및 project-local vcpkg 사용

## 이전 구조
Windows에서 플랫폼/컴파일러에 따라 표준 CMake 패키지명, 수학 상수, Windows 매크로, filesystem 문자열 변환, FFmpeg API 및 GNU 전용 테스트 intrinsic에 의존하는 부분이 남아 있었다.

## 새 구조
공통 Core/Monitor/Scanner/Index/Decoder 경계에서 Windows 호환성을 처리하고, 테스트도 표준 C++20 API를 사용한다. CUDA 계층은 기존 구조를 유지한다.

## 선택 이유
CPU와 CUDA에서 동일한 Core를 사용하므로 플랫폼 공통 수정은 한 기준으로 관리해야 중복 수정과 분기별 동작 차이를 방지할 수 있다.

## 검증
Linux에서 CUDA OFF / GUI OFF / FFmpeg OFF 구성으로 전체 소스가 컴파일되었고, 36개 테스트 바이너리가 생성되었다. Windows MSVC/Qt/CUDA 실행 검증은 사용자 Windows 환경에서 다음 단계로 수행한다.

## 버전/기준선
- 공식 보존 기준선: v0.9.2.32
- Windows CPU 테스트: v0.9.2.33-test
- 공통 Windows/CUDA 반영 검증선: v0.9.2.34


## 후속 정정 — Windows 빌드 기준 통일

v0.9.2.34 source-ready 검토 과정에서 Windows 빌드 기준을 실제 검증 환경인 Visual Studio 18 2026에 완전히 통일하지 못한 항목을 추가 정정하였다.

### 변경 필요성
- `CMakePresets.json`의 `windows-cpu`, `windows-cuda`가 Visual Studio 17 2022를 지정하고 있었다.
- `scripts/build_windows_cpu.ps1`도 Visual Studio 17 2022를 사용하고 있었다.
- CPU 스크립트의 vcpkg 설치 목록에 `qtbase`가 명시되지 않았고, project-local `vcpkg_installed`를 사용하지 않았다.

### 기존 구조
- Preset의 Windows CPU/CUDA Generator: Visual Studio 17 2022
- CPU PowerShell: Visual Studio 17 2022 + 외부/classic 설치 경로
- CPU 의존성 설치: `sqlite3`, `ffmpeg`
- CUDA PowerShell: Visual Studio 18 2026 + project-local `vcpkg_installed`

### 변경 구조
- 모든 Windows Preset: Visual Studio 18 2026
- CPU PowerShell: Visual Studio 18 2026
- CPU/CUDA 공통 의존성 기준: `vcpkg.json`의 `sqlite3`, `ffmpeg`, `qtbase`
- CPU/CUDA 모두 `<projectRoot>\vcpkg_installed\x64-windows` 사용
- CPU 스크립트도 `VCPKG_INSTALLED_DIR`, `VCPKG_TARGET_TRIPLET`, `unofficial-sqlite3_DIR`, `Qt6_DIR`, `MSF_FFMPEG_ROOT`를 명시

### 선택 이유
사용자 실제 Windows 검증 환경이 Visual Studio 18 2026이며, CPU와 CUDA가 동일한 Core/GUI/FFmpeg/SQLite 의존성을 공유하므로 Generator와 dependency 설치 위치를 동일하게 유지해야 재현성과 호환성 검증 결과를 비교할 수 있다.

### 해결된 상황
Windows CPU와 CUDA 빌드 스크립트 및 Preset 사이의 Generator 불일치와 vcpkg dependency 경로 차이를 제거하였다. CPU GUI 빌드에 필요한 `qtbase`도 manifest에 포함된 공통 의존성으로 확정하였다.

### 정확성/호환성 영향
실제 VS 18 2026 환경에서 Configure/Build할 때 잘못된 VS 17 2022 Generator 선택 가능성을 제거한다. CPU와 CUDA가 동일한 project-local dependency tree를 사용하므로 Qt6/SQLite/FFmpeg 버전 차이로 인한 검증 결과 왜곡 가능성도 줄인다. CUDA 알고리즘/커널에는 변경이 없다.

### 검증
소스 정적 검토로 Preset 2개와 CPU/CUDA 스크립트의 Generator 및 vcpkg 설정을 대조하였다. 수정 후 Windows 실제 Configure/Build/CTest 검증은 다음 단계에서 수행한다.

### 향후 영향
이후 Windows CPU/CUDA 빌드는 Visual Studio 18 2026과 project-local `vcpkg_installed`를 공통 기준으로 사용한다. project-local vcpkg는 Windows 전체 빌드/검증 완료 전까지 유지한다.

기준선 `0.9.4.162` → 본 빌드 `0.9.4.163`.
CPU CTest **134/134**, GPU CTest **135/135** (신규 실행 파일 없음, `video_gpu_benchmark_test`에 스윕 섹션 추가).
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10` / `kProtocol 1` 전부 불변.

## 1. 변경 필요성

- 외부 리뷰 P2 지적: GPU batch 크기와 CPU/GPU 전환 비용을 실측으로 조정해야 한다. 전환 임계값(`map.size()>=8`)과 pHash 청크 크기(256)는 측정 근거 없이 정해져 있었다.

## 2. 기존 구조

- MSSIM: 게이트 통과 쌍이 8 이상이면 `ssimBatch`, 미만이면 CPU `frame_ssim`.
- pHash: `recommendedBatchSize(256)` 청크로 `hashBatch` 호출. `processVideoFrames`는 kept 타깃(≤16)으로 이미 trim되므로 실스캔에서 청크 분할이 거의 발생하지 않는다.

## 3. 변경 구조

- 제품 코드 변경 없음. `video_gpu_benchmark_test`에 측정 섹션 추가:
  - SSIM 스윕: 배치 1/2/4/8/16/32/64/128에서 GPU vs CPU 쌍당 비용 + 1e-6 이내 일치 단언(미달성 시 실패).
  - pHash 청크 스윕: 동일 1024 프레임을 64/128/256/512/1024 청크로, 비트 완전일치 단언.

## 5. 해결된 상황 및 판정

- **SSIM 게이트 8 유지 (변경 NOT ACCEPTED).** crossover는 32~64 구간이나, 실스캔 행당 게이트 쌍은 kept 상한(≤16) 때문에 64 이상이 사실상 발생하지 않는다. 게이트를 올려봤자 절대 절약량은 매칭 MSSIM(전체 스캔의 ~0.1%대)의 일부에 불과한 반면, AGENTS.md 5에 따라 엔진 patch bump → 저장 쌍 전체 재검증(분 단위~시간 단위 일회성 비용)이 강제되어 순손실이다. 재검토 조건: `.162`의 `videoMatchGpuMs/CpuMs/Submitted/Completed`가 실스캔 분포에서 다른 그림을 보여줄 때.
- **pHash 청크 256 유지 (변경할 것 없음).** 실스캔 packing은 kept 상한으로 단일 청크에 들어가므로 청크 값과 무관하다. 스윕은 백엔드 특성 기록 + exactness 핀으로 유지한다.
- 두 임계값 모두 "근거 없이 건드리지 않는다"는 P2 원칙의 실측 사례로 남는다.

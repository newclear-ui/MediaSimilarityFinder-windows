# MediaSimilarityFinder v0.9.3.7 — Engine Lookup Before Budget Gate + Video Unit Fix

## Need for change
- Despite the v0.9.3.5 P0 (engine-produced thumbnails), only the first row showed
  thumbnails. Screenshot: 4 real thumbs out of 902 groups; the right detail pane
  (budget-bypassed) rendered fine, ruling out decoder/file problems.
- Root cause: the free engine lookup sat behind the paid decode-budget gate.
  Once 4 uncached rows per tick consumed the budget, later rows were cut to
  placeholders regardless of engine LRU hits. It looked frozen at the first row.
- Side finding: video lookup always missed on unit mismatch. The GUI passes
  milliseconds-since-epoch; the engine cache uses 100ns ticks-since-1601.

## Previous structure
- `fileThumb` order: cache → disk → fail skip → budget gate → engine → shell → heavy decode.
- Video lookup took caller-supplied size/mtime.

## New structure
- Engine lookup moved ahead of the budget gate. Hits cost no budget.
- Video lookup takes a path-only key; the engine stats the file itself. Unit
  mismatch eliminated at the source.
- Color LRU raised 512 → 2048 entries. Previously the sorted-first (visible) rows
  were evicted first as oldest.
- Version strings unified → 0.9.3.7.

## Resolved situation
- Scanned files display on engine hit regardless of row position. Beyond-LRU and
  unscanned files still fill progressively under budget.

## Validation
- Core+GUI Release build: PASS, **CTest 59/59 PASS**.
- GUI-thread visual behavior has no automated test; verified by code review and
  order comparison.
- Portable `--smoke` exit 0, `MediaSimilarityFinder-v0.9.3.7-Portable-Windows-x64.zip` produced.

## Future impact
- None. Budget and gate structure unchanged; only lookup order moved.

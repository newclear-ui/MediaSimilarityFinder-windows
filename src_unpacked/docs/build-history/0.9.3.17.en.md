# MediaSimilarityFinder v0.9.3.17 — Single-Sweep Video Decode, Duration Fallback

## Need for change
- A measured benchmark (2439 videos, 15GB, 17-minute wall) showed video analysis taking 97% of total time. The slowest file (4K 2160x3840, 182s) cost 175s, and direct measurement split it into a 32px sweep of 83.6s plus a 96px sweep of 84.0s. The workload is decode-bound; hashing costs ~0.
- The detail pane duration row always showed "-" on live/cancelled scans, because `fileDur_` is only filled by the final `onResults`.
- The conclusion is a decode-pass cut, not a full algorithm redesign: the pipeline structure (cache-backed temporal, streaming, GPU micro-batches) is sound.

## Previous structure
- `build()` / `buildFull()` ran two full-file sweeps, 32x32 and 96x96.
- The detail duration depended solely on `fileDur_`.

## New structure
- Added `VideoDecoder::framesAt96Plus32()`: one 96x96 sweep, 32x32 derived in software via an exact 3x3 box mean (same timestamps, 1:1 aligned).
- `build()` / `buildFull()` (96 mode) use the single sweep. The legacy two-sweep path remains only for non-96 size requests (all current callers use 96).
- Derived 32px values can differ from direct decodes, so the cache format went v8 → v9 (old caches invalidated, one-time re-fingerprint). The engine verdict version went 1.4.0 → 1.5.0 with automatic stored-pair revalidation.
- An empty detail duration now falls back to the engine file list and caches the result.
- Added `tests/video_decode_parity_test`: per-frame pHash drift direct-32 vs derived-32 plus `video_similarity` on a real re-encoded clip.

## Resolved situation
- Full-file video decoding per fingerprint build is halved (hashing, crop, and thumb logic unchanged).
- Durations display on live and cancelled scans too.
- Full-hash and temporal semantics are unchanged, so the verdict system is intact.

## Validation
- Slowest physical file (4K 2160x3840): sweeps of 83.6s + 84.0s → halved by construction. Parity test measured 6 frames, worst drift 4 bits, similarity 96.875.
- New `video_decode_parity_test` PASS (drift ≤ 4 bits, similarity ≥ 95).
- CUDA Release build PASS, **CTest 63/63 PASS**.
- CPU-only Release build PASS, **CTest 62/62 PASS**.
- Portable v0.9.3.17 creation and smoke PASS, `--version` 0.9.3.17.

## Future impact
- The v9 cache invalidation re-fingerprints everything once on the first scan; later scans are faster.
- One 4K software decode per file remains. The next candidate is NVDEC hardware decoding (needs AV1/codec coverage and dependency review).
- Benchmark analysis: 0.2% GPU duty is normal (2.5ms GPU vs 1183ms build per video — invisible to nvidia-smi). Mean 17% CPU reflects G:-drive I/O and decoder serial waits, not thread starvation. Zero analyze output is normal for scans stopped during the video stage.

# MediaSimilarityFinder v0.9.4.120 — GUI-less configure restored + badge-cost decision + product acceptance runbook

Baseline `0.9.4.119` -> this build `0.9.4.120`.
CPU CTest **123/123**, GPU CTest **124/124**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why it was needed (multiple)

1. **`MSF_BUILD_GUI=OFF` + `MSF_BUILD_TESTS=ON` did not configure** (an unfixed observation): the GUI test `msf_ui_detailed_log_test` linked `Qt6::Widgets` from inside the non-GUI tests block (CMakeLists line 456), so a GUI-less configure that never finds Widgets aborted with a CMake error.
2. **The badge-confirmation cost candidate (#2) needed a verdict**: the 0.9.4.113 full-content SHA-256 confirmation was measured at ~1.5 GiB extra reads per full scan (the user index; ~2.2% of 69.2 GB) and was a conditional candidate ("only if the field feels worse").
3. **No product acceptance runbook**: there was no executable checklist for the final Search/Index/Comparison acceptance (NOT ACCEPTED).

## 2. Previous structure

1. CMakeLists: the GUI build/tests live under `if(MSF_BUILD_GUI)` -> `if(Qt6_FOUND)` -> `if(MSF_BUILD_TESTS)` (line 675+), but `msf_ui_detailed_log_test` alone remained in the upper tests block (lines 451-460).
2. Badge confirmation: `MediaSearchEngine::loadMatches` runs one full SHA-256 per candidate-gated pair (size + quick hash), memoized per path, skipping files above the 512 MiB cap; each file is read at most once per pass (the .113 contract).

## 3. New structure

- **(1) GUI-less configure restored (code)**: `msf_ui_detailed_log_test` moved next to the other GUI tests. GUI=OFF + tests=ON now skips GUI tests and configures/builds the core tests only. The GUI=ON path keeps its registration counts (CPU 123 / GPU 124).
- **(2) Badge-confirmation cost = LOW PRIORITY verdict (no code change, recorded)**: rationale - (a) the .113 measurement: 3,493 pairs / 5,296 files confirmed with ~1.5 GiB reads (~2.2% of 69.2 GB; sub-second on NVMe); (b) the field (0.9.4.118 06:40 AB session): only 2 candidates confirmed, Load felt normal, no complaint; (c) a partial cap would reintroduce the differing-tail mislabel that audit B1 rejected. Revisit conditions: a reported Load stall, a dataset moving to HDD, or tens of thousands of identical copies.
- **(3) Product acceptance runbook (docs)**: new `docs/architecture/product-acceptance-runbook.{ko,en}.md` - Index/Search/Comparison checklists, expected evidence, recording format (1:1 detailed-log cross-check), crash-procedure reference.

## 4. What is fixed

- Test builds are now possible without the GUI, opening a CI/headless verification path (configure failure -> success; the headless tree registers 98 tests and builds a sample target).
- The badge cost is recorded as a decision with evidence and revisit conditions (including the no-partial-cap rule) instead of ad-hoc changes.
- Product acceptance now has a repeatable procedure document.

# MediaSimilarityFinder v0.9.4.101 — 열기 경로 상세 동기화

기준선 `0.9.4.100` → 본 빌드 `0.9.4.101`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변.

## 1. 변경 필요성

사용자 보고(0.9.4.100 실측, 스크린샷 2장 + `msf_scan.log`): 불러오기 후 그룹→파일 선택 시 미리보기는 표시되지만 상세 텍스트 행이 전부 `-`이다. 화면 증거상 행 자체는 멀쩡하고(`rows=9`), 값만 비어 있다.

## 2. 기존 구조

- `currentFile_`을 쓰는 곳은 모두 선택 직후 `refreshDetail()`을 호출했다. **유일한 예외**: 더블클릭 열기 경로 2곳(우측 그리드 `fileActivated`, 우측 리스트 람다)이 `currentFile_`만 세팅하고 상세 갱신을 건너뛰었다.
- 그 결과 오래된 `-` 행 위에, 나중에 도착한 썸네일이 미리보기만 칠하는 상태(빈 텍스트 + 살아있는 미리보기)가 가능했다. `detailAnomaly` 트립와이어(`vis=0` 실측)는 같은 방향을 가리켰다.

## 3. 변경 구조

- **단일화**: `showFileDetails(path)` 신설 — 세팅 + 갱신을 한 곳에서. `fileActivated`와 리스트 더블클릭 람다가 모두 경유한다.
- 그 외 `currentFile_` 기록부는 전수 대조 완료 (선택/해제/로드/스캔시작/정리 모두 갱신 동반).
- 테스트: phase 15 (뷰 선택 변경 없이 열기 경로 호출 → 파일명 표시 단언).

## 4. 해결된 상황

- 더블클릭 열기를 포함한 모든 `currentFile_` 전이는 상세 행과 함께 움직인다. 오래된 `-` 행 위에 미리보기만 살아나는 조합이 닫혔다.

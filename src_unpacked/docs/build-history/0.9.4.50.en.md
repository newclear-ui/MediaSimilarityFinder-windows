## 1. Why the change was needed

The GUI Detailed Log vs CLI benchmark log audit found these gaps:

- No **finish timestamp** in the GUI log (unlike CLI journal's
  `run_finished.completedAt`)
- No record of **which phase a cancellation stopped in** (only
  `completionReason=cancelled`)
- No **fingerprint duration/bytes**, so the 75 GB incident's actor cannot be
  proven from the log
- No **summed total** of `images.bytes` + `videos.bytes`
- No **absolute timestamp** in `series` for cross-run timeline comparison
- Process peak memory (`memMBMax`) exists but **system total** is missing,
  which matters on low-memory systems

## 2. Previous structure

- `meta.startedAt` recorded via `localTimeStr()`. No finish field
- `completionReason` exists but no phase concept
- `DatasetFingerprint` carries only hash/fileCount/totalBytes
- `series` is 7 positional elements `[tMs,cpuProc,cpuSys,memMB,gpu,ioReadBps,ioWriteBps]`
- `memMBMax` exists without system total

## 3. New structure (Phase-A sextet, all additive)

| Field | Location | Meaning |
|---|---|---|
| `meta.finishedAt` | recorded in finalize() via `localTimeStr()` | absolute finish, never derived from wallMs |
| `meta.cancelledDuring` | `fingerprint`/`walk`/`analyze` | phase at cancel time; empty unless actually cancelled |
| `dataset.durationMs` | whole walk+hash measured | fingerprint phase timing |
| `dataset.bytesRead` | bytes actually hashed | equals totalBytes on success, less on cancel/failure; partial chunks uncounted |
| `summary.totalScannedBytes` | `images.bytes + videos.bytes` fixed sum | distinct from `dataset.totalBytes` (fingerprint input) |
| `series[].wallTime` | absolute time per sample | `tMs` kept; 8th positional element |
| `resources.memSystemMB` | `GlobalMemoryStatusEx` total physical RAM | for judging the process peak; 0 means uncaptured |

### Phase latching design

Phases record on entry, but **do not advance once cancel is set**. A pre-set
cancel freezes at `fingerprint`; a mid-walk cancel freezes at `walk`. The point
is the cancel moment, not the finalize moment.

### Series guarantee for fast scans

A scan finishing before the 250 ms sampler fires left series empty and wallTime
unverifiable. `finalize()` now takes one synchronous sample when none exists.
It is a real measurement (CPU, memory, IO as they stand), not filler.

## 4. Resolved situation

- Finish time, cancel location, fingerprint cost/read volume, summed bytes,
  absolute times, and system total are all in the JSON
- Existing fields and meanings untouched; additive only

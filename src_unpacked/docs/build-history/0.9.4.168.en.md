# MediaSimilarityFinder v0.9.4.168 — V3 Segmented Kept Selection Becomes the Default + V2 Retained

Baseline `0.9.4.167` → this build `0.9.4.168`.
CPU CTest **138/138**, GPU CTest **139/139** (no new CTests; existing tests amended).
`kEngineVersion 1.5.2` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 11` / `kProtocol 1` (all unchanged).

## 1. Why the change was needed

- User decision: adopt V3, retain V2 as runner-up. Field evidence 1 (50-pair re-encode/flip) showed V3 buys flat-half coverage for effectively nothing (49/50 identical counts, one file +1 frame). It is the only change directly tied to preventing duplicate misses.

## 2. Previous structure

- Default was the legacy variance-ranked path; V3 ran only under `MSF_VIDEO_KEPT=segmented`. Cache identity split on `policyId()` alone.

## 3. New structure

- Default flipped: always segmented, legacy only under `MSF_VIDEO_KEPT=legacy` (rollback).
- The selection method joins the cache identity (`+seg`/`+var` suffix): rows from the other method miss and rebuild once (same mechanism as the 0.9.4.156 policy column; no format/engine bump).
- No V2 probe code change. `video_structure.h` now records the runner-up retention rationale + the reuse entry point (the only time-structure observer; deleting it would force a rewrite for structure-windowed kept selection).
- Tests: `video_kept_select_test` pins default (segmented flat coverage) + legacy rollback. `video_cache_test` pins legacy `v1` row miss + `v1+seg` row hit (one-time rebuild on the switch).

## 4. Resolved state

- The default path guarantees time-axis coverage. Legacy restores via environment variable if needed.

# MediaSimilarityFinder v0.9.4.146 — Sort display consistency + backend/GUI single-instance guards

Baseline `0.9.4.145` → this build `0.9.4.146`.
CPU CTest **125/125**, GPU CTest **126/126**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

- Field (C-5): starting a scan locked the sort combo to "None" but the list kept the previous sort order, so the combo and the visible order disagreed. Restoring the pre-scan sort after completion did not reorder the list either.
- Backend lifecycle requests:
  - prevent standalone backend launches; exit automatically when no GUI is present,
  - stop the backend from surviving GUI close/crash,
  - prevent duplicate backends,
  - prevent multiple GUI instances.

## 2. Previous structure

- `setRunning(true)` changed the combo to None with `blockSignals` and did not re-sort; `setRunning(false)` restored the combo but not the list order.
- The backend ran with `--backend --nonce` alone and never verified a parent GUI; an orphaned backend could remain after a GUI crash.
- Neither the GUI nor the backend had single-instance protection.

## 3. New structure

- **Sort**: on scan start, when locking to None, the list is rebuilt once in the None order; on scan end the pre-scan sort is restored and the list rebuilt in that order (guarded by `wasScanning`, so only a real scan completion does this). The 0.9.4.142 view freeze still prevents mid-scan churn.
- **Backend launch validation**:
  - the supervisor passes `--parent-pid <GUI PID>` and the env vars `MSF_BACKEND_LAUNCHED_BY_GUI=1` / `MSF_BACKEND_PARENT_PID`.
  - the backend enters server mode only when all match and the parent is alive; a standalone launch prints a notice and exits **3**.
  - a 1-second parent watchdog exits the backend when the GUI disappears (a second layer beside the Job Object).
  - one backend per user session: a named mutex (`Local\MediaSimilarityFinder.Backend.SingleInstance`) refuses duplicates with **exit 4**.
- **GUI single instance**: `Local\MediaSimilarityFinder.Gui.SingleInstance`; a second launch shows a notice and exits (smoke/version/help modes are exempt).

## 4. Result

- The sort combo and list order always agree (None at scan start; the previous sort restored on completion).
- The backend only runs when launched by the GUI and does not survive GUI exit/crash.
- Duplicate backend and GUI instances are blocked.

## 5. Verification

```text
CPU Release CTest 100% tests passed out of 125
GPU CTest 100% tests passed out of 126
GUI/Backend --version 0.9.4.146
```

- `ui_scroll_regression_test` (checks=104): pins combo/list agreement (None applied at scan start, pre-scan sort restored and applied at completion).
- `backend_e2e_test` (checks=92): **standalone launch refused (exit 3)**, **duplicate refused (exit 4)**, and the no-job parent-death control updated to the watchdog auto-exit.
- Field: a second GUI instance shows a notice and exits; closing the GUI ends the backend process.

## 6. Impact and limits

- Launch validation uses env vars/parent PID; it targets accidental standalone launches, not adversarial bypass.
- The test-only wedge backend loops before the watchdog and is cleaned up by the Job Object (not a production path).
- The sort restore rebuilds once at completion, a small cost to keep the user's sort order consistent.

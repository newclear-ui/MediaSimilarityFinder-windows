# MediaSimilarityFinder v0.9.4.71 — 백엔드 결함 수정 + ThumbnailStore

기준선 `0.9.4.70` → 본 빌드 `0.9.4.71`.
CPU CTest **116/116**, GPU CTest **117/117**.
`kEngineVersion 1.5.0` / `kDatabaseVersion 1.0.4` / `kBenchmarkSchemaVersion 9` /
`kCacheFormatVersion 9` — 전부 불변. 검색 의미·동작 변경 없음.

## 1. 변경 필요성

- P3/P4 프로세스 분리 후 2차 독립 재검토에서 확정된 결함 7건을 수정한다.
  가장 큰 두 건은 (a) 분리 이후 GUI의 자원 모드(Maximum 등)가 IPC로 전달되지
  않아 워커가 항상 `make_policy(Custom)`로 실행되던 것, (b) Backend 썸네일
  경로가 엔진 `thumbMap_`만 읽고 디스크 DB·decode fallback이 없어 분리 이후
  대부분의 미리보기가 비어 있던 것이다.
- `onFileMetaReady`가 `refreshFileViews()` 전체 재생성을 호출해 파일메타 도착
  시마다 선택이 파괴되던 회귀(0.9.4.66 in-place 패턴 위배)를 바로잡는다.
- 검증 과정에서 추가 회귀 1건을 발견한다: GUI가 JPEG을 Qt 플러그인으로
  디코드하는데 배포 세트에 플러그인 의존 DLL이 없어 썸네일이 전혀 그려지지
  않는다(테스트가 검출).

## 2. 기존 구조

- `ScanWorker::run()`이 `resourceMode_` 없이 `make_policy(Custom)`로 워커 수를
  계산. `START_SCAN` payload에 모드가 없음.
- GUI "Index Complete"는 `analyzedCount_`만 표시 → 재사용(unchanged) 파일이
  빠져 완료 시에도 0/미달로 보임.
- 요약 패널의 CPU/RAM 라벨을 `updateSysLabels()`(GUI 프로세스, 매 UI tick)와
  `onMonitorSnapshot()`(시스템 전체, 1s)이 번갈아 덮어씀 → MB/% 값이 진동.
- 느린 파일 목록에 cache-hit 비디오 재구성(~0ms)과 실패 decode(0ms) 항목이
  섞여 실제 알고리즘 이상치를 가림.
- `ScanWorker::allMatches_`가 최종 persist 이후에도 프로세스 수명 동안 유지.
- Backend 썸네일은 엔진 `thumbMap_`만 조회. 디스크 캐시·WIC/FFmpeg/shell decode
  연결이 없음(`thumbDb_`는 GUI에서 삭제된 뒤 이전되지 않음).
- `onFileMetaReady`가 `refreshFileViews()`로 위젯 전체를 재생성.
- loopback·supervisor가 JPEG을 `QImage::fromData`로 디코드.

## 3. 변경 구조

- **Execution policy 전달 (두 축 독립 유지)**: `ExecutionPolicy`
  `{cpuMode, cpuPercent, gpuPercent, strategy, gpuEnabled}` 신설.
  `BackendScanConfig.exec` → `START_SCAN` payload → `ScanWorker::setResourceMode`
  → `run()`의 `make_policy(resourceMode_)`. 라이브 갱신은
  `UPDATE_RESOURCE_POLICY` 명령 + `POLICY_APPLIED` 응답(partial=true = monitor
  즉시 / engine 다음 scan). GUI `resourceChanged`/`customResourceChanged`가
  `updateResourcePolicy`로 전환. scalar cpu/gpu 필드는 구독자 호환용으로 유지.
- **Index Complete**: 엔진 `unchangedCount_` atomic 추가(nUnchanged 증가 지점과
  동일 위치), `BackendStatus.unchanged` 전달, GUI `liveAnalyzed =
  analyzed + unchanged`.
- **요약 라벨 단일 의미**: `updateSysLabels()`는 GPU 상태만 기록.
  CPU/RAM은 작업 프로세스 기준 status snapshot(`onStatusSnapshot`)만 기록.
  `backend_sysinfo.*::sampleOwnProcess`가 Backend 프로세스 CPU%/WorkingSet을,
  loopback은 GUI 프로세스를 샘플.
- **느린 파일 목록**: `addImage`는 `decodeMs+hashMs+cropMs<=0` 제외,
  `addVideo`는 `cacheHit` 플래그(엔진 `VideoBuildStats.cacheHit`) 항목 제외.
  명시 없이 호출된 분석은 그대로 목록에 남는다.
- **메모리 해제**: 최종 `persistMatchesSnapshot()` 후 `allMatches_.clear()` +
  `shrink_to_fit()`. 정상 경로와 두 catch 핸들러 모두(핸들러 무throw 규칙에
  따라 `shrink_to_fit`는 try/catch로 감쌈).
- **ThumbnailStore**: 신규 `src/thumbnail_store.{h,cpp}` — 영속 SQLite
  (`IndexManager::resolve`) + 소형 메모리 LRU(256) + decode 체인(engine art →
  shell `IThumbnailCache` → WIC → FFmpeg → gray). JPEG을 end-to-end로 제공하고
  `ScanWorker` 수명과 독립. `backend_thumb`(JPEG 인코더)를 msf_core로 이동하고
  `libjpeg-turbo`를 `msf_core PUBLIC` 링크. `BackendSession::requestThumb`가
  `msf::JpegThumb` 반환, `backend_main::serveThumbnail`의 재인코딩 제거.
- **fileMeta in-place**: `fileMetaPending_`을 `QSet<QString>` →
  `QMap<quint64,QString>`(id 기반 dedup + requestId stale-drop)로 전환.
  `onFileMetaReady`는 일치하는 grid 셀 / list 행만 `refreshFileMetaRow`로
  갱신하고 현재 파일이면 `refreshDetail`만 호출. 위젯 재생성 없음.
- **JPEG 디코드 공용화(회귀 수정)**: 신규 `msf::decodeJpegArgb32`
  (`backend_thumb`, libjpeg-turbo)가 ARGB32 메모리 순서(BGRA) 바이트를 반환.
  loopback·supervisor가 이를 사용해 Qt JPEG 플러그인 의존을 제거.

## 4. 해결된 상황

- GUI에서 고른 자원 모드가 실제 워커 예산에 반영된다(Maximum 저하 해소).
- 분리 이후 비어 있던 미리보기가 엔진 art·디스크 캐시·decode fallback으로
  채워진다. GUI 프로세스는 여전히 media pixel decode를 하지 않는다.
- 파일메타 도착이 선택/스크롤을 파괴하지 않는다.
- 요약 CPU/RAM 라벨이 하나의 의미(작업 프로세스)로 고정되어 진동하지 않는다.
- Index Complete가 실제 인덱스 완료량을 표시한다.
- 느린 파일 목록이 실제 작업 파일만 보여준다.
- 최종 persist 후 Backend가 match 집합을 해제한다.
- 썸네일이 실제로 그려진다(배포 의존성과 무관).

## 5. 검증

### 결함별 대응

1. Execution policy: E2E/스캔 경로에서 mode가 전달됨(코드 경로) + CPU/GPU 전체
   CTest 통과. GPU MAX share boost 미구현은 문서화된 공백(자동 승격 없음).
2. Index Complete: `unchanged` push 배선 + GUI 합산. 테스트 전수 통과.
3. 요약 라벨: `updateSysLabels` GPU 전용, `onStatusSnapshot` CPU/RAM 단일 writer.
4. 느린 파일: `benchmark_test`가 cache-hit 제외 후에도 실제 분석 항목을 유지.
5. 메모리: 정상/실패 경로 모두 clear + shrink.
6. ThumbnailStore: `ui_scroll_regression_test`("thumbnails painted on arrival"),
   `view_mode_probe`("arrivals painted through the product path") 통과.
7. fileMeta in-place: `ui_scroll_regression_test`의 selection widget identity
   검사 통과(재생성 0).
8. JPEG 회귀: `QImageReader::supportedImageFormats()`에 jpeg 부재,
   `dumpbin imageformats/qjpeg.dll` → `jpeg62.dll`(배포 세트에 없음) 확인.
   공용 libjpeg-turbo 디코드로 대체 후 두 GUI 테스트 통과.

## 6. 향후 영향

- 실제 GUI 육안 acceptance는 여전히 필요하다(미리보기 표시, selection,
  kill 시 UI 가드, restart 후 복귀, Tiles/ListMode, 대형 dataset traversal).
- GPU MAX의 GPU share boost는 미구현 상태로 남는다(동작 공백 문서화).
- Backend 400MB의 정확한 비중은 VMMap/힙 스냅샷이 필요하다(코드만으로 비율
  판정 불가; allocator Working Set 미반환 caveat).
- `ExactnessPolicy::RefuseAll` 유지, Node E 종결 상태 불변.
- 0.9.5(ImageWorker/VideoWorker/MonitorService)는 별도 설계 범위.

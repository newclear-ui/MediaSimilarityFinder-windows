## 1. Why the change was needed

- XMP evidence stopped at decode level. `xmp_orientation_test` (38 checks) and the real-file probe (23 checks) prove the transform applies, but not that the fallback changes pair/group verdicts through the actual scan pipeline.
- The isolated Test Mode scan was only covered by `test_mode_test` with 4 BMPs. There was no Test Mode regression with XMP-bearing file character (conflict, invalid, EXIF-wins).

## 2. Previous structure

- `test_mode_test`: one production scan + one warm repeat + one Test Mode scan over 4 identical BMPs, asserting counts and production-index byte invariance. Its fixtures carry no XMP metadata, so the orientation branch never executes.

## 3. Changed structure

- New `tests/test_mode_xmp_test.cpp` (Windows-only, SKIP elsewhere): one WIC encode + per-file APP1 splicing for 5 JPEGs, then one production scan + one Test Mode scan.
  - a1/a2: no EXIF, XMP=1 (identical -> pair, control)
  - b1: no EXIF, XMP=6 (90CW -> unrelated to a)
  - c1: EXIF=6, XMP=1 (EXIF wins -> 90CW -> unrelated to a)
  - d1: no EXIF, XMP=banana (invalid -> identity -> pairs with a)
  - Pair verdicts asserted from collected `matchesBatch(LiveMatch)` items, no string parsing.
- Verdict contract: a1-a2 pair present, b1-c1 pair present (same rotation via different sources — end-to-end byte-equivalence evidence), no rotated-flat cross pairs, d1-a pair present, Test Mode verdicts == production verdicts, production index bytes unchanged, scratch-local index created.
- Two test bugs found and fixed during implementation (no product code involved):
  - APP1 spliced right after SOI was never resolved by WIC, forcing identity pairing everywhere. Fixed to camera order (after SOI + leading APP0) — the same layout the shared-WIC probe uses.
  - The initial "b1/c1 pair with nothing" assertion was wrong: they pair with each other as the identical rotation. Corrected to "b1-c1 pair present + no cross pairs".

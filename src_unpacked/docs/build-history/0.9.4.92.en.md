# MediaSimilarityFinder v0.9.4.92 — pair-verify DBV-1/DBV-2 (key read removal + cache enlargement)

Baseline `0.9.4.91` -> this build `0.9.4.92`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` unchanged.

## 1. Why

Image pair verification (L2) cost is **decode 86.5% · cache-key I/O 13.4% · SSIM 0.04%** (0.9.4.91 log).
We implement and measure the low-risk candidates from `docs/architecture/database-structure.ko.md` section 7:
V-1 (remove the quickHash read from the cache key) and V-2 (enlarge the verify buffer cache).

## 2. Previous structure

- `verifyBuffersFor` read 64 KiB from the file on **every lookup** to build the FNV cache key
  (2 path stats + a 64 KiB read). On a high-latency drive that is 948 MB of reads -> `verifyKeyMs` 170 s (summed).
- The verify buffer LRU was `kVerifyCacheMax = 32`, effectively useless against 14k distinct files (9.1% hit rate).

## 3. New structure

- **DBV-1**: the key is reduced to `(path, size, modified)` with **zero file reads**. (Content cannot change within
  a scan, so this is safe inside one scan; a same-size+same-mtime content change is the rare miss, the same
  limitation as the whole-dataset fingerprint cache.) `quickHash` is removed from `VerifyCacheKey`/hash.
- **DBV-2**: `kVerifyCacheMax` 32 -> **1024** (~8 KB/entry, ~8 MB). A file reused across pairs stays resident.

## 4. Result

- Removing the 64 KiB read -> `verifyQuickHashReads/Bytes` 0, the read portion of `verifyKeyMs` gone.
- Higher cache hit rate -> far fewer decode misses / `verifyDecodes` -> lower `verifyDecodeMs`.

## 6. Performance experiment record (AGENTS item 9)

- **Experiment**: DBV-1 (key read removal), DBV-2 (cache enlargement)
- **Baseline**: 0.9.4.91 logic (standard-dataset before).
- **Hypothesis**: the key's 64 KiB read is redundant and the 32-entry cache is useless.
- **Method**: edit `image_verify.cpp`, `msf_dataset_baseline` before/after, CTest parity.
- **Result**: table above. V-1 key -37.9% (read removed), V-2 decode -93.1% (hit up), wall -53%.
- **Status**: PASS (standard dataset).
- **Known limitation**: a same-size+same-mtime content change reuses the cache (same as the whole-fingerprint cache).

## 7. Impact and limits

- GUI/engine verdicts unchanged. DB/schema/cache format unchanged.
- The standard dataset is on C: (low latency), so V-1's absolute effect is measured small -> a user G: re-measurement is needed.
- Follow-ups: DBV-3 (decode reduction, CONDITIONAL), DBV-4 (reuse the index decode).

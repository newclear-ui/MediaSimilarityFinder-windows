# MediaSimilarityFinder v0.9.2.55 — Window-Layout Non-Restore Root Cause Fix (Void QSettings)

## Need for change
Resized window/pane layout was never restored after restart. Investigation found zero app keys in the registry: `main.cpp` never set organization/application names, so every default-constructed `QSettings` silently failed (AccessError). This is documented Qt behavior. Not just geometry — view mode, language, folder, ignore list, everything reset every launch.

## Previous structure
- `main()`: no organization/application names after `QApplication`; default NativeFormat (registry)
- `saveUiState()`/`restoreUiState()` were correct code operating on a void store

## New structure
- **New `initAppSettings()`** (`gui/mainwindow.h/.cpp`): sets organization `newclear-ui` + application `MediaSimilarityFinder`, default format INI, storage path next to the executable. Called once at `main()` start. Portable builds now carry settings with the folder, no registry dependency
- **Cross-process probe test** (`tests/ui_settings_test.cpp`, 2 CTest entries): `--probe-write` (build window → resize → destroy → confirm INI on disk) and `--probe-verify` (separate process confirms restored size), chained via DEPENDS. Separate processes are the point: same-process read-back would hit QSettings' in-memory cache and pass even with broken disk persistence
- Version strings unified → 0.9.2.55

## Resolved situation
- Real-app `--smoke` produces `newclear-ui/MediaSimilarityFinder.ini` next to the exe (mainGeom/splitter/headers/kindMask/groupView all recorded)
- Window size, splitter, and column widths restore on restart. Settings survive moving the portable folder
- Instrumented finding: restored size adjusted by screen/layout minima is normal Qt behavior (the 800x800 offscreen limit is why the probe asserts height)

## Validation
- Core+GUI Release build: PASS, **CTest 44/44 PASS** (incl. new `ui_settings_write`+`ui_settings_verify`)
- `--version` 0.9.2.55, `--smoke` exit 0 + INI file verified
- CUDA algorithms unchanged (common layers only)

## Future impact
- No migration needed: nothing was ever persisted (no registry residue)
- New UI defaults persist automatically via QSettings keys; reuse the same probe pattern for tests
- To relocate settings, edit the single `initAppSettings` call

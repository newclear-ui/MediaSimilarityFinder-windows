# MediaSimilarityFinder v0.9.4.167 — Start-Time Basis Fix + V2/V3/V4 Diagnostic Implementation

Baseline `0.9.4.166` → this build `0.9.4.167`.
CPU CTest **138/138**, GPU CTest **139/139** (3 new CTests: video_structure_test, video_structure_e2e_test, video_kept_select_test).
`kEngineVersion 1.5.1 -> 1.5.2` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 10 -> 11` / `kProtocol 1`.

## 1. Why the change was needed

- External-review P1, confirmed by measurement in 0.9.4.166: containers with `start_time != 0` shift the whole sample grid (measured: first-shift 2.5 s, kept 2 vs 3). Identical content could fingerprint differently and be missed as a duplicate. Fixed per user approval (a).
- User directive: build V2/V3/V4 now, validate later. Default behavior unchanged.

## 2. Previous structure

- `VideoDecoder::open()` never read `start_time`. `framesAt`/`frameAtColor`/the sparse executor copied request time (video-time, 0-based) straight into stream PTS.

## 3. New structure

- New `VideoInfo::startOffsetSec`. `open()` records `start_time x time_base` (finite values only, else 0). Seeks add the offset; decoded PTS subtract it. NOPTS fallback, tail tolerance, and the completeness contract keep operating in video time, unchanged.
- Identical content at identical video times now fingerprints identically (the 0.9.4.166 offset file's kept {2.5,5,8} normalizes to {0,5}, byte-identical to the zero-start file).
- V2: `probeVideoStructure()` (brightness, dark ratio, edge density, inter-frame change; median+3*MAD boundaries; segments; confidence). Pure function + unit test + env-gated (`MSF_VIDEO_STRUCTURE=1`) real-engine e2e. Touches no cache, storage, or verdicts.
- V3: `selectKeptSegmented()` (at-least-one per time segment, then global variance fill, chronological order). Used only under `MSF_VIDEO_KEPT=segmented`; the default path is byte-identical to 0.9.4.156.
- V4: per-pair `covShort/covLong/covSegments` always computed (report-only) + `MSF_VIDEO_STRICT_COVERAGE=1` diagnostic gate (explicitly unvalidated thresholds). `AnalyzeTelemetry.videoMatchCov*` sums + JSON (additive).
- Engine 1.5.1 -> 1.5.2: offset-file verdicts change, so stored pairs revalidate once. Cache 10 -> 11: one video-cache rebuild. Related test constants updated (match_revalidate, video_cache, crash_diagnostics).
- I-XMP CONDITIONAL -> CLOSED; field GUI acceptance -> ACCEPTED (user decision 2026-11-02).

## 4. Resolved state

- Nonzero-start_time files now sample and fingerprint exactly like zero-start files (pinned by test).
- V2/V3/V4 are built with default behavior unchanged. Accuracy-gate validation awaits user datasets.

# MediaSimilarityFinder v0.9.4.91 — 그룹 정렬 "없음" 최상단/기본값 + 스캔 중 append-only 목록

기준선 `0.9.4.90` → 본 빌드 `0.9.4.91`.
CPU CTest **122/122**, GPU CTest **123/123**.
`kEngineVersion 1.5.1` / `kDatabaseVersion 1.0.6` / `kBenchmarkSchemaVersion 9` / `kCacheFormatVersion 9` 불변(GUI 전용 변경).

## 1. 변경 필요성

0.9.4.90에서 그룹 정렬에 `없음`을 추가하고 스캔 중 `없음`으로 고정했지만, 스캔 중에도 매 갱신마다
목록을 **전체 재생성**(`clear()` 후 재구성)했다. 사용자 요구:
- `없음`을 정렬 목록 **최상단**으로 옮기고 **기본값**으로 한다.
- 스캔 시작 시 `없음`으로 고정한다.
- 스캔 중 **현재 그룹 목록(썸네일)은 그대로 고정**하고 **신규 아이템만 맨 아래에 하나씩 추가**한다.

## 2. 기존 구조

- 정렬 항목 순서: `0=유사도, 1=이름, 2=없음`. 기본값 유사도.
- `fillPair()`는 매 갱신마다 `tree->clear()/grid->clear()` 후 전체 재구성 → 기존 썸네일/스크롤이 매 틱 재생성.
- 정렬 콤보 변경은 `refreshGroupList()`만 호출(재정렬 트리거 없음).

## 3. 변경 구조

- 정렬 항목 순서를 **`0=없음(기본), 1=유사도, 2=이름`** 으로 변경. 기본 인덱스 0 = `없음`.
- **스캔 중 append-only 목록**:
  - `rebuildGroups()`의 `없음` 모드가 **안정적 순서**를 만든다. 이미 나열된 그룹은 위치 유지,
    신규 그룹(또는 병합으로 union-find root가 바뀐 그룹)은 하단에 root 순으로 추가.
    (`noneOrder_`에 표시 순서 보존)
  - `fillPair(..., append=true)`: 현재 (root, 서명) 목록이 직전 표시 목록의 **접두 확장**이면
    **신규 행만 하단에 추가**하고 기존 행/썸네일은 재생성하지 않는다. 접두가 깨지면(병합/삭제/순서 변경)
    그 틱에만 **전체 재생성으로 폴백**한다.
  - `groupSig()` = (파일 수, 최고 유사도). 기존 그룹 내용이 바뀌면 접두 검사에서 걸려 전체 재생성.
  - `imgShown_`/`vidShown_`에 kind별 표시 (root, 서명)를 보관. 전체 재생성 시 리셋.
- `refreshStreaming()`이 스캔 중 `refreshGroupList(scanning_ && 정렬==없음)`을 호출한다. 전체 재생성 비용이
  스로틀 간격에 반영되도록 `rebuildGroups()`까지 타이머 안에서 측정한다.
- 정렬 콤보 변경 시 `rebuildGroups()` 후 `refreshGroupList()`를 호출해 **즉시 재정렬**(기존 누락 보정).

## 4. 해결된 상황

- 스캔 중 목록이 재생성되지 않고 신규 그룹만 하단에 append → 썸네일/스크롤이 고정된다.
- `없음`이 최상단·기본값이라 스캔 시작 시 별도 전환 없이 append-only가 기본 동작.
- 병합/내용 변경 시에만 전체 재생성(안전 폴백) → 정합성 유지.
- 스캔 종료 후 유사도순/이름순 선택 시 즉시 재정렬.

## 6. 향후 영향 및 한계

- GUI 전용. 엔진/DB/schema/cache 불변.
- append-only는 `없음` + 빈 그룹검색 + 스캔 중일 때만 적용된다. 그 외에는 종전과 동일한 전체 재생성.
- 병합으로 root가 바뀐 그룹은 하단으로 이동하며 그 틱에 전체 재생성이 일어난다(의도된 폴백).
- `없음`은 root 순 추가 순서를 노출하므로 신규 그룹 간 순서는 의미가 없다.

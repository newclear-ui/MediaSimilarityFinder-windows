# V-길이밴드 후보선별 + ECO 비교 알고리즘 (제안, 측정 기반)

Status: **PROPOSED (measured on captures, product code untouched)**
Baseline: **0.9.4.173** · Date: **2026-11-06**
Related: `docs/field-reports/longform-ad-capture-efficiency.ko.md` (§5.3, §6)

## 1. 목적

50만 쌍 전수 비교가 불가능하므로, 길이 밴드로 후보를 먼저 추리고 ECO 비교를 추려진 쌍에만 적용한다.
사용자 지시(재생시간대 후보 선별 + 시작/중앙/엔딩 대조 + 유사점 부근 정밀 대조)를
측정 가능한 규칙으로 구체화한 것이다.

## 2. 후보 선별 규칙 (밴드)

- 숏폼 (둘 중 하나라도 20분 미만): `abs(d1-d2) <= 90초` 일 때만 후보.
  근거: 트림·짧은 삽입이 60초를 넘지 않는다는 사용자 관찰 + 30초 여유.
  설계 정합성만 확인됨 (f 원본 33~134초 + 30초 리더는 전부 통과). 캡처 기반 미측정.
- 장편 (둘 다 20분 이상): `max(d1,d2)/min(d1,d2) <= 1.2` 일 때만 후보.
  근거: 180초 광고가 30분 영상에 붙어도 1.10, 2시간에 붙으면 1.03.
  1시간 vs 1시간반(1.5)은 탈락, 20분 vs 22~23분(1.10~1.15)은 통과.
- 측정 (25편 실측): 전체 300쌍 → 후보 75쌍 (**25%**, 75% 제거).
  동일 작품 50쌍 재현율 **50/50 (100%)**. GoT 동일회차(L02↔L03)는 동일 밴드에 남아 정탐 기회를 유지한다.

## 3. ECO 비교 규칙 (후보 쌍에만 적용)

1. 시작 0–300초를 3초 간격으로 캡처(약 140장)하고 관용 3-of-4 순서 탐색(≤1 스킵, 케이던스 4.5초)으로 오프셋을 찾는다.
2. 중앙 고정 3점(중앙−120/0/+120초)과 엔딩 고정 3점(끝−6/−3/0초)을 대조한다 (2-of-3 통과).
3. 양방향으로 수행하고, 어느 한 방향이라도 확정하면 DUP.
4. 시작+중앙+엔딩 일관 → DUP. 시작만 → UNCERTAIN. 근거 없음 → 미스(DIFF가 아니라 보류).

## 4. 측정 결과 (기존 캡처 재사용, 신규 디코드 없음)

- 후보 75쌍: **DUP 19 (전부 정탐) / FP 0 / UNCERTAIN 30 / miss 26**.
- 원본-삽입본 20쌍 기준으로는 DUP 13~15, UNCERTAIN 0~2, miss 5 (ECO 고정대표 측정과 일치).
- UNCERTAIN은 탈락이 아니라 보류다. 밴드 단계 재현율이 100%이므로, ECO가 놓치는 쌍도 후보 풀 안에는 남아 있다.
- 비교 연산: 쌍당 수 ms. 디코드가 지배적이므로 시작 관문(앞 5분만)으로 탈락 쌍의 전체 패스를 생략한다.

## 5. C++ 매핑 (구현 시)

- 밴드 필터: `MediaSearchEngine` 후보 생성 지점 (`CandidateIndex` 후단 또는 `ScanPipeline` pendingVideo 적재 전).
  `MediaFile::duration`은 이미 있다. 판정이 아니라 후보 순위/제외용.
- ECO 비교: `temporal_anchor.*` V2 계열 별도 함수로 추가한다
  (`findLeadingOffsetV2` 일반화 + 3-of-4 허용 + 고정 대표 대조). V1 동결, 엔진/DB/스키마 불변.
- 숏폼 경로: 시작/중간/끝 수 프레임 직접 대조 (광고 로직 없음). 캡처 기반 검증은 후속.

## 6. Gate 기준 (제품 반영 전)

- 밴드 재현율 100% 유지 (동일 작품 쌍 기준).
- ECO DUP 중 FP 0 (교차 200쌍 이상 기준).
- L01형 약한 증거 규칙·다중 프로브·끝 비저정보 3장 규칙 중 1개 이상 측정.
- CPU/GPU 전체 스위트 녹색 + 기본값(LegacyV3) 바이트 동일.
